# docs/: 문서 작성 규칙

> **처음 오셨다면** [작업 흐름](WORKFLOW.md) 한 장부터 보십시오.
> 이슈를 만드는 것부터 머지까지, 무엇이 자동으로 도는지가 표로 있습니다.

## 폴더

| 폴더 | 무엇 | 웹 게시 |
|---|---|---|
| `research/` | 자료조사·실측 정제본 (원 출처 링크 필수) | **자동** |
| `meetings/` | 회의록 (타임코드 인용) | 안 함 |
| `notices/` | 공지 원고 | 안 함 (디스코드로 발송) |
| `ops/` | 검증 기록·인프라 체크리스트 | 안 함 |
| 루트 | 기획·규칙 (COLLAB · FLOW · PLAN · LEDGER · DECISIONS) · 팀원 소개 (`TEAM-MAENG.md` → `team-maeng.html`) | 지정된 것만. 오흥재 소개는 `team-lead.html`(볼트 원본) |

> ★ **`docs/` 는 정본만 둔다.** 다듬어지지 않은 제출물은 저장소 루트의
> [`inbox/`](../inbox/README.md) 로 간다. inbox 는 웹에 나가지 않는다.
> 팀원이 inbox 에 올리면 팀장이 읽고 쓸 만한 것을 `research/` 로 옮겨 정본으로 만든다.

## 형식

- **Markdown.** 이미지·PDF 는 문서 옆에 같이 커밋한다. **10MB 를 넘으면 넣지 않는다** (2026-08-27 통일. `AGENTS.md`·`WORKFLOW.md` 와 같은 기준).
  큰 것은 NAS 나 클라우드에 두고 링크만 남긴다.
- 제목(h1) 은 파일당 하나. 날짜와 작성자를 머리에.
- 표를 아끼지 않는다. 목록보다 표가 빨리 읽힌다.

## 웹 자동 반영 (가동 중)

`research/` 에 올린 md 는 다음 빌드에서 자동으로 웹 페이지가 되고 표지 카드에 실린다.
빌드가 민감정보·문체·도식 규칙을 검사하고, 하나라도 걸리면 배포가 멈춘다. **공개되면 안 되는 문서는 `meetings/` 에 두거나
머리에 `<!-- private -->` 를 적는다.**
