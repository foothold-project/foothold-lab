# 이번 주 알게 된 것: 8월 2주 (W33)

> 작성 2026-08-12 · 범위 8/9(토)~8/12(화) · 주간 리포트(무엇을 했나)와 다른 문서다. **무엇을 알게 됐나**만 담는다.
> 각 항목은 한 문장 + 증거 링크 하나. 5분이면 이번 주의 발견을 다 안다.

## 1. 우리 로봇의 첫 공식 기록: 통과율 86.7%

1,500 iteration 학습 정책이 «10m 전진 · 넘어짐 없음 · 20초» 기준으로 **30번 중 26번 성공**했다.
이제 «우리는 무엇을 개선했는가»를 숫자로 말할 수 있다.
→ [학습 성능 실측 §5-3](research-training-benchmarks.html)

## 2. 실패의 원인은 «넘어짐»이 아니라 «느림»이다

난이도 0~9 전 구간에서 넘어짐은 30번 중 0~3번뿐. 실패의 대부분은 **10m 를 시간 안에 못 가서**다.
따라서 개선할 것은 «안 넘어지게»가 아니라 **«험지에서도 속도를 유지하게»**: 프로젝트의 첫 구체적 문제 정의.
→ [난이도 곡선 §5-4](research-training-benchmarks.html)

## 3. 보상이 높다고 걷는 것이 아니다

보상 13.94 를 받은 정책의 실제 통과율은 **0%** 였다(웅크리고 버티기만 함). 보상 22.88 은 86.7%.
학습 로그만 보면 «잘 되고 있다»는 착시가 생긴다. **평가 파이프라인이 존재해야 하는 이유.**
→ [시각 증거 §04-2](research-visual-evidence.html) (얼어붙는 장면 영상 포함)

## 4. Windows 에서는 GPU 2장을 묶어 학습할 수 없다

PyTorch Windows 빌드에 NCCL 이 없어 DDP 가 **구조적으로 불가**. 두 번째 5080은 «다른 실험 동시 실행»에만 쓴다.
우분투 전환의 실질적 근거가 하나 더 생겼다.
→ [학습 성능 실측 §5](research-training-benchmarks.html)

## 5. 학습 씬과 렌더 씬은 완전히 분리된다 (실증)

회색 험지에서 학습한 정책을 **정책 파일 하나만 들고** 창고 씬에서 걷게 하는 데 성공했다.
극사실 렌더 경로의 주춧돌. 렌더 비용도 실측: 1080p Path Tracing 128spp = **프레임당 1.75초** (30초 영상 44분).
→ [시각 증거 §03](research-visual-evidence.html) · [렌더 실측 §3](research-render-benchmarks.html)

## 6. 공개 최상위 정책들은 «실물형 관측 45차원»이었다

RoboGauge 점수표 상위 정책(symmetry 0.7006 등)을 직접 받아 로드해 보니 입력이 45차원(높이맵 없음).
그들은 우리 Teacher 가 아니라 **우리 Student 의 비교 상대**다. 그리고 NVIDIA 공식은 그 점수표에 아직 없다:
**우리가 처음 올릴 수 있다.**
→ [Go2 공개 정책 조사 §3](research-go2-pretrained-policies.html)
