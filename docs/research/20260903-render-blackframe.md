# 렌더 검정 프레임 결함 조사

> 분류: 실험
> 작성: 오흥재 · 2026-09-03 21:04
> 근거: 실측
> 요지: 고해상도 생성 지형에서 완성되지 않은 RGB 버퍼가 노출되는 조건을 재현하고 프레임 검증과 재시도로 차단했다.
> 상태: 확정
> 판: v1.0
> 이슈: #99

## 결론

`확인됨` 결함은 물리 계산이 아니라 뷰포트 RGB를 가져오는 시점에 있었다. 1920×1080 생성 지형 조건에서 `env.render()`가 완성 영상과 전부 0인 RGBA 버퍼를 번갈아 반환했다. 검정일 때도 원시 Replicator 버퍼 크기는 8,294,400바이트로 1920×1080×4와 같았다. 따라서 배열 크기가 0일 때 Isaac Lab이 만드는 대체 프레임은 아니었다.

`확인됨` 프레임 밝기를 절대값으로 검사하고 검정이면 렌더를 최대 두 번 더 진행하는 보호 코드를 추가했다. 같은 결함 조건을 수정 전후 각각 10회 실행했을 때 결함 판은 5/10에서 0/10으로 줄었다. 마지막으로 `repeated_boxes(반복 박스)` 한 판 300프레임을 1920×1080, 50 fps로 기록해 검정 0장, 교대 `false`, 지형 가시성을 확인했다.

`미확인` Isaac Sim 내부에서 어느 스왑체인 또는 렌더 태스크가 늦는지는 이번 조사 범위에서 계측하지 못했다. 확인한 범위에서는 Replicator가 전체 크기의 검정 버퍼를 내보낸 뒤 다음 렌더 호출에서 완성 버퍼를 내보내는 비동기 준비 시점 결함으로 좁혔다.

## 시험 환경과 판정 기준

| 항목 | 값 |
|---|---|
| Isaac Lab | v2.3.2 · 커밋 `37ddf62` |
| Isaac Sim | 5.1.0.0 |
| NVIDIA 드라이버 | 591.86 |
| GPU | `cuda:1` |
| 실행 방식 | headless rendering kit · `--enable_cameras` |
| 물리와 렌더 주기 | `sim.dt=0.005` · `decimation=4` · `render_interval=4` · 환경 스텝 0.02초 |
| 기본 시험 | Go2 1대 · 카메라 1개 · 20프레임 · seed 42 |
| 검정 판정 | 프레임 전체 평균 밝기 10 미만 |
| 교대 판정 | 모든 인접 프레임에서 검정 여부가 반대 |

프레임 판정은 PyAV로 영상을 다시 디코딩한 뒤 NumPy 평균을 구했다. 원시 캡처 값만 보지 않고 저장된 MP4를 기준으로 최종 결과를 확인했다.

## 가장 작은 재현과 변수 분리

각 행은 앞 조건에서 한 변수만 바꿨다. `single`은 환경 스텝마다 `env.render()`를 한 번 호출해 그 결과를 그대로 저장한 방식이다.

| 지형 | 카메라 | 해상도 | 캡처 | 검정/전체 | 교대 | 관찰 |
|---|---|---:|---|---:|---|---|
| plane(평면) | chase | 640×360 | single | 0/20 | false | 정상 |
| repeated_boxes(반복 박스) | chase | 640×360 | single | 0/20 | false | 지형 보임 |
| repeated_boxes(반복 박스) | topdown | 640×360 | single | 0/20 | false | 정상 |
| repeated_boxes(반복 박스) | topdown | 1920×1080 | single | 10/20 | true | 한 프레임마다 검정 |
| plane(평면) | topdown | 1920×1080 | single | 0/20 | false | 정상 |

`확인됨` 이 실행들에서는 topdown, 생성 지형, 고해상도 중 어느 하나만으로 결함이 나지 않았다. 세 조건이 겹친 시험에서 결함이 드러났지만, 아래 10회 반복에서 정상 판도 나왔으므로 이 조합은 충분조건이 아니라 재현 부하 조건이다.

## 수정 전 재현율

동일한 `repeated_boxes(반복 박스)` · topdown · 1920×1080 · single · 20프레임 조건을 새 프로세스로 10회 실행했다.

| 실행 | 검정/전체 | 교대 |
|---:|---:|---|
| 1 | 0/20 | false |
| 2 | 10/20 | true |
| 3 | 0/20 | false |
| 4 | 10/20 | true |
| 5 | 0/20 | false |
| 6 | 0/20 | false |
| 7 | 0/20 | false |
| 8 | 10/20 | true |
| 9 | 10/20 | true |
| 10 | 20/20 | false |

`확인됨` 결함 판은 5/10이었다. 그중 4 에피소드는 정확한 검정 교대였고 1 에피소드는 20프레임 모두 검정이었다. 기존 `flat_env109_ep01_gate0.002m_topdown.mp4`도 1,000프레임 중 500장이 검정이고 정확히 교대했다.

## 원인을 가른 관찰

한 환경 스텝에서 렌더 호출을 두 번 연속 수행하는 `pair` 시험을 10회 반복했다. 모든 판에서 저장한 두 번째 프레임은 검정 0/20이었다. 실행 1, 2, 7, 9에서는 첫 호출 20장이 전부 검정이고 바로 뒤의 두 번째 호출 20장은 전부 정상이었다.

추가로 검정 첫 호출 직후 `env._rgb_annotator.get_data()`를 직접 다시 읽었다. 결함 판의 검정 프레임마다 배열 크기는 8,294,400바이트였다. `확인됨` Replicator가 빈 배열을 반환한 것이 아니라 전체 크기의 검정 RGBA 배열을 반환했다. 바로 다음 렌더 호출은 같은 카메라와 장면에서 지형과 로봇이 보이는 정상 배열을 반환했다.

Isaac Lab의 [`ManagerBasedRLEnv.render()`](https://github.com/isaac-sim/IsaacLab/blob/v2.3.2/source/isaaclab/isaaclab/envs/manager_based_rl_env.py)는 Replicator 렌더 제품과 RGB annotator를 만들고 `get_data()` 결과를 반환한다. Isaac Lab에는 Isaac Sim 5.1의 RGB annotator 결과에 관한 [별도 결함 보고](https://github.com/isaac-sim/IsaacLab/issues/4565)도 있지만, 그 보고의 증상은 이번 교대 검정과 같다고 확인하지 않았다.

## 가설 판정

| 가설 | 판정 | 근거 |
|---|---|---|
| 물리와 렌더 주기 불일치 | 버림 | 정상 판과 결함 판 모두 `dt=0.005`, `decimation=4`, `render_interval=4`였다. CSV 물리 판정은 정상이었고 한 스텝의 연속 렌더만으로 검정이 정상으로 바뀌었다. |
| 카메라 종류 자체의 결함 | 버림 | 저해상도 topdown은 정상이었고 기존 험지 chase에서도 결함이 보고됐다. |
| 생성 지형 자체가 카메라에서 빠짐 | 버림 | 같은 장면에서 검정 직후 렌더 호출에 반복 박스 형상이 나타났다. |
| 조명 또는 렌더 레이어 누락 | 버림 | 장면 설정을 바꾸지 않은 연속 호출 사이에 검정과 정상 영상이 갈렸다. |
| `--enable_cameras` 누락 | 버림 | 모든 재현 실행에서 이 옵션을 사용했다. |
| PathTracing 샘플 부족 | 버림 | PathTracing을 요청하지 않은 기본 headless rendering kit 실행에서도 재현됐다. |
| 시작 워밍업 부족 | 단독 원인 아님 | 8회 워밍업 뒤에도 교대 판과 전부 검정인 판이 나왔다. |
| RGB 버퍼 준비 시점 | 채택 | 전체 크기 검정 배열 뒤 추가 렌더 호출에서 정상 배열이 나왔고, 검증 후 재렌더로 10/10 정상화됐다. |

## 수정

[`sim/eval/render_capture.py`](../../sim/eval/render_capture.py)에 `capture_lit_frame()`을 추가했다. 밝아야 하는 장면에서 RGB 평균이 10 이상인 완성 프레임만 반환하며, 기본 최대 3회 렌더 뒤에도 기준을 넘지 못하면 검정 영상을 저장하지 않고 오류로 중단한다.

[`sim/eval/render_blackframe_probe.py`](../../sim/eval/render_blackframe_probe.py)는 최소 재현과 검증 도구다. 평면과 반복 박스, chase와 topdown, 해상도, 환경 수, `single`·`pair`·`retry` 캡처를 독립적으로 바꿀 수 있다. `retry`는 시작 때 최대 120회 안에서 첫 정상 버퍼를 확인하고, 매 프레임은 최대 3회 안에서 검증한다.

이 보호 방법은 의도한 장면이 밝다는 전제가 있는 영상 기록에만 적용한다. 야간이나 의도적으로 검은 장면에는 고정 임계값을 그대로 적용하면 안 된다.

## 수정 후 재현율

수정 전과 같은 `repeated_boxes(반복 박스)` · topdown · 1920×1080 · 20프레임 조건에서 `retry` 방식으로 새 프로세스 10회를 실행했다.

| 지표 | 수정 전 | 수정 후 |
|---|---:|---:|
| 결함 판 | 5/10 | 0/10 |
| 검정 프레임 | 60/200 | 0/200 |
| 교대 판 | 4/10 | 0/10 |

`확인됨` 수정 후 10 에피소드 모두 검정 0/20과 교대 `false`였다. 첫 실행은 시작 준비에 렌더 2회가 필요했고, 나머지 9회는 1회가 필요했다. 첫 실행의 기록 프레임 중 최대 재시도 횟수는 2회였으며 검정 버퍼는 저장되지 않았다.

## 남은 한계

`미확인` 정확한 Isaac Sim 내부 동기화 지점과 GPU 부하별 임계 해상도는 아직 모른다. 이번 수정은 잘못된 프레임을 결과물에 넣지 않는 방어이며 렌더러 내부 결함 자체를 고친 것은 아니다. Isaac Sim 또는 Isaac Lab 버전을 올릴 때 동일한 10회 재현 시험으로 재검증해야 한다.
