# 역할 지도: 이 프로젝트가 각자를 어떤 직무로 데려가는가

> 작성 2026-08-21 (WS) · 뿌리: 맹라현이 공유한 역할 분석 대화(«Simulation Engineer가 되려면 어떤 역할을 맡아야 하나», 원본 링크 소실)와 7/27 팀 배경 기록, 8/18 팀 자산 분석을 합쳐 정리.
> 용도: 역할 축을 정할 때 "누가 무엇을 하나"가 아니라 **"이 축이 어떤 직무로 이어지나"**를 함께 본다.

## 1. 다섯 축과 채용 시장의 직무명

| 프로젝트 축 | 채용 시장 직무명 | 우리 산출물 = 포트폴리오 증거 |
|---|---|---|
| RL 정책·학습 | Reinforcement Learning Engineer · Robotics ML | 커리큘럼 학습 설계, 보상·관측 설계, 일반화 벤치마크 |
| 지형·씬·시뮬 환경 | **Simulation Engineer** · Technical Artist (USD) | Isaac Sim 지형·씬 파이프라인, Domain Randomization |
| 디지털 트윈·렌더 | Digital Twin Engineer · 3D Pipeline TD | 실공간 재구성, 실사급 렌더 시연 |
| 인지·데이터·평가 | Perception Engineer · Data/ML Engineer | 센서 데이터 처리, 정량 평가 파이프라인, 결과 검증 |
| 실기 항법 (ROS2·SLAM·Nav2) | Robotics Software Engineer | 실물 Go2 자율주행 스택, 현장 실험 기록 |
| (공통) 환경·인프라 | MLOps · Robotics Infra | 다중 사용자 학습 환경, 실험 추적, 클라우드 실행 |

공유 대화의 프레임(RL 학습 / Terrain·DR / Sim-to-Real / SLAM / Nav2·통합 + 백업 페어)이 우리 두 트랙 구조와 정확히 포개진다. 역할 논의는 이 틀 위에서 "각자 메인 + 겹침 1개"로 정하면 된다.

## 2. 팀원별: 가진 것 → 이 프로젝트의 대응물 → 포트폴리오 문장

| 팀원 | 가진 것 | 이 프로젝트에서 | 포트폴리오 문장 (전·후) |
|---|---|---|---|
| 오흥재 | 영상·VFX 12년, 카메라·공간·3D 파이프라인 | PM + 실공간 3D 재구성·실사급 렌더 축 | "3D를 다룬다" → **"물리 시뮬레이터와 현실을 잇는 디지털 트윈을 설계·검증했다"** |
| 임석헌 | 비전 학습·파인튜닝 R&D, 데이터 구축 | RL 정책 주담당. 보상·관측·커리큘럼 설계 (occlusion 관심 = 부분관측 문제와 직결) | "지도학습을 했다" → **"강화학습으로 축을 확장하고, 실물 센서 제약에서 역산해 관측을 설계했다"** |

## 3. 이 지도를 쓰는 법

1. 역할 확정 회의에서 각자 "메인 축 1 + 겹침 1"을 이 표에서 고른다. 겹침은 백업 페어가 된다.
2. 전담 멘토의 개별 취업 멘토링(이력서·포트폴리오·기업 매칭)과 접속: **축이 정해지면 포트폴리오 문장이 정해지고, 멘토가 그 문장을 검증해 준다.**
3. 각 축의 "증거"는 이미 웹에 쌓이고 있다: 연구 기록·평가 CSV·영상. 12월의 포트폴리오는 새로 만드는 게 아니라 **여기서 골라 담는 것**이다.
