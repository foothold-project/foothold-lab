## 1. 저쪽이 우리와 다르게 한 것 셋

**이 셋이 보고의 핵심이다.** 나머지는 근거다.

### 첫째 · z속도 벌점을 0 으로 껐다. 그것도 실험으로 확인하고 껐다

우리와 저쪽의 **평지** 설정은 이 항에서 값이 같다. 둘 다 `-2.0` 이다.
저쪽은 **험지 설정에서만 이것을 명시적으로 0 으로 덮어썼다.**

```
go2_env_cfg.py:141   z_vel_reward_scale = -2.0     # Go2FlatEnvCfg
go2_env_cfg.py:290   z_vel_reward_scale = -0.0     # Go2RoughEnvCfg
                     # 주석: "Test9 (jumping 많은 지형 고려) # 참고: Extreme Parkour: -0.5"
```

**그 값에 도달한 경로가 브랜치 이력에 남아 있다.**

| 브랜치 | 기록된 결과 |
|---|---|
| `...v09-reference_branch...25_11_03` | 기준 브랜치 |
| **`...v10-zvelreward-0-reference_branch...25_11_04`** | **「Best Rough Terrain Locomotion in 3d space @ 20000 iter training」** |
| `EncodingLatent_HardTerrain...` 계열 주석 | 「Abl3 generally best but **z-vel reward caused instability in some runs**; later zvel_scale=0 series used」 |
| 이후 전 계열 이름 | `EncodingLatent_HardTerrain_zvel0_Abl1...` · `..._zvel0_Abl3.5...` 처럼 **`zvel0` 가 이름에 박혔다** |

즉 저쪽은 z속도 벌점을 **한 번 실험으로 떨어뜨린 뒤, 그 뒤의 모든 네트워크 실험을 zvel=0 위에서 돌렸다.**
Ablation 1 부터 7 까지 전부 z속도 벌점이 없는 조건이다.

> **우리 `-2.0` 은 우리가 고른 값이 아니다.** IsaacLab 기본값
> (`velocity_env_cfg.py:242`) 을 그대로 물려받았고, `config/go2/rough_env_cfg.py`
> 는 이 항을 건드리지 않는다. 그리고 **IsaacLab 자신도 g1 험지에서는 이 값을 0 으로
> 끈다** (`config/g1/rough_env_cfg.py:133` · `self.rewards.lin_vel_z_l2.weight = 0.0`).
> h1 은 아예 항을 지운다 (`config/h1/rough_env_cfg.py:24` · `lin_vel_z_l2 = None`).
> **끄는 것은 이례적인 선택이 아니다.**

### 둘째 · 발 체공 보상을 우리의 12.5배로 주었다 <sub>[09-09 정정 있음]</sub>

두 쪽이 **같은 식**을 쓴다. `(마지막 체공시간 - 0.5초) x 첫접지` 를 네 발에 합하고, 속도 명령이 0.1 이상일 때만 준다.
저쪽 구현(`go2_env.py:383`)과 IsaacLab `mdp.feet_air_time` 이 문자 그대로 같은 식이다. **그러니 스케일이 직접 비교된다.**

| | 값 | 출처 |
|---|---|---|
| IsaacLab 기본 | `0.125` | `velocity_env_cfg.py:249` |
| 저쪽 험지 | `0.125` | `go2_env_cfg.py:287` · 주석 「Test25 (@ Extreme Parkour: 0)」 |
| **우리가 쓰는 go2 험지** | **`0.01`** | `config/go2/rough_env_cfg.py:53` · `self.rewards.feet_air_time.weight = 0.01` |

> **[09-09 정정]** ~~**우리만 기본값에서 12.5배 낮췄다.** 저쪽은 기본값을 그대로 썼다.~~
>
> **주체가 틀렸다. 낮춘 것은 우리가 아니라 NVIDIA 다.** `0.01` 은 `config/go2/rough_env_cfg.py:53`
> 에 있고, 그 파일은 **상류 IsaacLab v2.3.2 트리의 일부**다. 우리 저장소에는 그 줄이 없다.
> 실측 근거는 §9-2 에 있다. 저쪽이 기본값을 그대로 썼다는 것은 맞다.

발을 오래 띄우는 것이 **우리가 상속한 설정**에서는 거의 보상되지 않는다.

### 셋째 · 갭을 0.1 m 부터 커리큘럼으로 키웠다. 우리는 0.275 m 를 고정으로 놓고 잰다

| | 저쪽 `gap_bar` | 우리 `gap` |
|---|---|---|
| 형상 | +X 로 이어지는 **띠(strip)**. 갭과 착지대가 반복 | 중앙 발판을 두르는 **고리(ring) 하나** (`MeshGapTerrainCfg`) |
| 갭 폭 범위 | `0.1 ~ 0.8 m` | `0.15 ~ 0.40 m` |
| 난이도 | **커리큘럼.** 10단, 성공하면 승급 | **`difficulty_range=(0.5, 0.5)` 고정** |
| 실제 폭 | 레벨 0 에서 `0.1 m` · 레벨 9 에서 `0.73 ~ 0.80 m` | 항상 `0.275 m` |
| 학습에 포함 | **포함.** 4096 env x 20000 iter | **불포함.** 우리 정책은 갭을 본 적이 없다 |

우리 정책은 NVIDIA 공식 체크포인트이고, 그것이 학습한 `ROUGH_TERRAINS_CFG` 는
계단·상자·거친바닥·경사 넷뿐이다. **구멍이 하나도 없다** (`terrains/config/rough.py`).

## 2. 영상 한 장면의 정체: 「80 cm 갭 하나」가 아니다

**이것이 코드를 읽어서만 알 수 있는 부분이고, 영상 해석을 바꾼다.**

`gap_strip_terrain()` (`mesh_terrains.py:600`) 은 갭 하나를 만들지 않는다.
**타일이 찰 때까지 「갭 + 착지대」를 반복한다.**

```
gap_width = 0.1 + difficulty x 0.7          landing_length = 0.45 (고정)
start_platform_length = 8.0                 타일 x 길이 = 23.0
스폰 위치 = start_len x 0.5 = 4.0 m
```

레벨 9 의 난이도는 `(9 + η)/10`, `η ~ U(0,1)` 이므로 **0.9 이상 1.0 미만**이다.
여기에 위 식을 넣으면 이렇게 된다.

| 항목 | 계산 | 값 |
|---|---|---|
| 갭 폭 | `0.1 + 0.7 x [0.9, 1.0)` | **0.73 ~ 0.80 m** |
| 착지대 | 고정 | **0.45 m** |
| 한 주기 | 갭 + 착지대 | **1.18 ~ 1.25 m** |
| 갭 개수 | `floor((23.0 - 8.0) / 주기)` | **12개** |
| 첫 갭까지 조주 거리 | `8.0 - 4.0` | **4.0 m** |

> **레벨 9 는 80 cm 갭 하나가 아니라, 45 cm 짜리 섬 위에 착지하며 건너야 하는
> 80 cm 갭 열두 개다.** 영상에서 로봇이 「미끄러진 뒤 격렬하게 반응해서 겨우 건넌다」는 것은
> 한 번의 도약 실패가 아니라, **주기 1.25 m 의 반복 장애물에 걸린 상태**다.
> Abl 3.5 가 「부드럽게 예측한다」는 것도 한 번의 점프 계획이 아니라 **주기적 구조를 스캔으로 미리 보는 것**이다.

**착지대 0.45 m 가 얼마나 좁은지는 우리 실측으로 바로 잰다.**
우리 [Go2 제원 대조](20260908-go2-제원-시뮬실기-대조.md) §3 에 hip 앞뒤 간격이 **0.3868 m** 로 적혀 있고,
이 값은 시뮬과 실기가 정확히 같다. 네 발을 한 섬에 올리려면 **여유가 총 6.3 cm** 밖에 없다.

> **주의 · 「몸길이 70 cm」로 갭을 논하면 안 된다.** 우리 제원 문서가 §3 각주에서
> 이미 경고해 둔 자리다. 0.70 m 는 머리·꼬리를 포함한 외곽이고, 갭을 걸치는 능력을
> 결정하는 것은 hip 앞뒤 간격 **0.3868 m** 와 다리 최대 폄 **0.426 m** 다.

## 3. 대조표

### 3-1. 보상 함수

두 쪽 모두 최종 보상에 `step_dt` 를 곱한다(저쪽은 `_get_rewards` 안에서, 우리는 RewardManager 가).
**그러므로 아래 스케일은 서로 직접 비교된다.**

> **[09-09 정정]** 아래 「우리 go2 험지」 열의 값은 **전부 NVIDIA 가 정한 값**이다. 우리가 고른 값이
> 하나도 없다. 열 이름을 「**우리가 상속한 값 (= NVIDIA Go2 rough)**」으로 읽어야 맞다.
> 무엇이 IsaacLab 공통 기본값이고 무엇을 NVIDIA Go2 가 덮어쓴 것인지는 **§9-1 에서 갈라 놓았다.**

| 항 | 저쪽 험지 (Test25) | 우리가 상속한 값 (= NVIDIA Go2 rough) | 차이 | 우리가 차용할 수 있나 |
|---|---|---|---|---|
| **`lin_vel_z_l2`** | **`0.0`** | **`-2.0`** | **저쪽이 껐다** | **예 · 1순위.** IsaacLab g1 도 0 으로 끈다 |
| **`feet_air_time`** | **`+0.125`** | **`+0.01`** | **저쪽이 12.5배** | **예 · 2순위.** 같은 식·같은 임계(0.5 s) |
| **`dof_torques_l2`** | **`-2.5e-5`** | **`-2.0e-4`** | **우리가 8배 세다** | **예 · 3순위.** 도약은 토크 스파이크다 |
| `track_lin_vel_xy_exp` | `+3.0` | `+1.5` | 저쪽이 2배 | 조건부. 아래 §6 참조 |
| `track_ang_vel_z_exp` | `+1.5` | `+0.75` | 저쪽이 2배 | 조건부 |

| `ang_vel_xy_l2` | `-0.05` | `-0.05` | 같음 | 해당 없음 |
| `dof_acc_l2` | `-2.5e-7` | `-2.5e-7` | 같음 | 해당 없음 |
| `action_rate_l2` | `-0.01` | `-0.01` | 같음 | 해당 없음 |
| `flat_orientation_l2` | `0.0` (주석: 험지니까 몸이 기운다) | `0.0` | 같음 | 해당 없음 |
| `base_height` (지면상대) | 항 있음 · `0.0` | 항 없음 | 저쪽만 | 낮음 |

| `dof_close_to_default` | `-0.01` | 항 없음 | 저쪽만 | 낮음 |

| `feet_stumble` | 항 있음 · **`0.0` 으로 껐다** | 항 없음 | 둘 다 없는 셈 | 해당 없음 |

> 저쪽이 도약을 얻은 경로는 발 높이를 직접 보상한 것이 아니라,
> **z속도를 벌하지 않고 · 체공을 크게 보상하고 · 스캔을 준 것**이다.
> 「발 높이 보상을 넣자」는 제안은 저쪽 근거로는 뒷받침되지 않는다.

### 3-2. 커리큘럼

| 항목 | 저쪽 | 우리 | 우리가 차용할 수 있나 |
|---|---|---|---|
| 학습 커리큘럼 | **켬.** 10단 x 18열 | 학습은 IsaacLab 기본 `terrain_levels_vel` | 이미 있다 |
| 승급 조건 | 에피소드 실이동 거리 > 타일 x길이의 **0.5배** | 명령 속도 x dt 의 비율 기준 (IsaacLab 기본) | 구조는 같다 |
| 강등 조건 | 실이동 < 기대거리(명령속도 x 20 s)의 **0.5배** | 좌동 | 구조는 같다 |
| **승급 실제 문턱** | `23.0 x 0.5` = **11.5 m** | 지형 크기 8 m 기준 | 아래 경고 참조 |
| 시작 레벨 | `max_init_terrain_level = 5` | 평가는 `0` 고정 | 검토 |
| 평가 커리큘럼 | Play cfg 는 끄지만 **실험은 학습 task 로 돌렸다** (README 명시) | 평가는 `curriculum` 분리 · `terrain_levels = None` | **우리가 더 낫다** |

> **저쪽 커리큘럼에는 실측으로 확인한 문서 드리프트가 있다.**
> `go2_env.py:479` 의 주석은 「size=(8.0, 8.0) 이니 지형 길이의 절반(=4 m)보다
> 멀리 걸었는가」라고 적혀 있고, `README-BRANCH_EXPERIMENTS.md` 도
> 「Move up if distance > 4m」이라고 적는다. **그런데 실제 `size[0]` 는 23.0 이다.**
> 승급 문턱은 4 m 가 아니라 **11.5 m** 다. 조용히 세 배가 됐다.
> 레벨 9 에서 이 문턱을 넘으려면 **80 cm 갭 6개를 연속으로 건너야** 승급한다.

레벨 9 기준으로 셋을 계산하면 이렇다.

| 판정 | 필요 이동 | 도달 x | 건너야 하는 갭 수 |
|---|---|---|---|
| 승급 | > 11.5 m | > 15.5 m | **6개** |
| 유지 | 10.0 ~ 11.5 m | 14.0 ~ 15.5 m | 5개 |

### 3-3. 관측

| | 저쪽 Abl 1 (영상) | 저쪽 Abl 3.5 (최선) | 우리 |
|---|---|---|---|
| Actor 원시 입력 | `prop 52D` | `prop 52D + scan 187D` = 239D | `prop 48D + scan 187D` = **235D** |
| Actor 실제 입력 | 52D | `prop 52 + z_scan 32` = **84D** | **235D (인코더 없음)** |
| Critic 원시 입력 | `prop 52 + priv 29 + scan 187` = 268D | 268D | **235D (Actor 와 동일)** |
| Critic 실제 입력 | 268D (raw scan) | `prop 52 + priv 29 + z_scan 32` = **113D** | **235D** |
| scan 인코더 | 없음 | `MLP[128, 64, 32] + Tanh` · **Actor·Critic 각각 별도** | **없다** |
| 비대칭 여부 | **비대칭** | **비대칭** | **대칭.** critic 관측 그룹이 아예 없다 |
| `prop` 구성 차이 | `joint_pos·vel 24 + 중력 3 + 선속도 3 + 각속도 3 + 명령 3 + 직전행동 12 + **접지플래그 4**` | 좌동 | 같은 구성에서 **접지플래그 4D 가 없다** |

**두 가지가 곧바로 눈에 띈다.**

1. **우리에게는 특권 critic 이 없다.** IsaacLab velocity 의 `ObservationsCfg` 에는
   `policy` 그룹 하나뿐이라 critic 이 actor 와 똑같은 235D 를 본다. 저쪽 실험 전체가
   「critic 에 무엇을 넣느냐」의 비교인데, 우리는 그 축이 없다.
2. **우리 actor 는 발 접지 여부를 못 본다.** 저쪽 `prop_obs` 에는 4D 접지 플래그가 있다
   (`go2_env.py:312` · 접촉력 노름 > 1.0 N). 이것은 **실기에서도 읽히는 신호**이고,
   갭처럼 「지금 발밑이 있느냐」가 전부인 지형에서 정확히 필요한 정보다.

### 3-4. Teacher-Student · 특권 관측 증류

**결론부터: 저쪽은 증류를 하지 않는다.** 이 과제의 답은 이 저장소에 없다.

`grep -rn "student|teacher|distill|Distillation|DAgger"` 를 `direct/go2/` 전체에 돌렸고 **일치가 0건**이다.

> critic 에 넣을 때 같은 함정이 있다: **시간에 따라 변하지 않는 양을 인코딩하지 말 것.**

## 4. 우리가 같은 실패를 하지 않을 수 있는 점

**팀장이 명시적으로 요청한 절이다.** 아래 열은 전부 저쪽 코드·주석·브랜치 이력의 **원문 근거**가 있다.

### 4-1. 저쪽이 실패로 기록한 것

| # | 저쪽이 겪은 것 | 원문 근거 | 우리에게 무슨 뜻인가 |
|---|---|---|---|
| 1 | **z속도 벌점이 험지 불안정의 원인이었다** | 「z-vel reward caused instability in some runs; later zvel_scale=0 series used」 | 우리는 아직 `-2.0` 이다. **첫 손잡이가 여기다** |
| 2 | **첫 험지 시도의 실패 원인은 네트워크가 아니라 커리큘럼이었다** | Exp 1: 「fails to step; **curriculum not working (needs fix)**」 | 험지에서 안 걸을 때 네트워크부터 의심하지 말 것. **커리큘럼 승강 로그부터 볼 것** |
| 3 | **평지 결론이 험지로 전이되지 않았다** | 평지 최선 = Case 2 + Test5 → 험지에서 순위가 바뀌어 **Test20~27 을 다시 훑고 Test25 로 정착** | 우리 현재 기준선은 전부 평지다 (`20260903-flat-*`). **평지에서 고른 스케일을 험지로 그대로 들고 가지 말 것** |
| 4 | **`tanh` 를 표준편차에까지 씌워 PPO 가 조용히 깨졌다** | v03: 「Apply tanh to action outputs(mean, noise_std). → **rollout's distribution and update's distribution mismatch**」 · v04 에서 **mean 에만** 씌워 해결 | 행동을 눌러 담는 어떤 처리도 **샘플링 분포를 건드리면 안 된다.** 오류가 안 난다 |
| 5 | **잔차 규약이 브랜치 하나에서 조용히 깨졌다** | v07: 「our action is the residual of the default pos, so when the action is 0, it has to be the default pos. **But the prev branch didn't sustain this**」 | 행동 = 기본자세 잔차라는 규약. **불변식으로 시험해 둘 것** |
| 6 | **Abl 2.5 의 「스캔을 앞에 놓기」는 실험이 아니었다** | `scan_first_in_policy=True` + `class_name="ActorCritic"` (평범한 MLP) | 완전연결 첫 층에 대한 입력 재배열은 **가중치 열 치환과 같다.** 무작위 초기화에서 함수공간이 동일하다. **하이퍼파라미터처럼 보이지만 아무것도 안 바꾸는 변경** |

### 4-3. 종료 조건이 갭 추락을 못 잡는다

저쪽 `_get_dones` (`go2_env.py:463`) 는 **base 접촉력 > 1.0 N 하나뿐**이다.
그런데 `gap_strip_terrain` 이 만드는 갭에는 **바닥이 없다**. 지형 상자는 `z ∈ [-1.0, 0.0]` 이고
갭 구간은 공기다. **갭에 빠진 로봇은 아무것도 안 닿아서 종료되지 않는다.**
타임아웃까지 떨어지고, `Episode_Termination/base_contact` 에는 안 잡힌다.

> **우리가 띠형 갭 지형을 만들면 같은 일이 난다.** 우리 종료 조건도
> `terminations.base_contact` 하나다. **높이 기반 종료를 반드시 함께 넣어야 한다.**
> (현재 우리 `gap` 은 고리형이라 몸통이 턱에 닿아 생존 21% 로 잡히고 있다.
> 이것은 지형 형상 덕이지 종료 조건이 옳아서가 아니다.)

### 4-4. 지표와 영상이 서로 다른 승자를 가리켰고, 저쪽은 영상을 골랐다

`README-BRANCH_EXPERIMENTS.md` 에 두 번 적혀 있다.

```
Abl7.0 ... reported better than Abl8.0 and Abl3.5;
However, in sim_videos Abl3.5 seems better.

Abl3.5 ... Best result in simulation video
Abl7.0 ... Best result in graphs
```

**그래프는 Abl 7.0 을, 영상은 Abl 3.5 를 골랐다.** 최종 README 가 채택한 것은 **Abl 3.5** 다.

> **우리 4축 AND 도 그래프다.** 숫자가 이겼는데 영상이 이상한 경우를 우리는 아직 안 겪었다.
> 저쪽은 겪었고, **숫자를 버렸다.** 우리 판정 절차에 「승자 후보의 영상을 반드시 본다」를
> 넣어 둘 근거가 이것이다. 우리는 이미 `record_*` 로 영상을 뽑고 있으니 절차만 붙이면 된다.

### 4-5. Abl 1 의 「blind」 는 실기 기준의 blind 가 아니다

저쪽 `prop_obs` 에는 `root_lin_vel_b` 3D, 즉 **몸통 실제 선속도의 참값**이 들어 있다.
실기 Go2 는 이것을 직접 못 잰다(IMU 적분·상태추정이 필요하고 오차가 크다).

**우리도 같다.** `PolicyCfg.base_lin_vel` 에 잡음 `±0.1` 만 얹은 참값이 들어간다.

> **영상을 「고유수용감각만으로 이만큼 된다/안 된다」의 근거로 쓰면 과장이 된다.**
> 저 Abl 1 은 **속도 참값을 아는 blind** 다. 발표 자료에 이 영상을 인용한다면
> 이 단서를 함께 적어야 한다.

## 5. 우리가 지금 바로 시험해 볼 수 있는 것

### 5-0. 먼저 · 이것은 평가 A/B 가 아니라 학습 A/B 다

**보상 스케일을 바꿔도 우리 현재 체크포인트에는 아무 변화가 없다.**
`20260903-rough10-1.0mps` 의 정책은 **NVIDIA 공식 체크포인트**이고, 그것이 학습한
`ROUGH_TERRAINS_CFG` 에는 **구멍이 하나도 없다**. 보상 항은 학습 때만 쓰인다.

아래 A/B 는 전부 **재학습을 전제로 한 훈련 실험**이다. 이 문장을 빼고 팀에 전달하면
「값 바꿨는데 왜 그대로냐」가 나온다.

### 5-1. 판정 자를 먼저 고정할 것 (A/B 보다 먼저)

**이걸 안 하면 A/B 결과를 못 읽는다.** 우리 두 실행이 서로 다른 자를 썼다.

| 실행 | `min_progress_m` | `max_lateral_drift_m` | 근거 |
|---|---|---|---|
| `20260903-flat-10m` | 10.0 | **0.05** | `run_manifest.json` |
| `20260903-rough10-1.0mps` | 3.0 | **0.75** | `run_manifest.json` |
| 팀장 결정(2026-09-03) | 명시 없음 | **1.5** | `results/20260903-rough10-1.0mps/README.md` 머리 |

그리고 **0.05 m 자로는 평지에서도 2% 만 통과한다.**

```
flat, 100 에피소드:  생존 1.00 · 전진 1.00 · 속도추종 1.00 · 방향 0.02 → 종합 0.02
              평균 횡이탈 0.255 m  (임계 0.05 m)
```

> **네 축 중 셋이 만점인데 종합이 2% 다.** 방향축 하나가 AND 를 지배하고 있다.
> 도약을 배운 정책은 횡이탈이 **더** 커진다. 자를 안 고치고 A/B 를 돌리면
> **갭을 실제로 건너는 정책이 「더 나빠졌다」로 보고된다.**
> 값의 선택은 팀장 결정 사항이고(운영 원칙 2절 「방향을 좌우하는 결정」),
> 이 문서는 **자가 실행마다 다르다는 사실**만 올린다.

건드리는 곳은 한 파일 한 블록이다.
