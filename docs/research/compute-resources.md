> 이 문서가 답하는 것: 5개월짜리 학습·평가를 **어떤 장비에서 어떤 순서로** 돌릴 것인가.

## 1. 문제: 학습 한 번이 두 시간이다

실측 기준선이 이렇다. 로봇 4,096마리를 동시에 굴려 초당 약 23,000 스텝, 1,500 iteration 완주에 **133분** `확인됨`.
여기에 결과 판독과 수정을 붙이면 **하루에 돌릴 수 있는 실험은 4~5회**다. GPU 처리량이 병목이 아니라
사람의 판단이 병목이라는 뜻이기도 하지만, 평가까지 같은 장비에서 돌리면 그 4~5회마저 줄어든다.

그래서 **학습과 평가를 다른 장비로 분리**하는 것이 이번 자원 계획의 핵심이다.

## 2. GPU 종류가 작업을 가른다 `확인됨`

Isaac Sim 은 **RT 코어가 있는 GPU 를 요구한다.** NVIDIA 공식 요구사항 원문이
*"GPUs without RT Cores are not supported"* 이고, 헤드리스로 우회할 수 있다는 통념은
NVIDIA 직원들이 일관되게 부정했다. 근거와 출처는 [클라우드 GPU 조사](cloud-gpu-options.md) §1 에 있다.

| GPU 세대 | RT 코어 | Isaac Sim 학습·렌더 | 순수 CUDA 연산 |
|---|---|---|---|
| RTX 40·50 시리즈 | 있음 | 가능 | 가능 |
| V100 (Volta) · A100 · H100 | 없음 | **불가** | 강함 |

이것은 «좋은 GPU / 나쁜 GPU» 의 문제가 아니라 **용도가 다르다**는 문제다.
V100 은 레이트레이싱 하드웨어가 없을 뿐, FP32 15.7 TFLOPS 와 HBM2 를 갖춘 연산용 GPU다.

## 3. 그래서 이렇게 나눈다

| 작업 | 필요한 것 | 어디서 |
|---|---|---|
| 강화학습 (Isaac Sim / Isaac Lab) | RT 코어 | RTX 계열 |
| 극사실 렌더 (Path Tracing) | RT 코어 | RTX 계열 |
| **평가 대량 롤아웃** (MuJoCo/MJX) | 병렬 연산 | **V100** |
| **정책 증류** (Teacher → Student) | 병렬 연산 | **V100** |
| **sim-to-sim 교차 검증** | 병렬 연산 | **V100** |
| **3DGS 지형 재구성** | 병렬 연산 | **V100** |

## 4. 왜 평가에 그렇게 많은 연산이 필요한가

첫 공식 기록은 30회 시행 기준 **통과율 86.7%** 였다 `확인됨`.
그런데 30회로는 «개선했다» 를 증명하지 못한다. 난이도 10단계와 지형 6종을 교차하고
조합당 100회를 돌리면 **한 정책당 6,000회 이상**이고, 정책 후보가 늘 때마다 그만큼 곱해진다.

평가를 아끼면 결론이 흔들리고, 평가를 늘리면 학습이 밀린다.
장비를 나누면 둘 다 할 수 있다. 그것이 외부 자원을 신청한 이유다.

## 5. 신청 규모

| 항목 | 신청값 |
|---|---|
| GPU | 상시 8장, 병렬 실험 기간 최대 16장 |
| Storage | 2Ti (팀 공유 볼륨 + 개인 작업 볼륨) |
| 기간 | 2026년 8월 중순 ~ 12월 중순 |

## 6. 배정 결과 `확인됨`

**2026-08-14 배정 완료.** V100 24장 풀(컨테이너 1개당 최대 8장), CPU·메모리 제한 없음,
스토리지 최대 4TiB. 컨테이너는 Docker Hub 이미지를 그대로 쓰고, 컨테이너 내부 SSH 를
포트 포워딩으로 열어 접속한다.

### 우리가 정한 운영 규율

계정이 **하나**다. 5인이 같은 공간에 들어간다. 기술보다 이 합의가 먼저였다.

| 규칙 | 왜 |
|---|---|
| 컨테이너·볼륨 이름 앞에 **자기 이름** | 누구 것인지 이름만 봐도 안다 |
| **남의 것은 건드리지 않는다** | 실행 중인 학습이 날아간다 |
| 다 쓰면 컨테이너를 지운다 (볼륨은 남긴다) | 자원은 다른 팀과도 나눠 쓴다 |
| 팀 공유 데이터셋은 공유 볼륨 하나에 | 같은 데이터를 5벌 복사하지 않는다 |

문서 저장소의 `inbox/` 를 사람별 폴더로 나눈 것과 같은 원칙이다.
**충돌은 규율로 막는 것이 아니라 구조로 막는다.**

### 붙자마자 확인하는 것

```bash
nvidia-smi
python -c "import torch; print(torch.cuda.get_device_capability(0))"
```

`(7, 0)` 이면 정상이다(Volta). 우리 워크스테이션이 쓰는 torch 조합이 이 세대에서도
도는지는 아직 확인하지 않았다 `미확인`. 안 되면 컨테이너의 torch 만 낮춘다.
**학습 환경과 버전을 같게 맞출 이유가 없다.** 여기서 도는 것은 평가·증류·3DGS 이고,
넘어오는 것은 정책 파일 하나뿐이기 때문이다.

### 첫 작업

**평가 파이프라인을 이 환경에서 재현해 기존 결과와 대조한다.**
같은 정책·같은 시드로 통과율 86.7% 가 그대로 나와야 이 환경을 믿을 수 있다.
숫자가 다르면 원인을 먼저 찾는다. **믿을 수 없는 환경에서 6,000회를 돌려봐야
그 숫자는 아무것도 증명하지 못한다.**

실제 사용량과 병목은 쓰면서 이 문서에 이어 적는다. `미측정`
