## 0. 이 문서를 읽을 때 조심할 것

**셋을 나란히 놓지만 같은 자로 잰 것이 아니다.** 아래를 먼저 읽지 않으면
숫자를 잘못 읽는다.

| 조심할 것 | 왜 |
|---|---|
| **계보가 다르다** | `v2g2` 는 NVIDIA 에서 resume 한 판이고 `fs1` · `fs2` 는 처음부터다. 같은 「3000 판」이 다른 뜻이다 |
| **GPU 가 갈렸다** | `fs1` 은 `cuda:0` · `fs2` 는 `cuda:1` 이다. `CRITERIA.md:495` 가 금지한 배치이고 `:544` 가 GPU 효과를 «미측정» 으로 둔다. 그래서 `fs1` 대 `fs2` 의 보상 대비는 **장치 효과를 품고 있다** |
| **`v2g2` 는 4500 판이 없다** | 3000 까지만 돌았다. 4500 칸은 비어 있는 것이 정상이다 |
| **어느 것도 배포 후보가 아니다** | 아래 2 절 |

`v2g2-feetair01` 은 iter3000 기준 48칸 평균이 가장 높지만 **일반화 후보로
확정된 것은 아니다.** 축 2 가 네 체크포인트에서 6/9 · 2/9 · 5/9 · 8/9 이고
CRITERIA v1.4 의 「네 점 전부 통과」를 못 넘는다. **지금까지 성적이 가장 좋은
판**일 뿐이다.

## 5. 폭주 · 처음부터도 터지나

resume 계보에서 **여덟 판**이 죽었다. 전부 같은 문구다.

```
RuntimeError: normal expects all elements of std >= 0.0
```

매개화 · 보상 가중치 · 시드 · optimizer 처리 **한 손잡이로는** 갈리지 않는다.
그리고 **모든 판에 똑같이 있던 것**이 `resume` 이다. 다만 그것이 원인이라는
근거는 **미확인**이다. `fs1` · `fs2` 가 그것을 잰다.

<!-- 자동:폭주 시작 -->
| 판 | 완주 | 마지막 체크포인트 | 오류 |
|---|---|---|---|
| `v2g2-feetair01` | **예** | 3000 |  |
| `fs1-scratch-f001` | **아니오** | 1175 |  |
| `fs2-scratch-f01` | **아니오** | 1150 |  |
<!-- 자동:폭주 끝 -->

**완주해도 「처음부터는 안 터진다」로 일반화하면 안 된다.** 시드 하나이고
환경 하나다. 터지면 전환 근거 하나가 사라지고, 그것도 결과다.
