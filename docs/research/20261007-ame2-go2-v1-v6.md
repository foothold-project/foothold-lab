## 2. AME-2 가 무엇이고 여기서 무엇을 만들었나

### 2.1 논문의 구조 `확인됨`

논문은 arXiv 2601.08485 v3 「Agile and Generalized Legged Locomotion via Attention-Based Neural Map Encoding」이다. 완성된 시스템에는 학습 결과가 셋 필요하다 (`docs/AME2_Go2_Implementation_Plan_ko.md` 1절).

| 구성 | 입력 | 역할 |
|---|---|---|
| teacher | 깨끗한 몸 상태 + **정답 높이지도** + 목표 | 목적지 도달 정책 (PPO) |
| Mapper | 깊이 카메라 점군 → 국소 격자 | 가려진 지형의 높이와 불확실성 예측 (지도학습) |
| student | Mapper 지도 누적 + 상태 이력 20프레임(LSIO) + 목표 | teacher 행동과 지도 표현을 배우는 실배포용 정책 (PPO + 증류) |

- 과제는 **속도 추종이 아니라 「목표 위치 + 도착 방향」 도달**이다. 논문 자체가 중간 운동의 직접 제어에 한계가 있다고 적는다 (`docs/AME2_HiPAN_Integration_Review_ko.md` 2절).
- 논문 수치는 ANYmal-D 시뮬레이션 기준 미학습 지형 평균 성공률 teacher 95.2 %, student 82.4 % 다. Go2 수치가 아니다 (`docs/AME2_Go2_Implementation_Plan_ko.md` 18절).
- 논문 학습 예산은 teacher 80,000회 · student 40,000회, 전체 약 60 RTX 4090 GPU-days 다 (같은 문서 14절).

### 2.2 볼륨에 실제로 구현된 teacher `확인됨`

코드: `experiments/ame2_flat_recovery_v14_candidate_20261006/bootstrap/teacher_network.py`, `policy_observations.py`, `teacher_env_cfg.py`. 신경망 파일 해시는 내부 v7 과 v12 에서 같다(`reports/flat_fresh_3322_20260929/manifest.json` 과 `reports/flat_gait_design_v12_20261006/comparison_plan.json` 의 `teacher_network.py` 1bcf8af6…). v13 은 `architecture_unchanged: true` (`reports/flat_precise_arrival_v13_20261006/manifest.json`), v14 는 「핵심 네트워크/보상/제어 코드 동일성 통과」(`reports/flat_recovery_v14_20261006/HANDOFF_ko.txt`)를 기록한다. v13 · v14 의 해시 자체는 대조하지 않았다.

**actor 입력 1,102 = 상태 49 + 지도 27×13×3**

| 묶음 | 차원 | 내용 |
|---|---:|---|
| 몸 상태 | 45 | 몸체 선속도 3 · 각속도 3 · 중력 방향 3 · 기본 자세 대비 관절각 12 · 관절속도 12 · 직전 행동 12 |
| 목표 명령 | 4 | 몸 좌표 목표 x · y (벡터 길이 2 m 로 자름) · sin · cos(상대 도착 yaw). 학습 중 2 m 밖 목표는 yaw 를 무작위로 가림 |
| 지도 | 1,053 | 27×13 격자(6 cm, 중심 x 0.36 m) 각 셀의 [상대 x, 상대 y, 상대 높이 z] |

**actor 구조**

- 상태 encoder: MLP 49 → 128 → 64.
- 지도 encoder: 셀별 위치 MLP 3 → 32 → 16, 높이만 넣는 CNN(5×5 두 층) → 48채널, 점별 MLP 64 → 96 → 96, 전역 MLP 96 → 128 → 64 를 max pool 해 전역 64. 상태 64 + 전역 64 로 query 96 을 만들어 351개 점에 **multi-head attention(96차원, 32 head)** → 국소 96. 합쳐 지도 표현 160.
- decoder: 224 → 512 → 256 → 128 → 12 (12관절 목표 offset). 활성함수 ELU.
- 은닉층 크기 · ELU 는 논문 미공개라 「구현 선택」으로 코드 주석에 표시돼 있다.

**critic 입력 420 = 몸 45 + 전체 목표 5 + 정답 높이 351 + 링크 접촉 19**

- 목표 5 는 자르지 않은 상대 x · y · sin · cos · 남은 시간 비율.
- 구조: **MoE 16 expert**(각 420 → 256 → 256 → 128 → 1) + softmax gate(420 → 128 → 128 → 16). 좌우 대칭 증강은 critic 에만 쓴다 (`experiments/ame2_restore_v1/README_ko.md`).

**제어와 PPO**

- 물리 400 Hz, 정책 50 Hz (decimation 8), 행동 1 = 관절 목표 0.25 rad (`teacher_env_cfg.py` 25 · 31 · 77행).
- Go2 용 보호: 목표각은 기본 자세 ±0.5 rad 안, 정책 주기당 변화 4 rad/s 이하. 출력 배율은 이동 중 0.8, 목표 근처 0.4 (내부 v8 이후, `reports/flat_move_focus_v11_20260930/manifest.json` 의 `control`).
- PPO: 4096 환경(논문 4800), rollout 24 step, 4 epoch, 3 minibatch, entropy 0.004 → 0.001, microbatch 512 (`experiments/ame2_restore_v1/README_ko.md`).

### 2.3 센서 · 지형 · 무작위화 (teacher 학습 전 단계) `확인됨`

9/22~9/23 에 다음을 만들고 0 행동 진단으로만 검사했다 (`docs/AME2_RESUME_ko.md`).

- 전방 · 하부 깊이 카메라 2대 160×120 · 25 Hz, Mapper 입력용 37×23 격자(4 cm), teacher 용 27×13 격자.

- payload ±5 kg, 마찰 0.3~1.0, PD 지연 0~20 ms, 지도 잡음 ±0.05 m · 조회 drift ±0.03 m.
- 19개 링크 접촉 센서로 자기충돌과 지면 접촉을 나눠 보상에 사용.

### 2.4 만들지 않은 것 `확인됨`

- Mapper 학습, 전역 지도 누적, LSIO, student 학습은 시작하지 않았다. `docs/AME2_RESUME_ko.md` 의 「남은 순서」가 그대로이고, `reports/public_go2_v15_20261007/HANDOFF_ko.txt` 도 「현재 학생/실센서 neural mapping은 구현한 것이 아니다」라고 적는다.
- 볼륨 목록 7,709개에서 `mapper` · `lsio` · `sim2sim` · `mujoco` · `foothold` 는 0건, `student` 는 rsl_rl 라이브러리 파일 4건뿐이다 (`계산`: 목록 grep).

## 10. 프로젝트와의 연결

### 10.1 두 트랙과 AME-2 의 자리

- 저장소 결정: 트랙 A = 시뮬 RL + 트윈, 트랙 B = 순정 보행 위 SLAM · Nav2 (`repo:docs/DECISIONS.md` 95행). `확인됨`
- 최종 트랙 A 는 「우리 정책이 ACC 디지털 트윈 안에서 걷는 것」이다(팀장 10/7 방향 · 일정과 완료 기준은 팀장과 설계 중).
- 트랙 B 는 Go2 순정 보행을 쓰므로 **AME-2 가 트랙 B 에 직접 들어갈 자리는 없다.** AME-2 가 쓰일 곳은 트랙 A 의 「우리 정책」 후보다. `추정`

### 10.2 인터페이스가 다르다

- AME-2 actor 의 명령은 `[dx, dy, sin dψ, cos dψ]` 목표 자세이고 속도는 정책이 스스로 정한다 (2.2절). `확인됨`
- 우리 foothold 계열은 Isaac Lab 속도 명령(`lin_vel_x` · `ang_vel_z` · heading)을 따른다 (`repo:docs/research/20260929-locomotion-direction.md` 95~98행). 같은 문서 175행도 「목표 도달이 세밀한 중간 속도 명령 준수와 같지 않다」고 적는다. `확인됨`
- Nav2 의 controller 는 속도 명령(cmd_vel)을 낸다. 이것은 Nav2 의 일반 구조이고 이 볼륨의 근거는 아니다.
- 그래서 AME-2 를 Nav2 아래에 붙이려면 둘 중 하나다. `추정`
  - (가) controller 를 거치지 않고 전역 경로의 앞쪽 지점을 AME 목표로 넘긴다(waypoint 추종형).
  - (나) cmd_vel 을 「현재 위치 + 속도 × 시간」 목표로 바꾼다. HiPAN 검토 문서는 이 방식이 속도 · 도착 시점을 강제하지 못하고, 0.3 m/s × 1초 = 0.3 m 목표는 AME 의 도착 · 정지 영역에 들어가 0.3 m/s 추종과 같지 않다고 적는다 (`docs/AME2_HiPAN_Integration_Review_ko.md` 3절 A). `확인됨`

### 10.3 석헌 쪽 상위 설계 문서 요약 (9/22, 실행 전 설계) `확인됨`

**`docs/AME2_HiPAN_Integration_Review_ko.md`**

- HiPAN(상위 10 Hz 경로 정책 + 하위 보행, 명령 vx · vy · ωz · 몸 높이 h · roll)과 AME-2 를 붙이는 네 방식을 비교했다.
  - A: HiPAN 출력을 수식으로 AME 목표로 변환. 연결 확인용, 최종 비추천.
  - **B: 상위 정책이 목표 위치 · 도착 방향을 내도록 학습. 사용자 채택.**
  - C: AME 를 속도 · 높이 · roll 추종기로 확장. 미채택.
  - D: 목표 + 자세 6차원 절충. 미채택.
- 두 카메라 160×120 계약(전방 아래 15°, 하부 아래 60°, 25 Hz)을 정했다. 통합 학습 · 성능 측정은 하지 않았다고 명시한다.

**`docs/AME2_PGCL_Navigation_Spec_ko.md`**

- AME-2 를 단독 학습한 뒤 **student 를 고정**하고, 상위 정책이 10 Hz 로 다음 목표 `[dx, dy, dyaw]` 를 낸다. 목표는 발행 시점 world 좌표로 저장해 다음 갱신까지 고정한다(`LocalPoseCommandBridge`).
- 상위 정책은 PGCL(경로 안내 curriculum)로 학습한다.
  - 학습 때만 정답 지도에서 경로를 만들고 1 m 간격으로 중간 목표를 둔다.
  - 순서대로 다 지나면 간격을 1 m 늘린다. 마지막 단계는 최종 목적지만 준다.
  - 도달 판정은 실제 로봇 위치로 한다.
- 모듈 6개(`FrozenLocomotionRunner` · `LocalPoseCommandBridge` · `PGCLScheduler` · `NavigationEnv` · `NavigationPolicy` · `NavigationTrainer`)를 정의했지만 「이미 존재하는 실행 파일 목록이 아니다」.

**이 프로젝트에 주는 함의** `추정` · lead 의견이며 계획은 팀장과 정한다

- PGCL 경로는 고정된 AME student 를 전제로 하는데 student 가 아직 없다(2.4절). 그래서 12/11 일정 안에 트랙 A 나 B 에 들어오기는 멀다.
- 다만 「목표 자세를 받는 하위 + 경로 지점을 주는 상위」라는 B 안의 인터페이스는 10.2 (가)와 같은 모양이다. 트랙 B 의 Nav2 전역 경로를 상위 대신 쓰는 시험(teacher 로 평지에서)은 비교적 싸게 해 볼 수 있다.
- 트랙 A 트윈에서 쓰려면 먼저 v14 candidate 를 우리 평가 하네스(속도 명령 과제)와 AME 목표 과제 양쪽에서 재는 대조표가 필요하다. 지금은 어느 쪽도 같은 잣대로 비교된 적이 없다(8절).
