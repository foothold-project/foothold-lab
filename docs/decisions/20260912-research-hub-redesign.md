## 1. 보존 계약 · 카드가 담는 것 전부

**대상은 `hub-research.html` 이다.** `research.html` 은 별도의 38장 목록이라
섞으면 안 된다.

「37장」은 **일반 목록 카드 36장 + 출발선 1장**이고 markup 이 다르다.

| 층 | 구성 | 수 |
|---|---|---|
| 묶음 바깥 | 묶음 제목 `.eg3` · 묶음 건수 · 컨테이너 `.evs3` | |
| 클릭 영역 | `<a class="ev3" href>` 전체 | 36 |
| 등록 정보 | `data-added` · NEW 표시와 읽음 처리에 쓴다. **작성일과 다르다** | 일반 카드 33 · 출발선 링크 1 · 보드 공통 링크 1 = **쪽 전체 35** |
| 번호 | `.ex3` · 묶음마다 다시 시작하는 표시 순번. **문서 ID 가 아니다** | 36 |
| 왼쪽 | 수치 `.en3` (숫자 11 · `·` 9) **또는** 출처 `.en3.src.s-*` | 20 / 16 |
| 본문 | `.eb3` 안의 제목 · 요약 · 작성 정보 `.em3` | 36 |
| 라벨 | `.em3` 안의 `<u class="ar-*">` 작업 영역 | 20장에 29개 |
| 그림 | `.eth3 > img` · `src` · 캐시 해시 · 빈 `alt` · `loading=lazy` | 6 |
| 반응형 | grid 배치 · hover · **모바일에서 썸네일 숨김** | |
| 출발선 | `.hero3` · 결론 링크 `.ht3` · 강조 숫자 · 제목 `.hd3` · 안내 `.hn3` | 1 |

**이 표의 모든 줄이 보존 대상이다.** 새 영역이 이 중 하나라도 지우면 그것은
개선이 아니다.

## 2. 배치 · 출발선을 지우지 않는다

### 2-1. 왜 「얹기」가 아닌가

| | PC 1440 | 휴대폰 390 |
|---|---:|---:|
| 지금 첫 목록 카드 y | 1263.02 | 3342.88 |
| 입구를 그냥 더하면 | **+128** | **+180** |

이미 첫 카드가 두 번째 화면 아래에 있다. 더 밀면 나빠진다.

### 2-2. 그런데 출발선을 지우면 무엇이 없어지나

v2.0 은 「출발선을 배포 요약으로 대체한다」고 했다. codex 가 `.hero3` 가 하는
일 셋을 짚었고, 그중 둘은 배포 요약이 대신하지 못한다.

| `.hero3` 가 하는 일 | 배포 요약이 대신하나 |
|---|---|
| 결론 문장 「기준 정책은 미경험 지형 10종 중 5종에서 실패한다」 | **아니다.** 이것은 «문제»이고 배포 요약은 «결과»다 |
| 강조 숫자 `10종 중 5종` 과 실측 문서 링크 | 링크는 목록에 남지만 **왜 그 다섯인가**가 사라진다 |
| 「실패한 다섯 지형은 아래에서 하나씩 본다」는 보드 연결 | **아니다.** 보드를 뒤로 내리면 연결이 끊긴다 |

게다가 출발선 선정은 수동 고정이 아니다. `hub3.py:492~501·728~775` 가
실측 문서 중 **열린 이슈 언급 수**를 먼저 보고, 같으면 참조 자식 수를 본다.
지우면 이 선정 규칙도 함께 죽는다.

### 2-3. 그래서 「대체」가 아니라 「합치기」다

한 블록 안에서 **그때의 문제와 지금의 결과를 나란히** 놓는다. 두 영역을
따로 쌓지 않으므로 높이가 늘지 않는다.

| 줄 | 내용 | 출처 |
|---|---|---|
| 1 | **문제** · 기준 정책은 미경험 10종 중 **5종**에서 실패한다 | 출발선 문서 (자동 선정 유지) |
| 2 | **지금** · foothold-v1 이 그중 **3종을 넘었다** · 1종 절반 · 1종 그대로 | 배포 원장 |
| 3 | 조건 한 줄 · 1.0 m/s · 난이도 0.5 · 지형마다 100판 · 측정 규격 2 | 배포 원장 |

**옛 수치를 현재 성적으로 읽히게 두지 않는다.** 출발선 원문은 지형당 **50판**,
현재 배포는 **100판**이다. 출발선 숫자에는 「당시 · 50판」을 붙인다.

### 2-4. 보드는 위에 남는다 · 전체는 펼친다

v2.0 의 「뒤로 내리거나 접는다」는 선택조차 끝나지 않은 문장이었다. 정한다.

| 부분 | 어디 | 기본 |
|---|---|---|
| **담당 지형 다섯 칸** (지형명 · 담당자 · 열린 이슈 수) | 배포 요약 바로 아래 · **항상 보임** | 펼침 |
| **전체 보드** (진단 · 설계 · 레시피 · 결과 네 단계 · 공통 · 미분류) | 그 아래 | **접힘** |
| 다섯 칸 중 하나를 누르면 | 해당 행의 네 단계만 열린다 | |

- 문서 목록의 길이와 **무관하게** 자기 지형으로 갈 수 있다.
- `#terrain-gap` 같은 주소로 **직접 진입**하면 그 행이 열린 상태로 그린다.
- 펼침·접힘은 `history.replaceState` 로 남겨 **뒤로 가기에서 복원**한다.
- 접힌 상태에서도 빈 단계 표시와 「외 N건」 건수는 보존한다 (`_tk_cell` · `_tk_kat`).

### 2-5. 높이 예산 · 이것이 관문이다

설계가 치수를 안 적으면 「밀렸는지」를 판정할 수 없다. 예산을 박고 **빌드가
잰다.**

| 항목 | PC 1440 | 휴대폰 390 |
|---|---:|---:|
| 배포 요약 + 출발선 (한 블록) | 210px 이하 | 300px 이하 |
| 담당 지형 다섯 칸 | 96px 이하 | 168px 이하 |
| 입구 거르개 단추 줄 | 56px 이하 | 92px 이하 |
| 전체 보드 (접힘 머리만) | 48px 이하 | 56px 이하 |
| **첫 목록 카드 y** | **1263 이하** | **3342 이하** |
| 모바일 카드 본문 최소폭 | | **240px 이상** |

**첫 카드 y 는 지금보다 커지면 안 된다.** 같거나 작아야 통과다. 재는 방법은
9절의 조판 관문에 붙인다.

## 3. 배포 요약 · 수치의 조건

### 3-1. 큰 수를 성공률의 분모로 붙이지 않는다

| 수 | 무엇의 수인가 | 어디에 |
|---|---|---|
| **100판** | `gap` 100 % 같은 **한 칸의 분모** | 그 수치 옆 |
| 14,400 | 난이도 0.5 성적표 **전체 표본** | 요약 줄 |
| 43,200 | 본 데이터 전체 (**raw CSV 54개** · 59열) | 상세 |
| 95,400 | 곡선 자료 전체 (**raw CSV 99개** · 27열) | 상세 |
| 90,000 | 그중 **미경험 10종 곡선** | 곡선 옆 |

「54 CSV」·「99 CSV」는 **요약 CSV 를 뺀 raw CSV 수**다. 그렇게 적는다.

### 3-2. 기준 배포는 「그때 발행한 묶음」으로만 쓴다

**v1 배포는 한 순간이 아니다.**

| 커밋 | KST | 영상 | 정본 웹판 | 합본·곡선 |
|---|---|---:|---|---|
| `62d0199` | 09-12 02:59 | 84 | 없음 | 없음 |
| `061f720` | 09-12 11:44 | 84 | 있음 | 없음 |
| `528fbe4` | 09-12 15:17 | 112 | 있음 | 없음 |
| `f3d5ab2` | 09-12 19:18 | **144** | 있음 | **있음** |

**제안: `f3d5ab2`.** 다만 v2.0 이 근거로 댄 「지금 live 이므로 현재 정본까지
대표한다」는 **성립하지 않는다.** 로컬 site 는 이미 그 뒤의 커밋이고, 실제
운영 배포 커밋은 이 범위에서 확인하지 못했다.

그리고 그때 본문과 지금 본문은 **뜻이 다르다.**

| `f3d5ab2` 시점 | 지금 |
|---|---|
| 3 m 통과선은 「여기를 넘으면 성공」 | **전진 축을 채우는 자리 · 성공은 네 축 AND** |
| parquet 92열 | 93열 |
| CSV 61열 통합 · 본 데이터 미완료 | **59열 · 43,200행 완료** |
| 대표 영상 112컷 | **144컷** |
| B 는 같은 조건에서 폭 두 줄만 다름 | 학습 설정의 차이 · 에피소드 초기 위치까지 같지는 않음 |

그러므로 `f3d5ab2` 의 뜻을 **「144칸을 채운 당시 발행 묶음」으로 한정**한다.
그때 문서는 **고정 스냅샷**이고, 정정된 설명은 **현재 문서로 따로 연결**한다.
한 카드가 둘을 함께 가리킨다.

함께 정할 셋.

| 무엇 | 정하는 값 |
|---|---|
| `release_revision` 과 기준 커밋의 관계 | `v1` 은 **배포 묶음 이름**, `v1.1` 은 **원장 개정 번호**. 서로 다른 축이다 |
| `lab_commit` | `f3d5ab2` 시점 site 를 만든 입력 lab SHA. 빌드 기록에서 읽어 박는다 |
| `published_at` | **배포 완료 시각**. 커밋 시각과 다르면 둘 다 적는다 |

**기준 시점 선언만으로 고쳐지는 오류는 0줄이다.** 산술·규격 귀속·센서 설명은
따로 고쳐야 한다. 정본에 **107줄**이 남아 있다.

### 3-3. 지형 보드의 자료를 바꾼다

| 턱 `rails` | 8 | **48** | 절반 |

10종 평균은 기준 정책 **50.5 %** · foothold-v1 **84.7 %** 다. 성적표·곡선과
소수 첫째 자리까지 일치한다.

`parse_csv()` 는 지형 하나에 결과 하나를 담는 구조라 **모델 둘을 섞으면
덮어쓴다.** 모델별로 나눈 구조로 바꾼다 (7절 함수표).

### 4-1. 한 문서는 레코드 하나 · 배포는 참조만 한다

정본과 보고서가 **입구**와 **배포 묶음**에 함께 나오는 것은 중복이 아니다.
입구는 «문서의 기능», 배포 묶음은 «특정 배포와의 관계»다. 다만 규칙을 박는다.

| 규칙 | 내용 |
|---|---|
| 레코드 | 문서 하나에 **ID 하나**. 목록 40개에 같은 ID 를 두 번 넣지 않는다 |
| 배포 묶음 | `report_id` · `current_explanation_id` · `attention_ids` 는 **ID 참조**다 |
| 건수 | 「40개」를 셀 때 배포 묶음 링크를 **더하지 않는다** |
| 관계 표시 | 참조마다 관계 이름을 적는다 (`이 배포의 성적표` · `그때 발행본` · `정정된 설명`) |

### 4-2. 거르개의 동작을 정의한다

v2.0 은 「정의한다」고만 적었다. 정한다.

| 항목 | 값 |
|---|---|
| 축 | 기능 (여섯 입구) · 출처 · 확실성 · 지형 · 배포 |
| 같은 축 안 | **OR** (「진단」 또는 「계획」) |
| 다른 축 사이 | **AND** (「진단」이면서 「실측」) |
| 선택 | 여러 개 |
| 주소 | `?fn=diagnosis,plan&src=measured` · 값은 영문 slug |
| 뒤로 가기 | `history.pushState` · 복원 시 선택과 스크롤을 되살린다 |
| 빈 결과 | 「이 조건에 맞는 문서가 없습니다」 + **해제 단추** · 목록을 숨기지 않는다 |
| 초기화 | 단추 하나로 전체 해제 · 주소도 비운다 |
| 건수 | 단추마다 현재 조건에서의 건수를 띄운다 (0 이면 흐리게 · 누를 수는 있다) |

## 6. 핵심 수치와 썸네일

### 6-1. 수치는 자동이지만 «뽑을 것이 없어서» 빈 것이 아니다

`num_in()` 의 실제 동작은 이렇다.

| 항목 | 지금 |
|---|---|
| 입력 | `meta()` 가 문서 앞 **2,500자**에서 읽은 `> 결론:` 과 `> 요지:` **뿐** |
| 안 읽는 것 | 본문 `## 결론` · 표 · 제목 · `> 근거:` 줄 |
| 규칙 | 숫자 뒤에 `%` `초` `종` `개` `배` `시간` `fps` 가 붙은 **첫 표현 하나** |

함수를 단독으로 불러 확인했다.

| 입력 | 지금 반환 | 무엇이 틀렸나 |
|---|---|---|
| `3,200개` | `200개` | 쉼표에서 끊긴다 |
| `-0.5%` | `0.5%` | 부호가 사라진다 |
| `10종 중 5종` | `10종` | 뒤 값이 요지인데 앞을 집는다 |
| `13.94` | 빈 값 | 단위가 없다 |
| `0.4~0.6 m/s` | 빈 값 | 범위와 복합 단위를 모른다 |

**그러니 「9개는 뽑을 것이 없었다」는 틀렸다.** 원문에 숫자가 있다.

| 문서 | 못 뽑은 직접 원인 | 원문에 있는 값 |
|---|---|---|
| `visual-evidence` | `13.94` 가 단위 없는 보상값 | 학습 시간 · 보상 · 에피소드 길이 |
| `benchmark-repro-protocol` | 요지에 숫자 없음 · 본문 안 읽음 | 체크포인트 · 환경 · 판정 조건 |
| `benchmark-setup-lim` | 요지에 숫자 없음 | **10개 지형 · 50 에피소드** |
| `compute-resources` | 요지에 숫자 없음 | **133분** · 하루 4~5회 |
| `20260903-default-1500iter-terrain-analysis` | `1500 iteration` 이 허용 단위 아님 | **600회** · 지형별 성공률 |
| `20260903-rails-isaac-sweep-design` | `열 칸·셋·여덟 칸` 은 한글 수사 | **3/10 에서 8/10** |
| `20260903-render-blackframe` | 요지에 숫자 없음 · `## 결론` 안 읽음 | **결함 판 5/10 에서 0/10** |
| `20260909-head-contact-observation` | `20판` `1,735 N` `846 N` 이 허용 단위 아님 | 전부 요지 6줄에 있다 |
| `NVIDIA공식체크포인트_속도단차교차평가분석` | 요지에 숫자 없음 · `> 근거:` 안 읽음 | **16조합 · 3,200 에피소드** |

**단위 몇 개를 더하는 것으로는 안 된다.** 「뽑기 규칙을 넓힌다」의 뜻을 다섯으로 박는다.

| | 무엇 |
|---|---|
| 1 | **수 표현** · 쉼표 · 부호 · 범위 · 분수 (`3/10`) · 복합 단위 (`m/s`) 를 온전히 읽는다 |
| 2 | **후보 출처** · 머리말 밖에서는 **원장이 지정한 절·표의 행/열·CSV 조건**만 읽는다. 문서 전체의 첫 숫자를 집지 않는다 |
| 3 | **의미 보존** · 값과 함께 지표명 · 단위 · 모델 · 지형 · 속도 · 난이도 · 규격 · 분모 · 원자료 위치를 반환한다 |
| 4 | **선택 계약** · 후보가 여럿이면 무엇이 대표값인지 원장이 고른다. 스윕 설계는 `1500판` 보다 `유효 학습 칸 3/10 에서 8/10` 이 요지다 |
| 5 | **실패 계약** · 선택자가 깨지면 **경고 또는 빌드 실패**로 알린다. 「수치 없는 문서」로 숨기지 않는다 |

`metric_selector` 의 형식도 정한다.

```
metric_selector:
  kind      heading | table | csv | literal
  locate    절 제목 · 표 제목 + 행/열 이름 · CSV 경로 + 조건
  filter    model · terrain · speed · difficulty · spec
  reduce    value | rate | delta | ratio
  unit      % | m | s | N | 판 | 종 | 배
  denom     분모 (있으면)
  label     카드에 쓸 짧은 이름
  on_fail   warn | error
```

우선순위는 셋이다.

```
1. 원장의 metric_selector
2. num_in() 이 넓힌 규칙으로 뽑은 값
3. 둘 다 없으면 그 자리를 비운다 (가운뎃점도 안 넣는다)
```

### 6-2. 썸네일 · 「첫 그림」은 선택 규칙이 아니다

40개를 전수로 훑은 결과다.

| 분류 | 수 |
|---|---:|
| 원장이 골라야 하는 것 | **5** |
| 첫 그림으로 되는 것 | **6** |
| 본문에 시각 자료가 없는 것 | **29** |

원장이 필요한 다섯과 그 까닭.

| 문서 | 왜 | 무엇을 골라야 하나 |
|---|---|---|
| `visual-evidence` | 첫 그림이 **Unitree 공식 홍보 영상의 참고 그림**이다. 자체 실측 카드에 쓰면 출처를 오해한다 | 자체 정책 장면 |
| `20260903-render-blackframe` | 이미지가 **일반 링크**로만 있어 이미지 문법 검색에 안 걸린다 | `frame_000.png` 등 · site 쪽 자산 복사 필요 |
| `20260903-default-1500iter-terrain-analysis` | markdown 에는 이미지 문법이 없는데 **웹 본문에는 실험 분기 SVG** 가 있다 | 그 SVG · 생성·자산화 경로 필요 |
| `generalization-benchmark-10-terrains` | 첫 그림 문법부터 **MP4** 다. 열 영상 모두 포스터가 없다 | 대표 지형 영상 + 포스터 |
| `report-v1` | markdown 이 없는 **생성 보고서**다. 차트 SVG 와 영상이 있다 | 생성 보고서용 선택자 |

「첫 그림이 장식」인 문서는 **1개**(`visual-evidence`)다. 무의미한 장식은
아니지만 출처를 오해하게 하므로 예외로 다룬다.

그래서 규칙을 **선택**과 **형식 처리**로 가른다.

```
[선택]  1. 원장의 thumbnail_selection      (사람이 고른 것이 먼저)
        2. 원문의 첫 미디어 후보           (이미지 문법 · 일반 링크 · 생성 SVG 모두)
        3. 없으면 자리를 비운다            (회색 상자를 안 넣는다)

[형식]  이미지  그대로 쓴다
        SVG     페이지 토큰을 쓰면 외부 img 로 못 넣는다.
                본문에 인라인하거나 토큰을 값으로 굳혀 자산으로 굽는다
        영상    manifest 의 포스터를 읽는다 (gallery_manifest.py:371~386).
                포스터가 없으면 make_posters.py 로 굽고 manifest 에 넣는다
        외부    호스트가 우리 것이 아니면 쓰지 않는다
```

**치수와 자름도 정한다.** 지금은 `object-fit:cover` 로 복합 차트를 잘라
판독이 안 되는 것이 있다.

| 그림 종류 | 처리 |
|---|---|
| 도해 · 차트 (글자가 있는 것) | `contain` · 배경은 카드 색 |
| 장면 사진 · 영상 포스터 | `cover` |
| 썸네일 치수 | PC 112 x 64 CSS px · 2배 자산 · 모바일은 지금대로 숨김 |

### 8-1. `_lab-main` 은 수동이다 · 강제 초기화를 그냥 돌리지 않는다

`docs_pages.py:41~55` 가 `_lab-main` 을 `foothold-lab` 보다 먼저 고르는 것은
**결함이 아니라 설계**다.

> `foothold-lab` 은 여러 세션이 함께 쓰는 작업 디렉터리라 브랜치가 수시로
> 바뀐다. 빌드가 그것을 읽으면 같은 소스로 돌려도 산출물이 달라진다.
> `_lab-main` 은 `origin/main` 에 고정된 별도 워크트리다.

주석에는 운영자가 실행할 `fetch` 와 `reset --hard origin/main` 이 적혀 있다.
**그대로 돌리면 안 된다.** 지금 `_lab-main` 에는 `doc-graph.json` 과
`versions.json` 변경이 있고, 이 둘은 **일반 빌드가 갱신하는 파생물**이다.

| 규칙 | 내용 |
|---|---|
| 대상 | `origin/main` 이 아니라 **승인된 정확한 lab SHA** |
| 절차 | `git -C _lab-main status --short` 로 목록을 **먼저 본다**. 파생물 밖 변경이 있으면 **중단하고 보고**. 없으면 그 SHA 로 맞춘다 |
| 책임 | 이 세션이 한다. 자동화하지 않는다 (커널 「청소 목적의 되돌릴 수 없는 명령 금지」) |
| 검증 | 맞춘 뒤 `git -C _lab-main rev-parse HEAD` 가 승인 SHA 와 같은지 **출력해 확인** |

### 8-2. 생성 입력과 검사 입력이 다르다

**본문은 `_lab-main` 에서 만드는데 메타데이터 관문은 `foothold-lab/docs` 를
직접 본다** (`build.py:264~265·668~674`). 만든 것과 검사한 것이 다를 수 있다.

**같은 lab SHA 에서 읽도록 맞춘다.** 원장 · 본문 · 메타데이터 · 그림 · 보고서
전부 한 입력이어야 한다.

### 8-3. 순서 · 빠진 여섯 단계를 채운다

```
 1. foothold-lab 에서 원장·생성기 작업 · 지역 검사
 2. lab PR 검토·머지 · 입력 SHA 확정                   (v2.0 에 없었다)
 3. _lab-main 을 그 SHA 로 · 8-1 규칙                  (v2.0 은 자동인 줄 알았다)
 4. MAI_UNIVERSE 코드 수정 · 대응 SHA 확정             (v2.0 에 없었다)
 5. 별도 생성기를 돌린다                               (v2.0 에 없었다)
      tools/md2site.py                 정본 웹판
      sim/eval/report/make_report.py   보고서
      sim/eval/gallery_versions.py     갤러리 색인
 6. 사이트 빌드
      python _build/build.py --check --verify --skip-secure
 7. 같은 입력으로 검사 · 8-2                           (v2.0 에 없었다)
 8. site diff 검토 · 커밋 · push
 9. 실제 배포 확인 · 파일이 생긴 것은 배포가 아니다     (v2.0 에 없었다)
10. 이관 전후 대조 (표지 문서 목록 · 갤러리 판 목록)    (v2.0 에 없었다)
```

`--check` 는 생성원과 복사본을 비교하고, `--verify` 는 외부 사실 관문을
돌린다. `--skip-secure` 는 **암호화 자료를 바꾸지 않는 작업**에서 기존 암호화
자산을 유지하며 공개 껍데기만 다시 굽는다. 암호화 자료 자체를 갱신하는
작업에는 **쓰면 안 된다.** 이번 작업은 안 바꾸므로 쓴다.

보고서 감사는 생성본과 site 복사본의 **바이트 일치**를 검사한다
(`make_report.py:81~105` · `audit.py:829~835`). 그래서 **생성 · 배치 · 최종
감사** 차례를 지킨다.

### 8-4. 실패하면 어디로 돌아가나

**자동 복구가 없다.** `build.py` 는 site 로 복사한 **뒤에도** 검사를 돌리고,
복사 과정이 자산 교체와 오래된 HTML 삭제까지 한다 (`145~185` · `650~674`).
후반 실패면 로컬 site 에 **실패한 생성물이 남는다.**

| 언제 실패 | 어디로 |
|---|---|
| 배포 전 (6~7단계) | **직전 검수 통과 소스 조합**에서 다시 생성. `f3d5ab2` 가 아니다 |
| 배포 후 (9단계) | **직전 통과 site 배포**를 복구한 뒤 소스를 고친다 |
| `_lab-main` 이 더러움 | 3단계에서 중단 · 보고. 강제로 밀지 않는다 |
