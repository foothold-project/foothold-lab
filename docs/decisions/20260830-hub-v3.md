## 1. 허브 여섯의 뼈대 (팀장 컨펌 2026-08-30)

| 허브 | 지배 축 | 뼈대 | 유입 (머리말이 정한다) |
|---|---|---|---|
| 일정 | 시간 | 이번 주 -> 관문 다섯 -> WBS·기록 | 관문 · 상태 · 담당 / `[주간]` 이슈 최신 주차 |
| 연구 | 근거 출처 | 출발선 -> 잰 것(본PoC 먼저) -> 읽은 것 | 근거 · 활동 · 갈래 · 요지의 숫자 |
| 회의 | 시간 · 자리 | 타임라인 + 자리 필터 칩 | 자리 · 요지 |
| 기획 | 안이냐 밖이냐 | 밖 3 크게 · 안 3 줄 | 손 등록 (여섯 장뿐) |
| 기술 | 배우는 순서 | 01->02->03 경로 | «차례» (신설) |
| 파이프라인 | 언제 보나 | 합류 -> 매일 -> 투고 세 절 | «언제 보나» (신설) |

세부 (팀장 지시 그대로):

- 표지 허브 타일은 PC에서 **3열×2행**. 타일은 장수 대신 **상태 한 줄**
  (코드가 계산한다 · 산문 금지).
- 관문 다섯은 **같은 골격·같은 크기**. 급함은 색과 위치로만 말한다.
- 회의는 타임라인을 유지하되 **자리 필터**(전체·팀내부·멘토링·운영진·조선대)를
  얹는다. 자리별로 페이지를 쪼개지 않는다. 시간이 척추, 자리는 렌즈다.
- 연구 「잰 것」 안에서 **본PoC가 먼저**, 파이프라인점검·운영이 뒤.
  활동·갈래는 작은 칩 (갈래 표기는 ROLES.md 그대로).
- 표지의 「연구 기록」 절은 없앤다 (연구 허브·최근과 삼중 겹침).

## 2. 머리말 필드 결정

| 결정 | 내용 |
|---|---|
| 상태 어휘 | 표준을 **초안 · 검토중 · 대기 · 확정 · 폐기** 로 확장. 산출물 5장이 이미 «대기»를 쓰고 있고, 어휘가 실사용을 따른다 |
| «언제 보나» 신설 | 운영·가이드 문서용. 값: 합류 \| 매일 \| 투고. 파이프라인 허브의 절을 정한다 |
| «차례» 신설 | 기술 문서용. 값: 01, 02, … 기술 경로의 자리를 정한다 |
| «결론» 신설 | 실측 문서용 (선택). 화면의 알맹이는 제목이 아니라 결론 문장이다. 연구 출발선이 이것을 크게 싣는다 |
| 「이 글이 선 자리」 제거 | 문서 상단 블록을 뺀다. 관계표는 화면 뒤(순서·출발선·노출 기준)에서만 쓴다. 그래프 시각화는 나중 일 |

## 3. 함께 기록하는 것 (증발 방지)

- **WBS·주간 목표·개인 목표는 GitHub 프로젝트 보드를 활용한다** (팀장 결정,
  구두로만 있던 것을 여기 처음 적는다). 일정 허브 「이번 주」 절은 `[주간]`
  이슈에서 자동 생성하고 보드로 링크한다.
- **관문 이름의 정본은 `deliverables_docs`** («MVP 중간발표 · 9월 30일» 형).
  LEDGER의 «MVP 9/30» 은 축약 표기로 허용하되 새 문서는 정본 표기를 쓴다.
- wiki 흡수(#72) 매핑: rl·nav·cv·ros2 -> 기술 허브 («차례»), learn·curriculum ->
  본사이트 커리큘럼과 병합(중복 대조), links -> 도구 백과(#6) 재료,
  index의 계획·역할 -> 흡수 안 함 (ROLES.md가 정본).
