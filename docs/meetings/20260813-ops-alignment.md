# 8/13 운영 미팅: 기획과 제시안이 갈라진 날

## 그날 무슨 일이었나

방문·OT 당일에 팀 안 기획과 운영진·멘토 쪽 제시안이 한 테이블에서 부딪혔다. 한 줄로 쓰면 **시뮬·강화·험지** 대 **ROS·SLAM**, 그리고 Edu에 커스텀 정책을 심을 수 있느냐였다.

팀이 가져간 그림은 미경험 험지, Isaac과 체크포인트, 시뮬 MVP, SLAM은 메인이 아니라는 쪽이었다. 제시안은 ROS에서 매핑으로 가고 Nav2로 닫으며, 험지 보행은 빼고, 내장 보행 위에 자율주행을 올리자는 쪽이었다.

권한은 분명했다. **주제는 팀이 정한다.** 험지와 시뮬로 역제안할 수 있다. 다만 기계와 멘토링 경로의 제약이 있어서, 원하는 그림을 그대로 우격다짐할 수는 없었다.

## 확인된 제약 : 왜 갈렸는가

Edu는 고수준 제어다. 저수준 관절 정책을 그대로 이식하는 일은 불가에 가깝다고 정리됐다. 내장 보행이 이미 강해서, 실기에서 험지 RL을 보여 임팩트를 내기도 어렵다. 보드가 Orin NX 16GB라 무거운 SLAM·인식은 로봇 안이 아니라 외부 PC 수준으로 보는 게 맞다.

멘토링은 주 2~3시간이고, 제공 경로는 ROS·SLAM 정석이다. 그 시간을 개발 공수로 쓰면 안 된다. 실기 슬롯은 검증용이다.

이 제약 때문에 「Edu에 우리 정책을 심고 실기 험지로 증명한다」는 한 줄은 당일 성립하지 않았다. 대신 키워드와 시뮬 메인, 실기의 역할을 다시 갈랐다.

## 당일 충돌을 표로

| | 팀 기획 | 당일 제시안 |
|---|---|---|
| 무대 | 미경험 험지 · Isaac · 체크포인트 · 시뮬 MVP | ROS → 매핑 → Nav2 |
| SLAM | 비메인 | 메인 경로 |
| 보행 | 험지 적응(시뮬) | 험지 보행 배제, 내장 보행 + 자율주행 |
| 정책 | 시뮬에서 학습 | Edu 이식은 사실상 불가 |

## 그날 고정한 것

| # | 내용 | 왜 |
|---|---|---|
| 1 | 키워드: **미경험 험지 · 사족보행 · 시뮬** | 제시안의 항법 서사와 구분되는 팀 과제 정의 |
| 2 | 시뮬 = **Isaac 메인**, MuJoCo는 보조 | 학습·체크포인트 경로를 Isaac에 둔다 |
| 3 | 실기 = **단차 코스 측정**. 정책 이식 없음 | Edu 이식이 안 되므로 실기는 측정·검증 슬롯 |
| 4 | 멘토링 = ROS·연결. SLAM을 12월 메인에서 빼 달라고 요청 | 제공 경로는 ROS·SLAM 정석이나, 과제의 메인은 험지·시뮬 |
| 5 | 장비 **A안 우선**. B안은 저수준·비용 확인 후 | B를 사양도 보기 전에 확정하지 않는다 |
| 6 | 실기 주 2~3시간 = **개발 시간이 아니라 검증 슬롯** | 멘토링 시간을 구현 공수로 쓰면 안 된다 |

운영진에는 단차 험지 KPI 한 문장, SLAM 비메인, A/B를 한 장으로 전달하기로 했다. Isaac에는 체크포인트와 단차 시나리오를 붙인다. 주 1회 실기·멘토링 요일·장소는 A안 기준으로 고정한다.

## 하지 말 것 (당일 합의)

- Edu에 커스텀 RL 정책을 이식하지 않는다
- SLAM·Nav2를 12월 메인 산출물로 두지 않는다
- 실기 주 2~3시간을 개발 시간으로 쓰지 않는다
- B안을 사양 확인 전에 확정하지 않는다
