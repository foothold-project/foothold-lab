## 왜 이런 일이 나나

```
     8/23  여러분이 브랜치를 땄다
             │
             │   ← 이 사이 main 에 12개 커밋이 쌓였다
             │      (회의록 복원 · 문서 표준 · 자동화 수정)
             │
     8/26  PR 을 올렸다
             │
             └─► AI 는 «8/23 의 저장소» 만 보고 작업했다
                 그래서 그 뒤에 생긴 것을 모르고 덮으려 했다
```

**AI 잘못이 아닙니다.** AI 는 여러분이 준 저장소 상태만 봅니다.
**오래된 상태를 주면 오래된 답을 냅니다.**

## 새로 생긴 것 · `AGENTS.md`

지금까지 규칙은 **웹페이지(자동화 지도)에만** 있었습니다.
그런데 **여러분의 AI 는 그 웹페이지를 보지 않습니다.**

그래서 저장소 맨 위에 **`AGENTS.md`** 를 두었습니다.
**Cursor 와 Codex 가 작업 시작할 때 자동으로 읽는 파일**입니다.
Claude Code 를 쓰시면 `CLAUDE.md` 를 읽는데, 그것도 같은 곳을 가리킵니다.

**여러분이 따로 하실 일은 없습니다.** 저장소를 열면 AI 가 알아서 읽습니다.
다만 **`git pull` 을 해야 그 파일이 여러분 컴퓨터에 생깁니다.**

**개인 구역이 있습니다.** `AGENTS.md` 맨 아래 9절에 각자 작업 방식을 덧붙이셔도 됩니다.
사람마다 도구도 습관도 다릅니다. **공통 규칙만 덮어쓰지 않으면 됩니다.**

## 어디에 쓰는가 (가장 자주 어기는 것)

```
  inbox/<내이름>/     ← 팀원이 만든 모든 것. 형식 자유. 다듬지 않아도 됨
                         PR 올리면 검토 없이 바로 머지됩니다

  docs/               ← 정리된 정본. 팀장이 승격합니다
                         ★ 직접 고치지 마세요. 남의 작업이 사라집니다

  .github/            ← 자동화. 팀장 담당
```

**`inbox/` 아래만 있는 PR** 은 바로 머지됩니다.
**`docs/` 나 루트 파일이 섞인 PR** 은 팀장 검토 후에 머지됩니다.

고칠 것이 보이면 **이슈로 알리거나 `inbox/` 에 수정안**을 올려 주세요.
직접 고치는 것보다 그게 빠릅니다.

## 문서를 올릴 때 · 머리 네 줄

`docs/` 로 올라갈 문서는 맨 위에 이것이 필요합니다.
**`inbox/` 에는 없어도 됩니다.** 달아 두시면 그대로 승격되니 편합니다.

```
> 분류: 리서치
> 작성: 홍길동 · 2026-08-26
> 근거: 공식 문서
> 요지: 한 줄로 이 문서가 말하는 것
```

**분류는 여덟 중 하나입니다.**
`회의록` `리서치` `실험` `계획` `결정` `운영` `현장` `가이드`

**내용과 분류가 맞아야 합니다.**
본인 학습 계획을 「회의록」으로 올리면 회의가 아닌 것이 회의 목록에 섞입니다.
그건 「계획」입니다. 실제로 그런 일이 있었고, 옮기는 데 시간이 들었습니다.

## AI 가 거의 확실하게 걸리는 것

**긴 줄표(em dash).** AI 가 습관처럼 씁니다. **우리 빌드는 이걸로 배포를 멈춥니다.**
`·` 나 마침표로 바꿔 달라고 하시면 됩니다.

**선으로 그린 글자 도식.** 표로 바꿔야 합니다.

**근거 표기 없는 단정.** 주장에는 `확인됨` · `추측` · `미확인` · `미측정` 을 답니다.
**재보지 않은 것에 「확인했다」를 쓰지 않는 것**이 이 팀 문서의 핵심입니다.
