**무엇이 들어 있나**

여러분이 올린 것이 어디로 가고, 무엇이 저절로 일어나고, 어디서 사람이 필요한지를 한 장으로 그렸습니다. **초록은 여러분이 하는 일, 파랑은 자동, 주황은 팀장 판단**입니다.

특히 아래 두 가지는 **읽어두시면 시간을 아낍니다.**

**«AI 에게 시킬 때 걸리는 것»**  AI로 작업하실 때 거의 확실하게 걸리는 것들을 정리했습니다. 가장 흔한 건 **긴 줄표(em dash)** 입니다. AI가 습관적으로 쓰는데 우리 빌드는 그걸로 배포를 멈춥니다. **«AI에게 붙여넣을 규칙 블록»** 을 그대로 복사해 쓰시면 이런 사고가 대부분 사라집니다.

**«실수로 main 에 push 했다면»**  일어나는 일입니다. 당황해서 `--force` 로 되돌리려다 남의 작업을 지우는 것이 진짜 사고입니다. **혼나는 자리가 아니니 빨리 알려주시면 됩니다.**

---

**inbox 제출 기준을 정했습니다**

**최소 규칙만 맞으면 됩니다.** 잘 만들어 오셨으면 그대로 올라갑니다.

| 최소 규칙 |
| --- |
| 본인 폴더 `inbox/본인폴더/` 에 넣기 |
| 개인정보 넣지 않기 (공개 사이트로 나갑니다) |
| 긴 줄표 · 글자로 그린 도식 쓰지 않기 |
| 확인한 것과 추측을 구분하기 |

**부족한 것이 있어도 여러분의 글을 마음대로 고치지 않습니다.** 대신 같은 PR에 **«보완» 커밋을 따로** 올리고 팀장이 확인합니다. 어디까지가 본인이 쓴 것인지 남아야 하기 때문입니다. 여러분 이름으로 나가는 글입니다.

팀장 피드백은 PR 코멘트로 남습니다. 여러분도 보실 수 있습니다.

---

**브랜치는 기존 규약 그대로입니다**

`feature/작업명-이름` (예: `feature/terrain-lim`). **이슈 번호는 넣지 않습니다.**

다만 **커밋이나 PR 본문의 `Closes #번호`** 는 반드시 넣어주세요. 이 한 줄이 있어야 이슈가 닫히고 보드가 움직이고 알림이 나갑니다. **빠뜨리면 자동화가 통째로 안 걸립니다.**
