📢 **이제 진짜로 올릴 수 있습니다: 시작 가이드** (2026-08-13)

전원에게 lab·rl **쓰기 권한**을 열었습니다. 아래 순서 그대로 하면 됩니다.

**1. 처음 한 번: 클론**
```
git clone https://github.com/foothold-project/foothold-lab.git
git clone https://github.com/foothold-project/foothold-rl.git
```

**2. 작업 시작 전: 항상 최신으로 맞추고 브랜치를 만든다**
```
git pull origin main
git checkout -b feature/작업명-이름
```
브랜치 이름 예시: `feature/terrain-lim` `feature/eval-csv-lee` `inbox-meang`
(작업명은 영어 짧게, 끝에 자기 이름. main 에는 직접 push 하지 않습니다. 팀장만 합니다)

**3. 이슈 = 작업 선언입니다**
순서는 이렇습니다.
- 작업 시작 전에 이슈를 만듭니다. «나 이거 진행합니다» 선언입니다.
  템플릿은 간단해졌습니다: **큰 칸 하나 쓰고, 갈래 하나 클릭**하면 끝.
- 만들면 자동으로: 보드 등록 + 날짜 + 담당자(본인) + 갈래 부모에 연결 + 디스코드 알림.
- 작업이 끝나면 **결과를 이슈에 코멘트로** 남기고 닫습니다.
  코드였다면 PR 설명에 `Closes #번호` 를 쓰면 머지될 때 자동으로 닫힙니다.
- 닫히면 자동으로: 보드 Done + 실적 날짜 기록 + 완료 알림.

**4. 올리기**
```
git add .
git commit -m "한 일 요약"
git push -u origin feature/작업명-이름
```
push 하면 GitHub 에 «Compare & pull request» 버튼이 뜹니다. 누르면 끝.
inbox 제출 PR 은 팀장이 검토 없이 바로 머지합니다.

**어디에 무엇을 올리나**
- 다듬지 않은 메모·측정 로그 → lab 의 `inbox/자기폴더/`
- 코드·실험 → rl (feature 브랜치 → PR)
- 웹사이트(foothold-site)와 brand 는 직접 수정하지 않습니다 (자동 빌드가 관리)

**막히면**: 이슈 «막힘·오류» 템플릿에 에러 메시지를 통째로 붙여넣으세요. 정리 안 해도 됩니다.
질문은 #foothold-general 로.
