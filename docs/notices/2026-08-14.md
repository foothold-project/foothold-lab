📢 **현장 확인: 저수준 제어가 이 프로젝트의 관문입니다** (2026-08-14)

Go2 실기를 만지게 되면 **가장 먼저 확인해야 할 것**을 정리했습니다.
전체 목록: <https://foothold-project.vercel.app/field-check-0813.html>

**왜 이게 먼저인가**

우리 정책은 관절 12개에 목표각을 **50Hz 로 직접** 쏘는 방식입니다.
그런데 Go2 에는 순정 컨트롤러(스포츠 모드, MCF)가 이미 관절을 잡고 있습니다.
**둘은 동시에 못 켭니다.** 순정을 비켜 세울 수 없는 개체라면 학습을 아무리 잘해도 실기에 못 올립니다.
그래서 이건 «나중에 볼 것» 이 아니라 **프로젝트 성립 조건**입니다.

**관문 3단계 (순서대로, 앞이 안 되면 뒤는 의미 없음)**
```
⑤ 질문   "이 개체에서 unitree_sdk2 low-level 예제를 돌려본 적 있나?"   로봇 안 움직임
⑥ 읽기   랜선 연결 → lowstate(관절각·IMU·발힘)가 수신되는지만 확인    로봇 안 움직임
⑦ 확정   엎드린 자세 → MotionSwitcher 로 스포츠 모드 해제
         → LowCmd 로 관절 1개 미세 명령                              관절 1개 소폭
```
⑦까지 되면 **우리 정책의 실기 탑재가 물리적으로 가능한 개체**입니다.
⑥에서 끊기면 저수준이 닫힌 개체이니 트림·펌웨어를 다시 확인해야 합니다.
**⑦은 로봇이 실제로 움직입니다. 반드시 관리자 허락 후 진행하세요.**

**그 전에 눈으로 5초**
- **EDU 모델인가**: AIR/PRO 는 RJ45 이더넷 포트 자체가 없어 **시작조차 불가**합니다.
- 몸통 측면·후면 **RJ45 포트 실물 확인 + 사진**. 유선 연결이 통신 설정의 전제입니다.

**현장 5분 테스트 (SSH · ROS2 환경이 있다면)**

이건 다른 질문에 답하는 테스트입니다. **«발밑 지형 정보를 저수준에서도 받을 수 있는가»**
```bash
# ① 스포츠 모드 켜진 상태에서 하이트맵이 나오는가
ros2 topic hz /utlidar/height_map_array

# ② 저수준 제어로 전환한 뒤 같은 명령
#    여기서 0 Hz 가 되면 우리 가설이 실증된다
ros2 topic hz /utlidar/height_map_array
```
```bash
# 관측 항목이 실제로 나오는지
ros2 topic list | grep -i "low\|sport\|imu\|utlidar"
ros2 topic echo /lowstate --once      # imu_state · motor_state · foot_force
```

**이 5분이 왜 값진가**: 0 Hz 가 되면 «저수준에서는 발밑 지형을 못 본다» 가 확정되고,
그러면 **Teacher-Student 증류가 유일한 길**로 정해집니다. 반대로 계속 나오면 증류를 건너뛰는
대안이 열립니다. **한 번의 측정으로 설계 갈림길 하나가 닫힙니다.**

**아직 확정 안 된 것**: `MotionSwitcher` 의 정확한 호출명(`CheckMode`/`SelectMode`/`ReleaseMode` 계열)은
문서상 `부분확인` 입니다. 현장에서 실물로 확인하면 그때 정본이 됩니다.
