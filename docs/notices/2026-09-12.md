## 1. 종합보고서 1차

기준선 NVIDIA · A · foothold-v1 을 **같은 조건**에서 견줬습니다.

<https://foothold-project.vercel.app/report-v1.html>

난이도 0.5 성적표 **14,400 에피소드**가 분모이고, 난이도 곡선까지 합한 전체 원자료는 **43,200 에피소드**입니다. 지형 16종 · 모델 3 · 속도 3 의 144칸이며 칸마다 100 에피소드입니다.

이번 판에 **난이도 곡선**이 들어갔습니다. 지금까지는 난이도 0.5 한 칸만 봤는데, 그 한 칸은 「지금 어느 쪽이 낫나」는 말해 주지만 **어디서 무너지나**는 말해 주지 않습니다. 미경험 험지 10종을 0.1 부터 1.0 까지 열 단으로 쟀습니다.

| 모델 | 난이도 0.1 | 난이도 1.0 |
|---|---|---|
| 기준선 NVIDIA | 76 % | **37 %** |
| A | 89 % | 59 % |
| foothold-v1 | 90 % | **77 %** |

foothold-v1 은 **열 단을 다 올려도 기준선의 가장 쉬운 자리(76 %)보다 높습니다.**

## 2. 평가 영상 갤러리 · 144컷

<https://foothold-project.vercel.app/gallery/>

**평가 칸 144개가 전부 영상을 갖습니다.** 처음 배포 때는 84컷이었고 빈 칸이 60개였는데, baseline 과 A 를 더 찍어 채웠습니다. 대조컷이 96컷입니다.

화면은 **지형으로 묶이고 속도 셋이 세 열**로 섭니다. 지형 머리에 그 지형의 성공률과 험지 참여도가 있고, 비교 모델은 한 줄로 접혀 있어 눌러서 폅니다.

거르개는 지형 · 지형집합 · 속도 · 모델 · 성공률 구간 · 험지 참여도 구간 · 영상 유무 일곱입니다. **고른 조건이 주소에 남아** 링크로 그대로 공유됩니다.

## 3. 3열 비교

<https://foothold-project.vercel.app/gallery/compare/>

같은 지형 · 같은 속도에서 (판, 모델) 세 쌍을 나란히 놓습니다. 한 곳에서 누르면 **셋이 같은 시각 기준으로 함께** 돕니다. 배속은 0.25 ~ 2배입니다.

기본은 `gap` 0.5 m/s 에 **기준선 · A · foothold-v1** 입니다. 판이 쌓이면 **기준선은 고정, 나머지 둘은 최근 두 판**으로 저절로 굴러갑니다 (v2 가 나오면 기준선 · v1 · v2).

**세 열의 길이가 다른 것은 정상입니다.** 해상도 1920x1080 · 초당 50장 · 카메라 시점은 세 열이 같습니다 (시점은 모델이 아니라 지형이 정합니다). 길이만 다른데, 촬영이 「전진 5.0 m 에서 자른다」라 빨리 간 모델은 짧고 못 간 모델은 시간 예산을 다 씁니다. **길이 차이가 곧 성적입니다.** 화면에 그 까닭을 적어 두었습니다.

## 4. 평가 프로토콜 정본

<https://foothold-project.vercel.app/research-20260911-eval-protocol-v2.html>

무엇을 어떤 기준으로 재고, 같은 결과를 어떻게 재현하며, 대표 영상을 어떻게 뽑는지. **수치를 인용하기 전에 여기를 보십시오.**

이번 판에서 **두 문서를 하나로 합쳤습니다.** 배포용 정본과 규격 2 갱신본이 따로 있었고 웹에는 갱신본만 올라가 난이도 스윕 곡선과 높이 스캔 해설이 빠져 있었습니다. 지금은 표 68개 · 그림 13장이 다 들어 있습니다.

읽는 차례는 **1부 지금 규격 · 2부 그 규격이 왜 그렇게 됐나** 입니다. 숫자만 필요하면 1부까지만 읽으시면 됩니다.

## 성적 (난이도 0.5 · 1.0 m/s · 기준선 -> foothold-v1)

| 지형 | 기준선 | foothold-v1 |
|---|---|---|
| gap | 1 % | **100 %** |
| pit | 2 % | **100 %** |
| floating_ring | 0 % | **99 %** |
| rails | 8 % | 48 % |
| stepping_stones | 0 % | **0 %** |

`stepping_stones` 는 세 모델 다 0 % 로 **2차의 첫 과제**입니다. 뛰어야 넘는 지형인데 수직 속도 벌점이 가장 커서, 보상 구조가 다음 용의자입니다.

기존 험지 6종은 **18칸 전부 기준선 이상**입니다. 새 지형을 배우면서 배운 것을 잃지 않았다는 뜻입니다.

## 영상 보는 법

HUD 에 명령 속도 · 실제 속도 · 전진 거리 · 자세가 얹혀 있습니다. 재생기의 배속 단추로 0.25 ~ 2배를 고를 수 있고 파일은 한 벌입니다.

다만 **HUD 의 추종 표시는 전후 오차의 누적 평균**이고, 평가의 속도추종 판정은 전후와 좌우를 합친 평면 오차입니다. **HUD 로 판정을 역산하지 마십시오.**

첫 화면에 깔린 그림은 첫 프레임이 아니라 **지형이 가장 잘 보이는 프레임**입니다. 로봇이 평평한 출발판에서 시작해 첫 프레임에는 지형이 없기 때문입니다.

## 직접 뽑으려면

저장소를 받고 `pip install av` 한 번 뒤

```
python sim/eval/render_gallery.py --checkpoint models/foothold-v1.pt
```

옵션 없이 한 줄이면 같은 한 벌이 나옵니다. 다만 **Isaac 환경의 python** 으로 부르고 환경 변수 둘(`KMP_DUPLICATE_LIB_OK` · `OMNI_KIT_ACCEPT_EULA`)을 채워야 합니다. 안 채우면 촬영이 조용히 다 실패합니다. 자세한 것은 그 파일 머리의 「쓰는 법」에 있습니다.

대조컷까지 다 뽑으려면 모델마다 한 번씩 돌려야 합니다 (`--label baseline` 등).

## 읽을 때 주의할 것

**옆에 적힌 성공률은 그 자리 평가 100 에피소드의 집계이고, 영상은 따로 촬영한 시연 한 판입니다.** 둘은 같은 실행이 아닙니다.

**난이도 축의 뜻이 지형마다 다릅니다.** `floating_ring` 은 난이도가 오르면 고리가 낮아져 장애물의 종류가 바뀌고, `random_rough` 는 난이도를 거의 타지 않습니다. 곡선을 일률적으로 「오를수록 어렵다」로 읽으면 안 됩니다.

**정본 2부의 옛 표는 성적으로 인용하지 마십시오.** 2026-09-10 에 잰 것은 규격이 기록돼 있지 않고, 규격 2 로 다시 잰 값과 공통 150칸 중 40칸이 다릅니다.
