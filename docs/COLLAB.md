# FOOTHOLD 협업 규칙

> **초안 v0.9 — 팀장 컨펌 전.** 컨펌 후 collab.html 로 사이트 게시(구조도는 SVG로 다시 그린다).
> 이 문서는 전부 공개한다. 솔직함은 최대로, **남의 정보(금액·개인사·주소·토큰)만 뺀다.**

## Ⅰ. 왜 이렇게 일하는가 — 원칙 셋

1. **기록이 우리를 증명한다.** 12월에 "누가 뭘 했나"를 기억으로 복원할 수 없다. 지금 남기지 않으면 그때는 없다.
2. **측정 없이 판단하지 않는다.** "잘 되는 것 같다"는 인상이지 기록이 아니다. 숫자를 먼저 잰다.
3. **침묵을 성공으로 착각하지 않는다.** 조용히 넘어간 것은 확인된 것이 아니다. 안 되는 것은 소리를 내게 만든다.

## Ⅲ. 일의 흐름 — 손으로 하는 건 두 가지뿐

**① 시작 = 레포에서 이슈 만들기.** 문서·조사 → lab, 코드·실험 → rl. 템플릿 빈칸을 채운다(특히 "끝났다는 기준").
→ 자동: 보드 등록 · 담당자=나 · 시작일=오늘 · 마감=+7일 · 디스코드 알림.
계획이 다르면(다음 주 시작, 3일짜리 등) **보드에서 날짜를 직접 고친다 — 고치는 게 정상 행위다.**

**② 끝 = 커밋에 `Closes #번호`.**
→ 자동: 이슈 닫힘 · 보드 Done · 완료 알림 · (예정) done date 기록.

**브랜치** — lab: main 직접 커밋 허용(문서), 남의 문서 크게 고칠 땐 PR.
rl: `feature/이슈번호-이름` → `dev` → `main`. main 은 PR로만(룰셋 강제).

**⚠️ 보드에서 `+ Add item` 타이핑 금지** — 초안(draft)이 되어 자동화가 전부 죽는다.
보드 상단 "Create new issue" 버튼은 진짜 이슈라 괜찮다.

## Ⅳ. 문서 규칙

- `docs/research/` 조사 · `docs/meetings/` 회의록 · `docs/ops/` 운영 · 루트 = 기획/규칙
- 파일명 소문자-하이픈, 회의록은 `YYMMDD_제목.md`
- **출처 등급**: 공식 문서 > 교재 > 논문 > 해설 블로그 > 백과. **숫자 인용은 논문·공식만.**
- 확인 못 한 것은 **`미확인`** 이라 쓴다. 미확인을 근거로 판단하지 않는다.
- 웹에 올라가는 문서의 구조도는 **ASCII 금지** — SVG·이미지·표로.

## Ⅴ. 하지 말 것 — 전부 실제 겪었거나 겪을 뻔한 것

1. **체크포인트(.pt)·대용량을 git 에 커밋 금지** — 한 번 들어가면 히스토리에서 못 지운다.
2. **타인 저작물 원문 업로드 금지** — 논문 PDF 추출·블로그 크롤 사본. 비공개 레포여도 금지. 링크로 대신한다.
3. **토큰·웹후크 URL 을 채팅·문서에 붙이지 금지** — 실제로 한 번 유출돼 재발급했다.
4. **site 직접 수정 금지** — 다음 빌드에 덮어써진다.
5. **결과 보고 판정 기준을 바꾸지 금지** — 통과선은 실험 전에 적는다.

## Ⅵ. 새 레포가 필요할 때 — 기준 셋

별도 빌드 체계(예: ROS2 워크스페이스) / 별도 실행 환경(예: 3DGS 도구) / 단독 공개물.
**그 외는 전부 폴더로.** 역할·파트는 레포가 아니라 폴더+담당자로 표현한다.

## Ⅶ. 막혔을 때

30분 룰: 30분 막히면 [막힘 이슈]를 만든다(기대vs실제·재현·환경·로그·해본 것). 혼자 3시간 파는 것이 팀에는 더 비싸다.
같은 에러를 두 번 겪으면 그건 문서감이다 — `docs/ops/` 에 남긴다.

## Ⅷ. 회의 규칙

1. **회의는 무조건 녹음한다.** 시작할 때 한 마디로 고지.
2. 녹음 파일은 NAS `foothold/meetings/` 에 `YYMMDD_제목.m4a`.
3. 전사→보고서는 파이프라인이 만든다(현재 반자동, WS+MOSS 화자분리로 자동화 예정).
4. 보고서의 모든 인용에는 **타임코드**를 단다 — 원문 대조 가능해야 한다.
5. 금액·개인정보가 든 회의록은 **lab(비공개)까지만.** 공개 사이트에 내보내지 않는다.

## Ⅸ. 결정 기록

결정이 나는 순간 **`docs/DECISIONS.md`** 에 한 줄(무엇·왜·출처). 채팅은 휘발이다.
뒤집을 때 지우지 않는다 — 취소선 + 새 행. 미결은 D번호로 관리하고 회의 안건이 된다.

## Ⅹ. 실험 규율 (rl — 팀 공통 규칙이다)

**한 번에 하나만 바꾼다** · **기준선과 대조한다** · **통과선을 먼저 적는다** · 결과는 채택이든 폐기든 **EXPERIMENTS.md 한 줄**.
실험 1회 ≈ 2시간(1,500 iter 실측 113분)임을 알고 계획한다.

## Ⅻ. 용어 — 같은 말을 같은 뜻으로

| 용어 | 뜻 |
|---|---|
| 퀘스트 | 완료 조건이 숫자·산출물로 명확한 작업 단위 (게임 비유에서 채택) |
| 게이트 | 통과 못 하면 다음으로 못 가는 관문 (PoC·MVP·sim2sim) |
| 기준선(baseline) | 비교의 0점 — 기성 체크포인트의 첫 측정값 |
| 증류(distillation) | 잘하는 큰 모델의 행동을 작은 모델이 흉내 내게 하는 학습 |
| sim2sim / sim2real | 다른 시뮬레이터에서 재검증 / 시뮬→실기 이전 |
| 통과율 | 성공 에피소드 ÷ 시도. "성공"의 정의를 먼저 계약한다 |
| 프리미티브 지형 | 기본 도형 조합으로 만든 학습용 지형 — 물리만 정확하면 된다 |
| draft(초안) | 보드에만 있는 가짜 이슈 — 자동화가 안 도는 함정 |
