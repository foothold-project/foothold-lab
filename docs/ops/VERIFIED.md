- 3차: GitHub API 로 커밋 파일 목록을 직접 조회 + **생략 사유를 항상 출력**하게 변경 → 통과.
- ★ 교훈: **조용히 건너뛰는 분기에는 반드시 이유를 출력한다. 침묵은 성공과 구별되지 않는다.**

## 9경로: 이슈 닫힘 → 보드 done date 자동 기입 (08-09 실검증)

- 테스트: 이슈 #7 을 열고 닫아 3회 트리거.
- 1차: "필드 없음 · 생략" 이 **success 로 표시됨** → 로그를 열어보고서야 알았다.
  같은 교훈 재확인: **침묵은 성공과 구별되지 않는다.** → 못 찾으면 실제 필드 목록을 출력하게 수정.
- 2차: 보드에 실제로 `start date`·`end date` 만 있음이 로그로 드러남 (done date 필드 부재).
- 3차: **워크플로가 필드를 직접 생성**(createProjectV2Field)하도록 승급 →
  `done date 필드 생성 완료` → `done date = 2026-08-09 (#7)` **기입 확인.**
- 계획(start/end)은 불변 · 계획 vs 실적 비교가 리뷰의 근거.
- rl 에도 동일 워크플로 배포(보드가 공유라 필드는 이미 존재, 기입만 수행).

## 10경로: site push → 사이트 갱신 알림 (08-11 실검증)

- site 레포에는 알림 워크플로가 **아예 없었다**(lab·rl 에만 있었음). 신설.
- 1차 실패 **403 Forbidden**. 원인을 "org 시크릿이 낡았다"로 잘못 지목해 팀장에게 갱신을 요청했다.
  진짜 원인은 **파이썬 urllib 의 기본 User-Agent 를 Discord(Cloudflare)가 차단**한 것.
  curl 을 쓰는 lab·rl 은 계속 성공했는데 site 만 실패한 것이 단서였다.
  → **교훈: 같은 일을 하는 기존 성공 사례와 먼저 대조한다. 다른 점이 원인이다.**
- 2차: curl 전환 → **HTTP 204 · "전송 확인"** 로그로 검증 완료.
- 파생 수정: `curl -sS` 는 4xx 를 받아도 종료코드 0 이라 **실패가 초록색으로 보인다.**
  lab·rl 알림에도 같은 맹점이 있어 HTTP 코드 검증을 함께 넣었다. 이제 웹훅이 죽으면 빨간 X.
- 부수 확인: lab 알림은 `docs/` 변경만 발송하는 설계대로 동작(생략 시 이유 출력).

## 사고 기록: sub-issue 자동 연결이 재귀 루프를 돌았다 (2026-08-12)

- 무엇이 일어났나: 워크플로가 단계 부모 이슈를 만들면 그 생성이 다시 `opened` 이벤트가 되고,
  부모의 본문에도 단계 문구가 들어 있어 또 부모를 만들었다. 제목이 매번 길어지다가
  **256자 제한에 걸려서야 멈췄다.** 쓰레기 이슈 14건(#10~#23) 발생.
- 왜 못 막았나: "자기가 만든 것에 반응하지 않는다"는 방어를 아예 넣지 않았다.
  이벤트로 도는 자동화의 기본 방어인데 빠뜨렸다.
- 조치
  1. 실행 조건에 두 겹 방어: `github.actor != 'github-actions[bot]'` 이고
     제목이 `[단계]` 로 시작하지 않을 때만 실행.
  2. 단계 추출을 **줄 전체가 단계 문구일 때**로 한정(본문 설명까지 읽어 제목이 길어진 직접 원인).
  3. 쓰레기 14건은 닫고 제목에 [삭제 예정] 표시. 간트 페이지는 [테스트]·[삭제 예정]·[단계] 를 제외.
  4. 차단 후 재검증: 이슈 #24 → 부모 #25 하나만 생성되고 멈춤 확인.
- 함께 드러난 것: 이슈 하나에 여러 워크플로가 동시에 반응하면 **먼저 push 한 쪽에 밀린다.**
  간트 수집이 그렇게 실패했다. pull-rebase 후 재시도 3회를 넣었다.
- 교훈: **이벤트로 도는 자동화는 자기 출력에 다시 반응할 수 있다.** 새 워크플로를 만들 때
  "이 워크플로의 결과가 이 워크플로를 다시 부르는가"를 먼저 묻는다.
