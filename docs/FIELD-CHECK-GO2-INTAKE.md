## 0. 왜 개체마다 다시 확인하나

- **트림이 다르면 시작조차 못 한다**: AIR/PRO는 저수준 2차 개발이 막혀 있고 RJ45 포트 자체가 없다. EDU만 개발용이다.
- **펌웨어·연식이 다르면 결과가 다르다**: 라이다 세대(L1/L2), 스포츠 모드 전환 동작이 개체마다 다를 수 있다.
- 한 개체에서 확인된 것을 다른 개체로 **옮겨 적지 않는다**. 개체별로 실측한다.

## 1. 🔴 신원 확인 (이것부터, 5분)

| # | 확인할 것 | 어떻게 | 왜 |
|---|---|---|---|
| ~~①~~ | ~~트림: EDU 인가?~~ **확정: EDU** ([ROBOT-SPEC](ROBOT-SPEC.md)) | 몸통 측면·후면의 **RJ45 포트 유무** (1차 판별: AIR/PRO 는 없음) + 하판 모델 라벨·시리얼 사진 + 대여 계약서상 모델명 | 저수준 개발의 성립 조건 |
| ~~②~~ | ~~컴퓨팅 보드~~ **확정: Orin NX 16GB** | SSH 후 `cat /etc/nv_tegra_release`, `free -h`, `df -h` (Orin NX/Nano · 메모리 · 저장공간) | 온보드에서 뭘 돌릴 수 있나 |
| ③ | 펌웨어 버전 | Unitree Go 앱 → 장비 정보 | 저수준 API 동작이 펌웨어에 따라 다를 수 있음 |
| ④ | 연식·이력 | 관리자에게: 도입 시기, 고장 이력, 이전 사용 프로젝트 | 상태 파악 |

## 2. 🔴 저수준 개방 실측 (프로젝트의 관문, 3단계)

> 순서대로. 앞 단계가 안 되면 뒤는 의미 없다. **반드시 관리자 허락 후 진행.**

| 단계 | 무엇 | 로봇 움직임 | 허락 부담 |
|---|---|---|---|
| ⑤ 질문 | "이 개체에서 unitree_sdk2 low-level 예제를 돌려본 적 있나? 스포츠 모드 해제가 되던가?" | 없음 | 없음 |
| ⑥ 읽기 | 랜선 연결 → 저수준 상태(lowstate: 관절각·IMU·발힘)가 **수신되는지만** 확인 | 없음 | 낮음 (설정 변경 없음) |
| ⑦ 확정 | 로봇 엎드린 자세 → MotionSwitcher 로 스포츠 모드 해제 → LowCmd 로 관절 1개 미세 명령 | 관절 1개 소폭 | **허락 필수** |

- ⑦까지 되면: 우리 학습 정책의 실기 탑재가 **물리적으로 가능**한 개체다.
- ⑥에서 끊기면: 저수준 인터페이스가 닫힌 개체 (트림·펌웨어 재확인).
- 준비물: 우분투(또는 WSL) 노트북 + 랜선 3~5m + LAN-USB 어댑터.

## 3. 🟠 센서·기구 (사진 필수)

| # | 확인할 것 | 어떻게 |
|---|---|---|

## 부록: 현장 명령 모음

```bash
# 보드 사양
cat /etc/nv_tegra_release
free -h
df -h

# ROS2 환경 (설치되어 있다면)
ls /opt/ros/
ros2 topic list

# 저수준 상태 수신 (읽기 전용)
ros2 topic echo /lowstate --once
ros2 topic hz /utlidar/height_map_array

# 네트워크
ip -br addr
```

> ⚠️ **대여 장비 공통 수칙**: 읽기 먼저, 변경은 허락 후. 설치·업데이트 금지. 원복 가능한 것만 만진다.
