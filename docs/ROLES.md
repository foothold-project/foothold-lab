## 왜 이 문서가 따로 있나

**같은 사실을 세 군데에 손으로 적어 두었다가 한 군데만 고쳤기 때문이다.**

2026-08-27 에 작업 영역을 5갈래에서 **8갈래**로 바꿨다. GitHub 라벨은 바꿨고
`COLLAB.md` 표도 바꿨다. 그런데 **팀 소개 덱과 피치 덱은 그대로였다.**
발표에 쓰는 두 장짜리가 8/13 의 옛 5분야(`PM·Digital Twin` `Policy·RL`
`Scene·Visualization` `Environment·Infra` `Perception·Data`)를 여전히 보여주고 있었다.

원인은 부주의가 아니라 구조다. **손으로 관리하는 마스터가 셋이면 셋 다 고쳐야 하고,
셋 다 고쳤는지 확인해 주는 것이 아무것도 없다.** 커널 철칙 4 와 같은 부류다.

그래서 이 문서를 **정본 하나**로 두고, 나머지는 여기서 **생성**한다.

| 어디 | 무엇을 보여주나 | 어떻게 |
|---|---|---|
| 이 문서 | 8갈래 배치 + 사람별 강점 | **손으로 쓴다. 여기만.** |
| `team-intro` 덱 R&R 장 | 사람별 카드 6장 | 빌드가 이 문서에서 생성 |
| `pitch` 덱 Team 장 | 사람별 카드 6장 | 빌드가 이 문서에서 생성 |
| `COLLAB.md` §3 표 | 갈래별 주·부담당·폴더 | 손으로 쓰되 관문이 이 문서와 대조 |
| GitHub 라벨 `A/` `B/` `C/` | 이슈 분류 | 관문이 이 문서와 대조 |

관문은 `_build/rolecheck.py` (빌드 `[3.9]`). 세 곳이 어긋나면 배포가 선다.

두 트랙(A 시뮬 · B 실기)과 공통(C)으로 갈린다. 트랙의 뜻은 [FLOW](FLOW.md) 참조.

| `A/평가` | 일반화 벤치마크 · 지표 | **오현민** | 맹라현 · 이민우 | `sim/eval/` |

| `B/항법` | ROS 2 · TF · SLAM · Nav2 | **오흥재** | 임석헌 · 이민우 · 오현민 · 맹라현 | `nav/` |

**주담당은 「혼자 한다」가 아니라 「막히면 이 사람에게 묻는다」이다.**
부담당은 리뷰와 대체를 맡는다. 한 사람이 자리를 비워도 갈래가 멈추지 않게 두 명 이상을 둔다.

### 옛 5갈래는 왜 버렸나

## 3. 짚어둘 것 (팀장 확인 필요)

**이민우의 강점과 배치가 어긋나 보인다.**

프로필상 강점은 **웹 풀스택 · 서버 구성·운영**인데, 8갈래에서 인프라는 `C/운영`
(오흥재)으로 갔고 이민우의 주담당은 `C/기록`(회의록·문서)이다.
8/21 역할 합의에서도 이민우는 네 축 모두에서 부담당이었고 주담당 축이 없었다.

이것은 둘 중 하나다.

1. **의도한 배치다.** 문서 축이 실제로 비어 있었고 그것을 맡기기로 했다.
2. **강점이 안 쓰이고 있다.** 그렇다면 `C/운영` 중 인프라 부분을 나누거나
   `A/정책학습`의 실행 파이프라인 쪽을 주담당으로 올리는 편이 낫다.

**추측으로 정하지 않는다.** 팀장이 정하면 이 절을 지우고 §1·§2 에 반영한다.
