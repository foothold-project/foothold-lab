## 1. 왜 이 환경을 쓰는가

`stepping_stones` 지형의 관측 게이트 판정(#67 · #82)을 하려면 Isaac Lab 을 돌릴 GPU 가 필요하다.
개발 노트북은 RTX 3060 6GB / 16GB RAM 이라 Isaac Sim 요구사항에 미달한다 `확인됨`.

2026-08-28 에 FOOTHOLD 팀 계정으로 RunPod 결제를 시작했고, 현재 실험은 RunPod 에서 돌리고 있다 `확인됨`.

> **이것은 확정 결정이 아니다.** 학습 컴퓨팅의 최종 선택(WS · RunPod · A6000)은 `docs/DECISIONS.md` **D6 에서 판단 대기** 상태다. 판단 근거는 "실험 병렬 필요성"이다. 이 문서는 결정 기록이 아니라 **현재 쓰고 있는 환경의 운영 기록**이다.

팀원 각자가 따로 Pod 을 만들면 학습 결과물이 각자 Pod 안에 갇힌다.
**공용 네트워크 볼륨 하나로 결과물을 공유하고, 각자 작업은 개인 폴더에서 하자**는 것이 이 작업의 목적이다.

## 2. 만든 것

### 2-1. 네트워크 볼륨

| 항목 | 값 |
|---|---|
| 이름 | `foothold-shared` |
| 용량 | 30 GB |
| 리전 | EU-RO-1 |
| 요금 | $0.07 / GB / 월 = 월 약 $2.1 `확인됨` |
| 마운트 경로 | **`/data`** |

**다섯 가지 성질을 알고 써야 한다.**

1. **Secure Cloud 에서만 쓸 수 있다** `확인됨`. Pod 용 네트워크 볼륨은 Secure Cloud 전용이다. Community Cloud Pod 에는 붙지 않는다.
   출처: https://docs.runpod.io/storage/network-volumes
2. **리전에 묶인다** `확인됨`. EU-RO-1 에 만들었으므로 Pod 도 EU-RO-1 에서만 띄울 수 있다. GPU 재고도 그 데이터센터 것으로 제한된다.
3. **Pod 배포 시점에만 붙일 수 있다** `확인됨`. 이미 돌고 있는 Pod 에 나중에 붙이지 못한다. 까먹으면 Pod 을 지우고 다시 만들어야 한다.
4. **Pod 수명과 무관하게 남는다** `확인됨` (09-01 실측). Pod `27df3ee78fd8` 에서 만든 `list_envs.log` 가, Pod 을 갈아치운 뒤 새 Pod `3ebc47b29eed` 의 `/data/logs/` 에 그대로 있었다.
5. **여러 Pod 이 동시에 붙을 수 있다** `확인됨` (09-01 실측). 다른 Pod 에서 같은 볼륨을 붙여 정상 동작했다.

> 5번의 단서: **부착이 된다는 것까지만 확인했다.** 두 Pod 이 같은 파일에 동시에 쓸 때의 동작은 `미검증` 이다. 아래 5-2 절의 이름 규칙으로 회피한다.

### 2-2. ★ 마운트 경로 정하기

**이 문서에서 가장 중요한 절이다.** 08-31 에 여기서 막혔다.

RunPod 기본값이 `/workspace` 이고 v1.0 이 그대로 따랐다. 그런데 Isaac Lab 이미지는 **`/workspace` 아래에 Isaac Lab 본체를 담고 있다.** 빈 볼륨을 그 위에 마운트하면 아래 내용이 **가려진다.** 삭제가 아니라 가림이다.

관측된 증상:

```
root@...:/workspace/isaaclab# ls
(아무것도 없음)

root@...:/# mount | grep workspace
mfs#euro-3.runpod.net:9421 on /workspace type fuse

root@...:/# ./isaaclab.sh -p ...
bash: /workspace/isaaclab/_isaac_sim/python.sh: No such file or directory
```

근거 세 겹 `확인됨`:

1. RunPod 공식 문서(스토리지 비교표): 네트워크 볼륨의 Mount path 가 `/workspace (replaces volume disk)`. 본문에도 "Network volumes **replace** the Pod's default volume disk, typically mounted at `/workspace`".
   출처: https://docs.runpod.io/pods/storage/types · https://docs.runpod.io/storage/network-volumes
2. RunPod 블로그: "`/workspace` **is a convention, not a guarantee.** Official templates use it, but community templates are free to mount the volume elsewhere. Before trusting a new template with real work, check where the volume is actually mounted. Then confirm it from inside the Pod with `df -h`."
   출처: https://www.runpod.io/blog/where-did-my-files-go-a-straight-guide-to-runpod-storage
3. Docker 공식 문서(마운트가 무엇을 하는지): "If you bind-mount a directory into a non-empty directory on the container, **the directory's existing contents are obscured by the bind mount.**"
   출처: https://docs.docker.com/engine/storage/bind-mounts/

> 헷갈리기 쉬운 지점: Docker 의 **named volume** 은 빈 볼륨에 이미지 내용을 **복사해 준다.** **bind mount** 는 **가린다.** RunPod 네트워크 볼륨은 뒤쪽으로 동작한다.

**규칙:**

1. 쓰려는 이미지가 어느 경로를 쓰는지 먼저 확인한다. 이미지마다 다르다(2-3 절 표).
2. 마운트 경로는 **이미지가 쓰지 않는 빈 경로**인지 확인한다.
3. 확인한 뒤 **팀 표준인 `/data`** 를 쓴다.

`/data` 가 기술적으로 특별한 것은 아니지만, 팀원끼리 경로가 갈리면 문서와 스크립트가 전부 갈라진다. 표준을 하나로 둔다.

### 2-3. 이미지마다 Isaac Lab 위치가 다르다

`/workspace` 아래인 것은 같지만 **폴더 이름이 다르다.** 확인하지 않고 경로를 외워 쓰면 걸린다.

| 이미지 | Isaac Lab 위치 | 근거 |
|---|---|---|
| `nvcr.io/nvidia/isaac-lab:2.3.2` (NVIDIA 공식 pre-built) | **`/workspace/IsaacLab`** (대문자 I·L) | 공식 문서 `확인됨` |
| 직접 빌드 (`container.py`) | `/workspace/isaaclab` | 공식 문서 `확인됨` |
| 팀 템플릿 `IsaacLab-2.3.2-Go2` | `/workspace/isaaclab` | 09-01 실측 `확인됨` |

공식 pre-built 컨테이너에 대한 문서 원문:

> "In Isaac Lab 2.0 release, we introduced a minimal pre-built container ... The Isaac Lab source code will be available in this container under `/workspace/IsaacLab`. This container is designed for running **headless** only."

출처: https://isaac-sim.github.io/IsaacLab/main/source/deployment/docker.html

> **공식 이미지는 정상이다.** v1.0 이 공식 이미지를 문제 원인처럼 적었던 것은 잘못이다.

#### 쓰지 말 것: `limseokheon/isaaclab-runpod:sim5.1-lab2.3.2`

**설치 누락 문제는 이 이미지 하나에 한정된다** `확인됨`. `/workspace/isaaclab` 에 소스 트리는 있으나 파이썬 패키지 설치가 되어 있지 않다.

```
ModuleNotFoundError: No module named 'isaaclab'
```

`./isaaclab.sh --install` 로 고칠 수는 있다. 다만 설치 결과가 `/isaac-sim` 아래 컨테이너 디스크로 들어가므로 **Stop 할 때마다 사라져 매번 10분씩 다시 깔아야 한다.** 설치가 이미 된 이미지를 쓰는 편이 낫다.

## 3. 두 개의 디스크

Pod 안에서 가장 자주 사고가 나는 지점이다. **v1.0 과 표가 뒤바뀌었으니 주의한다.**

| 경로 | 정체 | Stop | Terminate |
|---|---|---|---|
| **`/data`** | 네트워크 볼륨 30 GB | 남음 | 남음 |
| `/workspace` `/` `/root` `/tmp` | 컨테이너 디스크 50 GB | 사라짐 | 사라짐 |

**남겨야 하는 모든 것은 `/data` 아래에 둔다.** 이 한 줄이 규칙 전부다.
`/workspace` 는 Isaac Lab 이 사는 실행 공간이지 저장 공간이 아니다.

```bash
df -h | grep mfs
```

`mfs#euro-3.runpod.net:9421` 이 **`/data` 에** 붙어 있으면 정상이다. `/workspace` 에 붙어 있으면 잘못 배포한 것이다.

## 4. 접속: 웹 터미널

**브라우저만 있으면 된다. 설치할 것도, 키를 만들 것도 없다** `확인됨`.

1. RunPod 콘솔 → **Pods**
2. 해당 Pod 을 펼치고 **Connect**
3. 터미널이 꺼져 있으면 **Start**, 그다음 **Open Web Terminal**

브라우저에 터미널이 열린다. 이 문서의 명령은 **전부 여기에 그대로 복사해 붙이면 된다.**

출처: https://docs.runpod.io/pods/connect-to-a-pod

> **단, 웹 터미널은 오래 도는 작업에 권장되지 않는다** (공식 문서 표기). 브라우저 탭이 닫히거나 세션이 끊기면 그 터미널에서 돌던 것이 함께 죽는다. **학습처럼 오래 도는 것은 반드시 `tmux` 안에서 돌린다** (8-1 절). tmux 안에 있으면 세션이 끊겨도 Pod 안에서 계속 돈다.

### 접속 직후 확인 4줄

```bash

ls /workspace/isaaclab
ls /data

```

| 줄 | 기대 결과 |

**두 번째 줄이 비어 있으면 거기서 멈춘다.** 마운트 경로를 잘못 잡은 것이므로 그 상태로 진행하면 시간만 쓴다.

## 5. 네트워크 볼륨 사용 규칙

### 5-1. 왜 있는가

**git 에 못 올리는 것을 담는 곳이다.**

팀 규칙상 `.pt` 체크포인트는 저장소에 커밋 금지다(용량 제한 · 히스토리 오염). 그런데 학습 결과물의 본체가 바로 그 `.pt` 다. 코드는 git 으로, **결과물은 이 볼륨으로** 오간다.

### 5-2. 폴더 구조

`<사용자ID>` 는 각자의 짧은 식별자로 바꿔 쓴다.

| 경로 | 무엇을 두나 |
|---|---|
| `/data/shared/checkpoints/` | 학습된 정책 `.pt`. 예: `go2-rough/20260901-<사용자ID>-1500iter.pt` |
| `/data/shared/assets/` | USD · 지형 등 무거운 공유 자산 |
| `/data/shared/setup.sh` | Pod 켤 때마다 실행하는 스크립트 |
| `/data/<사용자ID>/repos/` | 개인 작업 저장소 |
| `/data/<사용자ID>/logs/` | 개인 학습 로그 |
| `/data/<사용자ID>/videos/` | 개인 영상 |

`/data/shared/` 는 팀 공유다. 읽기는 자유롭게 하되 쓰기는 조심한다. `/data/<사용자ID>/` 는 개인 작업 공간이다.

```bash
mkdir -p /data/shared/{checkpoints,assets} /data/<사용자ID>/{repos,logs,videos}
```

**개인 폴더와 공유 폴더를 나눈다.** 여러 명이 같은 볼륨을 쓰는데 루트에 다 쏟으면 누가 무엇을 지웠는지 추적할 수 없다.

**`/data/shared/` 에 넣는 파일은 이름에 날짜와 작성자를 박는다.** 동시 쓰기 동작이 `미검증` 이므로 덮어쓰기 사고를 이름으로 막는다.

### 5-3. 넣는 것

| 무엇 | 왜 |
|---|---|
| `.pt` 체크포인트 | git 금지 대상. 여기 말고 갈 데가 없다 |
| 학습 로그 · TensorBoard | 재현과 비교에 필요하다 |
| 영상 (mp4) | 발표 · 검증 자료 |
| USD · 지형 에셋 | 크고, 팀이 같은 것을 써야 한다 |
| `setup.sh` | Pod 켤 때마다 필요한 셋업 |

### 5-4. 넣지 않는 것

| 무엇 | 왜 |
|---|---|
| **토큰 · 자격증명** | **팀 전체가 마운트한다.** 여기 두면 전원에게 노출된다 |
| Isaac Sim · Isaac Lab 본체 | 이미지에 이미 있다. 볼륨은 네트워크 파일시스템이라 느리고 용량만 먹는다 |
| pip 패키지 · site-packages | 파이썬 경로가 꼬인다. 매번 설치가 정답이다 |
| 셰이더 캐시 · `/tmp` 부스러기 | 30 GB 가 금방 찬다 |

토큰 규칙은 예외가 없다. GitHub 인증은 `git config --global credential.helper cache` (메모리)로 처리한다. `credential.helper store` 는 평문으로 남으므로 쓰지 않는다.

### 5-5. 용량 관리

체크포인트 하나는 작지만 학습 한 번에 수십 개가 쌓인다.

```bash
du -sh /data/*
```

찼을 때 **남의 폴더를 지우지 않는다.** 볼륨은 콘솔에서 키울 수 있다(줄이는 것은 불가).

## 6. Isaac Lab 첫 실행

09-01 에 실제로 통과한 순서다 `확인됨`. 경로 `/workspace/isaaclab` 은 팀 템플릿 기준이므로, 다른 이미지를 쓰면 2-3 절 표로 먼저 확인한다.

### 6-1. 로그를 볼륨으로 돌려둔다

`/workspace` 는 Stop 하면 사라지므로 학습 로그가 날아간다.

```bash
mkdir -p /data/<사용자ID>/logs
cd /workspace/isaaclab
[ -e logs ] || ln -s /data/<사용자ID>/logs logs
```

### 6-2. 사전학습 정책으로 파이프라인 확인

학습 없이 NVIDIA 가 미리 학습해 둔 정책을 받아 돌린다. 환경이 살아 있는지만 본다.

```bash
cd /workspace/isaaclab
./isaaclab.sh -p scripts/reinforcement_learning/rsl_rl/play.py \
  --task Isaac-Velocity-Rough-Unitree-Go2-Play-v0 \
  --use_pretrained_checkpoint --headless
```

`--headless` 라 출력이 없고 무한 루프로 계속 돈다. **멈춘 것이 아니다.** `Ctrl+C` 로 끝낸다.

성공 판정은 두 줄이다.

```
Loading model checkpoint from: .../Isaac-Velocity-Rough-Unitree-Go2-v0/checkpoint.pt
Actor MLP: ... (0): Linear(in_features=235, out_features=512 ...
```

## 7. 파일을 노트북으로 가져오기

**웹 터미널과 Basic SSH 로는 파일을 직접 복사할 수 없다.** RunPod 공식 문서의 연결 방식 표에서 Basic SSH 의 SCP/SFTP 지원이 `No` 다.
출처: https://docs.runpod.io/pods/configuration/use-ssh

`runpodctl` 을 쓴다. Pod 에 기본 설치되어 있다 `확인됨`.

Pod 에서:

```bash
runpodctl send /data/<사용자ID>/videos/rl-video-step-0.mp4
```

일회용 코드가 나온다. **받는 쪽이 실행할 때까지 대기 상태로 멈춰 있다.** 다운로드가 안 되는 것이 아니다.

노트북에서 (최초 1회 설치):

```powershell
Invoke-WebRequest -Uri "https://github.com/runpod/runpodctl/releases/latest/download/runpodctl-windows-amd64.exe" -OutFile "runpodctl.exe"
```

받기:

```powershell
.\runpodctl.exe receive <코드>
```

`Runpod config file not found` 경고는 무시해도 된다. send/receive 는 설정 없이 동작한다 `확인됨`.

> v1.0 의 "git 이 유일한 통로다" 는 **정정한다.** 코드는 git 이 맞지만 `.pt` 와 영상은 `runpodctl` 로 옮긴다.

## 8. 터미널 작업 방식

### 8-1. tmux 로 세션을 Pod 에 남긴다

웹 터미널은 세션이 끊기면 그 안에서 돌던 것이 함께 죽는다. **학습처럼 오래 도는 것은 반드시 tmux 안에서 돌린다.**

```bash
tmux new -s work        # 새 세션
# Ctrl+b 를 누르고 뗀 뒤 d        빠져나오기 (detach)
tmux attach -t work     # 다시 들어가기
```

없으면 `apt update && apt install -y tmux`.

### 8-2. 편집은 nano

```bash
nano /data/<사용자ID>/repos/<저장소>/파일명.py
```

`Ctrl+O` 후 Enter 로 저장, `Ctrl+X` 로 나가기.

### 8-3. 코드는 git 으로 왕복시킨다

```
노트북에서 작성 -> git push -> GitHub -> Pod 에서 git pull -> 실행
Pod 에서 결과 커밋 -> git push -> GitHub -> 노트북에서 git pull
```

Pod 최초 설정:

```bash
git config --global user.name "<GitHub 사용자명>"
git config --global user.email "<이메일>"
git config --global credential.helper cache
mkdir -p /data/<사용자ID>/repos && cd /data/<사용자ID>/repos
```

클론 대상은 두 가지다.

| 무엇 | 주소 |
|---|---|
| 팀 정본 | `https://github.com/foothold-project/foothold-go2.git` |
| 개인 fork · 개인 실험 저장소 | `https://github.com/<GitHub 사용자명>/<저장소>.git` |

**개인 저장소에서 시작했더라도 커밋 기록은 정본으로 그대로 옮길 수 있다.** 정본을 remote 로 추가해 브랜치를 밀면 된다.

비공개 저장소는 비밀번호 자리에 **GitHub 토큰**을 넣는다. 일반 비밀번호는 거부된다.

> **토큰을 문서 · 저장소 · 볼륨에 적지 않는다.** 클론 URL 에 토큰을 끼워 넣으면 `.git/config` 에 평문으로 남으므로 하지 않는다.

### 8-4. 처음 돌리는 명령은 로그를 남기고, 자르지 않는다

08-31 에 `2>&1 | grep Go2` 로 묶어 실행했다가 에러까지 함께 삼켜 원인 파악이 늦어졌다.

```bash
./isaaclab.sh -p <스크립트> 2>&1 | tee /data/<사용자ID>/logs/<이름>.log
```

**`| tail -40` 을 뒤에 붙이지 않는다.** `tail` 은 입력이 끝나야 출력하므로, 붙이면 프로세스가 도는 동안 화면이 비어 있어 진행 중인지 죽은 것인지 구분할 수 없다. `tee` 까지만 걸어 진행 상황을 그대로 보고, **끝난 뒤에 따로** 본다.

```bash
tail -n 40 /data/<사용자ID>/logs/<이름>.log
```

### 8-5. 끝나면 Stop

작업 종료 습관: 결과물을 `/data` 로 복사 → tmux detach → 콘솔에서 Pod **Stop**.
Stop 을 잊으면 시간당 $0.74 가 계속 나간다.
