**한 줄 요약**: 현장에서 사람이 로봇을 **보면서 조종하고, 목적지로 보내고, 상황에 따라 멈추고 개입하고, 한 일을 기록하는** 앱을 만든다. 첫 로봇은 Go2이고, 다른 로봇은 그다음이다. 지금까지 통과한 MVP(시뮬 조종·목표 이동·STOP)는 **기반**일 뿐이고, 완성은 아니다.

> 이 문서는 «무엇을, 왜, 어떤 순서로» 만드는지를 쉽게 정리한 **상위 기획**이다. 요구별 ID·검수 기준·현재 상태는 [PRD](PRD.md)에 있다. 두 문서는 같은 방향을 다른 깊이로 쓴다.
> **상태는 2026-10-12 12시 기준**이다. 이 시각에 진행 중이던 작업(Go2 시뮬 정지 시험 c2, 앱↔Go2 시뮬 연결 수정)은 끝난 것으로 쓰지 않았다.
> 수익화·가격·시장·고객 상품 정의는 이 기획에서 뺐다 - **추후 검토**.

## 1. 무엇을 만드나

### 앱이 하는 일
- **보기**: 로봇 카메라 영상, 지도 위 로봇 위치, 로봇 상태(연결·준비·배터리 등 실제 출처가 있는 값만).
- **움직이기**: 화면 조작으로 직접 조종하거나, 지도에서 목적지를 찍어 보낸다.
- **멈추기**: STOP은 어느 화면에서든 항상 보이고, 누구나 누를 수 있다.
- **임무 운영**: 목적지 도착 → 운영자가 현장을 확인 → 결과 기록. 중간에 일시정지·수동 개입·중단을 할 수 있다.
- **기록**: 누가 언제 무엇을 명령했고 결과가 어땠는지를 나중에 다시 볼 수 있게 남긴다.

### 완성이라고 부르는 때
아래 셋이 **모두** 충족돼야 완성이다:
- **PC 필수 화면 네 가지**(뎁스 영상, 누적 3D 점군, 로봇 상태 창, 지도)가 PC에서 검수를 통과했다.
- **휴대폰 필수 화면**(카메라 전체 화면, 왼쪽 회전 막대, 오른쪽 앞뒤 막대, 지도, 후진)이 실제 휴대폰에서 검수를 통과했다.
- 정한 첫 임무 하나를 **실기 Go2**로 **실제 현장 조건**에서 반복 시험해 통과했다.

시뮬레이션 통과, 에뮬레이터 통과, «화면이 뜬다»는 완성이 아니다. 첫 현장 임무만 통과하고 PC 필수 화면이 없어도 완성이 아니다.

### 연결 구조 (한 줄)
앱(PC·휴대폰 웹) → 로그인 관문·gateway(로봇 PC, 조종권·STOP·끊김 판단) → 로봇 쪽 연결 → 로봇. 실기 Go2는 **내장 보행 위에 SDK 고수준 명령(이동·정지)만** 보내는 계획이다. Gazebo의 Go2 시뮬(A2)은 시뮬 대역일 뿐이며, 그 저수준 보행 컨트롤러를 실기에 옮기는 계획이 아니다. 카메라·뎁스·점군은 명령과 별도 흐름으로 화면에 온다. 실기 센서 장착은 미확정이다. 그림은 [PRD](PRD.md) 2장.

### 지금 하지 않는 것
- 분야 전용 상품(가스 점검, 소화, 시설 사진 보고서 등)을 필수 임무로 못 박는 일. 분야는 아직 정하지 않았다.
- 로봇·장비가 할 수 있다고 검증되지 않은 작업을 «실행 가능»으로 보여 주는 일.
- 다른 로봇 모델 지원. 구조만 열어 두고 구현은 뒤로 미룬다.

## 2. 누가, 어디서 쓰나

| 쓰는 사람 | 기기 | 주로 하는 일 |
|---|---|---|
| 현장 운영자 | 휴대폰(시험 기기 iPhone 16 Pro + Chrome) | 카메라를 보며 두 엄지로 조종, 미니맵 확인, STOP |
| 관제·준비 담당 | PC(노트북) | 뎁스·3D 점군·2D 지도·경로·층·로봇 상태를 한 화면에서 보고 목적지·임무 지시 |

- 같은 웹 화면을 PC와 휴대폰이 함께 쓴다. 설치형 앱은 그 화면을 감싸는 껍데기다(5장).
- 현장 네트워크는 로봇 PC와 휴대폰이 **같은 Wi-Fi**에 있는 것을 기본으로 한다. 다른 원격 접속은 이미 설치·사용 가능한 경우에만 대안으로 본다.

## 3. 화면 - 기기마다 꼭 있어야 하는 것

### PC 화면
- **뎁스 카메라 영상**.
- **SLAM이 쌓은 3D 점군**. 점군·지도·로봇 위치는 **같은 좌표계와 같은 시각 기준**으로 맞춘다.
- **2D 지도**: 목표·경로·층 표시.
- **로봇 상태 창**.
- 상세 패널은 접고 펼 수 있다. 다만 **조종자, 연결·준비 상태, STOP**은 접히지 않고 항상 보인다.
- 3D 보기가 느려지거나 실패해도 STOP과 상태 표시를 가리거나 멈추게 하면 안 된다.

### 휴대폰 화면
- 가로 방향에서 **RGB 카메라 영상을 화면 전체**로 띄운다.
- **왼쪽 아래**: 좌우로만 움직이는 막대 하나 → 회전.
- **오른쪽 아래**: 위아래로만 움직이는 막대 하나 → 앞으로·뒤로.
- **위쪽**: 미니맵. 누르면 큰 지도로 바뀌고, 다시 영상으로 돌아올 수 있다.
- 조작부는 배경만 반투명하게 두고, 기호·STOP은 선명하게 그린다. 노치·홈 막대(safe area)를 피한다.
- 주소창이 남거나, 세로로 들었거나, 홈 화면 추가가 안 되는 경우에도 **쓸 수 있는 대체 배치**를 둔다. 이 경우들은 실제 iPhone에서 확인하기 전에는 «된다»고 하지 않는다.

### 두 엄지 조작 - 지금 코드와 부딪히는 점
- 지금 화면은 «두 번째 손가락이 닿으면 누름을 전부 해제»한다(④ DRV-3). 오조작을 막으려고 만든 규칙인데, 두 엄지 동시 조작과 정면으로 충돌한다. **바꾸고 다시 검증할 계획**이다.
- 새 규칙의 방향:
  - 왼쪽·오른쪽 조작 영역마다 손가락 하나씩만 받는다.
  - 다음 경우에는 그 입력을 0으로 만들고, **이전 입력을 되살리지 않는다**: 새 탭·세 번째 손가락·터치 취소(cancel)·화면 회전·앱이 포커스를 잃음.

### 후진
- 후진은 **최종 제품에 필수**다. 숨겨 두고 완료로 치지 않는다.
- 지금 코드에는 후진 입력(화면 조작과 서버 설정)이 있다. 다만 운영 기본 설정에서 꺼져 있다.
- Go2 시뮬 연결 경로는 후진과 혼합 입력(전진 + 회전 동시)을 거부한다. Go2 후진은 **아직 검증하지 않았다**.

## 4. 안전과 조종권

- **로그인한 사람만** 조종한다. 조종권자는 한 번에 한 명이다. 조종권 받기·내려놓기·정지 해제는 모두 **명시적인 버튼**으로만 한다.
- **STOP은 누구나** 누를 수 있다. 여기서 «누구나»는 관문에 연결해 앱 화면을 보고 있는 운영자와 보기 전용 사용자를 말한다. 인증 없는 인터넷 접속에 명령 권한이 있다는 뜻이 아니다.
- 다음 경우에는 로봇을 멈추고 잠근다(장애 STOP):
  - 입력이 끊겼을 때
  - heartbeat(화면 생존 신호)가 끊겼을 때
  - 영상이 끊겼을 때
  - 재접속했을 때
  - 서버가 재시작했을 때
- 잠긴 뒤에는 **자동으로 다시 움직이지 않는다.** 사람이 상태를 확인하고 정지 해제를 눌러야 한다.
- **손을 떼는 것과 장애 STOP은 다르다.**
  - 보통 손을 떼면 앱이 **바로 0을 보낸다**. 로봇은 조종 준비 상태 그대로다.
  - 메시지가 끊겨 그 0이 못 오면, 서버가 마지막 입력 뒤 0.3 s(deadman)에 0으로 만든다.
  - 장애 STOP은 위 끊김 상황에서 걸리는 정지 + 잠금이다.
- 앱은 **명령 잠금 상태를 표시**한다. 로봇이 실제로 멈췄는지는 **별도 측정으로 검증**한다. 둘은 다른 증거다. Go2의 실제 정지는 아직 측정하지 않았다.
- 지금 쓰는 시한 값(deadman 0.3 s, 화면 신호 1.0 s 끊김 → 정지)은 **구현 설정값**이다. 현장에서 «이 시간 안에 선다»는 보증이 아니다.
- 장비(로봇에 단 작업 도구)를 멈추는 STOP 계약은 **아직 정하지 않았다**.

## 5. 지도와 층

| 용어 | 뜻 |
|---|---|
| SLAM | 움직이며 **지도를 새로 만드는** 것 |
| AMCL | **저장한 지도** 위에서 지금 위치를 찾는 것 |
| Nav2 | 한 층 지도 **안에서** 경로를 짜서 목적지로 가는 것 |

- 지금 시뮬(2층 건물 v5)의 «층 바꾸기»는 **사람이 로봇을 다른 층에 옮겨 놓는 일을 순간이동으로 흉내 낸 것**이다. 로봇이 스스로 계단을 오르는 기능이 아니다. 층간 자율 이동은 **현 단계 지원 범위 밖**일 뿐 영구 제외가 아니다. 다른 층 목적지 이동(계단·엘리베이터 등)은 향후 가능성을 검토하고 별도로 검증한다.
- 층을 바꾼 뒤에는 다음 순서를 지켜야 이동을 허락한다:
  1. 층 확인
  2. 그 층 지도 불러오기
  3. 초기 위치 지정
  4. 위치 추정이 수렴했는지 확인
- 목표 이동 흐름: 지도에서 목적지 찍기 → 명시 실행 → 진행·도착·취소 표시 → 언제든 운영자 수동 인계. 실행 전 경로 미리보기는 설계 제안이다. 경로 없음·위치 불확실·틀린 지도/층·중복 목표면 이동하지 않고 이유를 보인다. 지도 목표 이동·취소는 TB3 시뮬에서 검증했고, 경로 사전 표시는 미검증이다. **Go2 쪽은 아직 목표 이동을 열지 않았다**.
- 3D 점군 보기와 층 사이 자율 이동은 **서로 다른 기능**이다. 하나가 된다고 다른 것도 된다고 보지 않는다.

## 6. 임무

- 분야는 **미정**이다. 첫 사용은 **AI 없이**, 사람이 카메라를 보며 직접 조종하는 것이다.
- 그다음 단계의 임무 흐름은 다음과 같다:
  1. 목적지로 이동
  2. 도착
  3. 운영자가 영상으로 현장 확인
  4. 결과 기록
- 임무를 넓힐 때는 단계마다 다음 기준을 정한 뒤에 넣는다:
  - 이동: 어떻게 가나
  - 확인: 누가, 무엇을 보고 판단하나
  - 작업: 검증된 장비만 쓴다
  - 개입: 일시정지·수동 인계
  - 실패: 끊김·위치 상실·시간 초과
  - 결과: 성공을 무엇으로 판정하나
- **AI 목표물 인식**은 이 흐름과 따로 가는 후속 작업이다.
- **SpatialLM**(점군에서 벽·문·물체 구조를 뽑는 모델)은 **선택 기능**이다. 오프라인 분석이나 사람이 확인하는 보조 화면에만 쓴다. 실시간성이나 안전 판단은 보장하지 않는다.
- ROS 토픽이 보인다는 것만으로 «이 기능 준비됨», «이 작업 가능»이라고 표시하지 않는다. 근거는 어댑터 등록, 센서 상태, 검증 기록이다.

## 7. 센서

- 실기 Go2 후보 센서는 RealSense D435i(뎁스·RGB), Unitree L1 라이다, Hesai XT-16 라이다다.
- 실제로 접근할 수 있는 장비와 장착 구성이 확정되기 전까지 이 조합은 **제안**일 뿐이다.
- 카메라·점군·지도는 시각을 두 가지로 나눠 적는다:
  - **앱이 받은 시각**
  - **센서가 찍거나 잰 시각**
- 오래된 데이터, 연결 안 됨, 아직 확인하지 않은 상태는 화면에 구분해서 표시한다.

## 8. 앱 형태

- **공통 웹 화면**이 PC와 휴대폰의 핵심이다. 그다음 단계가 설치형 클라이언트다.
- 이미 만든 설치형 앱의 상태:

  | 설치형 앱 | 상태 |
  |---|---|
  | Android apk | 서명함. 에뮬레이터 시험만 통과, 실기기 미검증 |
  | Windows exe | 코드 서명 없음. Linux Electron 시험만 통과, 실기기 미검증 |

- iOS는 설치 파일(IPA)도 배포 경로도 아직 없다. 후속 검토 대상이다.
- «앱스토어 등록 완료», «iPhone에 설치 완료»라고 말하지 않는다.

## 9. 만드는 순서

| 순서 | 할 일 | 끝났다고 보는 때 |
|---|---|---|
| 1 | Go2 기본 정지 + 앱 연결 | Go2 시뮬에서 앱 STOP·끊김에 로봇이 실제로 멈추는 것을 측정으로 확인 |
| 2 | 카메라 화면·가로 휴대폰·두 엄지 조작·후진 | 실제 iPhone에서 조작·STOP 확인, 후진·혼합 입력을 시뮬에서 검증 |
| 3 | PC 뎁스·3D 점군 화면 | 좌표·시각이 맞는 점군 표시, 3D가 STOP을 막지 않음 |
| 4 | Go2 SLAM·Nav2·층 운영 | 저장 지도 위치 추정과 층 절차를 Go2로 확인 |
| 5 | 임무·기록·현장 반복 시험 | 첫 임무 하나를 실기 Go2로 현장 조건에서 반복 통과 |
| 6 | AI 인식·다른 로봇 | 별도 설계 뒤 |

- 위 순서 어느 단계에도 **GPU 구매나 확정 일정은 없다**. 범위는 완성 제품 전체를 남겨 두고, 순서만 정했다.

## 10. 지금 어디까지 왔나 (2026-10-12 12시 기준)

| 영역 | 상태 |
|---|---|
| 시뮬 조종·목표 이동·STOP·로그인·조종권 | Gazebo(TB3 로봇으로 대신)에서 동작·자동 시험 통과. 휴대폰은 주로 헤드리스 Chrome 에뮬레이션 |
| 휴대폰 가로 화면 | 실제 iPhone에서 지도가 눌리는 문제를 보고 배치를 고쳤다. 고친 화면을 실제 iPhone에서 다시 확인하지는 않았다 |
| 2층 건물 시뮬·층 바꾸기 | 순간이동 대역으로 구현. 실기용 «사람이 옮겼음 확인» 흐름은 미구현 |
| Go2 시뮬 정지 계층 | 계층 논리 시험 일부 통과. 정지 시험 1차는 도구 오류(시뮬 속도 부족)로 중단. 2차(c2)는 준비·검토 중이라 **결과 없음** |
| 앱 ↔ Go2 시뮬 연결 | 사본 코드와 순수 모의 시험만 있다. 검토 지적을 반영한 사본이 모의 시험을 통과해 재검수를 기다린다. **시뮬·운영 반영 없음** |
| 앱 STOP에 Go2가 실제로 멈추나 | **미검증** |
| 후진 | 코드(화면 입력·서버 설정)는 있다. 운영 기본은 꺼짐, Go2 시뮬 경로는 거부, Go2 후진 검증 없음 |
| 새 두 엄지 조작 화면 | **미구현** |
| PC 뎁스 영상·3D 점군 | **미구현** |
| 실기 Go2·현장 | **시작 안 함** |
