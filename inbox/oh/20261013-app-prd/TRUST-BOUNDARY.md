**결론**: 사람의 신원은 **관문(phone_gate)** 이 정하고, gateway·임무 서버는 **관문 서명이 붙은 명령만** 받는다. 같은 PC 안의 ROS(DDS)는 믿는 영역이다 - 같은 도메인에 프로세스를 띄울 수 있는 사람은 이 경계 밖에서 막지 못한다. 영상 확인은 «서버가 받은 프레임의 촬영 나이 + 화면이 신고한 그린 프레임이 서버가 수신·검사한 프레임인지»까지다 - 조작된 화면의 거짓 신고나 사람이 봤다는 것은 증명하지 않는다. 앱 스택의 DDS 는 127.0.0.1 UDP 로 한정하지만 인증·암호화는 아니다. Go2 실기 연결은 아직 검증 전이다(어댑터는 오프라인 mock 만).

## 경계 그림

| 순서 | 구간 | 믿음 |
|---|---|---|
| 1 | 휴대폰·노트북 브라우저 | 믿지 않음 |
| 2 | → HTTPS(로그인 쿠키) → 관문 phone_gate | 신원을 정하고 서명 |
| 3 | → ws(같은 PC 안 loopback) → rosbridge(허용 토픽만) | 이 PC 안 |
| 4 | → DDS → gateway · 임무 서버 · 지도 관리자 | 서명 확인 후 실행 |

| 구간 | 믿나 | 근거 / 막는 것 |
|---|---|---|
| 브라우저 → 관문 | 안 믿음 | 계정·비밀번호(scrypt) 로그인, 정확한 Origin 일치, 쿠키 세션, 서버가 정한 기기 id. 화면이 보낸 `sid`·`actor`·`tag`·`inst`·`gen`·`src` 는 관문이 지우고 다시 채운다 |
| 관문 → rosbridge | 같은 PC | 127.0.0.1 에만 열림. 발행은 `/app/cmd` 하나, 구독은 앱 토픽만, 서비스·액션 0 |
| `/app/cmd` → gateway·임무 서버 | 서명만 | HMAC 서명(ts·exp·sess·seq) - 서명 없음·위조·5 s 넘은 시각·재전송(seq)·로그아웃 세션·서버 기동 전 서명은 거부. 서명 없는 STOP 은 «멈춤»만 하고 권한·기한은 바꾸지 않는다 |
| 임무 서버 → gateway (`/app/mission_nav`) | 서명 + 인스턴스 | 임무 서버 자기 서명(sess=기동 id) + 그 gateway 인스턴스(inst) 일치 + 시도 표지(tag)·주체(sid)·번호(gen). 임무 목표는 임무 서버 생존 신호(alive, 0.2 s)가 1 s 끊기면 정지 래치 |
| DDS(같은 도메인) | **믿음** (이 PC 안으로만 한정) | `run_s1.sh` 가 앱 스택 전부에 `ros/fastdds_local.xml` 을 준다: **127.0.0.1 UDP 만**(공유 메모리 없음 - 영상 멎음 결함 때문, stall 4/4), SUBNET 범위 + 주소 화이트리스트, 정적 피어 없음. 스택 프로세스 소켓이 127.0.0.1 뿐임을 시험마다 확인(phone·slam N0). **인증·암호화가 아니다**(SROS2 아님) - 같은 PC·같은 `ROS_DOMAIN_ID` 에 프로세스를 띄울 수 있으면 `/cmd_vel` 등 하류를 직접 낼 수 있고, 같은 설정을 준 기본 ROS 도구도 붙는다. 막는 것은 OS 계정 권한뿐 - 도메인 분리(57·58)는 실수 방지다. **범위 밖**: Gazebo 자체 발견 포트(0.0.0.0:10317/10318)는 DDS 가 아니며 그대로 열린다(시뮬 한정, `GZ_PARTITION`·`GZ_IP` 는 이름·데이터만 좁힘 - `gz-discovery-control-181428.txt`). 다른 PC 간 DDS 는 시험 안 함. 실기 Go2 쪽 DDS 는 별도 계약 |

## 키와 계정

- 서명 키 `hmac.key` 와 계정 `accounts.json` 은 `.gate/`(0700, 파일 0600). 주소·로그·저장소에 싣지 않는다
- 시험은 런마다 새 `mktemp` 폴더의 fixture 키·계정(`test/auth_gz_run.sh`) - 결과 폴더에 비밀값이 섞이면 종료값 12
- 휴대폰 접속은 `S1_GATE_BIND=0.0.0.0` 을 명시할 때만 LAN 에 열린다. rosbridge·gateway 포트는 어떤 경우에도 밖에 열지 않는다

## 영상 확인의 범위 - 누가 무엇을 확인하나

| 층 | 확인하는 것 | 한계 |
|---|---|---|
| **서버(gateway VideoGate)** | 받은 프레임이 계약된 출처(`gz_camera:ros`)이고 JPEG 로 풀리며, 촬영 시각이 1.0 s 안이고 미래 시각이 아니며, 1.0 s 넘게 끊기지 않음 | 카메라가 맞는 방향을 보는지는 모른다 |
| **서버(렌더 확인)** | 주인 화면이 신고한 «그린 프레임 촬영 시각»(vs)이 **서버가 실제 수신·검사한 프레임**(VideoGate 가 본 촬영 시각) 중 하나이고 그 촬영이 1.5 s 안 | vs 는 비신뢰 브라우저가 신고한 값이다. **조작된 화면이 «그렸다»고 거짓 신고하는 것은 서버가 증명하지 못한다** - 서버는 값이 수신·검사한 프레임에 속하고 나이가 맞는지만 본다. 그 프레임이 이 화면에 전달·렌더됐다는 증명도 아니다 |
| **정상 앱(web/app.js)** | 실제로 디코딩된 프레임만 vs 로 보내고, 탭이 보이고 영상 영역이 80×60 이상·화면 안·가려지지 않았을 때만 보낸다(숨은 디코딩은 보내지 않음) | 정상 앱의 동작일 뿐 서버 쪽 증명이 아니다 |
| **확인 못 함** | 사람이 그 화면을 실제로 보고 있는지, 밝기·반사로 못 알아보는 경우 | 운영 절차(사람)의 몫 |
| **영상 파일** | **저장하지 않는다.** 임무 기록의 영상 근거는 메타데이터(출처·시계·촬영 나이·화면 확인 나이)뿐이고 `file: null` | 사후에 영상을 다시 볼 수 없다 |

- 영상이 못 미더우면 움직이지 않는다. 예외는 운영자가 「지도 운용」을 고르고 서버가 허용(`S1_MAP_OPS=1`)할 때만
