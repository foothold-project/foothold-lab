## 1. 최종 완료 기준

- **정해진 첫 임무 하나를 실기 Go2와 승인된 장비로 실제 현장 조건에서 반복 검증해 통과하는 것**(F7, 검수 D5·D6). 반복 시험 항목은 정지거리·가동 지속·통신/센서 장애·목표/작업 결과다.
- 조종·지도 이동·휴대폰 인증 연결·MVP 검수는 **중간 기반**이다. 종료 조건이 아니다.
- 지금(10-07 저녁) 통과한 것은 **로컬 시뮬의 자동 시험**뿐이다: loopback(S1 49/49, 임무시험 15/15, 반례) + **Gazebo TB3 대역·관문 로그인 경유**(fin-auth 13/13, fin-mission 7/7, fin-kill 4/4, 헤드리스 Chrome 휴대폰 에뮬 25/25, SLAM 5/5, 영상 멎음 4/4, 시험 결과 기록(작성자 로컬 근거 기록, 팀 열람 링크 없음)) + Go2 어댑터 오프라인 mock 9/9. 로그인·sid 위조 방지·조종권 내려놓기·기록 원자성·영상 서버 차단·임무 서버 죽음 래치는 **이 시뮬 전제에서** 통과했다. **실기 Go2·실제 휴대폰 조작(실제 iPhone 은 예전에 Safari 접속까지만)·사람 사용성·장비·현장·PWA·다층은 아무것도 통과하지 않았다.**
- (10-07 오전 판 기록: 그때는 «전부 loopback, 로그인·영상 미검증, ③ Isaac 이 실기 전 필수»였다. 같은 날 순서가 Gazebo → 실기로 바뀌어 아래로 대체.)

## 2. 순서 - 무엇이 무엇을 기다리나 (10-07 개정: Gazebo → 실기)

**제품 결정 트랙(병행)**: O-1 첫 현장 임무·성공 근거·환경·운용 조건. 관문 G-P: ② 분야 전용 설계 전에 고정한다.

| 단계 | 내용 | 상태(10-12) |
|---|---|---|
| ① 공통 현장 확인 임무 (F1·F2) | 로그인·권한·원자 기록·범위 조회 포함 | 완료(Gazebo) |
| ② 영상·근거·결과 (F3·F4) | 시뮬 카메라·서버 차단·휴대폰 조종 모드(에뮬)·이력 페이지 | 부분 완료(Gazebo). 남음: 실제 휴대폰 조작·사람 사용성, VID-3 근거 사진, MIS-11, REC-4 보고 |
| ③ Isaac 시뮬 임무 검증 (F5) | B0~B7 | 보류(필수 선행 아님) |
| ④ 실기 Go2 (F6, 별도 승인) | 어댑터 SDK 연결, D1(로봇 쪽 감시), D2~D4 | 다음(장비·사람·승인 필요) |
| ⑤ 현장 (F7, 별도 승인) | 장비 어댑터·인터록(STP-3·4, CAP-3), D5·D6 | 그다음 |

| 순서 | 묶음 | 앞 단계에 기대는 이유 / 지금 |
|---|---|---|
| ①-a | 신원·권한 (CTL-4·5, IDN-1·2, 검수 L1·L2·L5·L6) | **Gazebo 통과(10-07).** 남음: 실제 운영 계정 등록·실폰 로그인, 역할 권한(IDN-3) |
| ①-b | 명령 원자 처리 (MIS-13, 검수 R8) | **기록 원자성 구현(selftest).** 남음: Nav2·장비 쪽 «보냄 → 결과 확인» - 장비(⑤) 전에 필수 |
| ①-c | 사건 범위 조회 (REC-6, 검수 H4) | **통과(10-07).** 보존 기간·내보내기는 O-6 |
| ② | 영상·근거·결과 | 시뮬 카메라로 흐름·차단은 통과. 실제 Go2 카메라 소스·지연(O-2)이 정해져야 합격 판정 |
| ③ | Isaac | **보류.** 실기 전에 꼭 거칠 필요가 없게 순서를 바꿨다. 다시 필요해지면 B0-1~3 진단부터 |
| ④ | 실기 | Go2 어댑터의 실제 SDK backend 와 로봇 쪽 감시(STP-5)를 **실기에서** 확인해야 한다 - 오프라인 mock 통과는 몸이 선다는 증거가 아니다([GO2-ADAPTER](GO2-ADAPTER.md) 실기 검수표) |
| ⑤ | 현장 | 분야·첫 임무·장비가 정해져야 한다. 장비 정지 계약(STP-4) 없이는 장비 임무를 실행 가능으로 표시하지 않는다 |

- **제품 결정 트랙은 병행한다.** O-1(첫 현장 임무·성공 근거·현장 환경·운용 조건)은 F7 직전이 아니라 지금부터 정한다. 답이 없어도 공통 구현은 계속한다. 다만 **관문 G-P**: 분야 전용 영상·장비·성공 판정 설계에 들어가기 전에 O-1의 범위를 문서로 고정한다. «지점 확인 다녀오기»는 공통 기반이지 최종 임무가 아니다.
- 다층(FLR)은 **계획**이다(D-5). 계단·엘리베이터 이동은 확정된 능력이 아니다(FLR-4).
- **승격 조건**: 첫 현장 임무(O-1)가 층간 이동을 반드시 포함하면, 층 전환(FLR-1~3·5, 검수 P4·P5)은 ④ 실기 전 Gazebo 관문으로, 계단·엘리베이터(FLR-4, P6)는 ④ 실기 능력 검증 관문으로 앞당긴다.

### 가정 (확인되면 지운다)
- Go2 우선. 다른 로봇은 같은 계약에 어댑터만 바꾼다(ROB-3).
- Go2에 로봇 쪽 명령 끊김 감시를 걸 방법이 있다 - **미확인.** 어댑터 쪽 감시(0.3 s)는 오프라인 mock 으로만 확인했고, 어댑터 PC 자체가 죽을 때 로봇이 서는지는 실기에서만 안다(STP-5).
- Nav2 «성공인데 0.53 m»(Gazebo fin-mission-181804)의 원인은 goal checker `stateful` 로 **추정만** 했다 - 시뮬 사본만 False, 임무 도착 판정(반올림 전 오차 ≤ 0.5 m)은 유지.
- 수업 실기 Go2의 센서 구성을 이 로봇에 그대로 가정하지 않는다.
