## 이 화면을 쓰는 사람과 상황 - 모든 결정의 기준

현장 운영자는 **급하고, 한 손이고, 장갑을 꼈을 수 있고, 햇빛 아래서, 로봇과 화면을 번갈아 본다.** 그래서:

| 원칙 | 화면에서 이렇게 |
|---|---|
| **지금 할 일 하나만 크게** | 화면마다 주 버튼은 하나. 다음에 누를 것을 고민하지 않게 한다 |
| **멈춤은 언제나 같은 자리** | STOP 은 모든 화면에서 같은 위치·같은 크기·같은 색. 확인 창 없이 한 번에 멈춘다 |
| **쉬운 말** | «NAV»·«cmd_vel»·«래치» 대신 «목표로 이동 중»·«정지됨 - 「정지 해제」를 눌러야 다시 움직입니다». 오류는 «무엇이 문제인지 + 무엇을 하면 되는지» |
| **안 되는 건 이유와 함께** | 못 누르는 버튼은 숨기지 않고 회색 + 한 줄 이유(«장비가 연결되지 않음»). 운영자가 «왜 없지?»로 헤매지 않게 |
| **색만으로 말하지 않는다** | 상태는 색 + 모양(●▲■) + 글자. 색약·햇빛 반사에서도 읽히게 |
| **큰 손가락 영역** | 누르는 곳 최소 56 px(장갑 고려), 서로 8 px 이상 떨어짐. 위험 버튼은 STOP 과 멀리 |
| **되돌릴 수 있으면 확인창 대신 되돌리기** | 목표 잘못 찍음 → «취소» 한 번. 확인창은 되돌릴 수 없는 위험 작업에만(그것도 «길게 누르기») |
| **끊겨도 길을 잃지 않게** | 다시 붙으면 «끊긴 동안 있었던 일»을 먼저 보여준다 |
| **알림은 소리·진동도** | STOP·연결 끊김·확인 요청은 화면을 안 보고 있어도 알게(폰 진동, 노트북 소리) - 켜고 끄기 가능 |

### ④ 확인해 주세요 - 운영자 판단 단계

| 줄 | 내용 |
|---|---|
| 1 | 3/5 현장에 도착했습니다 |
| 2 | 영상을 보고 골라 주세요 |
| 3 | [맞음, 다음으로] (주 버튼) |
| 4 | [다시 보기(자리 조금 이동)] [임무 중단] |

- 진동 1회 + 화면 맨 위 줄 색 변화. 답할 때까지 로봇은 멈춰 있다(자동으로 넘어가지 않음).
- 정해진 시간 안에 답이 없으면 계속 기다리며 «아직 답을 기다리는 중 (2분)»처럼 경과만 보여준다.

### ⑤ 작업 명령 - 장비 (검증된 능력만)
- 지원되지 않으면: 버튼 대신 «이 로봇은 이 작업을 할 수 없습니다: 장비 미연결. 직접 처리하거나 임무를 다음 단계로 넘기세요.»
- 위험 작업(`safety: hazard`)은 **«길게 눌러 실행»(2초, 원이 차오름)**. 손을 떼면 취소. 확인 창을 겹겹이 띄우지 않는다 - 급할 때 창 닫기 실수가 더 위험하다.
- 실행 중: «작업 중 - 장비 중단» 버튼이 STOP 옆이 아닌 작업 카드 안에 있다(전체 STOP 과 헷갈리지 않게).
- 완료: 장비가 보낸 결과를 그대로 보여주고 운영자가 «결과 확인».

### ⑥ 결과·마무리
- 단계별 결과 요약(✓/✗/건너뜀 + 근거: 도착 오차, 확인한 운영자, 장비 보고).
- «복귀» 단계가 있으면 자동으로 이어서 하지 않고 «복귀 시작» 버튼.
- 끝나면 «이 임무 기록 보기»(F4 이력 화면으로).

## 사용성 확인 방법 (자세한 항목은 ③ 검수 문서 C1~C6)
- 앱을 처음 보는 사람 2~3명에게 «임무 시작 → 확인 단계 응답 → STOP → 다시 계속»을 설명 없이 시킨다. 막힌 곳·되물은 말·걸린 시간을 적는다.
- 첫 회는 **진단**(어디서 막히나 보기) → 문구·배치 고침 → 기준 고정 → 다른 사람으로 본시험.
- 10-07 현재: 화면 캡처(노트북·휴대폰 폭)와 자동 시험만 있다. **사람이 써 본 시험은 아직 없다**(10-07 사용성 시험 안내(첨부 미포함)가 첫 진단 절차).
