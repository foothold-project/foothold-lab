## 1. 제품 목표

현장에서 운영자가 로봇에게 **임무를 명령하고, 진행을 확인하고, 멈추고, 결과를 기록**하는 앱. 노트북과 휴대폰이 같은 웹앱을 쓴다.

- **최종 완료**: 정해진 첫 임무 하나를 실기 Go2와 승인된 장비로 **실제 현장 조건에서 반복 검증**하는 것(`7-roadmap-decisions.md` §1). 조종·지도 이동·MVP 검수는 중간 기반이다.
- **로봇**: Go2 우선. 다른 로봇은 같은 gateway·임무 계약 위에 어댑터를 바꿔 붙이는 후속 계획이다(ROB-3).
- **분야·장비**: 미정. 소방(소화)은 예시일 뿐이고 Go2에 소화 장비·내열성이 있다고 가정하지 않는다.
- **하지 않는 것**
  - 검증되지 않은 장비 작업을 «실행 가능»으로 표시하지 않는다.
  - ROS 2 토픽·서비스가 보인다는 사실을 «그 기능이 된다»는 증거로 쓰지 않는다. 토픽 탐색은 연결 확인일 뿐이고, 능력은 검증 기록이 있어야 등록된다(CAP-1).
  - 정상 동작 중 중복 방지 시험 통과를 «장애 중에도 정확히 한 번 실행»으로 쓰지 않는다(MIS-13).
  - **명령 수락이나 목적지 도착만으로 «작업 성공»을 기록하지 않는다.** 단계마다 성공 근거(위치 오차·운영자 확인·장비 결과)가 있어야 한다.

> **첫 현장 임무 (10-08 부분 확정, O-1)** - 설계안: 목적지까지 안전 이동 → 목표 위치에서 정지 → 카메라로 목표물 인식 → 근거·결과 표시 → 운영자 확인 → 기록. 대상 없음·불확실이면 멈추고 보고(자동 복귀·재탐색은 미결정). SC-1·SC-2 위에 `observe` 의 카메라 인식을 얹는 형태다. **지금 구현은 사람 확인 + 복귀까지**이고, AI 목표물 인식 모델과 근거 사진 저장은 **미구현**이다. 남은 결정: 대상(종류 탐지 / 특정 물체 식별 / 문자·상태 읽기) · 시험 환경 · 성공 기준.
