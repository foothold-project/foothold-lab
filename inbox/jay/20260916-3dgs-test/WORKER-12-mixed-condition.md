## 1. 실험 설계

### 고정할 것

- **기준 장면 R**: `IMG_6701.MOV` 에서 뽑은 프레임 중 **연속 구간 150 장**. 1차 촬영 위치와 겹치는 구간을 골라야 합니다. 코디네이터 확인으로는 6701 의 **55 ~ 75 초** 부근에 「주정차금지」 노면 문자와 벽돌 담이 나옵니다. 그 구간을 중심으로 고르고, 실제로 고른 시각 범위를 적으십시오.
- **붙일 대상 Q**: 1차 장면에서 뽑은 **100 장**. 아래 변형마다 만드는 법이 다릅니다.
- 매칭과 재구성은 모든 변형에서 **똑같이**: `sequential_matcher`(overlap 15) + `vocab_tree_matcher`(`--VocabTreeMatching.num_images` 60) → `mapper`.
- 카메라는 `--ImageReader.single_camera_per_folder 1`, 모델 OPENCV.

### 변형

| 변형 | Q 를 만드는 법 | 무엇을 보는가 |
|---|---|---|
| **V0 기준선** | 축소 재인코딩본에서 그대로 1920x1080 | 아무 대책 없이 넣으면 어떻게 되는가 |
| **V1 화소 크기 맞추기** | V0 을 **2560x1440 으로 확대** (Lanczos) | 화소 크기만 맞추면 되는가 |
| **V2 공통 상한** | Q 는 V0 그대로 두고, **R 과 Q 모두** `--FeatureExtraction.max_image_size 1600` | COLMAP 안에서 같은 크기로 줄이면 되는가. 가장 싼 대책 |
| **V3 어려운 매칭 옵션** | V0 그대로 · 특징 추출에 `--FeatureExtraction.estimate_affine_shape 1` `--FeatureExtraction.domain_size_pooling 1` 추가 | COLMAP 이 권하는 대책이 듣는가. 느려진다 |
| **V4 원본 사용** | **`IMG_6698.MOV` 에서 2560x1440 으로 새로 추출** | 애초에 원본을 쓰면 되는가 |

프레임 선별 방식(연속 3 프레임 창 최대 라플라시안)은 모든 변형에서 같게 합니다. V0 · V1 · V2 · V3 은 **같은 프레임 집합**을 씁니다(처리만 다릅니다). V4 만 원본에서 새로 뽑습니다. V4 의 프레임이 V0 과 같은 시각을 가리키도록 **시각 기준으로 맞추십시오.**

### 재는 것

변형마다 다음을 적습니다.

| 지표 | 정의 |
|---|---|
| **Q 등록 장수** | R 이 들어 있는 모델에 Q 가 몇 장 들어왔는가. **이것이 주 지표입니다** |
| 최대 모델 장수 | 250 장 중 몇 장 |
| 모델 개수 | 갈라졌는가 |
| 평균 재투영 오차 | |
| R-Q 교차 매칭 쌍 수 | 데이터베이스에서 R 이미지와 Q 이미지 사이의 검증된 매칭 쌍 수와 평균 인라이어 수. **붙지 않았다면 매칭에서 진 것인지 재구성에서 진 것인지 여기서 갈립니다** |
| 특징점 수 중앙값 | R 과 Q 각각 |
| 벽시계 | 단계별 |

**R-Q 교차 매칭 쌍 수가 핵심 진단입니다.** 등록이 0 이어도 매칭이 있었다면 원인이 다릅니다. COLMAP 데이터베이스의 `two_view_geometries` 테이블을 직접 읽으십시오(`image_id1` · `image_id2` · `rows`).

## 2. 순서

1. `_out/mixcond/frames/` 에 R 150 장과 변형별 Q 100 장씩을 만든다. 각 집합의 장수 · 해상도 · 출처 시각을 `inputs.json` 에 적는다.
2. 변형마다 독립된 폴더(`v0` ~ `v4`)에 데이터베이스를 새로 만들고 위 파이프라인을 돌린다. **기존 데이터베이스를 재사용하지 마라.** 변형 사이 오염이 생긴다.
3. 변형마다 `model_analyzer` 와 데이터베이스 직접 조회로 위 지표를 낸다.
4. 비교표와 그림을 만든다.
   - `fig_registered.png` · 변형별 Q 등록 장수 막대
   - `fig_crossmatch.png` · 변형별 R-Q 교차 매칭 쌍 수와 인라이어 분포
5. 보고서 `_out/mixcond/REPORT-12.md`.

## 3. 시간과 자원

- **한 변형당 30 분을 넘기면 그 변형을 중단하고 「시간 초과」로 적고 다음으로 넘어가십시오.** 다섯 변형 전체 150 분이 한도입니다.
- **V0 과 V4 를 먼저 하십시오.** 이 둘만으로도 「원본을 쓰면 되는가」에 답이 나옵니다. V1 · V2 · V3 은 그 다음입니다. 시간이 모자라면 못 한 변형을 「미수행」으로 적으십시오.
- **GPU 관문.** 시작 전과 각 특징 추출 · 매칭 직전에 `nvidia-smi` 를 보고 **8,000 MiB 이상 여유가 있는 GPU** 를 골라 `--gpu_index` 에 지정하십시오. 없으면 5 분마다 확인하며 최대 60 분 기다리고, 그래도 없으면 「GPU 대기로 미수행」으로 적으십시오. 확인할 때마다 시각과 두 GPU 사용량을 로그에 남기십시오.
- 작업서 10 워커가 같은 기계에서 COLMAP 과 Brush 를 돌립니다. **한가한 쪽을 고르고 겹치지 마십시오.**
