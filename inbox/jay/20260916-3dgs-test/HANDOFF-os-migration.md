## 0. 왜 이 문서가 생겼나

### 1-1. 물리 디스크 구성 `확인됨`

**v1.0 에서 이 절을 빼먹고 디스크 문자만 보고 잘못 썼다. 2 절에서 정정한다.**

| 디스크 | 제품 | 종류 | 크기 | 쓰임 | 남은 공간 |
|---:|---|---|---:|---|---|
| 0 | ST8000DM004-2CX188 | HDD SATA | 7,452 GB | **E:** (exFAT) | 923 GB |
| 1 | WDC WD80EAZZ-00BKLB0 | HDD SATA | 7,452 GB | **G:** (NTFS) | 680 GB |
| 2 | ST8000DM004-2U9188 | HDD SATA | 7,452 GB | **H:** (exFAT) | 7 GB |
| 3 | WDC WD80EAZZ-00BKLB0 | HDD SATA | 7,452 GB | **I:** (NTFS) | 155 GB |
| **4** | **Samsung SSD 990 EVO Plus 4TB** | **SSD NVMe** | **3,726 GB** | **비어 있음** | **3,726 GB** |
| 5 | WD_BLACK SN850X 4000GB | SSD NVMe | 3,726 GB | **D:** (NTFS) · **데이터를 NAS 로 옮겨 비웠다** | 37 GB (포맷 전이라 표시상 그렇다) |
| 6 | SHPP41-2000GM | SSD NVMe | 1,863 GB | **C: · 부팅 · 시스템** | 937 GB |

**디스크 4 의 Samsung 990 EVO Plus 4TB 는 이미 장착되어 있고 완전히 비어 있다.** GPT 로 초기화만 되어 있고 16 MB 예약 파티션 하나뿐이다. 데이터 파티션도 드라이브 문자도 없다. 할당되지 않은 공간이 3,726 GB 전부다.

**ESP(EFI 시스템 파티션)는 디스크 6 의 1 번 파티션(200 MB)에 있다.** 이것이 3-2-2 절의 유일한 실제 위험과 직결된다.

### 1-1-1. 팀장이 이미 세운 계획 (2026-09-17 확인)

디스크를 어떻게 쓸지는 이미 정해져 있다. 이 문서가 그것을 몰라서 v1.0 을 잘못 썼다.

| 디스크 | 계획 | 상태 |
|---|---|---|
| **4 · Samsung 990 EVO Plus 4TB** | **우분투 전용** | 비어 있다. 준비됨 |
| **5 · WD_BLACK SN850X 4TB (D:)** | **Windows 와 우분투 공용 데이터 드라이브** | **데이터를 NAS 로 이미 옮겼고 pipeline 세션이 전수 검증했다.** 포맷은 아직 안 했다 |
| 6 · SHPP41 2TB (C:) | Windows 그대로 | 건드리지 않는다 |
| 0 ~ 3 · 8 TB HDD 4 대 (E: G: H: I:) | 그대로 | 건드리지 않는다 |

**이 구성이 맞다.** 전용 SSD 에 우분투를 올리고, 빠른 NVMe 하나를 공용으로 두는 것은 듀얼부트에서 가장 깔끔한 형태다. v1.0 이 「E: 나 G: 를 쓰라」고 한 것은 이 계획을 모르고 쓴 것이며 틀렸다.

**공용 드라이브 포맷은 exFAT 를 권한다.** 이유는 3-2-3 절에 있다.

### 1-2. 설치 안전성에 관계되는 현재 상태

| 항목 | 값 | 뜻 |
|---|---|---|
| **빠른 시작(Fast Startup)** | `HiberbootEnabled = 0` · **꺼져 있다** `확인됨` | **다행이다.** 켜져 있으면 Windows 가 NTFS 볼륨을 「사용 중」으로 남겨 리눅스에서 마운트할 때 손상 위험이 있다. 이미 꺼져 있으므로 이 위험은 없다 |
| 펌웨어 | UEFI · 모든 디스크 GPT `확인됨` | Windows 와 우분투를 UEFI 부팅 메뉴로 고를 수 있다 |
| **BitLocker** | **확인 못 함** (관리자 권한 필요) | **설치 전에 반드시 확인한다.** C: 가 암호화되어 있으면 부팅 구성이 바뀔 때 복구 키를 요구할 수 있다 |
| **보안 부팅(Secure Boot)** | **확인 못 함** (관리자 권한 필요) | **설치 전에 확인한다.** 켜져 있으면 우분투에서 NVIDIA 독점 드라이버를 넣을 때 MOK 등록 절차가 필요하다 |
| 파일 시스템 | E: · H: 는 **exFAT**, C: · D: · G: · I: 는 NTFS `확인됨` | exFAT 는 Windows 와 리눅스가 안전하게 공유하기 쉽다. NTFS 는 리눅스에서 읽기 전용을 권한다 |

> **핵심: 리눅스는 이미 있고 GPU 도 이미 잡힌다. 빠진 것은 CUDA Toolkit 하나뿐이다.**
>
> 그것은 WSL2 안에서 apt 로 넣는다. **재부팅도 파티션 작업도 필요 없고 Windows 쪽을 전혀 건드리지 않는다.**

## 2. 그래서 권고

### 2-1. 지금 (이번 주)

**WSL2 에 CUDA Toolkit 을 넣고 D 후보(PGSR 또는 2DGS) 하나를 빌드해 본다.**

- 위험이 사실상 없다. Windows 쪽 설치가 0 이다
- 실패해도 WSL 배포판만 되돌리면 된다
- 이것으로 「리눅스가 필요하다」는 가설 자체를 싸게 검증한다

**주의 하나.** WSL 안에 NVIDIA 드라이버를 설치하면 안 된다. Windows 쪽 드라이버가 WSL 로 전달되는 구조이고, 안에 또 설치하면 깨진다. CUDA Toolkit 만 넣는다.

**주의 둘.** 작업 파일은 WSL 내부 디스크(`/`)에 둔다. `/mnt/c` 를 거치면 파일 입출력이 눈에 띄게 느리다.

### 2-2. 다음 (실기 단계 진입 전)

**네이티브 우분투가 실제로 필요해지는 시점은 ROS 2 Jazzy 로 실기를 붙일 때다.** 그때까지는 WSL2 로 버틴다.

그리고 그때가 와도 **이 머신을 듀얼부트로 만드는 것보다 두 번째 머신을 두는 쪽을 권한다.** 이유는 3 절.

## 3. 왜 이 머신에 듀얼부트를 권하지 않는가

### 3-1. 가장 큰 비용은 「동시에 못 쓴다」는 것이다

이 머신 하나에 지금 이것들이 모여 있다.

| 무엇 | 비고 |
|---|---|
| Isaac Sim 5.1 + Isaac Lab + `isaac311` | 팀의 유일한 학습 · 평가 환경 |
| 학습된 정책(`foothold-v1.pt` 등)과 평가 결과 | |
| **Orca 오케스트레이션과 워크트리 여럿** | lead · super · 3DGS PoC · 인지 세션이 지금 이 순간 돌고 있다 |
| 브랜드 런칭 영상 파이프라인 | Isaac previs 렌더 · Higgsfield |
| 3DGS PoC 원자료 3.1 GB | |
| COLMAP 4.2.0 · Brush · 3DGRUT 사본 | |

**우분투로 부팅하는 동안 이 전부가 멈춘다.** 죽는 것이 아니라 안 돌아간다. 지금처럼 여러 세션이 병렬로 작업하는 상황에서는 이 비용이 크다.

### 3-2. 팀장이 걱정한 「Orca 세션 소실」에 대한 정확한 답

**멀티부트 자체가 무엇을 지우지는 않는다.** 아래는 전부 NTFS 위의 파일이다.

```
C:/Users/AI-WS01/orca/workspaces/foothold-lab/...   Orca 워크트리(체크아웃)
C:/Users/AI-WS01/.orca/                              Orca 설정
C:/Users/AI-WS01/.claude/projects/.../*.jsonl        Claude Code 세션 기록
C:/Users/AI-WS01/Desktop/jay/.../foothold-lab        메인 체크아웃
```

파티션을 건드리지 않고 빈 드라이브에 설치하면 이것들은 그대로 남는다.

### 3-2-1. v1.0 의 오류를 정정한다

**v1.0 에서 「C: 를 축소하지 말고 E: 나 G: 를 통째로 우분투에 준다」고 썼다. 틀렸다.** 팀장이 지적했고 맞다. 물리 디스크를 보지 않고 드라이브 문자만 보고 쓴 것이다.

| v1.0 에서 쓴 것 | 왜 틀렸나 |
|---|---|
| 「C: 를 축소하지 않는다」 | **축소할 일 자체가 없다.** 디스크 4 에 비어 있는 NVMe 4 TB 가 이미 꽂혀 있다 |
| 「E: 나 G: 를 우분투에 준다」 | **둘 다 8 TB SATA HDD 이고 데이터가 6.5 TB 넘게 들어 있다.** 지우면 팀 자료가 날아가고, 설령 비었어도 OS 를 회전 디스크에 두는 것은 NVMe 를 두고 할 선택이 아니다 |
| 공용 드라이브 계획을 몰랐다 | D: 의 데이터가 이미 NAS 로 옮겨져 공용 드라이브로 쓸 준비가 되어 있다는 것을 모르고 「리눅스에서는 NTFS 를 읽기 전용으로만」이라고만 적었다. 공용 드라이브가 있으면 그 제약이 크게 풀린다 |

**맞는 계획: 우분투는 디스크 4(Samsung 990 EVO Plus 4TB) 에 통째로 설치한다.**

- **C: 와 HDD 4 대는 하나도 건드리지 않는다.** 파티션 축소가 없다
- 이것이 듀얼부트 중 가장 안전한 형태다. 전용 물리 디스크에 설치하는 것
- 4 TB 면 우분투 · CUDA · Isaac Sim(리눅스판)을 다 넣고도 남는다. 큰 데이터는 공용 드라이브에 둔다
- 이 디스크의 존재는 pipeline 세션도 알고 있다(팀장 확인)

**포맷하는 것은 D: 하나뿐이고, 그것은 이미 비워 둔 드라이브다.** 데이터를 NAS 로 옮기고 pipeline 세션이 전수 검증했다(팀장 확인). **포맷 직전에 NAS 사본을 한 번 더 확인하는 것을 권한다.** 되돌릴 수 없는 유일한 단계이기 때문이다.

### 3-2-2. 그래서 남는 실제 위험

전용 디스크를 쓰면 위험이 크게 줄지만 **0 은 아니다.** 남는 것은 셋이다.

| 위험 | 내용 | 대응 |
|---|---|---|
| **부트로더가 Windows 디스크를 건드린다** | ESP 가 **디스크 6(C: 부팅 디스크)** 에 있다. 우분투 설치 프로그램은 기본적으로 기존 ESP 를 찾아 GRUB 을 거기 쓴다. **이것이 유일한 「Windows 디스크에 쓰는」 단계다** | 설치 중 **디스크 4 에 ESP 를 새로 만들고 부트로더 대상을 디스크 4 로 지정**한다. OS 전환은 GRUB 이 아니라 **UEFI 부팅 메뉴(F 키)** 로 한다. 그러면 Windows 부팅 경로가 그대로 남는다 |
| **부팅 중에는 안 돌아간다** | 3-1 절 | **이것이 근본 비용이고 전용 디스크로도 사라지지 않는다** |
| **리눅스에서 Windows 저장소에 쓰기** | 읽기는 안전하나 **활성 git 저장소에 리눅스에서 쓰는 것은 위험**하다. 권한 · 줄바꿈 · 파일 잠금이 어긋난다 | C: 를 비롯한 Windows 볼륨은 리눅스에서 **읽기 전용으로만** 마운트한다. 주고받을 것은 **공용 드라이브(D:)** 를 쓴다(3-2-3 절) |

**설치 전에 확인할 것 둘** (1-2 절). 관리자 권한이 없어 이 세션이 확인하지 못했다.

- **BitLocker**: C: 가 암호화되어 있으면 부팅 구성 변경 시 복구 키를 요구할 수 있다. 켜져 있으면 **복구 키를 먼저 확보**한다
- **보안 부팅**: 켜져 있으면 우분투에서 NVIDIA 독점 드라이버 설치 시 MOK 등록이 필요하다. 끄거나 등록 절차를 준비한다

**빠른 시작은 이미 꺼져 있다** `확인됨`. 흔한 함정 하나가 이미 없다.

### 3-2-3. 공용 드라이브(D:) 를 어떤 형식으로 포맷할 것인가

팀장 계획대로 D: 를 Windows 와 우분투 공용으로 쓴다면 형식 선택이 남는다. **아직 포맷 전이므로 지금 정하면 된다.**

| 형식 | Windows | 리눅스 | 판정 |
|---|---|---|---|
| **exFAT** | 기본 지원 | 커널에 드라이버 내장(5.4+). 양쪽에서 읽고 쓴다 | **권장.** 두 운영체제가 대등하게 쓴다 |
| NTFS | 기본 | `ntfs3` 로 쓰기가 되지만 권한 모델이 맞지 않는다 | 차선 |
| ext4 | **기본으로 못 읽는다** | 기본 | 공용 목적에 맞지 않는다 |

**다만 exFAT 에는 한계가 있다.** 이것을 알고 써야 한다.

- **유닉스 권한과 심볼릭 링크가 없다.** 그래서 **git 저장소를 여기 두면 안 된다.** 실행 권한과 링크가 사라져 리눅스 쪽에서 문제가 생긴다
- 저널이 없어 갑작스러운 전원 차단에 약하다
- 대량의 작은 파일에 느리다

**그래서 공용 드라이브의 용도를 이렇게 나눈다.**

| 둘 것 | 두지 말 것 |
|---|---|
| 촬영 원본 영상 · 사진 | **git 저장소** (양쪽에 따로 clone 한다) |
| 프레임 · 점구름 · PLY · 메시 · USD | conda / venv 환경 |
| 학습 체크포인트 · 데이터셋 | 심볼릭 링크가 필요한 것 |
| 렌더 결과 · 영상 | |

**즉 「큰 산출물은 공용, 코드와 환경은 각자」** 가 원칙이다. 저장소 규칙이 이미 대용량 산출물을 커밋하지 않고 경로만 기록하게 되어 있으므로 이 구성과 잘 맞는다.

**그리고 하나 더.** **Orca 는 이 머신에서 Windows 앱으로 돌고 있다.** 우분투로 부팅하면 Orca 자체가 없다. 리눅스용 Orca 가 있는지는 **미확인**이며, 이전을 결정하기 전에 반드시 확인해야 한다. 지금의 멀티 세션 오케스트레이션 방식이 통째로 달라질 수 있기 때문이다.

### 3-3. 두 번째 머신이 나은 이유

- 두 환경을 **동시에** 쓴다. 학습은 Windows 에서 계속 돌고 복원 실험은 리눅스에서 돈다
- 실기(ROS 2)는 어차피 로봇 옆에 둘 머신이 필요하다
- 이전 실패의 되돌림 비용이 0 이다
- GPU 가 필요 없는 ROS 2 작업이라면 사양이 낮아도 된다

**다만 이 머신에는 이미 빈 NVMe 4 TB 가 꽂혀 있다.** 그래서 「새 머신이냐 이 머신 듀얼부트냐」의 위험 차이가 v1.0 에서 생각한 것보다 작다. 3-2-2 절 수준으로 내려왔기 때문이다.

**그래도 3-1 절의 「동시에 못 쓴다」는 남는다.** 지금 이 머신에서 세션 넷이 병렬로 돌고 GPU 작업도 돈다. 그것이 판단의 중심이고, 전용 디스크로도 사라지지 않는다.

**정리하면 이렇다.** 디스크가 준비되어 있으므로 **설치 자체의 위험은 낮다.** 남은 것은 순수하게 운영 문제, 즉 「부팅을 갈아탈 때마다 이 머신의 모든 세션이 멈추는 것을 감당할 수 있는가」다. 실기 단계에 로봇 옆에 둘 머신이 어차피 필요하다면 그쪽에 우분투를 두는 것이 낫고, 그렇지 않다면 디스크 4 에 설치하는 것이 합리적이다.

## 4. WSL2 의 한계 · 정직하게

WSL2 가 만능은 아니다. 아래는 **미확인**이며, 실기 단계 전에 실측해서 이 문서에 채워야 한다.

| 항목 | 우려 | 상태 |
|---|---|---|
| Isaac Sim GUI | WSLg 로 되기는 하나 RTX 렌더 성능과 안정성이 네이티브보다 떨어질 수 있다 | `미확인` |
| GPU 2 장 활용 | 멀티 GPU 학습(NCCL)이 WSL2 에서 제대로 되는지 | `미확인` |
| ROS 2 실시간성 | systemd · 실시간 스케줄링 · 네트워크(DDS 멀티캐스트)에 제약이 있을 수 있다 | `미확인` |
| USB 장치 | 실기 로봇 · 센서 연결은 usbipd 를 거쳐야 한다 | `미확인` |
| 파일 입출력 | `/mnt/c` 경유가 느리다 | 알려진 사실 |

**ROS 2 실기가 WSL2 에서 제대로 안 된다면 그때가 네이티브 우분투로 가는 시점이다.** 그 판단을 위한 시험을 실기 일정이 잡히면 넣는다.
