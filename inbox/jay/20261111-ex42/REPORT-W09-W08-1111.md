## 명령과 산출

runner 사슬은 E1 P1 m1000 PASS와 manifest에 적힌 모델 SHA, 평가 메시 SHA를 확인한 뒤 아래 한 줄을 **고정 사본**에서 부른다. 변수는 모두 실제 영수증에서 읽어 채워야 한다. `E1_EVAL_PLAN` 은 깃발 칸이 든 평가 plan이며, 이전 E1 학습 source plan과 혼동하면 안 된다.

```bash
cd "$FIXED_REPO" && "$ISAAC311_PYTHON" -m foothold_s2.scripts.ex42_flag_baseline_chain --checkpoint "$E1_RUN/model_1000.pt" --expected-checkpoint-sha256 "$E1_MODEL_SHA" --e1-gate "$E1_RUN/eval/scores/m1000/p1_score.json" --plan "$E1_EVAL_PLAN" --mesh-dir "$E1_EVAL_MESH_DIR" --expected-mesh-sha256 "$E1_EVAL_MESH_SHA" --device cuda:1 --out "$E1_RUN/eval/w09-w08-$SOURCE_HEAD" --execute
```

기동 전 `FOOTHOLD_MACHINE_PROFILE`, `ISAACLAB_ROOT` 등은 `~/mai/foothold-linux.env` 에서, `PYTHONPATH` 는 고정 사본 뿌리에서 설정한다. `--execute` 를 빼면 GPU 조회·Kit 실행·출력 디렉터리 생성 없이 여섯 회차, 12개 자식 argv를 JSON으로 인쇄한다. E1 졸업 PASS, checkpoint manifest SHA, 메시 SHA, 새 출력 경로를 만족하지 않으면 시작 전 거절한다.

순서는 W09 seed 42 깃발 한 개·네 개, W08 seed 42·42·43·44·45 각각 깃발 한 개·네 개다. 매 자식의 `flag_cells.json`, NPZ, 건별 JSON을 다시 읽어 정답·복원·끔 세 모드와 물리 GPU UUID를 확인한 뒤 다음 자식으로 간다. 중간 실패는 해당 `round_receipt.json` 및 `chain_receipt.json`에 HOLD를 쓰며 기준선·calibration 완료표지를 쓰지 않는다.

완료 때 `w09_baseline.json`은 네 판정 칸의 원자료 경로·SHA·성공·생존 수와 두 자식 영수증 SHA를 담는다. `w08_calibration.json`은 `summarize_repeats`의 정규 형식 `foothold-ex42-flag-calibration/1` 그대로라 E1F judge가 다섯 원자료를 다시 센다. `w08_proposed_q4.json`은 별도로 `max(가정 3, 반복 폭 × 2)`를 셀별로 기록한다. 이 수는 **제안값이며 E1F 출구 문턱에 자동 적용하지 않는다**. `chain_receipt.json`은 W09와 W08 파일 경로·SHA 및 12 자식 순서를 묶는다.

## 검증과 남은 연결

isaac311 CPU에서 알려진 64 env 전성공·한 회 실패·원자료 변조·잘못된 E1 판정·다섯 반복 결측·DRY 무 GPU·여섯 회 12 자식 순서·SHA 재집계를 시험했다. `test_ex42_flag_baseline_chain_cpu.py`와 E1F 관련 시험 합계 24 passed. 실제 Kit 시간, W09 수치, W08 반복 폭은 **미측정**이다.

runner 사슬에 이 명령을 연결하고, W08 완료 뒤 `w08_calibration.json` 경로·SHA를 materialized E1F plan에 고정하는 절차는 runner·verifier 소유다. 현재 기존 materializer는 flag calibration 자동 재핀 경로가 없으므로 이 산출만으로 E1F 무인 시작을 선언할 수 없다.
