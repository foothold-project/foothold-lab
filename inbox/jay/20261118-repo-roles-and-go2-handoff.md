# 저장소 역할과 실기 인수인계

모든 세션 (Claude · Codex · 숙소 `ai-lx01` · 학원 `ai-lt01`) 이 이 문서를 같은 규칙으로 읽는다.

## 1. 세 저장소가 하는 일

| 저장소 | 하는 일 | 하지 않는 일 | 주로 쓰는 세션 |
|---|---|---|---|
| `foothold-lab` (비공개) | 시뮬 학습 실험 · 결정 원장 · 정책 정본 (`inbox/jay/20261103-policy-handoff/`) · 실기 측정 원본과 기록 · 인수인계 문서 | 배포 코드 | lead-lx (시뮬 실험) · planner-lx · sonnet-code-lx |
| `foothold-go2` (공개) | 실기 Go2 X · Jetson 에서 도는 로봇 쪽 프로그램 · 저수준 제어기 · 정책 실행기 · 안전 관문 · 최종 배포 | 앱 코드 복사 · 학습 실험 · 측정 원본 · 주소와 serial | go2-lx (새 세션) |
| `foothold-app` | 앱 (서버 · 웹 · 모바일). 오현민이 `dev` 에서 개발 · 검토와 병합은 팀장 | 로봇 쪽 저수준 제어 | 오현민 · 팀장 |

- 앱과 로봇은 앱 저장소의 `contracts/` 입출력 약속으로 잇는다. `foothold-go2` 는 앱의 특정 태그를 가리키기만 하고 코드를 복사하지 않는다.
- 정책은 `foothold-lab` 이 원본이다. `foothold-go2` 에는 바이트 그대로 사본만 두고 `SHA256SUMS` 로 대조한다. contract · 관절 순서 · action scale · PD 값은 추측으로 바꾸지 않는다 (팀장 2026-11-18 15:48).
- **모든 프로젝트의 최종 승인자는 팀장 (오흥재) 이다** (팀장 2026-11-19 00:21). 병합 · 배포 · 로봇 명령의 승인은 팀장이 한다.
- `foothold-go2` 는 공개 저장소라 정책 파일을 올리는 것은 팀장 승인 뒤에 한다 (팀원 정책 포함 · 팀장이 진행하라고 하면 진행).

## 2. foothold-app 을 보고 고치는 길

| 할 일 | 어떻게 |
|---|---|
| 현민의 최신본 보기 | `ai-lx01` 의 읽기 전용 거울 `/home/jay/mai/wt/foothold-app/app-dev-view` (10 분마다 `origin/dev` 로 맞춤 · user timer `foothold-app-dev-view.timer` · 기록 `/home/jay/mai/tmp/lead/app_dev_view_sync.log`). 거울에서는 파일을 고치지 않는다. 고친 흔적이 있으면 맞추기를 멈춘다 |
| 팀장 · 현민이 고치기 | 둘 다 `dev` 에서 `feature/<작업>-<이름>` 가지를 따서 고치고 `dev` 로 PR. **검토와 병합은 팀장이 한다** (팀장 2026-11-19 00:21 · 최종 승인자). `dev` 에 직접 push 하지 않는다 |
| 같은 파일을 둘이 고칠 때 | PR 설명에 바뀐 파일과 까닭을 적고, 상대가 고치는 중인 파일이면 먼저 알린다 |
| main | 현민이 정한 때에 `dev` 에서 올린다. 11/18 기준 main 은 10/21 에 멈춰 있다 |

다른 기기 (학원) 에서는 `git fetch origin && git switch --detach origin/dev` 로 같은 것을 본다.

## 3. 실기 Go2 X 인수인계: 정본 입구는 이슈 하나

- **정본 입구**: `foothold-lab` 의 실기 연속 작업 이슈 하나 #861 「실기 Go2 X 연속 작업 (정본 입구)」 (https://github.com/foothold-project/foothold-lab/issues/861). 이슈 본문 맨 위 「지금 상태」 칸이 언제나 최신이다.
- **세션이 일을 마칠 때**: 이슈 본문의 「지금 상태」 칸을 고쳐 쓰고 (덧붙이지 않고 바꿈), 그날 한 일은 댓글로 남긴다. 측정 원본은 `foothold-lab` assets 로 PR 병합한 뒤 그 주소를 적는다.
- **세션이 일을 시작할 때** (숙소든 학원이든):

```text
foothold-lab main 을 pull 하고 이슈 #861 본문의 「지금 상태」 칸과 최신 댓글 셋을 읽어라.
본문이 가리키는 인수인계 문서와 foothold-go2 AGENTS.md 1a · 5a · 5b 절을 읽어라.
시작 보고에는 지금 상태 · 확정된 안전선 · 다음 한 단계만 적어라.
```

- 긴 내용 (장비 표 · 측정 순서 · 금지선) 은 `inbox/jay/20261118-go2-x-ai-lx01-handoff.md` 처럼 문서로 두고 이슈 본문은 그 주소와 「지금 상태」 만 가진다. 대화 기억이나 기기 안 파일을 정본으로 쓰지 않는다.

## 4. 기기 사이 규칙

| 항목 | 규칙 |
|---|---|
| 코드 · 기록 | git 으로만 오간다. 일 끝에 push, 다른 기기에서 pull |
| SSH | 기기마다 따로 키를 만들고 공개키만 Jetson `~/.ssh/authorized_keys` 에 더한다. 개인키는 옮기지 않는다. 기기마다 한 줄이라 숙소 키와 학원 키가 함께 등록되어도 부딪히지 않는다 |
| 직결 주소 | 랜선 직결에서 컴퓨터 쪽 주소는 `192.168.50.1` 하나다. 그래서 랜선은 한 번에 한 컴퓨터만 Jetson 에 꽂는다 (숙소 `ai-lx01` 이 꽂혀 있는 동안 학원 `ai-lt01` 도 같은 주소로 직결하지 않는다). Tailscale · Wi-Fi 로는 두 컴퓨터가 동시에 접속해도 된다 |
| 원격 접속 | 권고: Jetson 을 Tailscale 에 넣는다 (숙소 `ai-lx01` · 학원 `ai-lt01` 은 이미 같은 tailnet). 그러면 어느 망에 있든 같은 이름으로 SSH · NoMachine · 데이터 회수가 된다. 팀장 설치 동의 (2026-11-19 00:21) |
| 실시간 제어 | 저수준 제어 고리는 Jetson 안에서만 돈다. 망 너머 (Wi-Fi · Tailscale) 로는 보기 · 기록 · 시작과 정지 명령만 |

## 5. 실기 안전선

`foothold-go2` AGENTS.md 5a 절이 정본이다. 요지: 로봇 명령은 팀장 동의 아래 (동의한 명령은 AI 도 보냄) · 저수준 정책은 팀장 동의 + 업체 열 판정 · E-stop · 2 인 매달기 관문 뒤 · 움직임 명령을 보내는 프로그램은 한 순간에 하나 · 로봇 명령 서비스는 부팅 자동 시작 대신 손으로 켠다 (팀장 승인).
