### 크기 비율의 계산식과 한계

`[가정]` 대표 길이는 다리 길이, 동일 중력, 비슷한 질량 분포·관절 궤적·접촉 자세이며 동적 상사에서는 시간 척도 `T=√(L/g)`를 쓴다. 실제 두 로봇의 몸 폭·발 반지름·관성 배분·모터 한계는 상사하지 않으므로 **다음 값은 비교 기준이지 실제 정책 비용의 예측값이 아니다.**

`[계산] μ=mG/mL=15.018999692/9.038=1.661761`, `λ=LG/LL=0.213/0.200=1.065`, `t=T_G/T_L=√λ=1.031988`.

- 중력 지지 토크 척도: `[계산] τG/τL≈μλ=1.769776`, 제곱은 `3.132107`. lead의 약 `3.1배`는 이 조건에서는 맞다. 단순 질량 제곱도 아니고 실제 토크 시계열을 잰 결과도 아니다.
- 같은 관절 궤적을 같은 초 단위 속도로 움직이면 관성 토크 척도는 `μλ²`이고 중력 항은 `μλ`다. 실제 링크 관성·접촉 Jacobian이 다르면 한 배수로 합칠 수 없다. 일반식은 `τ=M(q)q̈+C(q,q̇)+g(q)+J(q)ᵀF`다.
- 동적 상사의 일률 척도는 `[계산] μ√λ=1.714918`, 수직 속도 제곱은 `λ=1.065`, 각속도 제곱은 `1/λ=0.938967`, 관절 가속도 제곱은 `1/λ²=0.881659`다.
- 반대로 **같은 토크 한계 사용률**에서는 hip/thigh 토크 제곱 비가 `[계산] (23.5/40)²=0.345156`, calf는 `(45.43/65)²=0.488493`다. 전 관절 정지 상한 제곱합 비는 `(8×23.5²+4×45.43²)/(8×40²+4×65²)=0.426719`. 즉 “Go2는 언제나 더 큰 토크 벌점”은 거짓이다. DCMotor의 움직이는 상한은 이 정지 상한보다 더 제한될 수 있다.
- 같은 raw action·같은 위치 오차에서 Go2 P 성분은 `[계산] 25/30=0.833333`, D 성분은 `0.5/0.8=0.625`다. 같은 기하 자세의 중력 부하를 버티는 위치 오차는 대략 `[계산] (μλ)/(25/30)=2.123731배`가 필요하다. PD·action을 무시한 가중치 이식은 이 항을 빠뜨린다.
- 동적 상사로 MGDP 제어기를 옮긴다면 `[계산] Kp≈53.0933`, `Kd≈1.46111`이지만 **권장 설정값이 아니다**. MGDP가 START 제어기라는 증거가 없고 Go2 토크 한계가 더 낮아 포화·진동·접촉 불안정을 키울 수 있다. 먼저 target 오차·토크 사용률·포화 비율을 기록해야 한다.

## START 보상 항별 의도·단위·이식

P:145~156의 `[논문] 14항`과 Q:81~91의 `[선행] 14항`을 대조했다. P:233~257은 단순 보상 계보와 가장자리 의도만 설명한다. 각 일반 항의 “왜”는 수식과 구현에서 읽은 **기능적 해석**이며, 저자가 가중치를 정한 실험 과정까지 밝혔다는 뜻은 아니다. 항별 최적성·필수성을 보여 주는 제거 실험은 일반 항마다 제시되지 않았다.

계보는 P:590의 Rudin 등과 [공식 legged_gym 보상 구현](https://github.com/leggedrobotics/legged_gym/blob/master/legged_gym/envs/base/legged_robot.py#L815)에서 확인한다. 공식 구현의 수직 속도·수평 각속도·자세·토크·가속도·행동 변화·접촉·추종·걸림 함수가 대응한다. 다만 START의 min 추종, 행동 이차 차분, 일률, 관절 오차 L2, 발 가장자리가 모두 그 원본의 동일 함수인 것은 아니다. 로컬 MGDP도 수정된 후손이므로 START 소스 그 자체로 취급하지 않는다.

아래 크기 비는 **앞 절의 동적 상사 가정과 같은 raw action 배율**에서의 원시 비용 비다. 이 가정을 채택하지 않으면 실제 비는 미측정이다. 가중치는 보상률을 만드는 역단위 계수이며, raw 항의 단위와 분리한다. rad는 관절각 단위 표기를 남겼다.

### 숫자가 같아도 보상이 달라지는 구현 차이

1. **선속도 min과 대칭식.** `[계산] c=0.5, v=1.0 m/s`에서 논문 A식 추종은 `1.5`, S1 B식은 `1.5e^(−1)=0.551819`다. `[계산] c=−0.5, v=0`에 raw min을 쓰면 완전 추종 `1.5`가 나와 후진을 안 해도 보상한다. `vy=0`에도 성분별 min을 적용하면 한쪽 옆 미끄럼만 허용한다. 논문의 스칼라 전진식인지 벡터 범위인지 실행 소스 없이는 확정할 수 없다. 원문을 명분으로 열린 명령에 그대로 복사하지 않는다.
2. **std와 분모.** P의 `[논문] 0.25`는 지수의 분모이고 S1 std는 `[코드] 0.5`라 제곱하면 일치한다. D2의 std `[코드] 0.25`는 분모 `[계산] 0.0625`다. 논문 숫자를 그대로 넣은 수정이 아니라 추종 폭을 좁힌 실험이다. 정지·yaw 정합에서 `[계산] c=0.5`이면 원래 추종 합 `1.5exp(−1)+0.5=1.051819`, 좁힌 선속도 항을 쓰면 `1.5exp(−4)+0.5=0.527473`다. 이것만으로 학습 최적해를 확정할 수는 없다.
3. **가속도.** ML:1044는 이전 정책 스텝 관절 속도 차이를 정책 dt로 나눈다. 설치 Isaac의 `I/assets/articulation/articulation_data.py:97~102·772~781`은 매 physics update마다 차분을 갱신하고, `I/envs/manager_based_rl_env.py:183~197`은 매 물리 서브스텝에 scene을 갱신한다. E:21·84의 `[코드] physics dt=0.005 s`, decimation `[코드] 4`이므로 정책 간격은 `[계산] 0.02 s`다. 같은 총 속도 변화가 마지막 서브스텝에 몰리는 답 아는 예에서는 `[계산] 가속도 4배·제곱 16배`가 된다. 매 서브스텝 일정 가속도면 `[계산] 비 1`이다. 따라서 항상 16배라고 말하지 않는다. 현재 값은 마지막 물리 차분 표본이라 충격·aliasing에 민감하다. START 실제 코드 미확인 상태에서 이 항의 계산 동등성을 먼저 고정해야 한다.
4. **시간 적분.** I/managers/reward_manager.py:150은 가중치×raw항×dt, :157은 진단 `_step_reward`를 다시 dt로 나눈 보상률이다. ML:671도 weight에 dt를 곱한다. `D/rw_*/rewards.json`의 값은 스텝당 적분 보상이 아니라 이 보상률 평균이다. 로그의 episode 정규화와도 분리한다. START의 total reward clip 여부·실제 dt 계약은 본문으로 확정 못 한다.
5. **제어기와 관측 이력.** E와 B의 기본 Kp·Kd·action scale은 같지만 calf 한계와 지연·DR은 다르다. A:11의 action clip은 null이다. Rx1은 clip `[코드] 17` 등을 추가했다. raw action `[계산] 17×0.25=4.25 rad`는 관절 한계 내 안전한 목표각 보장이 아니다. raw action, processed target, 실제 q, 토크 포화를 따로 기록해야 한다.

### 정지·회전 노출은 실제로 얼마인가

`S/foothold_s2/commands/mixed_core.py:29~35·110~130`에서 자유 가지의 `[코드] stand=0.1`, 이후 spin은 정지를 제외한 `[코드] 0.2`다. 자유 env 내 합은 `[계산] 0.1+0.9×0.2=0.28`, 전체 중 자유 env `[코드] 약 0.8`을 적용하면 `[계산] 약 22.4%`다. 깃발의 작은 속도 회전과 축 마스크로 생긴 영 선속도는 별도다. 따라서 “25%”는 정확히 정의된 전체 시간 노출률이 아니다.

### 원래 보상×명령 설계가 할 수 있는 것

보상 `{START 계열,NVIDIA}` × 명령 `{START 조건부 회전,우리 명령}`의 `[가정] 2×2`는 **나머지를 동일하게 고정하면** 보상 묶음과 명령 묶음의 효과 및 그 상호작용을 분리하는 최소 셀 구조다. 성능 `Y`에 대해 `[계산] I=(Y_START,ours−Y_START,paper)−(Y_NV,ours−Y_NV,paper)`가 상호작용 대비다. 각 셀 한 학습만 있으면 잔차 자유도가 없어 seed 변동과 효과를 구별하지 못한다. 다수 평가 episode는 이 문제를 해결하지 않는다.

| 사전 등록할 결과 패턴 | 허용 결론 | 금지할 결론 |
|---|---|---|
| START+논문 명령은 통과, START+우리 명령은 실패 | 고정한 scaffold에서 명령 묶음과 성능 차이가 연관. 반복 시 명령 처치 효과 지지 | START 전체 재현 성공, stop/spin 비율 하나가 원인 |
| START 양쪽 실패, NVIDIA 양쪽 통과 | 이 scaffold에서 보상 묶음 차이의 효과 지지 | START가 Go2에 부적합, 토크 하나만 바꾸면 해결 |
| 우리 명령에서만 두 보상 차이가 커짐 | 보상×명령 상호작용 후보 | 다른 지형·관측·학습 길이에서도 동일 |
| 모두 실패 | 공통 관측·제어·측정·학습 예산·환경부터 의심 | NVIDIA는 원래 통과해야 하므로 환경만 원인 |
| 모두 통과 | 이 조건에서 기본 보행 가능 | sparse·열린 명령 전체 목표와 sim-to-real까지 통과 |

기존 S1-a 셀을 재사용하고 새 판만 `[가정] 3개` 돌리려면 저장된 동일 회차 checkpoint에 대해 모든 나머지 조건이 같아야 한다. 공통 fbg `[코드] 0.25`, clip `[코드] 17`, 새로운 가속도 계약 등을 넣는다면 옛 S1-a는 같은 셀이 아니다. **새 기준 run이 필요해 `[계산] 최소 4개 셀`이 된다.** v2는 pretrained·관측·모터·DR·지형이 달라 NVIDIA 셀로 대입할 수 없다. “NVIDIA 쪽 기준”에서 이 요소까지 바꾸면 factorial이 아니라 두 전체 시스템 비교다.

### 권고: START를 유지하고 명령×속도 정보를 먼저 분리

이번 문제에서는 보상 계열 교체보다 START의 빠진 속도 정보 경로가 먼저다. 보상은 현재 START 계열로 고정하고, scan에 한정해 아래 셀을 권고한다. NVIDIA/v2는 측정기의 정상 보행 참고군으로만 쓴다. 이 선택은 START를 버리는 것이 아니라 그 구조적 전제를 복구하는 진단이다.

| 판 | 명령 | actor의 속도 정보 | 사전 예측과 판정 |
|---|---|---|---|
| C0O0 · 새 대조 | 우리 명령 | 현 S1 scan MLP | 같은 문제 재현 여부. 재현 안 되면 공통 수정·seed·평가 차이를 먼저 점검 |
| C1O0 | 논문 조건부 회전 명령 | 현 S1 scan MLP | C0O0보다 정상 자세/지속 보행이 개선되면 명령 묶음 부담 지지. 실패해도 START 실패 아님 |
| C0O1 | 우리 명령 | 진짜 base velocity를 명시 입력한 oracle | C0O0보다 개선되면 속도 정보 또는 그 입력이 주는 표현상 이득 지지. 센서 없이 배포 가능하다는 결론은 금지 |
| C1O1 | 논문 조건부 회전 명령 | 같은 oracle | 이것만 개선되면 명령과 정보의 결합 효과 후보. 앞 두 단독 처치 실패를 이유로 속도·명령 가설을 모두 버리지 않음 |

`[가정] O0`에도 같은 크기의 영 velocity 슬롯을 두어 네트워크 차원·파라미터 수를 맞춘다. 정규화·잡음·스케일은 동일하게 고정하고 O1의 속도만 실제값으로 바꾼다. 영 슬롯 때문에 옛 S1 checkpoint를 그대로 같은 대조라고 부를 수 없다. O1 성공 후에는 GT를 없애고 START식 시간 이력·속도 추정기로 대체하는 별도 검증이 필요하다.

공통 고정 조건은 다음과 같다.

- `[가정]` S1의 지형·기본 자세·모터·PD·DR·학습 초기화·PPO·환경 수·step 수·보상식·clip·종료·평가 코드를 모두 하나의 manifest로 고정한다. 알려진 구현 수정은 **모든 셀에 동일 적용**하고 새 기준을 둔다. 수정 내용이 불명확하면 학습을 시작하지 않는다.
- `[가정]` 명령 효과 진단에서는 현재 B 추종식을 양쪽에 유지한다. 그래야 command만 바뀐다. 이것을 “START 충실 재현”이라고 부르지 않고 “START 명령 처치”로 부른다. 논문의 A 추종식 효과는 전진 중심 조건에서 별도 비교한다. 후진에 raw min을 적용하는 판은 만들지 않는다.
- `[가정]` command 재표집은 공통 `4 s`로 고정한다. START 실제 주기는 미확인이므로 선택한 실험 조건으로 명시한다. 명령 처치는 분포·방향 묶음 효과이며 stop/spin 하나의 효과가 아니다. 그 원인을 더 좁힐 때만 같은 정지·회전 질량을 맞춘 후 옆·뒤 성분을 나누는 후속 판을 만든다.
- `[가정]` 먼저 같은 seed의 셀들을 짝지어 pilot `1500 update`까지 확인하되 **불통과를 수렴 실패로 확정하지 않는다**. 원 논문 `[논문] 약 10000 update`와 달리 초기 학습이다. 개선 가능성이 있는 셀·대조는 같은 경험량의 다음 고정 checkpoint까지 함께 연장하고, 최소 `[가정] 2개`, 가능하면 `3개` 학습 seed에서 방향을 확인한다. 단일 seed pilot은 탐색 결과라고 명시한다.
- `[가정]` 각 checkpoint마다 deterministic과 stochastic 평가를 같은 명령·같은 지형 seed로 분리한다. 영 명령 PD 유지와 NN 영 명령은 다른 대조다. 건강 검사에서는 NaN, action 증가, target/토크 포화, 접촉 시작, obs 계약을 먼저 본다. 실패 사건·검열된 run을 삭제하지 않는다.

**두 GPU에 두 판만 먼저 올리는 경우의 권고**는 같은 scan scaffold의 C0O0와 C1O0를 짝으로 두고 나머지 두 셀을 뒤에 완성하는 것이다. A0-scan과 A0-blind를 동시에 놓으면 각 modality에서 명령 전환의 대조가 부족하고, 원인이 다른 scan/blind 문제를 섞기 쉽다. 분석 중 어떤 두 판도 실행하지 않았다. 결과가 급해도 원래 대조가 빠진 채 다음 명령 확장이나 본 학습으로 승격하지 않는다.

### 크기 보정 축과 완전한 START 재현은 어디에 두나

Go2 크기 보정은 빠진 축이 맞지만, 곧바로 모든 가중치를 바꾸는 세 번째 factor로 늘리지 않는다. 먼저 **같은 보상 계산 계약**에서 raw torque·power·acceleration·포화 분포를 얻는다. 다음 중 목적을 하나 사전 선택한다.

| 후속 판 | 고정·변경 | 사전 예측 |
|---|---|---|
| 부하 상사 토크 판 | 나머지 고정, `[가정·계산] −1e−5 → −3.192739e−6`만 변경 | 과벌 가설이면 진행/보행 회복과 함께 정상화될 수 있음. raw torque·포화만 증가하고 보행은 그대로면 유용한 처방 아님 |
| C1형 토크 판 | 나머지 고정, `[가정] −2e−4`로 강화 | 약한 노력 벌점이 불필요한 큰 모멘트 자세를 허용했다면 torque 사용과 crouch가 함께 줄어야 함. 정지만 늘면 같은 가설의 단순 처방은 지지 못 함 |
| 동적 상사 비용 묶음 | 앞 표의 torque·power·속도·가속도 후보를 사전 등록한 묶음으로 변경 | 전체 이식 체계의 성능은 보지만 항별 원인은 못 가름. 단독 처치가 효과 없고 결합 가설이 남을 때만 단독판과 공통 대조를 함께 유지 |

위 숫자는 Lite3 대용 자산 기준이므로 START 실제 자산·PD 확인 전에는 **가정 검증 판**이다. 물리적으로 더 타당한 절대 가중치라고 선언하지 않는다. “C1 약함”과 “상사 과벌”은 반대 방향의 시험 가능한 가설로 남긴다. 성공 뒤에만 이유를 붙이는 방식은 피한다.

최종 재현은 low-random stones/평지 시작, terrain progression, edge mask, I-E velocity/latent, TR-Net, AdaSmpl, actor/critic 정보, 명령 A식의 의미를 함께 복구한 **전체 START 계열 Go2**다. 이를 먼저 통합해 성공 여부를 보는 시스템 검증도 가치가 있다. 다만 실패 시 원인 분리가 안 되므로 현재 보행 scaffold의 대조 결과·버전과 연결해야 한다. 단일 항 실험과 전체 조합 실험은 대체 관계가 아니다.

## 정상 보행 관문은 측정 계약부터 수정한다

제안된 높이 `[가정] ≥0.30 m`, swing `[가정] ≥3 cm`, 관찰 `[가정] 8 s`, 요 `[가정] ≤10°`를 지금 코드에 그대로 적용하면 v2도 탈락한다. 이를 정상 보행의 보편적 정의로 동결하지 않는다.

**v2가 떨어진다는 사실만으로 문턱이 틀렸다는 뜻도 아니다. v2가 통과하도록 문턱을 맞추는 것도 안 된다.** 임무가 실제로 더 큰 clearance나 더 정확한 방향을 요구한다면 v2도 실패가 맞다. v2의 역할은 지표가 무엇을 재는지 확인하고 기존 동작과 비교하는 참고군이다. START 목표의 정본이나 정상 보행의 정답표가 아니다. 아래 수정은 v2를 합격시키는 숫자 조정이 아니라 목적·정의·분모를 먼저 고정하자는 것이다. sparse 지형에서는 낮은 몸통·특수 보행이 합리적일 수도 있다(P:519의 지형별 gait 설명). 보기 좋은 자세를 전체 임무의 목적함수로 대체하지 않는다.

현재 저장 자료는 몸 높이의 일부 평균/중앙값, swing의 혼합 표본 분위수, 단일 정책의 일부 요 분포다. 동일 정의의 episode별 원 분포와 임무 허용 오차가 없으므로 **새 절대 합격선을 과학적으로 확정할 수 없다**. 팀장이 정할 임무 요구, 구현자가 고정할 측정 계약, 대조 자료로 확인할 반복 변동을 구분한다. 요구가 정해지기 전에는 아래 진단 지표를 연속값으로 보고하고, 다음 본 학습 자동 승격 기준은 미등록 상태로 둔다.

| 발 스윙 | DF는 착지 양끝 평균 z 기준 peak다. 지형 위 최소 여유나 발바닥 clearance가 아님. v2 평지/경사 p50 `[실측] 약 1.8 cm` | `[가정] 3 cm` 보편 하한을 합격 기준에서 보류. 평지·각 지형별 swing apex와 경로의 최소 toe-ground clearance를 분리. foot contact chatter·짧은 공중 구간도 분리 집계. 기존 지표는 기록용 보존 |
| 요 | DF가 degree 각을 단순 차분해 wrap 처리가 없고, RC는 원래 yaw 절댓값. 회전 명령에는 절대 yaw 하한이 부적절 | 고정 직진에서는 wrap된 초기 heading 대비 최대/끝 오차, 회전에서는 명령 적분 대비 오차와 wz 추종. `[가정] 10°`는 평지 직진 목표선으로만 유지 가능. v2 경사 `[실측] 중앙 11.135°`를 본 뒤 사후로 유리하게 문턱을 바꾸지 말고 지형별 기준을 재등록 |
| 지속 보행 | 서서 높이·요만 맞춰도 통과할 수 있음 | `[가정] warm-up 1 s` 뒤 목표축 world displacement, 속도 오차, 연속 정지 시간, 재출발을 필수 추가. 정지 판은 yaw/높이로 만회 못 함. 기존 stop `[코드] 2~4 s·0.05 m/s`도 함께 보존 |
| 영상 | 단일 정상 장면 선택, 빈 v2 열, reset 뒤 이어진 장면이 합격으로 오해될 수 있음 | 모든 판 같은 카메라·표본 선택 규칙, 명령/실제 속도/시간/종료 표시. 숫자 집계와 동일 seed 장면인지 확인. 영상은 필수 보조 근거지만 단일 장면을 성공률로 쓰지 않음 |
| 표본·분모 | 여러 env는 같은 정책이라 학습 반복이 아님. 생존 표본만 보면 낙상으로 수치가 좋아질 수 있음 | `[가정] 동일 평가 seed 200판/칸`과 학습 seed를 별도로 등록. 실패 포함 성공률, 생존, 조건부 자세 통계를 분리. 비교는 학습 seed 단위 효과와 평가 불확실성을 함께 보고 |

판정은 `[가정]` 평지 직진 정상 보행, rough 지속 전진, 회전 추종을 **별도 관문**으로 둔다. 시작 자세 PD 대조가 통과했다고 정책 보행이 통과한 것은 아니며, 기본 보행 통과가 sparse 정밀 발 놓기 통과인 것도 아니다. 보행 통과 후 열린 명령·sparse 검증으로 넘어가는 조건은 팀장이 이 측정 계약과 기준을 확인한 뒤 정해야 한다.

## 검증 기록과 남길 자료

- `[코드·계산]` URDF mass 합·joint geometry·FK를 XML로 다시 계산하고, 공식 USD mass를 CPU OpenUSD로 읽었다. nominal mass ratio와 torque-square ratio 계산은 입력이 같을 때 재현 가능하다. 새 시뮬레이션으로 실제 질량·접촉력·토크를 측정하지 않았다.
- `[실측]` C의 기준 측정 JSON 전부, D의 D1/D2/D3·재현·Rx1 해당 JSON과 reward 집계, S1 scan TensorBoard를 직접 읽었다. 일부 오래된 카드의 수치 인용으로 대체하지 않았다. 영상 그림 검토는 `analyzing-video` 스킬을 적용했고 핵심 그림과 JSON을 작성자가 다시 확인했다.
- `[코드]` E/A와 B/BA, SR, DF, RC, 설치 reward manager·joint acceleration 코드를 대조했다. 논문 줄 번호는 실제 LF 기준으로 고정했다. START의 비공개·미확인 실행 설정을 MGDP나 NVIDIA로 채워 넣지 않았다.
- `[실측]` CPU 검증 15개를 통과했다. 메타데이터·금지 문자·보상 표 행 수, 추종 함수의 정답/대칭/후진 반례, 토크 상사와 가중치 보존, 가속도 일정/충격 답 아는 예, 영 관절각의 평면 FK, 기준 JSON 수와 낮음·정지·관문 반례를 확인했다. 이는 문서 계산과 저장 자료 점검이며 실제 시뮬레이터의 동역학 검증이 아니다.
- 원 자료 재집계가 안 되는 항목은 저장 집계 재독으로만 적었다. 다음 승인 실험은 source commit, cfg/asset/terrain hash, checkpoint, 학습 seed, 평가 seed, 초기 상태, command tensor 분포, raw/processed action, q/qdot/torque, 발별 접촉·지면 높이, termination, 영상 프레임 시간을 함께 남겨야 한다.
- GPU·Kit·새 학습·평가·렌더는 실행하지 않았다. 공유 체크아웃·sonnet 작업 사본·원자료는 변경하지 않았다. 이 산출물만 로컬 커밋하며 push하지 않는다.

## 결론

**확정**

START는 전진 중심이지만 조건부 회전을 포함한다. S1-a는 선속도 식·edge 항·속도 추정·지형 진행이 달라 START 전체 재현이 아니다. scan의 낮은 자세와 blind의 정지는 같은 현상이 아니다. 명목 자산의 토크 제곱 상사 비 `[계산] 3.132107`은 조건부로 맞지만 실제 비용 배수가 아니다. 현재 발 높이·요 관문은 비교군에도 맞지 않고 측정 정의가 통일되지 않았다.

**가설(근거)**

열린 명령과 빠진 속도 정보가 결합해 탐색을 어렵게 만들고, 행동 변화·가속도 비용 및 tracking 구조가 정지 근처의 학습을 유지했을 가능성이 크다. 근거는 START와의 구조 차이, raw reward 집계, D2/D3의 서로 다른 결과, scan/blind 및 지형별 분리된 실패 양상이다. 토크 벌점 약함과 부하 상사 과벌은 아직 경쟁 가설이며 어느 쪽도 원인으로 확정할 수 없다.

**남은 위험**

START 실제 Lite3 실행 자산·PD·action scale·명령 주기·종료 수치가 미확인이다. Isaac/legged_gym 가속도 계약, 평가의 초기상태·관측·전진·높이 정의, 학습 seed 변동이 남아 있다. 새 `[가정] 1500 update` 실패만으로 START를 기각하거나, 한 판 통과만으로 본 학습과 열린 명령 확장을 승인하면 같은 혼란을 반복한다. 먼저 공통 측정 계약을 고정하고 START 중심의 통제된 셀을 완성한 뒤, 전체 지각·발 놓기 체계의 조합 성능을 검증해야 한다.
