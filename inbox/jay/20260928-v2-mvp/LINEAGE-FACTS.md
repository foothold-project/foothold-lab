## 0. 이 파일이 있는 까닭

계보를 채팅으로 주고받다가 압축이 걸리면 **확인한 숫자가 날아간다.** 그리고
설계 문서들이 「손잡이」라는 틀린 말을 쓰고 있어서, 인용할 때마다 고쳐
적어야 한다. 그래서 확인한 것만 여기에 굳혀 둔다.

**아래 숫자는 전부 파일에서 읽은 것이다.** 기억으로 적은 줄이 없다.

## 1. 왜 gap 을 «맨 먼저» 골랐나 `팀장 확인`

팀장 발언 (2026-09-28) 을 그대로 옮긴다.

> 여러 지형 중에서 gap을 제일 먼저 시도한 것은 **벽을 음수로 구멍을 양수로
> 표현하는 것**이 있었음. 그리고 gap을 제일 먼저 학습한 건 기존 6종에는
> **이런 구멍을 어떻게 처리하는지에 대해서 코드처리를 한 적이 한 번도 없었기
> 때문에** 시작한 것. (기대효과가 제일 클 것으로 파악되서)

이것이 **문제 파악**이다. 높이 스캔 한 줄기가 내는 값이 이렇다.

```
평지        -0.10   바닥이 발밑에 있다
턱이 솟음   -0.30   값이 더 음수로
바닥이 꺼짐  +1     광선이 아무것도 못 맞힌다
```

기존 학습 6종(`rough6`)은 **솟은 것**만 있다. 꺼진 것이 없다. 그래서
양수 쪽 값을 정책이 학습에서 만난 적이 없다.

**첫 실험을 gap 으로 고른 것은 기대 효과가 가장 클 자리라고 봤기 때문이다.**

## 5. `feet_air_time` 을 왜 건드렸나 `팀장 확인`

팀장 기억이 맞았고 내 초안이 틀렸다. 팀장 발언 (2026-09-28).

> `feet_air_time`은 터진 것을 피하려고 여러칸을 흔드는 중에 파악한거라기
> 보단, **우리가 rail를 넘어가기 위해서 설정을 하는데, 건널려면 발을 드는
> 행동에 대한 보상이 조금 있어야하지 않을까?** 하는 생각으로 설정을 했던걸로
> 기억하는데?

**근거가 우리 기획서에 이미 있었다** (`deliverables/plan/proposal.md`).

> 현재 정책은 관절이 **63.7 cm 까지 발을 들 수 있는데 3.25 cm 만 든다.**
> `feet_air_time` 이 **높이가 아니라 시간**을 점수로 주고, 발 높이 항이
> 없으며, `flat_orientation_l2` 가중치가 0 이기 때문이다.
> **여기가 실패 5종의 공통 뿌리다**

그리고 `rails` 는 **평지 위로 솟은 사각 테두리 두 겹**이다
(`mesh_terrains.py:rails_terrain`). 넘으려면 발을 들어야 한다.

**가중치 실측이 팀장 기억과 맞는다.**

```
기준 (v2a · v2b · v2n · v2s)   0.01
v2g                            1.0     (100 배)
v2g2                           0.1     ( 10 배)  <- 「조금」
```

**0.1 이 94.19 로 최고이고 1.0 은 93.08 로 오히려 낮다. 「조금」이 맞았다.**

## 5-2. 왜 «속도 하한» 이 아니라 `rel_standing_envs` 였나 `확인됨`

팀장 물음: 「명령에서 서는 것에 있어서 우리가 속도 제한으로 하지 않고
`rel_standing_envs` 를 왜 테스트 했는지?」

**원문을 열어서 확인했다** (`isaaclab/envs/mdp/commands/velocity_command.py`).

```python
141    self.is_standing_env[env_ids] = r.uniform_(0.0, 1.0) <= self.cfg.rel_standing_envs
162    standing_env_ids = self.is_standing_env.nonzero(as_tuple=False).flatten()
163    self.vel_command_b[standing_env_ids, :] = 0.0
```

**`rel_standing_envs` 는 환경의 «일부» 를 골라 명령을 통째로 0 으로 만든다.**
고르지 않은 환경은 `lin_vel_x` 에서 뽑은 속도를 그대로 받는다.

두 방법이 이렇게 갈린다.

```
속도 하한을 0 으로 내린다    모든 환경의 명령이 느려질 수 있다
                            -> 직선 거리가 안 늘어난다
                            -> 커리큘럼이 난이도를 안 올린다
                            -> 4 절에서 겪은 노출 붕괴가 다시 온다

rel_standing_envs 를 올린다  일부 환경만 «완전 정지» 가 된다
                            -> 나머지는 0.4 ~ 1.5 m/s 로 그대로 간다
                            -> 노출이 유지된다
```

**정지를 배우는 자리와 험지를 배우는 자리를 나눈 것이다.** 그래서 v2b 는
축 1 을 잃지 않고 축 2 회전 낙상을 0.9219 에서 0.0625 로 낮췄다.

## 5-3. 학습이 터진 기록 `보여주기용 아님 · 실험 기록용`

팀장 지시 (`[46]`): 「중간에 > 접기로 왜 랜덤 시드 다른 거에서 학습이 터졌고
어떻게 해결하려고 했었는지도 참고로 적어주면 좋을 것 같다 (보여주기용x,
실험 기록용o) : log, `exp()` clipping, 등 scalar, NaN, 음수 등」

보고서에는 **접기**로 넣는다. 「폭주」라고 적지 않는다.

### 무엇이 일어났나

```
RuntimeError: normal expects all elements of std >= 0.0
```

**시드를 바꾸면 터지고, 같은 설정이 다른 시드에서 완주했다.**

```
실패 로그 9 건 · 서로 다른 실행 이름 8 개
```

둘을 같이 적는 까닭 · `v2b-s3instr` 이 두 번 걸려 **두 번 다 같은 1670 에서**
죽었다. 재실행도 실제 실패 1 건이다. 그리고 **이 수는 독립 설정의 수가 아니다.**

### 내가 세운 가설과 그것이 틀린 것

**가설** · 「표준편차 매개화가 원인이다. `log` 로 바꾸면 음수가 안 나온다.」

**실험** · `scalar` 대 `log` 2 × 2.

**검증 · 가설이 틀렸다.** `log` 도 터졌다 (`v2LG-log-feet01-s44` · 마지막 완료
출력 번호 2923 · 같은 문구).

체크포인트 2800 · 2850 · 2875 · 2900 을 다 열어 텐서 68 개를 봤는데 비유한수가
**하나도 없었다.** **최초로 비유한수가 생긴 갱신 번호는 미확인이다.**

수학에서 `exp()` 는 양수지만 float 연산에서는 underflow · overflow · NaN 이
다 가능하고, torch 의 `std.min() >= 0` 검사는 **NaN 에서도 실패한다.**

| 매개화 | 일어났을 수 있는 것 |
|---|---|
| `scalar` | std 가 음수가 됐을 수 있다 |
| `log` | `log_std` 가 NaN 이 됐을 수 있다 |

**두 칸 다 개별 원인 미확인이다.** 문구가 같다는 것이 속이 같다는 뜻도,
다르다는 뜻도 아니다.

### 라이브러리에 관문이 없다 `확인됨`

`rsl_rl/modules/actor_critic.py` 전체에서 `clamp` · `clip` · `isnan` ·
`isfinite` 를 찾았다. **하나도 없다.**

gradient 자르기는 있는데 **NaN 을 막지 않는다. 퍼뜨린다.** 실측했다.

```
넣은 gradient               [1.0, 2.0, NaN, 3.0]
clip_grad_norm_(..., 1.0)
나온 gradient               [NaN, NaN, NaN, NaN]
```

전체 norm 이 NaN 이면 곱하는 계수가 NaN 이라 **전부** NaN 이 된다.

### 그리고 팀장이 잡은 것

16 판은 요인 설계가 아니고 교란이 섞여 있다. 시드 43 안에서는
`feet_air_time` 0.01 넷이 다 죽고 0.1 하나가 살았고, 시드 44 안에서는
`scalar` 0.01 둘이 죽고 `log` 0.01 이 살았다. **표본이 작고 조건이 통제되지
않아 어느 쪽으로도 말할 수 없다.**

그런데 **모든 판에 똑같이 있던 것**이 하나 있었다. **`resume`** 이다.

팀장이 여러 번 「터지는 게 뭔가 이상하다」고 말했다. 나는 그것을 **「어느
설정이 터뜨리나」** 로 옮겨 읽었다. 실험하는 사람이 보는 자리다.
**변하지 않는 변수는 그 방법으로 안 보인다.**

## 6. 이 파일이 「미확인」으로 남기는 것
