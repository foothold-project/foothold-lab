그림 ① · 전체 구조

명령은 앱 서버를 지나 Jetson 의 agent 에 닿고, 지금은 Sport 경로 하나로 Go2 순정 보행에 들어간다

오른쪽 아래의 점선 상자 셋 (모드 관리자 · 저수준 실행기 · 안전 정지) 이 이번에 정한 「만들 것」 이다. 이것들이 생기면 같은 agent 가 Go2 모터에 직접 LowCmd 를 보낸다.

읽는 순서

  1. 사용자 자리. 브라우저 웹 화면이나 Android 앱 (Capacitor, 1.2.3-dev) 이 앱 서버 주소를 연다. Android 앱은 서버 웹 열기 · 오프라인 시뮬 · 주변 로봇 찾기를 한다. iOS 빌드는 없다. 앱 시뮬 (MuJoCo + ONNX) 은 이 기기의 탭 안에서 돈다.
  2. 앱 서버 (NaverCloud). Caddy 가 443 에서 HTTPS 를 받고 정적 웹을 주며 API 요청과 websocket 을 uvicorn 으로 넘긴다. API 는 로그인 · 로봇 목록 · 로봇 상태 · 조종 명령 · 실시간 연결을 맡고, 기록은 PostgreSQL 16 에 둔다. 서버는 GPU 를 쓰지 않는다. 주소는 지금 <IP>.sslip.io, 앞으로 app. · api. · site.foothold-project.dev.
  3. 서버 연결. Jetson 의 agent 가 서버로 먼저 wss 연결을 연다. 그래서 Jetson 이 인터넷에만 붙어 있으면 바깥에서도 폰 · 웹 → 서버 → agent 로 조종된다.
  4. 명령 출처 하나. agent 는 한 순간에 출처 하나 (phone · nav2 · server) 만 받고, 서버 쪽에서는 lease 로 한 사람만 조종한다. STOP 은 모든 출처보다 먼저다.
  5. Sport 경로 (있음). 명령 3 개를 SportClient.Move(vx, vy, wz) 로 바꿔 Go2 순정 보행 제어기에 보낸다. 걷는 법은 Unitree 제어기가 정한다.
  6. 모드 관리자 · 저수준 실행기 · 안전 정지 (계획). 모드 관리자가 Sport · 저수준 정책 · 안전 정지 셋 중 하나만 로봇에 명령하게 한다. 저수준 실행기는 정책 ONNX 를 Jetson 에서 돌려 LowCmd 를 내고, 정책마다 다른 입력을 contract 를 읽어 맞춘다. 안전 정지는 정책 송신을 끊고 Kp 0 · Kd 만으로 관절을 무르게 한다. 순정 L2+B 가 저수준 모드에서 안 들을 수 있어 실행기가 LowState 의 wireless_remote 를 직접 읽는다.
  7. 센서. L2 라이다 점구름은 agent 의 지도 (mapping) 로 가서 앱의 점 지도 표시와 HiPAN 상위 · 위치 추정 쪽에 쓰인다. 정책 입력은 아니다. D435i 깊이는 agent 의 깊이 보기 (depth) 가 DDS 토픽을 찾아 색을 입혀 보여 준다. START 정책의 깊이 입력으로 쓰는 길은 저수준 실행기와 함께 만든다.

그림 ② · 앱 네 모드

정책은 지금 앱 시뮬에서만 돈다. 실기 쪽 칸은 ① 순정 보행을 빼고 모두 만들 것이다

모드 이름과 설계는 팀장 11/19 00:21 목표 설계, 「있음」 은 89d2a221 코드다. 코드의 모드 id 는 nvidia (기본) · start · ame2 · go2 이고, nvidia 는 네 모드 설계에는 없는 모드다.

  • ONNX 가 도는 자리. 지금은 사용자 브라우저 (onnxruntime-web Worker) 한 곳이다. Jetson 위 실행기는 계획이다. 실행기 하나가 정책별 contract 를 읽어 입력을 맞춘다 (앱 시뮬의 policy-onnx.js 가 이미 이 꼴). 입력은 정책마다 다르다: AME-2 몸감각 49 + 지도 29x13x3, START 몸감각 45 + 깊이.
  • START 판. 앱에 든 것은 m13000 이고 정본 3 m15500 은 아직 없다. 앱 시뮬의 깊이는 시뮬 광선으로 만든다 (카메라 0.25 · 0.12 · 35도). 실기는 D435i 깊이 60x60 을 ONNX 안 지각망이 복원한다.
  • AME-2 student. teacher 증류만으로 끝나지 않고 깊이 점과 몸 위치 추정을 합쳐 높이 지도를 쌓는 Mapper 를 따로 학습한다. 10/07 기록으로는 착수 전이고 지금 상태는 미확인 (석헌에게 확인).
  • AME-2 조이스틱. 앱 시뮬에서 막대는 몸 기준 앞 1 m 목표와 방향 오차가 되고, 찍은 점과 A* 경유점은 몸 좌표로 바꿔 2 m 로 자른다. 몸 선속도 칸은 시뮬 정답값을 쓴다.

그림 ③ · 명령 주인 하나 · 모드 관리자

로봇에 명령을 보내는 길은 agent 안 모드 관리자 하나만 둔다

조이스틱 키 표

Go2 조이스틱의 막대 · 버튼 값은 로봇 상태 신호 (LowState) 의 wireless_remote 칸으로 Jetson 에 들어온다. 저수준 실행기가 이 칸을 직접 읽으면 Sport 서비스를 해제한 저수준 모드에서도 조이스틱을 쓸 수 있다.

말로 부르고 앉히는 길, 그리고 위험할 때 로봇이 먼저 말하는 길

팀장 11/19 15:4x 지시를 그림으로 옮겼다. 두 길로 나눈다. 사람이 말하면 로봇이 알아듣고 대답하는 음성 명령, 배터리 · 온도 · 멈춤 · 통신이 문제일 때 로봇 (또는 앱) 이 먼저 말하는 음성 알림. 지금 앱 코드에는 음성 기능이 없다 (아래 근거 표). 담당: 음성 기본 제어 시험 이민우 · 총괄 오흥재 · 앱 작업자 오현민 · 이민우.

  • 음성 명령도 명령 출처 하나. 음성은 agent 의 출처 (phone · nav2 · server) 옆 새 출처로 들어가 lease 한 사람 규칙과 STOP 우선을 그대로 따른다 제안 · 팀장 결정 대기. 음성은 멈춤 수단으로 쓰지 않는다. 멈춤은 앱 STOP · 조이스틱 L2+B 다.
  • 받아들임 ≠ 앉음. agent 의 동작 코드는 SDK 가 받아들인 것을 「동작이 끝남」 으로 보지 않는다 (actions.py 머리말). 화면은 명령 칩을 먼저 띄우고, 앉았는지는 자세 값으로 확인해 바꾼다.

  • 배터리 남은 시간 어림. 11/19 새벽 한 번 잰 빠르기 (방을 걷는 동안 약 0.86 %/분 · 서 있기만 할 때 약 0.55 %/분, GO2X-JETSON-SETUP-1119.md 8 절) 로 나누면 20 % 에서 걷기 약 23 분 · 서기 약 36 분, 10 % 에서 약 12 분 · 18 분이다. 한 번 잰 값이고 낮은 잔량에서의 빠르기는 재지 않았다. 같은 문서는 05:20 녹화에서 본체 통신이 끊긴 까닭 후보로 낮은 배터리를 적어 두었다 (미확인).

정할 것 · 미정 (팀장 결정)

  • 말하는 자리: 로봇 스피커 · 폰 · 둘 다.
  • 말 알아듣는 자리: 순정 비서의 깨우는 말을 「Hey, X」 로 바꿀 수 있는지 (이민우 시험) · 안 되면 Jetson 이나 폰에서 알아듣기.

  • 「Sit Down」 확인 말 문구와, 다음에 더할 기본 명령의 순서.
  • 온도 위험에서 저절로 Damp 할지는 업체 답 뒤 (앞 절과 같음).

SLAM · Point-LIO 와 GLIM (v0.6)

걷는 동안은 Point-LIO 로 실시간 지도를, 임무 뒤에는 GLIM 으로 한 장 지도를 만든다

팀장 11/19 17:59 확정: 「SLAM: Point-LIO 와 GLIM 을 역할을 나눠 둘 다 쓰기」. 같은 L2 라이다 + IMU 자료를 두 길로 보낸다. 위 「Jetson · 11/19 설치 · 숙소 측정」 절의 방 지도는 odom 을 그대로 쌓은 1 차 그림이고 SLAM 이 아니다. 무엇을 재서 고르는지는 맨 아래 다음 측정할 것 · 제원 부담 표에 있다.

갈래어디서 · 언제내는 것서비스 가치상태
Point-LIOJetson Orin NX 16GB · CPU · 걷는 동안실시간 위치 · 국소 지도 → 발밑 높이 지도 · 앱 실시간 3D사족보행 걸음 충격에도 덜 흐르는 실시간 지도 = 화면 지도가 실제와 같다는 신뢰 · 정책 입력의 바탕계획 팀장 확정
GLIM학습 PC 또는 서버 · GPU · 임무 뒤 (걷는 중 안 돌림)루프 닫기 · 일관된 전역 지도일관된 한 장 지도 = 임무 기록 · 보고 · 다음 임무 계획 · 재방문계획 팀장 확정
FAST-LIO2 · DLIO견줄 후보같은 녹화로 재서 Point-LIO 와 견줌재 본 뒤 팀장 결정후보
지금 방 지도학습 PC (녹화 뒤 계산)cloud_deskewed 를 odom 그대로 쌓은 위에서 본 그림1 차 확인용있음 SLAM 아님
  • GLIM 을 걷는 중에 안 돌리는 까닭. GLIM 은 GPU 를 쓰므로 Jetson 에서 걷는 중에 돌리면 정책과 GPU 를 다툰다 (팀장 17:59). 그래서 임무 뒤에 학습 PC 또는 서버에서 돌린다.
  • ROS2 길. L2 공식 Point-LIO 예시는 ROS1 이다. Jetson 은 ROS 2 (Humble) 라서 ROS2 로 돌리는 길은 미확인이고 먼저 확인한다.
  • 앱으로 가는 것. 앱에는 전체 점구름이 아니라 지도 델타 (새로 바뀐 칸) 를 보낸다. 얼마나 되는지는 아래 표에서 잰다.
