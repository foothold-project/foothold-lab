## 2. Q6 · 장치 교차 실행으로 무엇을 분리할 수 있나

### 2-1. 이미 측정한 것과 아직 모르는 것

숫자가 다른 것은 `확인됨`이다. 그 차이 전부를 GPU 하드웨어 자체의 효과로 귀속하거나 모집단 효과 크기로 부르는 것은 부적절하다. 실행 날짜와 실행 환경의 차이도 있고, 난수 소비 배치도 달라졌다. 저장 YAML 일치는 과거 소프트웨어 전체의 비트 동일성까지 증명하지 않는다.

반면 `v2b-r` 대 `v2b-p11`은 **sim·PPO 동거 상태를 유지한 장치 번호 이동**이다. 이 조건에서는 121개 저장 상태가 같았다. 현재 fs도 동거 상태를 유지하므로 이 실측은 관련 있는 선행 근거다. 이를 아예 없는 것으로 처리하면 안 된다. 그러나 scratch의 무작위 초기화, 보상, 초기 학습률, 4501회 구간에 대한 동일성은 **미확인**이다. 과거 한 설정에서의 일치가 모든 미래 설정의 보증은 아니다.

### 2-2. 예정한 2 × 2의 정확한 대비

`판단` A를 보상 0.01, B를 보상 0.1, `Y_A0`를 A·GPU0의 사전 지정 성능 지표라고 하자. 학습 시점과 평가 조건을 맞춘 네 값으로 다음을 계산할 수 있다. 총 리턴은 보상 가중치가 달라 직접적인 공통 성능 지표로 쓰지 않는다.

| 질문 | 계산 |
|---|---|
| GPU0 안의 보상 대비 | `Y_B0 - Y_A0` |
| GPU1 안의 보상 대비 | `Y_B1 - Y_A1` |
| 두 장치 평균의 보상 대비 | `((Y_B0 - Y_A0) + (Y_B1 - Y_A1)) / 2` |
| 보상 A 안의 장치 대비 | `Y_A1 - Y_A0` |
| 보상 B 안의 장치 대비 | `Y_B1 - Y_B0` |
| 두 보상 평균의 장치 대비 | `((Y_A1 - Y_A0) + (Y_B1 - Y_B0)) / 2` |
| 장치에 따른 보상 대비 변화 | `(Y_B1 - Y_A1) - (Y_B0 - Y_A0)` |

네 조합은 [NIST의 완전 요인 설계 정의](https://www.itl.nist.gov/div898/handbook/pri/section3/pri333.htm)에 해당한다. **관측 대비를 계산할 수 있다는 것과 효과를 불확실성까지 분리 추정했다는 것은 다르다.** 한 칸에 한 학습이면 절편·보상·장치·상호작용으로 네 관측값을 모두 써서 오차를 따로 추정할 자유도가 없다.

게다가 실행 순서는 1차에 A0·B1, 2차에 A1·B0다. 이 배치에서는 **보상×장치 상호작용이 실행 차수와 겹친다.** 모든 실행에 같은 크기로 더해지는 차수 효과라면 평균 주효과 대비에서 상쇄된다. 그러나 GPU별 시간 변화, 서로 다른 동시 부하, 설정별 시간 효과까지 자동으로 없어지지는 않는다. 이 네 실행만으로 「교란을 완전히 제거했다」고 쓰면 안 된다.

권장 기록은 두 장치 각각의 보상 대비와 두 보상 각각의 장치 대비를 모두 보여 주는 것이다. 방향이 다르면 평균 하나로 숨기지 않는다. 이후에는 각 조합을 반복하고 실행 순서와 차수별 배정을 균형 있게 바꾸며, 같은 비교 묶음 안에서 소프트웨어·출발 상태·평가 장치·평가 시드·학습량을 고정한다. GPU UUID와 논리 device 매핑도 기록한다.

### 2-3. 비결정 변동의 최소 설계

`판단` 최소의 기술적 확인은 **같은 설정·같은 학습 시드·같은 sim/PPO 배치에서 새 프로세스로 총 두 번 실행**하는 것이다. 같은 체크포인트를 두 번 평가하는 것은 학습 비결정 변동을 재는 실험이 아니다. 모델·optimizer 상태, 손실 이력, 공통 평가 지표를 대조한다. 같지 않으면 그 조건에서 변동이 관측된 것이고, 같으면 그 두 실행에서 차이를 검출하지 못한 것이다.

표본 분산은 두 값에서도 계산되지만 자유도 1이라 정밀한 크기를 말하기 어렵다. 보상×장치 네 조합 각각의 반복 변동을 분리하려면 **각 칸 두 학습, 총 여덟 학습이 수학적 최소**다. 이는 충분한 검정력이나 최적 예산의 권고가 아니다. 필요한 반복 수는 사전 허용 차이와 원하는 정밀도로 정해야 한다. 여러 시드는 별도의 학습 시드 변동을 재며 같은 시드 재실행과 섞어 세지 않는다.

이미 `v2b-s`와 `v2b-s2`는 위 기술적 확인을 수행했고 67개 저장 상태가 같았다. 따라서 「같은 장치·시드 반복을 아직 한 번도 안 했다」는 틀렸다. 이를 근거로 **모든 실행의 비결정 분산은 0**, **이웃 부하는 결과를 절대 바꾸지 않는다**고 쓰는 것도 틀렸다. scratch 조건으로의 전이는 미확인이다.

### 2-4. CRITERIA 9절 교체 문안

> 비교 묶음에서는 sim과 PPO의 동거·분리 배치를 고정한다. sim만 옮기는 변경과 sim·PPO를 함께 다른 GPU로 옮기는 변경을 구분한다. 각 실행에 sim.device, agent.device, GPU UUID와 매핑, 소프트웨어 판, 학습 시드, 출발 체크포인트 해시를 기록한다.
>
> v2b-r(sim0·PPO0)과 v2b-p11(sim1·PPO1)은 시드 42의 해당 설정에서 121개 공통 체크포인트의 모델·optimizer 텐서가 일치했다. v2b-s와 v2b-s2는 시드 43·sim1·PPO0에서 67개 공통 체크포인트가 일치했다. 이는 해당 조건의 기술적 반복성 근거이며 다른 시드·레시피·하드웨어 전체의 동일성 보증이 아니다.
>
> 검증된 조건 범위 안에서 장치 번호를 달리한 병렬 실행을 허용하되 배정과 근거를 공개한다. 새 조건에서 장치 독립성이 필요한 주장을 하려면 교차·반복 대조를 수행한다. 한 번의 교차 대조만으로 평균 장치 효과나 비결정 분산을 확정하지 않는다. 동일 텐서의 재실행을 독립 학습 성능 표본으로 중복 집계하지 않는다.

544·545행도 각각 「장치 번호 이동의 기존 조건 실측 있음. scratch 전이는 미확인」, 「동일 시드 기술적 반복과 여러 시드의 학습 변동을 구분. 모집단 분산은 미확인」으로 고쳐야 한다.

## 3. Q7 · 판정 규칙의 구체적 문안과 재계산

### 3-1. 지금 정할 것

**fs 결과를 본 뒤 규칙을 고르면 안 된다.** 지금 불확실성 해석과 분석 범위를 문서로 고정하고, 기존 동결 판정은 보존한다. 이미 v2g2 결과를 보았으므로 새 규칙을 과거 실험의 사전 등록 기준이라고 부를 수 없다. 진행 중인 fs에도 「학습 시작 전 사전 등록」이라고 쓰면 안 된다.

`판단` 우선 기존 판정 옆에 **회전 낙상 Wilson 보조 판정**을 추가하는 것이 타당하다. 아래 영향 계산은 명시적으로 **turn/fell_ratio 하나만** 바꾸는 경우다. stop·hold까지 일괄 바꾸는 경우는 3-5절에 따로 계산했다. turn만 바꾼 결과에 「축 2 전체가 95% 신뢰구간으로 검증됐다」는 이름을 붙이면 안 된다.

**0.10은 그대로 둔다. 바꾸는 것은 0.109375를 바로 비교하는 함수다.** 상수를 0.11로 올리거나 반올림으로 7/64를 통과시키는 변경이 아니다.

### 3-2. 그대로 사용할 수 있는 기준 문안

> 회전 낙상률의 표본 단위는 고정된 18초 turn 대본을 수행한 env 하나다. 한 env의 여러 시간 표본이나 네 요 명령 구간을 독립 시행으로 늘려 세지 않는다. 실패한 env도 분모에 포함한다.
>
> 유효한 원자료에서 낙상 수 k와 시작 env 수 n을 직접 센다. 양측 Wilson 95% 구간 [L,U]을 반올림하지 않은 값으로 계산한다. U ≤ 0.10이면 통과, L > 0.10이면 미달, 나머지는 미판정이다. 원자료 누락·중복 env·불명확한 종료 상태·예정 표본 수 불일치는 미판정으로 두되 사유를 자료 오류로 별도 기록한다. 자료 오류를 통계적 경계 중첩과 합쳐 보고하지 않는다.
>
> 각 체크포인트의 필수 아홉 칸 중 하나라도 미달이면 그 체크포인트는 미달이다. 미달이 없고 미판정 또는 자료 오류가 있으면 미판정이다. 필수 아홉 칸이 모두 통과해야 통과다. 사전 지정한 네 체크포인트도 같은 AND 규칙을 쓴다. 미판정은 통과 수에 합산하지 않는다.
>
> 축 1의 기존 「하락 검출 0」 규칙은 별도이며 이번 변경으로 「모든 칸에서 비열등성 입증」으로 바뀌지 않는다. 축 2 통과, 축 1 규칙 충족, 사전 정의한 재현 조건을 모두 확인해야 후보 충족을 표시한다. 재현 누락은 후보 충족이 아니다.
>
> 신뢰수준은 각 낙상 칸의 구간에 관한 것이다. 여러 지표·체크포인트·후보 선택 전체에 대한 95% 보증으로 해석하지 않는다. 평가 횟수·시드·표본 수·중간 확인 규칙을 결과 확인 전에 고정한다. 미판정이 나왔다고 통과할 때까지 임의로 표본을 추가하지 않는다.

Wilson 공식은 [NIST 원문](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)과 대조했다. 이항 시행 해석에는 env 간 독립성과 공통 확률 등의 가정이 필요하다. 동일 시뮬레이션의 64 env가 학습 시드 변동을 대표하는 것은 아니다.

### 3-3. 구현해야 할 형태

다음은 **구현 제안**이다. 저장소 코드를 바꾸거나 이 코드로 운영 판정을 발행하지 않았다.

```python
from math import sqrt

TURN_FALL_RULE = {
    "method": "wilson", "level": 0.95, "sides": 2,
    "limit": 0.10, "unit": "env", "rule_version": "turn-ci-proposal-1",
}

def turn_fall_verdict(rows, expected_n):
    unknown = {"status": "미판정", "passed": None, "reason": "자료 오류"}
    if not isinstance(rows, list) or not rows or len(rows) != expected_n:
        return unknown
    if any(not isinstance(r, dict) or type(r.get("env_id")) is not int
           or type(r.get("fell")) is not bool for r in rows):
        return unknown
    if {r["env_id"] for r in rows} != set(range(expected_n)):
        return unknown
    k, n = sum(r["fell"] for r in rows), len(rows)
    z = 1.959963984540054
    p, d = k / n, 1 + z*z/n
    c = (p + z*z/(2*n)) / d
    h = z * sqrt(p*(1-p)/n + z*z/(4*n*n)) / d
    lo, hi = max(0.0, c-h), min(1.0, c+h)
    status = "통과" if hi <= 0.10 else "미달" if lo > 0.10 else "미판정"
    return {"status": status, "passed": {"통과": True, "미달": False,
            "미판정": None}[status], "reason": "경계 중첩" if status == "미판정"
            else "구간 판정", "k": k, "n": n, "low": lo, "high": hi}

def required_status(records, required_keys):
    # 호출 전에 중복 키, 원자료 해시, 정책/시나리오/평가 조건을 검증한다.
    vals = [records.get(k, "미판정") for k in required_keys]
    if "미달" in vals:
        return "미달"
    return "통과" if vals and all(v == "통과" for v in vals) else "미판정"
```

`expected_n`은 관측 행 수로 역산하지 않고 고정 평가 계획과 실행 manifest에서 검증한다. 원자료 provenance, 정책 해시, 시나리오 일치 확인도 호출 전에 필요하다. `passed=None`만 저장하면 원자료 누락과 통계적 미판정을 구분하지 못하므로 `status`·`reason`·k·n·구간·기준 판을 함께 저장한다.

`verdict_manifest.py`의 기존 `("turn","fell_ratio"): ("<=",0.10)`을 단순히 다른 튜플로 바꾸면 충분하지 않다. **판정 함수를 하나 만들고** `axis2_entries`와 `_out/loop/verdict.py`의 `axis2_one_checkpoint`가 함께 호출해야 한다. 뒤쪽 코드는 현재 상수만 가져와 자체적으로 `value <= limit`을 수행한다. `passed == 9`로만 요약하는 부분과 Markdown 출력도 세 상태를 표현하도록 함께 바꿔야 한다. 필수 키 집합은 고정하고, 추가 관측 지표를 통과 수에 더하지 않는다.

경계값 확인: n=64에서 **0~1건 통과, 2~11건 미판정, 12건 이상 미달**이다. 기존 점추정은 0~6건 통과였다. 미달 1칸과 미판정 1칸이 같이 있으면 전체는 미달이다. 네 점 중 세 점 통과·한 점 미판정이면 네 점 전체는 미판정이며 후보 충족이 아니다.

### 3-5. 세 낙상 칸 모두 바꾸면

`확인됨` n=64, 낙상 0건의 양측 Wilson 95% 상한은 **0.056624**다. 따라서 stop·hold의 0.03 문턱은 이 표본 수에서 어느 정책도 CI 통과할 수 없다. 0건일 때 상한 ≤0.03이 되는 최소 n은 **125**다. 125는 0건이라는 특정 관측에서의 경계이며 충분한 검정력을 보장하는 표본 수가 아니다.

세 낙상 칸 전체를 바꾸면 62×3=186칸 중 **125칸**이 바뀐다. 통과→미판정 104칸, 미달→미판정 21칸이다. p11 중복을 빼면 174칸 중 **115칸**, 각각 96·19칸이다. 축 2 전체 상태가 바뀌는 이름은 앞 표와 같은 네 표기이고, 네 점 전체 후보가 새로 생기지는 않는다.

이 규칙을 배포 관문으로 채택하려면 stop·hold의 표본 설계부터 다시 정해야 한다. 단측 구간, 다른 신뢰수준, 다른 문턱은 각각 다른 제안이다. 결과를 보고 통과 가능한 조합을 고르면 안 된다. 지금은 보조 결과를 병기하고, **세 낙상 지표를 통일한 최종 관문과 평가 예산은 별도 기준 판으로 동결**하는 것이 맞다.

## 5. Q9 · fs1·fs2가 완주하지 못하면

**미완주와 수치 실패를 먼저 구분해야 한다.** 프로세스 강제 종료, 정전, 메모리 부족, 저장·평가 실패와 std 오류는 다른 사건이다. 아직 종료하지 않은 실행도 실패가 아니라 관측 진행 중이다.

| 관측 | 말할 수 있는 것 | 말할 수 없는 것 |
|---|---|---|
| scratch에서도 같은 RuntimeError | 해당 scratch 설정에서도 같은 오류가 발생. 오류 발생에 resume은 필수 조건이 아님 | 과거 resume 실패와 최초 원인이 같음, resume은 위험에 전혀 영향 없음 |
| 다른 수치 오류로 중단 | scratch가 그 실행의 수치 안정성을 보장하지 못함 | std 경로의 동일 원인 확인 |
| 인프라 사유로 중단 | 그 실행의 성능·완주 검증이 끝나지 않음 | 학습 알고리즘의 발산 |
| 둘 모두 4501회 완주 | 해당 두 조건·시드·예산에서 완료했다는 관측 | scratch는 안 터짐, resume이 원인이었음, 수렴 또는 일반화 입증 |

scratch 실패는 **「resume을 없애면 충분히 해결된다」는 설명을 반박**한다. scratch 실험의 성능 비교·자체 학습 기준선이라는 다른 목적까지 무효화하지는 않는다. 반대로 완주해도 초기 가중치뿐 아니라 optimizer 이력·초기 학습률·std·학습 길이가 함께 바뀌었으므로 resume 원인설을 입증하지 못한다.

### 다음 실험의 순서

1. **실패를 보존하고 첫 비정상 위치를 잡는다.** 정확한 실행 명령, 저장 YAML, 코드 판, 로그의 마지막 완료 번호와 예외 위치를 기록한다. 관측·행동 평균·std 또는 log_std·리턴·advantage·loss·gradient·optimizer 상태에서 최초 비유한수 또는 음수 std를 구분한다. 마지막 정상 저장점만으로 최초 원인을 지정하지 않는다.
2. **같은 조건 재현에 진단을 붙인다.** 같은 시드·sim/PPO 배치·출발 상태로 재현하고, 비정상 값을 감지하면 증거를 저장하고 중단하는 진단을 둔다. 필요하면 RNG·환경 상태도 저장한다. std clamp나 업데이트 건너뛰기는 학습 규칙 변경이므로 순수 진단과 별도 실험으로 둔다. 계측 자체가 수치 경로를 바꾸지 않았는지도 확인한다.
3. **확인한 가설 하나를 가르는 대조를 건다.** 초기화 효과를 물으면 같은 보상·명령·지형·예산·장치 배치·초기 lr에서 사전학습 actor·critic과 무작위 actor·critic을 비교하고 양쪽 optimizer는 새것으로 맞춘다. optimizer 승계 효과는 같은 사전학습 가중치에서 새 optimizer 대 승계를 별도로 비교한다. lr 가설은 같은 초기 상태에서 lr만 바꾼다. 여러 변경을 한꺼번에 넣고 원인을 찾았다고 하지 않는다.
4. **여러 시드와 실패를 함께 보고한다.** 기술적 동일 반복을 독립 성공 표본으로 늘리지 않는다. 완주 비율뿐 아니라 중단 시점, 계획된 예산, 미완료 평가를 공개한다. 원인 조사와 최종 성능 비교는 별개 결과다.

이 순서는 조건부 제안이며 이번에 실행하지 않았다. 진단 자료 없이 std 하한부터 넣거나 scratch를 다시 포기하는 결정은 원인 확인을 대신하지 못한다.
