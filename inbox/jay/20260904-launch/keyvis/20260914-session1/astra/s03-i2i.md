# s03 clay→real · 프레임 판정과 Seedream 4.5 편집안

> 상태: 내부 제작 검토안. 생성은 수행하지 않았으며 아래 추천은 편집 시험용이다.
> 근거: f92·f96·f100 PNG, 시퀀스 컨택트 시트, 실패 v7 그리드, 안개·자갈 참조 직접 열람 및 렌더 메타데이터 확인.
> 범위: 지정한 이 파일만 작성한다. 기존 설계의 정정안은 아래에 적고 원본은 수정하지 않는다.

## 판정과 대표판

**f92를 현존 파일 중 접지 룩 시험의 대표판으로 선택한다. f100을 오른앞발 접지 완료판으로 승인하지 않는다.** f92는 두 발끝의 검은 부분이 바닥 그림자와 이어져 보이고 머리·몸통이 화면 밖이라 네 후보 중 우선한다. 다만 정지 이미지의 그림자 연결만으로 오른앞발의 실제 하중 수용까지 확정할 수는 없다. 최종 접지판 승인에는 원 시퀀스 또는 발 높이·접촉 기록 확인이 필요하다.

| 후보 | 직접 확인한 화면 | 판단 |
|---|---|---|
| f92 | 상단에서 하퇴 두 개가 들어오며 바닥이 네 모서리를 채운다. 두 발끝 아래 그림자가 이어져 보인다. | 우선 시험 베이스. 실제 접촉력은 미확인이다. |
| f96 | 정체 은닉·바닥 구도는 유지된다. 화면 왼발이 더 내려오지만 검은 발과 큰 그림자가 겹쳐 접촉 판단이 모호하다. | 예비판. f92보다 접지 증거가 강하다고 보기 어렵다. |
| f100 | 화면 왼쪽 발끝과 그 아래 분리된 그림자 사이에 밝은 틈이 보인다. | 접근 중 포즈·재질 시험에는 쓸 수 있으나 오른앞발 접지 완료 대표판에는 부적합하다. |
| f104 | 컨택트 시트에서는 화면 왼쪽 발이 내려오고 상단 중앙에 검은 몸체 일부가 걸린다. | 정체 은닉 여유가 부족하다. 개별 PNG가 없어 축소 시트 판정이며 원해상도 확인은 하지 못했다. |

f92·96·100은 감독 의도의 **정면 접근·위에서 다리 진입·바닥 가득·정체 미공개**와 대체로 맞는다. 큰 몸체 그림자가 왼쪽을 차지하므로 실사화에서 윤곽을 선명하게 새로 설명하면 은닉이 깨진다. 그림자 방향은 그대로 두고 대비만 낮춘다. 컨택트 시트 f108 이후에는 전면 구조가 드러나므로 그 구간을 s03 본편이나 핸들에 그대로 포함하지 않는다. 대표 접지판은 영상 시작판이 아니다. 빈 바닥에서 진입하는 시작과 후속 지지 인계는 별도로 검수한다.

렌더 JSON에서 높이 0.7m, 시선 높이차·수평거리 각각 0.7m, 수평 화각 약 33°, 해상도 1920×1080, 50fps를 확인했다. 하향각은 두 거리로 계산하면 45°다. 기록된 초점거리는 35.37mm, 수평 유효 폭은 20.955mm이며 풀프레임 폭 36mm로 환산하면 약 60.8mm다. “60mm”는 실제 기록값이 아닌 환산값이다. 기존 v5의 22cm·135mm·5°는 이번 블로킹과 함께 쓰지 않는다.

**접점과 돌 높이의 충돌:** 이번 바닥은 평지다. 발 아래 돌만 3cm 올리면 발이 돌에 파묻히거나 위치가 바뀐다. 첫 시험은 돌 윗면을 기존 접점에 고정하고 바로 주변 모래를 얕게 낮춰 3cm 기복으로 읽히게 한다. 기존 기준이 실제로 3cm 높이를 올라서는 동작까지 요구한다면, 돌과 발 지지를 Isaac에서 먼저 구현한 새 승인판이 필요하다. 편집 결과만으로 그런 동작을 검증했다고 쓰지 않는다.

## 웹 편집 절차와 슬롯

Seedream 4.5는 이미지 편집과 다중 이미지 입력을 지원한다. 다만 **현재 로그인된 Higgsfield 웹의 별도 베이스 슬롯·참조 슬롯·변형 강도 유무는 직접 확인하지 않았다.** 공개 모델 설명이나 API 입력 배열을 웹 UI의 구조로 단정하지 않는다. [ByteDance 공식 모델 설명](https://seed.bytedance.com/en/seedream4_5), [fal 편집 입력 스키마](https://fal.ai/models/fal-ai/bytedance/seedream/v4.5/edit/api).

1. 이미지 편집 화면에서 **Seedream 4.5 선택 여부**를 확인한다. 사이트 상단의 일반 “편집” 버튼만 보고 모델을 추정하지 않는다. 현재 별도 Layers 제품은 Seedream 5.0으로 안내되므로 다른 편집 모델과 혼동하지 않는다. [Higgsfield Layers 공식 안내](https://higgsfield.ai/higgsfield-layers).
2. 편집 대상 원본을 여는 영역 또는 원본 업로드 영역에 `launch_render/s03_block/block_f92.png`를 넣는다. 큰 편집 미리보기의 대상이 이 프레임인지 확인한다. 그리드 캡처·컨택트 시트·실패 v7은 업로드하지 않는다.
3. 실제 UI에 보조 참조 영역이 따로 있으면 베이스와 구분한다. 입력 썸네일만 있는 통합 방식이면 첫 이미지가 블로킹임을 확인하고 전문의 “supplied base image”가 그것을 지칭하게 한다. **첫 슬롯 자체에 강제 구도 보존 기능이 있다고 주장하지 않는다.** 베이스·참조 분리 UI가 없다는 이유로 실패는 아니지만 결과 대조는 필수다.
4. 첫 실행은 블로킹 한 장만 넣고 아래 전문을 사용한다. 16:9와 원본과 같은 화면 범위를 유지하고 시험 해상도는 2K로 한다. 자동 프롬프트 확장이나 재구성 옵션이 있으면 끈다. 한 번의 시험 결과부터 원본과 겹쳐 보고 다리·발·크롭이 보존됐는지 판정한다.
5. **변형 강도가 실제로 있을 때만** 높은 값일수록 많이 바뀌는 척도에서 0.20~0.30, 시작 0.25를 제작 제안으로 쓴다. 원본 보존도가 높을수록 덜 바뀌는 역방향 척도라면 0.70~0.80에 해당한다. 이는 Seedream 공식 권장값이 아니며 미실험 값이다. fal 공개 스키마에는 해당 강도 필드가 없으므로 없는 슬라이더를 찾거나 API 값으로 넣지 않는다.
6. 형태가 보존되면 룩을 보강한다. 지면·대기만 선택하는 마스크 기능이 실제 지원되면 다리·검은 발끝을 보호하고 해당 영역만 보정한다. 형태가 바뀌면 참조를 더 붙이거나 실패 결과를 연속 편집하지 말고 원본으로 돌아간다. 변경 강도 조절로도 구조가 유지되지 않으면 Isaac 재질·지면 렌더 또는 승인된 마스크 합성으로 전환한다.

## 합격 기준 · 세 줄

- 원본과 같은 화면 범위·두 하퇴의 외곽·발 위치를 유지하며 머리·몸통·센서·추가 다리·사람 형태가 없고, 큰 그림자가 정체를 새로 설명하지 않는다.
- 오른앞발과 돌의 접촉선이 보이고 발의 부유·돌 관통·발 크기 변경이 없으며, 자갈·얕은 홈·모래와 작은 먼지가 접점을 가리지 않는다.
- 원본 그림자 방향과 승인된 분지 색조·스케일을 유지하며, 모래빛 안개가 바닥 가득한 구도와 전경 접지 디테일을 훼손하지 않는다.

위 세 줄은 생성 결과의 시각 합격 기준이다. 실제 물리 접촉, 보행 연속성 및 최종 영상의 동시 정지는 별도 검증 대상이다.

## s15b·나머지 b컷 적용과 §E 정정

**s03 형태 보존 시험을 통과하면 같은 절차를 s15b에 우선 적용한다.** 다른 b컷도 정확한 발 접점·가림·대열 배치가 핵심인 컷부터 사용한다. s03 한 장의 성공이 전체 영상의 시간적 일관성을 보장하지는 않는다. 프레임마다 독립 편집한 결과를 그대로 연결하지 않는다.

| 정정할 자리 | 반영할 내용 |
|---|---|
| 스토리보드 §E · s03 | “프리비즈 입력 없음”은 **거부된 옛 프리비즈와 오염된 크롭의 입력 금지**로 유지한다. 이번처럼 감독 의도대로 새로 만든 승인 블로킹은 편집 대상 원본으로 허용한다. 버전·선택 프레임·승인 조건을 기록한다. |
| §E · s15·s15b | 우측 단일 접점에서 정면 집단 지지로 정정한 결정을 유지한다. 여러 앞열 개체와 깊은 행·열을 실제 최종 배치에서 렌더하고, 지지 완료판을 승인한 다음 실사화한다. 옛 43·46과 보행 중 프리비즈의 단순 크롭은 여전히 모델 입력에서 제외한다. |
| §E · 결말 연결 | s14~15b·s16·s17~18의 실제 개체·위치·방향 대응을 유지한다. 임의 직사각형 대열을 결말 글자 대형 대신 쓰지 않는다. 중앙 리더 한 대로 대표하지 않는다. |
| 제작 설계 §F · 시간 구분 | s03은 빈 지면 시작·접지 대표·지지 인계·핸들을 나눠 승인한다. s15b는 기존 설계상의 동시 마지막 접지 F6, 흡수 F7~11, 정지 홀드 F12~23을 실제 씬에서 구현·검수하고 F12를 대표 후보로 쓴다. 이 번호는 제작 설계값이며 이번 50fps 렌더 프레임 번호와 동일하지 않다. |
| 제작 설계 §F · 빛과 지면 | 이번 그림자 보존 지시를 따른다. 이전 v5 원고의 “먼 쪽으로 뻗는 그림자”와 현재 렌더의 화면 왼아래 그림자가 다르므로 둘을 한 전문에 섞지 않는다. 컷 간 월드 광원 일치는 씬 기준으로 확인하고, 틀리면 베이스를 고친다. 돌 접지는 편집으로 물리 검증을 대신하지 않는다. |

s15b 승인에는 여러 개체가 같은 정지 사건으로 마지막 지지를 완료하는지, 이후 발 미끄러짐·순차 정지 파동이 없는지 원 영상 검수가 필요하다. 남은 작업은 실제 웹의 모델·입력 UI 확인, f92 또는 접촉이 확인된 새 블로킹으로 첫 편집 실행, 원본 대조 및 정체 은닉 전 구간 검수다.

## 검토 범위

f104 개별 파일은 제공 경로에 없었고 컨택트 시트로만 비교했다. 원 영상의 직접 추출은 현재 기본 Python에 OpenCV가 없고 ffmpeg 실행 파일이 PATH에 없어 수행하지 못했다. 웹 UI를 조작하거나 이미지를 생성하지 않았다. 이번 판정은 접지·형태·입력 정책 검토이며 완성 이미지 승인이 아니다.

별도 검증을 `codex exec --model gpt-6-astra -c model_reasoning_effort=high`로 수행해 내부 검토안 기준 PASS·차단 오류 없음 판정을 받았다. 검증자는 f92·f100을 직접 열고 영어 전문 2,481자·금칙 문자열 0건, 하향각 45°·환산 초점거리 60.77mm를 독립 확인했다. 실제 하중·영상 연속성·f96·f104·기존 설계 원문·로그인 UI·변형 강도 효과는 이 추가 검증의 범위 밖이다.
