드라이버 v3.3 (머리 주석 (1)~(8)):
1. `--gpu 0|1`. GPU UUID 검사와 gpu_guard 가 그 장을 따른다.
2. `--plan base --order 24first`: 계획 (A)~(D) 의 실행 목록은 그대로, off24000 · on24000 실행만 앞으로 옮긴다. 블록 안 순서는 원래대로. 빠지는 실행 없음.
3. `--plan remeasure` (GPU 0, 학습 끝난 뒤): 24,000 의 시드 1000 (n 100) on − off 를 계획에 있는 모든 family × 칸 × noise 에서 훑는다 (평지 noise 켬 목표 세 칸은 (B) 가 이미 500 판이라 뺀다). 점추정이 −5 %p 이하이면 (정수 비교 `100 × (on 통과 − off 통과) ≤ −5 × n`) off24000 · on24000 의 시드 1001~1004 를 줄 세운다. 이 묶음은 base 계획에 없어서, 두 드라이버가 짝 묶음 (family, 칸, noise, 시드) 을 나눠 갖는 일이 없다. base 기록은 읽기만 한다.
4. 시도 기록: 실행마다 시도 ID (gpu-pid-시작 시각) 와 meta.json · cells.json · episodes.csv · traj.npz 의 sha256 을 실행 기록과 stamp 에 남긴다. 재사용할 때 해시가 바뀌었으면 다시 돈다. v3.2 stamp 는 해시가 없어 재검사만 통과하면 받고 이번에 해시를 붙인다 (ASTRA 15 9.2 「완료 기록 없음」).
5. 실행 중 명령 오차가 [0, 1e-6] 이어야 한다 (v3.2 는 음수를 통과시켰다 · ASTRA 15).
6. 기록 파일을 임시 파일 + replace 로 쓴다 (다른 인스턴스가 반쪽 파일을 읽지 않게). 시험 폴더 이름에 GPU 와 시작 시각을 넣어 재시작이 예전 시험 증거를 덮지 않는다.

## 3. 반박해 달라 (각 항목에 확인됨 · 추정 · 모름 을 붙여)

1. **순서 변경이 결과에 기대는 선택인가.** 24first 는 실행 목록을 줄이지 않고 순서만 바꾼다. 그래도 문제 되는 지점이 있나 (예: 14:00 이 아닌 다른 마감에서 잘리는 칸이 달라짐).
2. **재측정 표본에 훑기 시드 (1000) 를 넣는 것.** 걸린 칸은 시드 1000 이 나빠 보여서 뽑혔다. n 500 에 그 100 판을 다시 넣으면 평균으로의 회귀를 거슬러 퇴행 쪽으로 치우친다 (비퇴행 주장에는 보수적). 2(c) 문구 「500 판으로 다시 재서」 의 뜻으로 이게 맞나, 아니면 새 시드 400 판만으로 판정하고 1000 은 따로 적어야 하나. 400 판만 쓰면 구간 폭은 얼마나 넓어지나 (lead 계산 없음 · 확인해 달라).
3. **GPU 를 가른 것이 변수가 되나.** 시드 1000 묶음은 GPU 1, 재측정 시드 묶음은 GPU 0. 짝 비교 (on − off) 는 같은 묶음 안 같은 GPU 끼리다. 그래도 GPU 0 (화면 출력 장) 의 비결정성 · 속도 차이가 on − off 에 치우침을 줄 경로가 있나. 묶음 사이 (시드 사이) 변동을 따로 보고해야 하나 (ASTRA 7 2(b) 「배치 간 변동을 따로 보고」).
4. **기본 계약을 점추정으로 판정하는 것.** n 100 에서 95 % 선은 구간이 넓다. 점추정 · 구간 아래 끝 · 둘 다 적기 중 무엇이 2(c) 의 뜻에 맞나.
5. **훑기 통과 칸의 의미.** 점추정 −4 %p 인 n 100 칸은 구간이 −5 %p 를 크게 걸친다. 2(c) 통계 항목 「구간이 −5 %p 를 가로지르면 비퇴행 미확인」 과 팀장 확정 「점추정 −5 %p 이하 칸만 500 판」 이 부딪히나. 부딪히면 페이지에 어떻게 써야 정직한가.
6. **드라이버 구멍.** 임시 파일 replace (Windows · 읽는 쪽이 파일을 잡고 있을 때) · 재사용 한 번 훑기 · 시험 폴더 이름 · 학습 대기 · GPU UUID · 해시 stamp · base_finished (v3.3 기록만 끝으로 봄) · remeasure 의 끝나는 조건. 깨질 경로를 찾아 달라. 내가 만든 시험이 구현을 베낀 곳이 있으면 짚어 달라.
7. **집계 구멍.** v4 의 퇴행 · 계약 · 목표 판정이 2(c) 와 어긋나는 곳. 특히 MAE +10 % 를 퇴행 판정에 어떻게 넣어야 하나 (지금은 표시만 하고 판정 문구에는 안 넣는다).
8. **마감을 20:00 으로 늘리고 GPU 0 을 쓰는 것.** 팀장 조건과 부딪히는 것이 있나 (lead 가 아는 범위: 「자는 동안 GPU 상시」 · 로컬 GPU 두 장 실험은 승인 불필요 · 14:00 뒤 NAS 백업은 lead 몫이며 읽기만 한다).
