## 0. 먼저 볼 것

1. **실기 쪽 명령은 이미 속도형으로 정해져 있다.** 10/12 결정으로 실기는 Go2 EDU 순정 보행 + SLAM · Nav2 다 (`docs/DECISIONS.md` 134행). 순정 보행에 보내는 것은 「초속 몇 미터로 어느 쪽」 이라는 속도 지령이다 (`docs/FLOW.md` 6절).
2. **시뮬 쪽에서 지금 실제로 이어진 시험 셋도 모두 속도형이다.** 민우 (Isaac Sim + Nav2) · 현민 (Gazebo + 앱) · ACC 사이트 (MuJoCo + 경유점 제어기) 가 같은 파일 foothold-v2 (sha256 `e5c21321…`) 에 `(vx, vy, wz)` 를 넣는다 (ANALYSIS-members 5절). lead Top-down 설계의 맨 위 목표 (L0 · C1 「0.2 m/s 로 가 · 멈춰 · 옆으로」) 도 속도형 명령을 전제로 쓰였다.
3. **목표형은 둘 (현민 goal1r3 · 석헌 AME-2) 이고, 둘 다 Nav2 · 앱 · 트윈과 이어진 코드가 없다.**
4. **그런데 B-2 갈림길을 팀장이 정한 기록은 없다** (#546 · DECISIONS 에서 찾았으나 없음).
5. **속도형의 공통 약점은 저속과 정지다.** 민우 Nav2 명령 중앙 약 0.168 m/s (v2 학습 범위 0.4~1.5 밖) · 9/28 NVIDIA baseline 저속 제자리 · E1 0.1 m/s 이동 38 % · CMD-R 개선선 미충족 (+5.3 %p, #550) · 앱 STOP 뒤 0.32 m 더 이동.
6. **시뮬레이터가 넷이다** (Isaac Sim · Gazebo · MuJoCo · Isaac Lab 학습). 11/7 「정책이 트윈을 걷고 Nav2 가 돈다」 를 보이려면 한 곳에서 「앱 → Nav2 → 정책 → ACC」 가 한 번 이어져야 하는데 아직 없다.
7. **실기 다리 (Go2 SDK · 로봇 측 끊김 감시 · 제어권 · 정지거리) 는 코드 0 · 담당 0 이다.** 현민의 mock 9/9 뿐이다.
8. **RL 은 네 갈래가 따로 돈다** (v2 동결 · lead MoE-CTS · 현민 목표형 · 석헌 AME-2). ROLES 정본은 석헌이 `A/정책학습` 주담당인데 10/10~13 주 실험은 lead 가 돌렸다.

## 3. 이음매 B-1 · 앱 ↔ Nav2 (게이트웨이)

**사실** (ANALYSIS-members 3장)
- control-app 은 Nav2 의 경로 계산 · 목표 이동 · 취소를 `app_gateway.py` 가 대신 부른다 (TB3 에서 시험). foothold-app 은 「목표 보내기·자동 이동(NAV) · Nav2 미연결」.
- 만료가 넷이다: Gazebo 플러그인 0.5 s (시뮬 시간) · foothold-app 0.3 s · Go2 mock 0.3 s (실측 0.304) · 민우 어댑터 0.5 s (시뮬 시간).
- STOP = 명령 0 잠금이다. 몸이 서는 것과 다르다: exp33 명령 0 → 정지 시작 0.36~2.62 s · 최대 변위 0.3441 m, foothold-app STOP 뒤 3.6 s · 0.32 m.
- 목표 좌표: 현민 gateway 는 지도 판 `map_ver` 가 다르면 목표를 거부하고, AMCL 이 0.3 m · 20° 를 넘게 흔들리면 거부한다 〔첨부 locgate-r7〕. 민우는 코스 좌표를 런마다 실측해 map 으로 바꾼다.
- 「Nav2 SUCCEEDED 인데 실제는 미도착」 이 둘에게서 따로 나왔다 (민우 0.367 m · 현민 0.53 m).

**빈 곳 · 정할 것**
1. 앱 정본 (control-app · foothold-app) 과 둘을 합칠지.
2. 목표 좌표 기준 (ACC 코스 좌표 · SLAM map · 지도 판) 과 변환 책임을 어느 층 (앱 · 게이트웨이 · Nav2) 이 질지.
3. 「Nav2 성공인데 참값으로는 미도착」 을 앱에 어떻게 보일지 (ASTRA 검증 4-마 와 같은 물음). 실기에는 참값이 없으므로 무엇으로 도착을 판정할지도.
4. 만료 값 하나 (시뮬 시간 · 실제 시간을 구분해서).

### 4-2. 속도형의 공통 약점 · 저속과 정지

| 기록 | 값 | 근거 |
|---|---|---|
| 민우 Nav2 실제 명령 | `cmd_vx` 중앙 = 상한 0.5 의 33.6 % → 약 0.168 m/s (`계산`). foothold-v2 학습 `lin_vel_x` 0.4~1.5 | 〔민우 242〕 · 〔LD 95〕 |
| Nav2 + NVIDIA baseline (9/28~29) | 0.1~0.2 m/s 명령에서 거의 제자리 · foothold-v1 은 회전 명령에서 거의 안 돎 | 〔위키 exp-baseline-vs-v1〕 |
| lead E1 (MoE-CTS) | 평지 0.1 m/s 에 실제로 움직인 비율 38 % (model_20000) | #546 6105758209 |
| lead CMD-R (저속 · 정지 고치기) | 개선선 미충족 (+5.3 %p) | #550 2절 |
| 현민 exp33 · foothold-app | 명령 0 → 정지 시작 최대 2.62 s · 0.3441 m · STOP 뒤 3.6 s · 0.32 m | 〔위키 exp33 · app README.md 93행〕 |

그래서: 속도형을 고르면 「0.1~0.3 m/s 를 실제로 따르는가 · 0 을 주면 몇 초 · 몇 m 안에 서는가」 가 이음매 시험의 첫 항목이 된다. lead 설계의 C1 과 같은 물음이다. 실기 순정 보행의 저속 · 정지 성능은 아무도 재지 않았다 `미확인`.

### 4-3. 목표형의 사실

- 장점으로 든 근거: 「속도를 순간마다 정확히 맞추는 것보다, 지형에 따라 감속하거나 발을 옮긴 뒤 목표에 도달하는 행동을 학습할 여지」 〔현민 39〕 · AME-2 는 「속도는 정책이 스스로 정한다」 〔AME2 404〕.
- Nav2 와 잇는 방법 둘 (`추정`, 〔AME2 407~409〕): (가) controller 를 거치지 않고 전역 경로 앞쪽 지점을 목표로 넘긴다 · (나) `cmd_vel` 을 「현재 위치 + 속도 × 시간」 목표로 바꾼다. 석헌 HiPAN 검토 문서는 (나) 가 「속도 · 도착 시점을 강제하지 못한다」 고 적는다 (문서 인용 `확인됨`).
- 코드: 다리 코드 0. 석헌 쪽 상위 설계 (`LocalPoseCommandBridge` 등 모듈 6개) 는 「이미 존재하는 실행 파일 목록이 아니다」 〔AME2 431〕.
- 실기와: 순정 보행은 목표형 명령을 받지 않는다. 그래서 목표형을 이음매로 고르면 트랙 A 와 B 가 Nav2 아래에서 갈라진다.

### 4-4. 선택지 · 근거 · 영향

| 안 | 내용 | 근거 | 영향 |
|---|---|---|---|
| (가) 속도형 하나 | Nav2 → `(vx, vy, wz)` → 정책. 시뮬 · 실기 같은 계약 | 실기 고정 · 「같은 구조」 선호 · 붙은 코드 셋 · lead L0 · star 8/9 | 저속 · 정지를 정책이 해내야 함 (C1). 목표형 두 갈래는 이음매에서 빠짐 |
| (나) 목표형 하나 | Nav2 planner 경로 → 경유점 → 목표형 정책. controller 우회 | 정책이 지형에 맞춰 속도를 고름 · Nav2 저속 문제를 비켜 감 | 실기 (순정) 와 이음매가 갈림 · 다리 코드 0 · 11/7 위험 큼 · 앱 직접 조종 (속도형) 은 별도 경로로 남음 |
| (다) 이음매는 속도형, 목표형은 정책 연구 안에서 | (가) 를 계약으로 고정. 목표형은 트랙 A 연구 갈래로 같은 시험지에서 비교 · 나중에 (라) 로 갈 길을 남김 | (가) 와 (나) 의 근거를 같이 살림 | 목표형 결과가 11/7 시연에 안 들어감 · RL 분담 결정과 묶임 |
| (라) 두 모드 | 조종 · 근거리는 속도형 · 경유점 임무는 목표형 | 각 장점 | 정책 둘 또는 모드 전환 정책 · 시험 두 배 · 실기는 여전히 속도형뿐 |

**근거가 기우는 쪽** (`추정` · 결정은 팀장): 이음매 계약은 속도형, 곧 (가) 또는 (다). 까닭 다섯.
1. 트랙 B 실기가 속도형으로 고정돼 있다.
2. 팀장이 바란 「같은 구조」 는 이음매가 같아야 성립한다.
3. 지금 이어져 돌아가는 코드 셋이 모두 속도형이다.
