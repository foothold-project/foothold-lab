### resume 후보의 확인 범위

**확인됨.** `S/runners/on_policy_runner_cts.py:91~140,167~181,260~279`는 현재 번호부터 추가 N회 update하며 가중치·두 optimizer·저장 번호를 읽는다. `S/algorithms/moe_cts.py:299~311`는 별도 `alg.learning_rate`로 주 optimizer의 lr를 덮으므로 이 값도 맞춰야 한다.

**보강 필요:** 수정군 `pre_learn.state.json`은 counter=2,400인데도 zero 확률=0, base_height=-1, lin_vel_z=-2였다. 연속군 model_99의 해당 값은 0.006666…, -1.18, -1.866666…다. 명령 schedule은 resample 때, reward schedule은 curriculum 호출 때 갱신된다. 따라서 counter만 바꾸면 첫 rollout부터 맞는다는 보장은 없다. 또한 `code/resume_probe.py:116~125`는 **시험용 sidecar의 지형 레벨·RNG까지 복원한 후보**다. sidecar가 없는 E1에 그대로 적용할 수 없다. 100→200 작은 시험은 20k 명령 확대 경계를 시험하지도 않았다.

**미확인:** 이 후보로 E1 20k에서 처음 수집하는 command·reward가 모두 맞는지, E1의 정확한 중단 상태를 복원할 수 있는지, 수정 분기가 Q를 개선하는지. terrain 평균 5.67은 이번 지정 범위에서 원 학습 로그를 다시 집계하지 않은 lead 제공 수치이며, 평균만으로 env별 레벨을 복원하지 않는다.

## 2. G1·P1에 쓸 분기 규약

**제안: 처음부터 다시 학습하기보다, 동일 부모에서 상태를 명시적으로 재초기화한 대조 분기를 먼저 한다.** 묻는 것은 「같은 학습 이력 뒤 추가 개입의 효과」다. 원 학습의 연속 재현이나 scratch 대비 우월성은 별도 질문으로 남긴다. E1/E2 원본 checkpoint·로그·코드는 보존한다.

| 항목 | 양군에 공통으로 적용할 규약 |
|---|---|
| 부모 고정 | E1 model_20000을 사전 선택하는 안을 권고한다. 결과를 보고 20499와 교체하지 않는다. seed 43 반복은 E2의 같은 번호를 쓴다. 파일 SHA·코드 SHA·설정·G0 판을 기록한다. |
| 시계와 번호 | 마지막 저장 번호 L의 update가 완료됐음을 확인하고 다음 번호=L+1, `common_step_counter=(L+1)×24`. 24는 현재 runner·command·reward 코드와 일치해야 한다. parent 번호와 분기 후 update 수를 별도 기록한다. |
| 첫 rollout의 schedule | counter 설정만으로 끝내지 않는다. 해당 절대 시각의 명령 범위·env별 범위·남은 curriculum 항목·zero 확률·reward 가중치를 **명시적으로 동기화**한 뒤 새 episode 명령과 관측을 만든다. L=20000이면 평면 ±1, yaw ±1.5, zero 설정 0.1, base_height -10, lin_vel_z 0이어야 한다. 전체 curriculum을 무작정 호출해 지형 레벨까지 움직이지 않는다. |
| optimizer | 구조가 같은 분기는 두 Adam의 step·moment·group lr를 각각 복원한다. `alg.learning_rate`는 주 optimizer lr와 맞추되 학생 encoder lr를 그 값으로 덮지 않는다. 표본에서 주 lr≈0.0002963, 학생 lr=0.001이었다. 이후 적응형 lr 차이는 학습 결과일 수 있으므로 양군을 억지로 맞추지 않는다. |
| 지형과 episode | E1에 env별 상태가 없으므로 원 상태 복원을 주장하지 않는다. 양군 모두 새 episode 길이 0, 기존 초기화 범위인 level 0~5의 균등·층화 배정으로 시작하는 안을 권고한다. 같은 family·같은 env 슬롯은 같은 level·DR·초기 자세를 갖게 하고, 이후 같은 curriculum 규칙을 적용한다. level과 함께 terrain origin·scene origin·실제 root 위치의 일치까지 검사한다. 원 학습의 평균 level을 모든 env에 복사하지 않는다. |
| 난수와 위상 | 예: parent42→branch1042, parent43→branch1043을 새 난수 시드로 선언한다. 한 비교의 양군은 같은 seed·초기 배열을 공유하고 Python·NumPy·torch CPU/CUDA 상태를 기록한다. 시드 숫자만 같다고 pairing 완료로 보지 않는다. 초기 episode 길이를 다시 무작위화하는 `learn(init_at_random_ep_len=True)`는 이 제안과 충돌하므로 false로 고정한다. 이 변경도 양군 공통의 분기 규약이다. |
| 보존할 분기 상태 | 양군 개입 직전 가중치·optimizer·시계·실효 schedule·level 배열·origins·DR/자세·RNG·episode 위상·명령/history 초기화 규칙을 남긴다. 이 기록만으로 물리 엔진 내부까지 bitwise resume가 된다고 선언하지 않는다. |
| 추가 예산 | `--max_iterations=N`은 총 목표 번호가 아니라 추가 update 수다. L=20000, N=8000이면 20001~28000을 수행한다. 번호와 환경 수·24 step도 함께 기록한다. 시간 상한으로 한 군이 먼저 끝나면 공통으로 완료한 update 지점끼리만 비교한다. |

**실행 전 관문 제안:** 가짜 L=99로 다음 번호 100·counter 2,400·추가 3회가 100~102인지 먼저 확인한다. 이어 20k 경계의 목표값과 첫 관측·첫 reward·첫 24-step 수집·첫 update 후 상태를 검사한다. 같은 분기 설정으로 짧은 무개입 A/A를 먼저 돌려 초기 hash와 명령 표본·reward 설정이 일치하는지 확인한다. GPU 수치 비결정성은 별도로 재고, 불일치를 개입 효과로 넘기지 않는다. 이 GPU 관문은 아직 실행하지 않았다.

**G1:** 선택·고정된 동일한 명령 규약과 G0를 양군에 사용한다. 변수는 원 설계대로 p_gap=0 대 0.10, flat=0.15−p_gap뿐이다. 공통 family의 지형 seed·열·난이도를 보존하고 교체하는 flat 슬롯만 gap으로 바꾼다. 같은 전역 seed여도 생성 순서 변화로 나머지 지형이 달라질 수 있으므로 실제 배정을 비교한다. 군당 추가 8,000 iter·최대 12시간, seed 43 반복은 별도 24 GPU-hours라는 기존 제안 상한을 유지한다.

**P1:** G1 이후 채택한 같은 부모에서 masked/map 두 군을 새로 갈라야 한다. G1 대조군과 gap군을 각각 P1의 서로 다른 부모로 쓰면 지형 학습 이력까지 달라진다. 두 군의 student 구조·새 encoder 초기값은 같고 지형 입력 제공 여부만 달라야 한다. 구조 변경 시 기존 Adam을 무조건 전부 load하지 말고, 이름·shape가 같은 parameter만 이관하며 새 parameter의 상태 초기화 규칙을 양군에 같게 적용한다. 불가능한 경우 해당 optimizer 재초기화를 양군에 동일하게 선언한다. E1→P1 직접 분기도 가능하지만 그 경우 gap 학습을 마친 부모라고 부르지 않는다.

**scratch로 바꿀 때:** 수정 sampler가 처음부터의 학습에 미치는 효과를 묻거나, 부모·새 stage의 영향이 너무 커 개입을 판별하지 못했을 때 별도 실험으로 한다. 실패를 보고 한 군만 scratch로 바꾸지 않는다. 지금은 원 재현 E1/E2를 다시 만드는 것보다 통제 분기가 비용과 질문에 맞는다.

## 3. 명령 분포 개입의 자리·한 변수·예산

**순서 제안:** Q 계약 고정·E2 비교 → 분기 초기화 관문 → CMD-R → 필요 시 CMD-S·CMD-L → 명령 규약 고정 → G1 → P1. D1·G0 진단은 이와 병행할 수 있다. 이 일정은 기존 DESIGN 5절의 날짜 배치를 대체할 제안이며 자동 실행 승인이 아니다. 정지·저속 노출이 부족한 상태를 그대로 늘리는 25k·30k·50k 연장은 우선순위에서 내린다.

| 실험 | 바꿀 변수 하나 | 비교군과 통제 |
|---|---|---|
| **CMD-R · 먼저** | command reset에서 사용할 episode 나이: 종료 직전 값 대 새 episode의 0 | 같은 부모·G0·gap 미포함·동일 분기 규약. 외부 runner/adapter에서 command sampling에만 유효 episode 나이 0을 전달하는 안이다. 하한 식과 zero 처리의 남은 시간 계산에 같은 나이를 쓰고, periodic resample은 그대로 둔다. Isaac Lab 전체 reset 순서를 앞당겨 terrain curriculum·종료 통계까지 바꾸지 않는다. 범위·resample 주기·reward·네트워크·정지 비율을 같이 바꾸지 않는다. |
| CMD-S · 완전 정지 노출이 필요하면 다음 | 신규 완전 정지 슬롯 확률 p_stop=0 대 0.10 | CMD-R 판을 고정한 같은 부모에서 새 쌍을 만든다. 선택 슬롯만 `(vx,vy,wz)=(0,0,0)`으로, 유지 시간은 사전 고정한 5초. 나머지 sampler는 같다. 기존 planar-zero 확률을 바꾸는 실험과 혼동하지 않는다. |
| CMD-L · 저속 노출이 필요하면 다음 | 신규 저속 슬롯 확률 p_low=0 대 0.10 | 정지 슬롯 규약까지 양군에 같게 고정한다. 정지·저속 슬롯은 겹치지 않게 배정한다. 저속 슬롯은 전·후·좌·우를 균등 선택하고 속도 크기 U[0.05,0.20) m/s, wz=0, 5초 유지. 나머지는 기존 sampler. 정지와 저속을 동시에 바꾸고 각자의 효과를 따로 주장하지 않는다. |

확률은 **resample 슬롯 할당률 제안**이다. episode 조기 종료와 기존 가변 주기 때문에 실현 env-step 비율 10%를 보장하지 않는다. 슬롯 선택과 원래 난수 추출의 소비 순서도 양군에 맞추고, label·원인별 사건 수와 시간 비율을 실제로 잰다. CMD-R만으로 첫 하한이 약 0.225가 되고 명시적 정지도 없으므로 fwd01·정지 Q 회복을 당연한 결과로 기대하지 않는다. S/L의 비율은 최적값이라는 근거가 없는 **설계 제안**이다.

**예산 제안:** 우선 CMD-R만 seed42 부모의 양군에 군당 추가 4,000 iter 또는 6 GPU-hours 중 먼저 닿는 상한을 둔다. 쌍 합계 최대 12 GPU-hours, 판정이 유망하고 퇴행이 없으면 seed43 부모에서 같은 쌍을 반복해 추가 최대 12 GPU-hours다. 0·2k·4k를 사전 평가 지점으로 정하며 결과를 보고 좋은 중간 checkpoint만 고르지 않는다. S/L도 실행하기로 결정할 때 각각 같은 별도 상한을 승인받는다. 세 실험 모두 두 seed를 쓰면 최대 72 GPU-hours가 추가되므로 기존 총예산에 조용히 넣지 않는다. 초기 관문·평가 시간은 이 학습 상한과 별도 집계하며 기존 여유 예산을 넘기면 다시 정한다.

**판정 기준 제안:**

- 먼저 계측 관문: reset 나이=0, command 유효 범위, episode 로그·terrain curriculum의 기존 의미 보존, 의도한 슬롯/시간 노출을 검사한다. 후반부에도 하한>상한이 남을 수 있으므로 별도 카운터로 기록한다. CMD-R 시험 도중 그 sampler 동작까지 함께 고치지 않는다.
- Q는 VERIFY-astra-4가 요구한 시간 경계·noise·저속 기준의 **같은 판**을 사전에 고정한다. 실제 속도로 정지 잔류 속도·제동 시간·drift, 0.1/0.2 저속 MAE, 전·후·횡·회전과 기존 family의 성공/실패를 비교한다. teacher/student와 넘어짐·방향·속도 실패를 나누며 train reward만으로 채택하지 않는다.
- 초기 선별은 고정 validation의 cell당 100episode, 채택 전 확인은 해당 목표·퇴행 cell에 두 seed 각 500episode를 사전 배정하는 안이다. 같은 eval 배치·초기 상태로 쌍을 만들고 성공률 차이와 MAE 차이의 불확실성을 보고한다. env-step 수를 독립 episode 수로 세지 않는다. 개선할 cell과 확인할 손실 cell을 결과를 보기 전에 정한다.
- 성능 개선 주장은 목표 cell에서 통과율 +10pp 이상이 두 seed 같은 방향이고, 기존 cell 통과율 하락 ≤5pp·MAE 악화 ≤10%일 때의 후보로 한정한다. 대조 MAE가 0이면 상대비 대신 Q 허용 오차의 10%를 절대 상한으로 사전 설정한다. 작은 표본이나 구간이 퇴행선을 가로지르면 **미확인**이다. CMD-R은 성능 차이가 없어도 의미 오류 수정과 퇴행 없음이 확인되면 규약 교정으로 채택할 수 있으나, Q 개선이라고 쓰지 않는다.
- Q 회복이 없다고 즉시 scratch·장기 연장·네트워크 변경으로 넘기지 않는다. CMD-R 뒤 완전 정지가 여전히 0이면 S, 저속·축 단독 노출이 부족하면 L을 검토한다. 충분히 노출했는데 실패하면 reward·관측·동역학/증류 진단으로 돌아간다. Q 미달 상태에서도 G1을 원인 진단으로 할 수 있으나 기본 주행 능력 확보나 실기 채택의 근거로 쓰지 않는다.

## 4. Q-E1·QD-E1·20499 하락에 적용할 해석

**기존 측정값을 지우거나 합격으로 바꾸지 않는다.** 이번에는 해당 Q 원시 궤적 전체를 다시 평가하지 않았으며, 아래는 지정된 결과를 해석할 때 바꿀 설명이다.

**추정:** 명령 노출 부족과 상한 대각선 편향이 정지·저속 약점 및 확대 뒤 퇴행에 기여했을 수 있다. 기여 크기와 인과관계는 대조 학습 전까지 미확인이다.

| 대상 | 사용할 설명 | 아직 할 수 없는 결론 |

## 5. 팀장 확정 필요 항목

- 부모 model_20000 고정, 새 episode·level 0~5 균등 배정, branch1042/1043을 사용하는 **통제된 분기 규약**. 더 높은 level을 쓰려면 양군 공통의 다른 사전 규약으로 정하고 E1 상태 복원이라고 부르지 않는다.
- counter·lr·번호 후보에 첫 rollout schedule 동기화를 더한 외부 실행기 변경과 짧은 A/A 관문 실행. E1/E2 원본에는 적용하지 않는다.
- G1 앞 CMD-R 우선 배치와 최초 쌍 최대 12 GPU-hours. 반복과 S/L은 별도 판단·예산이며, 이 문서는 실행 승인이 아니다.
- Q 계약의 최종 판과 사전 목표 cell·퇴행선, CMD 판을 고정한 G1/P1의 새 부모 계보. 일정상 CMD를 생략한다면 G1 결과를 「기존 편향 sampler 아래 gap mixture 효과」로 제한할지 결정한다.

이번 작업은 이 파일 하나만 신규 작성한다. 원자료·학습 코드·다른 문서는 수정하지 않았고, 학습 실행·커밋·push는 하지 않았다.
