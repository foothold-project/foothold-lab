## 1. 무엇을 바꿨나

**물음.** E1 teacher 는 height scan 의 올바른 공간 배치로 이득을 얻는가 (설계 4절 D1).

**바꾼 변수 하나: teacher 에 들어가는 height block (187 칸) 의 공간 순서.** 정상 대 고정 순열 하나. 순열은 `numpy.random.RandomState(2026).permutation(187)` 로 만들어 모든 실행에 같은 것을 썼다 (sha256 `8c40566f6c545a9b474cbd5f85c1851582a5a019b2dca000440c0a7cee281888`, 제자리에 남은 칸 2 개, 순열 전체는 각 실행 `meta.json` 의 `height_perm`). 값의 묶음은 그대로이고 자리만 바뀐다 (확인됨: 정렬 비교가 모든 실행에서 같음). height 밖의 privileged 입력 · 지형 · 초기 상태 · 명령 · DR 은 그대로다.

**height block 의 자리. 확인됨.** critic 관측의 항 순서와 크기를 observation manager 에서 읽었다: base_lin_vel 3 · base_ang_vel 3 · projected_gravity 3 · velocity_commands 3 · joint_pos 12 · joint_vel 12 · actions 12 · joint_acc 12 · joint_torque 12 · contact_force 16 · height_scan 187 (합 275). height block 은 critic 의 88~274 칸이다. 이 칸을 ray sensor 에서 `clip(센서 높이 − 맞은 점 높이 − 0.5, −1, 1) × 2.5` (`env_cfg.py:225`~229, Isaac Lab `height_scan`) 로 다시 계산한 값과 비교해 모든 실행에서 차이 0 이다. 순열 뒤 height 밖 칸의 변화도 0 이다.

**teacher 평가 경로 (mean). 확인됨.** 학습 때 teacher 행동은 `ActorCriticMoECTS.act(obs, is_teacher=True)` (`actor_critic_moe_cts.py:210`~223) 가 `critic_obs_normalizer` → `teacher_encoder` 로 latent 를 만들고 `single_obs` 와 이어 `actor` 에 넣은 분포에서 표본을 뽑는다. 평가는 표본 대신 평균을 쓴다. `state_dependent_std` 가 False 라 평균은 `actor(...)` 출력 그대로다 (`_update_distribution`, :186~208). 평가 어댑터 `teacher_mean` (`_eval/q_eval.py`) 은 이 계산을 손으로 이었고, 모듈 자신의 `act(is_teacher=True)` 뒤 `action_mean` 과 모든 실행에서 차이 0 이다 (이 비교는 `torch.random.fork_rng` 안에서 해서 env 난수를 건드리지 않는다). 순열 없이 항등 순열을 넣은 결과도 정상과 차이 0 이다.

**cell · 지형 · 표본.** Q-E1 주 실행과 같다: 8 지형 (flat · wave · slope_up · slope_down · rough_slope · stairs_up · stairs_down · obstacles) × 11 cell × 100 episodes, 난이도 0.5, 관측 noise 끔, 평가 시드 1000. 경사 · 계단 띠 출발도 Q-E1 띠 출발 실행 그대로 (7 험지 × stand · stop03 · yawL05 · yawR05 × 100, stand · yaw +2.5 m, stop03 +1.75 m). 띠 출발 cell 을 stop03 하나로 줄이면 env 배치가 달라져 S 를 재사용할 수 없어 네 cell 을 모두 돌렸다. gap 은 D1-A 범위 밖이다. 학습 비중 0 은 gap 을 빼는 이유가 아니라 학습 외 일반화 시험으로 구분할 이유다. G0 (no-hit · finite · clip/scale · 발 지지면 검사) 를 마친 뒤 D1-B 로 따로 잰다. 판정 정의는 Q-E1 임시 평가 조건과 같다 (Q1 · Q2 · 낙상 · 이동 보조).

**짝. 확인됨 (범위는 아래).** 지형 · 출발 9 묶음 × 체크포인트 2 = 18 묶음 모두에서 S · T · Tp 세 실행의 초기 root 자세 · 관절각 · 몸 질량 sha256 과 지형 메시 sha256, 체크포인트 sha256, 지형 · cell · episode · 시드 · 출발 설정이 같다 (표 1). 판 1 은 여기에 「관절 강성」 hash 도 넣었는데, Go2 actuator 는 explicit 형이라 Isaac Lab 이 sim 관절 강성을 0 으로 두고 무작위 게인은 actuator 객체에 둔다. 그 hash 는 상수 0 을 잰 것이라 게인 DR 을 덮지 않았다 (판 2 에서 sim 강성 최소 · 최대 0 · 0 확인). 판 2 에서 COM · 마찰 · 반발 · actuator 강성 · 감쇠 · 모터 영점 · 지연까지 넓힌 fingerprint 를 만들어, stairs_up 설정을 S · T · Tp × 두 체크포인트로 rollout 전까지만 다시 띄운 6 실행 (`out/fp_*`) 에서 모두 같고, 이 6 실행의 옛 hash 는 기존 S · T · Tp 실행과 같음을 확인했다. 다른 지형 묶음의 넓힌 DR 동일성은 같은 시드 · 설정 · 코드 경로에서 나온 추정이다. 다른 것은 정책 경로와 순열뿐이다. Q-E1 주 실행은 `--spawn_offset` · `--heading_hold` 옵션이 생기기 전 판 (`q_eval_batch1.py`) 으로 돌아서 meta 에 그 칸이 없다. 없는 칸은 옵션 기본값 (출발 오프셋 없음 · heading hold 끔) 과 같게 보고 비교했다.

**장치. 확인됨.** 모든 D1 실행이 `CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=1`, env · sim · runner · policy 모두 `cuda:0` = UUID 315d098f (GPU 1). GPU 0 은 실행 내내 14,611 MiB 그대로 (E2), pid 25916 그대로. 실행마다 GPU 1 여유가 4 GiB 아래로 내려가면 멈추는 관문을 두었고 걸린 적 없다 (최소 여유 5.4 GB). GPU 사용 50.0 분.

## 7. 판정과 해석

**설계 D1 판정 (확인됨).** 「teacher 는 지형 정보 교란 시 유효 통과 비율이 10 pp 이상 낮아지는가」 에 대해: 지형 · 출발 묶음 15 개 중 20000 은 8 개, 20499 는 6 개에서 그렇다. 크게 떨어지는 곳은 wave · stairs_up · stairs_down 중앙 출발과 경사 · 계단 띠 위의 정지 · 회전이다. 실패는 주로 넘어짐이 아니라 추종 실패다. 20000 stairs_up 띠에서 생존은 100 % 그대로인데 통과가 91 → 48 % 로 떨어지고, MAE wz 가 0.080 → 0.180 으로 커진다 (띠 4 cell 의 평균. `out/D1-E1-cells.csv` 의 cell 값에서 계산). 낙상도 는다 (20000 47 → 117, 20499 41 → 99 건, 표 6). 따라서 **이 고정 순열 기준으로 E1 teacher 는 height scan 을 쓰고, 그 공간 배치가 바뀌면 계단 · 물결 지형에서 명령 추종이 무너진다.**

평지는 순열이 입력을 거의 바꾸지 않아 판정에서 뺐다 (표 2 의 첫 관측 차이 1e-5 수준). slope_up · slope_down 중앙 출발도 차이가 작다. 이 묶음은 출발이 3 m 평평한 platform 위라 첫 관측의 height map 이 평평하고 (표 2), 경사가 단순한 평면이라 순열이 만드는 혼란이 작을 수 있다 (추정). obstacles 는 두 체크포인트 모두 7 pp 안팎으로 기준 미만이다. 반대 방향 1 cell (20499 slope_up 띠 stop03, 67 → 96 %) 은 원인 미확인이다.

**teacher 대 student (확인됨).** 지형 합계로 teacher 와 student 의 Q 통과 차는 -3.7~+6.0 pp 이고 대부분 ±2.5 pp 안이다. cell 단위로는 양쪽 방향이 다 있다 (예: 20499 stairs_up back03 은 student 67 % · teacher 33 %, 20000 띠 출발 slope_up stop03 은 student 76 % · teacher 94 %). 낙상은 teacher 가 더 많고 (47 대 10, 41 대 12) 대부분 obstacles 에서 난다. 즉 **이 Q cell 들에서 teacher 는 height 를 쓰지만 student 보다 낫지 않다.** student 는 height 없이 몸 감각 history 만으로 같은 수준에 있다.

**다음 조건과의 연결 (추정).** 설계 D1 의 다음 조건은 「teacher 가 낫고 student 가 못 따라오면 P1, teacher 까지 gap 에 실패하면 G1」 이다. 이번 D1-A 는 학습한 지형에서 teacher 가 낫지 않으므로 P1 의 근거가 되지 않는다. 미리 보아야 하는 과제 (gap · 희소 발판) 는 D1-A 범위 밖이라, G1 · P1 을 고르는 근거로 쓰기 전에 G0 와 D1-B (gap 대조) 가 필요하다. 원인은 하나로 확정하지 않는다. 학습 지형은 몸 감각만으로도 풀리는 과제여서 height 의 이득이 통과율로 드러나지 않았을 수 있다 (추정).

**단서.**
- teacher 는 height 말고도 privileged 입력 (몸 선속도 · 관절 가속도 · 토크 · 발 접촉력) 을 받는다. 그래서 teacher 대 student 격차 (T − S) 전부를 height 효과로 쓰지 않는다. height 의 몫은 T − Tp 로만 본다.
- 순열은 학습 때 본 적 없는 입력 (분포 밖) 이다. 순열에서 나빠지는 것은 「배치를 쓴다」 와 「이상한 입력에 흔들린다」 를 함께 담는다. 순열에서 안 나빠지는 것은 「이 과제에서 배치 이용 증거 없음」 까지만 말한다. 이것만으로 지형 인지를 입증하거나 부정하지 않는다 (설계 D1 수치 판정 그대로).
- 판정은 Q-E1 임시 평가 조건 (Q2 는 순간값 · 50 표본, 관측 noise 끔) 을 쓴다. ASTRA 4 가 제안한 51 표본 정의 · 기울기 11 표본으로 다시 세면 D1-A 실행 46,400 episodes 중 생존이 바뀐 것은 4 episode 이고, 지형 합계 판정 (10 pp) 묶음 수는 20000 8 개 · 20499 6 개로 판 1 과 같다 (가장 큰 변화는 20000 stairs_up 띠 42.8 → 43.2 pp). 계약이 정해지면 궤적에서 `q_post.py` 로 다시 계산한다.
- 위험 착지 · 발 접촉은 재지 않았다 (계측기 없음). 낙상은 Q-E1 과 같은 세 규칙이다.
- cell 별 McNemar 는 여러 검정을 함께 한 **탐색 결과** 다. 232 검정에서 보정 전 p < 0.05 는 순열에서 나빠진 쪽 77 · 좋아진 쪽 1, Holm 보정 뒤 55 · 1 이다 (제안 시간 정의로는 보정 전 76 · 1, Holm 뒤 55 · 1. `out/Q-E1-astra4-tables.md` 표 A5).
