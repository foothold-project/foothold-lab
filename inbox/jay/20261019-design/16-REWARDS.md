## 2. 발 가장자리 보상

- 식: r = -Σ_{i∈feet} c_i · Σ_{d∈dist} ω_d · E_d[p_i], dist = [2.5, 5.0] cm, ω_d = [1.0, 0.5] (**논문** 239~257 행, 식 6).
- 마스크: 지형 전체 크기의 불리언 격자. 높이장을 메시로 바꿀 때 경사가 문턱을 넘는 곳을 세로 모서리로 찾고, 모폴로지 팽창으로 2.5 cm · 5 cm 띠를 만든다. 바깥 띠는 안쪽 띠와 겹치는 곳을 뺀다(**선행** 280 행).
- 경사 문턱 값: 미기재 → **가정** 「인접 칸 높이차 ≥ 0.05 m」 (돌 · 빔 높이 변화 ±5 cm 와 같은 크기로 맞춤).
- 방향과 무관한 기하 식이라 옆 · 뒤 디딤에도 그대로 성립한다(ASTRA 19f Q3 · fable 20e Q3). 이어진 지형(계단 모서리)에도 마스크가 생긴다. 계단 모서리는 정상 접촉이므로 **이어진 지형군에서는 이 항을 끈다** → **가정** (ASTRA 19f 「계단의 정상 모서리 접촉과 추락할 edge 가 섞인다」).

## 3. 결정 항목: 선속도 추종식

| 안 | 식 | 장점 | 단점 | 출처 |
|---|---|---|---|---|
| A. START 그대로 | min(v, v_cmd) | 논문 충실. 명령보다 느리면 벌을 받고 빠르면 받지 않는다 | 명령보다 빨리 가도 벌이 없다 → 주행층이 준 속도와 실제가 어긋난다 | **논문** 표 1 항 |
| B. 정확 추종 | exp(-‖v_cmd - v‖² / 0.25) | 주행층(HiPAN 상위)이 배운 「명령 → 움직임」 관계가 유지된다. HiPAN 저수준도 정확 추종(0.4 가중치) | START 와 한 항이 다르다 | **논문** HiPAN Table III r1 · fable 20e R4 |

**lead 권고: B.** 이유는 세 층 구조 때문이다. 보행층은 조이스틱과 주행층 둘 다의 「명령을 그대로 하는 장치」 여야 한다. START 는 단독 보행이라 A 로 충분했다. 가중치 1.5 는 START 값을 유지한다. 「우리 변경」 으로 기록한다. → 팀장 결정 필요.

## 4. 걸음새 교훈 (측정을 먼저)

| 사례 | 무엇 | 출처 |
|---|---|---|
| v2 | `feet_air_time` 하나만 발 보상, 「시간」 을 점수로 줘서 발을 3.25 cm 만 든다 | **실측** v2 보고서 6-10 · 7 절 |
| 석헌 AME-2 Go2 | 바운딩(네 발 동시 비행 25~33 %). 도약 벌점(-1, 문턱 0.2 m)이 스캔 무반사 · 고도차 조건 때문에 도약 스텝의 약 78 % 에서 꺼져 있었음. 10/12 설정 변경(도약 -5 / 0.3 m, 비발 접촉 -5, 자기충돌 센서, 처음부터) 뒤 대각 보행 75~80 % 로 돌아왔으나, 같은 판에서 0.3 m 넘는 틈 · 돌 성적이 떨어짐 | **실측** REPORT-seokheon-ame2.md 0 · 1.3 · 3 절 |

정리:
- START 표에는 발 높이 · 걸음 위상 항이 없다. START 영상은 듬성한 지형에서 「낮은 걸음 빈도로 안전 영역에 디딤」, 평균대에서 「역삼각 자세와 높은 걸음 빈도」 를 보인다(영상 1:30 · 1:46). 걸음새는 보상이 아니라 지형과 가장자리 항에서 나온 것으로 읽는다(해석).
- 그래서 1 차에는 걸음새 보상을 **더하지 않는다**. 대신 석헌의 `diag_gait.py` 지표(네 발 비행 비율 · 두 발 지지 중 대각 / 앞뒤쌍 / 같은쪽 비율)를 학습 중 체크포인트마다 자동 측정한다. 바운딩이 25 % 를 넘으면 경고 → **가정** (문턱).
- 석헌 사례의 교훈 「벌점이 켜지는 조건이 실제 상황의 22 % 에만 걸렸다」 를 따라, 우리 벌점 항은 켜짐 비율을 함께 기록한다.

## 5. 깃발 방식에서의 보상

- 깃발 지형에서도 보상은 위 14 항 그대로다. 깃발은 명령을 만드는 장치일 뿐 보상이 아니다(**코드** JEPLO: 깃발 지형도 같은 속도 추종 보상, evidence/maicode-jeplo-deep `rewards`).
