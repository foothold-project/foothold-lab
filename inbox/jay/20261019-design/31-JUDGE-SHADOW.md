# 31 · 판단층 (그림자 모드)

## 1. 자리

```mermaid
flowchart TB
  CTX[상황 요약 텍스트 · 위치 · 목표 · 지형 등급 · 최근 실패 · 배터리] --> J
  IMG[전방 카메라 프레임 · 1 Hz 이하] -.Jev 1.14 만.-> J
  J[판단 모델 · Laya 또는 Jev] --> LOG[조언 기록 · 그림자 모드]
  RULE[규칙 기반 판단 · 대조군] --> LOG
  LOG -.2 차부터 · 승인 뒤.-> ACT[목표 바꾸기 · 멈춤 요청 · 운영자 확인 카드]
  JOY[조이스틱 · 앱 손 조종] --> CLEAN[명령 정리기 · 1 차 규칙]
  CLEAN -- vx vy wz --> LOCO[보행층]
```

판단층은 50 Hz 보행 · 10 Hz 주행 루프 **밖**이다. 2~10 Hz 조언이고, 늦거나 끊겨도 로봇은 계속 안전하게 움직여야 한다. Laya 와 Jev 는 같은 자리에 바꿔 끼운다(팀장 10/19).

## 2. 두 모델

| 항목 | Laya | Jev 1.14 | 출처 · 등급 |
|---|---|---|---|
| 실행 위치 | 로컬 | 원격 API(호스팅, 공개 가중치 없음) | panews 기사 · **공개 자료** |
| 지연 | 약 33 ms(배치 7.2 ms) | 공급사 70~500 ms, 데모 평균 227 ms | 19d · 20c 인용값 · 우리 **미측정** |
| 입력 | 텍스트 | 텍스트 + 이미지(PNG · JPEG, 헤더 `TypeSafe-Danger-Zone-Images: true`) | TypeSafe 블로그 |
| 출력 | 선택지 고르기 | 선택지 + **Box 질문형**(이미지 위 상자 하나, 비율 좌표 + 신뢰도) | TypeSafe 블로그 · panews |
| 문맥 | 미기재 | 기본 64k / 질문 32k, 선택 시 262k | panews |
| 제품 사용 | 미기재 | **제작사가 이미지 · Box · 긴 문맥을 「danger zone」 으로 두고 제품용으로 보증하지 않는다고 명시.** 멀티모달은 텍스트보다 성능이 낮다고 적음 | TypeSafe 블로그 |

결론: Jev 이미지 · Box 는 **그림자 모드 실험 항목**이다. 제어 경로에 넣지 않는다.

## 3. 입력 · 출력 계약

**입력(상황 요약, 2 Hz)**: 현재 위치(지도 틀), 목표, 앞 3 m 지형 등급(22 문서 등급 지도 또는 실기 SLAM 추정), 최근 10 초 낙상 · 미끄러짐 · 추종 오차, 주행층 모드(HiPAN / Nav2 대체), 배터리, 운영자 명령. Jev 만 전방 카메라 프레임 1 장(≤ 1 Hz).

**출력(선택지 고정)**:

| 선택지 | 뜻 | 1 차(그림자) | 2 차(승인 뒤) |
|---|---|---|---|
| 계속 | 아무것도 안 함 | 기록 | 기록 |
| 멈춤 요청 | 주행층에 정지 요청 | 기록 | 운영자 확인 카드로 표시(앱 「운영자 확인 카드」, ANALYSIS-app-prd-553 72 행) |
| 목표 바꾸기 | 다른 경유점 제안 | 기록 | 운영자 확인 뒤 적용 |
| 위험 위치(Jev Box) | 프레임 속 위험 물체 상자 | 기록 · 화면 표시용 | 표시만 |

자동 실행은 없다. 2 차에도 사람 확인을 거친다(앱의 「자동 재개 없음」 원칙과 같음).

## 4. 규칙 기반 대조군

같은 입력에서 규칙이 내는 판단을 함께 기록한다. 두 검토(ASTRA · fable)가 모두 「규칙 기준선과 비교」 를 요구했다.

| 규칙 | 조건 | 판단 |
|---|---|---|
| R1 | 최근 10 초 낙상 · 큰 미끄러짐 2 회 | 멈춤 요청 |
| R2 | 앞 3 m 에 통과 불가 등급 | 목표 바꾸기(우회) |
| R3 | 추종 오차가 학습 때 95 분위를 5 초 넘게 넘음 | 멈춤 요청 |
| R4 | 통신 지연 > 1 s | 멈춤 요청(앱 hb 규칙과 같은 문턱) |

문턱은 **가정**. 비교 지표: 규칙과 모델의 판단 일치율, 사후 라벨(실제로 낙상 · 정체가 났는가)에 대한 정밀도 · 재현율.

## 5. 명령 정리기 (1 차: 규칙만)

1 차 보행층은 듬성한 발판 지형에서 옆 · 뒤 명령을 학습하지 않는다(14 문서 · 00 개요 합의 4). 그런데 손 조종은 아무 명령이나 보낼 수 있다. 명령 정리기가 보행층 앞에서 막는다.

| 조건 | 처리 | 등급 |
|---|---|---|
| 몸 주변이 듬성한 지형 등급이고 \|vy\| > 0.3 또는 vx < 0 | vy 를 ±0.3 으로, vx 를 0 이상으로 자름 · 앱에 경고 | **가정** (14 문서 깃발 방식 옆 보정 ±0.3 과 맞춤) |
| 그 밖 | 그대로 통과 | |

- 지형 등급은 실기에서 SLAM 지도 · depth 로 추정해야 한다. 추정이 불확실하면 「듬성한 지형」 쪽으로 본다(보수적) → **가정**.
- Laya 를 정리기로 쓰는 것은 2 차 이후. 정리기는 50 Hz 경로 위라 원격 API(Jev)는 넣지 않는다(지연 예산 6 절).

## 6. 지연 예산 · 실패 안전

| 경로 | 주기 | 허용 지연 | 넣을 수 있는 것 |
|---|---|---|---|
| 보행층 | 50 Hz | 20 ms | 명령 정리기(규칙) |
| 주행층 | 10 Hz | 100 ms | HiPAN · 깃발 추종기 |
| 판단층 | 2 Hz 이하 | 500 ms 이상도 허용 | Laya · Jev |

실패 안전: 판단층이 응답하지 않거나 오류를 내면 「계속」 으로 본다(판단층은 안전 장치가 아니다). 안전 정지는 앱 STOP · 끊김 감시 · 제조사 정지 세 겹이 맡는다(23 문서 4 절). Jev 원격 호출은 행사장 네트워크에 의존하므로 무대 시연에서 판단층이 꺼져도 시연이 성립해야 한다.

## 7. 구현 방법

1. 상황 요약기: ROS 노드가 2 Hz 로 3 절 입력을 JSON 텍스트로 만든다. 같은 JSON 을 규칙 · Laya · Jev 에 동시에 준다.
2. 기록: 입력 JSON · 각 판단 · 응답 시간 · 이후 10 초의 결과(낙상 · 정체)를 한 줄씩 jsonl.
3. Jev 이미지: 전방 프레임을 640 폭으로 줄여 assets 로 붙임. 키 · 토큰은 환경 변수로만, 저장소 · 기록에 쓰지 않는다.
4. 비용 · 호출 수 상한을 설정값으로 둔다(유료 원격 호출은 팀장 확인 뒤 켬).
5. 시뮬에서 먼저: 22 문서 방에서 주행 rollout 기록을 재생해 오프라인으로 판단을 모은다(실시간 호출 없이).

## 8. 검증할 가설

| # | 가설 | 어떻게 보나 |
|---|---|---|
| H31-1 | 모델 판단이 규칙보다 사후 라벨(낙상 · 정체) 예측 정밀도가 높다 | 오프라인 재생 기록 |
| H31-2 | Jev Box 가 듬성한 지형 · 틈 위치를 사람이 쓸 만큼 맞힌다 | 프레임 표본 수동 라벨 대비 IoU · 적중률 |

## 9. 열린 항목

- Jev 유료 호출 예산 · 사용 승인(팀장).
- Laya 의 실제 입력 · 출력 형식과 로컬 실행 장비(Jetson 인가, 별도 PC 인가).
- 지형 등급 실시간 추정 방법(SLAM 지도 등급화 · depth 기반).
- 앱 「운영자 확인 카드」 와의 연결 방식(현민 협의).
