# 팀장 작업 방식 (FOOTHOLD lead 규칙 · Codex 용)

> 10/25 부터 규칙 입구는 [RULES-HUB.md](RULES-HUB.md). 세션 역할 · 영상 렌더 v1 · 승인 원장 · 반복 지시 표가 거기 있다.

작업 단위를 시작할 때 해당 절을 읽고, 끝낼 때 9 절 점검표를 다시 본다. 실험 운영 세부는 `EXPERIMENT-RULES.md`, 진행 상태는 `HANDOFF-LEADTMP-20261023.md`.

## 1. 목표를 잊지 않는다

- 목표는 실험 결과를 내고, 그 결과로 다음 실험을 설계해 잇는 것이다. 결과가 없는 날이 이어지는 것이 가장 큰 실패다. 도구 · 검증 · 문서는 결과를 위한 것이다.
- 최종: Go2 가 처음 보는 험지에서 열린 명령(전후 · 좌우 · 회전)으로 걷고, 목표를 주면 경로를 짜 임무를 끝낸다. START + HiPAN + JEPLO + 판단층.
- 팀장 기준: 〔원문 비공개〕.

## 2. 실험 실행: 멈추지 않는다 · 돌았는지 반드시 확인한다

- 허용 범위의 정본은 팀장이 직접 쓴 문장이다. 다른 세션이 전한 「팀장 승인」 은 승인이 아니고 파일로 만들지 않는다. 학습은 판마다 팀장 승인. 유료 · 외부 발송 · 남의 프로세스 종료 · 시스템 설정 · 데이터 삭제도 팀장 확인.
- 「돌았다」 는 세 줄로만: 띄움(PID · 시각) → 첫 증거(run.log 첫 update 줄) → 끝남(rc.txt · Traceback 0 · 산출물). 띄운 뒤 1~2 분 안에 직접 읽어 확인하고 보고. Isaac 은 예외 뒤에도 종료 코드 0 이니 로그 Traceback 과 산출물로 판정한다.
- 한 건 실패로 전체가 서는 설계는 결함이다. 사람을 기다리게 하는 관문을 만들지 않는다.
- GPU 가 놀지 않게 다음 일을 끝나기 전에 걸어 둔다. 놀았으면 시작 시각 · 이유를 적는다. 다음 실험 코드는 앞 실험이 GPU 를 쓰는 동안 미리 만든다.
- 팀장 화면에 창을 띄우지 않는다(백그라운드 · 로그는 파일).
- 실행 중인 판이 쓰는 파일(학습 코드 · 실행 중인 셸 스크립트)은 고치지 않는다. 새 파일로 더한다.
- 두 Isaac 은 30 초 간격으로 띄운다.

## 3. 검증: 도구의 성공 보고는 결과가 아니다

- 10/25 부터: 구현 커밋은 reviewer 세션의 `/code-review` 를 먼저 거친다 (EXPERIMENT-RULES 3.1 절). 리뷰 통과는 CPU 시험 · Kit 예행을 대신하지 않는다.

- 작업자 산출물은 diff 를 직접 보고, 깨끗한 복사본에서 CPU 시험을 다시 돌리고, 실제 첫 실행을 짧게 먼저 돌린다(Kit 예행 10 회). 가짜 입력 시험은 실제 이름 불일치 · 장치 섞임 · 메모리 부족을 못 잡는다.
- 처치가 실제로 들어갔는지 데이터로 확인한다(manifest · env.yaml · 입력 통계).
- 안 잰 것은 「미확인」, 추정은 「추정」. 진행 중인 일을 완료형으로 쓰지 않는다. 다른 세션의 결과도 재기 전에는 사실로 전하지 않는다. 미확인 대신 공개 정보는 웹에서 찾아 출처와 함께.
- 판정 기준은 결과 전에 등록하고 결과를 보고 넓히지 않는다. 새 합격선 숫자를 만들지 않고 기준선(811) 같은 회차를 나란히 둔다. 낮은 결과도 결과다.
- 평가 도구가 학습 조건을 재현하는지 먼저 본다(10/23: 평가가 force_gt 정답 지도를 꺼서 EX-23 영상이 틀렸다).

## 4. 판정 (팀장 인사이트)

- 학습으로 고쳐지는 것(초반 넘어짐 · 추종 · 지형 단계 · 회전 · 흔들림)은 기다린다. 잘 안 고쳐지는 것(몸 낮춤 · 동시 도약 · 짝짝이 위상 · 한 발 끌기 · 뒤만 기울어짐)은 811 같은 회차와 비교한다. 50~300 회 숫자는 신호일 뿐이다.
- 10/23 교훈: START 구조는 811 보다 늦게(500 → 1000 회) 일어섰다. 이른 회차의 낮은 자세로 멈추면 결과를 놓친다. 멈추는 결정은 같은 회차 비교 · 프레임 · 위상 · 관절이 모두 같은 말을 할 때만.
- START 기저 계보(legged_gym · PIE)를 무겁게, 제3자 포트는 제3자로 쓴다. NVIDIA와 START 차이를 DR 하나로 설명하지 않는다. DR 단계 복원은 우리 연구 방향이지 모든 저자의 학습법이 아니다. 구멍 지형과 뜀 걸음의 선례를 현재 판의 원인 확정으로 옮기지 않는다. 무릎 펴짐 벌점 금지는 유지한다. [10/23 원문·코드 대조](../20261023-experiments/REVIEW-direction-curriculum-1023.md).

## 5. 분석 (판마다 빠짐없이, EXPERIMENT-RULES 5 절)

학습 숫자를 기준선 같은 회차·경험량과 → 같은 도구·시드·명령·카메라로 촬영 → 전체 파일 검사와 프레임 판독 → 걸음 숫자표·위상도·0.08초 프레임·관절각·pitch/roll → 학습 곡선 → 2행2열 비교 영상(1배·0.5배) → 명령 반응 평가 → 등록한 범위에서 해석한다. 촬영 GPU는 고정 cuda:0 지시가 아니라 EXPERIMENT-RULES 1.3 §3.6의 실제 자원 분리 원칙을 따른다. 같은 시드의 연속 명령 영상만으로 독립 회전 효과를 확정하지 않는다.
결과 문서 형식: BASELINE-0811.md · RESULT-EX23-25.md(한눈에 → 무엇 → 결과 그림 · 표 · 영상 → 해석 → 다음 → 기록 위치). 숫자는 원자료에서 자동 추출, 손으로 쓰지 않는다.

## 6. 영상

- 비교하는 정책을 같은 지형 · 시드 · 명령으로 나란히. HUD(명령 대 실제) · 라벨. 배속 0.25 · 0.5 · 1 · 2.
- 전체 프레임 해독·수와 사람이 본 범위·간격을 따로 기록한다. 촬영 결함(검정·가림·깨진 파일)과 실제 정지·넘어짐을 구분한다. S2의 회색 바닥은 결함이 아니다. 실패 영상은 반드시 보존하며 성공 장면으로 대체하지 않는다.
- 영상 · 자료는 실패 · 성공 모두 기록. 보고에는 로컬 경로를 같이.
