## 6. 장착과 지도의 판정

START 본문은 Lite3의 카메라 지상 높이, base 기준 정확한 장착 xyz, 35° pitch를 제공하지 않는다(`P:384`). 설계도 이들을 가정으로 표시했다(`11-SENSORS.md:38`~`40`). 따라서 그것을 START에서 Go2로 그대로 옮겨 검증된 값이라고 바꾸어 부르면 안 된다.

저장소 안에는 실제로 다른 값이 있다. L의 D435 링크 원점은 `(0.29, 0, 0.03)`, G는 `(0.34, 0, 0.06)`, 둘 다 rpy `(0, −1.0472, 0)`다(`L:63`, `G:74`). **이 −60° 링크 회전은 광학축 정의를 확인하지 않고 아래로 60°라고 해석할 수 없다.**

MGDP Warp 카메라의 실행 경로는 `random_dog.py:153`~`158`에서 `utils/sensor_config.py`의 Camera를 사용한다. 그 Offset은 `(0.34, 0, 0.07)`, rotation `[0, 30, 0]`이며(`sensor_config.py:19`~`23`), pattern은 120×120 · 수평 FOV 67° · min 0.1 · max 3(`:92`~`100`), process는 resize 16×16 · clip 0.1~2.5(`:53`~`57`)다. 이것도 START 장착 사양이 아니다. URDF의 카메라 링크만 보고 실제 렌더 설정을 추정할 수 없다는 직접 증거다.

계산은 평평한 바닥, base roll·pitch 0, 카메라 x = 0.25, 아래 pitch 35°, 수직 FOV 58°, 지상 카메라 높이를 h로 두었다. 지면 교점은 `x = 0.25 + h/tan(광선의 하향각)`이다.

| 조건 | 아래 가장자리 64° | 광축 35° | 위 가장자리 6° |
|---|---:|---:|---:|
| h = 0.45, 11 §7의 가정 | x = 0.469480 | x = 0.892667 | x = 4.531464 |
| h = 0.52, base를 cfg 스폰 0.4에 놓고 +0.12 | x = 0.503621 | x = 0.992637 | x = 5.197470 |

이는 **깊이 절단 전**의 무한 평면 교점이다. 11의 `distance_to_image_plane`와 far 3.0을 적용하면 h = 0.45의 먼 유효 지면 한계는 중앙 단면에서 `x = 0.25 + (3 − 0.45 sin35°)/cos35° = 3.597230 m`다. `4.53 m까지 유효 깊이가 나온다`고 쓰면 틀린다. 앞 1.1 m 지도는 이 절단에 걸리지 않는다.

| 대상 | 판정 | 계산으로 확인된 것과 확인되지 않은 것 |
|---|---|---|
| 장착 xyz `(0.25, 0, 0.12)` · 지상 높이 | **판단 불가: START의 대응 장착값과 실기 브래킷 실측 없음** | 공식 Go2 기하와 cfg 각도의 각 발 바닥 접촉 계산에서는 base 약 0.314~0.324, 카메라 약 0.434~0.444 m다. 이는 정적 평형 실측이 아니다. 0.45 m는 계산용 가정으로 둘 수 있으나 0.4 m 스폰에서 자동으로 얻어지지 않음 |

| 14의 처음 보는 뒤 · 옆 땅에서 명령 개방 | **판단 불가: 지도 범위만으로 관측 확보 불가** | h=.45에서 최초 지면 가시는 x≈.4695부터다. 기본 앞발 x≈.1763도 즉시 보이지 않는다. 뒤 지도와 발밑은 시간 기억에 의존한다. Go2/Lite3 치수 환산으로 이 사각이 해소되지 않음 |

따라서 11의 시험은 h=.45를 만들도록 base z=.33을 명시하거나, 실제 시험에 놓은 base 높이를 식에 넣어 기대 교점을 바꿔야 한다. 17의 스폰 z=.4를 바꾸라는 요구는 아니다. 14의 뒤 · 옆 명령은 기존 제한과 관문을 유지하고, 후방 지도 MAE나 발 위치 포함 여부를 새로운 땅의 가시성 증거로 쓰지 않는다.

## 8. 확인 범위와 재현 기준

- URDF XML을 읽어 모든 inertial mass를 합산하고, 실제 관절 origin · axis · limit를 추출했다. 질량 합은 위 표의 구성 항목 덧셈과 대조했다.
- COLLADA의 POSITION 배열, visual_scene 노드 변환, up_axis와 visual 원점을 적용했다. 회전 연산은 +x축 90°가 `(0,1,0)`을 `(0,0,1)`로 보내는 알려진 입력으로 먼저 확인했다.
- FK는 XML 관절 체인을 행렬로 곱하고 발 구 중심 오프셋까지 적용했다. 별도 단순 삼각식과 Lite3 hip=0 결과가 일치했다. 평형 높이 또는 보행 중 높이는 측정하지 않았다.
- USD는 임시 폴더의 `usd-core 26.8`로 binary layer와 참조 메시를 열어 mass · joint · collision 속성을 읽었다. Isaac Sim 또는 학습을 실행하지 않았다. Kit에서의 최종 설정 덮어쓰기, 실제 loaded mass, 접촉 동역학은 미확인이다.
