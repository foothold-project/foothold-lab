## 2. 팀장 인사이트 (기저로 삼을 것)

1. 정상 설계라도 학습 초반 숫자는 신호일 뿐이다. 학습으로 고쳐지는 것(초반 넘어짐 · 추종 · 지형 단계 · 회전 · 흔들림)은 기다린다. 잘 안 고쳐지는 것(몸 낮춤 · 네 발 동시 도약 · 짝짝이 위상 · 한 발 끌기 · 뒤만 기울어짐)은 기준선 같은 회차와 비교해 판단한다.
2. 걸음 위상이 처음부터 틀리면 더 학습해도 안 고쳐진다(단, 아래 6 절: 우리 판은 500 회 이후에도 바뀌었다).
3. 올바른 보행의 보상 근본은 논문마다 비슷하다(「고양이 · 사자 · 치타」).
4. START 의 기저 계보(legged_gym [41] · PIE [31])를 무겁게 본다. 제3자 포트는 제3자로.
5. NVIDIA 설정은 시뮬 보행용, START 는 실기 이전(distillation)용이라 DR 이 필수지만 처음부터 최대로 넣지 않았을 것 → 커리큘럼(쉬운 것부터).
6. 몸을 낮추는 것은 불안정에서 오는 생존 전략(무게중심 낮추기).
7. 무릎 펴짐에 벌점을 주지 않는다(관절 한계 벌점 안 씀).
8. NVIDIA 보상은 참고 · 진단용. NVIDIA 보상으로 trot 가 나오면 NVIDIA 기저를 따른 것이지 START 가 아니다.
9. 석헌 실험: 메뚜기 같은 뜀 걸음은 gap · stepping_stones(구멍) 지형을 빼서 고쳤다.
10. 실험은 본류와 지류를 구분해 사슬로 잇는다. GPU 는 실험을 위해. 설계는 학습 전에 고정. 다른 시드 확인은 끝에 한 번.
11. 해석이 가장 중요: 숫자 · 근거 · 이전 데이터 · 그래프 · 영상 · 프레임을 같이 본다.
12. 영상은 바로 공유한다(검사 통과 뒤).
- Top-Down 합의: START 구조(TR-Net · 깊이)를 먼저 세우고 약점을 코칭한다.

## 12. 팀장 요구 사항 (빠짐없이, 원문 중심)

1. 설계는 학습 전에 고정하고 중간에 바꾸지 않는다. 다른 시드 확인은 끝에 한 번.
2. 실험은 사슬로 잇는다: 가설 → 설정 · 코드 → 검증 → 평가 → 다음 가설. 본류와 지류 구분. GPU 는 실험을 위해.
3. 중간 점검(300 · 500 · 1000)은 「이 판을 계속할 가치가 있나」 를 일찍 가리는 것이다. 그래서 학습 중에도 바로 영상 · 위상 · 그래프를 끝난 판 분석과 똑같이 본다(촬영은 cuda:0). 미루면 의미가 없다(팀장 10/22).
4. 분석은 숫자 · 근거 · 이전 데이터 · 그래프 · 영상 · 프레임을 같이(「데이터를 바라보고 분석하는 능력이 진짜 필요한 시점」). 보행 판단은 위상을 영상으로 제대로 본다.
5. 영상은 실패 · 성공 모두, 바로 공유. 의미를 담은 장면 · 검정 · 카메라 흔들림 · 가림 없음 · HUD · 나란히 비교 · 배속 0.25 · 0.5 · 1 · 2. 로컬 경로를 함께.
6. 결과는 문서 한 장(RESULT 형식, 팀장 승인 「앞으로도 이런식으로 정리해라」)을 git 에, 링크를 텔레그램으로. 채팅으로만 흘려보내지 않는다. 기준선 같은 측정은 꼭 문서화.
7. 실험 기록 스킬(가설 → 설정 → 검증 → 평가 → 다음)을 만들 것: 아직 없음 → `LEAD-STYLE-AGENTS.md` 5 절 + RESULT 형식으로 대신, 정식 절차서(ANALYSIS-PROCEDURE.md)는 미작성.

9. 지시는 구체적으로, 팀장 의도를 반영해서. 근거는 실제 경로 · 행 번호, 숫자마다 등급(논문 · 선행 · 코드 · 실측 · 가정).
