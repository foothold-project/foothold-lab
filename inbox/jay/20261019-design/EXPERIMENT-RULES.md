# 실험 운영 철칙

## 1. 목표와 기저

- 목표는 실험 결과를 내고, 그 결과로 다음 실험을 잇는 것이다. 실험은 서로 이어져야 의미가 있다(본류와 지류를 구분, 지류를 본류로 착각하지 않음).
- 기저 계보를 무겁게 본다: START 는 legged_gym [41] · PIE [31] 를 따른다. 다른 코드는 보조다. 기저를 따르되 공개되지 않은 설정을 복원했다고 과장하지 않는다. 제3자 포트는 제3자로 쓴다.
- 정상 보행을 위한 보상의 근본은 어느 논문이든 비슷하다. 시뮬 전용 설정(NVIDIA)과 실기 이전 설정(START)의 차이는 DR 이고, DR 은 쉬운 것부터 단계적으로(커리큘럼) 넣는다.
- GPU 는 실험을 위해 쓴다. 채우려고 쓰지 않는다. 그러나 다음 일을 미리 걸어 두어 놀리지 않는다.

## 2. 설계

- 한 판은 한 가지 질문. 비교는 한 묶음만 다르게. 묶음이 둘 이상 바뀌면 그 사실을 카드에 적는다(예: 명령기를 바꾸면 지형 승급 규칙도 바뀜).
- **판정 기준은 결과 전에 등록**하고 결과를 보고 넓히지 않는다. 새 합격선 숫자를 만들지 않는다. 대신 **기준선과 같은 회차**를 나란히 놓는다.
- **기준선**(우리 데이터): 처음부터 학습 = 8/11 판(unitree_go2_rough/2026-08-11_20-32-58). 몸 높이(발 기준) 100 · 300 회 0.19 m → 500 회 0.32 → 1000 회 0.40 · 대각 0.97. 최종 성능 = NVIDIA 배포판 0.38 · 대각 0.98 / v1 0.39 · 0.89 / v2 0.38 · 0.87. resume 판(v1 · v2)을 처음부터 학습 판의 속도 기준으로 쓰지 않는다.
- 설계는 학습 전에 고정하고 중간에 바꾸지 않는다. 다른 시드 검증은 전체 과정이 끝난 뒤 한 번.

## 3. 실행 전 확인 (코드 무결성)

1. 바뀐 코드를 직접 읽는다(diff).
2. 깨끗한 복사본(`git archive <sha> foothold_s2 | tar -x`)에서 CPU 시험, CUDA 숨김.
3. **Kit 예행 10 회**. CPU 시험이 못 잡는 결함(장치 섞임 · 실제 속성 이름 · 메모리 부족)이 여기서 잡힌다.
4. 처치가 실제로 들어갔는지 데이터로 확인(예: 지도 입력 통계, 입력 차원, manifest 차이가 처치 묶음뿐).
5. 두 Isaac 은 30 초 간격으로 띄우고, 실행 중인 판이 소비하는 파일은 고치지 않는다.

## 4. 판정

- **학습으로 좋아지는 것은 기다린다**: 초반 넘어짐 · 추종 속도 · 지형 단계 · 회전 · 흔들림.
- **학습으로 잘 안 고쳐지는 것은 기준선과 같은 회차에서 비교해 멈춘다**: 몸 낮춤 · 네 발 동시 도약 · 짝짝이 위상 · 한 발 끌기 · 뒤만 기울어짐. 처음부터 학습은 300 회까지 몸이 낮은 것이 정상이므로 **500 회(몸 상승 · 전진)와 1000 회(trot)** 가 판정 시점이다. 300 회 이하에서는 초반 붕괴(뒤집힘 종료 80 % 이상 지속)만 본다.
- 50 회 숫자는 신호일 뿐 중단 근거가 아니다.
- 틀린 길로 확인되면 기다리지 말고 멈추고 다음 판을 준비한 뒤 보고한다. 새 계열은 팀장 확인.

## 5. 분석 (판마다 이 순서, 빠짐없이)

1. 학습 숫자(episode 길이 · track_lin/ang · 종료 비율 · 지형 단계)를 기준선 같은 회차와.
2. 같은 도구 · 같은 시드 · 같은 명령 열(전진 0.5 → 1.0 → 회전 +1.2 → -1.2, 각 3 초) · 같은 카메라로 촬영. **공유 전 전 구간 검사(2 초 간격 접촉 시트를 직접 본다): 검은 화면 · 단색 · 카메라 앞 가림(파란 하늘 등) · 로봇이 화면 밖 · 멈춘 화면 · 넘어짐. 하나라도 있으면 다시 찍고, 통과 전에는 문서 · 팀장에게 올리지 않는다(10/22 811 1499 띠의 파란 가림을 주석만 달고 올린 실수).**
3. 걸음 숫자표: 몸 높이(발 기준) · 스윙 높이 · 네 발 · 두 발 접촉 · 대각 비율 · 이륙/s · vx · wz · 전진 거리.
4. 걸음 위상도(trot = 대각 짝 교대, pronk = 네 줄 동시, 끌기 = 한 줄 연속).
5. 0.08 초 간격 프레임을 **직접 본다**.
6. 관절각(hip · thigh · calf · 기본각 대비 · 한계 여유) · 몸 pitch/roll.
7. 학습 곡선 겹침.
8. 비교 영상(3×2, 1 배 · 0.5 배)을 팀장에게 바로 공유.
9. 끝난 판은 명령 반응 평가.
10. 해석은 등록한 판정 안에서. 숫자 · 위상 · 프레임 · 관절이 같은 말을 하는지 대조. 미측정은 미측정. 추측을 사실로 쓰지 않는다.

## 6. 기록 · 공유

- 결정은 같은 날 #555 → APPROVED · 설계 문서 · EXP-MAP · 카드 · SCHEDULE · AGENDA · DECISION-SYNC → `tools/exp_sync_check.py` rc 0.
- 결과는 문서 한 장(RESULT-*.md: 한눈에 → 무엇 → 결과(그림 · 표 · 영상) → 해석 → 다음 → 기록 위치)을 git 에 올리고 링크를 텔레그램으로. 중간 점검은 이상 때만.
