# 실험 운영 철칙

> 규칙 입구는 [RULES-HUB.md](RULES-HUB.md) (세션 역할 · 운영 · 영상 렌더 · 승인 원장). 10/25 추가: 모든 링크 접촉 기록 · 저장 경계에서만 멈춤 · 평가는 커리큘럼 끄고.

## 1. 목표와 기저

- 목표는 실험 결과를 내고, 그 결과로 다음 실험을 잇는 것이다. 실험은 서로 이어져야 의미가 있다(본류와 지류를 구분, 지류를 본류로 착각하지 않음).
- 기저 계보를 무겁게 본다: START 는 legged_gym [41] · PIE [31] 를 따른다. 다른 코드는 보조다. 기저를 따르되 공개되지 않은 설정을 복원했다고 과장하지 않는다. 제3자 포트는 제3자로 쓴다.
- NVIDIA 계열과 START 계열의 차이를 DR 하나로 환원하지 않는다. 보상·관측·명령·종료·지형·로봇·학습 구현의 차이를 함께 적는다. DR·지연 단계 복원은 우리 연구 방향이며 START의 미공개 DR 램프를 재현한 사실이 아니다. MARG·AME-2 공개 코드·JEPLO는 초기 DR 사례, TAGA는 단계 분리 사례다. [원문 대조](../20261023-experiments/REVIEW-direction-curriculum-1023.md).
- GPU 는 실험을 위해 쓴다. 채우려고 쓰지 않는다. 그러나 다음 일을 미리 걸어 두어 놀리지 않는다.

## 2. 설계

- 한 판은 한 가지 질문. 비교는 한 묶음만 다르게. 묶음이 둘 이상 바뀌면 그 사실을 카드에 적는다(예: 명령기를 바꾸면 지형 승급 규칙도 바뀜).
- **판정 기준은 결과 전에 등록**하고 결과를 보고 넓히지 않는다. 새 합격선 숫자를 만들지 않는다. 대신 **기준선과 같은 회차**를 나란히 놓는다.
- **기준선**(우리 데이터): 처음부터 학습 = 8/11 판(unitree_go2_rough/2026-08-11_20-32-58). 몸 높이(발 기준) 100 · 300 회 0.19 m → 500 회 0.32 → 1000 회 0.40 · 대각 0.97. 최종 성능 = NVIDIA 배포판 0.38 · 대각 0.98 / v1 0.39 · 0.89 / v2 0.38 · 0.87. resume 판(v1 · v2)을 처음부터 학습 판의 속도 기준으로 쓰지 않는다.
- 설계는 학습 전에 고정하고 중간에 바꾸지 않는다. 다른 시드 검증은 전체 과정이 끝난 뒤 한 번.
- 사전 고정한 커리큘럼의 상태 전이·범위 변화는 설계 실행이다. 결과를 본 뒤 새 범위·보상·명령을 넣는 것은 별도 분기로 기록한다. “학습 중 변경 금지”가 사전 설계한 커리큘럼까지 금지하는 뜻은 아니다.
- 매 카드에 본류 단계·이번 질문·부모 checkpoint SHA·변경 묶음·대조·추가 경험량·본류 복귀 조건을 적는다. 학습 조건 표는 손으로 쓰지 않고 실행 기록에서 생성기로 뽑는다(11 절 · RULES-HUB 10.3). 한 시드 탐색을 일반화 입증이라고 부르지 않는다. 회차만으로 수렴·다음 단계 합격을 주장하지 않는다. 익숙한 조건 유지와 새 조건 내성을 함께 측정한다.

## 3. 실행 전 확인 (코드 무결성)

1. 바뀐 코드를 직접 읽는다(diff).
2. 깨끗한 복사본(`git archive <sha> foothold_s2 | tar -x`)에서 CPU 시험, CUDA 숨김.
3. **Kit 예행 10 회**. CPU 시험이 못 잡는 결함(장치 섞임 · 실제 속성 이름 · 메모리 부족)이 여기서 잡힌다.
4. 처치가 실제로 들어갔는지 데이터로 확인(예: 지도 입력 통계, 입력 차원, manifest 차이가 처치 묶음뿐).
5. 두 Isaac 은 30 초 간격으로 띄우고, 실행 중인 판이 소비하는 파일은 고치지 않는다.
6. **촬영은 학습과 GPU를 분리하는 것을 기본으로 계획한다.** 10/22 같은 GPU에 겹쳐 학습 정체·48바이트 영상이 생긴 사례와, 다른 시점에는 느려졌다 회복한 사례가 모두 있다. 둘을 근거로 “안정된 학습이면 항상 안전”이라고 일반화하지 않는다. 촬영 시간을 미리 배정하고 checkpoint를 보존한다. 불가피한 동시 사용은 당시 메모리 여유·처리량 영향과 허용 범위를 확인하며, 남의 프로세스를 임의로 멈추지 않는다. 시작 뒤2분 안에 학습과 촬영 양쪽의 실제 진전을 확인한다.
7. 자동 점검이 찾는 로그 경로 패턴은 실제 폴더 이름으로 한 번 시험한다(10/22 `2026102223*` 패턴이 `20261022_2300` 폴더를 못 찾아 감시가 조용히 대기만 했다).
8. DR은 cfg 범위와 실제 물리값을 대조한다. startup·reset·interval 중 언제 적용되는지, 마찰 합성 방식, delay의 단위와 실제 적용 순서를 기록한다. 재개 때 optimizer·정규화·난수뿐 아니라 지형 행/원점·DR 단계·지도 소비 모드도 확인한다. 저장된 force_gt가 새 cfg를 덮는 경로는 의도한 전환과 단순 재개를 구분한다.

## 4. 판정

- **학습으로 좋아지는 것은 기다린다**: 초반 넘어짐 · 추종 속도 · 지형 단계 · 회전 · 흔들림.
- 몸 낮춤·네 발 동시 도약·짝짝이 위상·한 발 끌기·뒤 기울어짐은 중요한 관찰 대상이다. 다만 **500회 몸 상승·1000회 trot는811의 관찰 기준이며 모든 구조의 합격 시한이 아니다.** 같은 회차와 함께 환경 수·rollout 길이·추가 경험량·지형 노출·부모 학습 이력을 적는다. 옛 “300회 이하 뒤집힘80%”는 보편적으로 검증한 중단선이 아니므로 새 판에 자동 이식하지 않는다. 조기 붕괴는 원자료를 남겨 원인을 구분하고 사전 지정한 해당 판의 대응을 따른다.
- 50 회 숫자는 신호일 뿐 중단 근거가 아니다.
- 틀린 길로 확인되면 기다리지 말고 멈추고 다음 판을 준비한 뒤 보고한다. 새 계열은 팀장 확인.

## 5. 분석 (판마다 이 순서, 빠짐없이)

1. 학습 숫자(episode 길이 · track_lin/ang · 종료 비율 · 지형 단계)를 기준선 같은 회차와.
2. 같은 도구·시드·명령열(전진0.5→1.0→회전+1.2→−1.2, 각3초)·카메라로 촬영한다. 회전 인과 비교에는 같은 초기 상태에서 방향별 독립 reset 시험도 둬 앞 명령의 영향을 분리한다. **전체 파일 해독·프레임 수·지속시간 확인과 사람이 본 프레임은 별개로 기록한다.** 검은 화면·가림·깨진 파일 등 촬영 결함은 원본을 남기고 재촬영 여부를 적는다. 실제 넘어짐·정지·나쁜 자세는 실험 결과이므로 삭제하거나 성공 장면으로 대체하지 않는다. 회색 지형을 단색 결함으로 자동 판정하지 않는다.
3. 걸음 숫자표: 몸 높이(발 기준) · 스윙 높이 · 네 발 · 두 발 접촉 · 대각 비율 · 이륙/s · vx · wz · 전진 거리.
4. 걸음 위상도(trot = 대각 짝 교대, pronk = 네 줄 동시, 끌기 = 한 줄 연속).

6. 관절각(hip · thigh · calf · 기본각 대비 · 한계 여유) · 몸 pitch/roll.
7. 학습 곡선 겹침.
8. 비교 영상은 팀장 지시대로2행2열,1배·0.5배와 원본을 연결한다. 판 수가 다르면 배열 이유를 명시한다. 로컬 경로와 외부에서 볼 수 있는 검증된 주소를 함께 공유한다.

10. 해석은 등록한 판정 안에서. 숫자 · 위상 · 프레임 · 관절이 같은 말을 하는지 대조. 미측정은 미측정. 추측을 사실로 쓰지 않는다.
