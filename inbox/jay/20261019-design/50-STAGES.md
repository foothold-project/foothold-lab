# 50 · 실험 단계 지도

## 0. 쉬운 요약

실험은 다섯 단계다. **S0** 는 자(평가 도구)를 먼저 만들어 옛 모델 셋(NVIDIA · v2 · E1)을 같은 자로 잰다. **S1** 은 카메라 없이 「명령 세 칸을 전부 열어도 험지를 걷나」 를 배운다(11/7 의 몸통). **S3** 는 그 보행 위에 「목표까지 길 찾기」 를 올린다. **S2** 는 카메라로 발밑 지도를 그리는 눈을 단다(다른 GPU 에서 S3 와 동시에). **S4** 는 발밑 라이다를 더해 징검다리에서 옆 · 뒤 걸음을 연다. 단계마다 「무엇 하나를 바꾸나」 와 「몇 점을 넘어야 다음인가(관문)」 를 학습 전에 적고, 설정을 해시로 고정(동결)한다. 학습 중 버그를 고치면 새 판 번호를 붙인다. 번호 S2 · S3 는 층 순서(지각 → 주행)이고 실행 순서는 S1 → S3 → S2 다.

## 1. 순서와 병렬

```mermaid
flowchart LR
  S0[S0 기준선<br/>NVIDIA · v2 · E1 평가 정리<br/>축 3 · START 시험지 하네스] -->|관문 S0 10/23| S1a[S1-a 열린 명령 보행<br/>이어진 지형 + 계단 · scan / blind]

  S2 -->|F26 사전 관문| R[S3 student 재증류<br/>또는 teacher 재학습 · D34]
  S3 --> R
```

이름 S2 · S3 은 「층」 순서(지각 → 주행)를 따른 번호이고, 실행 순서는 S1 → S3 → S2 이다(fable 20e 판정 ①: 1 → 2 → 3 으로 가면 2 가 막힐 때 3 이 없다). **팀장 승인 10/19 23:2x(D34 · D36) · 10/20 00:5x(J-A · J-D)**: S1 을 S1-a(이어진 지형 전체 + 계단, 11/7) 와 S1-b(blind 판에 깃발 · 듬성한 지형, 11/14) 로 나누고, S3 teacher 를 11/10 날짜 관문에서 「S2 가 F26 사전 관문을 넘었으면 S2 하위, 아니면 **S1-blind** 하위(실기 가능)」 위에서 시작한다. 그 전 GPU 0 은 11/3~11/5 에 **S2-G0(S2 틀에서 눈만 끈 판)** 을 돌려 눈 효과의 한 변수 기준선을 실제로 만들고, 11/6~11/10 은 S3 코드 디버그(짧은 실행 · S2-G1 중간 체크포인트 내장 1 회)에 쓴다. S1-b 는 S2 의 입력이 아니고 생성기 · 지형 코드만 공유한다(VERIFY-lead-final 1). 이유는 VERIFY 20f P30: S1 하위 위에서 배운 S3 teacher 는 듬성한 패치를 우회하는 습관을 갖고, student 재증류만으로는 바뀌지 않는다. Go2 는 기본 10/26 주 · 최악 11/7 도착으로 가정한다(D38, 70 §1.1).

## 3. 규칙 (모든 단계 공통)

- 학습 전에 41 §9 의 판정 기준을 등록하고 해시를 남긴다. 결과를 보고 넓히지 않는다.
- 한 단계에서 바꾸는 것은 하나. 둘을 바꾸면 결과를 결합 효과로만 말한다(ASTRA 19f Q3). S4 처럼 둘이 불가피하면 대조 한 판을 먼저 둔다.
- 검증 사다리를 단계마다 밟는다: L0 답을 아는 입력으로 CPU 시험(negative control 포함) → L1 실제 Isaac Lab 짧은 실행(학습은 첫 10 update, 평가는 예행 8 판) → L2 첫 update 로그 확인 → L3 본 학습(무인 사슬 · heartbeat) → L4 평가. **가짜 cfg 시험만으로는 통과가 아니다. 실제 Kit 첫 실행이 관문이다**(10/16 · 10/18 교훈).
- 한 시드로 끝까지 간다. 다중 시드는 맨 마지막(90 D9).
- 실패도 결과다. 좋은 결과가 나올 때까지 다시 돌리지 않는다. 다시 돌리면 새 판 번호.
- 2 단계 학습 시작은 설계 동결 뒤 Linux 이전을 마친 시점에 팀장이 직접 승인한다(APPROVED H). 다른 세션의 승인은 승인이 아니다.
- 역할(D41): 구현 rl + lead(Sonnet 코딩 세션), 감시 Haiku 하위 작업, 검증 fable(관문마다 L0 · L1 · 판정), ASTRA 1 회, sol 스크립트만(18 §6).
- GPU 두 장 상태를 보고마다 한 줄 적고, 다음 GPU 일을 끝나기 전에 걸어 둔다(70).
