# 5. 정책 깊이 입력: 정렬 깊이 대 원본 깊이

## 무엇을 · 왜

- 무엇: 정책에 넣을 60×60 깊이를 D435i 의 어느 영상에서 만들지 정한다. 후보 둘:
  - 원본 깊이 `/camera/camera/depth/image_rect_raw` (깊이 이미저 기준)
  - 정렬 깊이 `/camera/camera/aligned_depth_to_color/image_raw` (색 카메라 기준으로 다시 투영한 것 · `view_start.sh` 가 켬)
- 왜: 정책은 시뮬 카메라 하나의 시야 · 기하로 학습했다. 실기 입력이 그 시야를 다 덮지 못하면 덮지 못한 칸은 늘 「미검출」 로 들어가 학습과 다른 입력이 된다.

## 세 카메라 나란히 (값은 설정 · 녹화에서 읽음, 시야각은 계산)

| 항목 | 시뮬 (학습 정본) | 실기 원본 깊이 | 실기 정렬 깊이 |
|---|---|---|---|
| 해상도 | 60×60 | 640×480 | 640×480 |
| fx · fy | 55.9 · 54.1 | 387.12 · 387.12 | 604.28 · 603.53 (색 카메라) |
| cx · cy | 30 · 30 | 319.64 · 242.06 | 326.51 · 249.52 |
| 가로 시야 | 56.4° | 79.2° | 55.8° |
| 세로 시야 | 58.0° | 63.6° | 43.4° |
| 원점 | 몸 기준 (0.25, 0, 0.12) · 아래 35° | 왼쪽 이미저 | 색 카메라 (원본에서 x 쪽 +14.8 mm) |
| 값의 뜻 | 광축 방향 거리 (`distance_to_image_plane`) | 광축 방향 거리 (mm · 0 = 없음) | 같음 |
| 갱신 | 10 Hz · 1 프레임 지연 · 최근 2 장 | 30 Hz | 30 Hz |
| 정규화 | (d − 0.2) / 2.8 → [0, 1] · 미검출 1.0 | 같은 식을 실기에서 적용해야 함 | 같음 |

시뮬 60×60 칸의 광선이 실기 영상 안에 들어오는 비율 (계산 · 렌즈 왜곡 0):

| 실기 영상 | 들어오는 행 | 들어오는 열 | 덮는 칸 |
|---|---|---|---|
| 원본 깊이 | 60 / 60 | 60 / 60 | 100 % |
| 정렬 깊이 | 43 / 60 | 59 / 60 | 70 % |

뜻 (계산 · 미확인): 정렬 깊이는 시뮬 시야의 위 · 아래 끝 약 6~8° 씩을 볼 수 없다. 특히 아래 끝은 발 바로 앞 바닥이라 정책에 중요할 수 있다. 원본 깊이에서 시뮬 내부 행렬로 다시 뽑으면 다 덮는다. 원본 깊이 왼쪽의 검은 띠 (스테레오가 못 보는 곳) 는 시뮬 시야로 자른 영역의 왼쪽 끝이 원본 x ≈ 112 px 이라 대부분 그 바깥이다 (계산 · 가까운 바닥에서는 띠가 넓어지므로 녹화로 확인).

## 명령

로봇은 앉은 채 (또는 2 번 · 3 번 녹화를 그대로 쓴다). 로봇 명령 없음.

| 순서 | 누가 | 할 것 | 명령 |
|---|---|---|---|
| 1 | AI 또는 사람 | 카메라 켜기 (정렬 켬) | Jetson `bash ~/go2_diag/viewer/view_start.sh` |
| 2 | AI 또는 사람 | 원본 · 정렬 깊이를 같이 30 초 녹화 (`full_record.sh` 는 정렬 깊이를 안 남긴다) | Jetson `source /opt/ros/humble/setup.bash; export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp; R=~/go2_diag/records/$(date +%Y%m%d-%H%M)-depth-input; mkdir -p $R; timeout -s INT 30 ros2 bag record -o $R/bag /camera/camera/depth/image_rect_raw /camera/camera/depth/camera_info /camera/camera/aligned_depth_to_color/image_raw /camera/camera/color/camera_info /camera/camera/extrinsics/depth_to_color` |
| 3 | AI 또는 사람 | 카메라 끄기 | Jetson `bash ~/go2_diag/viewer/view_stop.sh` |
| 4 | AI | 회수 뒤 ai-lx01 에서 두 영상을 각각 시뮬 내부 행렬 60×60 으로 다시 뽑아 비교 그림 · 수치 | `.venv-rosbags` 로 읽음 · 결과 `derived/` |

다시 뽑는 법 (4 번): 시뮬 칸 (u, v) 마다 광선 ((u + 0.5 − 30) / 55.9, (v + 0.5 − 30) / 54.1, 1) 을 실기 영상 내부 행렬로 투영해 가장 가까운 화소 값을 읽는다. 밖이면 미검출. 원본 깊이에서 뽑을 때는 원점이 색 카메라가 아니라 깊이 이미저인 것만 다르다. 장착 위치 · 각 차이 (A 대 B) 는 여기서 고치지 않는다 (2 번 비교표 · 팀장 결정).

## 합격 줄

| 항목 | 합격 |
|---|---|
| 계산 검증 | 녹화로 다시 뽑은 60×60 에서 정렬 깊이의 「영상 밖」 칸이 약 30 % (위 · 아래 띠) · 원본 깊이는 0 % |
| 원본 깊이 60×60 의 빈 칸 | 앉은 자세 · 선 자세 각각 빈 칸 (0 값) 비율을 적는다. 기준 수치는 팀장이 정한다 (11/18 전체 영상 무효 11.18 % 참고) |
| 두 입력 같은 장면 | 바닥 부분에서 두 60×60 의 깊이 차이 중앙값 2 cm 안 (원점 14.8 mm 차이 외에 다른 어긋남이 없는지) |

판정: 위가 맞으면 「원본 깊이를 시뮬 내부 행렬로 다시 뽑기」 를 권고안으로 올린다. 고르는 것은 팀장. 앱 `apps/agent` 의 깊이 전처리 구현은 `foothold-app` 에서 한다.
