## 3. 데이터가 오가는 길

```
로컬 ──(S3 올리기)──▶ 저장소 rzklpc35sl (EU-RO-1) ◀──(붙임 /network-volume)── Pod
로컬 ◀──(S3 받기)─── jay/<일>/<시각>/ : progress.log · 결과 · DONE
```

- 저장소는 하나 (rzklpc35sl · EU-RO-1). Pod 는 이 저장소가 있는 데이터센터에만 뜬다.
- ssh 는 쓰지 않는다 (R3 에서 sshd 가 안 떴고, 이미지 안에서 apt 가 권한으로 막혔다: R3b 진행 로그 읽기). Pod 의 시작 명령 하나가 일을 다 하고 진행 로그를 저장소에 쓴다.
- 로컬 → Pod: 하위 정책 저장본 (EX-42 끝 저장본) · 방 메시 · 우리 코드 묶음. 올릴 때 sha256 목록을 같이 올리고 Pod 안에서 대조한다. 다르면 일을 시작하지 않는다.
- Pod → 로컬: 저장본 (정해진 회차마다 저장소에 바로 씀) · 학습 로그 · 평가 json · 영상. 로컬에 받은 뒤 sha256 을 대조한다.
- 로컬 자리: HiPAN 은 `/home/jay/data/foothold/hipan/<일>/<시각>/` · 영상은 `/home/jay/data/foothold/s2_lab/ex42_record/...` (지금 쓰는 자리 그대로).
- 키: 로컬에서 읽기만 한다. Pod 의 환경 변수 · 시작 명령 · 로그에 넣지 않는다.

## 4. Pod 표준 (모든 스크립트가 지킬 것)

| 항목 | 표준 | 까닭 |
|---|---|---|
| 이름 | `jay-<일>-<시각>` | 팀원 Pod 와 섞이지 않게 |
| 지우기 | 스크립트가 자기가 만든 id 만 지운다. 이름으로 찾아 지우지 않는다 | 팀원 Pod 금지 |
| 진행 로그 | `progress.log` 에 줄마다 시각 · 단계 · 종료 코드 · 30 초마다 살아 있음 줄 | ssh 가 없어 이것이 유일한 눈 |
| 끝 표식 | 저장소에 `DONE` | 로컬이 이것을 보고 받고 지운다 |
| 상한 | 스크립트마다 시간 상한과 달러 상한을 상수로. 넘으면 받을 것 받고 지운다 | 잊힌 Pod 가 계속 돈을 쓴다 |
| 로그 없음 | 12~15 분 안에 진행 로그가 안 생기면 지운다 | 시작 명령이 안 돈 Pod |
| 판정 | 종료 코드가 아니라 산출물로 (Isaac 은 예외 뒤에도 0 을 낸다) | 반복된 실수 |
| 두 단계 | `--print` (돈 0) 로 요청과 시작 명령을 먼저 보이고, lead 가 `--start --lead-approved` | 유료 실행은 승인 뒤 |
| 긴 학습 | 저장본을 저장소에 주기적으로 쓰고, 같은 스크립트로 이어 받기 | Pod 가 죽어도 잃는 것이 한 주기 |
| 두 번째 지킴이 | 로컬 감시 프로세스 말고 하나 더: systemd 타이머가 20 분마다 `jay-*` Pod 목록을 보고 상한을 넘긴 것이 있으면 알린다 (lead 가 만든다 · 지우는 것은 lead) | 로컬 감시가 죽으면 Pod 가 25 시간 뒤에도 돈다 |
| Pod 안 시간 상한 | 시작 명령의 단계마다 `timeout` 을 걸고, 전체 상한을 넘으면 저장본을 쓰고 DONE 을 남긴 뒤 일을 끝낸다 | 로컬 기기가 통째로 죽으면 위 둘이 다 못 막는다. 적어도 Pod 가 일을 계속하지는 않게 한다 |

두 번째 지킴이는 지금 없다. 2 단계 (본 학습) 전에 있어야 한다. 주의: 시작 명령이 끝난 (컨테이너가 끝난) Pod 가 과금을 멈추는지는 미확인이다. 멈추지 않는다면 Pod 안 시간 상한은 일만 멈추고 돈은 못 멈춘다. 그래서 지우기 (DELETE) 는 여전히 로컬 몫이고, 1 단계에서 한 번 확인한다 (끝난 Pod 의 상태와 과금 표시를 대시보드에서 lead 가 봄).

### 5.1 환경 차이 확인 (G3 앞 · 1 단계 안)

- 무엇: 같은 하위 저장본 (정본 3 · E1F m250) 을 같은 명령 칸 (전진 0.1 · 전진 0.2 · 옆 +0.2 · 옆 -0.2 · yaw 0.5) · 6 초 · 32 env · 평균 행동으로, 로컬 2.3.2 (PhysX) 와 Runpod 3.0 (PhysX 지정) 에서 돌린다. 3.0 의 Newton 기본도 같은 판에서 한 줄 더 잰다 (참고 · 판정에 안 씀).
- 재는 것: 칸마다 실제 속도 평균 (yaw 는 실제 각속도) · 성공 수 /32 · 넘어짐 수.
- 통과 기준 (제안 · 결과 전에 고정): 우리 판 사이 흔들림이 실제 속도 약 0.005 m/s 다 (lead 값). **칸마다 두 환경의 실제 속도 차가 그 3 배 (0.015 m/s) 안 · 성공 수 차 3 대 안 · 넘어짐은 두 환경 모두 0** 이면 통과. yaw 칸은 0.05 rad/s 안.
- 실패 기준: 어느 칸이든 6 배 (0.03 m/s) 를 넘거나 넘어짐이 생기면 실패. 이때는 G3 을 띄우지 않고, 무엇이 다른지 (물리 설정 · 마찰 · 구동기 · 관측 순서) 를 먼저 가른다.
- 사이 (3~6 배): 기록하고 G3 은 진행하되, teacher 결과를 읽을 때 「하위가 로컬과 조금 다르다」 를 같이 적는다.
- 3 배로 잡은 까닭: 흔들림의 2 배까지는 같은 환경에서도 나온다. 느린 전진 0.1 에서 0.015 는 명령의 15 % 라 그보다 크면 걸음이 달라진 것이다. 3 배가 너무 빡빡한지는 첫 실행을 보면 안다 (기준은 그 전에 고정하고, 바꾸려면 lead 가 원장에 적는다).
