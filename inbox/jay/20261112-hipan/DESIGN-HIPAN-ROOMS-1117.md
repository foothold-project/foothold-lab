## 0. 쉬운 요약

길찾기를 배우려면 「목표 쪽으로 곧장 가면 막히는」 곳이 있어야 한다. 지금 방은 운동장에 짧은 담 몇 개를 세운 꼴이라, 목표를 향해 똑바로 걸으면 거의 늘 도착한다. 그러면 정책은 「목표 쪽으로 걷기」 만 배우고, 논문이 겨냥한 「막다른 길에서 되돌아 나오기 · 반쯤 막힌 방 빠져나오기」 는 배울 일이 없다. 방을 복도 · 문 · 막다른 칸이 있는 구조로 바꾸고, 그 구조가 충분히 구불거리는지를 숫자로 확인하고 쓴다.

**1.4 공통 꼴** (다섯 출처)

1. 벽은 격자 (타일 · 칸) 의 경계에 선다. 막다른 길은 격자의 이음 구조에서 나온다.
2. 막다른 길 · 반쯤 막힌 방은 「생기면 좋은 것」 이 아니라 학습의 목표로 이름이 적혀 있다 (HiPAN · REASAN · GUIDE).
3. 시작 · 목표는 길이 있는 쌍만 쓰고, 어려움은 직선 거리가 아니라 **경로 길이** 로 잰다.
4. 치수를 적은 논문은 없다. 숫자는 공개 코드의 기본값 (타일 2 m · 벽 0.4 m · 문 0.8 m) 뿐이다.

## 2. 지금 방은 무엇이 다른가 (잰 값)

`rooms-1117/rooms_check.py` · G3 영수증의 방 여섯을 다시 세워, 논문 그림 5 실측 격자와 같은 자로 쟀다. 자 = 0.1 m 격자 8 방향 최단 길이 / 직선 거리 (시작 20 곳 x 목표 · 직선 2 m 이상 · 방마다 약 870 쌍).

|---|---|---|---|---|---|
| 우리 방 여섯 | 95~96 % | 1.06 | 0 % | 0 % | 0~8 개 |
| 논문 Corridor | 75 % | 1.15~1.18 | 35~44 % | 5~9 % | |
| 논문 Room | 75~76 % | 1.13~1.18 | 37~45 % | 17 % | |
| 논문 Complex-1 | 57~62 % | 1.13~1.22 | 24~57 % | 2~19 % | |
| 논문 Complex-2 | 73~79 % | 1.13~1.16 | 30~40 % | 9~13 % | |

(논문 방의 범위는 머리 위 장애물을 통과로 볼 때와 막힌 것으로 볼 때 두 값.)

- 우리 방의 1.06 은 격자에서 정확한 대각선을 못 타서 생기는 바닥값이다. 돌아가야 하는 쌍이 없다.
- 그런데 우리 계획기 (보로노이 A\*) 가 낸 길은 직선의 1.28~1.45 배다. 벽이 없어도 보로노이 뼈대가 빈 공간 한가운데로 돌기 때문이다. PGCL 부목표가 쓸데없이 구불거리는 길 위에 놓였다는 뜻이다 (그림 `rooms-1117/rooms_top.png` 위 줄).
- 원인 (코드): `room_generator.py` 는 「막힌 타일」 을 뽑아 놓고 그 타일에 벽을 확률 0.2 로만 세운다 (탁자 0.1 · 상자 0.1). 막힌 타일 열에 여덟은 빈 평지다. 논문의 「막힌 면 타일」 은 타일 자체가 못 지나는 덩어리다 (그림 2 · 그림 5).
- PGCL (`pgcl.py` · `nav_task.py`): d 1 m · 수준마다 +1 m · 도달 0.1 m · 마지막 수준은 목표만. 논문 IV-C2 · 식 10 과 같다. G3 에서 꺼져 있지 않다 (`NavTask` 기본값으로 만들어짐). 다른 것 하나: 마지막 수준에서 「연속 5 회」 는 논문에 없는 우리 가정이다 (논문은 「꾸준히 성공하면」).

| 막다른 타일 | 방마다 3 개 이상 | 「막다른 길」 이 학습 목표로 적혀 있다 |
| 이어짐 | 자유 칸의 98 % 이상이 한 덩어리 · 시작점 64 개 전부 그 안 | G3 첫 Pod 사고 |
| 가장 좁은 통과 폭 | 0.8 m 이상 (문 1.0 m · 탁자 옆 등) | 하위 정책이 안 배운 좁은 틈을 만들지 않는다 |
| 계획기 길 / 격자 최단 | 중앙값 1.15 이하 | 부목표가 쓸데없이 돌지 않게 (지금 빈 방에서 1.2~1.4) |

하나라도 못 넘으면 방을 쓰지 않고 생성 값을 고친다. 통과한 100 방의 표와 예시 그림 여섯을 영수증으로 남긴다.

### 3.5 구현 관문 (논문이 주는 확인)

논문은 PGCL 을 끄면 Room 성공률이 98.4 → 76.9 로 떨어진다고 적었다 (표 III · PLAN-HIPAN-V2 §6 의 관문). 지금 방에서는 PGCL 을 꺼도 차이가 안 날 것이다 (돌아갈 일이 없으므로). 새 방에서 이 차이가 나는지가 「방이 맞게 만들어졌는가」 의 마지막 확인이다. G4 대조군을 미룬 결정은 그대로 두고, G3 짧은 학습에서 PGCL 켬 · 끔의 부목표 도달 곡선만 견준다 (제안).

## 6. 틀릴 수 있는 자리 · 미확인

- 논문은 치수를 적지 않았다. 타일 2 m · 벽 0.2 m · 문 1.0 m · 덩어리 20~25 % 는 그림과 공개 코드 기본값에서 미룬 제안이다.
- 논문 그림 2 의 밀도는 눈으로 읽었다 (재지 않음). 판정 줄은 치수를 잰 그림 5 (벤치마크) 에 맞췄고, 학습 방이 그보다 빽빽하다는 것은 내 읽기다.
- 1.2 · 1.3 절의 논문 넷은 조사 대행이 원문을 읽고 낸 것이다. 절 · 그림 번호는 그 보고 그대로이고 내가 다시 열어 대조하지 않았다. 팀장판 전에 인용 줄을 한 번 더 확인해야 한다.
- 원형 생성기의 표는 방 24 개씩이다 (막힌 타일 30 % · 15 % 두 줄 포함). 100 개 판정은 정본 코드가 나온 뒤에 한다.
- 벽이 늘면 하위 정책이 벽 옆에서 걷는 일이 는다. 하위 (정본 3) 는 벽 옆 보행을 따로 배우지 않았다. 통과 폭 0.8 m 줄은 이것을 줄이려는 것이고, 부딪힘이 느는지는 G3 에서 본다.
- 굴곡 비는 2 차원 격자의 값이다. 계단 · 거친 면에서 느려지는 것은 들어 있지 않다.
