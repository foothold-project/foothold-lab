- 고정: p_map_off 는 하한 값으로 고정. 명령 계약 그대로.
- 관문: **절대 조건을 상속**한다. 켬(eval_gt) fwd1.0 ≥ 5.097 m · 생존 ≥ 54/64, 가림 ≥ 4.592 · 2.310 m · 60/64, **그리고** 배포(eval_pred) fwd1.0 ≥ eval_gt × 0.9. 두 저장본 연속. 상대 조건만이면 GT 0.5 m · PRED 0.5 m · 가림 4.8 m 도 통과한다(analyst 13 반례). manifest 에 실제 정답 · 복원 · 끔 스텝 수 세 개를 따로 남긴다(이론상 (1−p_off)·p_gt, (1−p_off)·(1−p_gt), p_off 이지만 실제 시간 비율은 다르다).
- 되돌림: 위 조건 어느 하나 두 저장본 연속 미달이면 `force_gt=True` 로 되돌리고 기록(M-T5 로 실제 선택까지 확인). 되돌린 뒤 켬 · 가림 유지가 연속 두 저장본이면 **한 번만** 다시 `force_gt=False` 로 진입하고, 두 번째 실패면 멈추고 보고. 재진입의 p 시작값도 저장본 값(되돌림 동안 force_gt 가 1.0 으로 둠) 이라 같은 규칙이다. p_gt 를 손으로 정하지 않는다(시작값 1.0 은 저장본 값이지 선택이 아니다).
- (c) 진입의 코드 방식(reviewer 막음 1 → sonnet-code X26c, impl-mapratio 71c2c946, lead 13:2x 확정): `SBRunner` 의 sol23f force_gt 대조(`sol23f_runner.py:227~228`) 는 **`resume_adasmpl` 이 있을 때만 완화**되어 저장본 True → 설정 False 의 변경을 허용하고, 설정 `force_gt` 와 `resume_adasmpl.force_gt` 가 다른 모순(설정 True + 인자 False 따위) 은 기동 때 거절한다(`start_runner.py:139~140`). 저장본의 `sol23f.force_gt` 는 설정값이 아니라 AdaSmpl 의 실제 값을 적는다(`:202`). 그래서 (c) 설정은 **둘 다 False** 이고, 확인은 실제 `SBRunner` 로 첫 회차 `EX33_FIRST_SOURCES` 기록과 **다음 저장본 세 곳(저장본 `sol23f.force_gt` · yaml · manifest 의 `perception.force_gt`) 이 False** 인 것으로 한다(일반 `StartRunner` 시험은 이 대조를 지나지 않는다).
- 코드 제약 `[코드 · analyst 13 절 지적을 11:0x 직접 확인]`: `models/start_perception.py:233~238` 의 `AdaSmpl.state_dict` · `load_state_dict` 가 `force_gt` 를 저장본에 넣고 **그대로 되살린다**. resume 경로 `runners/start_runner.py:747` 이 이것을 부르므로, 설정에 `force_gt=False` 를 적어도 부모 저장본(B · S-B 는 True) 을 읽으면 **오류 없이 True 로 돌아간다**(`MODE_DEFAULTS` 거절 목록에도 없다). (c) 진입은 M-T5(7 절) 가 먼저다: 복원 뒤 runner 설정값으로 덮고 실제 `sample` 결과(정답 · 복원 env 수) 를 첫 회차 출력에 남긴다.
- 끝: (c) 관문 통과 저장본은 「고정 칸에서 복원 지도로 전진하고, 에피소드 전체 가림에서 G0-B 의 80 % 선을 넘는」 저장본이다. 에피소드 안 순간 끊김은 3.5 에서 시험하지 않으므로 「실기 후보」 「지도가 끊겨도 G0-B 수준」 이라고 적지 않는다(analyst 13, v0.1 표현 철회).

### 3.4 회전 명령 과정과의 순서

- 비율 축((b) · (c)) 과 명령 축(걷기 → 걸으며 돌기 → 제자리 회전) 을 같은 창에 두지 않는다.
- 권고(DESIGN-NEXT v0.3 §11.4 (ㄱ) 그대로): 명령 과정은 **GPU 다른 장의 진단 판**(B1500 또는 b1510 부모, 정답 지도) 에서 분포 · 성공선(JUDGE-SPEC 4.4) 을 검증하고, 본류에는 (c) 뒤 창 전환으로 그 분포만 넣는다(가중치는 안 넘김). 진단 판에는 JUDGE-SPEC 5 절 지형 표식 수정이 먼저 들어가야 한다.
- 두 GPU 가 모두 학습 중이면 학습 중 평가는 못 하므로(RULES-HUB 8.1 예외) 진단 판은 본류 평가 시간을 빼앗는다. 직렬 배정 또는 저장 경계 평가 자리를 시간표에 적는다(5 절).

### 3.5 안 하는 것

- 지도를 0 으로 채우기(평지로 오독) · 큰 잡음 지도(Miki 류 「틀린 지도」 는 별 축) · 에피소드 안 구간 가림(실기의 순간 끊김에 가깝지만 원인 분리를 위해 뒤로) · 다른 시드(전체 끝에 한 번) · 보상 변경 · 비율을 결과 보고 넓히기.

8. **결정됨(팀장 10/26 21:0x 원문 「모든 명령에서 보정 켬」, lead 21:0x 전달)**: 지형 커리큘럼 판정 proxy(JUDGE-SPEC v0.7 5.4 · J-T10) 를 **기본 켬**으로. 실제 받은 명령으로 「갔어야 할 거리」 를 계산하는 보정을 원운동 과제뿐 아니라 기존 START 명령 전부에 적용한다. 옛 판정은 `world_frame=False` 인자로 남기고, 두 판정을 계속 둘 다 계산해 갈린 에피소드 수를 기록한다. 켜는 시점은 통합 코드의 다음 기동(이어 가기 판 첫 기동) 이고, 돌고 있는 S-B10 · S-B50 학습은 바뀌지 않는다(출발 저장본 S-B10 m1500 은 옛 판정으로 학습된 것, manifest 에 기록). 표식(JUDGE-SPEC 5.2 의 3) 의 승급 · 강등 생략은 기록용으로 전환. 구현은 sonnet-code(기본값 켬 · 시험 · 변이 · reviewer).
