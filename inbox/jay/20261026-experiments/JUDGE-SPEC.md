## 2. 회전 통계량 (식)

### 2.1 정의

env e, 경우 c, 명령 부호 s_c = sign(cmd_wz_c):

- q_e = s_c × mean_t( wz[e, t] | alive[e, t] ). alive 표본이 하나도 없으면 NaN 이고 kept 도 거짓이므로 판정에 안 들어간다.
- **Q_c = mean_{e ∈ kept}( q_e )**. 이것이 「16 env 평균 요(rad/s)」 의 유일한 정의다. 양수가 명령 방향이다. 1.2 가 완전 추종.
- C_c = mean_{e ∈ kept}( mean_t( four[e, t] | alive[e, t] ) ), four = 네 발 접촉력 > 1 N 모두 참.
- 보조(기록 · 분포, 판정 입력은 아니지만 표에 같이 낸다): kept 수, q_e ≥ 0.6 인 env 수, q_e < 0.12 인 env 수, q_e < 0 인 env 수(반대 방향), min · max q_e, mean_t |wz| (절댓값 평균, 진동 크기용).
- 보존: 옛 pooled 값 mean( wz[alive] ) 은 `yaw_pooled_legacy` 라는 이름으로 같은 표에 남긴다(그림 · 옛 표와 대조용). 판정에는 쓰지 않는다.

### 2.2 금지

- **절댓값 금지.** mean |wz| 또는 |mean wz| 로 성공선을 넘기면 반대 방향으로 도는 판이 통과한다(analyst 12.2 둘째). 합성 반례: 우회전 명령 −1.2 에 16 env 가 모두 +1.2 로 돌면 절댓값 식은 1.2 로 통과, 부호 정렬 식은 **−1.2 로 실패**. 유지 하락도 부호 정렬 좌표에서 본다(−0.95 → −0.25 는 수직선에서는 증가지만 능력 하락이다).
- **pooled 평균 금지.** 일찍 넘어진 env 의 무게가 작아진다. 합성 반례: 요 1.0 으로 1600 표본 산 env 와 요 0 으로 100 표본 산 env 는 pooled **0.941176**, env 동일 가중 **0.5**(`judge_recompute.py` 끝 줄, 내가 돌림).
- **alive_end 분모 금지**(1.1).

## 4. 단계 넘김 관문

### 4.1 공통 규칙

- 저장본은 50 회마다. 판정은 **저장 경계**에서, 평가는 다른 GPU 또는 학습 끝 뒤 몰아서(RULES-HUB 8.1 예외). 판정 함수의 입력은 「최신 저장본 묶음 · 직전 저장본 묶음 · 기준 저장본 묶음 · 단계 시작 회차 · 누적 회차」 다.
- **연속 조건:** 통과 · 유지는 최신과 직전(50 회 전) 저장본이 **둘 다** 같은 조건을 만족할 때만. 직전 자료가 없으면(단계 첫 저장본 · 평가 누락) 「판정 보류(자료 부족)」 상태로 적고 넘기지 않는다.
- **단계 최소 체류는 단계별 입력**(`min_stay`): 명령 과정 단계 **500 회**(lead 권고), 지도 비율 단계 **250 회**(DESIGN-MAPRATIO 3.2 추정). 둘 다 팀장 판단 대기. 체류 안의 「새 과제 미달」 은 정상 경로다. 체류 뒤에도 미달이면 보고 · 팀장 판단(자동 연장 · 자동 폐기 없음). 고정 500 을 함수 안에 박지 않는다(analyst 13: 250 회 정상 입력이 `NEW_TASK_PENDING` 으로 떨어지는 모순).
- **한 번에 한 축.** 명령 비중 확대와 지도 비율 변경, 지도 비율 변경과 복원 지도 섞기를 같은 창에서 하지 않는다(EXPERIMENT-RULES 2 절 · analyst 12.4 · 12.5).
- 상태와 다음 동작을 **나눈다**(analyst 13). 판정 함수는 상태 하나와 그 근거 필드를 돌려주고, 연속 실패 수를 세어 동작(계속 · 보류 · 되돌림 · 멈춤) 을 정하는 것은 평가 사슬(소비자, M-T4 · J-T9) 이다. 의사 코드(이어 가기 판):

```
def judge(latest, prev, base, stage, it_in_stage, min_stay):
    if operational_stop(latest):                 # NaN · 기동 실패 · 64 env 회전 생존 < 48 · 전진 유지 미달 · 어느 경우 Q < 0.12 (이어 가기 판만)
        return STOP                              # 동작: 멈춤 · 저장본 보존 · 보고
    if prev is None or latest.missing or prev.missing:
        return HOLD_NO_DATA                      # 파일 · 직전 평가 자료가 «없을» 때만. 관측된 낙상은 여기 오지 않는다
    if not (maintained(latest, base) and maintained(prev, base)):
        return MAINTAIN_FAIL                     # 유지 조건 미달(하락 · 넘어짐 · 전진 유지 중 어느 것이든). 동작은 소비자가: 1 회 → 보류, 2 회 연속 → REVERT
    if it_in_stage < min_stay or not (new_task_ok(latest, stage) and new_task_ok(prev, stage)):
        return NEW_TASK_PENDING                  # 새 과제 미달: 같은 조건 계속. min_stay 넘고 두 창 연속이면 보고
    return PASS                                  # 동작: 한 축만 확대

def consume(history):                            # 평가 사슬(소비자). history = 최근 판정 상태 열
    if history[-1] == STOP: return "멈춤 · 보고"
    if history[-2:] == [MAINTAIN_FAIL, MAINTAIN_FAIL]: return "REVERT(직전 값으로) · 기록"   # 두 번째 REVERT 면 멈춤 · 보고
    if history[-1] == MAINTAIN_FAIL: return "보류(같은 조건 한 창 더)"
    if history[-1] == PASS: return "한 축 확대"
    return "계속"
```

- `maintained` = 3 절 유지 하락 허용 + 넘어짐 허용 + 전진 유지 **셋 모두**. `new_task_ok` = 그 단계의 성공선(4.4 · 4.5). 어느 경우 kept < 12 면 그 경우의 회전 통계는 「무효」(`turn_valid=False`, Q 를 평균에 넣지 않음) 이고 **생존 조건 미달(`survival_ok=False`) 은 `maintained` 거짓**이다. 즉 G0-B m1500 좌 → 우 kept 10 을 이어 가기 규칙으로 넣으면 `MAINTAIN_FAIL` 이지 `HOLD_NO_DATA` 가 아니다(v0.1 의 「HOLD_NO_DATA」 철회, 6.5 기대값과 맞춤). 64 env 생존 < 48 이면 STOP. 처음부터 판(4.3) 은 `maintained` 를 부르지 않고 「달성 미달 · 계속 관찰」 로 적는다.

### 4.2 이어 가는 판 (부모 있음)

- 기준 저장본 = 부모(예: B1500 또는 b1510) 를 **같은 코드 · 같은 식 · 같은 모드**로 잰 값. 옛 표 숫자를 그대로 쓰지 않는다(2.3).
- 운영 중단선 적용. 멈추면 저장본 보존 · 보고. 「회복 불가」 라고 적지 않는다.
- 유지 하락 두 창 연속 → 마지막 확대만 되돌림(DESIGN §5 「후퇴와 보존」).

## 5. 지형 커리큘럼: 원운동 강등 오판 수정 규칙

### 5.1 지금 코드 `[코드 · 내가 다시 읽음]`

- `rules.judge_free(max_dist, cmd_sum_xy)` (`rules.py:14~26`): norm = ‖cmd_sum_xy‖, active = norm > eps, 승급 = active & max_dist > size_x/2, 강등 = active & max_dist < 0.5 × norm × 4 s × 0.9 & ¬승급.
- `terrain_levels_mixed` (`terrain_levels_mixed.py:20~27`): cmd_sum = term.cmd_sum_xy × step_dt / 4 s 로 「재추출 한 번당 한 번 뽑힌 값의 합」 단위로 맞춘 뒤 judge 에 넘긴다. `cmd_sum_xy` 는 `_update_command` 에서 **매 스텝** 몸 기준 (vx, vy) 를 더한다(`mixed_command.py:202`). 제자리 회전(vx 0) 과 정지는 0 을 더하므로 spin 만 있는 에피소드는 active 가 거짓이라 판정에서 이미 빠진다(docstring 7 행).
- 반례(analyst 2.1, 내가 재현): vx 0.5 · wz 0.5 로 20 s 정확한 원(반지름 1 m) 은 max_dist 2 m, 명령 합 10 m → 강등. `judge_free([10, 2], [[2.5, 0], [2.5, 0]]) == [1, −1]`.
- Isaac 의 reset 순서(`manager_based_rl_env.py` `_reset_idx`, 내가 다시 열어 확인): `curriculum_manager.compute(env_ids)` 가 먼저, 그 뒤 이벤트 reset, 그 뒤 `command_manager.reset(env_ids)`. 그래서 curriculum 이 읽는 `max_dist` · `cmd_sum_xy` 는 **방금 끝난 에피소드** 값이고, command reset(`_reset_episode_state`) 이 그 뒤에 비운다(`terrain_levels_mixed.py:3` 머리말과 같음).

### 5.2 수정 규칙 (정확히)

1. **표식.** 명령 term 에 `had_new_task (N,) bool` 을 둔다. 새 과제 = 걸으며 돌기(vx > 0 & wz ≠ 0) · (뒤에 들어오면) 정지 → 재출발 · 뒤 · 옆. **기존 START spin(vx 0 · wz ≠ 0) 과 직진은 새 과제가 아니다.**
2. **켜는 때.** `_resample_command` 가 새 과제 모드를 뽑은 env 에서 참으로. 매 스텝 바뀌는 과제(S4 정지 → 재출발 프로파일, 깃발의 spin · backoff 류) 는 **그 모드가 실제로 소비된 스텝**에서 켠다(analyst 12.3 1: `mode/profile` 과 실제 소비를 연결). 마지막 명령만 보고 분류하지 않는다.
3. **읽는 때.** `terrain_levels_mixed` 안에서 `move = rules.judge(...)` 뒤에 `move[term.had_new_task[env_ids]] = 0`. 승급 · 강등 둘 다 막고 행을 유지한다(임시 행 유지. 성과 기반 지형 커리큘럼 완성이 아니다).
4. **비우는 때.** `_reset_episode_state(env_ids)` 에서 `had_new_task[env_ids] = False`. Isaac 순서상 curriculum 이 읽은 뒤다. env 부분 reset 은 그 env 만.
5. **범위.** 표식 있는 에피소드의 **자동 거리 승급 · 강등 생략**에 한정한다. 「그 cohort 는 외부 성과로만 행을 넓힌다」 는 이번에 구현하지 않는다(analyst 12.3 2). 다른 env · 다른 에피소드는 기존 규칙 그대로.
6. **기록.** update 마다 표식 참 에피소드 수 · 비율, 표식 유무별 승급 · 강등 · 유지 수, 지형 행별 표본 수를 `train_extra.jsonl` 에 남긴다. 「새 명령 경험이 섞인 에피소드 비율 23 %/56 %」 는 슬롯 독립 가정 계산이므로 실측으로 바꾼다.
7. **S1 에는 영향 0.** S1(걸으며 돌기 0 %) 에서는 표식이 늘 거짓이라 B 와 같은 흐름이다. 이것이 동등성 시험이다.

### 5.3 답 아는 입력 (CPU, Kit 없이)

부분 reset 시험은 **「비운 직후」** 와 **「새 과제를 재추출한 직후」** 를 나눈다. 전자는 표식이 거짓이어야 하고, 후자는 재추출된 명령이 다시 새 과제면 참일 수 있다(analyst 13). 설계 동의와 구현 통과는 별개이며, 1000 스텝 동등성 · Kit 시험은 구현 뒤 미확인이다.

| 입력 | 기대 |
|---|---|
| `judge_free([10, 2], [[2.5, 0], [2.5, 0]])`, 표식 [F, F] | [+1, −1] (지금과 같음) |
| 같은 입력, 표식 [F, T] | [+1, **0**] |
| spin 만 있는 에피소드(cmd_sum 0), 표식 F | 0 (지금과 같음) |
| 새 과제 → 직진 → reset 한 에피소드 | 표식 T → 0. 마지막 명령이 직진이어도 0 |
| env 부분 reset: env 3 만 reset | env 3 표식만 거짓, 다른 env 유지 |
| 창 전환 직후 잔여 명령이 옛 계약(S1 직진 · spin) | 표식 F |
| S1 설정 1000 스텝 | 표식 참 수 0, 승급 · 강등 결과가 수정 전 코드와 비트 단위로 같음 |
