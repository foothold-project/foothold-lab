## 2. 회전 통계량 (식)

### 2.1 정의

env e, 경우 c, 명령 부호 s_c = sign(cmd_wz_c):

- q_e = s_c × mean_t( wz[e, t] | alive[e, t] ). alive 표본이 하나도 없으면 NaN 이고 kept 도 거짓이므로 판정에 안 들어간다.
- **Q_c = mean_{e ∈ kept}( q_e )**. 이것이 「16 env 평균 요(rad/s)」 의 유일한 정의다. 양수가 명령 방향이다. 1.2 가 완전 추종.
- C_c = mean_{e ∈ kept}( mean_t( four[e, t] | alive[e, t] ) ), four = 네 발 접촉력 > 1 N 모두 참.
- 보조(기록 · 분포, 판정 입력은 아니지만 표에 같이 낸다): kept 수, q_e ≥ 0.6 인 env 수, q_e < 0.12 인 env 수, q_e < 0 인 env 수(반대 방향), min · max q_e, mean_t |wz| (절댓값 평균, 진동 크기용).
- 보존: 옛 pooled 값 mean( wz[alive] ) 은 `yaw_pooled_legacy` 라는 이름으로 같은 표에 남긴다(그림 · 옛 표와 대조용). 판정에는 쓰지 않는다.

### 2.2 금지

- **절댓값 금지.** mean |wz| 또는 |mean wz| 로 성공선을 넘기면 반대 방향으로 도는 판이 통과한다(analyst 12.2 둘째). 합성 반례: 우회전 명령 −1.2 에 16 env 가 모두 +1.2 로 돌면 절댓값 식은 1.2 로 통과, 부호 정렬 식은 **−1.2 로 실패**. 유지 하락도 부호 정렬 좌표에서 본다(−0.95 → −0.25 는 수직선에서는 증가지만 능력 하락이다).
- **pooled 평균 금지.** 일찍 넘어진 env 의 무게가 작아진다. 합성 반례: 요 1.0 으로 1600 표본 산 env 와 요 0 으로 100 표본 산 env 는 pooled **0.941176**, env 동일 가중 **0.5**(`judge_recompute.py` 끝 줄, 내가 돌림).
- **alive_end 분모 금지**(1.1).

## 4. 단계 넘김 관문

### 4.1 공통 규칙

- 저장본은 저장 간격마다(지금 사슬 100 회). 판정은 **저장 경계**에서, 평가는 다른 GPU 또는 학습 끝 뒤 몰아서(RULES-HUB 8.1 예외). 판정 함수의 입력은 「**그 저장본 하나**의 평가 묶음 · 기준 저장본 묶음 · 단계 시작 회차 · 누적 회차 · `min_stay`」 다. 직전 저장본은 판정 함수에 들어가지 않는다.
- **연속 조건은 소비자가 센다**(reviewer X26 고침 1): 넘김은 연속 두 저장본의 상태가 **둘 다 `PASS`** 일 때, 되돌림은 **둘 다 `MAINTAIN_FAIL`** 일 때만. v0.3 까지는 판정 함수가 「최신 또는 직전 미달 → `MAINTAIN_FAIL`」 을 내고 소비자가 그것을 두 번 세어, good · good · **bad** · good · good 열에서 최신이 good 인 세 번째 창이 REVERT 를 냈다(`repro_x26.py` 재현). 한 저장본의 미달은 한 번만 세어져야 한다. 직전 자료가 없으면(단계 첫 저장본) 소비자는 「연속 미완 · 계속」 이고, 사이에 `HOLD_NO_DATA`(평가 누락) 가 끼면 연속이 끊긴 것으로 보아 넘기지도 되돌리지도 않는다(보수적 · 기록).
- **단계 최소 체류는 단계별 입력**(`min_stay`): 명령 과정 단계 **500 회**(lead 권고), 지도 비율 단계 **250 회**(DESIGN-MAPRATIO 3.2 추정). 둘 다 팀장 판단 대기. 체류 안의 「새 과제 미달」 은 정상 경로다. 체류 뒤에도 미달이면 보고 · 팀장 판단(자동 연장 · 자동 폐기 없음). 고정 500 을 함수 안에 박지 않는다(analyst 13: 250 회 정상 입력이 `NEW_TASK_PENDING` 으로 떨어지는 모순).
- **한 번에 한 축.** 명령 비중 확대와 지도 비율 변경, 지도 비율 변경과 복원 지도 섞기를 같은 창에서 하지 않는다(EXPERIMENT-RULES 2 절 · analyst 12.4 · 12.5).
- 상태와 다음 동작을 **나눈다**(analyst 13). 판정 함수는 상태 하나와 그 근거 필드를 돌려주고, 연속 실패 수를 세어 동작(계속 · 보류 · 되돌림 · 멈춤) 을 정하는 것은 평가 사슬(소비자, M-T4 · J-T9) 이다. 의사 코드(이어 가기 판):

```
def judge(ckpt, base, stage, it_in_stage, min_stay):   # 저장본 «하나» 를 판정한다. 직전 저장본은 보지 않는다
    if operational_stop(ckpt):                   # NaN · 기동 실패 · 64 env 회전 생존 < 48 · 전진 유지 미달 · 어느 경우 Q < 0.12 (이어 가기 판만)
        return STOP                              # 동작: 멈춤 · 저장본 보존 · 보고
    if ckpt.missing:
        return HOLD_NO_DATA                      # 파일 · 평가 자료가 «없을» 때만. 관측된 낙상은 여기 오지 않는다
    if not maintained(ckpt, base):
        return MAINTAIN_FAIL                     # 이 저장본이 유지 조건 미달(하락 · 넘어짐 · 전진 유지 중 어느 것이든)
    if it_in_stage < min_stay or not new_task_ok(ckpt, stage):
        return NEW_TASK_PENDING                  # 이 저장본이 새 과제 미달 또는 체류 전
    return PASS                                  # 이 저장본은 통과. 넘김은 소비자가 연속 둘을 보고 정한다

def consume(history):                            # 평가 사슬(소비자). history = 저장본 순서대로의 판정 상태 열. 연속은 여기서만 센다
    if history[-1] == STOP: return "멈춤 · 보고"
    if history[-2:] == [MAINTAIN_FAIL, MAINTAIN_FAIL]: return "REVERT(직전 값으로) · 기록"   # 연속 두 저장본이 «각각» 미달일 때만. 두 번째 REVERT 면 멈춤 · 보고
    if history[-1] == MAINTAIN_FAIL: return "보류(같은 조건 한 저장본 더)"
    if history[-2:] == [PASS, PASS]: return "한 축 확대"                                 # 연속 두 저장본이 각각 통과
    if history[-1] == PASS: return "계속(연속 미완, 한 저장본 더)"
    return "계속"                                # NEW_TASK_PENDING · HOLD_NO_DATA(사이에 끼면 연속이 끊긴다)
```

- 답 아는 열(J-T9): good · good · bad · good · good → 상태 PASS · PASS · FAIL · PASS · PASS → 동작 「계속 · 확대 · 보류 · 계속(연속 미완) · 확대」, **REVERT 없음**. bad · bad → REVERT. FAIL · HOLD_NO_DATA · FAIL → 보류(연속 끊김). PASS · HOLD_NO_DATA · PASS → 계속(넘기지 않음).
- `maintained` = 3 절 유지 하락 허용 + 넘어짐 허용 + 전진 유지 **셋 모두**. `new_task_ok` = 그 단계의 성공선(4.4 · 4.5). 어느 경우 kept < 14 면 그 경우의 회전 통계는 「무효」(`turn_valid=False`, Q 를 평균에 넣지 않음) 이고 **생존 조건 미달(`survival_ok=False`) 은 `maintained` 거짓**이다. 즉 G0-B m1500 좌 → 우 kept 10 을 이어 가기 규칙으로 넣으면 `MAINTAIN_FAIL` 이지 `HOLD_NO_DATA` 가 아니다(v0.1 의 「HOLD_NO_DATA」 철회, 6.5 기대값과 맞춤). 64 env 생존 < 48 이면 STOP. 처음부터 판(4.3) 은 `maintained` 를 부르지 않고 「달성 미달 · 계속 관찰」 로 적는다.

### 4.2 이어 가는 판 (부모 있음)

- 기준 저장본 = 부모(예: B1500 또는 b1510) 를 **같은 코드 · 같은 식 · 같은 모드**로 잰 값. 옛 표 숫자를 그대로 쓰지 않는다(2.3).
- 운영 중단선 적용. 멈추면 저장본 보존 · 보고. 「회복 불가」 라고 적지 않는다.
- 유지 하락 두 창 연속 → 마지막 확대만 되돌림(DESIGN §5 「후퇴와 보존」).

### 5.2 수정 규칙 (정확히)

1. **표식.** 명령 term 에 `had_new_task (N,) bool` 을 둔다. 새 과제 = 걸으며 돌기(vx > 0 & wz ≠ 0) · (뒤에 들어오면) 정지 → 재출발 · 뒤 · 옆. **기존 START spin(vx 0 · wz ≠ 0) 과 직진은 새 과제가 아니다.**
2. **켜는 때.** `_resample_command` 가 새 과제 모드를 뽑은 env 에서 참으로. 매 스텝 바뀌는 과제(S4 정지 → 재출발 프로파일, 깃발의 spin · backoff 류) 는 **그 모드가 실제로 소비된 스텝**에서 켠다(analyst 12.3 1: `mode/profile` 과 실제 소비를 연결). 마지막 명령만 보고 분류하지 않는다.
3. **읽는 때.** `terrain_levels_mixed` 안에서 `move = rules.judge(...)` 뒤에 `move[term.had_new_task[env_ids]] = 0`. 승급 · 강등 둘 다 막고 행을 유지한다(임시 행 유지. 성과 기반 지형 커리큘럼 완성이 아니다). **결정 8 뒤(v0.7)**: 세계 좌표 proxy 가 기본 켬이라 표식 에피소드도 바르게 판정되므로 이 생략은 **기록용**이 된다(5.4 의 5). 즉 `move` 를 0 으로 덮지 않고, 표식 유무별 승급 · 강등 수만 6 의 기록으로 남긴다. 옛 동작(덮기) 은 `mask_new_task=True` 인자로 남긴다(기본 False).
4. **비우는 때.** `_reset_episode_state(env_ids)` 에서 `had_new_task[env_ids] = False`. Isaac 순서상 curriculum 이 읽은 뒤다. env 부분 reset 은 그 env 만.
5. **범위.** 표식 있는 에피소드의 **자동 거리 승급 · 강등 생략**에 한정한다. 「그 cohort 는 외부 성과로만 행을 넓힌다」 는 이번에 구현하지 않는다(analyst 12.3 2). 다른 env · 다른 에피소드는 기존 규칙 그대로.
6. **기록.** update 마다 표식 참 에피소드 수 · 비율, 표식 유무별 승급 · 강등 · 유지 수, 지형 행별 표본 수를 `train_extra.jsonl` 에 남긴다. 「새 명령 경험이 섞인 에피소드 비율 23 %/56 %」 는 슬롯 독립 가정 계산이므로 실측으로 바꾼다.
7. **S1 에는 영향 0.** S1(걸으며 돌기 0 %) 에서는 표식이 늘 거짓이라 B 와 같은 흐름이다. 이것이 동등성 시험이다. **결정 8 뒤(v0.7)**: 표식 경로의 동등성은 그대로이나, J-T10 이 기본 켬이라 S1 의 지형 판정 자체는 B 와 다른 것이 **정상**이다(B 와의 비트 동등성은 `world_frame=False` 인자 경로에서만 확인).

### 5.4 범위 판단: 기존 명령 전체로 넓히나 (analyst OPINION 2 절 반례 · lead 14:0x 의뢰)

판단(v0.5, 14:2x): **J-T5 의 표식 범위는 그대로 두고(새 과제만), 기존 명령 전체의 바른 판정은 proxy 교체(J-T10) 로, 단 기본 끔 스위치 + 병행 기록으로 넣는다.** 켜는 때는 판 경계에서 팀장이 정한다(결정 8). 까닭 다섯.

**결정 8(팀장 10/26 21:0x 원문 「모든 명령에서 보정 켬」, lead 21:0x 전달, v0.7)**: 실제 받은 명령으로 「갔어야 할 거리」 를 계산하는 보정을 원운동 과제뿐 아니라 **기존 START 명령 전부에 켠다**. 그래서 아래 4 의 「기본 끔」 은 **기본 켬**으로 바뀐다: `world_frame=True` 가 기본, 옛 판정은 `world_frame=False` 인자로 남기고, 두 판정은 계속 둘 다 계산해 **갈린 에피소드 수**(9 칸) 를 기록한다. 켜는 시점은 통합 코드의 **다음 기동**(이어 가기 판 첫 기동) 부터다. 돌고 있는 S-B10 · S-B50 학습 프로세스는 바뀌지 않고, 출발 저장본 S-B10 m1500(OPINION 1) 은 옛 판정으로 학습된 것임을 manifest 에 적는다(D6 「돌고 있는 판 중간에 켜지 않는다」 는 지켜진다: 켜는 자리가 판 경계다). 아래 5 의 표식 전환도 함께 한다(5.2 의 3). 1~3 의 까닭은 그대로 유효하다(빈도가 낮아도 한 방향 오판이라 바르게 고치는 쪽이 맞고, 신호 손실이 없다).

1. **빈도 `[모의 · 실제 표집기]`.** 완벽 추종 모의에서 기존 명령의 강등 오판은 에피소드의 0.85~0.91 %(5.3 마지막 행) 이고 승급은 97.5 % 다. 기존 명령 오판은 **드물고 한 방향(보수적)** 이며, 실제 학습의 강등 대부분은 추종 실패 · 낙상이다(추정 · 에피소드별 판정 기록이 없어 실측 불가 → J-T10 의 기록으로 잰다). analyst 2 절 「주원인이라는 빈도 · 개입 증거는 아직 없다」 와 같다. 회전 오르내림(OPINION 2) 의 설명도 아니다.
2. **표식으로 넓히면 신호가 반으로 준다.** 회전 뒤 전진이 있는 에피소드가 56 % 다(모의). 이것을 표식 「0」 으로 빼면 지형 커리큘럼 신호의 절반이 사라지고 S1 이 B 와 다른 흐름이 된다(5.2 의 7 동등성 깨짐). 표식 「0」 은 새 과제 비율이 커지는 S2a · S2b 에서도 신호 손실이 크므로 임시 방편이다.
3. **바른 고침은 proxy 교체다.** `cmd_sum_xy`(몸 기준 합) 대신 **세계 좌표 기대 변위** `cmd_sum_w += R(yaw_t) · vel_command_b[:, :2]` (매 스텝, 실제 yaw) 의 노름을 **같은 식**(0.5 × ‖·‖ × 4 s × 0.9, `step_dt / 4 s` 단위 변환 그대로) 에 넣는다. 완벽 추종이면 max_dist ≥ ‖기대 변위‖ > 0.45 × ‖기대 변위‖ 라 강등이 0 이다(5.3). Isaac `terrain_levels_vel` 의 가정(에피소드 안 명령 방향 불변) 을 재표집 명령에 맞게 일반화한 것이고 새 보상 · 새 문턱 · 새 명령이 아니다(R11 · D5). 승급 조건 `max_dist > size_x / 2` 는 그대로 둔다(회전 많은 에피소드의 승급 기회 손실은 보수적 방향, 기록만).
4. **돌고 있는 판 중간에 켜지 않는다(D6).** (v0.5 문구, 결정 8 로 기본값만 바뀜: 위 결정 8 문단) 스위치 `world_frame=False` 가 기본이고 끔이면 지금 코드와 비트 동일(답 아는 시험). S1 동안 두 판정(현행 · 세계 좌표) 을 둘 다 계산해 **불일치 수**(현행 −1 · 세계 0 따위) 와 표식 유무별 수를 `train_extra.jsonl` 에 적어 실측 빈도를 얻는다. 켜는 것은 새 판 시작 또는 단계 진입에서 팀장 결정 8(DESIGN-MAPRATIO 6 절) 로.
5. **켠 뒤 표식과의 관계.** 세계 좌표 proxy 가 켜지면 새 과제(걸으며 돌기) 도 바르게 판정되므로 표식의 「승급 · 강등 생략」(5.2 의 3) 은 **기록용**으로 바꿀 수 있다. 그 전환도 결정 8 과 함께 하고, 그 전까지 5.2 는 그대로다. **(v0.7) 결정 8 이 났으므로 전환한다**: 5.2 의 3 은 기록용, 옛 덮기는 `mask_new_task` 인자로 보존.

모의 스크립트: 이 폴더 `judge_startcmd_sim.py`(읽기만, 인자 = impl-sb 경로 · N · 시드, isaac311 python -I). 범위 밖(이번에 안 함): 깃발 규칙(`judge_flag`) · 승급 조건 변경 · 성과 기반 행 넓히기 · 명령 분포 변경. 재지 않은 것: 실제 학습의 에피소드별 판정 분포(J-T10 기록 뒤) · 모의의 조기 종료 에피소드(낙상은 모의에 없다, 모의는 완벽 추종 상한만).
