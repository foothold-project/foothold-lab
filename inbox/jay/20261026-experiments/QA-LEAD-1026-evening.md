# 팀장 질문 답 (10/26 저녁)

## 1. 듬성 지형: 왜 지도를 가린 쪽이 더 많이 건너나

**짧은 답: 지금 숫자로는 우연과 구별이 안 된다.** 같은 S-B10 을 평가 시드만 바꿔 세 번 쟀더니 건넘 합이 크게 흔들렸다.

전진 1.0 명령, 64 대 중 건넌 수 (레벨 0 · 1 · 2 · 6, 18 초, 지형 해시 레벨마다 같음):

| 판 · 평가 시드 | 지도 켬 | 지도 가림 |
|---|---|---|
| S-B10 · 42 | 2 · 0 · 0 · 0 (합 2) | 2 · 2 · 1 · 0 (합 5) |
| S-B10 · 43 | 0 · 0 · 0 · 0 (합 0) | 0 · 0 · 0 · 0 (합 0) |
| S-B10 · 44 | 3 · 0 · 0 · 0 (합 3) | 3 · 2 · 1 · 0 (합 6) |
| B1500 · 42 | 1 · 0 · 0 · 0 (합 1) | 0 · 0 · 0 · 0 (합 0) |
| S-B50 · 42 | 4 · 1 · 1 · (재는 중) | 2 · 1 · 0 · (재는 중) |

- 시드만 바꿔도 S-B10 가림은 0 ~ 6, 켬은 0 ~ 3 이다. 판 사이 차 (0 ~ 6) 가 이 안에 들어간다. 그래서 「같음」 으로 본다.
- 세 시드 중 둘에서 가림 ≥ 켬 이긴 하다. 팀장 짐작 (「복원 지도가 듬성 지형에서 부정확」) 은 이번 경우엔 맞지 않을 수 있다: **「지도 켬」 평가는 복원 지도가 아니라 정답 지도 (eval_gt) 를 넣는다.** 지도가 정확한데도 못 건넌다는 뜻이다.
- 그래서 더 그럴듯한 설명 (추정): 정책은 듬성 지형을 한 번도 학습하지 않았다. 지도에 처음 보는 깊은 구덩이 모양이 들어오면 그 입력이 오히려 행동을 흔들 수 있고, 지도를 가리면 연속 지형에서 배운 대로 그냥 걷는다. 이 가설은 이 지형을 학습시킨 뒤 같은 칸으로 다시 재야 가려진다.
- 영상은 아직 안 봤다 (아래 5 절).

## 2. 결정 8: 「모든 명령에 보정을 켜면 되지 않나」

**짧은 답: 팀장 안이 맞다. 켜는 쪽으로 바꾸길 권한다.**

- 「보정」 = 실제 받은 명령으로 「갔어야 할 거리」 를 계산해, 그 거리와 견주어 승급 · 강등을 정하는 것. 원운동 · 회전 · 천천히 걷기 모두 이것이 더 바른 판정이다.
- 첫 판에 끄자고 한 까닭은 「한 판에 한 가지만 바꾸기」 였다. 그런데 기존 명령에서 판정이 바뀌는 비율이 약 0.9 % (planner 모의) 라 섞이는 효과가 작다. 바른 판정을 미루는 손해가 더 크다.
- 그래서 권고: **모든 명령에 보정 켬**. 대신 옛 판정과 갈린 에피소드 수를 기록해 (코드에 기록 열이 이미 있다) 결과 해석 때 함께 본다.
- 팀장이 「켬」 이라고 확정해 주면 planner JUDGE-SPEC · 통합 코드의 기본값을 바꾼다.

## 3. 시작 방향을 +x 로 맞춘 까닭 · 깃발 과제와 충돌하나

- 맞다. 듬성 칸은 띠가 +x 방향으로 놓여 있어서, 로봇이 띠를 따라 도착 단 쪽을 보고 출발해야 「건너는가」 를 잴 수 있다. 무작위 방향이면 옆으로 걸어 나가 버린다.
- **평가에서만** 맞춘다. 학습에서는 지금처럼 방향이 무작위다. 그래서 정책이 「늘 +x 를 볼 때만 걷는」 버릇은 생기지 않는다.
- 깃발 (목표점) 과제는 계획기가 목표 쪽으로 회전 · 이동 명령을 내는 구조라, 시작 방향은 무작위로 두고 평가한다. 문제 없다.

## 4. 「떨어짐」 · 「건넘」 기준이 맞나

**떨어짐 문턱 (「문턱」 = 몸 높이 기준선, 레일 · 험지 이름이 아니다)**

- 지금 기준: 몸 높이가 **출발 단 윗면 + 0.25 m** 밑으로 내려가면 낙하. 서 있을 때 몸은 출발 단 위 약 0.34 m, 레벨 0 구덩이 바닥은 출발 단 아래 0.60 m.
- 처음 쓴 「서 있을 때보다 0.1 m 내려가면」 은 틀린 기준이라 버렸다 (시작 직후 구덩이로 떨어진 로봇의 기준 높이가 구덩이 높이가 돼서 가짜 건넘이 나왔다).
- 팀장 질문 「낮아졌다가 다시 올라가며 걸을 수도 있지 않나」: 맞다. 그래서 확인했다. 한 번이라도 문턱 아래로 간 로봇 4,694 대 중 0.2 초 안에 다시 올라와 끝까지 산 것은 53 대이고, 그중 도착 단까지 간 것은 0 대다. 지금 결과에서는 「잠깐 내려감」 이 건넘 수를 바꾸지 않는다. 그래도 낙하 수 자체는 이런 순간을 세서 부풀려지므로 지표로 쓰지 않는다.

**「문턱에 따라 판정이 바뀌는 경우」 표의 뜻**

| 판 · 조건 | 지형 | 문턱 0.225 | 0.25 (기준) | 0.275 |
|---|---|---|---|---|
| B1500 L0 켬 · 전진 0.5 | 틈 | 2 | 2 | 0 |
| S-B10 L0 가림 · 전진 1.0 | 틈 | 1 | 1 | 0 |
| S-B50 L0 켬 · 전진 1.0 | 틈 | 2 | 1 | 0 |
| S-B50 L0 가림 · 전진 1.0 | 틈 | 1 | 0 | 0 |
| G0-B L1 · 전진 0.5 | 평균대 | 4 | 4 | 2 |

- 같은 원자료를 문턱 셋으로 세어 본 것이다. 숫자는 건넌 로봇 수.
- 틈을 건넌 로봇들은 건너는 동안 몸이 출발 단 위 0.251 ~ 0.256 m 까지 내려갔다. 기준 0.25 와 1 ~ 6 mm 차이라, 문턱을 조금만 올려도 (0.275) 「떨어짐」 으로 바뀐다. 「틈 건넘」 은 경계선에 걸친 숫자라는 뜻이다.
- 기준 0.25 는 결과 전에 정한 값이라 바꾸지 않고, 민감도만 함께 적는다.

**「건넘 = 6.5 m」**

- 6.5 m 는 임의 숫자가 아니라 칸의 실제 길이다. 출발 단 (칸 x 0.5) 에서 도착 단 (칸 x 7.0) 까지.
- 처음엔 평가가 6 초라 1 m/s 로도 닿을 수 없었다 (결함). 지금은 18 초라 0.5 m/s 로도 9 m 까지 갈 수 있다.

## 5. 듬성 지형 영상은 봤나

아직 안 봤다. 듬성 칸 영상을 아직 찍지 않았다. 바탕 렌더 대기열 (runner 가 만드는 중) 이 생기면 GPU 빈 시간에 B1500 · S-B10 의 듬성 칸 (평균대 · 틈) 을 찍어 판독한다.

## 6. 「판끼리 같은 지형인가」 는 해결됐나

해결됐다. 지형 생성 시드를 고정했고 (20261026), 실제 만들어진 지형의 해시를 결과마다 남긴다. reviewer 가 25 칸을 다시 만들어 25/25 일치, 시드를 하나 바꾸면 0/25 일치를 확인했다. 판끼리는 해시가 같을 때만 비교하고, 비교 도구가 해시 · 시드가 다르면 거절한다.

## 7. L0 · L1 · L2 · L6

지형 **난이도 레벨** (Level) 이다. 0 이 가장 쉽고 9 가 가장 어렵다. 돌 간격 · 빔 폭 · 틈 너비가 레벨에 따라 커진다.

## 8. 영상: 1x 만 · 전하는 것 · 바탕 렌더

- 0.5x 가 끊겨 보인 것은 팀장 말이 맞다. 1x 로 찍은 프레임을 두 번씩 넣어 늘린 것이라 진짜 느린 화면이 아니다.
- 지금부터 1x 만 만든다 (다른 배속은 보류, RULES-HUB 4 절에 적음 fa76102c).
- 만드는 것: CMP (비교 조건별) 와 단독 판 각각 seq · forward · spin_left · spin_right, 1x.
- **팀장에게 전하는 것 (예)**
  - `CMP-B1500-G0B-SB50-SB10-m1500_mapon_rough_seq_1x.mp4` (네 판 지도 켬 비교)
  - `CMP-B1500-G0B-SB50-SB10-m1500_mapmasked_rough_seq_1x.mp4` (네 판 지도 가림 비교)
  - `EX34-SB10-m1500_mapgt_rough_seq_1x.mp4` · `EX34-SB10-m1500_mapmasked_rough_seq_1x.mp4` (단독 seq)
  - `..._forward_1x` · `..._spin_left_1x` 같은 구간 영상은 폴더에만 두고 따로 전하지 않는다.
- 바탕 렌더: GPU 가 학습 · 평가에 안 쓰일 때만 낮은 우선순위로 하나씩 돌리고, 학습 · 평가가 뜨면 다음 건부터 멈추는 대기열을 runner 가 만든다.
- 화면 정렬 (그림 두 장의 빨간 표시): 글자 줄 · 칸 경계 · 왼쪽 이름 열 맞추기, 「정책에는 0」 이 「()」 로 잘리는 것, 지도 없음 판의 빨간 세로선 정체를 runner 에 맡겼다.

## 11. 회색 제안 문장일 때 한도 경고가 「막힘」 인 것

맞다, 「보냄」 이어야 한다. 화면에 보이는 글은 회색 제안뿐이고 진짜 친 글은 따로 (빈 ❯ · 끝 빈칸 0) 잡히므로, 경고 · 재개도 캐시 신호와 같은 규칙을 쓰면 된다. super2 에 고치게 했다 (PR 뒤 팀장 병합 확인).
