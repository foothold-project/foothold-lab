# EX-23·25 이후 마찰 원인 비교와 START 본류 복귀 계획

## 1. 이번 판단

**다음 우선 비교는 이어받기가 아니라, EX-23 설정에서 처음부터 시작하는 두 판이다.** A는 현 마찰 고정, B는 예전 마찰 분포만 복원한다. 둘 다 같은 초기 신경망에서 같은 경험량을 쌓는다. 팀장의 마찰 가설을 가장 직접적으로 반박할 수 있고, 특정 checkpoint를 계속 다듬는 경로에 먼저 고정되지 않는다.

이것은 팀장의 첫 목표인 DR·행동 지연 일부 복원을 취소하는 것이 아니다. 그 목표의 첫 원인 비교를 구체화한다. **마찰 원인 확인, 이미 배운 정책의 적응, 최종 START 공동 학습은 서로 다른 질문**이다. 세 질문을 한 판의 성공으로 답하지 않는다. [방향 검토](REVIEW-direction-curriculum-1023.md)의 같은 부모 이어받기 A/B 권고는 적응 질문에만 남기고, 이번 원인 비교의 우선안으로는 이 문서가 대신한다.

기존 번호 EX-01~25와 파일은 보존한다. 새 EX 번호는 실행 결정 때 [EXP-MAP](../20261021-experiments/EXP-MAP.md)에 등록한다. 아래 A/B는 제안 이름이며 기동 지시가 아니다. A 시작 전에 A/B 양쪽 설계·구현 SHA·초기 상태·실제 소비 설정·평가 목록을 함께 동결한다. A 결과를 본 뒤 B만 바꾸지 않는다. 새 규칙이나 합격선을 결과를 본 뒤 덧붙이지 않는다.

### 무엇을 통제해야 하나

- A/B는 같은 초기 weight SHA와 지형 높이장·종류·초기행·질량 표본·명령 생성 조건을 확인한다. 단순히 seed42라고 쓰는 것으로 충분하지 않다. 마찰 표집 호출이 공통 난수열을 밀어 다른 질량·초기 상태를 바꾸면 처치가 섞인다. 준비 코드에서 두 판의 동일 난수 호출 구조 또는 처치별 난수 분리를 쓰고 실제 비처치 배열 해시를 비교한다. A 고정 범위도 B와 같은 표집 경로를 소비하게 한다.
- 반대로 학습 이후 방문 지형·reset 횟수·정책 행동이 달라지는 것은 처치의 결과다. 이를 강제로 같게 맞추거나 결과 분석에서 없애지 않는다. 환경별 지형·명령·종료 분포를 남겨 총효과와 노출 차이를 함께 설명한다.
- B는 **낮은 마찰 하나**가 아니라 정적·동적 분포 폭과 평균·결합분포가 달라지는 처치다. B 악화로 ‘0.2 자체가 원인’이나 ‘오직 낮은 쪽이 문제’라고 말할 수 없다. 필요하면 후속에 폭·하한을 나누지만 지금 세 번째 판을 몰래 추가하지 않는다.
- 로봇 재질 값뿐 아니라 지면 재질·combine_mode·실제 적용 재질 표를 보존한다. 설정값0.2가 최종 접촉쌍 마찰0.2라는 보장은 없다. 곱셈/평균/우선순위가 실제 어떻게 적용되는지 Kit에서 확인하고 미확인은 남긴다.
- 새 계측은 두 판 모두에 같은 코드로 넣는다. 관측·보상·종료·난수 소비·학습 손실에 영향을 주지 않도록 한다. 실제 처리량 비용은 첫 실행에서 별도 측정한다.

## 4. 평가와 해석을 결과 전에 고정

### 공통 평가 표

기존 영상과 이어 볼12초 시퀀스는 유지한다. 그와 별도로 각 명령을 **같은 초기 자세·위치에서 독립 reset**하여 평가한다. 명령은 전진0.5·1.0m/s, 회전±1.2rad/s, 정지→0.5 재출발이다. 순수 회전에서는 전진 명령0이다. 정지/재출발은0.5를3초,0을3초,0.5를6초로 준다. 나머지는12초 유지, 고정 명령4종은 앞2초와 뒤10초를 분리 보고한다. 정지·재출발은0~3초 전진,3~6초 정지,6~12초 재출발을 각각 집계하고 전환 시각의 원시 시간곡선을 남긴다. 이 길이는 이번 측정용 설계값이지 논문 합격선이 아니다.

새 독립 평가의 지형은32×32m 유효 영역으로 따로 고정하고 시작 위치는중앙에서x방향−8m,y=0으로 둔다. 최대 전진1m/s의12초가 유효 지형 안에 남도록 root 경로와발·512칸지도 footprint의 경계 여유를 매스텝 기록한다. 기존8m타일 영상을 단순히12초로 늘리면 rough 밖 평탄 테두리에 나가므로 금지한다. 새 긴 지형은 과거 영상과 다른 평가판임을 명시한다. 정지/낙하/명령 이탈은 실패 기록이고, 실제 지형 밖으로 나간 표본은 경계 이탈로 별도 집계하며 무조건 좋은 구간만 자르지 않는다. 설치된 평가기의 지형크기·timeout·자동reset·history 초기화가 이 계약을 소비하는지 Kit10회 예행에 포함한다.

장면은 평지 근사와 고정 rough 두 종류, 재질은 현 고정·옛 분포 두 조건이다. 동일 정책을 둘 다 평가해 ‘학습이 망가짐’과 ‘어려운 바닥에서만 성능 하락’을 가른다. 기본 5명령×2지형×2재질×5개 고정 평가 초기조건 = **100 episode/checkpoint/정책**. 앞선 초안의6명령·120개는 계산 오류라 정정했다. 기존12초 연속 명령 영상은 별도 재현 자료이며100개에 섞지 않는다. 평가 초기조건5개는 학습 시드5개를 뜻하지 않는다. 목록·지형·재질 표본은 학습 전 고정한다. 작은 진단 표본이며 일반화 성공률의 정밀 추정이 아니다. reset·낙하·timeout을 숨기지 않는다.

주 비교는 최종 model_1500으로 고정한다. 가장 좋아 보인 중간 checkpoint를 사후 선택하지 않는다. 수치 평가는500·1000·1500 checkpoint에서 한다. 300은 학습 로그와 저장 checkpoint로 조기 기술 이상만 점검한다. 기존811의500/1000 모습은 참고 열이지 중단 문턱이 아니다. 영상은 각 checkpoint의 고정 대표 초기조건 첫 항목을 빠짐없이 촬영하고, 다른 항목에서 발견한 이상 구간은 추가한다. 좋은 장면을 골라 대표로 바꾸지 않는다.

### 평가 소비·종료·분모 고정

- 주 평가 모드는 **행동 평균·지각 latent z 평균·몸 감각 관측 잡음 끔**, normalizer 갱신 끔이다. 두 정책의 학습된 normalizer는 각각 자기 checkpoint 값을 사용하되 평가 중 고정한다. 카메라 렌더/깊이 노이즈와 시간 이력 경로는 두 판 동일 cfg로 고정·기록한다. G1-GT actual use_gt mask가 모든 env의 첫 스텝·reset 뒤에도True인지 확인한다. 이 주 평가를 stochastic 학습 rollout과 같은 조건이라 부르지 않는다. 추가 표집 평가를 하면 별도 표로 낸다.
- 사례 ID는F0~F4·R0~R4와고정/분포재질을 조합한다. 지형 생성 seed4200~4204,초기 yaw/roll/pitch0·몸속도0·기본관절각·관절속도0,위치는위32m장면 규격이다. 이 seed는 이번 평가용 선택이며 학습 seed42와 별개다. 초기 z와 접지 정렬은 실제 지면·로봇 모델에 맞춰 평가 준비에서 생성하고 동일 state 배열로 저장한다. 고정 재질뿐 아니라 분포재질 bucket·shape별할당·질량 등 비처치 물리값도 **한 번 만든 배열과 SHA를 A/B·모든checkpoint에서 재사용**한다. 매번seed문자열만 넣어 재생성하는 것으로 대체하지 않는다. 몸 높이·접촉 안정 초기화의 실제 계약은 기존 평가기를 검증해 파일로 동결한다. 아직 그 실값 파일을 생성·확인한 상태는 아니다.
- 최초 물리 종료 시 그 사례를 끝낸다. 자동reset 뒤 값은 앞 사례에 붙이지 않는다. 재시도는별도ID다.12초이전 종료는 종료시각·이유·관측길이를 보존하고 성공장면으로 교체하지 않는다. 종료 뒤를0속도·0오차로 채우지 않는다.
- 추종·자세·접촉 지표는 생존 구간 조건부 값이다. 이 값 옆에 완료 길이·종료 건수와원인·유효 표본 수를 반드시 둔다. 일찍 넘어진 판의 짧고좋은구간 평균을 긴완주보다 우수하다고 평가하지 않는다.100개 사례와 프레임 수를 혼용하지 않는다. 모든지표가같이개선되지않으면 단일우승을주장하지 않는다.

## 5. 발 속도 기록과 보폭의 기술 계약

기록할 수 있다. 학습에서는 고정 env ID 소수의 짧은 구간을 원시 저장하고 나머지는 집계, 평가에서는 전 구간을 저장한다. 제안은32 env,매100 update의 연속2 rollout(48제어step),기본50Hz다. 이는 저장량 제안이며 실제 부하 미측정이다. 착지 충격·짧은 슬립은5ms 물리주기 기록이 필요한 경우가 있어 평가 대표 구간만200Hz 추가한다. 미관측 미세 슬립을 ‘없음’이라고 쓰지 않는다.

필드: 시각·실제dt·env ID·episode ID·reset·명령·관절각/속도·root pose/속도·foot pose/선속도/각속도·접촉력·접촉 mask·지형/물리 재질·policy checkpoint SHA. 가능하면 접촉점과 법선·지면 속도도 기록한다. feet 순서는 이름으로 고정하고 단위·좌표계를 manifest에 쓴다. reset 경계를 차분하지 않는다.

평지 고정 지면의 발 중심 상대 XY 속도는 1차 **슬립 대용 지표**다. 경사면은 법선 n에 대해 `v_t = v_rel - (v_rel·n)n` (n은 단위법선), 움직이는 지면은 지면 속도를 뺀다. 둥근 발은 접촉 중 굴러도 중심이 움직이므로 실제 접촉점 속도는 `v_center + omega × r_contact - v_ground`가 필요하다. 접촉점이 없으면 ‘발 중심 접선 속도’로 이름 붙이고 실제 슬립 확정 수치로 승격하지 않는다. 접촉 누적 이동은 순변위가 아니라 `L=Σ c·||v_t||·dt`, 접촉시간은 `T=Σ c·dt`, 접촉 평균은L/T로 쓴다. T=0은0이아니라미정의다. 순변위는 별도 지표이며 왕복 슬립이 상쇄되어 사라지지 않게 한다. 회전식의 위치·선속도 기준점은같은발COM으로 맞추고 같은세계좌표·시각을 쓴다. 저속 접촉 노이즈와 touchdown 순간은 별도 버킷에 남긴다.200Hz 기록은 실제센서/물리값이5ms마다 갱신되는지 timestamp로확인하며 같은20ms값 네번저장을고속실측으로세지않는다.

알려진 입력 CPU 시험: 정지 발0,평면에서0.1m/s 이동은0.1,경사 법선방향 운동은접선0,발·지면 같은 이동은상대0,순수 구름의 접촉점0,reset 점프 제외,부호·feet 순서·단위 확인. Kit에서 실제 rigid body API 좌표계와 값이 맞는지는 CPU 시험과 별개다. 센서 접촉력 문턱은 기존 기록기의 값을 먼저 확인하고 임의로 새 값으로 바꾸지 않는다.

**권고 자원 배치: 학습 한 판은1501회 연속으로 끝까지 돌리고, 다른 GPU를 해당 checkpoint 촬영·평가에 예약한다. A 완료 뒤 같은 학습 GPU에서 B를 돌린다.** 성능을 중간에 눈으로 확인하면서 startup 표본을 바꾸지 않는 가장 단순한 방법이다. 두 학습을 동시에 채우는 것보다 느리지만, 아직 물리 재개 계약이 없는 상황에서 단순 속도를 위해 실험 조건을 바꾸지 않는다. 중간 평가는 저장 완료 영수증과 SHA가 확정된 checkpoint 사본을 읽고, 평가 실패가 학습 프로세스를 끝내지 않도록 분리한다. B는 미리 준비해 A가 끝나면 승인 범위 안에서 실행 담당이 연결할 수 있다. 촬영 GPU의 남는 시간을 채우려고 새 계열 학습을 만들지는 않는다.

중간 촬영 때문에 학습을 분할 재개하는 방식은 이번 우선안에서 제외한다. 현재 checkpoint가 startup 표본·실제 지형 원점을 완전히 복원하지 않으므로 마찰 원인 시험을 ‘동일 물리’로 유지한다고 보장할 수 없다. 두 판 병렬 학습을 선택하려면 별도 촬영 자원 또는 이미 검증된 실제 물리 복원 방법이 먼저 있어야 한다. 그런 선택은 비용·실험 계약을 같이 다시 적는다. 남의 프로세스 종료나 즉흥 kill은 하지 않는다.

## 7. 이어받기와 실제 소비를 쉬운 말로

**DR 설정표는 물리 세계를 바꾸는 스위치 자체가 아니다.** 지금 `startup` 이벤트는 로봇을 만들 때 설정표를 읽어 마찰 등을 한 번 적용한다. 학습1000회에 Python 설정의 범위만 바꾸면 이미 만들어진 로봇의 재질은 그대로일 수 있다. 설치된 `events.py:225~265`는 재질 bucket64개도 객체 초기화 때 한 번 만들고 이후 호출은그 bucket의번호를 배정한다. 따라서 이벤트를 다시 호출하는 것만으로 새 범위의 bucket이 만들어진다고 가정해서도 안 된다. 커리큘럼은 언제, 어떤 로봇의 실제 재질을 바꿀지 실행 코드까지 있어야 한다. 접지 중 갑자기 바꾸는 것보다 episode reset 경계에서 적용하는 방안을 설계하고 실제 적용 분포를 저장한다.

**checkpoint는 시험지뿐 아니라 예전 수업 방식도 저장한다.** EX-23은 ‘정답 지도를 계속 써라’라는 force_gt=True를 저장했다. 새 cfg에 False를 써도 현재 load 경로는 저장된True를 복원한다. 따라서 깊이 복원 지도를 쓴다고 설정만 해 놓고 실제로 정답을 볼 수 있다. 단순 재개는 옛 모드를 보존, 의도한 지도 전환은 별도 migration으로 모드·AdaSmpl 통계·관측 경로를 명시하고 실제 선택 mask를 기록해야 한다.

근거: `start_runner.py:539~647`, `start_perception.py:230~232`, `train_start.py:114~134`, [SOL-23d](REPORT-sol-23d.md). 저장 지형행과 실제 env origin의 일치, optimizer/lr/정규화/이력·물리 표본 복원도 함께 본다. 지금 고쳐졌다는 보고가 아니라 확인된 설계 위험이다.

마찰 커리큘럼 후보는 분포 폭을0→1로 점차 확대하는 방식이다. 예를 들면 정적범위 `[0.8−0.6α, 0.8+0.4α]`, 동적 `[0.6−0.4α, 0.6+0.6α]` 후 동적≤정적 일관성 처리다. α=0은현재,1은옛분포다. **α의 시작 회차·증분은 이번 결과 전에 확정한 실행이 아니며 다음 적응 명세에서 정한다.** 지연0~15ms도 실제5ms 하위스텝으로0→1→2→3 최대 지연을 검토하되 마찰과 동시 상승시키지 않는다. 논문에 없는 우리 설계값을 저자 설정이라고 쓰지 않는다.

G0·DG1·DG3는 같은본선 조건·예산으로 비교하는별도판이며, DG3를DG1보다추가20,000회학습시켜그차이를가장자리보상효과라고부르지않는다. 원설계53의Linux S0-L실제통과등선행조건은보존한다. 진단완료를본선승인으로대체하지않는다.

기존 목표2의 ‘일부 복원 결과’와 완성된 실기용 보행을 구분한다. 적응이 안 되면 무조건 이어 학습 시간을 늘리지 않는다. scratch/다른노출분포/지연 단독 등 반증 갈래를 결과표에 연결한다. “1500회가 되었으니 다음”, “20,000회를 채우면 완성” 모두 잘못이다.
