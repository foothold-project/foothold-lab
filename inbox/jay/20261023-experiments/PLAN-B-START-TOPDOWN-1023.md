## 2. B의 변경 계약

기준 코드 `7cab5223e0990533d51d46b4d498693213b99f73`, `foothold_s2/tasks/s2_x23_cfg.py` 및 해당 agent cfg를 상속한다. 시드42, 3072환경, rollout24, checkpoint 간격50, 1501 update를 유지한다. 첫 정책·추정기·복원망은 새 초기화이며 기존 EX-23 체크포인트는 비교에만 사용한다.

처치는 robot material의 정적·동적 마찰 범위를 각각0.2~1.2로 바꾸는 것이다. 64 bucket과 startup 적용, `make_consistent=True`에 따른 동적≤정적 보정까지 처치 정의에 포함한다. 따라서 실현된 동적 마찰 분포는 독립 균등분포 그대로가 아닐 수 있다. 표에 선언 범위만 쓰지 말고 전체 환경·shape의 실제 두 마찰 배열과 보정 전후 규칙, 바닥 material·combine mode를 저장한다. EX-23의 고정값은 정적0.8·동적0.6이다.

**추가 계측이 물리·신경망·난수 호출 순서를 바꾸지 않았는지 검토한다.** B의 초기 모델 state hash, terrain seed·분포, DR 외 cfg diff를 보존한다. EX-23의 과거 초기 물리 배열 등이 없으면 없는 것으로 남긴다. 같은 시드가 과거 GPU 실행을 완전히 복원한다는 뜻은 아니다. B 대 EX-23은 하나의 시드와 과거 대조에 한정한 근거이며, 전체 학습의 일반화 검증은 유용한 결과를 얻은 뒤 한다.

| 물리·센서 | START §II-D는 PIE DR을 인용 | §4 범위와 적용 시점·실제 소비값을 기록. JEPLO 추가 가림·별도100ms 지연을 원문 값으로 혼입하지 않음 |
| 낙하 종료 | §II-D는 지면 평면 아래 발을 종료하며 정확 문턱은 미기재 | TopDown 전용은 tile 출발/도착 지지 평면과 world 변환을 기준으로0.25m 여유를 적용. 구덩이 바닥의 최근접 ray 높이와 구분. B는 기존 ray 종료 불변 |

층 폭·학습률·PPO 세부·초기 p·에피소드 통계창·종료 각도 등 원문 미기재 값은 기존 구현의 근거와 우리 선택을 보고서에 열거한다. `force_gt` 자체도 우리 스위치 이름이며 논문 API가 아니다. 구현이 일부만 됐으면 “완벽 구현”이라고 보고하지 않는다.

### 종류 진행의 작업 가정

배정 비중 gap10%·sparse90%, sparse의 쉬운 집합 low:flat=1:1, 어려운 집합 high:balance:stepping=1:1:1을 제안한다. 모두 **논문 미기재·우리 선택**이며 실제 열 수의 반올림과 환경 배정 수를 저장한다. gap도10단계의 지형 난이도 승급은 받을 수 있지만 이 종류 변경에는 들어가지 않는다.

기존 정량 계약의 p_max0.9·T_start1000·T_end8000을 유지하는 안이다. 시간창에 맞춰 빨리 어려워지도록 압축하지 않는다. T는 절대 PPO update이며 Linux 재개 때0으로 돌아가지 않는다. 원문 인쇄식 `max(min(x,0),p_max)`는 p_max≥0에서 항상p_max가 되어 본문의 선형 증가와 모순이다. 구현은 본문의 의도에 맞춘 `clip(x,0,p_max)`임을 명시하고 시작·중간·끝 값을 시험한다. 저자 확인을 받았다고 쓰지 않는다.

원문 수치가 있는 최대 난이도는 보존한다. Go2에서 무조건 통과할 것이라는 뜻은 아니다. 쉬운 단계의 스폰이 네 발 지지면 위인지, 실패가 발 디딤 학습인지 시작점 오류인지 먼저 구분한다. 8×8 시절 좌표를 섞으면 학습 결과 자체가 무효다.

TopDown의 초기 몸 방향은 코스의 +x로 고정한다(yaw=0). START는 x방향으로 배치한 지형과 몸 기준 전진 명령을 쓰지만 초기 yaw 범위는 공개 원문에 없다. 따라서 이것은 저자 값이 아니라 **우리의 시작 조건 선택**이다. 기존 ±π를 그대로 상속해 뒤나 옆을 보고 출발하는 과제를 더하지 않는다. 주행 중 양방향 회전 명령과 관절·물리 DR은 유지한다. B는 과거 EX-23과 같게 기존 yaw를 보존한다. 네 발 출발 지지를 맞추는 root XY 보정도 실제 표집 관절을 기준으로 하며 관절 무작위화를 없애지 않는다.

## 4. DR·지연과 재개 상태

PIE Table II: payload−1~+2kg, Kp·Kd·motor strength 각각0.9~1.1배, COM 각축±50mm, 마찰0.2~1.2, system delay0~15ms, 카메라 위치 각축±10mm·pitch±1°·수평FOV86~88°. 초기 관절0.5~1.5에는 rad 표기가 있으나 절대각인지 기본각 배율인지 불분명하다. Go2 기본 관절각의0.5~1.5배+관절 한계라는 해석을 제안하고 원문과 같다고 단정하지 않는다. 몸 관성·모터한계·자기충돌 등 Go2 고유 상수는 Lite3 수치를 그대로 옮기지 않는다.

이번 TopDown은 출처 범위의 물리 DR을 처음부터 사용하고, 쉬운 지형·AdaSmpl로 초기 탐색을 돕는 판이다. **START가 DR을 처음부터 전부 최대로 켰다는 사실은 미확인**이다. DR의 시점·표집 주기는 우리 구현 선택으로 기록한다. B가 실패해도 TopDown이 반드시 실패한다는 뜻은 아니며, TopDown 실패도 마찰 원인 확정이 아니다. 별도 DR 램프 판은 결과를 본 뒤 설계할 수 있다.

5ms 물리 step에서0~3 substep의 행동 지연으로 구현한다면 연속 균등0~15ms와 다른 이산 근사임을 표기한다. 최근 명령이 actuator에 실제 도착한 시각·reset 버퍼·첫 지연을 CPU 정답 입력과 Kit에서 확인한다. 깊이10Hz의 프레임 유지와 이 행동 지연은 서로 다른 시간축이다.

선언 cfg뿐 아니라 startup 적용 뒤 material·mass·COM·gain·motor·카메라 실제 값과 지연을 읽어 manifest에 남긴다. cfg 범위를 바꿔도 이미 만들어진 PhysX 물성이 바뀌는 것은 아니다.

저장 대상: 정책·critic·지각망·각 optimizer·정규화·LR·절대 update·AdaSmpl 통계·선택 규칙·지형 단계/종류/원점·RNG·실현 DR 및 카메라 상태·코드/환경 SHA. 50 update 및 종료 경계에 원자 저장하고 공개 완료 파일 뒤에만 평가한다. 재개는 새segment 폴더에 부모checkpoint·SHA를 연결하며 이전manifest·물성·YAML을 덮어쓰지 않는다. Linux 재개는 optimizer를 포함한 학습 재개이나 물리 simulator/episode의 연속 상태까지 복원하지 못하면 reset을 포함한 새 실행 구간으로 표기한다. 완전히 같은 궤적의 연속 재현이라고 주장하지 않는다.

저장된 지형 단계·종류·원점에 맞춰 새 시뮬레이터의 로봇도 다시 배치해야 한다. 숫자만 복원하고 로봇은 옛 출발점에 두는 재개는 허용하지 않는다. 그 재배치 때문에 지형 승급을 한 번 더 수행해서도 안 된다. `model_initial.pt`는 학습 전 진단 snapshot이며 완료 회차가 아니므로 이어 학습의 부모로 쓰지 않는다. 깊이 프레임의 별도 지연도 checkpoint와 평가기가 같은 값을 소비해야 한다. TopDown은 원문에 없는 추가100ms 지연을0으로, B는 기존값을 보존한다.

## 5. B를 1500 전에 끝낼지

500회에 뒤처지는 것은 **그 회차에서 학습이 늦다는 근거**다. 영구적으로 못 배운다는 근거는 아니다. 특히 EX-23도500회 판독을 뒤집고1000회에 일어선 이력이 있으므로 “EX-23은500회부터 정상”을 관측 사실로 전제하지 않는다.

기본 상한1501은 유지하되,1000회에 같은 조건의 EX-23 대조·500→1000 추세·위상·관절·프레임·독립 명령 결과가 함께 나쁘고 추가500회가 새 정보를 주기 어렵다면 **운영 목적의 조기 종료를 팀장과 선택할 수 있다**. 이때 결론은 “1000회 예산에서 마찰 분포를 복원한 B가 과거 대조 EX-23보다 뒤처졌다”, 최종1500 비교는 미실행이다. 이는 이 조건에서 마찰 분포의 영향을 지지하는 탐색 근거이며 낮은 마찰 단독 원인 확정이 아니다. 종료 이후의 성능을 추측해 채우지 않는다. 보고 후 같은 판을 몰래 연장하지 않는다.

NaN·OOM·설정 미적용·잘못된 지도 선택·파일 손상은 과학적 실패와 별도다. 처치가 틀리면 원인 비교를 계속 적립하지 않는다. 현재 턴은 남의 프로세스 종료 승인이 아니며, 실행안에 합의한 정상 저장·마감 종료와 별개 강제 종료를 혼동하지 않는다.

발 XY 속도는 추가 기록한다. 우선 발 중심의 접촉 중 수평 속력이며 미끄러짐의 대용 지표다. 경사 법선·회전 접촉점·움직이는 지면을 보정하지 않았으면 실제 접촉점 미끄러짐으로 부르지 않는다. 접촉시간T=0이면 평균은 미정이다. reset 뒤 위치 점프는 제외하되 reset 직전 유효한 종료 스텝은 보존한다. 적분 이동길이L와 L/T를 함께 저장한다.

본류에는 깊이 영상·GT 지도·rough/refined 지도·오차 그림을 같은 시각으로 넣는다. 몸 앞/아래/뒤 및 발 주변·가장자리 오차와 정책의 실제 지도 선택을 분리한다. loss 감소, p 감소, 보상 증가 중 어느 하나도 복원 전용 보행 성공을 대신하지 못한다.

## 7. 평가 조건

B는 같은 평가기·checkpoint 회차·행동 평균/latent 평균·정규화 동결·지형 seed·초기상태·명령·물리 배열로 EX-23을 다시 평가한다. 저장 force_gt와 첫/reset use_gt를 검증한다. 과거 잘못된 평가 영상은 재사용하지 않는다. 독립 명령5개(vx0.5, vx1.0, wz+1.2, wz−1.2,정지), 평지/rough와 고정마찰/복원마찰을 구분한다. 초기상태5개를 더한100 episode 정량 묶음은 최종 또는 종료 판단용이며, 매 중간점에 같은 큰 평가를 강제로 돌리지 않는다. 첫 종료 전 값·종료 사유·초기 분모를 보존하여 reset 후 값이 실패를 지우지 않게 한다.

본류의 핵심은 **복원 전용 평가**다. force_gt=False만으로 끝내지 않고 GT 선택 마스크를 모든환경·첫스텝·reset 뒤0으로 고정한 별도 평가 모드를 쓴다. 같은 checkpoint에서 GT 입력 진단도 별도 돌려 차이를 본다. GT 조건에서만 좋고 복원 조건에서 나쁘면 “START 성공”이 아니다. sparse 학습 종류/난이도별 통과 거리·종료·발 가장자리 위반과 명령 응답을 보고한다. 반복 rollout은 한 번의 학습 시드에서 얻는 변동 범위이지 학습 시드 일반화가 아니다.

정지·재출발은 이번 명령 분포의 독립 학습 항목으로 충분히 주어지는지 미확인이다. 평가에서 진단하되 paper와 다른 후진·횡 이동 커리큘럼을 이 판에 몰래 추가하지 않는다.

## 8. GPU와 최대24시간 운영

시작 전에 절대 마감 시각을 manifest에 고정한다. 팀장 답은 “최대24시간 뒤 이전을 생각하고 결과를 중간에 확인”이며,24시간 뒤 성공 보장이나 무조건 설치 승인으로 읽지 않는다. 기동 시점이 늦어졌다고 Linux 검토 시각을 조용히 뒤로 미루지 않는다.

과거 EX-23 로그의 update 경과시간은 마지막500 평균23.24초, 전체평균25.70초였다([ETA 원자료](ETA-1023.json)). 같은 처리량이라면 B500회3.2~3.6h,1000회6.5~7.1h,1500회9.7~10.7h다. 본류10,000회64.6~71.4h,20,000회129.1~142.8h는 **기존 처리량 대입값**이며 본류 속도 예측 측정이 아니다. 첫100update 실측 뒤 ETA를 고친다. 논문의 A6000·Isaac Gym16.6h를 우리 Windows·Isaac Lab 시간으로 옮기지 않는다.

두 GPU 학습과 촬영 동시 실행은 관행만으로 허용하지 않는다. 첫 예행에서 두 학습의 최대 VRAM·처리량과 촬영 peak를 재고, 덜 찬 GPU에 촬영1개만 실행한다. 촬영 첫2분에 두 학습 update가 계속 증가하는지 확인한다. 부족하면 학습을 끊어 바꾸지 않고 촬영 요청을 보류해 B 종료 뒤 GPU0에서 처리한다. 계측·CPU 그래프·로그 확인은 계속한다. 평가 실패가 학습을 죽이는 부모 사슬은 쓰지 않는다.

checkpoint는 원자 게시와 SHA 확인 뒤 소비한다. 촬영은 `seq_video`의 자식rc·전체MP4 해독·JSON/NPZ 계약·세 파일SHA가 맞아야 완료다. 옛 wrapper의 무조건 ALL.done은 쓰지 않는다. 학습 마감은 update 경계 저장·완료 영수증·정상 종료로 한다. watchdog은 상태/마감 감시이지 과학적 판정기가 아니다. 실행 창 없이 숨김 프로세스·로그 파일로 운영한다.

회차 표기는 `model_500.pt`처럼 파일 번호와 실제 완료 update 수를 함께 쓴다. 현재 runner의 번호는0부터이므로 이 파일은501 update를 마친 상태다. B와 EX-23은 같은 파일 번호·환경 수·rollout 길이로 맞추고, 본류의 다른 환경에서는 회차만으로 같은 난도·경험이라고 주장하지 않는다.

중간 점검 요청기 `monitor_23d.py`는 완료 checkpoint의 SHA를 읽어 요청을 만드는 CPU 도구다. 상태 `completed`는 촬영 영수증 검증 완료이며, 사람의 영상 판독·위상·그래프 분석 완료를 대신하지 않는다. 배경 반복 호출과 실제 촬영 소비자는 실행 시 연결해야 한다. 현재 배경 감시나 GPU 소비자를 기동했다고 보고하지 않는다.

## 9. B 종료 뒤 GPU 0의 우선순위

| B 결과 | 정직한 해석 | 다음 GPU0 일 |
|---|---|---|
| 같은 회차에서 나쁨 | 마찰 분포를 복원한 B가 과거 EX-23보다 뒤처짐. 단일 시드·과거 대조의 미복원 차이 한계 내에서 영향 가설을 지지 | 먼저 본류 영상·복원 전용 평가. 별도 마찰 램프/분포 제한 판은 결과를 보고 설계 |
| 초반 나쁘나1500에 회복 | 주로 학습 속도·경험량 문제일 가능성 | 본류 분석과 이전 준비. “고마찰만이 해법” 주장 철회 |
| 차이 작거나 B가 좋음 | 마찰만으로 과거 포복을 설명할 근거 약화 | 다음 후보는 지연·gain·COM·명령/보상 상호작용. 원인 판을 자동 추가하지 않음 |
| 기술적으로 무효 | 과학 결론 없음 | 고정 코드·실제 소비 문제 해결, 실패 원자료 보존 |

GPU를 채우려고 불필요한 세 번째 학습을 만들지 않는다. 본류가 막힌 경우에도 GT warm-start나 DR 약화판으로 자동 교체하지 않는다. 실패 위치를 확인하고 원문 본류와 우리 변형을 구분해 팀장과 결정한다.

### 방향에 대한 반론과 한계

두 판을 병행하는 방향은 타당하다. 다만 “처음부터 DR을 넣으면 걷기를 배울 수 없다”는 일반 명제는 확인되지 않았고, “낮은 자세를 안전하다고 생각했다”도 행동을 설명하는 비유이지 원인 측정이 아니다. 보상과 초기 상태·종료·구동기의 상호작용이 같은 모습을 만들 수 있다. B는 현재 조건에서 마찰 분포의 영향을 좁혀 보는 판이다.

EX-23과 같은 조건의 A를 다시 돌리지 않는 결정은 유지한다. 대신 과거 실행의 초기 물리값과 비결정적 GPU 연산까지 복원하지 못했다는 한계를 숨기지 않는다. B의 차이를 전체 과거 실패의 단일 원인으로 확대하지 않는다.

TopDown에서 많은 요소를 함께 켜는 것은 전체 방법이 작동하는지 보는 데 맞지만, 실패 원인을 한 번에 분해하는 실험은 아니다. 그래서 설정·실제 지도 선택·복원 오차·종료·발 접촉을 먼저 계측하고, 결과 뒤에 필요한 한 요소만 분리한다. 처음부터 보이는 자세에 맞춰 보상이나 DR을 계속 바꿔 성공 장면을 고르는 방식은 피한다.

24시간은 Windows 작업 창이며 학습 완성 기한이 아니다. 이전 처리량으로는 본선10,000~20,000회를 그 안에 끝낼 수 없다. 이번 창의 현실적인 성과는 B의 같은 회차 대조와, 깊이 복원·추정·보행이 실제로 함께 갱신되며 복원 지도에서 얻는 첫 보행 증거 및 재개 가능한 상태다. 성공하지 못한 것을 “구조 구현 완료”와 섞어 성공으로 보고하지 않는다.
