# 이어 학습 · DR 복원 · Linux 이전 논의

**10/23 저녁 갱신:** 현재 두 판의 설계는 [B·START TopDown 계획](PLAN-B-START-TOPDOWN-1023.md)이다. 새 A 없이 B 대 기존 EX-23, 다른 GPU는 scratch START 공동 학습이다. 아래 이전 권고·ETA는 논의 이력으로 남긴다. 현재 실행 완료를 뜻하지 않는다.


**후속 정정:** 팀장이 첫 목표를 DR·지연 일부 복원으로 선택했다. [방향 재검토](REVIEW-direction-curriculum-1023.md)에 원문·실제 코드·독립 반박을 연결했다. 아래 “선호·결정 대기”는 앞선 질의 이력이다. EX-23은 G1-GT, 기존53의 깊이 복원·AdaSmpl G1은 DG1, 발 가장자리 항 추가 G3는 DG3로 표시한다. 옛 실행키는 보존한다. Depth Range 제안은 raw 훼손이 아니라 후단 표현 개선이라는 뜻으로 바로잡았다. 세부 처치·회차·GPU·이전 날짜는 아직 확정하지 않았다.

## 마지막 질문 반영 · 이어받기를 우선 전제로 두지 않음

앞선 이어받기 설명은 가능한 방법이지 반드시 택할 정답이 아니다. 팀장이 제안한 ‘EX-23과 같게 처음부터 시작하고 마찰만 옛 분포로 바꾸기’를 [최종 논의용 계획](PLAN-friction-curriculum-1023.md)의 첫 원인 비교로 권고한다. 같은 초기화에서 현 마찰 대조도 새로 학습해야 새 코드·추가 경험 효과를 분리한다. 같은 부모의 이어받기 A/B는 이후 적응 질문에만 사용한다. 새 학습을 시작하지 않았다.

설정표만 바꾸면 물리값이 그대로일 수 있다는 말은, 지금 DR 코드가 로봇 생성 때 한 번만 설정을 적용하기 때문이다. 커리큘럼은 살아 있는 로봇의 실제 재질을 변경하는 코드와 적용 기록까지 필요하다. EX-23 checkpoint는 ‘정답 지도 강제 사용’도 저장하므로 새 cfg의깊이 모드를 옛True가 덮을 수 있다. 단순 재개와 의도한 지도 전환을 나누고 실제 선택된 입력을 확인해야 한다. [실제 함수 대조](REPORT-sol-23d.md).

아래 ETA는 이전 이어받기 선택지의 계산 이력이다. **이번 scratch 원인 비교의 시간은 위 계획의 자원 배치·ETA를 우선**하며, 원인 비교를 더하면서 이전20~44시간 약속을 그대로 유지하지 않는다.

## 팀장이 물은 핵심과 현재 답

학습 조건을 바꿀 때마다 처음부터 배울 필요는 없다. 같은 신경망에서 마찰·질량·행동 지연의 범위를 조금씩 바꾸는 커리큘럼은 이미 배운 정책을 이어서 발전시키는 방법이다. 새 지형을 배울 때 기존 지형과 명령도 섞어 잊지 않는지 본다. 반면 서로 다른 방법의 효과를 비교하는 실험에서는 출발 checkpoint·경험량·커리큘럼을 맞추거나 차이를 명시해야 한다. 개발용 이어 학습과 논문용 독립 비교를 같은 말로 쓰지 않는다.

팀장의 높이뛰기 비유는 이 뜻에 맞는다. 도움닫기·도약·착지를 단계적으로 가르쳐도 선수의 기억을 매번 지우지 않는다. 봉을 넣은 뒤 어려워지면 쉬운 동작을 다시 섞어 연습한다. 다만 신경망은 새 과제만 오래 배우면 기존 기능을 잊을 수 있어 전진·양방향 회전·정지/재출발을 계속 함께 확인한다.

팀장 방침: 먼저 한 시드로 전체 과정의 유용한 결과를 얻고, 그 뒤 확정한 전체 과정을 다른 시드로 재현한다. 각 진단마다 다중 시드를 강제하지 않는다. 현재 결과는 단일 시드의 관찰이며 일반화 증거로 과장하지 않는다.

## 확인한 명칭 충돌

| 이름이 쓰인 자리 | 실제 뜻 | 이번 논의에서 구분하는 말 |
|---|---|---|
| EX-23의 G1 | force_gt=True, 정책에 시뮬레이터 정답 지도 고정 제공 | G1-GT · 정답 지도 진단 판 |
| EX-25의 G0 | 정책의 지도 입력 없음, 몸 감각·이력 기반 | G0 · 지도 없는 진단 판 |
| 기존 53의 S2-G1 | TR-Net 복원 지도·AdaSmpl, 발 가장자리 보상 없음 | DG1 · 복원 지도 본선 |
| 기존 53의 S2-G3 | 위 본선 + 발 가장자리 보상 | DG3 · 복원 지도 + 발 가장자리 본선 |

lead_tmp의 앞선 설명과 흐름 문서의 “G1 정답 → G3 깊이”는 기존 본선 명세와 이름이 겹친다. 53의 학습 계약은 유지하며 표시 이름 대응표만 정정했다. 다음 카드에는 이름뿐 아니라 `정답/복원/지도 없음`, `force_gt`, `feet_edge`, 부모 checkpoint를 쓴다. 진단 EX-23을 기존 G1 본선 완료로 승격하지 않는다.

S1과 S2도 동일 정책의 단순 학년 번호가 아니다. 기존 S1은 다른 관측·신경망 계약이며, 53 §4는 S1 checkpoint를 가져오지 않고 S2를 처음부터 학습한다고 정했다. 현재 EX-23·25는 이미 START 계열 S2 진단이다. 지금 S1부터 다시 해야 한다는 뜻이 아니다. S2 하위 보행을 HiPAN 상위 주행에 연결하고 하위 변경 때 상위 재적응을 검증하는 방향은 유지한다.

## 코드에서 확인한 이어받기와 주의점

읽은 코드: sonnet-code `7cab5223`, 기존 실행 파일은 수정하지 않았다.

- `foothold_s2/runners/start_runner.py:589~647`: 정책·관측 정규화·optimizer·학습률·지각망·지각 optimizer·AdaSmpl·지형 단계·명령 커리큘럼·회차·난수 상태를 저장하고 복원한다. 물리 세계의 모든 로봇 상태를 그대로 이어가는 저장은 아니므로 비트 단위 동일 궤적 재개라고 부르지 않는다.
- `start_runner.py:633~638`: est_mode·critic_mode를 대조하고 모델 state를 복원한다. 지도 없음에서 지도 CNN을 추가하는 변경은 같은 구조의 단순 resume가 아니다. 이식 또는 처음부터 학습 계약이 필요하다.
- `models/start_perception.py:228~232`: AdaSmpl 저장 상태가 force_gt를 복원한다. EX-23을 복원 지도 소비로 전환할 때 cfg만 바꾸면 정답 고정 상태가 되살아날 수 있다. 명시적인 전환과 실제 소비 입력 확인이 필요하다. 아직 그 전환 구현·실행은 하지 않았다.
- `scripts/train_start.py:143~148`: max_iterations는 추가 횟수가 아니라 총 완료 목표다. model_1500은 1501회 완료이며 500회 추가라면 총 2001회다.
- 현재 DR은 약한 값 고정이다. 마찰·게인·질량·지연 범위를 변화시키는 새 커리큘럼의 단계와 재개 상태까지 자동 보존된다고 확인한 것은 아니다. 구현 시 단계·범위·증가 조건을 저장하도록 해야 한다.

권고: EX-23을 지각 보행 개발의 주 계보로 삼고 EX-25는 비교용으로 보존한다. 이는 “G1이 모든 회전에서 이겼다”는 판정이 아니라 최종 지각 입력을 연결하려는 개발 선택이다. 조건 복원 효과를 분리하려면 같은 EX-23 부모에서 고정 조건 연장 대조도 남기는 편이 좋다. 대조 실행 여부·예산은 미결정이다.

선택지 3에서 짧은 depth smoke를 성공시키는 것과 하위 보행을 완성하는 것은 다르다. 정확한 완료 ETA는 미확인이다. 기존 18·53의 36~60h/판은 실측 전 가정이고, 현재 실행의 처리량으로는 충족하지 못하므로 현 일정에 재사용하지 않는다. Linux에서 빨라질 수 있다는 가정으로 임의 할인하지 않는다.

권고: 금요일(10/23)부터 시작할 경우 2번의 첫 결과를 토요일~일요일에 보는 시간 상자로 잡되, 결과가 미달해도 checkpoint·환경·자료를 보존해 Linux에서 같은 실험을 계속할 수 있다. “성공할 때까지 Windows에 남기”를 이전 조건으로 걸지 않는다. 이전 직전 저장과 복원 확인은 필요하지만 정상 보행 완성 자체는 OS 이전의 기술적 필수조건이 아니다. Linux 설치·자료 이동 시간은 담당자의 준비 상태 확인 전 미확인이고 위 ETA 밖이다.

## 행동 지연 · 지도 · 최종 그림

행동 지연은 “발을 들어라”라는 새 목표가 계산돼도 잠깐 옛 목표를 모터가 받는 것이다. 발을 디딜 시점과 균형 보정이 늦어져 헛디딤·진동·늦은 회복으로 이어질 수 있다. 현재 구현은20ms 제어 주기 안에서5ms 물리 스텝0~3개 동안 이전 목표를 쓰는 방식이며 EX-23·25는 이 추가 지연을 껐다. 같은 조건이라면 실제 지연과 들쭉날쭉한 지연은 줄이는 편이 유리하다. 그러나 시뮬에서 지연을0으로만 배웠다고 실제 기기의 지연이 없어지는 것은 아니다. 측정 가능한 실제 지연 범위에 견디도록 학습하는 목적이다.

G1-GT는 시뮬레이터 RayCaster가 얻은32×16 높이값을 정책의 지각 경로에 넣는다. 카메라 RGB를 이해하거나 명시적인 발 디딤 계획기를 실행한다고 증명한 것은 아니다. 지도와 몸 감각을 받은 정책이 관절 목표를 낸다. “지도 수신”과 “지도를 효과적으로 사용”은 다르며 후자는 지도 오류·가림·동일 정책 입력 교란과 보행 비교로 별도 확인한다. 같은 지형의 한 영상만으로 지도 효과를 확정하지 않는다.

512칸은187칸보다2.74배 많고5cm는10cm보다 촘촘하다. 그러나 현 지도 중심 간 범위1.55×0.75m와 옛1.6×1.0m는 다르므로 더 넓게 본다는 뜻은 아니다. 기존 촬영 NPZ에 정책이 소비한512칸 텐서는 없어, 현재 영상에 실제 소비 지도를 사후 합성했다고 표시하면 안 된다. 다음 촬영에서 입력 지도·정답·유효성·로봇 자세를 동시 기록해 점 또는 격자로 표시할 수 있다.

최종 그림은 몸 감각 기반 보행을 유지하면서 지형 정보가 있을 때 미리 적응하는 하나의 정책이다. G0→G1-GT→DG1·DG3 세 정책을 차례로 켜야 한다는 뜻이 아니다. 지도 소실 때 G0 수준으로 자동 복구한다는 보장도 없어, 가림·오류 학습과 별도 비교가 필요하다.

## 아이디어 원장 · 이번 실험에 즉시 넣지 않음

### 깊이 Range·Keyer 아이디어

팀장 제안: VFX에서 깊이 계조를 조절하듯 먼 물체를 더 일찍 구분하게 할 수 있는가. 현재 `sensors/depth_aug.py:17~40,85~99`는 미터 깊이에 잡음·무효 처리를 거쳐0.2~3.0m를0~1로 선형 정규화한다. 이 범위는 START 원문 수치가 아니라 우리 가정이다.

판단: 시각화 대비를 높이는 것과 센서 정보를 늘리는 것은 다르다. 가까운 범위로 좁히면 먼 물체가 모두 흰색으로 포화되어 오히려 거리 차이를 잃는다. 센서 밖·가림 뒤·미검출 거리도 계조 변환으로 복구할 수 없다. 지금은 float 깊이를 쓰므로 디스플레이8bit 계조 문제와도 구분한다. 먼저 표시용 LUT만 바꿔 사람이 보기 좋게 만들고, 모델 입력 변경은 미터 깊이를 보존한 원본 대비 비선형/근거리·원거리 분리 표현으로 따로 비교하는 것이 타당하다. 재구성 오차·장애물 발견 시점·보행 결과를 비교해야 하며 보기 좋은 색만으로 채택하지 않는다.

### 재질과 실제 지지면 아이디어

팀장 제안: 눈·수풀·스티로폼·진흙은 보이는 높이와 발을 받치는 높이가 다르다. 접촉 뒤 몸 감각으로 알기 전에 재질을 예상해 행동을 조절할 수 있는가. Jev/Laya 같은 판단층 가능성을 기록한다.

판단: 기하학적 표면과 지지 가능성·마찰·변형을 분리하려는 유효한 연구 질문이다. 다만 “눈 아래에는 안전한 강체가 있다”는 가정은 위험하며 재질 이름만으로 바닥 높이·지지력을 확정할 수 없다. [Miki 등의 지각 보행 연구](https://leggedrobotics.github.io/rl-perceptiveloco/)는 이미 눈·식생·비강체로 잘못된 지도를 받는 문제를 명시하고 외부 지각과 몸 감각을 순환 attention으로 결합한다. 기존 연구가 이 문제를 모른다고 서술하지 않는다.

우리 확장 후보는 재질·지지력의 불확실성을 추정해 속도·경로·탐색적 접촉·정지 조언에 반영하는 것이다. Laya/Jev가 이를 실제로 판별·제어할 능력은 여기서 검증하지 않았다. 언어 모델에 고속 관절 제어를 넘기지 않는다. 강체 지형만 학습한 결과로 눈 침하·진흙 유동 내성을 주장할 수 없다. 기본 지각 보행을 얻은 뒤 (몸감각+기하) 대비 (+재질 단서), 잘못된 재질 단서까지 포함해 비교한다.

## 지금 팀장이 정할 것

2번은 선호이고 확정이 아니다. 위 시간 범위와 전체 DR 복원이 아니라 일부 복원의 첫 결과라는 범위를 확인해 이전 전 목표를 정한다. 이어 학습 부모·회차·DR 항목·실제 실행은 그 다음 카드에 기록한다. “주말까지 성과가 나와야 이전”인지 “주말에는 저장 상태가 준비되면 결과와 관계없이 이전”인지가 일정의 핵심 갈림길이다.
