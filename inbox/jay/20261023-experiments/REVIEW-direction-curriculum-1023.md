# EX-23·25 다음 방향의 반박 검토

**10/23 저녁 갱신:** 현재 두 판의 설계는 [B·START TopDown 계획](PLAN-B-START-TOPDOWN-1023.md)이다. 새 A 없이 B 대 기존 EX-23, 다른 GPU는 scratch START 공동 학습이다. 아래 이전 권고·ETA는 논의 이력으로 남긴다. 현재 실행 완료를 뜻하지 않는다.

## 판단부터

**방향은 유지하되 설명과 실험 방법은 고쳐야 한다.** 약한 고정 DR·추가 행동 지연 없음에서 START 계열이 전진 보행을 얻었다. 이제 내성을 회복하려는 목적은 옳다. 그러나 이것은 저마찰 단독 원인, 점진 복원이 최선, 정답 지도 우월의 입증이 아니다. 다음 결과가 이 생각을 틀렸다고 보여줄 수 있게 설계해야 한다.

### 행동 지연 0~15ms의 정확한 출처

[PIE Table II·III-C3](https://arxiv.org/html/2408.13740v3#S3.SS3)에는 system delay0~15ms가 명시돼 있다. START는 PIE DR을 따른다고 인용한다. 따라서 START 계보에서 가져온 근거는 있지만, 비공개 START 코드가 정확히 어떤 큐·표집 시점으로 지연을 만들었는지는 미확인이다. 우리 구현은20ms 제어 주기 안의5ms 물리 스텝0~3개에 이전 목표를 유지한다. EX-23·25는 추가 지연0이다.

지연 내성은 필요하다. 다만 마찰·질량·센서 잡음과 한 번에 늘리면 실패 원인을 다시 잃는다. 실제 센서→추론→통신→모터 지연과 변동을 나중에 재서 학습 범위와 맞춰야 하며,0~15ms만 넣었다고 전체 실기 지연을 덮었다고 할 수 없다.

### 실제 코드에서 잡힌 설계 주의점

[SOL-23d](REPORT-sol-23d.md)의 핵심 경로를 lead_tmp가 sonnet-code `7cab5223`에서 다시 읽었다. `s2_x23_cfg.py:22~30`은 로봇 마찰0.8/0.6 고정, 질량−1~+3kg 표집 유지, COM·gain·motor 무작위화 해제, 추가 지연 해제다. 따라서 **DR 전체가 꺼진 상태가 아니며 질량 범위는 오히려 옛−1~+2kg보다 넓다.** “모든 조건을 줄였다”도 부정확하다. 실제 접촉쌍의 합성 마찰은 아직 미측정이다.

같은 보고의 현재 지형은7종23열, 초기0~2행이며 START의 듬성한 디딤점 종류 진행과 다르다. 새 DR 설계가 `startup` 범위만 바꾸는지 실제 실행 중 적용값까지 바꾸는지 구별해야 한다. 기존 지형 승급은 대조에서도 유지하고, 양쪽이 방문한 행·종류 분포 차이는 결과로 기록한다.

lead_tmp는 실제 함수만 AST로 추출해 CPU에서 다음 두 입력을 대입했다(Kit·GPU·전체 환경 시험 아님).

| 실제 함수와 입력 | 관찰한 출력 | 다음 구현에서 필요한 것 |
|---|---|---|
| `start_runner.py:556~572` `_load_env_state`, 저장 행8·종류2, 새 환경 행0·원점[0,0,0] | 행은8로 복사되지만 원점은[0,0,0] 그대로. 별도 env hook 없는 경우 | 실제 env reset까지 포함해 행·종류·원점이 일치하는지 시험. 현재 정적 대조만으로 모든 실행의 잘못된 스폰을 확정하지 않음 |

`train_start.py:114~130`은 환경 생성 후 runner를 복원한다. `start_runner.py:589~647`은 학습 상태를 복원하지만 startup에서 뽑힌 개별 물리값까지 완전한 동역학 이어받기를 보장하지 않는다. 이 차이를 저장된 상태로 증명하지 못하면 같은 분포의 새 환경으로 재개했다고 적어야 한다. “완전히 같은 물리 궤적의 연속”이라고 부르지 않는다. 이 검토에서는 코드를 고치지 않았다.

[ASTRA-23c](VERIFY-astra-23c.md)는 다른 작업자의 새 의견을 읽지 않고 독립으로 같은 부모 고정 연장 대조, G0와 G1-DR 대조의 구별, 지형 커리큘럼과 DR 램프의 혼동을 지적했다. lead_tmp는 새 주장에 연결된 원문·코드를 직접 대조했고 이전 수치는 [RESULT](../20261021-experiments/RESULT-EX23-25.md)의 재사용 실측으로 남긴다. 별도 전체 재실측을 했다고 보고하지 않는다.

현재 G1 checkpoint를 연구 시작점으로 권하는 이유는 최종 목표가 지각 보행이기 때문이다. G0보다 전반적으로 좋다는 판정 때문이 아니다. G0와 현재 G1 checkpoint·영상·원자료는 그대로 보존한다.

최소 비교의 권고는 같은 G1 부모에서 **A: 현 조건 그대로 이어 학습**, **B: DR의 한 항목 또는 지연만 바꿔 이어 학습**이다. 추가 경험량·명령·지형·최적화 조건을 맞춘다. 학습 시드를 매 판 늘리자는 것이 아니라, 더 학습해서 좋아진 효과와 복원 처치 효과를 구분하는 비교다. 두 GPU 동시 사용은 실행 계획이 결정된 뒤에만 한다.

| 나올 수 있는 결과 | 해석과 다음 행동 |
|---|---|
| A도 좋아지고 B도 비슷하게 좋아짐 | 더 학습한 효과일 수 있음. B의 새 조건 내성이 늘었는지 별도로 보고 복원 비용 판단 |
| A는 유지·개선, B만 기존 조건에서도 악화 | 처치나 소비 구현·강도·재개 상태를 먼저 검사. “시간이 부족해서”라고 무조건 연장하지 않음 |
| B가 새 조건에서 개선하지만 깨끗한 조건에서 회전 악화 | 강건성과 명령 반응의 교환. 두 결과를 모두 보고, 쉬운 조건 노출·증가 속도 검토 |
| A·B 모두 같은 회전 정체 | DR만으로 설명 안 됨. 명령 전환·지형·보상·평가 상태 이력을 조사하고 본류 진행을 위한 대안 제시 |
| B의 실제 적용값이 설정과 다름 | 실험 무효 또는 제한된 해석. 성능 비교 이전에 코드 소비 경로를 고침 |

DR 램프가 반드시 필요한지를 입증하려면 추후 같은 목표 범위를 즉시 적용하는 갈래도 필요하다. 첫 판에서 모든 조합을 다 돌릴 필요는 없지만, 램프만 시험하고 “램프가 최선”이라고 결론 내릴 수는 없다.

실행 명세에는 부모 SHA, 추가 update 예산과 누적 update 구별, 변화 한 항목, 쉬운 조건 유지 비율, 평가 조건, 확인 시점, 중단·복귀 이유를 채운다. 지금 문서에서 임의 숫자를 합격선으로 새로 만들지 않는다. 장시간 GT-only 연장으로 본류의 깊이 재구성·AdaSmpl·듬성한 지형이 계속 밀리는 것을 경계한다.

## 중간 확인을 체계화하는 방법

[운영 규칙](../20261019-design/EXPERIMENT-RULES.md)에 같은 표를 연결한다. 기존 점검을 실행 증거와 이어 주는 방식이며 새 사람 승인 관문을 늘리는 것이 아니다.

| 시점 | 실제로 남길 증거 | 잘못됐을 때 구분 |
|---|---|---|
| 코드 준비 | 부모 복원 전후 동일 입력 출력, 정규화·optimizer·학습률·누적회차·AdaSmpl·DR 상태 저장/재개 시험. 경계 전/후·reset·무효 입력 반례 | 설정만 바뀌고 실제 재질·지연 버퍼가 그대로면 구현 결함 |
| 승인된 짧은 실제 실행 | 소비한 물리 재질·합성 방식, delay 실표집·적용 스텝, 지도 선택 비율, 지형 행·종류·명령 실분포. YAML와 값 대조 | CPU 통과를 실제 PhysX 적용 증거로 쓰지 않음 |
| 첫 update와 DR 단계 변경 직후 | 처리량·메모리·유효 episode·접촉/종료 항·raw/clip action·loss/KL, 적용 시각 | 단순 cfg 수정인지 실제 rollout 분포가 바뀌었는지 분리 |
| 사전 지정 checkpoint | 같은 초기조건의 전진·양방향 회전·정지/재출발. 평지와 rough, 익숙한 조건과 복원 조건. 전체 영상+위상+관절+높이+명령 반응 | 잘 도는 방향만 고르지 않음. 이전 명령 영향은 독립 reset 시험과 연속 명령 시험으로 분리 |
| 종료·재개 | checkpoint·코드·설정 해시, 끝난 update, 다음 불러오기 동일성, 분석 산출물과 공개 링크 | MP4 빈 파일·receipt 성공과 실제 보행 성공을 분리 |

모든 프레임의 파일 해독과 사람이 눈으로 본 프레임은 다르다. 문서에 각각의 검사 범위·간격·이상 구간을 적고 미판독 구간을 감추지 않는다. 실패 보행 영상을 지우거나 재촬영 성공 장면으로 대체하지 않는다.

## 본류와 명칭

| 앞으로 문서에서 부를 이름 | 의미 | 옛 이름·파일 호환 |
|---|---|---|
| EX-25 G0 | 지도 없는 진단 | 기존 실행명 유지 |
| EX-23 G1-GT | 시뮬레이터 정답 높이 지도 고정 소비 진단 | 기존 `G1`, force_gt=true. 깊이 복원 성공을 뜻하지 않음 |
| DG1 | 깊이 복원 TR-Net·I-E·AdaSmpl 본선, 발 가장자리 항 없음 | 설계53의 옛 S2-G1. 당장은 표시 별칭이며 코드키·봉인 gates·체크포인트 이름은 변경하지 않음 |
| DG3 | DG1에 발 가장자리 보상 추가한 본선 | 설계53의 옛 S2-G3. DG1과 다르게 학습한 데이터·부모가 있다면 효과 비교 한계 기입 |

팀장 제안 DG1·DG3는 혼선을 줄이므로 표시 이름에 적용한다. 본류는 **START 보행 기반 → DR·지연 내성 복원 검토 → 열린 명령·듬성한 지형 연결 → DG1·DG3의 실제 깊이 지각 → HiPAN 하위 정책 연결**이다. 이것은 기존 본선 예산·평가 계약을 진단1500회로 덮는 변경이 아니다. START의 공동 학습과 AdaSmpl이 본류이며, GT에서 오래 학습한 뒤 나중에 깊이만 붙이는 경로를 원 논문 그대로라고 부르지 않는다.

매 새 EX 카드에 본류 단계, 이번 질문, 부모, 무엇이 달라졌는지, 본류로 돌아오는 조건, 그때 필요한 미구현 항목을 적는다. [EXP-MAP](../20261021-experiments/EXP-MAP.md)이 정본이고 [DECISION-SYNC](../20261019-design/DECISION-SYNC.md)가 실제 반영 여부를 잇는다. 아직 학습하지 않은 판을 완료 화살표로 그리지 않는다.

## 아이디어 정정 기록

### Depth Range: 원본 훼손 제안이 아니다

팀장은 raw 깊이를 보존하고 Keyer 노드처럼 후단에서 먼 물체의 구분을 돕는 표현을 제안했다. 이 의도를 “원본을 바꾸려는 제안”으로 읽지 않는다. 가능한 이득은 센서 정보의 증가가 아니라 **이미 있는 원거리 정보를 모델이 이용하기 쉬운 표현**이다.

먼 물체가 늦게 보이는 원인이 표시 대비인지,3m clipping·FOV·가림·유효값 제거인지, 로컬 지도 범위·시간 기억·학습 손실인지 먼저 나눈다. 사람이 보는 LUT만 바꾸면 정책은 달라지지 않는다. raw를 보존해도 모델에 들어가는 후단 텐서를 변환하면 모델 입력 분포는 바뀌므로 별도 비교다. 포화되기 전 미터 깊이를 보존하고, 원거리 구간 오차·첫 탐지 시점·발 디딤 성능으로 효과를 잰다. 센서 밖이나 가려진 정보는 계조만으로 복구되지 않는다. 현재 `depth_aug.py`의0.2~3.0m는 우리 설정이지 START 원문 확정값이 아니다.

### 눈·수풀: 보이는 표면과 몸을 받치는 면이 다름

15cm 눈을 보고 발을 내렸는데 하중을 받지 못하고 더 내려가는 경우가 핵심이다. 단순 height map은 보이는 표면 높이일 뿐 지지력·침하량을 보장하지 않는다. 예측한 접촉과 실제 힘·관절 움직임·몸 자세 변화가 어긋나면 지지면 추정과 다음 발 동작을 갱신해야 한다. 깊이 카메라만으로 눈 아래 단단한 바닥 깊이를 확정할 수는 없다.

[Miki 등 지각 보행](https://leggedrobotics.github.io/rl-perceptiveloco/)은 불확실한 외부 지각과 몸 감각을 결합하는 선례다. 그 선례가 현재 우리 정책의 눈·진흙 대응 능력을 입증하지는 않는다. 단단한 높이 지형만으로 학습하고 마찰만 바꿔서는 침하·휘어짐·시각 표면과 충돌 표면 불일치가 생기지 않는다. 추후 시각층과 지지층을 달리한 통제 시험, 접촉 예측 오차·침하·회복 시간·넘어짐 비교가 필요하다. Laya/JEV의 재질 단서는 사전 추정에 도움을 줄 수 있으나 빠른 접촉 보정은 하위 제어가 맡아야 한다. 지금 DR 복원 판에 이 새 변형 지형까지 한꺼번에 넣지 않는다.
