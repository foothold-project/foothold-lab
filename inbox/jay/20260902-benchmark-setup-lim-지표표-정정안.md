## 1. 무엇이 틀렸나 `확인됨`

지표 표의 세 칸이 값을 「누적」 또는 「적분」이라 설명합니다. **코드는 셋 다 끝점 변위입니다.**
`#125` 7번은 1019행 하나만 지목했지만, **같은 오해가 세 칸에 퍼져 있어 함께 고칩니다.**

코드 근거는 복원한 Candidate 스냅샷
`sim/eval/provenance/candidate-20260822/eval_generalization.py` 입니다.

| 코드 행 | 실제 계산 |
|---|---|
| 473 | `displacement = pre_step_pos[env_id] - start_pos[env_id]` |
| 475~478 | `forward = dot(displacement, forward_dir[env_id])` |
| 487~489 | `lateral = abs(dot(displacement, lateral_axis))` |

`displacement` 는 **끝점에서 시작점을 뺀 벡터 하나**입니다. 매 스텝을 더하지 않습니다.
따라서 셋 다 적분도 누적도 아닙니다.

## 3. 그대로 옮겨 쓸 표 조각

```
| `direction_success` | 방향 유지 | 측면 끝점 이탈 0.75 m 이하 |
| `forward_progress_m` | 초기 전방축 끝점 전진거리 | 시작점 대비 변위의 전방축 투영 |
| `lateral_drift_m` | 초기 측면축 끝점 이탈 | 시작점 대비 변위의 측면축 투영 절댓값 |
```

## 4. 왜 이것이 사소하지 않은가

끝점 변위는 **경로를 보지 않습니다.** 로봇이 옆으로 크게 밀렸다가 돌아오면
끝점 이탈은 작고, 「방향을 지켰다」로 셉니다. 적분이라면 그 흔들림이 남습니다.

`#125` 1번이 **최대 좌우 이탈 열**을 따로 더하는 이유가 이것입니다.
판정은 멘토 기준대로 끝점을 그대로 두고, 최대값은 관측용으로 붙입니다.

그러니 표를 고칠 때 「적분이라고 고쳐 적는 것」이 아니라 **「끝점이라고 바로 적는 것」**이 맞습니다.
실제로 적분이 필요하면 그것은 새 열이지 이 열의 정의 변경이 아닙니다.
