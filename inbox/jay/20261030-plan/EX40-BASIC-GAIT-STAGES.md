# EX-40 기본 보행 단계별 학습 방법과 실행 초안

**이번 판은 정해진 회차에 과제를 더하고, 성과는 별도로 계속 측정한다.** 성과가 먼저 좋아져도 자동으로 단계를 당기지 않고, 점수가 미달이라고 같은 단계에 자동으로 머물지도 않는다. 이것이 최신 D72다. 과거 의견서의 성과 승급안과 섞지 않는다. 마지막 평가가 미달이면 기본 보행 졸업으로 부르거나 다음 지형 단계로 자동 연결하지 않는다.

문서의 막음은 승인된 설계를 현재 v6 코드로 실행할 수 있다고 말하지 못하는 연결 공백이다. 진행 중인 다른 실행에 대한 종료 지시가 아니다. 새 코드와 Kit 결과는 이 문서에서 검증하지 않았다.

### 쉬운 용어

- **갱신·iter**: 로봇들이 모은 경험으로 신경망을 한 차례 고치는 단위다. 이번 설정은 환경 3,072개 × 환경당 24걸음이므로 갱신당 73,728개 전이 자료를 모은다(코드·계산: A:3, E:86). `model_0`도 갱신을 마친 저장본이다. 초기 가중치 파일과 다르다.
- **명령 슬롯**: 전진·정지·회전처럼 연습할 과제를 고르는 칸이다. 비율은 뽑을 확률이며 실제 소비한 걸음 비율이 반드시 같지는 않다. 넘어짐이나 재추출 때문에 달라지므로 둘 다 기록한다.
- **vx·vy·wz**: 몸 기준 앞뒤 속도·좌우 속도·회전 속도다. 앞의 둘은 m/s, 회전은 rad/s다. 양수 회전은 좌회전, 음수는 우회전이다.
- **heading**: 목표 몸 방향을 향하도록 회전 명령을 보정하는 장치다. 목표 위치까지 찾아가는 깃발 항법과 다르다.
- **GT / PRED / OFF**: 시뮬레이터 정답 높이 지도 / 깊이 영상에서 복원한 높이 지도 / 지도 경로 가림이다. HMap은 height map, GT는 ground truth, Pred는 predicted의 줄임말이다. OFF는 로봇의 몸 감각까지 끄는 뜻이 아니다.
- **그림자 평가**: 학습 옆에서 시험을 보고 점수를 남기되, 그 점수로 이번 단계 전환을 조종하지 않는 방식이다. 시험이 누락된 것은 PASS가 아니다.
- **DR**: 마찰·질량 등 현실의 차이를 시뮬레이션에 섞는 domain randomization이다. 이번 단계마다 모든 DR을 더 세게 하는 계획은 아니다.

### 3.3 heading은 무엇을 하나

모든 단계에서 전진 슬롯의 절반만 목표 방향을 유지하도록 보정한다. 회전 명령은 `0.5 × 방향 오차`를 계산하고 전진 중에는 크기 0.5 rad/s까지만 쓴다. 나머지 전진은 회전 명령 0이다. 이 숫자는 가정·채택(Y:9, M:311~335, O:124)이다. 전진 heading의 전체 몫은 B0 36%, B1 20%, B2 15%, B3a 이후 12.5%다(계산).

B2 이후에는 제자리 회전 슬롯의 30%, 전체의 6%가 목표 방향 회전이다. 나머지 전체 14%는 직접 회전 속도를 지정한다. 목표 yaw는 −π~π에서 뽑고 gain 0.5, 회전 보정 상한 1.5 rad/s를 쓴다(Y:9, M:311~335, 가정·채택·코드). 이 경로의 작은 방향 오차에서는 명령이 회전 하한보다 작을 수 있다. 표의 회전 하한은 직접 회전 슬롯의 범위다.

**구현상 주의:** M:316은 현재 이름 B2·B3·T0만 목표 회전 대상으로 고른다. B3a·B3b·B3c로 바꿀 때 이름 검사를 함께 고치지 않으면 heading이 사라진다. 또 M:324~336은 목표 오차를 줄일 뿐 목표 도달 때 `stand=True`로 전환하지 않는다. O의 “목표 방향 후 정지”와 W57의 “목표 도달 후 명시적 정지”(D58:83)를 동일하게 구현했다고 말하면 안 된다. 현재 확실한 정지 보상 대상은 정지 슬롯이다. 목표 도달 후 정지 상태를 넣을지는 기존 약속과 맞춰 scripter가 명시적으로 닫을 항목이다.

## 4. 보상: 무엇을 칭찬하고 무엇을 줄이나

### 4.3 RR 발을 드는 문제에 대응하는 정지 두 항

발마다 바닥과 발 충돌면의 간격을 h, 수직 접촉력을 Fz, 해당 환경 로봇의 전체 질량을 m이라고 두면 다음과 같다(R:103~123, 가정·채택·코드).

`간격 비용 = −0.2 × Σ max(h−0.005 m, 0) / 0.05 m`

`하중 비용 = −0.1 × Σ max(0.05mg−max(Fz,0), 0) / (0.05mg)`

두 항은 정지 전환 후 0.5초 동안 0에서 원래 크기까지 올린다. 5 mm 이내 간격을 벌하지 않고, 네 발에 정확히 25%씩 무게를 나누라고 강제하지도 않는다. 5%는 거의 무하중인 발을 구분하려는 **우리 첫 시험값**이다. 학습 효과는 미확인이다(O:82~100).

측정은 발별 광선의 지형 교점과 실제 발 충돌면으로 한다(R:188~238). 현재 힘은 각 발 `net_forces_w`의 z성분이다. 이를 바닥 접촉만 분리한 힘으로 부르지 않는다. 발 벽 접촉과 경사 조건은 함께 기록해야 한다. NaN 간격·힘은 R:114~122에서 비용을 0으로 마스킹하므로, 비용이 작다는 사실만으로 네 발 지지가 좋다고 판단하지 않는다. `train_extra.jsonl/ex40_stand_sensor`의 유효 표본 수·발별 비정상 수가 먼저다(S:469~475).

## 6. 그림자 평가: 무엇을 보고 무엇을 아직 배웠다고 말하지 않나

저장본 번호 250의 배수에서 GPU1 평가를 예약한다. m250~6500은 **26번**이며 각 단계 끝 m1500·3000·4500·5000·5500·6000·6500도 포함한다(의뢰의 간격·D72, 계산). m0은 초기 갱신 자료로 보존하되 별도 정규 평가를 추가했다고 가정하지 않는다. 숫자는 저장본 번호이며 완료 갱신 수는 m+1이다.

### 7.2 마감과 중단 후 재개

총 43시간은 **lead 추정**이다(D72:97). 새 판의 실측이 아니다. 현 계약은 갱신당29초 보수 예산과 추가24시간 여유를 요구한다(K:129~145, 가정·코드). 새6501갱신에 그대로 적용하면 약52.37시간+24시간, 시작으로부터 최소 약76.37시간의 마감 여유다(계산). 최대 wall time96시간은 L:47·K:129의 실행 상한이다. 최종 END_BY는 runner가 실제 시작 시각으로 산출하고, 첫50회 실측 속도로 예상 끝과 여유를 다시 보고한다(M77). “일요일 오후 끝 허용”은 일요일에 회차를 잘라 종료하라는 뜻이 아니다.

정상 경계에서는 한 프로세스가 계속 돈다. 중단이 필요해 저장한 뒤 재개할 때의 초안은 다음과 같다.

1. 해당 EX-40 실행의 저장본·manifest·SHA를 확인한다. 다른 부모를 가져오는 transfer가 아니다.
2. policy·perception·두 optimizer·adaptive lr·AdaSmpl·지도 상태·지형 상태·RNG·curriculum stage·B1 실제 진입 번호를 복원한다(S:850~866·1027~1055, C:548~591).
3. 남은 횟수는 `6501−(저장본 번호+1)`이다. 예를 들어 m3000 뒤는3500회다(계산). 같은 회차를 중복 학습하거나 누락하지 않는다.
4. 새 segment 영수증에 부모 경로·SHA·재개 stage·완료 횟수와 물리 reset을 적는다. 현재 T:359~369의 `scratch/B0` 고정 표기를 재개에도 재사용하면 안 된다.
5. 재개 첫 갱신의 lr·std·stage·실제 명령/지도 소비·지형 레벨을 저장 직전과 대조한다. 새 물리 환경과 지각 기억 초기화가 있으므로 끊지 않고 달린 궤적과 완전히 같다고 부르지 않는다(S:292~297, V `runners/sol23f_runner.py:222~242`).

**현재 재개는 준비되지 않았다.** 내부 load 기능은 있으나 L:64~65와 K:117~118이 EX-40의 resume_from을 거절한다. 새 launcher 경로에서 같은 실행의 재개를 허용하고 remaining·영수증·score 중복 방지를 연결한 뒤에만 “무인 복구 가능”이라고 쓴다.
