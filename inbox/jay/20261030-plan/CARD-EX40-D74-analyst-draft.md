# EX-40 D74 실행카드 수정 초안

R4·R6·R8·M30·M76·M77 적용. 저장 YAML·실제 PhysX·지연 버퍼·지도 선택을 읽어 명목 설정과 대조한다. CPU 시험만으로 실행 준비를 선언하지 않고, 새 runtime adapter의 짧은 Kit 증거를 별도로 확인한다. W51의 기존 정책 평가는 이 학습 사슬의 성공 증거가 아니다.

## 1. 변하지 않는 것

처음부터 학습, arm B, env 3072, seed42, rollout24, physics dt 5 ms·policy dt 20 ms. 고정 회차+그림자 판정이며 점수로 단계를 앞당기거나 지연시키지 않는다. 최종 졸업 D57은 기존 13명령·세 지도 모드에서 생존60/64 이상, 추종 오차0.15 이하라는 프로젝트 가정이다. 학습 완주와 졸업은 별개다. 깃발과 대칭 증강은 끈다.

마찰 정적·동적 U(0.2,1.2)와 base 추가 질량 U(−1,+3) kg은 startup에서 그대로 적용한다. 관측 잡음도 m0부터 끝까지 현재1배 고정이다: 각속도±0.2 rad/s, projected gravity±0.05, 관절 위치±0.01 rad, 관절 속도±1.5 rad/s. 명령·이전 action에는 별도 관측 잡음을 추가하지 않는다. 관측 잡음은 아래 확대 배율 대상이 아니다.

명령 슬롯·범위·heading·보상은 [단계 문서 §3~4](EX40-BASIC-GAIT-STAGES.md)를 함께 고정한다. 지형은 연속7종의 L0~2 유지안이며 자동 승급과 혼동하지 않는다. 실제 runner 카드의 ‘팀장 결정 대기’ 표기를 lead가 채택 기록과 맞춰 닫아야 한다. 이 초안 자체가 그 선택을 승인하지 않는다.

총8001갱신, 589,897,728 환경 전이. `model_N`은 N+1번 갱신을 마친 저장본이다. 최대 반복 인자는8001, 최종 model_8000.pt다. 단계는 전역 갱신 경계에서 목표를 바꾸되 각 env의 자연 reset에서 채택한다. 단계 전환 시 전체 강제 reset이나 PPO·optimizer·lr·std 초기화를 넣지 않는다. 경계의 old/new 실제 소비 비율을 기록한다.

## 3. 다섯 DR의 전체 범위와 적용 계약

밀기 값은 선행 코드 기반 프로젝트 제안이다. [범위표 §3](../../../_out/reports/DR-RANGES-EX40-1030.md)의 논문·코드 비교와 한계를 함께 읽는다. 힘 N과 속도 변화 m/s를 같은 숫자로 비교하지 않는다. 각 축 독립 표집이므로 D 평면 최대 변화량은0.707m/s이며 방향각 균일 표집은 아니다.

밀기는 reset에서 로봇을 치지 않는다. 자연 reset에서 해당 env의 강도·다음 interval 상태를 정하고 에피소드 중 timer에 따라 발생시킨다. 0배율일 때 실제 변화량0이어야 한다. 자연 reset마다 타이머를 다시 뽑는지, 이어받을 때 남은 시간을 어떻게 복원하는지 카드와 영수증에 고정한다. 실제 적용된 env·시각·배율·전후 속도·PhysX 읽기를 남긴다.

## 4. 저장·평가·재개

- 저장: m0,50,…,8000 총161개 번호. 파일 존재만으로 완성으로 보지 않고 저장 완료 manifest와 SHA를 대조한다.
- 그림자 평가: m250,500,…,8000 총32개. 같은 cp의 중복 소비 방지. 평가가 늦게 도착해도 원래 cp·stage에 귀속하고 끝까지 배출한다.
- GPU: 학습 GPU0, 평가·촬영 GPU1에서 하나씩. 이 초안은 학습 기동 명령이 아니다.
- 결과: 모드×명령×지형×레벨별 분모·생존·추종, 발별 정지 간격·힘·발 위상·관절·기울기, 학습 곡선, 실제 지도 소비·지도 오차, 1배속 영상. 새 DR은 배율·물리값·지연 hist·밀기 회복을 추가한다. 미수집은 미측정으로 둔다.
- 재개: 같은 실행의 policy·perception·두 optimizer·adaptive lr·std·RNG·지형·stage·B1시작·AdaSmpl·지도 상태·DR 명목 배열·환경별 배율·timer 복원. 새 물리 환경 때문에 궤적이 완전히 이어진다고 주장하지 않는다.
- 남은 갱신: `8001−(N+1)`. m3000에서 재개하면5000갱신이 남는다. 저장 경계·재개 첫 회의 실제 인자를 대조한다.
- 마감: 총8001갱신이 주 목표. 29초/갱신 예산이면64.45시간+24시간 여유=88.45시간은 계산이며 실측이 아니다. 시작 뒤50회 실측으로 끝 시각과 여유를 다시 보고한다(M77).

## 5. 구현자가 닫아야 할 칸

1. 모든 consumer의 stage8개·D/T0 경계·max_iterations8001·최종8000 일치.
2. 다섯 DR 실제 적용과 잡음1배 고정. reset 반복 후 COM·모터 범위 누적이 없고 env_ids 밖은 안 바뀌는 답 아는 CPU 시험 및 짧은 Kit.
3. 설정7.5ms와 실제 delay histogram의 관계. 현재 round 구현의10ms 표본 허용은 ‘7.5ms 상한’과 다르다.
4. 그림자 점수 지연·누락·FAIL/HOLD를 보존하며 fixed 단계 제어와 분리. 최종 T0점수까지 기록.
5. runner 기존 카드의 최대6000·5단계·arm/승급 미결 문구를 이 초안과 최신 결정으로 교체. 코드가 v8이라는 이유로 옛 카드가 갱신됐다고 보지 않는다.
