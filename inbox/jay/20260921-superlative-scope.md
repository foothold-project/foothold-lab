# 최상급에 범위를 강제하는 관문 · **만들어 보고 안 쓰기로 했다**

> 분류: 운영
> 작성: Claude 세션 (오흥재 지시) · 2026-09-21
> 근거: 오늘 두 세션이 낸 여덟 건 · 판정문 다섯 장에 린트를 시제로 돌린 실측
> 요지: 린트는 **오검출 70 %** 라 못 쓴다. 대신 **이미 있는 관문(검증 회차)이 다섯 건을 다 잡았다** · 그 관문에 조항을 «명시» 하는 것이 답이다
> 상태: 확정
> 판: v1.1

## 0. 무엇이 문제였나

2026-09-21 하루에 **두 세션이 같은 부류로 여덟 번** 걸렸다 · **범위를 안
밝힌 최상급**.

```
내가 낸 것 다섯
  「D 의 8/9 가 최고」                 -> nvidia-zero 가 9/9 다
  「회전 네 칸을 다 넘은 판이 없다」     -> 원본은 넘는다
  「v2b 가 «첫 판» 이다」              -> v2a 3000 도 한 점에서는 같다
  「F 가 3 칸으로 가장 낮다」           -> v1 0 · control 1 · 둘이 2 다
  「열 판 전부 0」                    -> 셋이 0 이 아니었다

리드가 낸 것 셋
  「전방 0.8 m 가 아쉽다」 · 「격자가 성기다」 · 「신호가 잡음보다 작다」
```

**여덟 번이면 사람 탓이 아니라 자리 탓이다.** 그래서 리드가 **「최상급에
비교 범위를 괄호로 강제하는 규칙」**을 제안했다.

## 1. 만들어서 돌려 봤다 · **오검출 70 %**

판정문 다섯 장(`20260921-*/README.md` 등)에 시제 린트를 돌렸다.

| 무엇을 잡나 | 결과 |
|---|---|
| 최상급 어휘가 든 줄 | **61** |
| 그중 «범위 표시가 없는» 줄 | **43 (70 %)** |

**어휘를 좁히고 범위 표현을 넓혀도 70 % 아래로 안 내려갔다.** 남은 것이
대부분 거짓 양성이다.

```
| ... | 최저 성분 |                     <- 표의 «열 이름» 이다
**가장 크게 빗나간 것은 rails 다.**       <- 범위가 «바로 위 표» 다
| 원본 · D · E · G | 전부 19.98 초 |     <- 사실 보고
「처음」 · 「유일한」 · 「가장」은 범위를    <- 규칙을 «설명하는» 줄이 자기를 문다
```

**까닭은 구조적이다** · 판정문에서 최상급의 범위는 **바로 위 표**에 있는
일이 많고, 린트는 한 줄만 본다. 표까지 읽는 린트는 못 짠다.

> **70 % 로 우는 관문은 하루 만에 꺼진다.** 그러면 없는 것보다 나쁘다 ·
> 「관문이 있다」고 믿게 되기 때문이다. **그래서 안 만든다.**

## 2. **이미 있는 관문이 다섯 건을 다 잡았다** `확인됨`

돌아보면 **내 다섯 건 중 «새어 나간» 것이 하나도 없다.** 전부
`codex exec --model gpt-6-astra` 검증 회차에서 잡혔다.

| 언제 | 무엇 | 잡은 것 |
|---|---|---|
| 축 2 판정 v1.3 | D 8/9 가 최고 | astra |
| 축 2 판정 v1.3 | 회전 넷 다 넘은 판 없음 | astra |
| NVIDIA 판정 v1.2 | v2b 가 첫 판 | astra |
| 축 2 판정 v1.8 | F 가 가장 낮다 | astra |
| NVIDIA 판정 v1.1 | 열 판 전부 0 | astra |

**관문이 없는 것이 아니라 «조항이 안 적혀 있었다».** 내 검증 프롬프트는
「`확인됨` 이 붙었는데 확인 안 된 것」은 적어 두었지만 **「최상급의 범위」는
따로 안 적었다.** 그런데도 다섯 번 다 잡혔다 · astra 가 원자료를 열어 보기
때문이다.

## 3. 그래서 무엇을 바꾸나 · **조항을 명시한다**

검증 프롬프트에 고정으로 넣는다. **그대로 복사해 쓴다.**

```
N. 최상급에 «비교 범위» 가 문장 안에 있는지 보라.
   「가장」 「최고」 「최저」 「유일한」 「첫」 「아무도」 「한 번도」 「전부」.
   범위가 없으면 «어느 집합에서» 인지를 물어라.
   특히 아래 여섯을 빠뜨렸는지 확인하라.

     1. NVIDIA 원본            (우리가 손대기 «전» · 축 2 는 9/9 다)
     2. foothold-v1            (배포본 · 축 1 기준선)
     3. 석헌 판들              (rails10 2950·3000 · control 3000)
     4. 같은 판의 다른 체크포인트  (네 점을 재 놓고 한 점만 쓰는 일)
     5. 같은 설정·같은 규모로 «성공한» 외부 사례
     6. 우리 «기존 실측» 중 반례   (특히 극단값 두 칸)
```

**이름으로 적는 것이 요지다.** 내 다섯 건 중 **셋이 1 번(원본)을
빠뜨린 것**이고 하나가 4 번이었다.

**5 · 6 번은 리드가 보탰다** `전해 받음`. 내 넷은 전부 **저장소 «안»**
의 비교 대상인데, 리드의 오늘 세 건은 그 바깥에서 났다.

```
「전방 0.8 m 가 아쉽다」   빠뜨린 것: 같은 격자로 «성공한» 외부 연구 (MARG)
「격자가 성기다」          빠뜨린 것: 같은 10 cm 로 성공한 외부 연구 (Hwang)
「신호가 잡음보다 작다」    빠뜨린 것: «우리 실측» 안의 반례
```

**6 번이 제일 싸고 제일 비쌌다** · 리드 말로는 반례가
`sim/eval/results/maindata-v1` 안에 있었고 **읽는 데 2 분**이었다.

### 3-1. 5 번이 지금 우리 문서에 걸리는 자리

**`stepping_stones`** 다. 우리는 「열 판 중 아무도 안 넘었다」까지만
적었고 그 범위는 맞다. **그러나 5 번을 대면 물음이 하나 남는다** ·
**같은 지형을 «넘은» 외부 사례가 있나.** 우리는 **모른다** `미확인` ·
논문을 안 찾아봤다.

**지금 문서가 틀린 것은 아니다** (범위를 우리 판으로 적었다). 다만
**「아무도 못 건넌다」로 넓히면 바로 5 번에 걸린다.**

### 3-2. **6 번을 내 것에 대 봤다 · 바로 걸렸다** `확인됨`

말로만 두지 않고 내 가장 센 주장(「`wz +1.00` 은 F 하나만 넘었다」)에
6 번을 댔다. 그 표의 **행 목록을 내가 손으로 적었으니** 빠뜨린 판이
있으면 주장이 통째로 무너진다.

```
probe_manifest.json 이 있는 폴더   23
내 표에 넣은 것                    18
빠진 것                             5
```

**다섯이 빠져 있었다.** 열어 보니 전부 `*-videos/axis2/` 아래의
**`num_envs 1` 촬영본**이었다 (성적의 정본은 **env 64** 다). 그중
`nvidia-zero` 촬영본은 `wz +1.00` 을 0.855 로 넘는데, **원본은 이미
표에 있으므로** 주장은 안 바뀐다.

> **결과적으로 틀리지 않았다. 그러나 «맞는 줄 몰랐다».** 목록이 맞은
> 것은 내가 확인해서가 아니라 **그렇게 타이핑했기 때문**이다.

**그래서 도구가 대신 세게 했다** · `--matrix` 가 이제 저장소를 훑어
**`num_envs 64` 인 판을 하나라도 빠뜨렸거나 `num_envs 1` 이 섞였으면
먼저 찍는다.**

```
행 목록 점검 · env 64 판 18 개를 빠짐없이 담았다
```

돌연변이로 확인했다 · 촬영본을 끼우면 **「섞여 든 것 (촬영본, env 1)」**,
`D` 를 빼면 **「빠뜨린 것 · command-baseline/D」** 가 뜬다.

**6 번이 싸다는 리드 말이 맞다** · 이 점검에 2 분 걸렸고, 찾은 것은
「오류」가 아니라 **「확인 안 된 전제」**였다.

## 4. 쓰는 쪽에서도 하나

**최상급을 쓸 때 괄호로 범위를 «먼저» 적는다.**

```
안 좋다   D 의 8/9 가 최고다
좋다      D 의 8/9 가 최고다 (추가 학습한 판 중 · 원본은 9/9)
```

**규칙이 아니라 습관 쪽이다.** 관문이 이미 잡고 있으므로 이것이 줄이는
것은 «샌 오류» 가 아니라 **«고치는 회차»** 다. 오늘 그 회차가 판정문마다
세 번에서 다섯 번이었다.

## 5. 안 한 것

- **린트를 안 만들었다** (1 절). 만들 수는 있는데 70 % 로 운다
- **`docs/` 를 안 고쳤다** · 이 문서는 `inbox/jay/` 제출물이다
- 리드 쪽 셋은 **내가 안 봤다** · 부류가 같다는 것은 리드가 적은 것이다
