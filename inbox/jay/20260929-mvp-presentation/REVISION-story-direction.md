## 1. 무엇을 잘못 이해했는가

초안은 키워드와 주제를 나눴지만 연구 판단의 연결을 잃었다. ‘무엇이 실패했나, 왜 그 문제를 먼저 골랐나, 무엇을 바꾸었나, 어떤 결과와 새 문제가 나왔나’가 빠져, 성능 그래프 앞에 방법을 나열해도 개선 이유를 따라가기 어려웠다. 브릿지 대사만으로 메울 수 있는 문제가 아니다.

기획 발표의 실패 중심 접근을 이어받아야 한다. 같은 로봇과 같은 지형의 변화가 다음 장면의 질문을 만들도록 연출해야 한다. 빈 자료 상자와 반복되는 두 칸 배치에 이미지만 채우는 수준의 수정을 하지 않는다. 기술 정보는 생략하거나 용어만 추가하는 대신 관측·행동·학습의 실제 관계를 보여준다.

## 3. 도입에서 연구 출발점까지의 연결

### 발표자의 인사와 정서

프로젝트명과 팀장 오흥재 소개. ‘아기가 한 걸음씩 배워 세상에 나아가도록 돕는 아빠의 마음’은 발표자의 마음을 전하는 말로 사용한다. 앞서 삭제했던 아기 비유는 최신 사용자 의도에 따라 복원한다. 이후 NVIDIA 사전학습 출발점을 명시해 scratch 학습과 혼동하지 않게 한다.

### 오프닝과 엔딩 한 시퀀스

| 장면 | 화면 | 연결·정지 지점 |
|---|---|---|
| 어둠 | 연기·불분명한 공간·위험을 암시하는 환경음 | 발표자의 인사 뒤 재생 시작 |
| 탐색 | 한 줄기 빛이 움직이며 바닥과 장애물을 드러냄 | 불필요한 자막보다 공간 인지 우선 |
| 임무 | 멀리 빨간 점등, 목표와 필요한 작업을 HUD로 표시 | 무엇을 하러 가는지 이해 |
| 등장 | Go2가 프레임에 들어오고 지형 앞에 섬 | 목표와 로봇이 같은 화면 안에 존재 |
| 첫걸음 | 발을 들어 첫 디딤 | 여기서 컷. ‘FOOTHOLD의 첫걸음을 함께 시작하겠습니다’ |
| 엔딩 회수 | 같은 공간과 목표를 향해 주행·탐험 | 연구 성과와 남은 일을 설명한 뒤 미래 활용 장면으로 재생 |
| 임무 완료 | MISSION COMPLETE와 목표 상태의 변화 | 성과 시연과 혼동하지 않는 개념 영상 표시 |
| Q&A | 마지막 공간 또는 Go2 정지 화면, 질문 안내와 보고서 링크 | 재생이 계속되지 않는 안정된 마무리 |

미래 장면은 현재 미경험 험지 실기 통과를 입증하는 자료가 아니다. 엔딩 전 발표 멘트와 화면 표식으로 구분하면 사용자의 임무 완료 연출을 살리면서 성과를 정확히 전달할 수 있다.

### 배경과 선택

큰 험지 이미지에서 경사·틈·폭·표면의 다양성을 먼저 본다. ‘미경험’은 학습에서 경험한 조건과의 관계로 정의한다. 재료 강도·마찰·미끄러움의 다양성을 설명하되 이번 MVP가 모든 변수를 검증했다고 말하지 않는다.

같은 현장에 여러 이동 로봇을 보여주며 선택을 묻는다. 다음 클릭에서 각 로봇이 맡을 임무와 경로로 움직인다. 지면 가까이에서 반복 수행할 작업과 불연속적인 디딤 공간이라는 조건으로 사족 보행 연구에 집중한다. 산양은 이 직후 한 컷으로 보완하는 위치를 제안한다. 동물의 능력 자체가 로봇의 우수성을 입증하지는 않는다.

소방·위험 현장의 공공 수요를 먼저 보여주고, 산업 점검에서 반복 점검을 로봇이 맡고 사람이 수리에 집중하게 된 전후 변화를 다음에 제시한다. 두 사례가 서로 다른 임무임을 드러낸다. 그 뒤 오늘 발표의 문제·방법·성과·남은 과제를 안내한다.

| F | 187개 height scan 입력을 묶어 이동 | 어떤 공간의 값인지 연결선으로 유지 |
| G | 몸 상태, 명령, 이전 행동의 48개 입력 구분 | 명령은 지시, 관측은 상태라는 구분 |
| H | actor MLP 입력·은닉층·출력 흐름 | 로봇을 지우지 않고 옆에 유지 |
| I | 12개 출력이 실제 관절 위치 목표로 연결 | 각 다리와 출력의 정확한 대응 |
| J | 움직임과 다음 관측, 환경에서 계산한 보상 | 실행의 반복 구조 |
| K | critic과 PPO 갱신 경로를 추가 | critic이 12개 관절 명령을 출력하는 오해 방지 |
| L | 카메라가 빠져 여러 환경과 4096개 병렬 경험을 보여줌 | 앞서 본 로봇이 환경 하나였다는 관계 |

A~L은 슬라이드 수가 아니다. 하나의 장면에서 클릭으로 전환할 상태다. 뒤로 넘길 때도 정확한 상태로 돌아가야 한다. 설명 중에는 현재 상태를 멈출 수 있어야 한다. 신경망의 전체 연결선을 쏟아내기보다 512·256·128 규모와 실제 역할을 읽을 수 있게 표현한다. 강조 애니메이션은 데이터 흐름의 개념 표현이며 실제 뉴런 활성 측정으로 표시하지 않는다.

현재 187개 scan은 실제 LiDAR에서 바로 흘러오는 값이 아니다. 시뮬레이션 ray casting이다. 실제 센서 소개에서 시뮬 관측으로 전환하는 상태 D가 이 차이를 설명한다. 12개 출력은 관절 위치 목표이며 토크 직접 출력과 구분한다.

Manim은 수치·연결·학습 경로 같은 정확한 모션 후보다. Go2의 실제 관절과 분해는 사용 가능한 USD/URDF/메시 기반 제작을 우선 검토한다. 생성 이미지·영상은 장면의 분위기와 개념 컷에 쓸 수 있으나 관절 수나 센서 위치를 임의로 바꾸지 않는다.

이는 사용자가 전달한 핵심 계보를 보존한 인과적 설명 순서다. 실제 변경 시점·체크포인트 계보와 일치시키는 작업은 별도로 필요하다. 버전별 결과를 이어 설명하는 것과 가중치를 순서대로 resume했다는 주장은 다르다. 각도·비율·성적은 확인된 실행 기록을 사용한다.

### 대조한 사실과 남은 확인

- `확인됨`: 기존 기획 발표 6~9장은 실패 중심 접근, 평지 기준선, 미경험 10종, 낙상·전진불능 구분을 담고 있다. 11장은 다섯 레시피 탐색이다. 이번에 원문을 다시 읽었다. 당시 수치의 원시 로그를 이번 턴에서 재계산한 것은 아니다.
- `확인됨`: `sim/policy/gap_env_cfg.py`는 forward_gap 비중 0.10, 횡이동·yaw 명령 0을 설정한다. v1의 실제 실행 조건과 성적은 대응 기록으로 함께 표시한다.
- `확인됨`: `gap_f_env_cfg.py`는 omni_gap, heading 범위 ±pi, yaw rate 범위 ±1 rad/s를 설정한다. 사용자 언급 ‘xz ±23도’의 정확한 대상 설정은 아직 미확인이다. 각도와 각속도를 섞지 않는다.
- `확인됨`: 정지 표본 0.1은 명령 표집 비율이다. 모든 환경이 정확히 10% 시간 동안 서 있다는 뜻으로 바꾸지 않는다.
- `확인됨` 및 앞선 설명 정정: 로컬 Isaac Lab HEAD `37ddf62`의 기본 `height_scan`에는 ray miss를 별도 처리하는 분기가 없다. `observations.py:292~300`은 센서 높이에서 hit z와 offset을 뺀다. `utils/warp/ops.py`는 miss 위치를 inf로 둔다. 기본 velocity 설정은 scan을 [-1,1]로 자르므로 이 경우 -inf가 -1이 된다. 우리 `sim/policy/gap_observations.py:16`은 유한값 검사를 추가해 miss를 +1로 바꾸고 `gap_env_cfg.py:38`에서 사용한다. 원본 observations.py와 ops.py는 해당 HEAD 대비 로컬 변경이 없음을 확인했다. 관측 처리 보완과 학습 경험 추가를 모두 발표에 포함한다. 모든 구멍은 ray miss라는 뜻은 아니며, 바닥에 광선이 닿지 않는 경우에 대한 설명이다. NVIDIA 전체 버전이나 과거 배포 당시 소스 해시까지 같은지는 이번 대조로 확정하지 않는다.
- `미확인`: gap 선택이 유일하게 합리적인 선택이었다는 주장. 당시의 근거와 가설에 따른 첫 선택으로 설명한다.

## 7. 이야기를 따라 걷는 Go2: 추가 피드백

사용자는 할머니의 옛이야기처럼 다음 이야기가 자연스럽게 이어지는 발표를 강조했다. 기술 정보의 깊이를 유지하면서 앞 장면의 관찰과 질문이 다음 실험의 이유가 되게 구성한다. 예를 들어 ‘어디서 실패했나 → 왜 gap부터인가 → 무엇을 바꿨나 → 무엇이 나아지고 무엇이 어려워졌나 → 다음에 무엇을 바꿨나’가 한 과정으로 이어져야 한다. 순서대로 일어난 일이라는 이유만으로 원인 관계를 단정하지는 않는다.

사용자 결정: 하단 발자국 표시를 대신해 우측 상단에 Go2가 작은 지형 경로를 따라 이동하는 진행 표시를 둔다. 첨부 그림의 여섯 구간과 지형선은 아이디어 설명용이다. 그림의 크기·문구·모양을 그대로 구현하라는 뜻은 아니다. 픽셀 애니메이션 또는 험지 느낌의 표현은 후보로 남긴다.

최신 사용자 정정: Go2 그림의 위치만 바꾸는 표시가 아니다. 픽셀 Go2가 다리를 움직이며 실제로 지형을 걷고, 틈을 넘고, 경사를 오르는 애니메이션을 원한다. 각 지형에 맞는 발 디딤과 몸통 움직임이 보여야 한다. Nano Banana 등으로 픽셀 원화를 만들고 동작 프레임이나 sprite-gen을 조합하는 방법은 제작 후보이며 도구는 미확정이다. 재생을 페이지 전환 순간에만 제한하는 앞선 제안도 확정하지 않는다. 설명 중에도 작은 영역에서 자연스러운 이동을 보여줄 수 있다. 구간 전환 때만 턱·경사에 대응하는 동작을 주며, 현재 구간명을 읽을 수 있게 표시한다. 본문 안에서 관측과 신경망을 설명하는 클릭마다 이동하지는 않는다. 이전 화면·임의 페이지 이동도 해당 위치로 복원한다. 전체 화면 영상에는 숨기고, PDF와 동작 줄이기 설정에는 정지 상태를 쓴다. 과제 구간은 발표 목차이며 실제 학습 성과의 지도는 아니다.

Star 목록에서 아래 후보를 찾아 9월 30일 저장소 README를 직접 열었다. 설치나 생성은 하지 않았다. 사용자가 기억한 특정 저장소가 무엇인지는 미확인이다.

|---|---|

## 8. 다음 제작의 순서

1. 전체 지도를 유지하되 첫 페이지부터 순서대로 말·그림·움직임·다음 장면의 연결을 제작하고 함께 확인한다. 첫 묶음은 표지와 인사, 오프닝, 첫걸음에서 본론으로 전환이다. 후반부 추가 설명은 계속 반영한다. 전체를 다시 일괄 제작하지 않는다.
2. Go2 관절·센서·관측·actor·critic·출력의 연속 장면은 해당 순서에 도달했을 때 앞 장면과 함께 제작한다. 어려운 자산의 가능성 확인은 앞서 할 수 있다.
3. 실패 분류에서 gap 선택·명령 변경·omni_gap까지의 실제 증거를 같은 방식으로 연결한다.
4. 오프닝과 엔딩은 같은 공간·기체·목표를 공유하는 컷 설계로 준비하고 Higgsfield MCP로 제작한다. 제작 전 필요한 참조 자산과 실제 모델의 조건을 맞춘다.
5. 정해진 시각 표현을 다른 장면에 확장한다. 기존 34개 화면에 사진만 채우는 작업으로 돌아가지 않는다.

사용자는 9월 30일 제공 이미지와 팀 기체가 동일하며 Orin NX 16GB, D435i, HESAI-360을 추가 보유한다고 답했다. 이미지의 기본 LiDAR 표기는 L2다. 사용자 확인과 이미지 표기에 따른 구성으로 기록하며, 실물 개체를 직접 검사한 결과는 아니다. 모듈 영상과 근거의 범위는 [Go2 장비 참고 기록](GO2-HARDWARE-REFERENCE.md)에 남겼다. 현재 장착·연동 여부는 미확인으로 두고 장면 설계는 진행한다. 발표 시간은 아직 미확정이므로 전체 장수와 각 영상 길이를 확정하지 않는다.
