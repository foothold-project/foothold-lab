## 0. 지도와 제작물의 관계

여섯 큰 목차는 유지한다. 각 목차 안의 세부 주제를 먼저 정하고, 주제마다 전달할 주장과 근거가 확보되면 화면으로 나눈다. 세부 주제 하나가 반드시 슬라이드 한 장이라는 뜻은 아니다. 한 장에서 단계를 나눠 설명할 수도 있고 두 장으로 분리할 수도 있다.

앞선 28장에서는 학습 출발점과 resume, 명령·보상·관측의 역할, 평가 지표의 해석, 실기·항법과의 연결이 압축되어 있었다. 이를 본문에서 설명할 자리를 확보한다. 현재는 본문 35~40장 안팎을 작업 범위로 열어 두지만 최종 장수는 미확정이다. 발표 시간은 사용자에게 질문했으며 답변 대기 중이다.

슬라이드 수와 발표 시간을 같은 것으로 취급하지 않는다. 표지·목차·전환·한 장면을 보여주는 화면은 짧게, 결과와 한계를 설명하는 화면은 충분히 배정한다. 배경과 비유가 결과 설명을 가리지 않게 한다.

도입의 전체 목차는 여섯 제목만 보여준다. 각 구간 진입 시 그 구간의 세부 주제를 짧게 안내한다. 아래 상세 목차 전체를 발표 한 화면에 작은 글씨로 넣지는 않는다.

## 1. 위험한 현장과 이동 로봇의 역할

청자의 질문: 왜 이 프로젝트에 시간을 들여야 하는가?

| 세부 목차 | 전달할 내용 | 근거·시각 자료 | 범위 |
|---|---|---|---|
| 1.1 사람이 직접 들어가기 어려운 현장 | 위험한 바닥과 접근 경로가 점검·탐색의 제약이 된다 | 실제 현장 또는 개념 장면. 출처와 생성 여부 구분 | 본문 |
| 1.2 반복 점검과 사람의 역할 | 로봇의 측정과 사람의 판단·조치가 연결되는 업무를 보여준다 | AB InBev 사례의 실제 사진과 작업 흐름 | 본문 |
| 1.3 현장에서 확인된 운영상의 가치 | 숫자는 실제 사례의 범위 안에서 설명한다 | 주 1,800건 개별 점검, 첫 6개월 약 150건 이상 발견. 제조사 공개 사례라고 표시 | 본문 |

이 구간의 결론: 현장에 이동 로봇이 필요한 이유가 있다. 어느 이동 방식이 적합한지는 임무 조건으로 결정해야 한다.

국내 고령화와 특정 점검 직무 인력 부족의 직접 연결은 미확인이다. 근거 없이 본문 통계로 넣지 않는다. 기업 매출 추정이나 우리 프로젝트의 사업성 입증은 범위에 포함하지 않는다.

## 2. 사족보행을 선택한 이유

청자의 질문: 드론이나 바퀴가 있는데 왜 다리로 걸어야 하는가?

| 세부 목차 | 전달할 내용 | 근거·시각 자료 | 범위 |
|---|---|---|---|
| 2.1 임무와 이동 방식 | 점검 위치·반복 방문·탑재 센서·체류 시간·경로를 기준으로 비교한다 | 한 시설 공간의 공중 관찰과 지상 점검 경로. 드론의 지하 점검 가능성도 인정 | 본문 |
| 2.2 발을 들어 디딜 곳을 바꾸는 이동 | 다리를 쓰는 이동의 특징을 이해시킨다 | 좁은 발 디딤의 짧은 참고 장면, 로봇의 실제 발 움직임 | 본문 |
| 2.3 미경험 험지의 의미 | 학습에서 경험한 조건과 새로운 조건의 차이를 설명한다 | 지형 높이·틈·배치의 변화. 재난 여부만으로 정의하지 않음 | 본문 |
| 2.4 FOOTHOLD가 이번에 다룬 범위 | 전체 임무 중 현재 MVP가 보행 정책과 평가에 집중했다는 사실을 설명한다 | 인지·항법·보행의 역할을 구분하고 이번 검증 범위를 표시 | 본문 |

이 구간 끝에서 첫 발걸음 멘트와 발자국 전환을 사용한다. 사족보행이 모든 임무에서 우월하다는 주장은 하지 않는다. 반복 지상 점검은 적용 시나리오 후보이며 현재 MVP에서 수행한 산업 임무가 아니다. 항법이나 실기 결과는 확인된 자료가 없으면 완료로 표시하지 않는다.

## 3. 미경험 험지를 학습하는 방법

청자의 질문: 로봇은 무엇을 보고 무엇을 배우며, 잘 배웠는지는 어떻게 아는가?

| 세부 목차 | 전달할 내용 | 근거·시각 자료 | 범위 |
|---|---|---|---|
| 3.1 학습의 출발점 | NVIDIA 사전학습 정책을 바탕으로 추가 학습했다 | 기준선과 추가 학습의 관계. 처음부터 걸음마를 가르쳤다는 오해 방지 | 본문 |
| 3.2 명령·보상·정책의 역할 | 무엇을 하라고 하는지, 결과를 어떻게 평가하는지, 행동을 무엇이 정하는지 구분한다 | 한 번의 행동과 업데이트를 단계적으로 보여주는 도식 | 본문 |
| 3.3 현재 정책의 관측 | 몸 상태뿐 아니라 명령·이전 행동·height scan도 입력한다 | 실제 height scan 그림. 앞의 48개 입력을 전부 고유수용감각이라고 부르지 않음 | 본문 |
| 3.4 병렬 환경과 경험 수집 | 4096개 환경의 경험이 공통 정책 업데이트에 쓰인다 | 실제 학습 영상과 경험 수집 도식. 렌더 수와 실제 환경 수 구분 | 본문 |
| 3.5 학습 지형·명령·커리큘럼 | 경험할 상황을 만드는 설정이 학습 결과에 영향을 준다 | 전진·회전·정지 명령과 지형 배치의 관계. 초기 레벨과 최대 난이도 구분 | 본문 |
| 3.6 험지와 명령의 두 평가 축 | 지형 통과와 기본 명령 수행을 함께 평가한다 | 축1·축2 평가 장면. 성공은 생존·진행·추종·방향의 복합 판정임을 설명 | 본문 |
| 3.7 학습 지형과 미경험 평가의 구분 | 평가 16종 중 공통 미경험 8종을 따로 집계한다 | 기존 지형 자료와 학습 포함 여부. rails와 gap을 미경험 8종에 섞지 않음 | 본문 |

resume은 3.1에서 학습을 이어가는 출발점을 설명하는 데 필요한 수준으로 다룬다. 전체 optimizer 상태 복원과 가중치 재사용은 같은 말이 아니므로 상세 조건은 부록으로 둔다. 설계 변경 실험의 순서를 가중치가 차례로 전달된 계보로 그리지 않는다.

3.2~3.5에서 새 개념을 한꺼번에 제시하지 않는다. 명령 하나를 받은 로봇이 행동하는 사례를 이어 사용하면 연결을 이해하기 쉽다. 아기 걸음마는 한 문장 비유 후보이며 별도 슬라이드를 만들지 않는다.

## 4. MVP에서 개선한 보행과 실험 결과

청자의 질문: 실제로 무엇을 바꾸었고 어떤 증거로 개선을 말하는가?

| 세부 목차 | 전달할 내용 | 근거·시각 자료 | 범위 |
|---|---|---|---|
| 4.1 기준선에서 발견한 어려움 | 추가 학습이 필요한 이유를 실제 평가에서 보여준다 | NVIDIA의 특정 지형 결과와 조건이 맞는 영상 | 본문 |
| 4.2 첫 개선 모델에서 얻은 것 | 큰 험지 성능 향상이 v1 단계에서 이미 나타났다 | 동일 조건의 기준선·v1 결과 | 본문 |
| 4.3 전진 성능만으로 드러나지 않은 문제 | 정지와 회전을 따로 평가하자 제한이 나타났다 | 명령 전환 시점이 보이는 실제 영상. 낙상과 명령 추종을 구분 | 본문 |
| 4.4 명령 설정 변경과 성능 변화 | 설정 변경 과정에서 gap 성능이 낮아지는 현상을 보았다 | v1·D 비교. 여러 필드 변경임을 표시. 드문 실패 컷을 평균처럼 사용하지 않음 | 본문 |
| 4.5 v2에서 조정한 학습 조건 | 지형 배치, 명령, 정지 표본 등 여러 요소를 조정했다 | forward_gap·omni_gap 실제 형태와 설정의 역할 | 본문 |
| 4.6 같은 속도에서의 미경험 지형 결과 | 먼저 1.0 m/s의 비교를 제시한다 | 원자료 재계산 NVIDIA 62.0%, v1 87.4%, v2 90.5% | 본문 |
| 4.7 속도에 따른 차이 | 세 속도의 결과와 평균을 함께 본다 | 평균 43.9%, 86.7%, 88.5%. NVIDIA의 1.5 m/s 학습 범위 밖 조건 표시 | 본문 |
| 4.8 통과·감속·낙상을 구분해서 보기 | 성공률만으로 실제 행동을 오해하지 않게 한다 | 같은 조건 영상과 필요한 지표. 0% 성공을 100% 낙상으로 번역하지 않음 | 본문 |
| 4.9 기본 명령 응답에서 개선된 부분 | 정지 응답 개선을 해당 측정 조건 안에서 설명한다 | v1·v2와 NVIDIA의 같은 프로브 결과. 64환경과 1024환경 측정을 섞지 않음 | 본문 |

실험 레시피 이름을 전부 발표하지 않는다. 문제·가설·변경·관측 결과가 이야기의 단위다. 원인 분리가 없는 비교는 현상과 해석을 구분한다. v2의 평균 향상을 v1에서 이룬 향상까지 모두 합쳐 설명하지 않는다.

숫자 선정과 계산 조건은 STORYBOARD.md의 4절에 기록했다. 새 모델이나 새 실험 결과가 추가되면 현재 비교에 섞기 전에 모델·조건을 다시 맞춘다.

## 5. 아직 해결하지 못한 과제

|---|---|---|---|
| 5.1 회전과 명령 판정의 남은 기준 | 축2의 8/9는 정지·유지·회전 관련 9개 판정 기준이며 범용 능력 완성이 아니다 | 판정표와 기준선 9/9. 현재 부족한 항목을 실제 자료로 표시 | 본문 |
| 5.2 디딤돌 지형과 시드별 변동 | 특정 시드의 높은 값으로 안정적인 통과를 말할 수 없다 | 실패 영상과 1.0 m/s 다섯 시드 24·1·3·19·0% | 본문 |
| 5.3 평가가 더 필요한 행동과 조합 | 횡이동·후퇴·외란·험지 회전 등 검증 범위를 넓혀야 한다 | 측정됨·미측정·평가 조건 추가 필요를 구분. 구현 유무는 제작 때 실제 하네스와 대조 | 본문 |
| 5.4 시뮬레이션과 실제 임무 사이 | 현재 증거가 시뮬레이션 보행 평가라는 점을 정리한다 | 관측·구동·안전·항법 연결에서 실기 확인이 필요한 조건 | 본문 |

못하는 장면을 나열하는 데서 끝내지 않고, 각 제한이 다음 절의 어떤 실험 질문으로 이어지는지 연결한다. 신경망의 용량 부족이나 height scan의 부족을 원인으로 확정하지 않는다.

## 6. 최종발표까지의 다음 단계

청자의 질문: 다음에 무엇을 바꾸며 어떻게 성공 여부를 판단할 것인가?

| 세부 목차 | 전달할 내용 | 근거·시각 자료 | 범위 |
|---|---|---|---|
| 6.1 지형을 실제로 만나게 하는 과제 | 목표·경유점으로 험지 통과 경험을 만드는 실험을 제안한다 | ㄷ자 경로와 경유점. 직선 거리만 보상할 때의 지름길 문제 설명 | 본문 |
| 6.2 기본 명령을 함께 유지하는 학습 | 목표 도달과 정지·회전·저속 등의 요구를 함께 설계한다 | 험지 과제와 기본 명령 과제의 관계. 어떤 혼합이 효과적인지는 미측정 | 본문 |
| 6.3 관측과 신경망의 비교 실험 | 지형 정보의 표현과 시간 이력이 도움이 되는지 확인한다 | 현재 구조와 후보 구조. 더 큰 신경망으로 해결된다고 단정하지 않음 | 본문 |
| 6.4 다음 모델의 평가 기준 | 여러 시드에서 험지·명령·결합 조건을 평가하고 이전 능력 유지도 확인한다 | 확장 평가표. 결과를 본 뒤 유리한 문턱을 정하지 않음 | 본문 |
| 6.5 실기와 전체 시스템으로 연결 | 보행 평가 이후 인지·항법·실기 연결에 필요한 조건을 제시한다 | 선행 조건을 둔 연결도. 현재 팀의 확정 일정과 완료 상태는 별도 대조 | 본문 |
| 6.6 다음 일정과 현장으로의 복귀 | 확인한 성과, 다음 실험, 최종 목표를 구분하고 처음 현장으로 돌아간다 | 완료·계획이 다른 일정과 미래 발자국. 보고서 QR 및 마무리 | 본문 |

다음 연구의 후보는 이미 수행한 실험과 시각적으로 구분한다. 특정 논문 구조를 그대로 채택하기로 결정된 것은 아니다. 목표점 과제, 관측, 신경망 중 하나가 다른 둘을 대체하지 않는다.

## 8. 애니메이션 도구를 선택하는 기준

도구 조사와 내용 설계는 병행하되, 도구의 기능 때문에 목차를 바꾸지 않는다. 먼저 정적 화면만으로도 주장과 근거가 이해되도록 설계하고, 움직임이 이해를 돕는 자리에 적용한다.

| 설명 목적 | 필요한 움직임 |
|---|---|
| 발표 진행 위치 | 구간 전환 시 기존 발자국 표시 |
| 한 번의 행동과 학습 | 관측·명령·정책·행동·업데이트를 발표자 조작에 맞춰 순차 표시 |
| 병렬 경험 수집 | 여러 환경의 경험이 공통 정책 업데이트로 모이는 흐름 |
| 설정 변화 | 실제 지형 배치와 명령 조건을 비교하며 변화 지점만 강조 |
| 결과 비교 | 동일한 축에서 모델별 결과를 순차 표시 |
| 다음 단계 | 현재 완료와 계획을 구분하고 선행 조건을 따라 진행 |

도구 도입 시 확인할 것: 기존 HTML의 전체화면·단축키·직접 페이지 이동을 유지할 수 있는지, 앞뒤 이동 시 상태가 올바른지, 영상 재생과 충돌하지 않는지, PDF에는 모든 핵심 정보가 정적으로 남는지, 생성물이 편집 가능하며 팀이 유지할 수 있는지.

Star 저장소 조사: 사용자 요청에 따라 Luna가 현재 연결 계정 `vfxpedia`의 저장소를 읽기 전용으로 조사한다. 별도 이슈 [#503](https://github.com/foothold-project/foothold-lab/issues/503). 목록은 197개로 확인했다. 사용자가 언급한 후보는 [heygen-com/hyperframes](https://github.com/heygen-com/hyperframes)로 확인했으며, 공식 README는 HTML·CSS·미디어와 시간 위치를 지정할 수 있는 애니메이션을 MP4로 렌더하는 프레임워크라고 설명한다. 기존 발표 조작과의 통합 적합성은 아직 미확인이다. 설치·clone·실행·도입을 승인한 것으로 확대하지 않는다. 결과는 `STARRED-REPOS.md`에 기록한다.

## 9. 다음 작업의 순서

1. 이 지도에서 누락·중복·연결이 약한 세부 주제를 검토한다.
2. 각 주제의 주장과 근거, 실제 영상·그래프를 대응시킨다.
3. 발표 시간에 맞춰 화면을 나누고 STORYBOARD.md를 갱신한다.
4. 내용과 구도가 정해진 시각 자료부터 제작한다. 첫 키 비주얼을 후속 자산의 기준으로 삼는다.
5. HTML에 발표 조작과 애니메이션을 적용하고 정적 PDF의 정보 보존을 확인한다.

문서나 이슈를 사용자가 따로 열어야 진행되는 방식으로 운영하지 않는다. 논의할 내용은 채팅에 제시하고 이 파일에 기록한다.
