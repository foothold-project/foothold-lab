## 차단 문제 · blockers

### B1. 1600×900보다 작은 브라우저에서 오른쪽·하단 내용 잘림

**우선순위 높음 · 확인됨.** 기존 1600×900 이미지에서는 정상처럼 보이지만, 새 브라우저를 1280×720 또는 1366×768로 열면 슬라이드가 오른쪽 아래로 밀린다. 5장 최종 단계의 오른쪽 디딤·재료 설명과 하단 범위 문구가 화면 밖으로 잘린다. 브라우저 창을 줄이는 경우에도 재현됐다.

재현: 해당 크기로 HTML을 열고 `#slide-5`로 이동한 뒤 두 번 다음을 누른다. `footholdDeck.show(4,2)`로 같은 상태를 지정해도 같다.

| 브라우저 CSS 픽셀 | 실제 슬라이드 경계 x / y / right / bottom | 결과 |
|---|---|---|
| 1280×720 | 160 / 90 / 1440 / 810 | 오른쪽 160px, 아래 90px가 창 밖 |
| 1366×768 | 117.33 / 66 / 1482.67 / 834 | 오른쪽 약 116.67px, 아래 66px가 창 밖 |
| 1920×1080 | 약 0 / 0 / 1920 / 1080 | 화면 경계 안 |

원인은 `design/deck.css:2`의 Grid 컨테이너와 `:3`의 고정 1600×900 슬라이드 조합이다. 작은 창에서도 자동 Grid 트랙은 1600×900으로 남고, `transform:scale(...)`는 배치 크기를 줄이지 않는다. `#viewport`의 `overflow:hidden`이 넘친 부분을 자른다.

원본을 건드리지 않고 브라우저 메모리에만 `#viewport{grid-template-columns:minmax(0,1fr);grid-template-rows:minmax(0,1fr)}`를 넣어 원인을 분리했다. 1280×720의 경계가 0 / 0 / 1280 / 720으로, 1366×768의 경계가 약 0.33 / 0 / 1365.67 / 768로 복원됐다. 이 선언은 수정 후보이며 저장소에 적용하지 않았다.

**해제 조건:** 공통 화면 배치를 수정한 뒤 1280×720·1366×768·1920×1080에서 첫 10장과 엔딩의 텍스트·영상 컨트롤·근거 링크가 창 안에 남는지 확인한다. 험지 `.content`의 top을 다시 고치는 문제와는 별개다.

### B2. 험지 두 장에서 요청된 우측 상단 진행 표시가 사라짐

**우선순위 보통 · 확인됨.** 최신 지시의 공통 화면 원칙은 우측 상단 픽셀 Go2와 지형 아래 진행 맥락 표시다. 4장 임무·5장 낯선 조건에는 헤더와 섹션명이 있지만 진행 표시는 없다.

`design/intro_story.css:12`에 `.terrain-slide .route{display:none}`가 있다. 최신 HTML의 두 장에서 `getComputedStyle(route).display`도 모두 `none`이고 새 화면에서도 보이지 않았다. 전체 영상의 몰입 화면과는 다른 설명 슬라이드이며, 의뢰 범위의 최신 지시에는 이 두 장을 공통 규칙에서 제외한다는 내용이 없다.

**해제 조건:** 이 두 장에서도 읽을 수 있는 진행 표시를 유지한다. 기존 CSS의 숨김을 해제하는 경우 어두운 사진 위 대비와 헤더 겹침까지 확인한다. 발표 재생 자체가 멈추는 오류는 아니지만, 요청된 공통 화면 체계의 완료 판정은 막는다.

## 선택 보강 · optional
