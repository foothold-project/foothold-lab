## 확인 범위

`확인됨` sim/eval/probe_go2_bodies.py는 Isaac 에셋 루트 아래 /Isaac/IsaacLab/Robots/Unitree/Go2/go2.usd 또는 /Isaac/Robots/Unitree/Go2/go2.usd를 LoadAll로 연다. sim/eval/probe_go2_joint_limits.py는 회전 관절 범위와 FL_thigh·FL_calf·FL_foot 변환을 읽는다. 저장소 파일 목록에서는 USD 원본을 찾지 못했다. 원본 내부 메시·텍스처·부품 분리 수준은 아직 미확인이다.

`확인됨` 이 PC에 Blender 4.5·5.2 설치 폴더가 있다. 현재 도구 목록에는 bl_* 연결이 없다. /Exploded-view 안내는 /use-blender 설치·연결 확인 후 로컬 MCP의 blender-camera-led-assembly 스킬을 사용한다. 워크플로 안내만 읽었으며 설치·연결·씬 편집 완료를 주장하지 않는다. 사용자의 이번 메시지는 활용 의견과 설계 질의이며 원본 씬을 덮어쓸 지시가 아니다.

## 클릭 단위 흐름

| 단계 | 보이는 내용 | 다음 단계로 잇는 요소 |
|---|---|---|
| 1 | 실물 비례의 Go2 정면, 짧은 턴테이블 후 정지 | 같은 기체·카메라·조명 유지 |
| 2 | 몸통과 네 다리의 절제된 분리, 한 다리의 3관절에서 전체 12관절로 강조 | 관절 식별점과 라벨 |
| 3 | 카메라·기본 센서의 위치 표시. 팀의 Orin NX 16GB·D435i·HESAI-360 추가 모듈은 별도 구성 | 실제 장비 사진·모듈 영상과 대조 |
| 4 | 동일 모델이 Isaac Sim 공간으로 넘어가고 48차원 몸 상태·명령·이전 행동 및 187 height scan 설명 | 실제 실행 설정으로 차원·항목 재확인 |
| 5 | 관측에서 Actor로 흐르고 12개 출력이 관절로 돌아감 | 출력이 곧 토크라는 표현을 피하고 실제 action scale·관절 목표·제어기를 확인 |
| 6 | 학습 시 Critic·보상·업데이트를 별도 경로로 공개 | Critic을 실기 제어 직렬 경로처럼 그리지 않음 |
| 7 | 같은 카메라가 빠지며 다수 환경과 하나의 정책 업데이트를 보여줌 | 4096 환경은 실제 구성·시뮬 자료로 확인 |

48+187 입력은 실물 카메라나 LiDAR의 원시 출력과 동일하지 않다. 센서 하드웨어 설명과 현재 시뮬 정책 관측을 분리한 뒤 연결한다. 모델에서 보이지 않는 내부 기어·액추에이터 구조를 실제 설계처럼 생성하지 않는다. 공인 제원 수치와 USD 물리 파라미터도 동일한 것으로 가정하지 않는다.

## 제작 산출물

원본 USD와 참조·payload·텍스처를 별도 수집하고 원본은 보존한다. 파생 .blend, 부품 목록·관절 대응표, 카메라·재질을 공유하는 구간별 영상, 정지 포스터 프레임을 만든다. HTML은 클릭할 때 다음 구간을 재생하고 다음 설명 위치에서 정지한다. 탐색·역방향 이동·발표자 메모와 충돌하지 않게 한다. 처음부터 긴 자동재생 한 편으로 고정하지 않는다.

## 다음 확인

USD 실제 경로·가져오기, 부품 계층·스케일·관절축·재질, 실제 센서와 추가 모듈 구성을 읽기 전용으로 확인한다. 실물 사진과 비교한 한 장의 분해 구도부터 검토한 뒤 애니메이션을 만든다. 영상·PPT의 승인된 브랜드 로고, 각도, 폰트 분위기, 슬로건을 유지한다.
