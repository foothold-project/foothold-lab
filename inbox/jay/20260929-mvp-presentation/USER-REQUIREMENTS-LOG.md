## 기록 원칙

사용자 요구는 대화 요약이나 새 디자인으로 대체해 지우지 않는다. 변경되면 원 요구와 변경 이유를 함께 남긴다. 아래 인용은 사용자 발언 중 핵심 구절의 원문이며, 전체 대화의 축어록은 아니다. 전체 요소별 반영표는 [수정 설계](REVISION-story-direction.md)에 있다. 제작 제안은 사용자 승인과 구분한다. 기록에 있다는 사실만으로 구현 완료라고 표시하지 않는다.

## 이전에 전달된 요구의 보존 위치

다음 항목들은 최신 요청으로 취소된 것이 아니다. 상세 내용은 수정 설계와 연결 문서를 함께 읽는다.

- 전체화면·단축키·직접 넘김·되돌리기와 발표자가 제어하는 애니메이션.
- 표지와 엔딩의 임팩트, 마지막 Q&A, 같은 공간·기체·목표로 이어지는 오프닝과 엔딩.
- 인사에서 팀장 오흥재 소개와 아기의 걸음마를 돕는 아빠의 마음. 어둠·연기·탐색광·붉은 목표 점등·임무 HUD·Go2 등장·첫 디딤에서 컷.
- 험지 이미지, 미경험의 의미, 임무별 이동 로봇 선택, 짧은 산양 이미지, 소방 공공 수요 뒤 산업 사례, 그다음 목차.
- 동일 Go2의 턴테이블·12관절·기본 센서와 추가 모듈, 같은 자세의 시뮬 전환, 187개 scan과 나머지 48개 입력, actor·critic·12개 출력·4096개 병렬 환경.

- NVIDIA에서 현재 모델까지의 개선 흐름, 지형과 명령 두 축, 낙상과 전진 불능의 구별, 해결한 과제와 남은 과제.

- 모든 것을 한 장에 몰지 않음. 외부 청자에게 불필요한 내부 사정·실험 ID는 줄이되 연구의 판단과 근거는 생략하지 않음.
- 실제 실험 결과와 생성 콘셉트 영상 구별, 수치·사례는 출처 대조, 미확인 사항은 미확인 유지.
- star 저장소·논문·시각 자료 조사 기록 유지. 특정 도구를 썼다는 이유만으로 시각적 완성도를 충족했다고 판단하지 않음.

## 이번 표지 제작 범위

표지의 한 가지 역할은 ‘우리가 연구하는 로봇과 문제’를 소개하고 발표자의 인사에서 오프닝으로 연결하는 것이다. 공식 프로젝트명을 유지하며 미경험 험지 적응을 크게 보여준다. 험지 앞 Go2는 생성 콘셉트 이미지다. 처음에는 화면에도 표기했으나 U26에 따라 표지의 우측 하단 문구는 삭제하고 제작 기록·메모에 출처를 보존한다. 기술 성적이나 임무 성공을 표지에서 주장하지 않는다. 픽셀 진행 표시, 오프닝 영상, 다음 본문은 별도 제작 대상으로 남는다.

## U157 · 부드러운 블랙 전환과 다음 이미지·HUD 제작 계획

## U158 · HUD는 영상 동작과 함께 변해야 함

사용자는 카메라·보행이 움직이는데 별도 HUD 합성이 정지 수치·정지 height scan으로 남는 것 아닌지 지적했다. 정지 캡처를 그대로 붙이는 방식은 채택하지 않는다. 화면 고정 계기판도 시간에 따라 상태가 변해야 하고, 지형 scan·CV 박스는 카메라와 대상에 맞춰 추적·가림을 반영해야 한다. 생성 영상에는 실제 IMU·LiDAR 로그가 없으므로 이를 측정값으로 주장하지 않는다. 지형에 붙는 scan은 카메라·깊이 추정이나 3D 장면 기반 합성이 필요하며, 현재 SVG는 디자인 정본일 뿐 해당 동적 합성은 아직 구현되지 않았다. 관측 컷 하나에서 움직임·디딤면·틈 가림을 먼저 검증한 뒤 확장한다.

## U159 · 관측 컷은 HUD 합성 참조를 주고 AI 영상화 우선

사용자는 실제 배경에 HUD·scan을 합성한 레퍼런스를 AI 영상 모델에 주어 카메라·보행·지형에 따라 scan과 표시가 반응하도록 만들 것을 제안했다. 이에 따라 모든 HUD를 후반 합성으로 분리한다는 기존 계획을 수정한다. 관측 컷은 승인 배경과 기존 HUD 디자인을 결합한 참조 이미지 확인 후 통합 AI 영상화 시험을 우선한다. 근거리 scan 컷은 주변 HUD를 생략하는 기존 요구를 유지한다. 발밑에서 앞쪽으로 이어지는 scan, 틈과 지지면 구분, 카메라 움직임, 수평계·표시 변화의 관계를 문안에 명시한다. 수치가 물리적으로 맞거나 실제 센서 측정이라고 보장하지 않는다. 글자·숫자 변형은 결과를 보고 필요한 항목만 합성 보완한다. 영상 시험은 승인된 1컷 범위와 견적을 먼저 확정하며 현재 제출하지 않았다.

## U160 · 레이어 분리 여부는 시험으로 판단, 독립 이미지 진행 승인

사용자 원문: “이미지 작업 들어갈 수 있는 것 (지금 결정에 영향 안받는 것은 진행해)”. 레이어 분리를 필수로 삼지 않는다. 통합 이미지로 카메라·지형·계기판 반응이 구현되는지 먼저 시험한다. E3 후면·E4 측면 이미지를 각 1장 승인 범위로 진행했다. E3를 먼저 열람한 뒤 E4의 공간 참조로 전달하고, 공통 Go2·발 디테일·E2 재질 참조를 첨부했다. 합계 사전 견적 5.5크레딧. [관측 제작 설계](HUD-VIDEO-PRODUCTION-PLAN.md)에 상세 반응 기준과 보완 판단을 남겼다.

## U161 · 새 E3에서 사라진 물·좁고 불규칙한 통로

사용자는 새 E3가 기존 원화의 물, 좁은 통로, 불규칙한 폭을 잃었다고 지적했다. 직접 비교에서도 새 E3는 넓고 비슷한 크기의 콘크리트 판이 반복되는 인상이 강하다. 외형·재질 정렬 과정에서 지형을 재설계한 것이 문제다. E3를 다음 제작의 배경 정본으로 확정하지 않는다. E4도 새 E3를 참조했으므로 공간 연속성 승인 완료로 취급하지 않는다. 수정 방향은 기존 엔딩 원화의 물·통로·발판 윤곽을 배경 기준으로 복원하고 Go2 외형과 과한 HDR만 조정하는 것이다. 추가 생성은 아직 하지 않았다.

## U162 · 원래 지형을 임의 변경한 E3·E4 프롬프트 오류

사용자는 E4의 정갈한 일자 단면과 건너기 쉬워진 지형을 지적하고 프롬프트 변경을 재차 문제 삼았다. 기존 원문과 실제 요청을 대조해 원화 직접 참조 누락, 넓은 지지면·동일 높이 발판 강제, 새 E3를 E4 정본으로 사용한 오류를 기록했다. 원래 원문에도 15~25cm 짧은 틈 조건은 있었으므로 수치 자체를 새로 발명했다고 한 설명은 정정한다. [수정 범위와 요청문](E3-E4-PROMPT-CORRECTION.md). 추가 생성은 실행하지 않았다.


## U163 · 프롬프트 재확인·작업 목록·재질 수정·같은 자리 비교

사용자는 E3·E4를 원래 지형으로 다시 만들고 각 제출 직전 프롬프트와 앞뒤 컷을 대조할 것을 반복 요구했다. E5pre의 외부 바닥 카메라 통과를 잊지 말아야 한다. 작업 가능한 다른 지형 이미지도 진행하되 모든 요구와 실제 결과를 기존 스토리보드에 반영해야 한다.

새 v2 두 장의 HDR·광택 과다를 지적했다. 원화 구도 보존과 재질 보존은 다르다. v3는 장면 전체의 국부 대비·하얀 반사·선명도를 줄이고 표면별 반사를 구분하도록 요청했다. v3 생성 뒤 웹에는 v2가 남아 있었고, 사용자가 표시 버전을 물어 확인한 뒤 교체했다. 현재 v3이며 승인 전이다. 추가 생성은 최신 화면 확인 전 보류했다.

원문: “웹페이지 스토리 보드 E3 아래 버튼 만들라고”. 확대창에서만 비교하는 방식이 아니다. E3 이미지 바로 아래 원래 원화·현재 시안 버튼으로 그 자리에서 바뀌어야 한다. E4와 다른 컷에도 같은 방식을 적용했다.

## U164 · 개선 허용과 나머지 컷 진행

사용자는 v3의 재질이 다소 덜 적용된 느낌을 언급하면서도 나머지 컷 진행을 지시했다. 이후 “구도 지형이 더 나아지는 방향이 있고 앞뒤랑 전체랑 연결해서 더 좋다면 문제는 없어”, “결과로 이야기해”라고 명시했다. 기존 원화는 비교 기준이지 절대 수정 금지가 아니다. 이야기·목적·정해둔 핵심 동작을 보존하고 전체 연결과 결과가 나아지는 구도·지형 개선을 허용한다. 새 지시는 앞선 무조건적 원화 형상 고정 원칙을 완화한다. 이는 E3·E4 최종 승인 또는 모든 결과 자동 채택을 뜻하지 않는다.

O1·O2·O3·O3b·E5pre·E5·E5b 이미지를 각 1장 제출했다. 실제 제출 문안은 수정하지 않고 저장했으며, 이후 작업에는 위 개선 허용을 반영한다.


## U165 · O1 공간 참조와 조명 참조, E5b 다리와 턱 연결

O1 새 어두운 이미지가 영상 기준으로 적절한지, 밝은 원화를 두고 빛의 연출을 해야 하지 않는지 사용자가 질문했다. 기존 밝은 원화를 공간 참조, 새 어두운 이미지를 조명 참조로 구분한다. 어두운 한 장만으로 원경 전체를 재구성하거나 전역 밝기 변화로 이동광을 대신하지 않는다.

E5b 새 앉은 이미지의 다리 형상과 턱을 넘어온 장소인지 사용자가 지적했다. 앞다리 링크가 두껍게 뭉치고 뒷다리 접힘이 불명확하다. 정면 컷에서 로봇 뒤에 보여야 할 넘어온 턱과 위쪽 발판의 관계도 약하다. 해당 이미지와 이미 요청된 파생 서 있는 프레임은 자동 채택하지 않는다. 단일 이미지로 실제 턱 오르기 수행을 입증하지 않는다.


## U166 · 재질 수정과 지형·연출 개선의 구분

사용자는 이번 결과가 거의 같은 이미지에 톤·재질만 수정한 것인지 물었다. 실제 제출은 원화 구도와 지형 보존을 강하게 요구했고, 이번 결과는 재질·외형 수정본이다. 지형 자체의 개선안이라고 설명하지 않는다. 후속에는 선호한 깊은 틈·가장자리의 불필요한 변경을 피하고, 연결이 약한 E5b의 다리·턱·발판 구조처럼 효과가 분명한 부분을 개선한다.


## U167 · E3에서 E5b로 이어지는 공간 불일치

사용자: “E3에서 전체 지형이 원경으로 보여지잖아? 그 느낌이랑, E5b에서 시안, 서있는 시작 후보 둘다 배경이 이어지지가 않는 것 같아.”

E3 v3, E5 v1, E5b 앉음·서 있음 v1을 직접 나란히 열람했다. E3는 양옆 수면이 넓고 중앙의 좁고 불규칙한 발판이 목표로 이어진다. E5b는 넓은 전경 바닥 뒤에 통로 폭을 가로지르는 반복 단차가 이어져 다른 경로처럼 보인다. 시점이 목표 쪽에서 돌아보는 방향으로 바뀌는 것은 맞지만, 그 시점 변화만으로 통로 폭·수면 배치·발판 구조의 차이가 설명되지는 않는다. 두 E5b 후보가 같은 배경 오류를 공유한다.

원인은 E5b의 기존 독립 원화를 장면 정본으로 잠근 것이다. E3와 E5의 동일 공간을 역방향에서 재구성한 결과가 아니다. 톤 수정이나 단순 좌우 반전으로 해결하지 않는다.

수정 기준: E3를 전체 경로 기준, E5를 목표 직전 턱과 도착 발판 기준으로 삼는다. 목표 설비 쪽에 카메라를 놓고 출발 방향을 돌아보며, 전경의 도착 발판 위 Go2 뒤로 방금 올라온 턱의 위치와 낮은 접근로, 그 너머 중앙의 좁은 불규칙한 발판, 양옆 수면이 읽혀야 한다. 보이지 않는 수직 단면을 억지로 드러내지 않는다. 목표 설비는 카메라 뒤에 둔다. 배관과 기둥은 같은 공간의 반대 시점에 맞게 배치한다. 배경을 먼저 정한 뒤 같은 화면에서 서 있음·앉음 한 쌍을 만든다. 기존 E5b 배경을 다시 고정 참조하지 않는다.

현재 판단은 시각적 연속성 검토이며 정확한 3D 좌표 복원 결과가 아니다. 이번 검토에서 새 유료 생성은 하지 않았다.


## U168 · O1 암전과 빨간 점, 별도 밝은 원경

완전 블랙에서 멀리 작은 빨간 점이 두 번 깜빡인 뒤, 이동광이 바닥·기둥을 훑어 위험한 지형을 보여준다. 천장 조명 점등과 실제 손전등 물체는 금지한다. 다음 근거리 컷으로 시선을 이어간다. 발표 질문용 밝은 원경은 별도 생성됐고 사용자가 승인했다.

## U169 · E5b 원래 구도와 부분 수정, 두 포즈 승인

전체 배경 재구성과 위치 이동안 대신 원래 서 있음·앉음의 구도와 로봇 위치를 유지한다. 사용자가 표시한 뒤 중앙 영역만 불규칙한 좁은 경로로 수정한다. 서 있는 부분 수정본과 이를 기준으로 자세만 바꾼 앉은 끝 프레임을 사용자가 각각 승인했다.

## U170 · HUD 전체 이미지 승인

임무·원경 관측·근거리 scan·촬영·전송·붉은 완료 6장에 사용자가 승인했다. GUI는 의미 전달을 보존하며 개선 가능하다. 수치는 실제 측정 로그가 아닌 콘셉트 예시다. 영상에서는 카메라·지형·보행과 함께 반응해야 한다.

## U171 · E5pre 보행 POV 확정

사용자: “그럼 그냥 POV로 진행하는데 … 턱이 다가오면 라이더 스캔하는 듯한 모습으로 보여주고 턱 바로 앞까지 카메라 컷. 다음 장면 넘어가는 것 이렇게 보여주자. 기록해”

기존 바닥 카메라 통과안은 보존하되 현재안에서 제외한다. 틈을 건넌 뒤 Go2 높이의 보행 POV로 접근하고, 턱 가까이에서 표면 스캔이 높이 차를 드러낸다. 턱 앞에서 컷한 뒤 E5 외부 후면에서 오르는 동작으로 잇는다. 같은 턱·진행 방향·접근 속도를 연결한다. 실제 LiDAR 실측 또는 actor height scan의 정확한 재현으로 주장하지 않는다. 새 POV 이미지는 아직 미제작이다.

## U172 · HUD 대비 재수정과 영상 진행 승인

사용자는 HUD 정보·배치는 승인했으나 과한 대비·HDR 재질을 지적하며 6장 모두 재수정하도록 했다. 국소 대비·과도한 선명도·반사·글로우를 낮추는 v2를 생성했다. 이어 “영상 작업 진행하자. 최종 승인된 컷 시나리오 전달사항 모두 잘 반영해라”, “HUD 모두 승인 반영해”라고 지시했다. 영상은 최신 승인 v2를 입력으로 쓰며 기본 음향을 포함한다. 최종 음악·공간음·효과음은 전체 흐름을 기준으로 별도 제작·믹싱한다.


### U173 · HUD 전체 승인 반영

사용자: “HUD 모두 승인 반영해”. 대비·재질 보정 v2 6종을 최종 이미지 기준으로 기록하고 통합 스토리보드 O4·O5·O6·E6·E7 전송·완료에 반영했다. 영상 승인은 별개다. 원화 비교를 보존하며 승인된 정지 화면에 추가 대비 필터를 적용하지 않는다.
