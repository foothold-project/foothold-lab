## 1. 판정

기존안의 큰 방향은 유지할 수 있지만 그대로 제작하기에는 연구 질문과 방법의 설명이 부족했다. 배경과 비유는 풍부한데 무엇을 검증했는지 늦게 등장했고, 기술 설명을 줄이는 과정에서 PPO, 현재 신경망 구조, 실제 보상 변경, 성공률 정의까지 흐려졌다. 중간에 들어간 Digital Twin 설명은 보행 성과에서 한계로 이어지는 흐름을 끊었다.

이를 반영해 34개 화면으로 조정했다. 장수를 채우기 위한 증량이 아니다. 제품 소개와 산업 사례는 합치고, 연구 질문·핵심 보상 비교·다음 평가 기준에 자리를 배정했다. 기존 화면에도 기술적 핵심을 복원했다. 사용자 요청에 따른 현재 세션의 검토이며 별도 Astra 세션은 호출하지 않았다.

## 2. 설득과 이해를 점검한 기준

목표는 청자가 프로젝트의 필요성뿐 아니라 결과를 믿을 수 있는 범위와 다음 실험의 이유를 설명할 수 있게 하는 것이다. 특정 심리학 원칙을 적용했다는 이유만으로 설득력이 검증된 것은 아니다.

Mayer·Moreno의 멀티미디어 학습 연구는 불필요한 자료 제거, 중요한 정보의 표시, 내용을 나누어 제시하는 방식을 다룬다. 이를 산양·제품 소개의 제한, 구간 표시, 발표자 조작에 따른 설명에 참고했다. 해당 연구는 주로 학습 상황의 실험이며 FOOTHOLD 발표의 설득 효과를 직접 검증한 자료는 아니다. [원문](https://faculty.washington.edu/farkas/TC510-Fall2011/MayerMoreno9WaysToReduceCognitiveLoad.pdf)

Garner 등의 기술 발표 연구는 핵심 주장을 담은 제목과 이를 뒷받침하는 시각 자료의 구성을 비교했다. 따라서 결과 화면은 ‘실험 결과’ 같은 주제명만 두기보다 조건과 관찰을 말하는 제목을 쓴다. 이 역시 모든 청중에게 효과를 보장하는 공식은 아니다. [연구](https://peer.asee.org/assertion-evidence-slides-appear-to-lead-to-better-comprehension-and-recall-of-more-complex-concepts)

아래 흐름은 이 근거를 참고한 편집 판단이다. 심리 효과를 측정한 결과로 표시하지 않는다.

| 청자가 판단할 질문 | 발표에서 줄 답 | 주의할 논리적 비약 |
|---|---|---|
| 왜 관심을 가져야 하나 | 접근이 어려운 곳에서도 점검이 필요함 | 재난 이미지가 곧 우리 실증 범위인 것처럼 보임 |
| 왜 지상 보행을 연구하나 | 선택한 임무의 접근·센서·체류 조건과 발 디딤 문제 | 유명 기업의 제품이나 산양의 능력이 우리 방법의 우수성을 입증함 |
| 정확히 무엇을 검증하나 | 험지 성능을 높이면서 기본 명령도 유지할 수 있는가 | 모든 험지와 행동을 이미 해결한 것으로 읽힘 |
| 무엇을 바꾸었나 | 기존 정책의 지형·명령·보상 조건과 비교 절차 | 기존 기술을 새 알고리즘 발명으로 포장함 |
| 무엇을 근거로 개선을 말하나 | 조건을 맞춘 평가, 성공 정의, 실제 영상 | 0% 성공을 모두 낙상으로 해석하거나 한 영상으로 전체를 대표함 |
| 어디까지 믿을 수 있나 | 개발 평가의 범위, 시드 변동, 남은 명령 제한 | 시뮬 결과를 실기·현장 신뢰성으로 확대함 |
| 다음에 무엇을 확인하나 | 한계에 대응하는 과제·관측·구조 비교와 평가 계획 | 새 기술 이름만 나열하고 성공 여부를 판단할 기준이 없음 |

발자국은 현재 설명하는 구간을 알려주는 정도로 사용한다. 발자국·배경 영상·텍스트·그래프가 동시에 움직이지 않는다. 한 화면의 문구는 짧게 두되, 결론을 바꾸는 조건은 읽을 수 있는 크기로 남긴다. 도입 길이는 실제 발표 시간에 맞춰 조정하며 화면 수만으로 적정 시간을 판단하지 않는다.

## 3. 발견한 누락과 수정

| 기존안의 문제 | 수정 | 반영 위치 |
|---|---|---|
| 연구 질문이 암묵적이고 기여가 분산됨 | 질문 하나와 현재 기여의 범위를 직접 제시 | 8장 |
| 상용 제품·산업 사례의 비중이 높음 | 임무 조건을 먼저 제시하고 제품·사례를 한 화면으로 통합 | 4~5장 |
| PPO를 생략하고 관측을 개념적으로만 설명 | 학습·실행 경로, actor·critic 역할, MLP 입력·출력 복원 | 12~13장 |
| v2가 지형·명령만 조정한 것처럼 보임 | feet_air_time 가중치 비교를 본문에 복원 | 20~21장 |
| 성공률의 구성과 평가 표본 단위가 약함 | 네 조건의 AND, 모델·속도·난이도·에피소드·평가 시드 명시 | 16~17장 |
| 성과와 한계 사이에 트윈 소개가 끼어듦 | 보행의 성과와 한계를 연속해서 제시하고 트윈은 후속 실행 흐름에 배치 | 22~31장 |
| 다음 연구의 채택 기준이 약함 | 조건 분리, 시드 반복, 기존 능력 유지와 결합 평가를 제안 | 32장 |

## 4. 연구 발표 본문에 남겨야 할 기술

- NVIDIA 사전학습 정책에서 시작했다는 사실과 모델별 실제 학습 조건. 연구 버전 순서를 가중치 전달 계보로 바꾸지 않는다.
- Isaac Lab의 병렬 강화학습과 PPO. actor가 관절 목표를 출력하고 critic이 학습을 돕는 구조. optimizer의 수식과 전체 설정표는 부록에 둔다.
- 현재 관측 235차원과 actor·critic의 MLP 구조. height scan은 시뮬레이션 ray casting이며 실제 카메라·LiDAR를 이미 통합했다는 뜻이 아니다.
- 지형 노출, 명령 분포, 정지 표본, 보상항 가중치 중 실제로 바꾼 것. 연구 질문과 관계없는 설정 목록은 설명하지 않는다.
- 종합 성공의 정의와 기본 명령 프로브의 범위. 평가 축 이름만 보여주고 정의를 생략하지 않는다.
- 관찰 결과, 원인 해석, 다음 실험 가설을 구분한다. 전문성은 용어 수가 아니라 방법과 증거를 판단할 수 있는 정보에서 드러나야 한다.

이번에 읽은 구현 근거는 `sim/policy/gap_ppo_cfg.py`, `sim/policy/v2a_env_cfg.py`, `sim/policy/v2b_env_cfg.py`, `sim/eval/metrics.py`다. 로컬 Isaac Lab의 `velocity_env_cfg.py`, Go2의 `rsl_rl_ppo_cfg.py`, `mdp/rewards.py`도 읽었다. MLP 설정과 관절 위치 행동, feet_air_time 계산을 대조했다. 배포 파일의 텐서 전체와 모든 실행의 설정을 새로 감사한 것은 아니다. 최종 화면의 모델별 설정표는 해당 실행 기록과 대응시킨다.

## 5. 추가로 주의할 관점

### 미경험과 독립 최종 평가의 구분

학습에 지형을 넣지 않은 것과 모델 선택에도 사용하지 않은 시험은 다르다. 반복 평가 결과로 설정·체크포인트를 고르면 그 평가 집합은 개발 의사결정에 사용된 것이다. 기존 결과를 무효라고 할 필요는 없지만, 이를 완전히 독립된 최종 시험으로 소개해서는 안 된다. 다음 단계에서는 선택에 사용하지 않은 지형 조건과 시드를 분리하는 방안을 제안한다. 현재 그 분리가 완료됐는지는 미확인이다.

### 결과의 크기와 불확실성

1.0 m/s에서 v1 87.375%, v2 90.5%의 차이는 3.125%p다. NVIDIA 대비 변화와 v1 이후의 추가 변화를 구분한다. 이 차이가 학습 시드 전반에서 안정적으로 재현되거나 통계적으로 유의하다고 이번 검토에서 판정하지 않았다. 100에피소드는 100개 독립 지형 배치도, 100번 독립 학습도 아니다. 같은 설정의 학습 시드 변화와 고정 정책의 평가 시드 변화를 구분한다.

### 보상 변경의 의미

feet_air_time은 체공시간을 사용하는 기존 항이다. 가중치를 키웠다는 사실을 발 높이 보상이나 안전한 착지점 학습으로 바꾸어 말하지 않는다. 관측된 성능 변화만으로 여러 실패의 공통 원인을 입증한 것도 아니다. 0.1을 채택한 비교 근거를 보여주되 모든 지형·시드에 대한 최적값이라고 주장하지 않는다.

### 현재 기여와 다음 연구의 구분

현재 발표에서 뒷받침할 수 있는 기여는 학습 조건 설계, 기존 정책의 추가 학습 결과, 험지와 기본 명령을 함께 보는 평가다. 새 신경망 구조나 새로운 강화학습 알고리즘을 이미 제안·검증한 연구로 소개하지 않는다. 신경망 비교는 다음 가설이며, 현재 한계의 원인이 구조라고 확정되지 않았다.

### 영상과 전체 평가의 관계

좋아 보이는 시연을 먼저 고른 뒤 숫자를 붙이지 않는다. 모델·속도·난이도·명령 시나리오가 맞는 영상을 고르고 전체 평가 결과를 함께 보여준다. 조건이 다른 영상밖에 없으면 그 차이를 표시한다. 실제 영상의 선정과 대표성은 아직 미확인이다.

## 6. 제작 후 한 번 확인할 항목

실제 청중 검증은 아직 하지 않았다. 제작 후 프로젝트를 모르는 사람이 연구 질문, 바꾼 조건, 성공의 의미, 남은 제한, 다음 평가를 자기 말로 설명할 수 있는지 확인하면 된다. 이해가 끊긴 화면만 수정한다. 반복되는 별도 모델 검증을 자동으로 실행하지 않는다.

발표 시간과 실제 화면이 확정되기 전에는 ‘누구나 이해한다’, ‘설득력이 검증됐다’, ‘레이아웃 검증 완료’라고 쓰지 않는다.
