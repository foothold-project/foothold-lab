## 사용자 요청과 제작 제안

| 장면 | 사용자 요청 | 구체화 제안 |
|---|---|---|
| 조명 | 실제 영상에서 빛을 영화적으로 처리 | 영상 생성에서 표면·안개에 반응하는 이동광을 만들고, 최종 편집에서 노출과 컷 연결을 맞춤. 현재 CSS는 방향 확인용 |
| E2 | 원경은 좋지만 로봇이 너무 가까움. 가운데 정도에 배치 | 단순히 더 축소하기보다 아래 전경에 있는 로봇을 화면 중앙 부근의 중경으로 이동. 몸통 중심을 가로 50%, 세로 50~55% 부근에 두는 후보. 작은 기체와 큰 공간의 대비 유지 |
| E5 | 턱을 오르고 한두 걸음 간 뒤 앞다리는 펴고 뒷다리만 앉아 목표를 바라봄 | E5a에서 턱 오르기, E5b에서 한두 걸음·뒷다리 접기·앞다리 지지·정지 시선. 사용자 후속 지적으로 사선 대신 Go2 바로 뒤 중앙축에서 목표를 정면으로 보는 시점으로 동작 확인. 다음 컷은 그 시선의 설비 POV |
| 완료 문구 | MISSION CLEAR보다 MISSION COMPLETE 제안 | MISSION COMPLETE 채택 제안. 전송 완료와 임무 완료를 단계로 구분 |
| 완료 색 | 문구·100% 및 HUD에 빨간 디자인을 도입 | 진행 중 녹색, 100% 도달 시 진행 막대·숫자·완료 문구를 주홍빛 적색으로. 주변 계기는 정리하고 완료 정보만 남김 |
| 컷 전환 | Higgsfield에서 영화적 연출 | 지형 컷은 시선·움직임·소리 연결. 임무 시작과 종료에만 강한 신호 효과. 모든 컷에 glitch 반복하지 않음 |

E5의 앉기는 생성 콘셉트 동작이며 현재 foothold-v2가 수행한다고 주장하지 않는다. 실제 Go2 형태와 관절 방향을 유지하고, 몸통이 녹거나 다리가 추가되는지 확인한다. 여러 행동을 무조건 5초 한 컷에 압축하지 않는다. 기본 5초 원본 두 개 또는 충분한 단일 길이를 비용·동작 결과에 따라 고른다.

## 완료 화면의 순서 제안

1. 녹색 촬영 HUD에서 대상 기록. CV 박스는 대상에 붙이고 불필요한 계기는 줄인다.
2. TRANSMITTING과 진행 막대. 100% 도달 시 숫자와 막대가 적색으로 전환된다.
3. DATA RECEIVED로 수신을 확인한 뒤 화면 중앙에 MISSION COMPLETE. 완료 문구와 절제된 적색 프레임만 강조한다.
4. 잠깐 안정적으로 유지한다. 경보처럼 반복 점멸시키지 않고 짧은 완료음과 음악 해소를 연결한다.
5. 화면이 수축하고 짧은 신호 노이즈 뒤 블랙. 다음 슬라이드는 기존처럼 Q&A만 중앙에 둔다.

적색은 경고로도 읽힐 수 있으므로 색만으로 성공을 표현하지 않는다. COMPLETE 문구, 수신 확인, 정돈된 화면과 소리를 함께 쓴다. HUD 문구·정확한 100%·진행 막대·glitch 타이밍은 별도 그래픽 레이어로 편집해 제어한다. 영화적 영상과 별도 UI가 이질적이지 않도록 노이즈·잔광·노출을 맞춘다.

## 이미지 모델 비교 제안

전체 컷을 두 모델로 다시 만들기 전에 대표 3장 × 2모델, 총 6장으로 비교한다.

- O1: 어둠·이동광의 인상·산업 공간 규모.
- E2: Go2 형상·중경 중앙 배치·작은 기체와 큰 공간.
- E5b: 턱을 오른 뒤 뒷다리만 앉고 앞다리로 지지하는 목표 응시 자세.

기존 프롬프트와 같은 참조 원화를 기반으로 한다. 최종 변경인 E2 배치와 E5b 자세만 양쪽 모델에 동일하게 반영한다. 첫 비교에서는 모델마다 서로 다른 연출 지시를 넣지 않는다. 순수 텍스트 새 생성과 참조 이미지 편집도 같은 실험으로 섞지 않는다. 16:9, 같은 참조, 같은 출력 크기로 비교하며 모델별 품질 옵션과 원문 프롬프트를 함께 저장한다. 서로 다른 모델에서 같은 시드 숫자를 주더라도 동일 조건을 보장하지 않는다.

선택 기준은 예쁜 한 장뿐 아니라 같은 Go2·같은 공간 유지, 영상화 가능한 발 디딤, 어둠 속 가독성, 컷 연결이다. 기존 승인 이미지는 삭제하지 않는다. 이번 턴에는 모델 조회만 했고 이미지 업로드·생성·크레딧 사용은 하지 않았다.

## 영상 시험 순서 제안

1. 선택한 원화로 O1 이동광, E2 공개, E5 턱 오르기·앉기부터 시험한다. 앞의 두 컷은 조명, E5는 관절·접지·다단계 행동을 확인한다.
2. 최저 지원 해상도로 동작과 카메라부터 확인한다. 낮은 해상도는 발 접촉·세부 HUD 가독성의 최종 검증을 대신하지 못한다.
3. 중요한 동작 컷은 최종 해상도 한 개를 먼저 확인한 뒤 나머지 제작으로 넓힌다.
4. 승인된 영상은 업스케일 또는 지원되는 초안 완성 경로를 검토한다. 재생성은 같은 움직임을 보장하지 않고, 업스케일도 잘못된 관절 동작을 고치지 않는다.
5. 컷 연결, 정확한 HUD, 색보정 후 하나의 음악 전개·환경음·접지음·효과음을 제작한다. 최신 사용자 지시에 따라 초기 동작 시험부터 generate_audio=true로 컷별 현장 소리를 포함한다. 개별 음악·대사·보컬은 요청하지 않고 전체 음악과 음향은 편집 확정 후 따로 구성한다.

## MCP에서 확인한 선택지

2026-09-30, 연결된 Higgsfield 카탈로그 조회. 아래는 도구가 반환한 기능이며 실제 성공·비용·권한을 시험한 결과가 아니다.

| 모델 ID | 확인된 선택지 |
|---|---|
| nano_banana_pro | 참조 이미지, 1k·2k·4k, 16:9 |
| gpt_image_2_5 | 참조 이미지, flare·sunburst, 1k·2k·4k, low~max 품질 |
| seedance_2_0 | 4~15초, fast는 480p·720p, std는 480p·720p·1080p·4k. 360p 선택지 없음 |
| seedance_2_5 | draft=true로 480p 초안, 완료된 draft_job_id를 사용한 1080p 완성 옵션. 도구 설명상 초안 7일 이내 완성 |

Seedance 2.5의 초안 완성이 프레임·동작을 얼마나 보존하는지는 미확인이다. 이 기능이 존재한다는 이유만으로 결과 동일성을 보장하지 않는다. 가격과 구독 혜택 적용은 실제 제출 직전 estimate 도구와 계정 조건으로 확인한다. 기존에 말한 3초·5초 동일 비용도 모델 전체에 일반화하지 않는다.

공식 참고: [Higgsfield 이미지 모델](https://higgsfield.ai/ai-image), [공식 CLI 모델 안내](https://github.com/higgsfield-ai/cli/blob/main/MODELS.md), [Seedance 사용 안내](https://higgsfield.ai/creator-hub/help-center/ai-models/how-do-i-use-seedance). MCP와 웹 노출이 다를 경우 현재 실행 경로의 파라미터를 우선 확인한다.
