전체 설계 지도: [큰 목차 아래의 전체 세부 주제와 본문·부록 경계](SECTION-MAP.md). 내부 검토용 주제를 빠짐없이 보존하는 지도이며, 모든 항목을 독립 슬라이드로 만들지는 않는다. 9월 30일 추가 피드백에 따라 외부 청자에게 필요한 주장과 시각 자료를 중심으로 STORYBOARD.md를 다시 편집했다. 레시피 변경은 한 화면, resume 세부 조건과 실험 식별자는 부록으로 옮긴다.

이 문서는 다른 세션이 대화의 맥락을 이어받기 위한 설계 기록이다. 공식 발표 원고나 최종 슬라이드가 아니다. 사용자가 승인한 요구사항과 이번에 제안한 구성을 구분한다. `확인됨`은 대화·코드·출처에서 확인한 사실이며, 외부 사례의 수치는 원자료를 독립 실측했다는 뜻이 아니다. 근거가 부족한 주장은 `미확인`, 측정하지 않은 수치는 `미측정`으로 둔다.

추가 검토: [서사·연구성 재검토](REVIEW-story-research.md). 최신 STORYBOARD.md v0.3은 연구 질문, PPO·actor·critic 구조, 보상 변경과 성공 정의를 본문에 복원했다. 기술 세부를 전부 부록으로 보내지 않으며, 아래 초기 분류와 충돌하면 이 최신 구성을 따른다.

## 1. 사용자가 승인한 방향과 필수 요구사항

- 청자가 왜 이 프로젝트가 필요한지 납득한 뒤 실험 내용을 이해하도록 전체 서사를 구성한다. 배경 설명의 상세 순서는 함께 논의한다.
- 미경험 험지를 시각적으로 설명한다. 재난·안전 현장의 이미지나 영상은 도입 후보이며, 미경험은 정책의 학습 경험을 기준으로 정의한다.
- 사족보행을 선택한 이유를 임무 조건과 근거로 설명한다. 바퀴는 험지를 못 간다거나 드론은 지하에서 못 쓴다는 주장은 사용하지 않는다.
- 목차는 무엇을 이야기할지 구체적으로 드러내야 한다. 페이지 수보다 발표자의 호흡과 한 화면의 명료함을 우선한다.
- 한 슬라이드에 하나의 핵심을 전달하고 영상·그래프·인포그래픽을 적극 활용한다.
- 기존 HTML 발표의 전체화면, 단축키, 화면 넘기기 등 사용성을 유지한다. 애니메이션을 추가한다.
- FOOTHOLD의 의미를 첫 발걸음과 연결한다. 배경 설명 뒤 “이제 우리의 프로젝트의 첫 발걸음을 같이 내딛어볼까요?”라는 취지의 전환 멘트를 사용한다. 최종 문구는 다듬는다.
- 발표 진행 표시는 우측 상단의 작은 Go2와 지형 경로로 변경한다. 픽셀 표현은 후보이며, 구체 동작은 최신 수정 문서의 제안을 따른다.
- 우리가 풀어낸 과제와 남은 과제를 명확히 구분하고, 중간발표 이후 최종발표까지의 다음 한 걸음을 보여준다.
- 사업성 입증은 이번 발표 요구에서 제외한다. 경제적 가치는 출처와 비교 조건이 있는 수치로 설명한다.
- 경제적 가치의 후보는 산업 점검 업무의 효율과 시뮬레이션 병렬 학습의 효율이다. 외부 사례를 우리 성과로 표현하지 않는다.
- 한국어는 자연스럽고 구체적으로 쓴다. AI가 만든 듯한 추상어와 표어를 줄인다. 비유는 이해를 돕는 용도로 쓰고 기술적 근거를 대신하지 않는다.
- 채팅에서 내용을 충분히 검토하고 합의가 사라지지 않도록 이 문서에 이어 기록한다.

## 2. 앞선 대화에서 합의한 기술적 경계

사용자는 직전 답변의 방향에 동의했다. 다음 내용은 이후 제작에서도 유지한다.

- 사족보행이 항상 세 발로 지지하는 것은 아니다. 정적 보행과 trot 등 동적 보행을 구분한다. 균형 유지 능력을 무전도 보장으로 표현하지 않는다.
- 고유수용감각 기반 보행 연구는 존재하지만, 현재 FOOTHOLD MVP는 height scan을 입력으로 사용한다. 카메라·LiDAR 없이 모든 지형을 알아내는 모델로 소개하지 않는다.
- 보행 안정화와 위치 추정·항법·통신은 서로 다른 문제다. 고유수용감각만으로 모두 해결된다고 말하지 않는다.
- 미경험 지형은 학습에서 경험하지 않은 조건을 뜻한다. 재난 현장에만 한정하지 않는다. 평가 지형의 학습 포함 여부와 시드 조건을 명시한다.
- 현재 MVP는 NVIDIA 사전학습 정책을 바탕으로 추가 학습했다. 아기의 걸음마 비유가 처음부터 학습했다는 오해를 만들지 않게 한다.
- 동물 동작을 이용한 모방학습은 근거가 있지만 현재 프로젝트가 수행한 방법으로 소개하지 않는다. 동물 영상의 양과 바로 쓸 수 있는 로봇 학습 데이터의 양은 다르다.
- Go2 공식 SDK의 여러 동작 기능은 확인했으나, 정확히 네 가지 신경망을 routing한다는 내부 구성은 미확인이다.
- 험지 특화는 정지·방향 전환·속도 조절을 포기하는 근거가 아니다. 이 행동도 현장 임무 수행에 필요하다.
- 4096개 환경에서 경험을 모아 공통 정책을 업데이트하는 설명을 사용한다. 4096배의 시간·비용 절감으로 환산하지 않는다.
- 시뮬레이션 성과와 실기 검증을 구분한다. 목표 장면이나 생성 이미지를 실제 실험 성과로 보이게 하지 않는다.

## 3. 목차 제안: 여섯 구간

아래는 이번 답변의 제안이며 아직 최종 승인된 목차가 아니다. 각 구간은 여러 슬라이드로 나눌 수 있다.

| 구간 | 목차에 쓸 제목 후보 | 청자가 이해할 내용 | 시각 자료 후보 |
|---|---|---|---|
| 1 | 위험한 현장과 이동 로봇의 역할 | 현장에 사람이 직접 들어가기 어려워도 점검과 탐색은 필요하다 | 현장 영상, 실제 점검 사례와 수치 |
| 2 | 사족보행을 선택한 이유 | 임무에 맞는 이동 방식을 고르고, 다리가 필요한 지형을 설명한다 | 동일 현장의 공중 관찰과 지상 점검 경로, 발 디딤 장면 |
| 3 | 미경험 험지를 학습하는 방법 | 이미 배운 보행을 새로운 지형에 대응하도록 개선한다 | 학습·평가 지형 구분, 관측과 행동, 병렬 학습 |
| 4 | MVP에서 개선한 보행과 실험 결과 | 무엇을 바꾸었으며 동일 조건에서 무엇이 달라졌는가 | 비교 영상, 축1·축2 결과, 실패와 감속 구분 |
| 5 | 아직 해결하지 못한 과제 | 어떤 지형과 명령에서 제한이 남았는가 | 대표 실패 장면, 미검증 조건과 남은 과제 |
| 6 | 최종발표까지의 다음 단계 | 다음 실험과 실기 검증이 무엇이며 어떤 조건으로 평가할 것인가 | 완료·진행·계획을 구분한 일정, 처음 보여준 현장으로 복귀 |

도입의 경제적 가치 사례와 위험한 현장이 서로 다른 장소라면 명확히 구분한다. 공장 점검 사례가 재난 잔해 통과 능력을 입증하는 것처럼 연결하지 않는다. 산업 점검의 필요와 불규칙한 지형에서 이동하는 연구 문제 사이의 연결을 발표자가 설명해야 한다.

팀 소개, 기술 목록, 전체 일정은 이 흐름을 방해하지 않는 위치와 분량으로 줄인다. 발표 시간은 아직 미확인이다. 페이지 수를 먼저 고정하지 않는다.

## 4. “드론으로 하면 되지 않나?”에 대한 설명 제안

드론으로 해결되는 임무는 드론이 적합하다고 인정한다. GPS가 없거나 지하라는 이유만으로 드론을 배제하지 않는다. Elios 3처럼 SLAM 기반의 실내 점검 드론이 실제로 있다.

우리 적용 시나리오는 센서를 운반하면서 정해진 점검 지점을 반복 방문하고, 필요한 곳에서 멈춰 측정한 뒤 돌아오는 지상 점검을 후보로 둔다. 이 시나리오는 사용자가 아직 최종 확정한 적용처가 아니며 현재 MVP가 수행한 임무도 아니다.

비교할 조건은 접근 위치, 비행 가능한 공간, 탑재 센서, 반복 방문 빈도, 체류 시간, 충전과 복귀 방식이다. 드론도 정밀 점검과 센서 운반이 가능하므로 이를 사족보행만의 능력이라고 말하지 않는다. 접촉 작업도 전용 드론이 있을 수 있다. 먼지와 암전이 사족보행에 자동으로 유리하다고 단정하지 않는다.

지상 플랫폼은 지면의 지지를 받으며 정지할 수 있다. 그러나 지면을 따라 접근해야 하므로 계단·요철·잔해·틈이 이동의 제약이 된다. 이 지점에서 발 디딤과 보행 적응을 설명한다. 평탄한 경로에 바퀴로 충분하다면 그 사실도 인정한다. 사족보행과 바퀴 달린 다리 로봇의 우열은 실제 임무 조건 없이 확정하지 않는다.

발표 답변 후보:

> 공중에서 보고 확인하는 것으로 끝나는 임무에는 드론이 좋은 선택입니다. 저희가 염두에 둔 것은 지상의 점검 지점을 반복 방문하는 임무입니다. 지상 로봇이 그 역할을 하려면, 센서를 싣고 이동하는 동안 처음 만나는 계단이나 불규칙한 바닥에서도 멈추고 방향을 바꿀 수 있어야 합니다. FOOTHOLD는 그 보행 능력을 연구합니다.

설계 판단: 특정 비행 방식의 약점을 길게 나열하는 것보다, 하나의 구체적 임무와 경로를 보여주는 편이 연구 선택의 이유를 설명하기 쉽다. 드론과 지상 로봇의 협력도 가능한 그림이다.

## 5. 경제적 가치에 사용할 근거와 시각화

| 근거 후보 | 원출처에서 확인한 내용 | 발표에서 쓸 수 있는 표현 | 주의점 |
|---|---|---|---|
| AB InBev Leuven의 Spot 점검 | 주 1,800건의 개별 점검, 도입 첫 6개월 약 150건의 이상 발견 | 반복 점검의 규모와 사람이 수리에 집중하는 업무 변화를 설명 | 제조사 공개 고객 사례. 1,800회 순찰 또는 사람 1,800회 출동 대체가 아님. 우리 실측 아님 |
| 같은 사례의 수리 기간 | 기존 수개월에서 평균 13일로 줄었다고 소개 | 본문 보조 설명 후보 | 기존 값이 정확한 수치가 아니므로 감소율이나 정밀한 전후 막대그래프를 만들지 않음 |
| 병렬 학습 연구 | 단일 워크스테이션 GPU에서 평지 정책 4분 미만, 불규칙 지형 정책 약 20분 학습을 보고 | 병렬 시뮬레이션의 가능성을 보여주는 외부 연구 사례 | 실제 로봇 1대와의 동일 과제 비용 비교가 아님. 우리 학습 시간 아님 |
| 우리 4096 환경 학습 | 프로젝트 설정과 보고서에 근거한 병렬 경험 수집 구조 | 로봇 여러 대의 경험이 하나의 정책 업데이트로 모이는 도식 | 속도 향상률·원화 절감액은 미측정 |
| 국내 고령화와 점검 인력 부족 | 이번 설계에서 직접 연결할 통계는 미확인 | 필요하면 공식 통계와 해당 직무 자료를 추가 조사 | 고령 인구 증가가 특정 점검 직무 부족이나 로봇 도입 효과를 곧바로 입증하지 않음 |

권장 시각화는 현장 사진 옆에 주 1,800건을 큰 숫자로 두고, 별도의 보조 정보로 첫 6개월 약 150건의 이상 발견을 표시하는 방식이다. 시간 단위와 측정 대상이 다르므로 같은 축의 막대그래프로 비교하지 않는다. 출처와 제조사 공개 사례라는 성격을 함께 적는다.

실제 학습 비용 비교를 만들려면 같은 과제와 성능 기준 아래 GPU 사용 시간·요금, 실기 점유 시간, 감독·초기화·복구 시간 등을 알아야 한다. 실제 실험을 하지 않았다면 가정을 명시한 추정으로만 표현한다. 대외비 장비 대여 금액은 사용하지 않는다. 이번에는 근거가 있는 점검 규모를 우선 사용하고 원화 절감액을 억지로 만들지 않는다.

## 6. Go2의 이동으로 보여주는 발표 진행

9월 30일 사용자 피드백에 따라 하단 발자국 누적안을 우측 상단의 Go2와 작은 지형 경로로 변경한다. 첨부 스케치는 배치와 의도의 참고이며 그대로 복제할 완성 도안이 아니다.

- 우측 상단에서 작은 Go2가 발표 진행에 맞춰 지형 경로를 따라 이동한다. 픽셀 애니메이션은 표현 후보다.
- 최신 사용자 요구: 픽셀 Go2가 실제 다리와 몸통을 움직여 걷고, 틈을 넘고, 경사를 오르게 한다. 단순한 위치 이동으로 대신하지 않는다. 재생을 슬라이드 전환 때로만 제한하지 않으며, 구체 재생 방식은 장면을 보며 맞춘다.
- 제안: 현재 구간명은 선명하게 표시한다. 전체 목차는 별도 목차 화면에서 읽도록 하고 작은 영역에 긴 문구를 모두 압축하지 않는다.
- 뒤로 이동하거나 특정 화면으로 건너뛸 때도 해당 위치에 정확히 대응한다. 동작 줄이기 모드와 PDF에서는 정적 위치로 표시한다.
- 오프닝과 엔딩 영상에서는 숨기는 방안을 제안한다. 본문과 도식의 공간을 침범하지 않는다.
- 이는 발표의 진행 위치이며 지형 통과 성능이나 연구 완료를 의미하지 않는다. 마지막에도 앞으로 검증할 과제가 남아 있음을 보여준다.

움직임에는 설명상의 목적을 준다. 병렬 학습에서는 여러 환경의 경험이 정책 업데이트로 모이는 과정을, 결과 비교에서는 동일 축 위에 기준선과 개선 결과가 차례로 나타나는 과정을 보여준다. 숫자를 불필요하게 카운트업하거나 계속 움직이는 장식은 피한다.

애니메이션은 발표자가 넘기는 동작에 맞추고 자동으로 다음 슬라이드로 이동하지 않는다. 키 하나가 애니메이션 진행과 페이지 넘기기에서 혼란을 만들지 않도록 조작 규칙을 제작 때 정한다. 되돌리기, 특정 슬라이드로 이동, 동작 줄이기 모드에서도 최종 정보가 남아야 한다. PDF에는 완성된 정적 상태와 영상의 주요 장면을 제공한다.

기존 HTML에서 직접 확인한 조작: 방향키·Space·PageDown·Enter로 다음 화면, 반대 방향키·PageUp·Backspace로 이전 화면, F 전체화면, G 전체 보기, B 암전, 숫자와 Enter로 페이지 이동, Home·End로 처음·끝 이동.

브랜드 심볼 파일 `web/assets/brand/foothold-symbol-brand.svg` 등은 존재한다. 사용자가 말한 발자국 원본과 일치하는지는 아직 미확인이다. 제작 단계에서 원본을 선택하고 비율을 유지한다.

## 10. 후속 합의: 전체 구성 검토와 시각 자료 제작

사용자는 직전 채팅 답변의 목차·연출·임무 중심 비교·경제적 가치 표현 방향에 모두 동의했다. 3~6절의 제안을 작업 기준으로 삼되, 완성된 전체 흐름을 검토하며 조정할 수 있다. 구체적인 적용처, 최종 슬라이드 구성, 개별 시각 자료는 아직 확정하지 않았다.

- 문서나 이슈를 사용자가 별도로 읽어야 대화가 진행되는 방식으로 운영하지 않는다. 결정이 필요한 내용은 채팅에 충분히 제시하고 합의사항을 문서에 기록한다.
- 사용자가 처음 제시한 소재도 전체 서사를 방해하거나 중복되면 삭제·축소·부록 이동할 수 있다. 전체 구성을 만든 뒤 처음 보는 청자의 관점에서 다시 검토한다.
- 재검토는 기본적으로 현재 세션의 편집 검토다. 별도의 Astra 세션이나 반복 검증을 자동 실행하라는 지시가 아니다.
- 시각 자료는 내용 설계를 먼저 마친 뒤 적극적으로 제작한다. 사용자는 Higgsfield Plus의 무료 크레딧 리셋·충전 혜택을 2026-09-30 23:59 UTC까지 이용할 수 있다고 전달했다. 한국 시각으로 2026-10-01 08:59이다. 계정의 실제 조건과 잔액은 미확인이다.
- 사용자가 언급한 이미지 생성 후보는 나노바나나프로와 GPT Image 2.5다. 실제 제공 모델명과 호출 가능 여부는 제작 시 확인한다. 이 메모를 근거로 현재 생성 작업을 시작하지 않는다.
- 생성 이미지 후보는 배경 상황과 개념 설명이다. 실험 영상과 정량 그래프는 실제 자료를 사용한다. 생성한 장면을 현장 실증이나 실험 증거로 제시하지 않는다.

## HTML 레이아웃 제작과 사용자 설명 보완

사용자는 전체 화면을 스케치처럼 먼저 연결하는 제작을 승인했다. [HTML 초안과 조작 안내](LAYOUT.md)에 34개 화면의 배치와 자료 자리를 기록했다. NVIDIA에서 v1·v2까지는 하나의 연구 성과 흐름이다. 버전 이름 자체가 연구 기여를 나누는 기준이 아니며, 특정 변경의 인과 효과와 전체 성과를 구분한다는 뜻이다.
