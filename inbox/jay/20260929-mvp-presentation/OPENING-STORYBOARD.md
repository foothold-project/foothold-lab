# MVP 오프닝 컷 구성

최신 영상 제작 기준: [전체 연출·음향 점검](FILM-DIRECTOR-NOTES.md). E2는 뒤쪽에서 빛 안으로 걸어 나오며, 영상 초안은 컷별 소리를 포함한다. HTML은 구도 확인용이다.

최신 변경: [Higgsfield 컷별 연출 문안](HIGGSFIELD-SHOT-PROMPTS.md). E2는 이동광 대신 고정광 실루엣 공개, E5는 바닥 카메라 통과·후면 오르기·정면 원경 앉기로 수정했다. 원화와 HTML 반영 완료, 영상 미제작.

최신 후속 연출과 시험 제작 논의: [FILM-FINAL-DIRECTION.md](FILM-FINAL-DIRECTION.md). E5 앉기·E2 중앙 중경 배치·적색 MISSION COMPLETE는 이 후속안을 따른다. 현재 HTML에 E2 중앙 배치, E5 중앙축 오르기·앉기, 적색 MISSION COMPLETE를 반영했다. 이전 사선 제안은 최신 중앙축 구도로 대체했다.

최신 전체 설계: [오프닝과 엔딩을 잇는 한 편의 영상](OPENING-ENDING-FILM.md). 사용자 후속 피드백에 따라 오프닝 몸체 컷은 엔딩으로 옮기고, 전면 MISSION HUD와 가까운 발밑 관측 표현을 추가한다. 아래 이미지와 설계는 이전 과정으로 보존한다.

## 현재 제작 기준 · 깊은 틈 복원과 카메라 거리 수정

[최신 HTML](output/FOOTHOLD-film-storyboard.html). 오프닝은 **O1 → O2 → O3 → O3b → O4 → O5 → O6 → O7**, 8컷이다. 기존 번호를 유지하고 빠뜨렸던 선호 컷을 O3b로 추가했다. 아래 7컷 설계는 이전 기록이다.

| 수정 | 현재 적용 | 근거·한계 |
|---|---|---|
| O2 | 수직에 가까운 바닥 질감 시점으로 새 원화 제작 | 기존 O2·O3의 비슷한 사선 원근을 분리. 이전 질감 컷은 T2로 보존 |
| O3 | 이전 선호 가장자리 컷 유지 | 바닥 표면에서 단절의 시작을 발견 |
| O3b | 사용자가 다시 올린 깊은 틈 컷 복원 | v6 첫 줄 오른쪽 원본 사용. 수면·양쪽 절벽·철근 구도 보존, 재생성하지 않음 |
| E2a | 거의 검은 공개 직전 키프레임 추가 | E2와 동일 원화. 기체가 처음부터 밝게 보이지 않게 함 |
| E2 | 카메라를 더 멀리 두어 기체를 작게 하고 공간을 넓힌 새 원화 | 이전 기체 화면 크기의 약 60~70%를 목표로 생성. 정확한 비율 실측은 미측정 |
| E2 전환 | 어둠에서 빛이 Go2가 있는 방향으로 들어오며 기체·발밑 공개 | 전체 화면 밝기 상승 대신 국소 이동광. HTML 시안이며 영상은 미제작 |
| E5 | 목표 설비 바로 앞 낮은 콘크리트 턱 추가 | 턱을 넘고 안정된 면에서 촬영으로 이어짐. 프롬프트의 치수는 연출 제안, 실측 아님 |

O2의 표면, O3의 가장자리, O3b의 틈 깊이를 짧게 연결한다. 컷 수 증가만큼 전체 오프닝을 길게 늘리는 것은 아니다. 같은 지형을 반복 설명하지 않도록 각 인서트 길이는 영상 편집에서 조절한다. 원경 HUD·근접 scan 분리와 기존 발 접촉은 유지한다.

새 원화와 프롬프트는 built-in image_gen으로 제작했다.

## 이전 제작 기준 · 선택한 원화를 복원한 7컷

[현재 HTML](output/FOOTHOLD-film-storyboard.html)이 컷 순서의 기준이다. v6의 6칸 이미지를 통째로 최종 오프닝으로 쓰지 않는다. 사용자가 좋다고 한 기존 v3 구도를 원본 해상도로 복원하고, 새 원경과 가까운 scan을 섞었다. 아래 이전 버전은 변경 이력이며 충돌하면 이 절을 따른다.

| 컷 | 장면과 출처 | 정보·전환 |
|---|---|---|
| O1 | v6 첫 정면 원경 | 블랙에서 시작. 작은 이동광에 닿는 부분만 드러남. 손전등 물체 없음 |
| O2 | v3 첫 바닥 질감 근접 | 빛이 자갈과 거친 표면을 드러냄 |
| O3 | v3 두 번째 끊긴 가장자리 | O2의 질감에서 발 디딜 곳이 끝나는 위험으로 전환 |
| O4 | 블랙 MISSION | 배경 없이 임무를 먼저 전달한 뒤 녹색 시야가 돌아옴 |
| O5 | v3 네 번째 녹색 원경 | 공간 여백에 자세·명령·상태 HUD. 멀리 목표와 앞으로 갈 길 |
| O6 | v6 다섯 번째 가까운 지형 scan | 바닥의 점과 메시만. 주변 HUD 없음 |
| O7 | v3 여섯 번째 발 접촉 | 사용자가 다시 올린 선호 구도. 연속 발걸음으로 지나가며 발표로 연결 |

O2는 표면 질감, O3는 단절된 가장자리로 역할을 나눈다. O5와 O6은 넓은 시야에서 가까운 디딤으로 좁혀 간다. O7과 엔딩 E1은 같은 선호 발 이미지를 사용한다. 엔딩 E2~E7의 배경은 유지한다. 밝은 원경은 HTML 하단 T1에 별도 보존해 미경험 험지 설명 자료로 활용한다.

[사용자 조명 참고](https://img.hankyung.com/photo/202402/01.35788243.1.jpg)를 직접 확인했다. 화면 전체를 밝히지 않고 빛이 닿는 작은 부분만 보이는 것이 핵심이다. 현재 O1은 CSS 이동 마스크로 이 의도를 확인하는 시안이며 실제 영상 조명을 완성한 것이 아니다.

### HUD 정보의 의미 점검

- 자세와 속도·회전 명령은 실제 로봇·정책에서 의미 있는 항목이다. ROLL/PITCH는 자세를 읽기 쉽게 표시하는 값이며 actor 입력의 원래 명칭과 동일하지 않다. 명령과 측정 반응은 분리한다.
- 실측 로그가 없는 숫자는 `--`로 비운다. 이전에 넣었던 임의 파형·히스토그램·관절 반응 막대·높이 숫자는 제거했다. 모든 그래픽에 실제 데이터 근거가 있었다고 설명하지 않는다.
- 원형 눈금과 테두리는 화면을 구분하는 디자인이다. 현재 지형 점·메시와 임무 지형도는 개념 표현이며 실제 187개 scan이나 측정 지도가 아니다.
- CV 박스와 특징점은 목표 설비를 인식·촬영하는 시나리오다. 실제 검출 모델 결과나 confidence 수치를 주장하지 않는다.
- REC, 전송 진행률, 수신 완료는 영상 속 임무 단계 표현이다. 실제 녹화·통신 측정 기록이 아니다.

[원경 HUD](output/FOOTHOLD-film-selected-observe.png) · [가까운 scan만](output/FOOTHOLD-film-selected-height.png) · [복원한 발](output/FOOTHOLD-film-selected-foot.png) · [이동광](output/FOOTHOLD-film-selected-light.png) · [촬영 CV](output/FOOTHOLD-film-selected-record.png).

`확인됨`: 브라우저에서 오프닝 7컷, O6 HUD 없음, O5 이전 원화 복원, 수치 공란, Q&A 단독, 모바일 가로 넘침 없음, JS 오류 없음. 이번 수정에는 새 이미지 생성을 사용하지 않았다. 영상·사운드는 아직 제작하지 않았다.

## 이미지 v3

[6컷 수정 보드](assets/opening-storyboard-v3.png) · [생성 프롬프트](assets/opening-storyboard-v3.prompt.txt). built-in image_gen으로 v2와 표지를 참조했다. 가까운 바닥, 지지면의 끝, 다음 디딤, 관측 화면, Go2의 전반부, 발 접촉으로 컷의 역할을 구분했다. 사용자에게 방향 확인을 요청한 상태이며 승인으로 기록하지 않는다.

직접 확인: 첫 컷의 원경이 없어지고 5·6컷도 기체 전반부와 발 접촉으로 거리 차가 생겼다. 4컷의 점 격자는 지지면 위에 놓인 관측 연출이다. 실제 센서 출력이나 187개 height scan의 재현은 아니다. 단절 구간의 폭과 기체의 도달 범위는 영상 시작·끝 프레임을 만들 때 같은 지형으로 맞춰야 한다. 임무 HUD 문구는 아직 미합성이다.

## 최신 v3: 처음부터 Go2의 가까운 시야

사용자는 v2의 지형 위험성은 좋아졌지만 마지막을 제외한 컷의 앵글이 단조롭다고 지적했다. 첫 화면부터 Go2가 보는 가까운 바닥으로 시작한다. 이전의 사람 눈높이 관찰자 POV를 최신안에서 대체한다. 아래 이전 절들은 논의 이력이며 이 절이 우선한다.

| 컷 | 거리·시점 | 시각적 역할 |
|---|---|---|
| 1 | 몸체 높이에서 바로 앞 바닥을 내려다보는 극근거리 POV | 어둠 속 국소 조명으로 표면만 발견 |
| 2 | 단절 가장자리에 다가가 아래를 보는 POV | 발밑 지지면이 끝난다는 위험 인지 |
| 3 | 시선을 조금 들어 가까운 건너편 발판을 보는 POV | 다음 발을 어디에 놓을지 읽음. 목표는 멀리 작은 표식 |
| 4 | 같은 바닥의 관측 화면 | 저채도 녹색, 얇은 카메라 모서리 표시, 약한 입자·스캔 질감, 실제 표면에 붙는 점 격자 |
| 5 | 가까운 외부 측면에서 Go2 전반부를 보여줌 | 앞서 본 시야의 주체를 드러냄. 은색 기체와 남색 공간 복귀 |
| 6 | 발과 바닥 접촉의 극근접 측면 | 첫 디딤의 촉각적 순간에서 종료 |

관측 점 격자는 연출 개념이다. 생성 이미지의 점을 실제 187개 ray 기록으로 표시하지 않는다. 틈에 연속된 지지면이 있는 것처럼 격자를 덮지 않는다. 강한 glitch는 센서 고장처럼 보일 수 있어 제안에서 제외하고, 약한 질감과 화면 프레임으로 카메라 시야임을 전달한다. 센서 모델명·실시간 수치·성공 판정을 임의로 만들지 않는다. 임무 HUD는 지형과 목표가 드러난 뒤 별도 그래픽으로 얹는 계획을 유지한다.

## 추가 설계: 지형을 보고 발을 딛는 감각

사용자는 POV가 Go2의 지형 인식과 보행을 시각적으로 설명할 수 있다고 제안했다. 로봇에 부착한 RGB·Depth 카메라의 흔들리는 시야, 새로 star한 연구 저장소의 LiDAR 처리 시연과 같은 느낌을 원한다. 이 요구는 기존의 손전등 POV와 연결하되 시점 주체를 구분한다.

- 오프닝 앞부분은 현장을 발견하는 관찰자의 시점이다. Go2 등장 뒤 낮은 몸체 시점으로 넘어가 발을 디딜 때의 시야 변화와 지형의 접근을 짧게 보여주는 추가 컷을 제안한다. 기존 6컷 보드에는 이 추가 컷이 아직 없다.
- 카메라는 발 디딤과 몸통 자세에 맞춘 작은 상하·피치·롤 변화를 사용한다. 무작위 흔들림이나 강한 멀미 효과를 보행 표현으로 대신하지 않는다. 가까운 발판은 빠르게, 먼 목표는 안정적으로 움직여 공간을 읽게 한다.
- 한 번의 디딤 전후에 실제 바닥과 겹치는 점·격자가 짧게 나타나고 다시 실제 모습으로 돌아가는 표현을 제안한다. RGB·Depth·LiDAR 화면을 한꺼번에 쏟아내지 않는다.
- 본문의 기술 설명에서 같은 시점과 지형을 다시 사용한다. 카메라 시야, 거리 표현, 현재 정책의 187개 height scan 격자를 순차 비교한 뒤 관측·actor·관절 목표로 연결한다. 이 순서는 설명을 위한 비교이며 RGB에서 depth를 만들고 LiDAR를 거쳐 height scan으로 변환하는 현재 파이프라인이라고 주장하지 않는다.
- 현재 정책의 height scan은 시뮬레이션 ray casting이다. 팀이 추가 보유한 D435i·HESAI-360의 입력으로 배포 정책이 주행한다는 근거는 아직 없다. 실제 기술 설명용 데이터는 같은 시뮬레이션 시점에서 직접 수집하는 것을 우선한다.
- 기존 연구 저장소 조사 문서는 README와 링크 확인 단계다. 센서 시연 영상의 동작은 아직 직접 판독하지 않았으므로 봤다고 주장하지 않는다. 관련 후보는 RESEARCH-REPO-REFERENCES.md의 JEPLO 등이며 구체 컷을 만들 때 해당 영상의 시점·원자료·오버레이를 구분해 확인한다.

이 설계는 추가 제안이다. 사용자 이미지 컨펌 이전 영상 생성 금지는 유지한다.

## 이미지 v2

[수정 스토리보드](assets/opening-storyboard-v2.png) · [생성 프롬프트](assets/opening-storyboard-v2.prompt.txt). built-in image_gen으로 v1과 표지 이미지를 참조해 생성했다. 첫 세 컷의 주변광을 줄이고 손전등 범위만 지형을 드러냈다. 중앙 방향의 통로, 바닥이 사라진 자리, 좁은 디딤을 강조했다. 네 번째 컷은 야간 시야 전환 후보, 마지막 두 컷은 기존 Go2의 질감을 유지한다.

이미지 직접 확인: v1보다 위험을 국소적으로 발견하는 구성이 분명해졌다. 다만 컷별 발판의 정확한 형상과 폭이 완전히 고정된 것은 아니다. 방향 컨펌 후 영상의 시작·끝 프레임 제작 때 동일 지형의 연속성을 맞춘다. 특히 첫 디딤의 도달 거리와 접지 동작은 영상 제작에서 확인한다. 이미지 컨펌 이전에 영상을 생성하지 않는다.

## 최신 수정 방향: POV에서 위험을 발견한 뒤 Go2 등장

v1은 전반적으로 밝고, 넓은 바닥 위 잔해가 보여 발 디딤 선택의 어려움이 약했다. 사용자 요구는 정말 어두운 공간에서 관찰자가 손전등을 들고 이동하며 빛이 닿는 곳만 보는 느낌이다. 우측 소실점은 중앙으로 바꾼다. 구체적인 위험은 바닥의 일부가 사라진 좁은 통로, 끊긴 발판, 서로 다른 높이로 제안한다. 무작정 큰 구덩이나 잔해의 양으로 위험을 대신하지 않는다.

| 컷 | v2 이미지 설계 |
|---|---|
| 1 | 거의 검은 화면. 바로 앞의 윤곽만 희미하게 보임 |
| 2 | POV 손전등이 가까운 끊어진 바닥 끝을 비춤. 주변은 검게 가림 |
| 3 | 조금 전진한 시야. 좁게 남은 통로와 높이 다른 발판을 비추고 정중앙 멀리 목표가 나타남 |
| 4 | 같은 길에서 저채도 녹색 야간 시야로 짧게 전환. Go2가 진입하기 시작하는 후보 |
| 5 | 기존 보드에서 좋았던 은색 Go2와 남색 공간으로 복귀. 위험한 길 앞의 기체를 측후면에서 보여줌 |
| 6 | 짧은 틈 너머 견고한 디딤 위치에 앞발을 놓는 첫걸음. 임무 완료 전 멈춤 |

‘그런 공간을 지나가면서 Go2가 나오고 지금 화면이면 나쁘진 않긴 하거든’이라는 사용자 보충에 따라 기존 후반부의 Go2 질감과 구도를 살린다. 야간 시야를 영상 전체에 적용하는 것은 제안하지 않는다. 녹색 전환은 실제 탑재 센서 기능을 입증하는 장면이 아니며, 최종 채택 여부는 이미지 컨펌에서 결정한다.

현재 표는 최신 제안이다. 아래 v1 이미지와 최초 컷 구성은 변경 이력으로 보존한다. 이미지 컨펌 전 영상 생성 금지는 그대로다.

## 이미지 v1

[6컷 스토리보드 이미지](assets/opening-storyboard-v1.png). 왼쪽 위부터 오른쪽으로 읽고 다음 줄로 내려간다. 표지 원화를 참조해 built-in image_gen으로 생성했다. [생성 프롬프트](assets/opening-storyboard-v1.prompt.txt).

직접 이미지 확인: 여섯 컷의 색·공간·기체 방향은 연결되지만, 첫 컷에서도 붉은 목표가 이미 보인다. 원안처럼 목표가 나중에 드러나게 할지는 다음 조정에 남긴다. 임무 HUD의 문구는 아직 합성하지 않았다. 정적 발 자세는 개념 이미지이며 실제 보행 동작과 접지 품질은 영상 단계의 별도 확인 대상이다. 이 보드 자체를 확대·이동하는 것으로 영상 제작을 대신하지 않는다.

## 고정할 이야기

사용자 원안의 순서는 어둠과 연기, 한 줄기 빛, 움직이는 헤드라이트가 드러내는 험지, 멀리 붉은 점등의 목표와 임무 HUD, Go2 등장, 첫걸음에서 컷이다. 표지에서 사용한 은색 Go2와 산업 공간의 분위기를 유지한다. 표지 이미지 자체를 모든 컷에 반복 확대하는 방식으로 영상을 대신하지 않는다.

인사 멘트가 끝난 뒤 영상을 시작한다. 첫 디딤에서 멈춘 다음 발표자가 “그럼 우리 FOOTHOLD 프로젝트의 첫걸음을 함께 시작하겠습니다.”라고 말하고 미경험 험지 소개로 넘어간다. 엔딩은 같은 공간·기체·목표를 다시 보여주며 아직 검증하지 않은 미래 활용 개념임을 구분한다.

## 제안하는 컷과 호흡

전체 길이 약 22초는 제작 제안이며 확정값이 아니다. 컷 사이 연속성을 확보한 뒤 실제 재생 시간을 조정한다.

| 컷 | 시간 제안 | 화면과 동작 | 전달할 것 |
|---|---|---|---|
| 1 | 0~3초 | 거의 보이지 않는 공간. 낮게 흐르는 연기와 멀리 구조물의 윤곽 | 어디인지 알 수 없지만 진입이 쉽지 않은 공간 |
| 2 | 3~7초 | 빛이 바닥을 천천히 훑음. 깨진 콘크리트와 높이 차가 드러남 | 이동할 길의 조건 |
| 3 | 7~11초 | 시야가 앞으로 열리며 틈 너머 붉은 목표 점등이 보임 | 가야 할 곳과 그 사이의 험지 |
| 4 | 11~14초 | 최소한의 임무 HUD 등장. 후보 문구: ‘목표 지점 접근 · 현장 상태 확인’ | 왜 이 길을 가야 하는가 |
| 5 | 14~18초 | 같은 Go2가 프레임에 진입해 지형 앞에 섬. 카메라는 로봇과 목표의 관계를 유지 | 임무를 맡은 주체 |
| 6 | 18~22초 | 발이 들리고 가까운 안전한 디딤 위치에 닿는 순간. 지형 전체를 통과하기 전에 정지 | 우리의 첫걸음과 발표의 시작 |

HUD는 생성 영상에 글자를 맡기지 않고 별도 편집 요소로 제작한다. 임무 문구는 현재 연구가 실기 자율 임무까지 완성했다는 뜻으로 사용하지 않는다. 픽셀 진행 표시는 이 영상과 분리한다.

## 컷 사이에서 유지할 것

- 로봇의 형상·다리 수·센서 하우징·은색 외장. 임의로 모듈을 붙이거나 다른 기체로 바꾸지 않는다.
- 바닥의 주요 틈·붉은 목표 위치·조명 방향. 매 컷마다 다른 공간으로 바뀌지 않는다.
- 첫발은 실제 접지의 순서가 읽히게 한다. 보행 정책을 검증한 실측 영상으로 표시하지 않는다.
- 소리는 낮은 공간음과 발 디딤을 중심으로 한다. 발표 멘트를 덮는 큰 효과음은 피한다.
- 로고와 공식 슬로건을 영상 생성 모델이 다시 그리게 하지 않는다. 필요한 경우 정본 자산을 편집 단계에 얹는다.
