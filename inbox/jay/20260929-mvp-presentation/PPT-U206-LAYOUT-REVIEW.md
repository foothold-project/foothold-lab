## 2. 빈 공간과 설명 흐름

- **23쪽이 후반부에서 가장 먼저 통합을 검토할 페이지다.** `.method-proof`는 (64,201,1472,205.4), `.version-process`는 (64,461.4,1472,66), `.finding`은 (64,557.4,1472,53.3). 핵심 내용이 y611에서 끝나 y611~810 약199px가 비어 있다. 기획의 FIVE RECIPE 약속과 현재 채택 방식의 차이는 반드시 보존해야 하지만, 현재는 문장 두 덩어리와 프로세스 한 줄로 한 장을 쓴다. 22쪽 보상 비교의 결과를 받아 `좋아 보인 후보 → 전체 재평가 → 채택` 브릿지로 압축하거나, 24쪽 평가 기준 도입과 통합하면 설명 호흡을 줄일 수 있다. 단순 삭제하면 기획발표와의 연결이 사라진다.

- 15쪽 rough6와 새 지형 → 16쪽 입력 결함 → 17쪽 학습 조건 → 18쪽 개선과 정지 한계 → 19쪽 명령 확대 퇴행 → 20·21쪽 지형·명령 재설계 → 22쪽 보상 비교의 인과는 연결된다. 성공만 나열하는 구성은 아니다.

- 28쪽 성공 시연 다음 29쪽 정지 개선, 30~32쪽 회전·난도·시드 한계로 이어져 과장을 줄인다. 32쪽 실패 영상이 남아 있어 남은 과제가 수치만으로 끝나지 않는다.
- 33~36쪽은 PoC 증거 → 순정 보행 기반 항법 구조 → 다음 연구 질문 → 세 흐름의 관문으로 연결된다. 같은 내용만 반복하는 구간은 아니지만, 35쪽과 36쪽의 연구 과제 문장은 발표에서는 재독하지 않고 일정으로 연결하는 편이 자연스럽다.

## 구현자 후속 조치

39장 검토 이후 37장으로 통합했다. 기존17쪽 초기훈련은15쪽으로,23쪽 채택과정은보상비교쪽으로 합쳤다.13쪽 그림 높이를 줄여 하단넘침을 해소했다.15쪽 hero는 평가gap이 아닌 학습forward_gap 이미지로 바꿨다. 기존21쪽 표22px,27쪽 범례20px,32쪽 시드라벨20px로 확대했다. 이 내용은 구현자 기록이며 위 독립검토 범위를 소급해 바꾸지 않는다.
