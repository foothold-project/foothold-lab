## 1. 검증 대상과 방법

[의뢰서](TASK-U206-REVIEW.md), [U206 요구와 승인 범위](PPT-REVISION-U206.md), [연구 근거 목록](PPT-U206-EVIDENCE.md), [미디어 목록](PPT-U206-MEDIA.md), [Go2 제작 계획](PPT-U206-GO2-PLAN.md)을 읽었다. 이 문서들의 완료 주장과 기존 `u206-verification.json`·제작자 스크린샷을 통과 증거로 쓰지 않았다.

대상은 [현재 발표 HTML](output/FOOTHOLD-MVP-cover.html)의 **37쪽 전체**다. 각 장의 본문·발표자 노트·미디어 연결을 읽고 직접 화면을 캡처했다. 3·6·8·10·11·12쪽은 초기 상태를 포함한 클릭 단계들을 따로 검사했다. 기존 통과한 산업 사례 공식 출처와 U205의 원 USD·정책 구조 감사 전체는 반복하지 않았다. 이번에 바뀐 연구 집계와 Blender v5 저장 씬, 영상 컷, 화면·인쇄 동작을 새로 확인했다.

세 HTML을 직접 비교했다. 최초본에서 두 번째 본으로의 차이는 print 명시 규칙 추가, 두 번째에서 최종본으로의 차이는 `.policy-page .content img.policy-front` 규칙 추가였다. 변경된 화면을 재검사했고 작성 직전 SHA도 최종 판정본과 같았다. 따라서 처음 검사한 다른 장의 결과를 새로 바뀐 장의 결과와 혼동하지 않았다.

Chrome `file://` 실행, 실제 키보드 다음·이전, DOM/CSS 계산값, Canvas 상태, PyAV 영상 디코딩, 새 PDF 렌더를 사용했다. 기준 화면은 1600×900, 경계 검사는 1280×720·1366×768·1920×1080이다. Blender는 `--background --disable-autoexec`로 저장 씬을 읽었으며 재생성·저장하지 않았다.

**원본 수정·빌드·pull·브랜치 변경·이슈 생성·commit·push는 하지 않았다. 저장소 작성 파일은 이 파일 하나다.** 검사 스크립트·JSON·스크린샷·PDF는 `%TEMP%/u206-independent-review/`에만 두었다.

## 2. 차단 문제와 최종 해제 판정

**최종 판정: 통과. 현재 남은 차단 문제 0건.** 아래 세 수정은 구현자의 설명 대신 실제 렌더와 계산값으로 확인했다.

### B1. 하드웨어 print 로봇 가시성: 통과

사용자가 전달한 print 수정본을 새로 열어 10쪽 PDF를 생성했다. 첫 진입 상태와 화면에서 10쪽 마지막 단계까지 진입한 상태 양쪽을 검사했다.

- `.hardware-page .technical-robot`: `display:block`, `visibility:visible`, `opacity:1`.
- 크기 640×620, 장 내부 위치 left 480 / top 216.
- PDF에서 정면 로봇과 좌우 카메라·LiDAR 설명 및 연결선이 함께 보인다. 로봇이 사라지거나 설명 글자를 덮는 현상은 재현되지 않았다.
- 최종 policy-front 수정본에서도 위 print 계산값이 유지된다.

### B2. 정책 print 정지 이미지 width:100% 충돌: 통과

- `.policy-v5-print`: 770×577.5, left 415 / top 255, `display:block`, `visibility:visible`, `opacity:1`.
- 새 11쪽 PDF에서 머리가 왼쪽인 측면 로봇과 격자가 가운데에 들어간다. 관측 버스, 좌측 Critic, 우측 Actor, 하단 설명을 가리지 않는다.
- 첫 상태와 다른 장의 마지막 단계 방문 후 출력에서 모두 확인했다. 화면용 Canvas·정면 이미지 대신 인쇄용 정지 이미지가 보인다.
- 최종 policy-front 수정본에서도 같은 print 크기와 가시성을 직접 재확인했다.

### B3. 11쪽 stage 0 정면 로봇의 발표 화면 잘림: 통과·해제

이 검수에서 실제로 재현한 문제다. print 수정본에서도 화면의 `.policy-front` 계산값이 **1600×900, left 530 / top 247**이었다. 이미지 영역이 오른쪽 2130, 아래 1147까지 뻗어 기체의 오른쪽과 다리가 잘렸다. 선언된 540×510보다 `.content img`의 공통 크기 규칙이 우선했다.

마지막 재빌드에서 계산값이 **540×510, left 530 / top 247**로 바뀌었다. 새 스크린샷에서 정면 기체 전체가 보이고 왼쪽 질문과 겹치지 않는다. 세 검사 해상도에서 11쪽 첫 상태 및 나머지 기술 장면의 클릭 상태를 다시 검사하여 화면 경계 초과가 없음을 확인했다. print 규칙도 유지된다. **B3 해제.**

- `sim/policy/gap_env_cfg.py`에서 기존 여섯 지형 합 0.90, forward_gap 0.10, x 명령 0.5~1.5, y·yaw 0을 직접 확인했다. 내리막 계단과 내리막 경사가 기존 rough6에 포함된다. 15쪽 이미지·이름·설명은 ‘기존 지형은 모두 솟은 장애물’이라는 오류를 피한다.

- 보상 후보 CSV에서 `v2b-r` 4454, `v2g2-feetair01` 4521, `v2g-feetair1` 4468 / 각 4800을 다시 셌다. 각 manifest의 실제 체크포인트 폴더 `params/env.yaml`에서 `feet_air_time` weight **0.01·0.1·1.0**을 읽어 후보 이름과 대조했다. 표시 92.79·94.19·93.08%와 일치한다.
- `feet_air_time`을 발 높이 직접 보상이라고 설명하지 않는다. 21쪽은 병렬 후보 탐색→전체 지형·명령 재평가→버전별 채택을 남기고, 이번 비교를 단일 학습 시드의 관찰로 제한한다. 15쪽 통합 노트에 첫 전진 학습과 이후 명령 문제로 이어지는 멘트도 남아 있다.

## 5. 영상과 인쇄

2쪽은 표지에서 실제 다음 키를 눌러 `paused=false`, `muted=false`, 재생시각 증가를 확인했다. 35쪽도 34쪽에서 다음 키로 진입하여 같은 결과를 확인했다. 브랜드 영상 실제 URL은 별도 `20260930-mvp-brand/_out/review/FULL_v6.mp4`, 길이 83.588초다. 도입 영화는 80.625초였다. 원음 재생 설정·타임라인 검증이며 현장 스피커 청취 검증은 아니다.

17·18·19·26·27·28·29·30·31쪽 실험/PoC 영상은 직접 진입했을 때 음소거·자동 재생·반복 상태였다. 장을 떠난 모든 영상이 정지했다. 12쪽 병렬 학습 시연은 클릭으로 재생되는 별도 연출이며 `loop=false`다. 이를 실험 비교 영상의 반복 검증과 섞지 않았다.

| 실제 디코딩한 컷 | 길이 / fps | 원본 대응 확인 |
|---|---|---|
| stop NVIDIA·v1·v2 | 각각 6.74초 / 50fps | 첫 프레임 원본 2.00초, 끝 근처 원본 8.66초. 표기 구간 2.00~8.74초와 일치 |
| turn v2 | 9.00초 / 50fps | 첫 프레임 원본 9.00초, 끝 근처 원본 17.92초. 표기 구간 9.00~18.00초와 일치 |

원본 `docs/assets/video/v2/`와 컷의 앞·뒤 프레임을 직접 디코딩하여 대조했다. RGB 평균 절대차는 0.46~0.74/255로 재인코딩 차이 수준이다. JPEG poster도 실제 컷의 첫 프레임과 대응한다(평균 절대차 약 1.39~1.44/255). v1 정지 컷 끝 근처에서 실제로 뒤집힌 자세가 보인다. `per_env.json`에서 stop 낙상은 NVIDIA 0/64, v1 13/64, v2 0/64로 다시 셌다. 영상 한 판을 64판 집계와 동일시하지 않고, 무낙상이 완전 정지를 뜻하지 않는다는 문구도 남아 있다.

새 PDF는 37쪽이다. 기술 설명·병렬 학습·실험 비교·실패·3DGS·브랜드·Q&A·원본 클로징을 렌더해 확인했다. 지정된 기술 이미지와 비디오 poster가 백지로 빠지거나 수치·설명을 덮는 차단 문제는 없다. 마지막 화면용 policy-front 변경은 print에서 숨겨지는 요소에만 적용되고, 최종 print 계산값도 유지됨을 확인했다.

## 6. 선택 보강과 확인 범위의 한계

1. **추가 모듈 장착은 후속 미완료 작업으로 유지.** 실제 메시·장착 위치를 확보하기 전에는 현재 기기 소개를 완성된 장착 연출이나 실기 디지털 트윈이라고 부르지 않는다. 현재 발표는 그 완료를 주장하지 않으므로 차단으로 잡지 않았다.
2. **제품 분리 이미지의 원본성.** Elios·B2W·Hesai·Orin의 식별성은 확인했지만 imagegen을 거친 분리 이미지의 미세 외형을 공식 원본과 픽셀 단위로 검증한 것은 아니다. 측정·장착 설계 근거로 쓰지 말고, 후속판에서는 공식 제품 컷으로 교체하거나 가공 사실을 근거 문서에 계속 남기는 편이 좋다.
3. **인쇄용 영상 정지화면 정리.** 일부 PDF poster에는 영상 컨트롤 모양이 남는다. 내용 판독을 막지 않으나, 배포용 인쇄본을 다듬을 때 영상별 정지 이미지를 일관되게 쓰면 더 깔끔하다.
4. **발표장 가독성.** 주요 문장은 커졌지만 footer·출처·진행표시 등 작은 보조 글자는 남아 있다. 세 브라우저 해상도에서 잘림은 없었으며, 실제 투사 거리와 장비에서의 가독성은 미측정이다.

검사한 핵심 수치·작동·화면 기준으로는 **잔여 차단 없음**이다. 이 판정은 위 최종 SHA의 발표 자료 검수이며, 실제 로봇 성능 재실험·모든 프레임의 정량 충돌 검사·현장 음향 검증·새 디자인 승인을 대신하지 않는다.
