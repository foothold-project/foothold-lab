## 범위와 화면 원칙

사용자는 전문의 `>>> 내용 >>>`을 이전 에이전트 답변을 기록한 메모라고 구분했다. 해야 할 일이나 전부 한꺼번에 처리할 뜻은 아니다. Go2 제원 설명 전까지와 엔딩을 먼저 작업한다. 중간에 원하는 이미지·애니메이션은 필요시 추가 설명하고 제안을 검토한다.

`#`은 HTML 슬라이드 단위, 대부분의 문장은 발표 멘트다. `???`는 맥락에 맞는 설명을 채울 부분, `*`는 AI 실행 지시다.

- 화면을 밀도 있게 사용한다. 이미지·인포그래픽·그래프·중요한 수치를 적극 활용한다.
- 같은 어셋을 이어 쓰는 Prezi 방식. 포인터 다음 버튼에 맞춰 움직이고 설명 위치에서 멈춘다.
- 레이아웃 규칙을 앞뒤에서 통일한다. 좌측 상단은 섹션, 우측 상단은 픽셀 Go2가 험지를 걸어가는 진행 표시. 지형 아래 진행 맥락 표시.
- 매 페이지에서 전달 메시지·시각적 근거·다음 페이지로 이어지는 질문을 함께 본다.

## 도입 원고와 장면 순서

### 표지

사용자 원고:

> 오늘 발표를 하기 앞서 이번 프로젝트는 저희에게 굉장히 어려운 프로젝트였습니다.
> 저희는 사족보행 로봇의 보행을 연구하고 탐구하는 것이 마치 아기가 한걸음 한걸음 발걸음을 내딛으면서 세상을 향해 걸음마를 시작는 것과 닮았다고 생각했습니다.
> 아직은 어린 아기가 세상을 향해서 내딛는 한걸음을 지켜보는 아빠의 마음이랄까요?
> 이런 마음을 먼저 공유해드리면서 그럼 우리의 도전적인 첫 발걸음은 어떻게 시작하려 했는지 그 과정을 소개하겠습니다.
> 안녕하세요 저는 "4족보행 Unitree Go2 미경험 험지 적응 정책 프로젝트"를 발표를 맡게된 FOOTHOLD 팀장 오흥재 입니다.
> 그럼 오늘 본격적인 발표하기 앞서 오늘 발표에서는 우리 프로젝트에서는 무엇을 집중하고 있고, 어떤 과제를 풀려고 하는지 '실제 시뮬레이션을 통해서 얻은 영상'을 통해서 간단히 먼저 시청하고 오시겠습니다.

### 전체 영상

기존 O/E 분할 상영 계획을 변경했다. 초반에 완성된 전체 영상을 보여 핵심 목적을 전달한다. 파일은 assets/film-master-v8.mp4. 분할 영상은 보존한다.

> (시청 도중) 사실 우리가 프로젝트를 통해서 하고자하는 목적의 메시지는 매우 단순합니다.
> "사족 보행 로봇을 어느 환경이든 잘 걷게하는 것 입니다."

U203 사용자 정정 원문:

> 완성된 영화는 Higgsfield로 만든 콘셉트 영상이므로 “실제 시뮬레이션에서 얻은 영상”이라고 소개하면 안 됩니다. => 넘어갈 것. 이유는 내가 직접 Isaac Sim 에서 학습한 걸 바탕으로 만든 것이기 때문에 문제 없음.

반영: 제작 기원 논의를 반복하지 않는다. 발표 멘트는 사용자의 취지를 살려 **“저희가 Isaac Sim에서 학습한 내용을 바탕으로 만든 영상”**으로 연결한다. 생성 영상을 실제 실험 성공률의 측정 증거로 사용하지는 않는다.

### 픽셀 Go2와 질문

정면 Go2 픽셀 애니메이션이 중앙에서 걷고 돌고 뛰고 앉는다. 로봇 아래에 질문 키워드가 위로 슬라이드 등장하고 로봇은 위로 이동한다. 사용자 원문은 ‘3가지’라고 했지만 아래 네 질문을 제시했다.

> 왜 로봇을 잘 걷게 하는 것이 중요할까요?
> 왜 우리는 왜 다양한 이동 로봇 중에서도 사족보행 로봇에 집중하고 있는 것일까요?
> 왜 로봇을 잘 걷게 하는 것은 어려운 것 일까요?
> 왜 미경험 험지 탐험 정책 적응 일까요?

제작 정리: 왜 잘 걸어야 하는가 / 왜 사족보행인가 / 낯선 지형에서 잘 걷기가 왜 어려운가. 마지막 두 원문 질문의 의미를 세 번째 질문에 통합한다.

### 같은 험지 이미지: 임무

원경 이미지 전체. ‘이 길을 건너 점검 지점까지 가려면?’ 목표에 MVP 영화 최종 타게팅과 같은 계열 MISSION HUD를 배치한다.

> 너무나 당연한 질문이겠죠? 시청 자료에서 봤듯이, 로봇에게 특정 임무가 주워지고 그 임무를 수행하기 위해서는 "경험하지 않은 험지"를 기본적으로 '잘 걷는 것'이 첫번째 필수 수행 능력 입니다.

### 같은 험지 이미지: 낯선 조건

제목 ‘미경험 험지란 무엇일까요?’ 포인트·라인·설명 박스가 이미지의 해당 위치와 연결된다. 재료 특성: 마찰·재료 강도·미끄러움. 형태: 단차·층·경사·불규칙성. 같은 이미지에서 다른 애니메이션으로 이어간다.

> 그렇다면 미경험 험지란 무엇일까요?
> 현실에는 마찰·재료 강도·미끄러움도 존재합니다. 로봇은 '학습 때 경험한 조건을 벗어나도, 다음 발을 디딜 수 있을까요?'

재료 특성은 이 이미지에서 실제 측정했다는 뜻이 아니고, 이번 MVP가 모두 검증했다는 뜻도 아니다. 발언을 끊는 경고문보다 캡션·발표 메모에서 범위를 명확히 한다.

### Go2 중심: 실제 산업의 임무

assets/go2-reference/go2-character-sunburst-v1.png의 정면을 활용한다. 원 안의 Go2 주변으로 산업별 원·아이콘·연결선이 등장한다. 그룹을 함께 축소하고 중앙에 고정해 다음 페이지로 연결한다.

> 실제 사족 보행 로봇은 여러 특수 임무를 가지고 다양한 산업군에서 활용되고 있습니다.

국내 근거를 조사해 소방·안전·기타 산업을 채운다. 임무와 역할이 읽혀야 한다. 해외 사례 하나를 포함해도 된다. 경제 효과도 조사 근거로 연결한다. 소방 수요 공고는 도입 실적과 구별한다.

### 같은 Go2 원: 이동 방식 비교

드론은 왼쪽, Go2는 가운데, 바퀴형 로봇은 오른쪽 같은 행의 원 안에 배치한다. 바퀴·다리 결합, 이족보행도 맥락상 설명한다.

> 그럼 다양한 이동 로봇이 있는데 꼭 사족 보행 로봇이어야할까요?
> 맞습니다. 이동로봇에는 다양한 몸체를 가진 로봇이 많습니다. 드론, 사족보행 로봇, 바퀴와 다리가 달린 로봇, 이족 보행 등...

각 방식의 장단점·특화 임무를 밀도 있게 채운다. 단순히 다른 로봇은 험지를 못 간다고 주장하지 않는다.

### 같은 Go2 원: 선택 이유

> 우리는 발을 옮겨 지지점을 바꾸는 이동에 주목했습니다.
> 이러한 이유로 우리는 발을 하나씩 옮길 수 있고 지지점을 바꾸면서 안정된 무게중심을 가져갈 수 있고, 효율적인 에너지 활용을 하면서 '사용자의 임무'를 수행할 수 있기 때문에 '사족 보행 로봇'을 선택하여 실험을 진행하고자 했습니다.
> 그럼, 왜 사족 보행 로봇은 잘 걷게 하는 것이 어려운 것이고, 우리가 집중해서 풀어갈 과제가 어떤 것인지 설명 드리겠습니다.

제작 해석: 발 디딤을 선택하고 균형을 유지하는 문제에 초점. 사족보행이 모든 이동 방식보다 에너지 효율이 높거나 항상 안정적이라는 일반 명제로 확대하지 않는다.

### Go2 소개 진입

같은 정면 Go2가 중앙으로 커지고 원 테두리는 선을 따라 사라진다. 이 장면에서 Blender 자산으로 연결한다. 센서에서 어떤 관측을 얻는지, 어떤 명령(코드)을 받는지, 관절·액추에이터 제어가 필요한지 보여준다. 다양한 정보를 복합적으로 제어해야 하므로 잘 걷는 것이 어렵다는 의미다. 우선 여기까지 수정한다.

## 이후 중간부를 위한 메모와 기술 계획

이 구간은 이번에 전부 완성할 순서가 아니다. 흐름은 ‘왜 필요한가 → 무엇을 보고 어떤 선택을 했는가 → 무엇이 달라졌고 어디까지 확인했는가 → 그래서 다음에 무엇을 해야 하는가’.

| 기획에서 약속한 것 | MVP에서 답할 것 |
|---|---|
| 현재 정책의 실력·실패 관찰 | 어떤 실패였고 왜 gap부터 해결했는가 |
| 다섯 실패 레시피 탐색 | 무엇을 배웠고 왜 버전별 채택·재평가로 바꿨는가 |
| 지형 적응 개선 | 입력 처리·지형·명령·보상을 왜 바꿨고 무엇이 개선·퇴행했는가 |
| 보행·Digital Twin·실기 항법 연결 | 어디까지 했고 무엇을 끝까지 병행하는가 |

다음 버튼 → 정해진 동작 → 설명 위치에서 정지 → 다음 버튼. 이전 버튼으로 복원. GSAP tweenTo 참고: https://gsap.com/docs/v3/GSAP/Timeline/tweenTo()/

| 어셋 | 제작 방식 |
|---|---|
| 정면·턴테이블·분해·관절 | 실제 USD/메시 기반 Blender |
| 클릭 재생·정지 | 프레임 시퀀스·Canvas·GSAP |
| 장비·관절축·명령 화살표·연결선 | 부품 위치에 동기화된 HTML/SVG |
| Actor·Critic·입출력·학습 | Manim 모션, 같은 클릭 단계 |
| height scan·관측·출력 | 같은 Isaac Sim 실행의 영상·데이터 |
| 우측 상단 진행 | 픽셀 Go2 걷기·틈 넘기·오르기 |
| 성능·비교 | 원자료 그래프·실제 실험 영상 |

Go2 설명의 단계(한 단계가 반드시 한 장은 아님): 정면 정지 → 턴테이블 후 정지 → 몸통·다리·장착 부품 분해와 연결 위치 → 한 다리 3관절에서 전체 12관절 → 기본 센서·추가 모듈 → 재조립된 기체의 전후·횡이동·회전 축. ‘그렇다면 무엇을 먼저 가르쳐야 했을까요?’로 실패 진단과 연결한다.

사용자 실행 지시: Blender MCP 연결, Exploded-view 설명·적용, Go2 USD의 참조와 메시 가져오기. 자산 확보 → 연결 확인 → 정면·턴테이블·분해·12관절 한 구간 제작 → 기존 HTML에서 클릭 재생·정지·되돌리기 검증.

참고: https://github.com/blender/blender · https://github.com/ahujasid/mcp-for-blender . Higgsfield /Exploded-view는 부품을 벌려 연결 구조를 보여주고 다시 조립하는 애니메이션이다. 원래 메시 내부에 없는 부품을 발명하지 않는다.

사용자가 인용한 기존 감사의 미완료: Manim 정보 흐름은 정적 HTML뿐, 픽셀 실제 동작 없음, Go2 분해는 참조·설계뿐, 실물→시뮬 전환 미구현, 보행 동기화 관측/출력 미구현, 4096환경 줌아웃 미구현, 이동방식별 동일현장 임무 애니메이션 미구현. 이 표는 인용 당시 상태이며 새 작업의 완료 증거가 아니다.
