## 1. 같은 로봇으로 연결하기 위한 기준

페이지마다 다른 정면 이미지를 바꾸어 보여주는 방식은 중단한다. 현재 확보한 **실제 USD 기반 `assets/go2-blender/go2-front-v4.png`**를 공통 정면으로 삼고, 그 이미지를 만든 `go2-technical-v4.blend`의 기체·자세·재질을 이어 쓴다. 도입의 작은 원형 로봇, 산업 사례 중앙, 이동 방식 비교, 제원 소개 확대, 정책 소개 시작이 같은 기체로 이어져야 한다.

확인된 원본은 Isaac Lab의 `UNITREE_GO2_CFG`가 가리키는 [Go2 USD](https://omniverse-content-production.s3-us-west-2.amazonaws.com/Assets/Isaac/5.1/Isaac/IsaacLab/Robots/Unitree/Go2/go2.usd)와 [참조 메시](https://omniverse-content-production.s3-us-west-2.amazonaws.com/Assets/Isaac/5.1/Isaac/IsaacLab/Robots/Unitree/Go2/Props/instanceable_meshes.usd)다. `assets/go2-blender/geometry-manifest.json`, `joints-source.json`에 원본 형상과 관절을 기록했다. 시각 메시 17개, 회전 관절 12개를 사용한다. ## 2. 클릭별 장면 설계

한 번 클릭하면 아래 목표 상태까지 진행하고 멈춘다. 발표자가 설명하는 동안 자동으로 다음 상태로 넘어가지 않는다. 이전 클릭은 해당 상태를 즉시 복원하거나 역재생한다. 프레임 수는 24fps 기준 제작 초안이다.

| 단계·권장 길이 | 보여줄 동작 | 정지했을 때 전달할 정보 |
|---|---|---|
| 정면 공개 · 정지 | 앞 페이지의 같은 Go2가 커지며 기술 설명 자리로 이동 | 오늘 설명할 동일 기체 |
| 턴테이블 · 72프레임 | 몸체 중심을 기준으로 부드럽게 회전. 네 다리와 몸통을 확인하고 전방 사선에서 정지 | 몸체와 네 다리의 구조 |
| 네 다리 분리 · 48프레임 | FL·FR·RL·RR 각각 hip/thigh/calf/foot를 하나의 연결된 묶음으로 유지하고 몸통에서 벌림. 부착 지점 연결선 유지 | 다리마다 세 회전 관절이 있다는 다음 설명의 준비 |
| 기본 센서 · 36프레임 + 설명 정지 | 네 다리가 재조립된 뒤 전면 센서 쪽으로 카메라 접근. 전면 카메라와 LiDAR 위치를 순차 강조 | 장비가 얻는 정보. LiDAR 스캔 원리는 별도 작은 도식으로 연결 |
| 추가 모듈 · 모듈당 24~36프레임 | D435i → Orin NX 16GB → HESAI-360 순서로 역할과 위치 설명 | 깊이 관측, 계산, 주변 거리 관측의 역할 차이. 실제 동시 장착 구조는 확보 자료 범위 내에서만 제작 |
| 한 다리 관절 · 축당 36~48프레임 | 앞 왼쪽 다리를 확대하고 hip → thigh → calf 실제 회전축과 링크 동작 강조 | 한 다리 3자유도. 해당 링크와 함께 움직이는 축 |
| 전체 12관절 · 36프레임 | 같은 다리에서 전체 기체로 복귀하며 네 다리의 대응 관절을 순서대로 표시 | 3 × 4 = 12개 위치 목표를 함께 조절해야 함 |
| 명령 · 축당 36~48프레임 | 조립된 몸체 중심 +X·+Y·+Z 표시 후 전후·횡이동·yaw 회전 예시 | 명령은 `v_x`, `v_y`, `ω_z`. 실제 걸음·실험 결과는 뒤의 시뮬레이션 자료로 연결 |
| 정책 소개 연결 · 48프레임 | 동일 기체의 정면에서 머리가 화면 왼쪽인 측면으로 카메라 이동. 발 주변 격자와 관측 흐름 등장 | 장비 소개에서 현재 정책이 실제 사용하는 입력으로 초점 이동 |

네 다리 분리 시 각 다리 내부 관절 계층과 기존 자세를 보존한다. 초기 이동량은 몸체 좌우 0.12~0.18m 범위에서 화면 가독성을 보고 정한다. 원본에 없는 내부 기어·모터 단면·케이블을 만들지 않는다. 재조립 후 원래 위치와 자세가 수치적으로 일치해야 한다.

기존 v4 `forward/lateral/yaw` 클립은 방향을 보여주는 기체 이동 도식이다. 접지된 보행 동역학이나 정책 평가 영상으로 설명하지 않는다. 발이 미끄러져 보이는 문제가 생기면 실제 모델은 제자리에 두고 명령 화살표와 좌표축만 움직이는 구성이 낫다.

## 3. LiDAR 회전과 추가 모듈의 확인 범위

**L2 내부 회전은 공식 근거가 있다. 외부 보호 하우징 전체를 돌리는 근거로 확대하면 안 된다.** Unitree L2 설명서는 고속 모터가 반사경을, 저속 모터가 측정 코어를 회전시켜 공간을 스캔한다고 설명한다. 현재 USD에서는 별도 회전 부품으로 분리된 LiDAR 메시를 확보하지 못했다. 따라서 기본안은 기체의 센서 외형을 고정하고 스캔 방향·점군의 누적을 애니메이션으로 보여주는 것이다. 내부 회전 원리는 공식 구조 도식을 작게 병치할 수 있다. [Unitree L2 공식 사용자 설명서 v1.1, 인쇄 3·6쪽](https://oss-global-cdn.unitree.com/static/Unitree%204D%20LiDAR%20L2%20User%20Manual.pdf).

`GO2-HARDWARE-REFERENCE.md`의 팀 장비 L2 표기는 사용자 제공 구성에 근거한다. 원 USD의 전면 `radar` 프레임만으로 그 모델의 세대가 L2임을 독립 검증한 것은 아니다. 발표자 메모에는 근거 수준을 유지한다.

| 추가 장비 | 지금 확보된 것 | 실제 장착 애니메이션에 더 필요한 것 |
|---|---|---|
| D435i | 사용자 보유 확인, 공식 소개 영상의 전면 상부 장착 모습 | 해당 카메라 메시·치수, 실제 브래킷과 장착 자세 |
| Orin NX 16GB | 사용자 보유 확인, 모듈 소개 영상 | 보드 자체인지 캐리어·케이스 포함 제품인지 식별, 실제 외장 메시와 위치 |
| HESAI-360 | 사용자 보유 확인, 공식 영상의 상부 장착 모습 | 정확한 Hesai 모델명, 치수·메시, 케이블·브래킷과 다른 모듈의 동시 배치 |

현재 프레젠테이션 자산과 확보한 Go2 USD 범위에서 위 세 장비의 독립 3D 메시를 확인하지 못했다. PC 전체에 없다는 뜻은 아니다. 원본이 없는 상태에서 일반 상자·원통을 실제 장비처럼 장착해 완성하지 않는다. 해당 단계는 우선 **공식 모듈 장착 이미지와 연결선**으로 설명할 수 있으며, 정확한 원본 확보 뒤 동일 카메라의 3D 장착 장면으로 교체한다. Orin은 관측 센서가 아니라 계산 장치다. 영상의 다른 선택 사양 MID-360·로봇 팔은 추가하지 않는다.

추가 장비 보유와 현재 정책 연결 완료를 구분한다. 현재 187개 높이 스캔은 시뮬레이션 RayCaster이며 D435i 또는 HESAI 원시 점군을 Actor에 바로 연결하는 선을 그리지 않는다.

## 4. 정책 페이지의 실제 모델과 17×11 격자

모델 좌표는 앞 +X, 왼쪽 +Y, 위 +Z다. 정면에서 카메라를 +Y 쪽으로 이동하면 머리가 화면 왼쪽인 측면이 된다. 로봇 좌우를 이미지 반전으로 바꾸지 않는다. 격자가 보이도록 약간 위에서 내려다보는 측면을 최종 상태로 삼고, 정확한 각도는 단일 시험 프레임으로 확인한다.

격자는 몸체 중심으로 x ±0.8m, y ±0.5m, 0.1m 간격의 **17 × 11 = 187점**이다. 격자의 XY 위치는 `body_xy + Rz(yaw) × [x,y]`로 계산한다. 몸체 yaw를 따르지만 roll·pitch에 맞춰 격자 전체를 기울이지 않는다. 점의 높이는 같은 장면의 지면 hit에 맞춘다. 머리 앞에서만 펼쳐지는 부채꼴 LiDAR나 화면에 고정된 CSS 격자로 대신하지 않는다.

실험 설정의 ray origin offset 20m는 가상 광선 검사 설정이며 로봇 위에 실제 센서가 20m 떠 있는 모습으로 그리지 않는다. 지면까지 내려오는 광선은 선택한 일부만 얇게 보이고, 187점과 높낮이가 주인공이어야 한다. 처음에는 몸 아래 격자 전체, 다음 클릭에는 gap 주변 일부 표본과 높이 입력의 의미를 강조한다.

확인 근거는 [PPT-TECHNICAL-SCENE-EVIDENCE.md](PPT-TECHNICAL-SCENE-EVIDENCE.md)의 저장 설정과 `sim/policy/gap_observations.py`다. 현재 확보한 평가 93열 시계열에는 187채널 높이 배열이 없다. Blender 지면에 반응하는 격자는 기하 설명으로 제작 가능하지만 실험 프레임별 실제 관측값이라고 표시하지 않는다. 실제 반응값 연출은 동일 Isaac Sim 실행에서 새 계측·캡처가 필요하다.

## 5. Actor와 Critic의 화면 흐름

주 흐름은 `몸 상태·명령·이전 행동 48 + 지면 높이 187 → 관측 235 → Actor → 행동 12 → 관절 위치 목표 → 로봇`이다. 숨은 층은 512·256·128, 활성화 ELU다. 출력은 직접 토크 12개가 아니라 `q_target = q_default + 0.25 × action`으로 변환되는 값이다.

Critic은 관측 235에서 분기하는 별도 학습 경로다. `Critic → V(s)`와 보상·반환값이 PPO 갱신에 연결되고 Actor·Critic을 갱신한다. Critic에서 로봇으로 제어선을 연결하거나 Actor 다음에 Critic을 직렬로 두지 않는다. 첫 클릭은 실행 흐름만, 다음 클릭은 아래쪽 학습 경로를 더한다. 실제 뉴런 활성값이 없으므로 흐르는 점은 정보 흐름 도식으로 표현한다.

12개 출력선의 실제 배열은 `FL/FR/RL/RR hip → FL/FR/RL/RR thigh → FL/FR/RL/RR calf`다. 화면에서 다리별 세 출력으로 묶더라도 연결 매핑은 이 실제 순서를 따라야 한다. 숫자·차원·현재 정책 설정의 근거는 위 기술 근거 문서에 있다.

## 6. 프레임·앵커·여백의 제작 계약

1600×900 슬라이드를 기준으로 다음 영역을 먼저 고정한다. 아래는 실제 DOM 측정 결과가 아니라 **다음 제작의 예약 영역**이다. 공통 상단 제목·진행 표시와 하단 각주 영역을 침범하지 않아야 한다.

| 화면 | 로봇·격자 영역 | 본문·설명 영역 |
|---|---|---|
| 정면·장비 | x420~1180, y180~780 | 왼쪽 x64~370, 오른쪽 x1230~1536. 설명선은 이미지 밖 여백에서 꺾음 |
| 관절 확대 | x420~1180, y180~780 | 축 설명은 좌우 여백. 한 다리 확대와 전체 12관절은 같은 중앙 영역 사용 |
| 정책 | x64~700, y210~750 | x750~1536에서 관측·Actor·출력. y630~790에 Critic 학습 경로. 본문 설명은 도식 위쪽 별도 줄 |

v4 정면의 알파 유효 영역은 1600 정사각 안의 약 x221~1378, y201~1427이다. 이미지를 감싸는 사각형만 맞추면 실제 로봇 크기가 달라 보이므로 **불투명 실루엣의 바닥점·머리점·중심점**으로 전환을 맞춘다. 픽셀 측정값은 기존 정면 파일에만 해당한다.

기존 정면 센서 앵커는 이미지 정규화 좌표로 전면 카메라 `(0.5000, 0.2345)`, LiDAR `(0.5000, 0.3911)`다. 전면 카메라는 표면 설명용 앵커이며 보정된 Camera prim이 아니다. LiDAR는 USD `base/radar` 프레임이다. IMU `(0.5000, 0.1828)`는 내부 프레임이므로 외부 부품을 가리키는 선으로 쓰지 않는다. **새 카메라 각도에 이 좌표를 그대로 재사용하지 않는다.**

다음 렌더 묶음은 고정 Canvas 비율과 공통 포즈를 사용한다. 각 프레임마다 같은 Blender 카메라로 다음을 JSON에 투영한다.

- 몸체 중심·머리·네 발·불투명 실루엣 경계.
- 12개 관절의 중심과 회전축 양 끝, 가려짐 여부.
- 기본 카메라·radar·내부 IMU. 추가 모듈은 확인된 원본 확보 뒤 별도 등록.
- 187개 격자점과 몸체 좌표축. 좌표계·단위·카메라 ID·프레임 ID 포함.

영상 위 SVG 설명선은 이 좌표를 사용한다. 기체가 움직였는데 라벨이 제자리에 남는 문제를 막는다. 본문과 실루엣 사이 최소 32px, 라벨과 다른 라벨 사이 최소 16px을 목표로 한다. 제작 후 각 클릭 정지 상태와 중간 애니메이션 프레임의 경계를 실제 화면에서 측정하고 겹치면 카메라·배치부터 고친다. 1600×900 원본과 브라우저 축소 표시, PDF 정지 포스터를 함께 확인한다.

현재 `v4-player.js`는 `ready`, `setState`, `playSegment`, 역재생, `stop`을 지원하지만 정면과 클립 해상도가 다르다. 새 장면은 하나의 논리적 Canvas 크기를 유지하고 내부 letterbox·투영을 계산해야 한다. `file://`에서 동작하도록 manifest JS를 먼저 읽는 기존 방식을 유지한다. 자동 넘김 없이 명시한 정지점으로 이동하는 `setStage(id, {animate})` 계약을 추가하는 안이 적합하다.

## 7. 다음 작업 순서와 완료 조건

1. v4 정면을 모든 공유 Go2 장면의 기준으로 연결하고 기존 AI 정면과 섞이는 지점을 제거한다. 먼저 이미지 크기와 앞뒤 페이지 전환을 검증한다.
2. 기존 USD 계층에서 네 다리 묶음을 만들고 한 개 시험 프레임으로 분리 방향·카메라·설명 여백을 확인한다. 승인 전 전체 시퀀스를 렌더하지 않는다.
3. 정면 → 턴테이블 → 네 다리 분리 → 재조립 구간을 공통 카메라와 고정 Canvas 규격으로 제작한다. 원 자세 복원·관절 한계·모든 프레임의 화면 경계를 검사한다.
4. 기본 센서와 L2 데이터 스캔 설명을 붙인다. 추가 모듈은 공식 이미지 설명을 먼저 연결하고, 실제 모듈 메시와 장착 정보 확보 후 3D 장착으로 교체한다.
5. 한 다리 세 축 → 네 다리 12축 → 명령 축을 연결한다. 가려진 관절은 투시 점선·작은 확대 창으로 드러내되 실제 위치를 이동시키지 않는다.
6. 측면 Go2와 지면 격자의 시험 프레임을 먼저 확인한 뒤 관측·Actor·Critic 흐름을 연결한다. 실제 데이터가 필요한 구간은 설명 도식과 분리해 표시한다.
7. 클릭 재생·정지·이전 상태 복원, 설명선 추적, 본문 겹침, PDF 포스터까지 확인한다. 새 제작물은 v5로 분리해 v3·v4를 덮어쓰지 않는다.

현재 바로 진행 가능한 것은 USD 기체 통일, 네 다리 묶음, 관절·축·기본 센서 앵커, 몸체 기준 격자와 설명 도식이다. 원본 확인이 더 필요한 것은 **추가 모듈의 정확한 형상·장착 구성**, **L2 내부 회전 부품의 독립 메시**, **187채널 관측을 영상과 동기화한 실제 시계열**이다. 이 세 가지를 임의 외형이나 임의 측정값으로 채우지 않는다.
