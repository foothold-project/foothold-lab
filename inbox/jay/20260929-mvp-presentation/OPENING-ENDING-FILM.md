## 지금 제작에 적용하는 기준 · 2026-09-30

사용자 원문: “우리 이미지는 imagegen으로 만들어서 일부 과한 HDR이나 플라스틱 같은 광택으로 실사감을 대신하고 있는 부분도 있는데 현실의 작은 불균일함이 살아있는 사진이었으면 좋겠어.”

이 요구는 이미지부터 적용한다. 영상 후처리로 미루지 않는다. 기존 장면은 구도·공간 참조이며 재질 정본이 아니다. 거친 콘크리트, 도장, 금속, 고무의 반사를 구분하고 마른 면·젖은 면·고인 물을 불균일하게 배치한다. 과한 HDR·국부 대비·윤곽 선명도·전면적인 젖은 광택을 줄인다. 빛이 닿지 않는 부분은 어둡게 남긴다. 불균일함은 표면과 빛의 자연스러운 차이를 뜻하며, 무작위 노이즈·기울어진 카메라·과장된 흠집을 뜻하지 않는다.

| 구간·요소 | 현재 확정한 요구 | 제작에서 확인할 것 |
|---|---|---|
| O1 | 블랙에서 시작. 정면 원경에서 움직이는 빛으로 위험한 공간을 발견 | 손전등은 설명을 위한 비유. 손전등 소품·사람·손을 넣지 않음. 시선과 빛이 바닥으로 내려오며 근경 연결 |

| E6·E7 | CV 인식, 촬영, 전송 진행, 적색 100%·MISSION COMPLETE, 신호 종료 후 블랙 | 완료는 경보가 아닌 해소. 이후 별도 슬라이드 가운데 Q&A, 발표용 브랜드 폰트 |

E2 이미지·기준 문서·HTML 반영을 완료했고, 사용자가 제작을 승인한 **E2a 시작 이미지 한 장을 생성했다. v1은 미채택, v2는 공간 조명 수정, v3는 기체의 뒤쪽 이동을 반영했다. 최신 v3는 2026-10-01 사용자가 승인했으며 실제 영상은 생성하지 않았다.** E2는 빛 속에 도착한 상태의 이미지이며 2026-09-30 사용자가 승인했다. 승인 원문: “지금 E2 작업한 결과물 좋아. 컨펌 ok”. E2a 결과 확인 뒤 영상 A/B 비교를 진행하는 순서다. 다른 컷의 외형 통일과 최종 음향은 후속 범위를 정해 진행한다. 정지 이미지나 HTML 전환을 실제 보행·연결 검증 완료로 기록하지 않는다.

최신 시안: [E2 캐릭터·재질 적용 이미지](assets/ending-e2-sunburst-v1.png), [HTML 비교](output/FOOTHOLD-film-storyboard.html#e2-review). E2 이미지는 사용자 승인 완료이며 영상은 미제작이다. 새 시작 후보: [E2a 이미지](assets/ending-e2a-sunburst-v1.png), [시작·도착 비교](output/FOOTHOLD-film-storyboard.html#e2a-review). 기존 E2a 조명 참고는 보존한다.

## 이전 제작 기준 · 선택한 원화를 복원한 7컷

[현재 HTML](output/FOOTHOLD-film-storyboard.html)이 컷 순서의 기준이다. v6의 6칸 이미지를 통째로 최종 오프닝으로 쓰지 않는다. 사용자가 좋다고 한 기존 v3 구도를 원본 해상도로 복원하고, 새 원경과 가까운 scan을 섞었다. 아래 이전 버전은 변경 이력이며 충돌하면 이 절을 따른다.

| 컷 | 장면과 출처 | 정보·전환 |
|---|---|---|
| O1 | v6 첫 정면 원경 | 블랙에서 시작. 작은 이동광에 닿는 부분만 드러남. 손전등 물체 없음 |
| O2 | v3 첫 바닥 질감 근접 | 빛이 자갈과 거친 표면을 드러냄 |
| O3 | v3 두 번째 끊긴 가장자리 | O2의 질감에서 발 디딜 곳이 끝나는 위험으로 전환 |
| O4 | 블랙 MISSION | 배경 없이 임무를 먼저 전달한 뒤 녹색 시야가 돌아옴 |
| O5 | v3 네 번째 녹색 원경 | 공간 여백에 자세·명령·상태 HUD. 멀리 목표와 앞으로 갈 길 |
| O6 | v6 다섯 번째 가까운 지형 scan | 바닥의 점과 메시만. 주변 HUD 없음 |
| O7 | v3 여섯 번째 발 접촉 | 사용자가 다시 올린 선호 구도. 연속 발걸음으로 지나가며 발표로 연결 |

O2는 표면 질감, O3는 단절된 가장자리로 역할을 나눈다. O5와 O6은 넓은 시야에서 가까운 디딤으로 좁혀 간다. O7과 엔딩 E1은 같은 선호 발 이미지를 사용한다. 엔딩 E2~E7의 배경은 유지한다. 밝은 원경은 HTML 하단 T1에 별도 보존해 미경험 험지 설명 자료로 활용한다.

[사용자 조명 참고](https://img.hankyung.com/photo/202402/01.35788243.1.jpg)를 직접 확인했다. 화면 전체를 밝히지 않고 빛이 닿는 작은 부분만 보이는 것이 핵심이다. 현재 O1은 CSS 이동 마스크로 이 의도를 확인하는 시안이며 실제 영상 조명을 완성한 것이 아니다.

### HUD 정보의 의미 점검

- 자세와 속도·회전 명령은 실제 로봇·정책에서 의미 있는 항목이다. ROLL/PITCH는 자세를 읽기 쉽게 표시하는 값이며 actor 입력의 원래 명칭과 동일하지 않다. 명령과 측정 반응은 분리한다.
- 실측 로그가 없는 숫자는 `--`로 비운다. 이전에 넣었던 임의 파형·히스토그램·관절 반응 막대·높이 숫자는 제거했다. 모든 그래픽에 실제 데이터 근거가 있었다고 설명하지 않는다.
- 원형 눈금과 테두리는 화면을 구분하는 디자인이다. 현재 지형 점·메시와 임무 지형도는 개념 표현이며 실제 187개 scan이나 측정 지도가 아니다.
- CV 박스와 특징점은 목표 설비를 인식·촬영하는 시나리오다. 실제 검출 모델 결과나 confidence 수치를 주장하지 않는다.
- REC, 전송 진행률, 수신 완료는 영상 속 임무 단계 표현이다. 실제 녹화·통신 측정 기록이 아니다.

## 이전 구도 보정 · 오프닝 v6

사용자는 v5의 지형과 엔딩 배경은 긍정적으로 보았으나 O1·O3·O4의 같은 원경 반복을 다시 지적했다. 손전등은 움직이는 빛을 설명한 비유이며 실제 손전등 물체를 넣으라는 요청이 아니다. 다음을 최신 기준으로 삼는다.

| 컷 | 최신 구도 | 유지·수정 |
|---|---|---|
| O1 | 중앙 소실점의 정면 원경. 화면 밖 광원의 빛이 큰 공간의 지형을 훑음 | 보이는 손전등·램프 제거. 빛에 드러나는 영역이 움직임 |
| O2 | 발앞의 끊긴 가장자리를 내려다보는 근접 시점 | 사용자 긍정, 유지 |
| O3 | 시선을 내리고 가까운 다음 발판의 윗면과 높이를 찾는 구도 | 원경·기둥·목표의 반복 제거 |
| O4 | 완전한 블랙 위 MISSION | 원화의 검은 칸은 의도된 것. HUD는 별도 SVG |
| O5 | 근거리 지형 관측 화면 | O4 뒤 이 화면이 블렌딩되어 돌아옴 |

엔딩 v2 배경은 유지하고 E6에 CV 인식 연출을 추가한다. 설비와 경광등의 경계 박스, 모서리 특징점, 스캔선과 TRACK 표시가 대상에 붙는다. 화면의 특징점은 연출용 예시이며 실제 CV 모델의 검출·추적 결과가 아니다. 실측처럼 보이는 confidence 수치는 넣지 않는다. 촬영 → 전송 → 수신 확인 → MISSION CLEAR → 화면 꺼짐은 유지한다.

## 공간 규모와 HUD v3

사용자의 마지막 수정은 이전 근접 시작안을 대체한다. 원경에서 움직이는 손전등으로 위험한 공간을 먼저 보여주고, 다음 컷에서 발앞의 틈으로 들어간다. 첫 빛은 화면 전체가 켜지는 효과가 아니라 왼쪽·중앙·오른쪽의 벽과 바닥을 훑는 이동광이다. POV 시선의 작은 방향 변화와 연동한다.

같은 좁은 복도를 반복한 기존 원화를 새 공간으로 교체했다. 높은 기둥과 배관이 이어지는 지하 산업 공간, 단절된 정비 통로, 통로 양옆의 깊은 수면과 어둠으로 공간 깊이를 만든다. 큰 공간 속 작은 Go2와 가까운 발의 대비를 사용한다. 통과 경로 자체의 틈을 무작정 크게 만들어 불가능한 도약을 요구하지 않는다. 이 공간은 콘셉트이며 실제 실험 지형의 치수가 아니다.

## 이전 수정 결정 · HUD v2

사용자는 기존 HUD의 폰트·레이아웃·MISSION 표현을 강하게 거부했다. 기존 v1은 비교 기록으로만 보존하고 제작 기준으로 사용하지 않는다. 최신 결과는 [HUD v2와 화면 전환](output/FOOTHOLD-film-storyboard.html)이다.

- 영상 안 UI는 모두 영어. HUD 전용 고정폭 코딩 폰트(Consolas 우선, Cascadia Code 등 대체) 사용. 브랜드 로고·본문 폰트를 바꾸는 지시는 아니다.
- Iron Man의 시야 HUD처럼 얇은 눈금·끊어진 호·정렬된 데이터와 지형에 붙는 표식을 사용한다. 기존 큰 반투명 정보 상자와 한국어 패널은 제거한다.
- 시작은 완전한 블랙. O3 뒤에도 블랙을 넣고, 신호음과 함께 MISSION이 켜진다. 읽는 구간 이후 배경이 opacity로 돌아오거나 짧은 신호 흔들림으로 연결한다.
- O6은 한 번의 디딤에 멈추지 않고 ‘탁탁탁탁’ 연속 걸음으로 프레임을 지나가며 끝난다.
- E2는 eye-level 근접에서 더 높고 먼 정면으로 변경. 아래로 내려다보며 기체와 뒷공간을 함께 보여준다. 어둠에서 드러나는 방향은 유지한다.
- E7은 전송·수신 확인과 MISSION CLEAR 뒤 지지직 꺼져 블랙. 영상 위 로고·슬로건·Q&A 합성안을 폐기한다.
- Q&A는 영상 종료 후 직접 넘기는 별도 슬라이드로 둔다. 기존 기획발표 마지막 장의 로고·홈페이지 구조를 참고해 Q&A 중심으로 단순화한다. 현재 시안에는 슬로건 타이틀을 별도로 끼우지 않았다. 공식 슬로건 자체는 바꾸지 않는다.
- 화면 전환 미리보기는 정지 원화와 HTML/SVG 그래픽으로 구성한 무음 프로토타입이다. 실제 로봇 보행 영상이나 완성 효과음을 생성한 것이 아니다.

## 오프닝과 엔딩의 역할

| 구간 | 청자에게 남길 것 | 화면의 역할 |
|---|---|---|
| 오프닝 | 저 길을 가야 하는 이유가 있고, 첫발을 놓는 일부터 어렵다. 우리는 이 첫걸음을 연구한다 | 험지의 단절·높이 차·좁은 디딤을 먼저 체감시키고, 첫 디딤에서 다음 슬라이드의 미경험 험지 설명으로 연결 |
| 엔딩 | 첫걸음을 안정적으로 이어갈 수 있어야 위험한 현장에 도달하고 필요한 일을 수행할 수 있다 | 오프닝에서 받은 임무의 결과를 회수하고 연구의 다음 목적을 보여줌 |

하나의 편집 완성본 안에서 같은 기체·지형·목표·임무가 이어진다. 그 완성본에서 오프닝 구간과 엔딩 구간을 분리해 발표에 사용한다. 영상 모델에 전체를 한 번에 생성시키는 방식까지 뜻하지는 않는다. 컷별로 생성하더라도 같은 원화·공간·기체를 기준으로 편집해 한 편으로 완성한다.

엔딩은 현재 MVP가 검증을 끝낸 실기 임무 시연이 아니라 앞으로 연결할 현장 활용 장면이다. 발표 연결 멘트에서 ‘오늘 만든 첫걸음이 앞으로 어디까지 이어져야 하는지’로 소개한다. 실제 성과 증거는 본문의 시뮬레이션 결과와 구분한다.

## 하나의 임무

제안: 붕괴된 지하 통로 너머의 목표 설비에 접근해 현장 상태를 영상으로 확인한다. 붉은 점등은 목표 위치다. 임무 완료는 단지 골인한 장면이 아니라 목표를 카메라로 확인하고 그 정보가 확인 화면에 전달된 뒤 표시한다. 미확인 가스 농도·온도·실제 통신 성공률은 만들어 넣지 않는다. 로봇 팔이나 구조 동작처럼 현재 설계에 없는 기능을 추가하지 않는다.

MISSION 문구 제안: ‘목표 지점 접근 / 현장 상태 확인’. 엔딩 문구 제안: ‘목표 지점 도착 / 현장 영상 확인 / MISSION COMPLETE’.

## 발표 중간의 분리 지점

오프닝의 마지막 발소리에 맞춰 미경험 험지 소개 화면으로 전환한다. 영상의 환경음을 짧게 줄이고 발표자가 ‘그럼 우리 FOOTHOLD 프로젝트의 첫걸음을 함께 시작하겠습니다’라고 말한다. 검은 화면을 길게 끼우거나 임무 완료 화면을 먼저 보여주지 않는다.

마스터 영상에서는 같은 전진 동작이 다음 컷으로 이어진다. 엔딩 재생본은 직전 접촉 순간을 약 0.5초 회상한 뒤 그다음 동작으로 이어지는 편집을 제안한다. 앞뒤 분리용 편집 여유를 남긴다.

E2는 처음부터 밝게 보이는 제품 정면 샷으로 시작하지 않는다. 발소리와 희미한 윤곽이 먼저 있고, 기체가 빛을 받으면서 모습을 드러낸다. 공간 전체를 한꺼번에 밝히거나 갑자기 기체가 생성되는 효과를 넣지 않는다. 오프닝과 같은 은색 Go2와 어두운 공간을 유지한다.

E2에서 E3으로 복잡한 180도 회전을 강제하지 않는다. 정면 공개 후 컷으로 뒤쪽에 연결한다. 로봇의 진행 방향과 목표 위치는 유지한다. E4는 별개 장애물을 추가하기보다 같은 통과 동작의 측면으로 구성한다. 틈을 넘는 방식을 과도한 도약으로 단정하지 않고 실제 체형·도달 거리와 맞춘다.

촬영 시작, 전송 진행, 수신 완료, MISSION CLEAR, 지지직 꺼짐, 블랙의 순서를 지킨다. 진행 막대는 임무 콘셉트 연출이며 통신 속도나 지하 무선 통신의 실측 증거가 아니다. 완주·정지·촬영·전송은 앞으로 연결할 현장 활용 시나리오다. 발표에서는 그 성격을 소개하고 현재 MVP의 시뮬레이션 성과와 구분한다.

## HUD의 정보와 모양

`확인됨`: 기본 명령은 `lin_vel_x`, `lin_vel_y`, `ang_vel_z`다. 화면에는 청자가 이해할 수 있게 ‘전진·후진 vx (m/s) / 횡이동 vy (m/s) / 회전 ωz (rad/s)’로 표시한다. yaw 각도와 yaw 각속도는 구분한다. 근거: Isaac Lab `velocity_env_cfg.py:103`, `sim/policy/gap_f_env_cfg.py:54~70`.

| 요소 | 위치·역할 | 주의점 |
|---|---|---|
| MISSION | O4 중앙에서 크게 전개, O5 상단 작은 임무 표시로 축소 | 긴 설명 대신 두 줄. 브랜드 글꼴과 정렬 유지 |
| 명령값 | 하단의 작은 고정 영역 | vx·vy·ωz를 단위와 함께. 존재하는 축이라는 이유로 현재 정책이 모두 잘 수행한다고 표현하지 않음 |
| 실제 반응 | 필요한 순간 명령값 옆에 측정 속도·각속도를 나란히 | 명령과 측정은 동일값이 아님. 실제 로그 확보 전 숫자 확정 금지 |
| height scan | 몸통 주변과 가까운 전방 바닥에 붙는 점·격자 | 원거리 발판 하나만 공중에서 비추는 형태 수정. 빈 공간에 가짜 바닥을 만들지 않음 |
| 센서 화면 질감 | 녹색 SF HUD, 수평 주사선과 얇은 화면 격자, 잔광·미세 노이즈 | O4 켜지는 순간만 짧게 강해지고 이후 가독성 확보. 지면에 붙는 관측 격자와 화면 질감을 구분 |
| 디딤 시점 | 발과 바닥 접촉에 맞춘 짧은 시각 변화 | 실제 발 접촉 센서를 읽었다고 단정하지 않음 |

기본 height scan 설정의 격자 규격은 0.1m 간격, 1.6×1.0m다. 현재 정책을 설명하는 본문에서는 해당 체크포인트의 설정과 오프셋에 맞춘다. 오프닝 콘셉트에서는 사용자 요청에 따라 시선을 가까운 발밑에서 앞쪽으로 들며 관측 표현을 확장할 수 있다. 첫 화면부터 먼 곳만 스캔하는 구도는 피한다. 시선을 든다는 것은 카메라 구도 변화이며 Go2에 움직이는 목이나 센서 짐벌이 있다고 가정하지 않는다.

사용자는 다른 연구에서 센서를 앞쪽으로 두거나 더 먼 지형을 보는 셋업을 본 경험을 설명했다. 해당 연구의 실제 설정은 이 문서에서 재검증하지 않았으므로 `미확인`이다. 그 경험은 이번 연출의 참고이며 우리 현재 정책의 센서 범위가 같다는 근거로 쓰지 않는다. 원거리 점은 전방 지형 관측 콘셉트로 다루고, 현재 actor의 187개 height scan이 그 범위를 실제로 본다고 설명하지 않는다. 시뮬레이션 ray casting과 실기 LiDAR 입력도 구분한다.

UI는 이미지·영상 생성 모델에 글자를 맡기지 않고 별도 그래픽으로 만든다. HUD의 영어·고정폭 폰트는 이번 사용자 수정 지시가 이전 글꼴 제안보다 우선한다. 모든 프레임에 숫자를 가득 넣지 않는다. 숫자가 필요한 컷에서 명령과 반응을 구분해 읽게 한다. 현재 v2 설정의 vy 범위가 0이라는 점도 유지한다. 임의의 횡이동 명령을 넣어 기능을 입증한 것처럼 보이지 않게 한다.

## 관측 수치와 HUD의 시각 구성

사용자 승인: 정보 UI는 아래 제안대로 진행한다. O5의 자세·근거리 지형 관측을 중심으로 명령과 측정 속도를 보조하고, 엔딩에서는 REC 촬영·전송 진행·수신 확인으로 전환한다. 녹색 SF HUD와 CRT 질감을 적용한다. 구성에 대한 승인이며 아직 이미지 시안이나 영상이 완성된 것은 아니다.

`확인됨`: 로컬 Isaac Lab `velocity_env_cfg.py:123~138`의 policy 관측은 몸체 선속도·각속도, projected_gravity, 속도 명령, 기준 자세 대비 관절 위치, 관절 속도, 이전 행동, height scan이다. `sim/policy/gap_env_cfg.py:38~44`는 height scan 처리를 교체한다.

O5는 왼쪽 아래에 BODY STATE와 작은 자세 수평선·roll/pitch 각도, 오른쪽 아래에 CMD와 측정 속도를 구분해 배치한다. 바닥에는 높이 관측 점을 붙인다. 각속도와 관절 상세는 본문 또는 몸체 공개 장면에서 필요한 항목만 확장한다. 원시 IMU 가속도가 actor 입력이라고 표시하지 않는다. roll/pitch는 이해를 돕기 위한 가공 표시이며 실제 입력 projected_gravity와 구분한다. 실기 선속도를 IMU 하나의 직접 측정값이라고 설명하지 않는다.

사용자가 말한 옛 방송 화면의 격자 질감은 수평 주사선(scanline)과 CRT 화면 질감을 중심으로 해석한다. 검은 바탕, 녹색 빛, 가는 직선 눈금, 옅은 화면 격자, 짧은 잔광을 사용한다. O4에서 HUD가 켜지는 순간은 드라마틱하게, O5에서는 바닥과 수치를 읽을 수 있게 절제한다. 화면에 고정된 질감과 지형에 붙어 움직이는 관측 점의 좌표를 분리한다. 브랜드 글꼴·로고·각도 원칙은 유지한다.

현재 동기화 가능한 관측 로그와 해당 영상은 `미확인`이다. 실측 수치는 로그 확보 후 채운다. 생성 영상과 다른 실험의 로그를 같은 장면의 측정값처럼 합치지 않는다. 콘셉트에 예시 데이터를 쓸 때는 그 성격을 구분한다. 접촉 힘·토크·마찰계수를 현재 actor의 직접 관측으로 추가하지 않는다.

## 제작 길이와 사운드 결정

사용자 결정: 생성 원본은 컷당 5초를 기본으로 확보하고 편집에서 필요한 3초 등으로 줄여 쓴다. 원본 앞뒤에 동작 여유를 둔다. 생성 길이를 그대로 발표 재생 길이로 사용하지 않는다. UI 전환이나 엔딩 로고처럼 같은 원화와 편집으로 만들 수 있는 것은 별도 영상 생성을 자동으로 추가하지 않는다. 모델별 3초·5초의 실제 요금과 지원 길이는 이번에 조회하지 않았으며, 실행 시 확인한다.

사운드는 영상·이미지와 같은 중요도로 다룬다. 이미지와 영상 문안이 확정된 뒤 별도 제작한다. 전체 마스터에 하나의 음악적 전개와 마무리를 설계하며, 컷마다 다른 생성 음악을 붙이지 않는다. 음악·공간음·동작 효과음·임무 UI 효과음을 분리해 편집하되 하나의 공간과 이야기로 들리게 혼합한다.

- 전개: 암흑의 공간과 긴장, 지형 발견, 임무 활성화, 첫발, 지속되는 보행, 목표 촬영·전송, 임무 완료와 여운.
- 공간음: 같은 지하 공간의 잔향과 환경 소리가 컷 앞뒤를 연결한다. 시점과 거리에 따라 크기·방향·잔향을 조절한다.
- 동작음: 실제 접촉 순간에 맞춘 발소리, 구동음, 작은 파편 소리. 화면보다 먼저 소리가 이어지거나 다음 컷까지 남는 편집을 활용한다.
- UI 효과음: MISSION 활성화, 촬영 시작, 전송·수신 확인에 서로 연관된 짧은 소리. 모든 HUD 요소에 경고음을 붙이지 않는다.
- 분리 재생: 오프닝은 첫걸음에서 잠시 열어 둔 음악적 끝맺음, 엔딩은 같은 동기와 공간음으로 재개해 최종 해소. 발표 중간 내내 음악을 재생한다는 뜻은 아니다.
- 마무리: 수신 확인과 MISSION COMPLETE에 음악적 도착점을 맞추고 공식 슬로건에서 잔향이 정리되어 Q&A 발화 공간을 남긴다.

이번에는 소리·음악·영상 생성 요청을 보내지 않는다. 실제 제작 때 컷별 생성 음성이 있다면 소재로만 검토하고, 최종 사운드 전체 구성에 맞춰 선택한다.

사용자는 실제 Go2의 Bluetooth·Wi-Fi 지원을 근거로 통신 상태와 전송 UI의 사용 의도를 설명했다. 통신 UI를 허구 기능으로 배제하지 않는다. 연결 아이콘과 전송 과정은 이번 콘셉트에 사용하며, 특정 지하 현장에서의 전송 성공·통신 속도를 실측했다고 주장하는 것과는 구분한다. 이번 턴 장비 사양 재조사는 하지 않았다. 수평계는 BODY STATE 표시로 채택한다.

## 현재 이미지의 충분성

현재 v3 이미지로 오프닝의 질감과 일부 동작을 시험할 수 있다. 그러나 오프닝과 엔딩의 완성 영상을 만들기에는 부족하다. 기존 컷을 확대·반복해 임무 수행 과정을 대신하지 않는다.

필요한 추가 원화:

1. 가까운 POV 위 전면 MISSION HUD와 축소 후 관측 UI. 실제 그리드 위치를 대조해 제작.
2. O6와 E1을 연결하는 같은 발·같은 디딤·같은 동작의 시작과 끝.
3. Go2 정면 eye-level 공개, 뒤쪽 Follow, 틈 통과 측면 시점. 같은 기체·통로·진행 방향을 유지.
4. 목표 설비가 가까워지는 POV와 안전한 지지면의 정지·확인 장면.
5. 촬영 REC UI, 전송 진행 막대와 수신 확인, 임무 완료, 로고·슬로건·Q&A 연결.

오프닝 v4와 엔딩 v1의 이미지 시안을 만들었다. [컷별 HUD 미리보기](output/FOOTHOLD-film-storyboard.html)에서 이미지와 그래픽을 함께 확인한다. 이미지 컨펌 이전 Higgsfield 영상 생성은 계속 보류한다. 시안 숫자는 표시용 예시이며 실측 로그가 아니다.

사용자 후속 지적: 오프닝 v4의 3~5번 지형과 구도가 반복돼 보인다. 4~5번은 같은 POV의 임무·관측 상태 전환이지만, 현재 정적 시안에서 반복감이 남는다. 전체 HUD 미리보기를 먼저 제공하고, 다음 영상용 원화에서는 탐색광 이동·시선 변화와 편집 길이를 조정한다. 현재 해결 완료로 표시하지 않는다.

이미지 점검: 오프닝 몸체 컷 제거와 발밑 관측 추가, 엔딩 정면·후면·측면·목표 컷 확보. 정면 컷은 ending-e2-wide-v3.png로 교체했다. 높은 정면 시점과 넓은 배경을 확보했고, 역방향 카메라 뒤에 목적지가 잘못 보이던 v2의 경광등·설비를 제거했다. 어둠 속 시작 키프레임은 영상 제작 시 연결한다. Go2 발 접촉과 지형 폭, 컷 사이 디딤 위치는 실제 영상용 원화를 만들 때 맞춘다. 엔딩 녹색 촬영 화면에서 목표 경광등도 단색으로 바뀌며, 실제 경광등 색 변경을 뜻하지 않는다.

사용자 원문: “이건 지금 go2 만 명도 낮췄는데? 뭐라고 프롬프트 썼길래 저따구냐? 레퍼런스 이미지를 제대로 안줘서 그래? 분위기?”

실제 요청은 승인 E2·공식 정면·캐릭터 시트·디테일 시트 4장을 포함했다. 그러나 `Keep the same environmental exposure`와 어둠을 기체 위치만으로 표현하라는 문구로 배경 밝기를 고정했다. 이 지시가 거의 암흑인 공간 안에서 빛만 살아 있는 분위기 요구와 충돌했다. 외형 참조 누락이 아니라 조명 설계와 요청의 오류다. 생성기가 내부적으로 무엇을 우선했는지는 미확인이다.

결과는 보존하되 후속 영상 시작 프레임으로 채택하지 않는다. 다음 요청은 카메라·지형·기체 외형을 고정하고, 공간의 주변광과 반사광을 낮추며 국소광만 남기는 방향으로 수정한다. 영상에서는 전체 노출을 올려 공개하는 효과 대신 Go2가 고정광으로 걸어 들어오게 한다. 새 이미지 생성은 아직 하지 않았다.

### E2a v2 분위기 수정 결과 · 2026-10-01

[수정 이미지](assets/ending-e2a-sunburst-v2.png), [실제 요청](assets/ending-e2a-sunburst-v2.request.json). 배경 노출 고정 지시를 제거하고 공간 전체의 주변광 감소와 제한된 고정광을 우선했다. `확인됨` 직접 열람: 주변 벽·기둥·바닥의 밝기가 낮아지고 국소광이 남았다. **미해결: Go2가 여전히 빛 안쪽에 있어 뒤쪽 어둠에서 출발하는 위치가 아니다.** 사용자 승인과 영상 연결 검증은 하지 않았다. 추가 비용 2.75크레딧, E2a 두 차례 합계 5.5크레딧. 사용자 제작 지시로 수정 한 장을 생성했으며 영상은 제출하지 않았다.

### E2a v3 결과 · 2026-10-01

[이미지](assets/ending-e2a-sunburst-v3.png), [HTML 비교](output/FOOTHOLD-film-storyboard.html#e2a-review), [실제 요청](assets/ending-e2a-sunburst-v3.request.json). v2를 편집 원본으로, 승인 캐릭터 시트를 외형 참조로 사용했다. v2의 공간 조명을 유지하며 기체 위치만 뒤로 옮기는 수정이다. 사용자 “다음 작업”을 E2a 미해결 수정으로 해석해 제출했고, 질의에 제출 사실과 2.75크레딧 견적을 설명했다. 이후 사용자가 “진행 하고 결과 보자”라고 지시했다.

`확인됨` 직접 이미지 열람: 앞쪽 빛 아래 기존 기체 자리가 비었고 Go2가 더 뒤쪽에서 작게 보인다. 어두운 공간과 고정광이 유지됐다. `미확인` 어둠에 묻힌 지지면의 전체 연결과 실제 보행 접촉. 이 정지 이미지로 실제 움직임까지 검증했다고 기록하지 않는다. 사용자 이미지 승인 완료. 이동 속도와 연결은 영상 시험에서 확인한다.

실제 잔액 4978.75 → 4976, 이번 차이 2.75크레딧. E2a 누계 8.25크레딧. 기존 v1·v2는 이력으로 보존한다. 영상 비교는 시작 이미지 확인 이후 단계다.


### 다음 작업 준비 · 2026-10-01

E2a v3 사용자 승인 완료. [E2 영상 시험 준비](E2-VIDEO-TEST-PREP.md)에 실제 제출용 요청 2개와 32.5크레딧 견적을 기록했다. 두 모델은 시작·끝 이미지 모두 지원하나, 밝은 E2를 끝 프레임으로 강제하면 배경 전역 밝기 변화와 충돌하므로 일반 외형·도착 구도 참조로 사용한다. 이번에는 준비와 비용 조회까지만 수행했으며 영상은 미제출이다.

### E2 카메라 최신 수정 · 2026-10-01

사용자가 약간의 달리인을 제안했다. 앞선 고정 카메라 시험 문안을 대체해 처음 약 0.5초 구도 유지 후 아주 느리고 짧은 달리인으로 준비한다. 광원은 고정하고 원경 공간감을 유지한다. Go2의 보행과 카메라 접근을 구분하며 줌·급가속을 금지한다. 두 모델에 같은 문안을 사용한다. 상세 요청은 [시험 준비 v1.1](E2-VIDEO-TEST-PREP.md)이 최신이다. 영상은 아직 미제출이다.
