# HUD·관측 영상 제작 설계

> 분류: 계획
> 작성: Codex · 2026-10-01 01:48
> 근거: 사용자 U158·U159와 최신 레이어 논의, 기존 HUD SVG·연출 정본
> 요지: 합성 참조로 AI 영상화를 먼저 시험하고 레이어 분리는 필요할 때만 한다.
> 상태: 관측 시험 설계. 외부 보행 컷 이미지는 별도 진행
> 판: v1.0

## 확정한 제작 순서

레이어 분리는 선행 조건이 아니다. 사용자는 카메라·보행·지형에 반응하는 HUD와 scan을 포함해 AI 영상화하는 방식을 요구했다. 기존 SVG는 정지 디자인 기준이며 이를 그대로 영상 위에 붙인 것을 완성본으로 삼지 않는다.

1. 기존 O5 원경 관측 구도에 승인한 HUD 디자인과 지형 scan을 배치한 단일 참조 이미지를 준비한다. 같은 배경의 HUD 없는 원본과 SVG는 수정용으로 보존한다. 사용자가 통합 이미지를 확인한다.
2. 승인한 단일 이미지를 영상 시작 프레임으로 쓰고, 해당 모델이 허용하면 깨끗한 배경·HUD 디자인을 보조 참조로 준다. 참조별 역할을 명시하고 다중 이미지가 콜라주로 복제되지 않도록 한다.
3. 관측 컷 1편을 Seedance 2.5·5초·480p·음향 포함으로 시험한다. 실제 입력이 정해진 뒤 견적을 조회한다. 현재 영상 제출은 하지 않았다.
4. 카메라·scan·수평계·문구를 영상 프레임에서 확인한다. 잘 작동하면 이 방식을 채택한다. 불안정한 항목만 따로 보완한다. HUD 전체를 무조건 재합성하거나 무조건 레이어 분해하지 않는다.
5. 근거리 O6는 주변 계기판 없이 지형 scan만 보여준다. 임무 O4와 촬영·전송 E6·E7은 각 상태의 가독성과 사건 순서를 별도로 확인한다.

## 영상 모델에 전달할 동작 관계

| 요소 | 요청할 관계 | 실패로 볼 현상 |
|---|---|---|
| 카메라 | Go2 높이의 POV, 보행에 따른 작은 상하·좌우 움직임. 가까운 바닥을 본 뒤 시선을 앞쪽으로 올림 | 카메라 흔들림과 바닥 이동이 분리되거나 갑자기 다른 지형으로 바뀜 |
| scan | 발 앞의 가까운 실제 표면부터 갱신하고 앞쪽 발판으로 이어짐. 점·메시는 지형에 붙으며 카메라 시점에 맞게 투영 | 화면에 고정된 스티커, 벽 관통, 틈을 고체 바닥으로 메우는 메시 |
| scan 용어 | 이 컷은 height scan을 시각화한 콘셉트. 별도 회전형 LiDAR 연출을 같은 데이터처럼 섞지 않음 | 실제 187개 관측이나 LiDAR 실측의 재현이라고 주장 |
| 수평계 | 보행의 기울기 변화에 맞는 작은 pitch·roll 반응, 멈출 때 안정화 | 크게 무작위 회전하거나 지형 반응과 반대 방향으로 흔들림 |
| 명령·속도 | 명령 `CMD VX`, `CMD VY`, `CMD YAW`와 반응 `EST VX`를 구분. 일정 명령은 유지하고 추정 속도만 작은 변화를 가짐 | 명령값까지 이유 없이 흔들림, 수치가 읽을 수 없는 글자로 변형 |
| 파형·상태 | 관성 변화와 접촉을 암시하는 작은 파형 반응. 모든 패널이 동시에 요동치지 않음 | 의미 없는 랜덤 숫자·과도한 점멸로 지형을 가림 |
| 촬영·전송 | 목표 고정 후 CV 박스가 대상에 붙고 촬영, 전송 진행, 수신 완료 순서 | 목표와 박스가 어긋남, 100% 이전 완료 표시, 빨간 완료가 경보로 읽힘 |

수치 애니메이션은 생성 영상의 콘셉트 데이터다. 실제 IMU·LiDAR·Isaac Sim 로그와 동기화됐다고 표시하지 않는다. 사용자가 원하는 반응성을 없애거나 정지 수치로 바꾸지 않되, 정확한 물리적 측정값 생성까지 보장하지 않는다. 명령이 일정하면 명령 표시는 일정한 것이 맞다. 움직임을 위해 모든 숫자를 바꾸지 않는다.

## 참조 이미지와 레이어

영상 모델이 최종 화면의 배치와 질감을 볼 수 있도록 합쳐진 완성 구도 이미지를 주는 것이 우선이다. 기존 HUD SVG는 원래 분리된 원본이므로 AI로 다시 추출할 필요가 없다. 생성 결과에서 특정 요소만 분리해야 할 때 Higgsfield Layers를 검토한다. 가느다란 반투명 선과 glow가 정확히 분리되는지는 시험 전 미확인이다. 2개 레이어라는 형식 자체가 목표가 아니다.

## HUD 결정과 독립적인 이미지

E3 후면 보행과 E4 측면 틈 통과는 외부 카메라 컷이므로 HUD를 넣지 않는다. E3를 먼저 생성·열람하고, 결과를 E4의 지형·재질 참조로 전달한다. 승인한 Go2 캐릭터·발 디테일과 공식 후면 자료를 함께 사용한다. 그 다음 E5pre·E5·E5b 시작·끝을 같은 목표·진행축으로 준비한다. 기존 이미지와 실제 요청 문안은 보존하고 결과를 전체 스토리보드 하나에서 확인한다.
