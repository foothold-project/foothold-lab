# Higgsfield CLI · MCP · API · 웹 비교 조사

> 요지: CLI는 재현 가능한 터미널 작업과 로컬 파일 입출력에 강하고, MCP는 현재 채팅에서 바로 실행·추적하기 쉽다. Cinema Studio 관련 기능은 경로별 공식 설명과 실제 매개변수를 구분해 확인해야 한다.
> 상태: 조사 완료. 계정 웹 UI의 실제 견적·산출물 품질은 미확인
> 판: v1.0

## 조사 목적과 범위

FOOTHOLD Go2의 영화적인 오프닝·엔딩 약 20컷과 후속 Dune풍 브랜드 영상 제작을 염두에 두고 네 경로를 비교했다. 질문은 기능, 자동화, 비용, 캐릭터와 장면의 연속성, 대량 처리, Cinema Studio와 Elements, 로컬 파일, 재현성, 그리고 채팅 안에서 에이전트가 CLI를 끝까지 조작할 수 있는지다.

CLI는 공식 공개 문서와 GitHub README/MODELS를 읽었다. 저장소를 clone하거나 CLI를 설치하지 않았다. MCP는 현재 연결된 도구의 설명과 스키마, 기존에 확인한 비청구 비용 견적을 바탕으로 했다. 계정 웹 화면에서 유료 생성을 하거나 브라우저에 로그인하지 않았다. 따라서 UI의 버튼별 동작, 현재 계정이 보는 최종 견적, 출력 품질을 직접 비교한 결과는 아니다.

아래에서 **확인됨**은 직접 읽은 공식 문서, 현재 MCP 도구 메타데이터, 또는 앞서 받은 동일 설정의 견적에 근거한다. **미확인**은 여기서 읽지 못했거나 실제 실행·시각 검수가 필요한 내용이다. 공개 자료가 광고성으로 품질을 주장하는 경우는 품질 사실로 취급하지 않았다.

## 결론

현재 상태에서 채팅으로 바로 기획하고 몇 개의 컷을 생성·확인하는 데는 연결된 MCP가 가장 간단하다. MCP는 채팅에서 모델을 고르고, 비용을 미리 계산하고, 여러 독립 작업을 묶어 보내며, 완료 상태를 기다릴 수 있다. 다만 호출당 묶음은 최대 6개 영상 작업이어서 20컷 전체를 한 번에 제출하는 방식은 아니다. 여러 번 나누어 제출할 수 있지만 계정의 실제 동시 처리 상한은 확인되지 않았다.

CLI는 셸에서 JSON 결과를 다루고, 파일 경로를 인자로 주며, 생성·비용 확인·대기·결과 조회를 스크립트로 묶기 좋다. 공식 안내는 CLI를 설치한 뒤 브라우저 로그인과 동반 skill 설치를 하도록 안내한다. **채팅으로 CLI를 전부 제어할 수 있는가?** 기술적으로는 Codex가 이 환경의 명령 도구를 사용할 수 있고, CLI에는 기계 판독 JSON과 대기 옵션이 있다. 하지만 현재 이 저장소 환경에 CLI가 설치·인증되었다는 증거가 없고, 이번 조사에서 설치나 로그인을 하지 않았다. 그러므로 지금 이 대화만으로 바로 사용할 수 있다고 단정할 수 없다. 설치와 브라우저 인증이 끝난 뒤에는 명령 실행과 결과 수집을 채팅에서 보조할 수 있지만, 로그인 단계의 브라우저 상호작용과 영상의 미적 선택까지 자동으로 끝난다는 뜻은 아니다.

Higgsfield 공식 Cinema Studio 안내는 카메라, 렌즈, 조명, 장르, 멀티샷, 캐릭터와 장소 Elements를 설명한다. 3.5는 AI Director와 팀 공유를, 4.0 안내는 최대 50개 참조와 긴 영상, 다중 모델 등을 제시한다. 그러나 공개 페이지들이 4.0의 길이와 세부 기능을 서로 다르게 설명하고 있어 실제 계정에서 보이는 옵션을 기준으로 해야 한다. MCP에 보이는 Cinema Studio 모델은 웹 UI의 모든 콘솔 기능을 자동으로 의미하지 않는다.

API는 토큰 단가가 공개된 별도 개발자 표면이다. 영상 제작을 반복 자동화하거나 자체 파이프라인에 넣을 때 비교 대상이 된다. 단, API의 일반 Cinema Studio 4.0 playground는 480p·720p 가격을 보여주며, MCP 크레딧 비용이나 웹 구독의 무제한 모델 정책과 같은 과금 체계가 아니다. 세 가격을 숫자만 나란히 놓고 어느 쪽이 싸다고 말할 수 없다.

## 기능 비교

| 경로 | 현재 확인된 장점 | 이 작업에서의 한계 |
|---|---|---|
| 채팅 MCP | 모델 카탈로그 조회, 이미지·영상 생성, 비용 사전 추정, 1~6개 독립 영상 요청 묶음, 최대 8개씩 대기, 최대 24개 결과 갤러리 | 묶음 제출은 가능하지만 공식 UI 전체 제어기가 아니다. Cinema Studio 4.0 기능 전체, 큐 상한, 저장 위치 자동화 범위는 확인되지 않음 |
| CLI | 모델/워크플로 목록과 스키마 조회, generate cost/create/get/wait/list, JSON 출력, 로컬 경로를 넣는 명령 예시, 40개 이상 모델 표기 | 이번에는 설치·실행·로그인하지 않음. CLI 문서에 모델이 있다는 사실만으로 웹 UI의 모든 카메라·장르·Elements 옵션이 같은 방식으로 노출된다는 보장은 없음 |
| 개발자 API | 공개 모델 페이지에 기계 호출용 playground와 토큰 단가, 입력 조건 및 가격 산식이 표시됨 | 별도 개발자 계정·인증·요금 정책이 필요할 수 있음. UI의 프로젝트·Elements 관리 경험과 동일하다고 확인되지 않음 |
| 웹 Cinema Studio | 카메라와 렌즈, 장르, 조명, 색상, 멀티샷, 캐릭터·장소·소품 Elements, AI Director 등 시각 중심의 제작 흐름 | 반복 작업을 코드로 재현하기 어렵고 UI 수작업이 개입함. 실제 계정 권한·버전·가격은 로그인 화면에서 확인하지 않음 |

### 채팅에서 CLI를 끝까지 실행할 수 있는 조건

공식 CLI 안내는 `npm i -g @higgsfield/cli`, `higgsfield auth login`, 동반 skills 설치 순서를 제시한다. 로그인은 브라우저에서 완료한다고 안내한다. README에는 `--wait`, `--json`, `generate create`, `generate cost`, `generate get`, `generate wait`, `model list`가 적혀 있다. 이 구조는 에이전트가 이미 접근 가능한 셸과 유효한 CLI 세션을 가지고 있을 때 작업을 자동화하기 좋은 형태다.

현재 조사에서는 설치·인증·실제 생성 실행을 하지 않았다. 따라서 **이 Codex 세션에서의 CLI 완전 제어는 미확인**이다. 브라우저 로그인 등 최초 인증은 사람의 상호작용이 필요할 수 있다. 인증 후에도 파일 업로드 권한, 네트워크, 로컬 CLI 버전, 계정 워크스페이스 선택을 점검해야 한다. 웹 UI에서만 보이는 설정을 CLI가 지원하는지 역시 `higgsfield model get`과 실제 help/매개변수 스키마로 확인해야 한다.

## Cinema Studio, Elements, 연속성

공식 Cinema Studio 도움말은 3.0에서 캐릭터·장소 등 참조를 최대 9개 사용하고, 3.5에서 프로젝트 간 Elements 재사용과 팀 공유, AI Director를 설명한다. 4.0 도움말 및 제품 페이지는 더 많은 참조와 장면 연출 옵션을 제시한다. 공식 설명에 따르면 Elements는 반복 등장할 캐릭터, 장소, 소품의 기준 자산으로 재사용하는 기능이다. 이는 매 컷의 프롬프트에 외형을 다시 쓰는 것보다 연속성 관리에 유리한 설계다. 이것이 결과물에서 동일성을 보장한다는 독립 검증은 아니다.

사용자는 Higgsfield 한국어 `/ko/generate` 화면에서 모델 선택 메뉴, Cinema Studio 4.0 기본 추천 표시, Movement 카메라 선택 항목을 직접 봤다고 전했다. 이 UI는 이번 조사에서 다시 열어 검증하지 않았다. 따라서 Cinema Studio를 하나의 고정 모델로 취급하지 않는다. 제품/작업공간(wrapper), Cinema Studio 버전, 그 안에서 선택한 생성 모델을 각각 구분해 작업 기록에 남겨야 한다. 웹의 모델 선택과 MCP/CLI/API의 모델 ID 대응은 별도 확인이 필요하다.

현재 MCP 도구 메타데이터의 Elements 경로는 워크스페이스 단위 Elements 생성·조회·재사용을 지원한다. 도구는 생성 이미지 하나를 캐릭터 Element로 만들고, 프롬프트에 `<<<element_id>>>` 플레이스홀더를 넣어 지원 모델에 전달하는 방식을 설명한다. 하지만 도구가 열거한 동영상 Element 지원 모델은 `cinematic_studio_video_v2`, `cinematic_studio_3_0`, `seedance_2_0`, `kling3_0`이다. `seedance_2_5`는 이 Elements 목록에 없다. Kling 3.0은 Element만 넣어서는 부족하고 시작 이미지가 필요하다고 명시되어 있다. 이 차이는 **전체 MCP가 Cinema Studio를 지원하지 않는다는 뜻이 아니라, 현재 Elements 주입 기능의 모델별 범위**다.

20컷의 동일 Go2 외관과 세계관을 유지하려면 기준 이미지·Element를 먼저 확정하고, 각 컷에 동일 참조를 재사용하는 접근이 합리적이다. 그래도 컷 간 얼굴/기체 세부, 센서·다리 형상, 조명 연속성은 샘플 생성 후 사람이 확인해야 한다. MCP에서 `cinematic_studio_3_0`의 비용 견적이 확인되었다고 해서 그 모델이 Seedance 2.5 기반이라고 추론할 수 없다. 반대로 Cinema Studio 웹의 최신 버전 설명이 Seedance 2.5를 언급해도 MCP의 Cinema Studio 3.0 모델과 같은 백엔드라고 볼 근거가 없다. 모델명과 UI 버전을 별개로 기록해야 한다.

제작 적용 후보로는 엔딩 브랜드 노출에서 tracking/crane 같은 카메라 이동을 시험할 수 있다. 반면 E2 장면은 고정 카메라 구도와 로봇 자체의 보행 움직임을 분리해 설정하는 편이 장면 의도를 비교하기 쉽다. 이는 사용자가 본 Movement 선택 항목을 바탕으로 한 제안이며, 해당 옵션이 실제 결과에서 의도한 대로 작동하는지는 미확인이다.

## 자동화, 로컬 파일, 재현성, 대량 처리

CLI README는 JSON 응답, 비용 확인, 생성 대기, 생성 이력 목록, 로컬 파일을 받는 예시를 보여준다. 이미지/영상/오디오 업로드 명령도 있다. 따라서 로컬 원본 파일을 업로드하고 스크립트가 작업 ID와 결과 URL을 기록하는 자동화가 가능하다는 점은 문서로 확인된다. 로컬 디렉터리에 결과를 자동 다운로드하는 기본 기능이나 전체 재현 가능한 프로젝트 내보내기 형식은 이 자료만으로 확인되지 않았다.

MCP는 `generate_image_batch`와 `generate_video_batch` 각각 한 번에 1~6개 독립 작업을 받으며, 각 작업은 결과 수 1개로 고정된다. 반환된 작업을 `jobs_wait`로 최대 8개씩 기다리고, 작업 세트가 끝난 뒤 최대 24개까지 한 갤러리에 모아 볼 수 있다. 이 숫자는 도구 호출의 묶음 크기이지 계정의 전역 동시 실행 제한이나 서비스 처리량 한도가 아니다. 20컷은 최소 4회의 묶음 제출로 나눌 수 있지만, 큐가 실제로 병렬 실행되는 수와 속도, 분당/일일 한도는 미확인이다.

CLI도 자체 셸 스크립트로 반복 호출하거나 병렬 실행할 수 있지만, README에서 배치 전용 명령과 계정 동시 실행 상한은 확인하지 못했다. CLI로 요청을 빨리 많이 보낸다고 서버 제한이 없어지는 것은 아니다. API의 요청 제한도 이 조사에서 수치 확인을 못했다.

재현 가능한 제작 기록을 위해 컷별로 다음을 표에 고정하는 편이 좋다: 작업 번호, 모델 ID와 버전, 프롬프트 원문, 입력 참조 파일의 해시/ID, 길이, 해상도, 비율, 오디오 설정, 시작·종료 프레임, 생성 시각, 비용 견적/실청구, 작업 ID, 결과 파일 위치, 채택 여부. CLI의 JSON과 MCP 작업 ID는 이 기록을 만드는 재료가 된다. 다만 랜덤 시드 파라미터가 각 사용 모델에서 노출되는지는 모델별 스키마를 확인해야 한다. 같은 요청을 다시 보낸다고 픽셀 단위로 같은 영상이 나온다고 약속할 수 없다.

## 가격과 제작비 가늠

### MCP 크레딧 견적

기존 비용 추정 도구에서 같은 시작 이미지 조건으로 5초, 16:9, 오디오 활성 설정을 넣은 견적을 비교했다. 생성 작업은 제출하지 않았다.

| 모델·설정 | 480p | 1080p | 확인 상태 |
|---|---:|---:|---|
| Seedance 2.5, `omni_reference` | 15 크레딧 | 60 크레딧 | 견적 도구 응답. 실제 청구·품질 미확인 |
| Cinema Studio 3.0, 장르 `auto` | 17.5 크레딧 | 50 크레딧 | 견적 도구 응답. 실제 청구·품질 미확인 |

20컷을 모두 5초로 가정하면, 동일 견적 조건에서 단순 합계는 Seedance 2.5가 480p 300크레딧 또는 1080p 1,200크레딧이다. Cinema Studio 3.0은 견적 원값 기준 480p 350크레딧 또는 1080p 1,000크레딧이다. 이는 컷당 한 번씩 성공적으로 생성한다는 계산이다. 재생성, 더 긴 컷, 이미지 제작, 후반 편집 비용, 세금은 포함하지 않았다. 실패 작업의 청구 처리도 여기서 확인하지 않았다.

사용자는 9월 4일 Higgsfield Plus에 가입했다고 전했다. 별도 시점에 유료 크레딧 4,000개를 세전 190달러에 구매했다고 전했다. 이를 단순 나누면 세전 크레딧당 약 0.0475달러다. 사용자가 총액을 221달러로 기억하고 10% 세금을 언급했으나, 190달러의 10%를 더하면 209달러이므로 221달러와 맞지 않는다. 인보이스로 확인하지 못했으므로 세금 포함 단가를 계산하지 않는다. 이 사용자의 실제 구매 단가는 할인·플랜·세금 조건에 묶인 개인 기준이며, 공개 정가가 아니다.

### API 가격과 개인 크레딧 단가 비교

핵심 후보인 Seedance 2.5의 공식 API 이미지→영상 playground는 16:9, 영상 입력 없음 조건에서 생성 영상 초당 480p $0.2056, 720p $0.4622, 1080p $1.1372를 제시한다. 같은 페이지는 토큰 과금 산식과 별도 할인이 적용될 수 있음을 밝힌다. 공개 Explore 화면은 ByteDance 모델의 30% 할인 표시를 보여주지만, 해당 할인이 이 사용자 계정에 적용되는지는 미확인이다.

아래는 한 컷 5초 가정이며, 사용자가 제공한 크레딧 구매 단가 $0.0475/credit으로 달러 가격을 크레딧 상당액으로 환산했다. 이는 서로 다른 결제 체계를 비교하기 위한 환산이며 실제 API 청구 크레딧이 아니다. 세금·재생성·영상 입력은 제외했다.

| Seedance 2.5 API 16:9, 영상 입력 없음 | API 표준 단가 | 5초 API 비용 | $0.0475/credit 환산 | 30% 할인 가정 시 5초 비용 | 할인 후 환산 |
|---|---:|---:|---:|---:|---:|
| 480p | $0.2056/s | $1.028 | 21.64 credits | $0.7196 | 15.15 credits |
| 720p | $0.4622/s | $2.311 | 48.65 credits | $1.6177 | 34.06 credits |
| 1080p | $1.1372/s | $5.686 | 119.71 credits | $3.9802 | 83.79 credits |

20컷을 각각 5초로 잡으면 API 표준 비용은 480p $20.56, 720p $46.22, 1080p $113.72다. 공개된 30% 할인이 실제 적용된다고 가정한 비용은 각각 $14.392, $32.354, $79.604이며, 사용자 크레딧 단가로 환산하면 약 303, 681, 1,676 credits 상당이다. 같은 사용자의 MCP Seedance 견적은 480p 300 credits, 1080p 1,200 credits 합계다. 따라서 480p에서는 공개 할인 가정 시 두 경로가 근접하고, 1080p에서는 이 MCP 견적이 더 낮다. 조건이 같은 모델 경로라고 확정할 수 없으므로 이 결과는 비용 기준의 참고 비교로만 읽어야 한다.

같은 5초 조건의 MCP 견적은 Seedance 2.5 `omni_reference`, 시작 이미지 포함, 오디오 활성 설정에서 480p 15크레딧, 1080p 60크레딧이었다. 따라서 API 480p 표준가는 이 사용자의 구매 단가로 환산한 MCP 견적보다 높고, 공개 30% 할인이 실제 적용되면 거의 비슷해진다. 720p MCP 비교 견적은 없으므로 비교하지 않는다. API 가격은 해상도와 설정, 영상 입력 여부에 따라 달라진다.

**Cinema Studio 4.0은 보조 참고치다.** 공식 API playground에서 5초 16:9의 표시 가격은 480p $0.2057/s, 720p $0.4623/s다. 이 모델은 MCP에서 견적한 Cinema Studio 3.0과 동일 모델이라고 확인되지 않았으므로 두 견적을 같은 모델 가격 비교로 읽으면 안 된다.

**Sunburst 이미지 API**는 고정된 요청당 가격으로 확정하기 어렵다. 공식 API 설명은 입력 텍스트·이미지와 출력 이미지 토큰을 기준으로 과금하고 완료 후 실제 사용량에 맞춰 정산한다고 적는다. 표시되는 이미지당 대략적 범위는 설정에 따라 $0.0095~$0.5414이며, 이를 단순히 $0.0475/credit으로 나누면 약 0.20~11.40 credits 상당이다. 이는 범위 양 끝의 단순 환산이지 특정 품질·해상도의 견적이 아니다. MCP에서 앞서 본 Sunburst 2K high 견적 2.75크레딧과 직접 대조하려면 API의 동일 프롬프트·참조·설정을 입력해 비용을 다시 산출해야 한다.

**Nano Banana Pro API 가격은 미확인**이다. 이번에 확인한 공식 API 모델 페이지와 공개 가격 자료에서 같은 모델 ID의 명시적 가격을 찾지 못했다. 모델이 API에 없다고 단정하지 않는다.

웹 UI의 실계정 정확 견적은 확인하지 못했다. 공개 도움말은 웹 생성이 플랜의 Unlimited 포함 모델인지 여부에 따라 크레딧 차감이 달라질 수 있다고 설명한다. 구독 플랜의 월 비용, 무제한 대상 목록, 길이와 해상도에 따른 크레딧은 로그인된 계정에서 별도로 확인해야 한다.

## 품질 평가와 아직 모르는 것

Cinema Studio 공식 페이지는 물리적으로 그럴듯한 움직임, 카메라 파이프라인, 캐릭터 일관성 등을 장점으로 주장한다. 이는 공급자 설명이지 Go2 장면에 대한 검증 결과가 아니다. Seedance 2.5와 Cinema Studio 3.0을 같은 입력 이미지, 동일 프롬프트, 동일 길이·비율·해상도로 생성해 비교하지 않았다. 따라서 어느 쪽이 Go2 외형, 발걸음 물리, 먼지 상호작용, 영화적 구성, 컷 간 연속성에서 우수하다는 결론은 **미확인**이다.

또한 다음은 실제 제작 전에 확인할 항목이다.

- 계정 웹 UI에서 사용 가능한 Cinema Studio 버전, 프로젝트/Elements 접근, 장르·카메라 설정, 컷당 실제 비용
- 스토리보드와 Popcorn이 현재 웹·CLI·MCP/API 중 어느 경로에서 제공되고, 컷 구성과 참조 입력을 어떻게 넘기는지
- 사용하려는 CLI 버전에서 Cinema Studio 모델별 지원 매개변수와 로컬 파일 입력 방식
- API에서 사용 가능한 Cinema Studio 모델, 참조 유형, 최대 영상 길이, 요청 한도와 실제 청구 규칙
- 공통 Go2 기준 참조를 넣은 짧은 테스트 컷의 기체 형상, 움직임, 영상 품질과 연속성
- Elements를 여러 컷에서 재사용했을 때의 동일성, 해당 Elements가 각 선택 모델에서 실제 반영되는 정도
- 20개 작업을 여러 묶음으로 제출했을 때 계정의 큐와 완료 시간
- 웹 구독이 해당 모델을 Unlimited로 처리하는지, 어떤 설정이 크레딧을 소모하는지

다음 실험을 하게 되면 동일한 Go2 레퍼런스 한 장과 같은 5초 장면 설명으로 2~3개 후보 모델을 소량 비교하고, 품질 검수 후 20컷 분량을 확정하는 방식이 비용을 통제하기 좋다. 다만 유료 생성을 시작하기 전에는 컷 수, 길이, 해상도, 재생성 여유를 넣어 실제 총 비용을 다시 계산해야 한다.
