# 질문과 답

## PD 제어 · Kp 25 · Kd 0.5 는 무엇인가
정책은 토크를 직접 내지 않고 관절마다 「이 각도로 가라」는 목표 각도를 50 Hz 로 낸다. 모터 쪽 PD 제어기가 그 목표를 토크로 바꾼다.
토크 = Kp × (목표 각도 − 지금 각도) − Kd × 관절 속도.
Kp(25 N·m/rad)는 용수철 세기다. 목표에서 0.1 rad 벗어나면 2.5 N·m 로 당긴다. Kd(0.5 N·m·s/rad)는 완충기다. 빨리 움직일수록 반대로 잡아 흔들림을 줄인다.
정책은 이 값으로 「목표 각도를 얼마나 내면 다리가 얼마나 움직이는지」를 배운다. 학습 중에 Kp · Kd 를 바꾸면 같은 출력이 다른 힘이 되어 배운 것이 어긋난다. 실기에서도 저수준 명령(LowCmd)에 같은 Kp · Kd 를 넣어야 학습한 대로 걷는다. 그래서 「막음」 칸이다(흔들기는 DR 의 ±10 % 가 맡는다). 근거: `foothold_s2/deploy/params/deploy.yaml` stiffness · damping.

## 지각 추정값 51 개는 무엇인가
지각 모듈(GRU · transformer)이 몸감각 이력 · 깊이 · 지도를 받아 actor 에게 넘기는 요약이다. 몸 속도 추정 3 · 몸과 지형 상태 z 16 · 몸 둘레 지도 특징 zb 16 · 발 둘레 지도 특징 zf 16. 사람이 뜻을 정한 숫자가 아니라 신경망이 만든 압축 표현이라 「좌우를 뒤집은 값」이 정의되지 않는다. critic 만 거울 증강할 때는 이 51 개를 건드리지 않는다(actor 는 평소대로 받는다). 근거: `start_perception.py:10-11`.

## critic 입력 664 는 무엇인가
잡음 없는 몸 상태 52(몸감각 · 실제 속도 · 발 접촉 넷 포함) + 정답 지도 512(32 × 16) + 발 둘레 지도 100(발마다 5 × 5). 근거: `start_runner.py:73,238`.

## 대칭은 왜 critic 만 하나
지도는 좌우로 뒤집으면 되지만 51 개 추정값과 GRU 기억은 뒤집을 수 없다. critic 은 정답 상태와 지도만 받는 MLP 라 거울이 정확히 정의된다. 좌우 대칭인 가치 판단이 actor 의 학습 신호를 대칭 쪽으로 이끈다. AME-2 가 쓴 방식(2601.08485 193 행).

## 회전 L1 항은 왜 yaw 를 줄이나
L1 = 절댓값. 회전 명령이 0 일 때 매 걸음 −0.5 × |실제 회전 속도| 를 보상에 더한다. 지금 회전 보상 exp(−오차²/0.25) 는 오차가 작으면 평평해서 0.02 rad/s 로 돌아도 보상이 0.16 % 만 준다. L1 은 0 근처에서도 기울기가 같아 작은 치우침을 계속 0 쪽으로 민다.

## AdaSmpl · p_map_off
AdaSmpl 은 env 마다 정답 지도를 쓸지 복원 지도를 쓸지 확률 p 로 고른다. p = tanh(최근 에피소드 보상의 변동계수). 아직 불안하면 정답을 더, 안정되면 복원을 더 쓴다(`start_perception.py:194-230`, START 193 행). p_map_off(0.1)는 그와 별개로 지도를 아예 끄는 확률이다.

## ONNX 와 브라우저용 ONNX 런타임
ONNX 는 신경망을 「계산 순서 + 가중치」로 적는 공통 파일 형식이다. PyTorch 모델을 ONNX 로 내보내면 파이썬 없는 곳(브라우저 · C++ · 로봇 컴퓨터)에서 같은 계산을 한다. onnxruntime-web 은 그 파일을 브라우저에서 돌리는 라이브러리다. 같은 파일을 실기 로봇 컴퓨터에서도 쓸 수 있다.

## Isaac Lab 지형 비율 0
Isaac Lab 은 시작할 때 지형 열을 비율 누적합으로 고정 배치한다. 비율 0 이면 그 지형의 열이 만들어지지 않는다(`terrain_generator.py:244-246`). env 도 시작 때 열에 고르게 고정된다(`terrain_importer.py:348`). 그래서 나중에 쓸 지형은 처음부터 열로 만들고, 노출은 리셋 때 env 를 열에 다시 배정하는 코드로 조절한다.
