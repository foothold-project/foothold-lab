## 1. 왜 필요한가 · 숫자

### 1.1 B1500 세 모드와 EX-25 (고정 칸 64 env · 레벨 0~2 · sonnet-code 측정 · 내 재계산 없음) `[실측]`

| 명령 | B1500 eval_pred 적분 m / 생존 | B1500 probe_prop_only 적분 m / 생존 / 요추종 | EX-25(지도 없이 학습) 적분 m / 생존 / 요추종 |
|---|---|---|---|
| fwd 0.5 | 2.90 / 63 | 0.00 / 51 / 0.14 | 2.99 / 64 / 0.01 |
| fwd 1.0 | 5.69 / 59 | 0.75 / 44 / 0.03 | 5.82 / 64 / 0.00 |
| spin +1.2 | 0.66 / 64 / 0.88 | −0.21 / 24 / 0.06 | 0.20 / 58 / 0.44 |
| spin −1.2 | 0.00 / 64 / 0.15 | −0.09 / 48 / 0.17 | 0.19 / 53 / 0.52 |

- 지금 정책은 지도 토큰이 없으면 전진하지 않고(적분 0.00 · 0.75 m) 좌회전에서 24/64 만 산다. 지도에 크게 기댄다(QA 문서의 팀장 · lead 해석과 같다).
- EX-25 는 지도 없이 배운 정책이라 참조선이 된다: 생존은 전부, 회전은 좌우가 0.44 / 0.52 로 비슷하다. 단 EX-25 는 마찰 고정으로 배웠고 평가는 두 판 모두 마찰 무작위를 끈 같은 조건이다(표 머리 `[실측]`).
- 이 표의 EX-25 는 「지도 없이 얼마나 걷나」 의 참조이지 부모 후보가 아니다(QA 「EX-25 를 부모로 쓰지 않는 까닭」 `[팀장]`).

### 1.1a 창 1 결과(m1750) 추가 (v0.2 · 08:0x) `[실측 window2 자동 평가 · gate.out]`

| 판 | 지도 가림(probe_prop_only) 생존 fwd0.5 · fwd1.0 | 가림 전진 1.0 적분 m | 복원 지도 전진 1.0 적분 m |
|---|---|---|---|
| 부모 B1500 | 48 · 45 | 0.62 | 5.65 |
| EX-30 m1750 (PRED · AdaSmpl) | **22 · 2** | 0.47 | 5.40 |
| EX-31 m1750 (GT) | **59 · 38** | 0.94 | 5.26 |

- PRED 판은 250 회 만에 지도를 가리면 거의 전부 넘어진다(fwd1.0 생존 2/64). GT 판은 반대로 부모보다 가림에 강해졌다. 두 판의 차이는 학습 때 받는 지도가 복원인지 정답인지뿐이다(DESIGN §2). 복원 지도는 잡음이 있어 정책이 몸 감각을 더 쓰리라는 기대와 반대다. 원인은 재지 않았다(미확인). 한 저장본 · 한 시드의 값이다.
- 이 문서에 걸리는 것 둘. (1) **부모 선택(§4)**: 부모를 EX-30 으로 둔 권고는 그대로다. 판 C 가 고치려는 것이 바로 PRED 판의 지도 의존이고, EX-31 을 부모로 쓰면 「GT 로 배운 몸 감각」 을 재는 것이 되어 실기 경로(복원 지도) 와 어긋난다. 다만 EX-30 의 가림 생존이 2/64 라 D1 목표(≥ 60/64) 까지의 거리가 v0.1 이 가정한 부모 B1500(45/64) 보다 훨씬 멀다. 2 % 로 시작해 세 단계로 올리는 §2.3 의 속도로 500 회 안에 닿을지는 추정조차 못 한다. (2) **기준선 행**: §3 의 「분기 저장본(기준)」 에 그 저장본의 가림 생존을 반드시 적고, 창마다 상승 폭으로 「승급」 을 판정한다(절대 목표만으로는 첫 창이 반드시 실패로 적힌다).
- 팀장이 정할 것(§8 에 6 번으로 추가): PRED 판의 가림 붕괴를 보고도 판 C 의 분기 시점을 「두 판 종료 뒤」 로 둘지, 창 3 처방과 겹치지 않는 GPU1 자리에서 EX-30 m2000 분기(C-중) 로 당길지.

### 1.2 왜 EX-30 · 31 에 넣지 않나 `[팀장·lead 10/25]`

QA 문서: 「EX-30 · 31 에는 넣지 않고(원인 분석이 어려워짐) 다음 판에서 조건부로, 소량(예 2~5 %) 지도 가림 학습부터.」 두 판은 「지도 처치 하나만 다른 짝」 이라는 설계가 핵심이라, 거기에 가림을 넣으면 복원 지도 효과와 가림 효과가 섞인다.

### 1.3 선행 `[논문]`

- **Miki 외 2022**(Science Robotics 7(62) eabk2822, arXiv 2201.08117): 몸 감각과 외부 감각(높이 표본) 을 attention 기반 순환 인코더로 합치고, 학습 때 외부 감각을 흐리거나 막아 정책이 몸 감각으로 되돌아갈 수 있게 한 보행. 오늘 확인한 것은 초록 · 구조 서술까지다. **잡음 모형의 수치 · 가림 확률 · 커리큘럼 수치는 본문을 읽지 않아 미확인** 이고 이 문서의 비율은 그 논문에서 가져온 것이 아니다.
- **START**(arXiv 2512.13153): AdaSmpl 은 GT 지도와 복원 지도를 섞지만 「지도 없음」 은 섞지 않는다. 지도 가림은 START 에 없는 **우리 추가** 다(PROVENANCE 3 절 아이디어 은행 「지도를 가리는 학습」). 발표 때 「START 재현」 으로 부르지 않는다.
- 우리 코드에는 이미 가림 경로가 있다 `[코드]`: `probe_prop_only` 평가 모드가 지도 토큰을 attention 키에서 빼는 마스크로 구현돼 있다(`start_perception.py:164~167`, 「0 높이 지도로 바꿔 넣지 않는다」). 판 C 의 학습 가림은 이 경로를 env 단위로 켜는 것이다.

## 2. 장치

### 2.1 가림의 정의 `[코드 기반 · 우리 제안]`

- 리셋마다 env 별로 d ~ Bernoulli(p_drop) 를 뽑아 그 에피소드 동안 고정한다(AdaSmpl 의 `use_gt` 플래그와 같은 자리 · 같은 수명 `[코드 PerceptionState.use_gt]`).
- d = 1 인 env: `IEEstimator.estimate` 의 self-attention 에 지도 토큰 128 개를 **key padding mask** 로 뺀다. prop 토큰 하나만 남는다. 지금 `mask_map_tokens` 는 모듈 전역 bool 이라 env 단위 텐서로 바꿔야 한다(§6 C-T1). 지도를 0 으로 채우지 않는다(0 은 「평평한 땅」 으로 읽힌다).
- TR-Net 은 그대로 돈다(입력이 깊이라 가림과 무관). 복원 지도는 만들어지지만 정책에 안 들어간다. L_TR 은 모든 env 에서 그대로 학습한다.
- 재생 버퍼가 d 를 저장하고 `sequence_loss` 재생이 같은 d 로 마스크를 건다(「재생 = 수집」 불변식 유지 `[코드 StartPerception 머리말]`).
- critic 은 바꾸지 않는다. critic 입력 664 에는 GT 지도 512 가 그대로 들어간다(`start_runner.py:17` `[코드]`). 비대칭 actor-critic 이라 가림 env 에서도 가치 추정은 지형을 안다.
- AdaSmpl: d = 1 env 의 에피소드 보상은 CV 통계에서 **뺀다**. 안 빼면 가림 에피소드의 낮은 보상이 CV 를 키워 다른 env 의 GT 비율을 올린다(p = tanh(CV) `[코드 AdaSmpl.update]`). d = 1 env 에서는 `use_gt` 가 의미가 없으므로 뽑되 쓰지 않는다.
- I-E 손실 중 `hb`(zb → GT 지도 512 복원 `[코드 sequence_loss]`) 는 가림 env 에서 「몸 감각만으로 지형을 추정하라」 는 뜻이 된다. 이것이 몸 감각 기반의 목표에 맞으므로 **켠 채로 두고** 가림 · 비가림을 나눠 기록한다. 가림 쪽 hb 가 비가림의 2 배를 넘어 계속 벌어지면 가림 env 의 hb 를 0 으로 두는 대안(C-옵션 B) 으로 바꾸고 그 사실을 적는다 `[추정]`.

### 2.2 어느 env 에서 `[팀장 (원장)]`

- 1 단계: 스폰 칸 종류가 random_rough · hf_pyramid_slope · pyramid_slope(이어진 지형의 「평지 계열」, REVIEW-ef84fd2c v0.2 의 분류 `[실측]`) 이고 레벨 0~2 인 env 에서만 d 를 뽑는다. 다른 env 는 d = 0.
- 2 단계(§3 승급 뒤): 계단 up/down · 상자 · 단차의 레벨 0~2 를 더한다. 계단에서 지도 없이 걷는 것은 뒤 · 옆 계단과 별개의 과제이고, 「본 계단 / 처음 보는 계단」 평가 분리(DESIGN §4.2) 를 그대로 쓴다.
- 지형 종류는 리셋 시점의 `terrain_types` · `terrain_levels` 에서 읽는다(env_state 에 있음 `[실측 부모 체크포인트]`). 칸 중간에 다른 칸으로 넘어가면 에피소드 안에서 d 는 바꾸지 않는다(에피소드 단위 처치).

### 2.3 비율 단계 `[팀장 2~5 %]` `[추정]`

| 단계 | p_drop(대상 env 안) | 전체 env 기준 가림 비율(추정) | 가림 데이터/창(추정) |
|---|---:|---:|---|
| C1 | 0.02 | 평지 계열이 전체의 약 46 % 중 어느 비율인지에 따라 1 % 안팎 | 3072 × 0.01 × 24 × 250 ≈ 184 k 스텝 |
| C2 | 0.05 | 2~3 % | ≈ 460 k |
| C3 | 0.10 | 4~5 % | ≈ 920 k |

- 숫자의 등급: 2~5 % 는 팀장 · lead 의견(QA), 0.10 상한과 단계 셋은 내 제안이다. 정확한 「전체 기준 비율」 은 실제 리셋 배정에서 재서 기록한다(§5 기록).
- 비율은 **회차가 아니라 §3 성과로** 올린다(RULES-HUB 「승급은 회차가 아니라 성과로」).
- 명령은 가림 env 도 같은 분포를 받는다(제한하지 않음). 평가는 명령별로 나눈다.

### 2.4 고른 것과 버린 것

| 선택지 | 처리 | 까닭 |
|---|---|---|
| 토큰 마스크(에피소드 단위) | **채택** | 평가 경로가 이미 있다. 「없음」 을 「평지」 와 구분한다 |
| 지도에 0 또는 큰 잡음 넣기 | 기각 · 보류 | 0 은 평지로 오독. 큰 잡음(Miki 류) 은 「틀린 지도」 학습이라 별 축 |
| 에피소드 안 구간 가림(1~3 s 끊김) | 보류(C 뒤 축) | 실기의 순간 가림에 더 가깝지만 원인 분리를 위해 처음은 에피소드 단위 |
| 별도 blind 정책 + 전환기 | 보류 | 정책 둘과 전환 규칙이 생긴다. DESIGN §10 「blind fallback」 은 이 판이 실패할 때의 대안 |
| EX-25 가중치로 초기화 | 기각 | 지도 쓰는 법을 처음부터 배워야 한다(QA) |

## 3. 판정 (결과 전 등록)

**측정.** 고정 칸 64 env(fixed_table 형식 · 레벨 0~2 · 배열 SHA 단언 · 커리큘럼 끔 `[RULES-HUB]`), 명령 fwd 0.5 · fwd 1.0 · spin ±1.2, 세 모드(eval_pred · eval_gt · probe_prop_only), 분기 저장본(기준) 과 각 창 끝 저장본(판정).

| 지표 | 정의 | 기준 |
|---|---|---|
| D1 가림 생존 | probe_prop_only 생존 64 중 | 목표(EX-25 수준): fwd 두 칸 ≥ 60/64, spin 두 칸 ≥ 50/64 `[추정 · EX-25 64/64/58/53 에서 여유]` |
| D2 가림 전진 | probe_prop_only vx 적분 | fwd 0.5 ≥ 2.4 m(명령 적분 3.0 m 의 80 %), fwd 1.0 ≥ 4.8 m `[DESIGN §5 80 % 규칙]` |
| D3 가림 회전 · 대칭 | probe_prop_only 요추종 좌 · 우 | 둘 다 ≥ 0.40, 차 ≤ 0.15 `[추정 · EX-25 0.44/0.52]` |
| D4 지도 유지 | eval_pred 의 성공 · 생존 | 분기 저장본보다 0.10 넘게 떨어지지 않음(64 합산 규칙 `[팀장 F3]`) |
| D5 자세 | fwd 1.0 몸 높이 · 보폭(eval_pred) | 분기 저장본보다 몸 높이 0.03 m 넘게 낮아지면 멈춤(인사이트 6 「불안하면 낮춘다」 `[팀장]`) |

**규칙.**
- 승급(C1 → C2 → C3): 직전 두 창의 D1 · D2 가 **둘 다 개선** 이고 D4 · D5 되돌림 없음. 한 창에 비율 한 단계만.
- 목표 달성: D1~D3 모두 만족 · D4 · D5 유지. 그때 「몸 감각 기반 확보(평지 계열 · 레벨 0~2 한정)」 로 적고, 2.2 의 2 단계(계단) 로 간다.
- 되돌림: D4 또는 D5 가 걸리면 비율을 한 단계 내리고 기록 보존. 두 번 걸리면 판 C 를 멈추고 §10 의 blind fallback 설계로 넘긴다.
- 숫자는 결과 전 고정. EX-25 수준을 「넘는다」 가 아니라 「도달한다」 가 목표다. EX-25 와는 학습 마찰이 달라 같은 잣대의 비교는 평가 조건(마찰 무작위 끔) 안에서만.

## 4. 언제 · 어디서

## 5. 기록

- 리셋마다: env · d · 지형 종류 · 레벨 · 명령. 창마다 「실제 가림 비율(전체 기준 · 대상 env 기준)」 과 종류별 분포.
- 갱신마다: hb · hf · o_next · kl 손실을 d 로 나눠, AdaSmpl p 와 통계에 쓴 에피소드 수(가림 제외 확인).

## 7. 위험

1. **보수적 걸음으로 수렴**: 가림 에피소드에서 살려고 몸을 낮추거나 보폭을 줄이는 전략이 지도 있는 걸음에도 번질 수 있다(인사이트 6). D5 로 지키고, 비율을 0.10 넘게 올리지 않는다.
2. **hb 손실 충돌**: 몸 감각만으로 512 칸 지도를 맞추라는 손실이 I-E 의 공통 표현을 흔들 수 있다. 2.1 의 대안 B.
3. **데이터 양**: C1 에서 창 하나의 가림 스텝 약 184 k 는 전체의 1 % 다. 효과가 작아 승급이 더딜 수 있다. 그래도 2 % 에서 시작하는 것은 팀장 의견이고, (원장) 가 설계다.
4. **평가 모드 의미**: probe_prop_only 는 「지도 토큰 없음」 이다. 실기의 「지도가 틀림」 은 다른 상황이고 이 판이 보장하지 않는다(DESIGN §9 의 「GT 성공 · PRED 미달」 분기는 그쪽).
5. **GPU 자리**: 두 판이 도는 동안은 자리가 없다. C-중 을 고르면 Chrome 종료 또는 EX-31 조기 종료가 전제다.

## 8. 팀장이 정할 것

1. 분기 시점: C-후(기본) · C-중 · C-Linux.
2. 시작 비율 0.02 와 상한 0.10(세 단계) 에 동의하는지, 상한을 더 낮게 둘지.
3. 가림 env 의 hb 손실을 켠 채 두는 것(2.1) 에 동의하는지.
4. 목표치를 EX-25 「도달」(D1~D3) 로 두는 것에 동의하는지.
5. 대상 지형의 1 단계 집합(random_rough · hf_pyramid_slope · pyramid_slope · 레벨 0~2).
6. **분기 시점 재고(v0.2)**: §1.1a 의 PRED 판 가림 붕괴(2/64) 를 보고 C-후(기본) 를 유지할지 C-중으로 당길지.
