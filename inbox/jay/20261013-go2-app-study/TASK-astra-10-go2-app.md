# ASTRA 의뢰 10 · Go2 앱의 지도 정제 기법

결과는 같은 폴더 `REPORT-astra-10-stage1.md` 새 파일 하나. 커밋 · push 하지 않는다. **이 단계에서는 앱 설치 파일 (APK 등) 을 내려받거나 실행하지 않고, rea 도 설치하지 않는다.** 실기 로봇에 접속하지 않는다. 키 · 토큰 · 계정 정보를 다루지 않는다.

## 1 단계에서 할 것

1. **이미 공개된 것 먼저.** Go2 앱의 통신 (WebRTC) 은 공개 저장소들이 이미 풀어 두었다. 예: `legion1581/unitree_webrtc_connect` (이전 이름 go2_webrtc_connect) · `abizovnuralem/go2_ros2_sdk` · `VectorRobotics/unitree_webrtc_connect` · `phospho-app/go2_webrtc_connect`. 이 코드와 문서에서 확인할 것:
   - 앱이 로봇에서 받는 지도 자료의 형식 (LiDAR 가 로봇에서 voxel 로 바뀌어 오는지 · 압축 · 디코더 (WASM 등) · 갱신 주기 · 좌표계).
   - 「정제」 가 어디서 일어나나: 로봇 쪽 (펌웨어 · SLAM) 인지 앱 쪽 (그리기) 인지. 앱 쪽이면 무엇을 하는지 (voxel → mesh · 높이 색 · 평활 · 누적 · 잡음 제거).
   - 로봇 상태 · 경로 · 카메라 등 앱이 받는 다른 자료와 그 표현.
   - 각 저장소의 라이선스와, 「앱을 분석했다」 고 적은 범위.
2. **약관과 법적 범위.** Unitree 앱 · 서비스 이용 약관에 리버스 엔지니어링 · 디컴파일 금지 조항이 있는지 원문을 찾아 인용한다 (못 찾으면 미확인). 한국 저작권법 제101조의4 (프로그램코드역분석) 가 허용하는 범위 (호환에 필요한 정보 · 다른 방법으로 얻을 수 없을 때 · 얻은 정보를 비슷한 프로그램 개발에 쓰지 않을 것 등) 를 원문으로 확인해, 「우리 dashboard · app 에 쓸 기법을 배운다」 는 목적이 어디에 걸리는지 사실대로 적는다. 판단은 팀장 몫이다.
3. **rea 확인 (설치하지 않고 문서만).** `morluto/rea` README 에서 Android 앱 · WASM · 네이티브 분석에 필요한 것 (Node 판 · Ghidra 등 · OS · 유료 도구 여부 · 외부 전송 여부) 을 정리한다. Go2 앱이 무엇으로 만들어졌는지 (Flutter · React Native · Unity · 네이티브) 공개 자료로 알 수 있으면 적고, 그 경우 rea 로 볼 수 있는 범위를 적는다.
4. **foothold-app 에 쓸 기법 후보.** 위에서 확인한 것 중 우리 dashboard · app (지도 · 로봇 상태 표시) 에 쓸 수 있는 것을, 「공개 코드로 이미 쓸 수 있음 · 앱 분석이 있어야 알 수 있음 · 로봇 펌웨어 안이라 못 봄」 으로 나눠 적는다.

## 2 단계 (팀장 확인 뒤 · 이번에는 하지 않음)

앱 설치 파일을 어디서 받을지 (공식 스토어 · Unitree 사이트), 약관 결과, 1 단계로 모자란 것이 무엇인지 보고 팀장이 정하면 rea 로 앱을 분석한다.
