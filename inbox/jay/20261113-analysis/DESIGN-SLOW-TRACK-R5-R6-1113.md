## 1. slow_track 수식과 값

몸 기준 평면 명령을 **c=(cx,cy)**, 몸 기준 실제 평면 속도를 **v=(vx,vy)**, 명령 크기를 **s=‖c‖**로 둔다. 둘 다 m/s이며 yaw 명령을 s에 섞지 않는다.

\[
G=\mathbf1[0.1\le s<0.3]\,
  \mathbf1[|c_{wz}|<10^{-6}]\,
  \mathbf1[\neg heading\land\neg flag],\qquad
r_{slow}=wG\exp\left(-\frac{\|v-c\|^2}{(k\max(s,c_0))^2}\right).
\]

| 설정 | 권고 값 | 뜻·근거 등급 |
|---|---:|---|
| `slow_track_sigma`, k | 0.5 | planner 식의 분모 0.25는 k²이다. 0.25를 sigma에 넣어 다시 제곱하지 않는다. 수식 검산 |
| c0 | 0.1 m/s | 0 명령 나눗셈 방지. 현재 코드에서는 `speed.clamp_min(speed_min)`으로 구현 가능. 별도 0.05 명령 문턱을 만들지 않는다. 코드·설계 |
| `slow_track_speed_min` | 0.1, 포함 | 정확히 0.1인 평가도 포함. 학습 최소 약 0.10016이라는 planner 측정과 모순되지 않음. 결정·실측 인용 |
| `slow_track_speed_max` | 0.3, 제외 | 15:41 결정은 하한만 포함으로 바꿈. 정확히 0.3도 포함하려면 별도 변경이다. 결정 |
| 처음 등록한 가중치 | 0 | 기동 때 처치 없음. 결정 |
| R6 첫 활성 가중치 | 0.2 | 완벽한 추종의 추가 값은 기존 선속도 보상 최대 2의 10%. 아래 이득표에 근거한 운영 가정 |
| 이번 보완의 확대 상한 | 0.3 | 0.2를 두 경계 확인한 뒤 최대 한 번 +0.1. 선속도 보상 최대의 15%. 최적값 실측이 아닌 운영 가정 |
| 스키마 허용 범위 | [0,1.0] | 허용 범위와 권고 운용 상한은 다르다. 0.3 초과는 명령별 보상 비용을 재고 별도 결정 |

기존 선속도 추종은 가중 2.0이고 yaw 추종은 1.0이다. 실행 부모의 `params/env.yaml:2044~2055`를 읽었다. 폭 0.35와 zero_yaw −1.0은 이번 시작 설정이다. `RewardManager`는 항마다 **가중치 × dt**를 한 번 곱한다. 여기서는 dt=0.02초이고, 아래 표는 dt를 곱하기 전 값이다. 보상 함수 안에서 dt를 다시 곱하지 않는다. 근거: `/home/jay/mai/projects/IsaacLab/source/isaaclab/isaaclab/managers/reward_manager.py:150`, `:157`.

### 서기와 걷기의 차이

각 방향의 명령에 정확히 맞춰 움직이는 경우와 v=(0,0)인 경우를 비교했다. 다른 보상은 이 표에 포함하지 않는다. 수치는 [계산 CSV](slow-track-r56-data/direction_gain.csv)에서 재생성한다.

| 명령 | 방향 | 서기 r, w=0.2 | 정확한 추종 r | 걷기 이득 | dt 적용 후 이득 |
|---:|---|---:|---:|---:|---:|
| 0.1 m/s | 전진·후진·좌·우 각각 | 0.003663 | 0.200000 | 0.196337 | 0.003927 |
| 0.2 m/s | 전진·후진·좌·우 각각 | 0.003663 | 0.200000 | 0.196337 | 0.003927 |
| 0.5 m/s | 전진·후진·좌·우 각각 | 0 | 0 | 0 | 0 |
| 1.0 m/s | 전진·후진·좌·우 각각 | 0 | 0 | 0 | 0 |

가중치를 빼면 서기 exp(−4)=**0.0183156**, 정확한 추종 **1**, 이득 **0.9816844w**이다. 절반 속도로만 움직이면 0.367879w, 명령 속도의 두 배로 움직이면 서기와 같은 0.0183156w다. 따라서 진행 거리만 키우는 보상과 달리 과속을 최대값으로 보상하지 않는다. 횡 오차도 벡터 오차에 들어간다.

| 전진 명령 | 선속도·yaw 추종·zero_yaw·slow_track 네 항의 걷기−서기 차이 | 가정 |
|---:|---:|---|
| 0.1 | +0.213905 | 걷기 vx=c, 실제 wz=0.1 rad/s, 서기 vx=wz=0, w=0.2 |
| 0.2 | +0.614282 | 같음 |
| 0.5 | +1.600944 | 같음. 이 칸의 slow_track 기여는 0 |

이것은 **부분 보상 계산**이다. 동작 매끄러움·관절 가속·미끄럼·에너지 등의 저속 명령별 비용이 빠져 있다. 전체 env의 벌점 평균을 저속 걷기의 비용으로 대신 넣어 「반드시 걷는 편이 유리하다」고 단정하지 않는다. 실제 저속 보상 항별 합은 `미측정`이다. 식을 개선했다고 학습 성공이 보장되는 것도 아니다.

**영향 0의 범위:** s≥1.0이면 G=0이라 이 항의 직접 보상은 모든 실제 속도에서 0이다. 회전 명령·heading·깃발도 마찬가지다. 하지만 정책 파라미터와 PPO advantage 정규화는 다른 명령과 공유된다. 따라서 해당 능력의 학습 결과까지 불변이라고 주장하지 않으며 4절 유지표를 계속 잰다.

### 구현 계약

- 실제 속도와 명령은 같은 몸 좌표계. `root_lin_vel_b[:,:2]`와 `base_velocity[:,:2]`의 계약을 유지한다.
- heading 표식 또는 flag 표식이 참이면 실제 yaw 명령이 우연히 0인 순간도 제외한다. 표식이 필요한 실행 경로에서 표식이 없으면 조용히 false로 채우지 않는다.
- 가중치 0 등록은 기록이지 학습 적용이 아니다. 양의 가중치를 켤 때 runtime 소비·실제 RewardManager 가중치·경계 영수증을 함께 확인한다.
- 0 명령에서 0으로 나누지 않는다. 비활성 NaN에 단순히 0을 곱하지 않는다. 활성 비유한 행의 처리는 기존 env 단위 격리 계약과 연결한다.
- 답 아는 입력: 전진/후진/좌/우 0.1·0.2 정확 추종은 1, 서기는 exp(−4), 0 명령·0.3·0.5·1.0·회전·heading·깃발은 0. 이 문서의 CPU 검산은 운영 코드 시험을 대신하지 않는다.

### 순정 Go2 공개 자료와 구분

공식 [SportClient](https://github.com/unitreerobotics/unitree_sdk2_python/blob/master/unitree_sdk2py/go2/sport/sport_client.py)는 `Move(vx,vy,vyaw)`와 여러 gait 호출을 공개한다. 공식 [Go2 소개](https://www.unitree.com/go2/)도 다양한 보행을 보여 준다. 하지만 이번에 확인한 공식 자료에는 **순정 정책의 0.1·0.2 m/s 명령별 발 공중 시간·주기 원자료가 없다**. 영상에서 조이스틱·속도·시간이 보정되지 않은 값을 정상 저속 기준 숫자로 만들지 않았다.

공식 [ROS 2 상태 설명](https://github.com/unitreerobotics/unitree_ros2)은 velocity·gait_type·foot_force·foot_position_body·foot_speed_body를 제공한다. 순정 비교를 수치화하려면 펌웨어·gait 모드·명령·타임스탬프·발순서·힘 단위를 함께 기록해야 한다. **0.04초는 순정 정책에서 가져온 값이 아니다.** 공개 SDK의 다른 학습 예제나 제삼자 시뮬레이터 gait 주기를 Sport의 내부 주기라고 인용하지 않았다.

| R6 켜기 | G1b GT의 같은 저속 전진 칸(0.1 또는 0.2, L0/L5 구분)이 완료된 두 경계 연속 R<0.8. 유지표는 유효. 이미 정한 첫250 처방과 충돌하지 않는 다음 경계 | slow_track 0→0.2. k·속도 범위는 고정. 기존 추종 항을 대체하지 않고 더함 |

| R5 켜기 | R6 이후 두 경계 동안 유지 회귀가 없고, 전진0.2의 L0·L5 R이 모두≥0.5. 같은 접촉 정의로 잰 발 자료에서 0.5초 기준이 짧은 완전 구간을 주로 음수로 만드는 사실 확인 | threshold 0.04·weight 0.1을 한 보상 처방으로 적용. R6나 다른 보상은 그 경계에서 바꾸지 않음 |

R6 번호가 뒤라고 R5를 먼저 켜지 않는다. **저속에서 계속 서 있으면 공중 시간 보상은 발생할 이벤트 자체가 부족하다.** m13250의 전진0.1 앞발과 옆0.1 자료가 그 반례다. R6는 정지→작은 이동의 연속적인 차이에 값을 주므로 첫 처방으로 더 직접적이다. 다만 Gaussian의 서기 근처 기울기도 크다고 보장되지 않으며, 정책 표준편차·실제 저속 표본 몫을 함께 기록한다.

## 4. 두 경계 연속 악화 시 되돌림

**비교 기준은 각 처방 활성 직전 저장본으로 고정**한다. 매번 직전 저장본으로 바꿔 조금씩 떨어지는 것을 숨기지 않는다. checkpoint·mesh SHA·seed·지도 모드·명령·시간·시작 배치가 같아야 한다. GT/PRED/지도 끔을 합치지 않는다.

| 유지 축 | 비교할 성분 | 같은 칸이 두 경계 연속이면 되돌릴 변화 | 문턱의 근거·한계 |
|---|---|---|---|
| 좌·우 회전 | map64의 `yaw_follow_median`, 방향별 생존 | 추종 비율이 활성 직전보다 >0.05 감소 | 0.05는 운영 가정. 이 부모의 회전 반복 폭 미측정. 생존 hard HOLD는 아래 우선 규칙 |
| 옆 ±0.4·±0.5 | 각 방향 R·추종 오차·생존, 대칭비 S=min/max | 어느 방향 R이 >0.05 감소. S만 좋아져도 양쪽 R 감소는 회귀 | m2000 S 반복 폭 .025209(±.4), .008118(±.5)을 참고. S 하락>.03은 기록·진단이며 R 감소 없이 단독 되돌림하지 않음 |
| Y1, fwd0.5·1.0 | env별 순 yaw 크기의 중앙값·p90, 진행 R | 중앙값 >0.02 rad 증가 또는 p90 >0.04 rad 증가 | m2000 세 시드 최대 폭 .018060·.039290 rad 참고. 다른 정책의 세 시드 폭이므로 부모 신뢰구간은 아님 |
| 정지 | 기존 stand 성공 수·stop의 몸속도·각속도 | 성공 수가 기준보다 4 env 이상 감소, 또는 몸속도 중앙값 >0.02 m/s 증가, 또는 yaw 속도 크기 중앙값 >0.05 rad/s 증가 | 3/64 허용을 넘는 정수 감소·속도 문턱은 운영 가정. 이 부모 반복 폭 미측정 |
| 빠른 전진·후진·기존 나머지 | 기존 26칸 유지표와 성분 | 기존 hard HOLD 규칙을 그대로 적용 | 직접 보상 0인 칸도 공유 정책 때문에 확인 필요 |

- **기존 유지표가 HOLD면 두 창을 기다리지 않는다.** 기존 R4의 「다음 구간 미기동·lead 확인」이 우선이다. 이 문서는 그 조건을 완화하지 않는다.
- 완성된 비교 가능한 **같은 칸(지도 모드·명령·레벨·지표 성분)**의 연속 두 경계만 센다. 한 경계의 좌회전 악화와 다음 경계의 옆 악화를 합쳐 두 번이라고 하지 않는다. Y1 중앙값 한 번과 p90 한 번도 같은 성분의 두 번이 아니다. 회복하면 해당 칸 연속 수를 0으로 한다.
- 빈 결과·오류·비교 조건 변경은 회복이나 통과가 아니다. 증량·새 처방을 보류하고 부족한 기록을 알린다. 기존 학습 중단 여부는 기존 관문에 따른다.
- 되돌림은 **가장 최근에 적용한 보상 처방의 직전 승인 값**으로만 한다. 예: R6 0→0.2 뒤 악화면 0으로, 0.2→0.3 뒤 악화면 0.2로. R5 0→0.1 뒤 악화면 0으로. 같은 경계에 다른 처방을 새로 켜지 않는다.
- checkpoint·optimizer를 자동으로 과거로 되돌리는 규칙이 아니다. 가중치를 되돌린 뒤에도 정책의 학습된 변화가 즉시 복구된다고 가정하지 않는다. 두 경계 재확인 후 회복 여부를 보고한다.
- 두 확인 창 동안 다른 보상 처방을 넣지 않는다. 승인된 지형 난이도 변화 등이 겹치면 겹친 변수를 영수증에 적는다. 안전한 되돌림은 가능하지만, 원인을 R5/R6로 확정하지 않는다.
- 추가 항 raw/weighted·활성 env-step 수·명령별 몫, 이전/새 값, 원자료 SHA, 되돌림 reason과 해당 칸을 같은 적용 영수증에 기록한다. 이 연결은 planner·runner 구현 검토 대상이다.
