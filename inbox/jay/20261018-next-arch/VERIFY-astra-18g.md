## 1. M1을 다시 설계할 것인가

**추정기를 포함하는 방향에 찬성한다. 「MARG 전체」라는 명칭에는 반대한다.** 18a §1은 M0/M1의 지도 효과만 분리하려고 추정기를 뺀 권고였다. 지금 목적은 각 논문의 접근을 살린 시스템 비교이므로, M1에만 추정기가 있다는 이유로 막거나 M2에도 같은 추정기를 강제할 이유가 없다. 이전 권고를 이 새 목적에 그대로 적용하면 잘못이다.

원문은 추정값 7개를 actor에 넣고, 추정기는 정책 gradient와 속도·접촉 MSE를 함께 받는다. elevation 특징은 critic에도 들어간다. 관측 ablation은 명시적 추정의 가치를 지지하지만 **우리 CTS latent에도 속도 정보가 없다는 증거는 아니다**. 논문 구성 수치는 현재 HTML의 IV-A이며, II-B와 V-C를 함께 확인했다. [MARG v2 II-A·II-B·IV-A·V-C](https://arxiv.org/html/2509.20036v2)

E1의 CTS·actor·critic을 보존하면 논문의 단일 정책 구성과 같아질 수 없다. 원문의 지형·보상·지도 생성까지 재현한 것도 아니다. 권장 이름은 **「E1 + MARG식 명시적 상태 추정·고도 특징」**이다. 기존 b3는 「E1 + 고도 MLP」로 보존한다. 새 판은 다음처럼 구체화하는 것이 타당하다. 아래 계수와 입력 선택은 **우리 설계 제안**이며 공식 구현을 확인한 값으로 포장하지 않는다.

| 항목 | 제안과 주의점 |
|---|---|
| 추정기 입력 | 기존 10프레임×45=450 이력을 별도 MLP에 넣는다. 기존 CTS latent 뒤에 붙이지 않는다. 50 Hz에서 10개 표본은 통상 0.2초 창이라 부르지만 최신~최구 표본 간격은 0.18초다. 논문의 H=5 표기와 같지 않으며 프레임 순서·reset padding은 기존 관측 계약을 유지한다. |
| 추정기 폭 | `450→258→128→7`, 숨은 층 ReLU, 최종 선형을 제안한다. 원문 `[258,128,7]`을 층 폭으로 채택한 이식이다. **258을 공식 이력 입력 차원이라고 단정하거나 256으로 임의 정정하지 않는다.** 음수 속도를 내야 하므로 출력 7개 전체에 ReLU를 붙이면 안 된다. |
| 정답 | 같은 시각의 몸체 좌표계 선속도 3개와 정해진 발 순서의 접촉 4개. 선속도는 물리 단위 m/s, 접촉은 0/1. b6 critic 선속도는 이미 ×2이고 접촉은 ×0.001된 힘 이력 16개이므로 그 일곱 칸을 그대로 잘라 정답으로 쓰면 틀린다. 별도 label 항을 rollout 시점에 저장한다. reset 뒤의 상태나 다음 시점 센서를 현재 이력 정답에 붙이지 않는다. |
| 접촉 정의 | b6의 `foot_contact_flags`는 현재 합력 norm>1 N을 쓴다. 이를 초기 계약으로 재사용할 수 있지만 논문 공식 threshold로 확인된 값은 아니다. 발 body ID 순서를 기록하고 이 정의가 수직 지지뿐 아니라 측면 접촉도 포함한다는 점을 남긴다. 정답에는 gradient를 흘리지 않는다. |
| actor 연결 | `[기존 latent32, 현재45, 지도16, 추정7]`로 100차원. 같은 E1 부모 77열을 복사하고 새 23열은 0으로 시작한다. map·estimator 내부 가중치는 무작위 초기화한다. teacher/student 모두 **예측값**을 쓰며 teacher에만 정답 7개를 공급하지 않는다. 초기 행동 보존은 유한 입력의 초기 시점에만 성립한다. |
| critic 연결 | 논문의 지도 특징→critic 경로도 살리려면 현재 `[latent32, critic275]` 307차원에 같은 지도16을 붙여 323차원으로 확장하고 새 열을 0으로 시작한다. 원래 특권 관측은 유지한다. 이는 E1 보존형 연결이며, raw 지도와 CTS까지 남으므로 공식 critic 입력과 같다는 뜻은 아니다. actor만 지도16을 받게 두면 그 차이를 명시해야 한다. |
| 회귀 손실 | `L_reg = mean((v_hat-v)^2) + mean((c_hat-c)^2)`로 각각 평균낸 뒤 합산한다. `mean(7개 오차)`는 속도·접촉 가중치가 달라진다. 초기 **λ_reg=1.0**을 제안하되 공식 PPO 대비 최적 계수는 미확인이다. 속도·접촉 오차와 gradient 크기를 따로 보고한다. 접촉 회귀값을 곧바로 보정된 확률이라고 부르지 않는다. |
| gradient·optimizer | `L_total=L_PPO+λ_reg L_reg`를 한 PPO optimizer에서 함께 갱신하고 estimator는 **actor의 PPO gradient를 허용**한다. 지도를 critic에 연결하면 value gradient도 지도에 흐른다. estimator를 CTS의 no_grad 안에 넣거나 7개 출력을 detach하지 않는다. 기존 CTS student encoder의 증류 optimizer·no_grad 계약은 유지한다. 새 estimator를 두 optimizer에 중복 등록하지 않는다. teacher/student 양쪽 rollout의 정답을 같은 sample 가중 규칙으로 사용한다. |
| 활성화 | 새 elevation과 estimator의 숨은 층은 ReLU로 한다. E1 actor·critic·CTS의 ELU까지 전역 설정으로 ReLU로 바꾸면 부모 보행 보존 계약이 깨진다. 새 모듈별 activation을 지정한다. |

기존 CTS는 teacher의 32차원 latent를 모사하고 그 teacher는 속도를 포함한 특권 관측을 읽는다. 따라서 student latent에 속도 정보가 **일부 담길 가능성은 있지만**, 속도 3개를 식별 가능한 형태로 보존하거나 정확히 추정한다는 보장은 없다. 현재 손실은 latent 회귀와 gate 균형이며 명시적 속도·접촉 회귀가 아니다. 새 추정기의 의미는 정보가 완전히 새로 생긴다는 데 있지 않고 **해석 가능한 일곱 값과 직접 감독 신호**를 추가하는 데 있다. 중복인지 보완인지는 실제 오차·성공률로 판정한다. 별도 latent probe는 후속 해석에 유용하지만 실행 선행 조건은 아니다.

근거 코드: `C:/Users/AI-WS01/s2_lab/step1_18b_b6_frozen/` 아래 `source/robot_lab/robot_lab/tasks/go2/env_cfg.py:121–242,501–504`, `mdp/observations.py:41–63`; `source/rsl_rl/rsl_rl/modules/actor_critic_moe_cts.py:146–183,326–362`; `algorithms/moe_cts.py:439–458`. 회귀 추가는 저장·로드·평가 때 100/323 입력 폭과 optimizer 상태도 함께 바뀌는 **새 모델 판**이다.

새 actor 열이 0이어도 estimator는 회귀 손실로 첫 갱신부터 배울 수 있다. actor 경유 gradient만 처음에 0이다. λ_reg=1에서 회귀 gradient가 공통 gradient clipping을 지배하면 기존 PPO까지 약해질 수 있으므로, 그 값의 적정성은 미확인으로 두고 성분별 gradient를 기록한다. 이것은 효과 확인 항목이며 별도 실행 승인 조건이 아니다.

## 2. M2도 「AME-2 전체」인가

**아니다.** b6의 지형 모듈은 공식 크기를 반영하지만 77차원 E1 입력과 160차원 추가 출력을 유지한다. 이번에 b6 소스를 직접 읽어 확인했다(`actor_critic_moe_cts.py:44–89,151–176`). 보고서의 CPU 51/51 통과 주장은 이번에 재실행하지 않았다.

원 논문의 전체 체계와 비교하면 다음이 남는다.

- student는 명령·선속도를 제외한 20-step 이력의 LSIO embedding과 명령을 결합한다. 현재는 명령을 포함한 10-step CTS 이력이다.
- 공식 정책의 proprio embedding·행동 decoder, **MoE critic**, 단계별 teacher→student 학습이 다르다. CTS의 student MoE를 공식 MoE critic과 혼동하면 안 된다.
- student 학습은 PPO·행동 증류·지도 embedding 정렬을 함께 사용한다. 현재의 CTS latent 회귀와 동일하지 않다.
- 실제 센서 기반 불확실도 지도, 지도 잡음·가림·융합, 목표 위치·방향 명령과 해당 보상·지형 curriculum도 이번 속도 추종·정답 광선 실험과 다르다.

근거: [AME-2 v3 III-B·IV-A~E·V](https://arxiv.org/html/2601.08485v3). 다만 논문은 proprio encoder 교체 가능성도 명시한다. **LSIO가 없다는 이유로 AME-2 지형 encoder 이식 자체가 무효가 되는 것은 아니다.** `ame2_minimal/README.md`의 Current features는 공개 G1 minimal 코드에 neural mapping과 LSIO student가 아직 제공되지 않는다고 적는다. 지금 전체 재현을 요구하면 공개 파일 몇 개 교체로 끝날 일이 아니다.

따라서 **b6를 유지하고 이식 범위를 명시하라.** M1에는 명시적 추정, M2에는 상태 조건부 attention이라는 각 접근을 살리는 것은 허용 가능한 비교다. 어느 한쪽에 상대의 모듈을 억지로 복제하지 않는다. 정말 전체 논문 정책 비교를 목표로 바꾸면 E1 보존·이번 일정과 별개의 실험 계획이 필요하다.

작은 코드 차이도 남아 있다. b6 global pooling은 `amax`이고 공식은 `torch.max(dim=1)`이다. 동률 최대값에서 gradient 분배가 다르므로 바이트 수준 동일 구현은 아니다(`actor_critic_moe_cts.py:83`, 공식 `AME2_models.py:169`). 이것만으로 현재 실행을 중단할 근거는 없으며 결과 기록에 남길 차이다.

## 3. 각각 10000회, 중간 5000회 비교

**찬성한다. 구조·용량은 다르게 두고 시험 문제와 집계 기준을 같게 둔다.** 같은 부모 E1, 각 판의 추가 update·env transition·실제 GPU 시간을 기록한다. 동일 update는 동일 연산 비용이나 동일 수렴을 뜻하지 않는다. 평가에는 student inference, 동일 지형·명령·초기조건·seed 묶음을 사용하고 E1 기준선도 함께 둔다. 단일 학습 seed의 결과는 해당 실행의 비교이지 구조 일반 우열의 확정은 아니다.

현재 b6 runner의 최초 반복 번호는 20000이며 update 뒤 같은 번호로 저장한다. 정확한 대응은 다음과 같다. 재개 시에는 metadata의 완료 횟수를 우선 확인한다.

| 추가 완료 update | 파일의 iter | 4096 env×24 step의 누적 transition |
|---|---|---|
| 5000 | `model_24999.pt` | 491,520,000 |
| 5001 | `model_25000.pt` | 491,618,304 |
| 10000 | `model_29999.pt` | 983,040,000 |

정기 저장이 번호 500배수라면 **24999 파일이 자동으로 생기지 않는다.** 새 M1 판에는 추가 5000회 경계 저장을 넣으면 된다. 이미 도는 M2에 그 파일이 없으면 두 판의 25000을 골라 「5001회 중간 비교」라고 정확히 적는다. 파일명만 24999로 바꾸면 안 된다. 근거: b6 `runners/on_policy_runner_cts.py:100–113,166,212–242`, `tasks/go2/step1_resume.py:32–45,94–118`, `rsl_rl_cfg.py:6`.

M1이 먼저 도달해도 M2를 기다리며 학습을 멈출 필요는 없다. 해당 checkpoint를 고정하고 10000회까지 계속한다. M1 종료 후 확보한 GPU에서 중간·최종 평가를 진행하면 M2 학습과 병행할 수 있다. 5000회 성적을 보고 구조·보상을 바꾸면 이후 결과는 새 실험으로 구분하고 같은 10000회 곡선에 섞지 않는다.

## 4. 지금 멈추고 재시작할 가치와 비용

**권고는 두 판 일괄 중단이 아니라 M1 한 번 교체다.** 새 M1 구현을 준비하는 동안 기존 실행은 그대로 두고, 새 판 준비 후 기존 checkpoint와 기록을 보존한 다음 같은 E1 부모에서 추가 10000회를 시작한다. 약 1700회 학습한 M1에서 확장해 계속하면 가능은 하지만, 새 구성의 10000회와 기존 구성의 선행 학습이 섞인다. 이번 목적에는 같은 부모 재시작이 더 해석하기 쉽다. 기존 M1은 추정기 없는 참고 결과로 남긴다.

약 1700회라는 진행량과 기존 M1 총 3.52초/update는 lead 보고이며 이번에 재측정하지 않았다. 그 값으로 계산하면 선행 계산량은 약 **1.66 GPU-hour**, 새 10000회는 기존 속도 기준 약 **9.78시간**이다. 추정기·회귀·critic 연결을 추가한 실제 시간과 구현 시간은 여기에 더해지므로 월요일 완료를 보장하지 않는다. 다만 의미 있는 명시적 추정 경로를 넣는 비용으로는 현재의 제한된 진행량을 보존하고 교체할 가치가 있다. 개선 보장은 아니다.

**M2 b6는 유지한다.** LSIO·MoE critic·지도 생성까지 지금 추가하여 또 재시작하면 지형 encoder 비교에서 전체 sim-to-real 체계 구축으로 범위가 바뀐다. 그 비용은 지금 확보된 시간 자료로 추정할 수 없다. b6의 실제 지속 처리량도 미확인이므로 작은 b4의 속도나 MAC 비율로 새 완료 시각을 확약하지 않는다.

일정 판단은 단순하다. 예를 들어 10/18 19:00에 새 판을 시작해 화요일 09:00까지라면 38시간이다. 5000회에는 평균 **27.36초/update 이하**, 10000회에는 **13.68초/update 이하**가 필요하며 저장·평가 여유를 빼면 더 빨라야 한다. b6가 이를 못 맞추면 화요일에는 중간 비교 또는 미완료로 보고하고, 10000회 최종 비교는 실제 완료 뒤 한다. 둘 다 10000회를 원한다는 지시를 근거 없는 화요일 완료 약속으로 바꾸면 안 된다.

이번 자문은 설계·해석 의견이다. GPU·Isaac 실행, 프로세스 종료, 코드 수정, 커밋은 하지 않았으며 추가 승인 관문도 만들지 않았다.
