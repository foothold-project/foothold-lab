# ASTRA 19d · START → HiPAN 위의 추가 아이디어

## 0. 범위와 결론

팀장이 든 비율과 수치는 확정값으로 취급하지 않았다. 다른 검토자의 19d 의견은 읽지 않았다. 기존 명세에서는 START 원문 경로만 찾았고, 판단 근거는 논문과 코드로 다시 확인했다. 요청 산출물만 추가하며 실행 코드·원자료·진행 중 프로세스·git 이력은 바꾸지 않는다. 기존 작업 변경이 많아 공유 체크아웃에 pull/merge도 하지 않았다. 이 자문은 #557에 속하며, 아래 실험은 권고이지 매번 사람의 허락을 기다리는 새 관문이 아니다.

**가장 유망한 가설은 “기억을 더 복잡하게 만들자”보다 “카메라에서 사라진 디딤면에 새 LiDAR 관측을 넣으면 기억의 오판이 줄어드는가”이다.** 관측이 실제로 늘어나는지부터 확인해야 한다. 턱의 L1이 모든 발밑을 본다는 가정, 점 수 비율이 그대로 보행 성능 비율이라는 가정, 낮은 정책 확신을 언어 모델이 해결한다는 가정은 근거가 없다.

권고 순서는 **바탕 재현 → L1 보강 → 융합 방식 비교 → 필요한 항법 연결 → Laya의 추가 효과**다. 센서 기록·외부 보정과 위치 추정 인터페이스는 바탕 학습과 병행한다. JEPLO식 자기지도 학습은 LiDAR를 추가하는 것과 별도 실험이다. 11/7에 네 아이디어 모두의 폐루프 효과를 보여주겠다는 일정은 현재 속도·구현량 실측 없이 약속할 수 없다.

## 1. L1 + D435i와 JEPLO: 타당하지만, 그대로 꽂는 문제가 아니다

### 1.1 센서 보완의 근거와 반례

L1 공식 설명서는 유효 21,600점/s, 수평 360°·수직 90°, 둘레 11 Hz·세로 180 Hz, 최소 거리 0.05 m를 명시한다. Livox 공식 MID-360 사양의 200,000점/s와 나누면 약 **9.26배 차이**다. 다만 둘의 FoV·스캔 시간·배치·반사 조건이 다르므로 “우리 지형 셀의 관측량도 정확히 1/9”은 아니다. [L1 공식 설명서, 개요·제원](https://oss-global-cdn.unitree.com/static/f5ca3e9038d44ca29f711f90005a2185.pdf), [MID-360 공식 사양](https://www.livoxtech.com/mid-360/specs).

100 ms의 명목 유효 점 수는 L1 2,160점, MID-360 20,000점이다. 이 점들이 모두 발 디딤 영역에 들어가는 것은 아니다. 2° 간격은 거리 1 m에서 약 3.49 cm, 2 m에서 약 6.98 cm에 해당한다. START의 5 cm 높이 격자에서 얇은 디딤면·가장자리 일부는 실제로 관측되지 않을 수 있다. 이 수치는 단순 기하 계산이며 실제 커버리지 측정값이 아니다.

“D435i는 앞쪽, L1은 가까운 주변”이라는 역할 분담은 합리적인 가설이다. **고정 거리로 둘을 잘라 쓰지는 말자.** 몸체·다리의 가림, D435i의 장착 피치·최소 거리·깊이 모드, L1의 실제 설치 방향이 커버리지를 결정한다. 겹치는 영역은 외부 보정과 센서 불일치 검출에 유용하다. L1도 유리·반사·약한 반사율에서 항상 정답을 주는 센서가 아니다. 실제 Go2에서 이용 가능한 토픽에 원시 점별 시각이 남아 있는지, 턱 장착에서 각 발 주변을 얼마나 보는지는 **미확인**이다.

### 1.2 JEPLO 원문과 공개 코드에서 확인한 것

JEPLO 논문 §II·III는 Mid-360 전방 120°×50°를 2° 구면 거리 영상으로 만들고, 최근 5스캔을 **운동 왜곡 보상 없이** 누적한다. JEPA는 미래 latent 예측과 SIGReg를 쓰며, teacher/student 및 PPO와 학습 목적·gradient 경계를 구분한다. 즉 구면 ViT를 붙이는 것만으로 JEPLO의 예측 학습이나 CJTS 효과를 얻지는 않는다. [원문 v1 §II·III](https://arxiv.org/html/2609.15770v1).

검토한 공개 코드는 `ASIG-X/JEPLO@460e2272907af053d6e66b57fec71fdbe6ca1774`이다. 이하 J 루트는 [이 고정 커밋](https://github.com/ASIG-X/JEPLO/tree/460e2272907af053d6e66b57fec71fdbe6ca1774)을 뜻한다.

### 1.3 어떤 형태로 붙일 것인가

**첫 추가판:** L1 점을 시각·외부 파라미터와 함께 현재 몸체 기준의 희소 높이 관측으로 바꾸고, `높이·valid mask·최근 관측 경과시간·점 수`를 별도 갈래로 TR-Net에 공급한다. D435i 갈래와 겹치는 곳에서 서로 일치하는지도 입력/평가한다. 기존 START 지도 정답과 rough/refined 지도 손실은 유지한다. 새 채널은 우리 추가이며 논문 원형과 분리한다. 단순 encoder가 기준선이고, 그다음에 같은 LiDAR 입력으로 JEPLO식 구면 ViT를 비교한다. 처음부터 CNN/ViT·센서·손실을 동시에 바꾸지 않는다.

희소 점을 높이 격자로 만드는 과정도 중립적이지 않다. 벽·책상 윗면·천장을 발 디딤면으로 투영하거나, 여러 높이를 평균 내어 공중의 바닥을 만들면 안 된다. 지면 후보와 수직/머리 위 장애물을 구분하고, 근거 없는 셀은 unknown으로 남긴다. 상부 장애물은 HiPAN의 depth/공간 표현으로 계속 전달한다. 모든 3D 정보를 2.5D 발판 지도 하나로 대체하지 않는다.

**추가 JEPA 실험:** 센서 보강 효과가 확인된 뒤 동일 ViT에 예측+붕괴 방지 목적을 더해 비교한다. 처음에는 START의 기존 지도 감독을 그대로 두고 보조 목적을 LiDAR 표현에 제한한다. 손실 계수·gradient 소유권은 우리 선택으로 기록한다. SIGReg 없이 이름만 JEPA라고 하거나, CJTS의 detach를 무심코 복사해 START 지도 학습 경로를 끊지 않는다. JEPLO 전체 재현이 목적이면 별도 방법으로 다뤄야 한다.

### 1.4 누적·기억·스캔 지우기

- **누적은 프레임 수가 아닌 ms와 pose로 정의한다.** L1 SDK의 `PointUnitree.time`은 cloud stamp 대비 상대 시각이며 `cloud_scan_num` 기본값은 18이다. ROS 메시지 다섯 개를 L1 둘레 다섯 바퀴와 동일시할 수 없다. [SDK `1bd7d95`, `unitree_lidar_sdk.h:45-74,138,152`](https://github.com/unitreerobotics/unilidar_sdk/blob/1bd7d95d8ab7ce7a22058d2bb07e39fd62612aa6/unitree_lidar_sdk/include/unitree_lidar_sdk.h#L45).
- 고속에서 누적은 공짜 밀도 증가가 아니다. 예를 들어 1.5 m/s에서 100 ms 동안 15 cm 이동한다. 과거 range 영상을 그대로 최소값 누적하면 턱·벽이 현재 위치에 남는 잔상이 생길 수 있다. 점별 pose 또는 짧은 구간별 pose로 정합하고, 시각·오도메트리 오차도 학습에 넣는다. 정확한 정합이 안 되면 짧은 창+age를 먼저 쓴다. 허용 창 길이는 실제 로그로 정할 값이다.
- **측정 없음은 안전한 빈 공간도, 구멍의 확정도 아니다.** 무반사·스캔 미방문·가림·거리 밖을 mask로 구분한다. JEPLO식 먼 거리 채움 하나만 쓰면 LiDAR 미방문을 열린 공간으로 읽을 위험이 있다.
- 지우기는 독립 점 dropout만으로 부족하다. 연속 몇 메시지 손실, 특정 방향 섹터 가림, 발/몸체 가림, 시간 지연·지터, 반사율 의존 손실, 센서 한쪽 전체 정지를 포함한다. 확률·기간은 실측 기반으로 정하고 현재는 미확인이다. 두 센서가 함께 실패하는 조건도 별도 평가한다.
- GRU가 계속 같은 지형을 추정한다고 정보가 새로 관측된 것은 아니다. 장기 미관측과 새 장애물 등장 조건에서 낡은 지도의 잔존 시간을 잰다. 두 센서 모두 없을 때의 불확실함을 숨기지 않는다.

### 1.5 L1을 Isaac Lab에서 충실하게 흉내 낼 수 있는가

**각도·시간·가림의 기하 모델은 구현 가능하나, 현재 JEPLO 코드를 그대로 써서 충실하다고 할 수 없다.** 설치된 `C:/isaac/IsaacLab/source/isaaclab/isaaclab/sensors/ray_caster/ray_caster.py:281-305`는 갱신 시점 자세로 광선을 만들고 지정 mesh에 raycast한다. `ray_caster_cfg.py:62-75`의 패턴/정렬만 바꿔도 점별 취득 시각, 움직이는 다리 가림, 재질별 무반사까지 자동으로 해결되지는 않는다. JEPLO 설정도 `mesh_prim_paths=["/World/ground"]`라 실제 몸체 가림은 별도 증강에 의존한다.

제안은 L1의 실제 `각도·상대 시각·ring` 기록에서 반복 가능한 패턴을 얻고, 환경별 시작 위상과 시간 변화를 재현하는 것이다. FOV와 11/180 Hz만으로 광학계의 정확한 궤적을 지어내지 않는다. 실측 로그는 이미 반환된 점만 담으므로 무반사 방향의 발사 패턴까지 완전히 식별하지 못할 수 있다. 누락 ray·반사 손실 모델은 구분해서 둔다. 시뮬레이터에서는 구간별 몸체/다리 자세와 ray를 연결하고 몸체 가림 또는 실측 가림 mask를 적용한다.

충실도는 평면·단차·얇은 디딤면의 정지/회전/보행 로그에서 방향별 점 밀도, 시간별 새 관측 셀 비율, 가장자리 위치 오차, false surface, 미관측 지속시간으로 비교한다. 이것은 개선 데이터를 얻는 시험이지 본선 학습 전체를 정지시키는 승인이 아니다. 광학 반사·동시 센서 간섭까지 완전 재현한 것은 **미확인**으로 남긴다. 재현이 약하면 실기에서는 지도에 없는 턱, 남아 있는 과거 발판, 좌우 관측 공백, GRU의 과신이 나타날 수 있다.

L1의 360°를 JEPLO의 전방 120°로 잘라 버리면 카메라 뒤쪽 보완이라는 장점을 잃는다. 반대로 360° 전체를 같은 해상도로 한 ViT에 넣으면 토큰·attention 비용이 증가한다. 첫 추가판은 START 지역 지도 범위에 필요한 점과 별도 방향별 장애물 정보를 이용하고, 전체 구면 ViT는 계산량을 따로 측정한다.

## 2. 기억 0.3 · 현재 0.7: 비교 기준선이지 정답이 아니다

**현재 range 영상과 GRU hidden vector는 단위·의미·차원이 달라 그대로 더할 수 없다.** START에는 이미 recurrent update가 있다. 여기에 임의 scalar를 곱하는 것과 “과거 지도와 현재 지도 추정 중 어느 것을 신뢰하는가”는 다른 문제다.

우선 같은 시각·좌표·해상도로 맞춘 높이 추정끼리 비교한다. 제안 형태는 `h = (1-g)·h_prior + g·h_current`이되, 이 수식도 같은 표면에 대한 추정일 때만 쓴다. 바닥과 벽/상판처럼 서로 다른 표면이면 평균해서 가짜 발판을 만들지 말고 불일치/unknown으로 처리한다. prior는 이전 로봇 좌표 그대로가 아니라 현재 좌표로 옮겨야 한다.

| 방식 | 판정과 사용할 자리 |
|---|---|
| 고정 0.3/0.7 | 팀장 예시를 대조군으로 사용할 수 있다. 두 값이 모두 유효할 때만 적용한다. 하나만 유효하면 그것을, 둘 다 무효면 unknown. 0.7이 최적이라는 근거는 없다. |
| 학습형 gate | **우선 실험 권고.** 셀별 valid·age·점 수·거리·시선각·센서 간 차이·pose 품질을 보고 g를 학습한다. 지도 정답으로 감독하되 실제 분포에서 calibration/오차를 별도 잰다. 단순히 성공 보상만 주어 과신하는 gate를 만들지 않는다. |
| 불확실도 기반 융합 | 측정/예측 분산이 실제 오차를 설명할 때 유용하다. START 원형의 point estimate를 확률로 포장해서는 안 된다. 추가 분산 head·proper loss·held-out calibration이 필요한 별도 변경이다. |

AME-2 §V-A 식 (6)~(8)은 고정 가중 평균이 아니라 **확률적 winner-take-all**이다. `R_eff=max(R,0.5P)`, 유효한 경우 `p_current=P/(P+R_eff)`로 현재값이 셀을 덮어쓴다. 따라서 이상적인 상한은 2/3이고, “새 관측을 항상 0.7로 신뢰”하는 구조가 아니다. [AME-2 v3](https://arxiv.org/abs/2601.08485v3). 직접 읽은 공식 `ame2_minimal@8beb9a688d67882828019583f7d5a78e3517f233`, `ame2/ame2/sensors/neural_mapping_utils.py:681-715`는 상대 허용을 `1.25P`, 절대 허용을 `0.04`로 구현한다. 논문 상대 허용 `1.5P`와도 다르다. 이를 채택하면 어느 판을 썼는지 밝혀야 한다.

이 코드의 목적은 같은 정보의 반복 예측으로 분산이 계속 줄어드는 과신을 피하는 데 있다. 그러나 잘못된 지도·보정 오류·분포 밖 입력까지 해결한다는 보장은 아니다. GRU prior가 이미 현재/직전 LiDAR를 사용했다면 독립 측정 둘로 간주하는 역분산 평균은 이중 계산이다. AME 방식도 정답 보증은 아니고, 얇은 디딤면에서 셀별 무작위 교체가 지도 깜빡임을 만드는지 확인해야 한다.

비교는 현재 관측만, prior만, valid 기반 단순 융합, 예시 0.3/0.7, 학습 gate 순서다. 확률 융합은 그 다음 선택이다. 같은 저장 궤적에서 지도 오차·가장자리 위치·새 장애물 반영 지연을 먼저 비교하고, 폐루프 학습에서는 같은 예산으로 보행 효과를 확인한다. 오프라인 지도 오차 감소를 보행 성공 증가로 대신 보고하지 않는다.

### 3.2 “확신이 낮다”를 무엇으로 정의할 것인가

한 숫자를 정책 확신이라고 부르지 말고 세 갈래를 분리한다.

1. **관측의 신뢰:** 후보 착지 영역 valid 비율·age, 센서 불일치, pose/시간 보정 잔차, 예측 지도 오차의 보정된 상한. 측정이 없는 경우에는 unknown임을 보존한다.
2. **실행의 위험:** 발판 경계까지 여유와 위치 오차의 관계, 지지 상태, slip·추종 오차, 현재 동작의 실행 가능 범위. START가 직접 착지 후보 분포를 출력한다고 가정하지 않는다. 후보 애매함을 쓰려면 별도 후보 생성/채점기가 필요하다.
3. **상위 진행의 막힘:** 일정 시간 목표 진전 없음, 반복 방문·명령 반전, 접근 가능한 대안의 차이가 작음. HiPAN의 탐색 능력과 중복될 수 있다.

actor entropy, critic 값, GRU 크기, JEPA 예측 오차를 곧바로 낙하 확률로 쓰는 것은 부적절하다. 알려진 실패/성공의 held-out 장면에서 위험 점수와 실제 실패의 관계를 보정해야 한다. 관측 부족은 재관측·감속 사유이고, 충분히 보이는 복수 경로 중 선택이 모호할 때가 판단 모델을 시험하기 더 좋은 상황이다.

### 3.3 권고 구조와 실패 경로

Laya는 비동기 **전술 조언자**로 둔다. 입력은 수치·단위·좌표계·시각·unknown·허용 동작 목록을 가진 고정 스키마로 만들고, 출력은 자유 텍스트 속도값이 아니라 제한된 action ID로 받는다. 만료 시각/장면 버전이 지난 답은 버리고 저수준 보행 주기를 기다리게 하지 않는다. `usage.truncated`처럼 입력 잘림도 확인한다. 명령 반전에는 hysteresis와 최소 유지 규칙을 둔다.

**도움닫기를 속도와 몸 높이를 올리는 것으로 정의하면 안 된다.** 실제 gap 통과 기능, 접근 거리, 착지 가능 범위, 지지 단계가 학습되어 있어야 한다. START 명령으로 검증하지 않은 점프·횡이동·후진·자세 변경은 Laya의 선택으로 생기지 않는다. 첫 action 집합은 실행 가능한 감속·재관측·정지 유지·이미 가능한 우회 중에서 정한다. 도움이 될 실험임을 확인한 뒤 검증된 동작을 늘린다.

`RomanSlack/jev-drone@974b47378c14c6dcf7d11f7c813fba0f5f4d8b6a`의 [run.py:161-218](https://github.com/RomanSlack/jev-drone/blob/974b47378c14c6dcf7d11f7c813fba0f5f4d8b6a/run.py#L161)는 조언 유효시간·특수 동작 선행조건·마지막 reflex override를 실제로 둔다. 이 권한 분리는 참고할 만하다. 그러나 drone의 거리 기반 회피가 보행 로봇의 지지 안정성까지 보장하지는 않는다. 무조건 순간 정지도 가장자리/동작 중에는 불안정할 수 있다. 복사할 것은 숫자가 아니라 역할 분리다.

더구나 같은 파일에서 climb 분기는 조언 사용 경로 안에 있다. 이 방식 그대로 “판단 모델 없음”을 만들면 사용 가능한 동작도 줄어 모델 추론 효과와 동작 집합 효과를 섞게 된다. 우리 비교에서는 규칙 선택기·작은 MLP·Laya 모두 **동일 동작 집합과 동일 거부권**을 사용해야 한다.

### 3.4 미세조정 자료와 검증

시뮬레이션의 같은 시작 상태에서 허용 동작별 분기 rollout을 만들어 성공·낙하·접촉·소요시간·진전량을 기록한다. 관측 입력에는 실기에서 얻을 수 있는 것만 넣고, 정답 선정에는 simulator truth를 사용할 수 있다. 애매한 상태는 억지 단일 정답 대신 동률/기권으로 표시한다. 사람은 경계 사례를 검토하며 언어 모델이 자기 답을 정답으로 삼지 않는다.

학습/검증/시험은 영상 프레임이 아니라 **지형·장면·궤적 단위**로 나눈다. 선택지 순서·부정·단위·unknown 표현 변화도 시험한다. 저확신 사례에만 부르면 그 조건의 분포에서 calibration과 오답을 재야 한다. 전체 상태에서의 분류 정확도로 대신하지 않는다. shadow는 답과 실행했다면의 선택만 기록하고 현재 명령을 바꾸지 않는다.

비교 지표는 낙하/충돌률·임무 성공·정체 회복·불필요 정지·조언 거부율·p95/p99 전체 지연이다. 판단 정확도만 높고 정체나 지연이 늘면 채택 근거가 약하다. 원격 모델/통신을 쓰면 왕복·끊김도 포함한다. Laya 코드의 Apache-2.0 표기와 사용 가중치·학습 자료의 권리는 별도로 확인한다. 현재 로봇 자료도 없는 상태에서 11/7 본선에 넣을 우선순위는 낮다.

## 4. HiPAN과 SLAM/Nav2: 시연은 HiPAN + 목표 좌표 공급부터

### 4.1 원문이 말하는 것과 말하지 않는 것

HiPAN §IV-C는 high-level student가 depth 외에 고유수용·추정 몸 상태·**몸 기준 상대 목표 위치**를 받는다고 명시한다. §V-D는 Go1·D435i·NUC의 실기 실험을 설명하지만 이 상대 목표를 실기에서 어떤 위치 추정기로 계속 갱신했는지 충분히 밝히지 않는다. Fig.6의 LiDAR 지도는 시각화용이다. 이것으로 “LiDAR를 위치 추정에도 썼다” 또는 “위치 추정이 전혀 필요 없다” 어느 쪽도 확정할 수 없다. [HiPAN 원문](https://arxiv.org/abs/2604.26504), 로컬 원문 `C:/Users/AI-WS01/s2_lab/_papers/2604.26504.txt:527-535,871-883` 직접 확인.

SPL 88.7과 SR 96.5는 논문의 특정 평가 조건 결과다. 막다른 길 회복 사례는 유망하지만 모든 긴 경로에서 완전성이나 최단 경로를 보장하지 않는다. Go2·START 저수준·우리 행사장으로 자동 이전되는 수치가 아니다.

**먼저 해결할 인터페이스:** START 원문 §III-D는 전진·정지 상태 회전 중심의 명령 분포다. HiPAN은 평면 속도·yaw와 몸 높이·roll 명령을 사용한다. START를 그대로 두고 HiPAN 출력을 연결하면 지원하지 않는 명령이 생긴다. 자세/명령 범위를 지원하는 저수준 학습이 필요하고 이것은 “START 원형 그대로”와 구분할 추가판이다. HiPAN §V-C도 저수준을 고정해 교체했을 때 명령 분포 차이·충돌 증가를 보고한다. 시작부터 Laya를 더하면 이 책임을 세 층이 나눠 원인 추적이 더 어려워진다.

### 4.2 발표장과 최종 트랙의 권고

**발표장 작은 폐쇄 코스:** HiPAN에 하나의 상대 목표를 주고, 검증 가능한 pose 공급원을 붙이는 구성이 우선이다. 초기 위치를 아는 짧은 구간+오도메트리 또는 이용 가능한 외부 위치 기준을 쓸 수 있다. 외부 기준은 숨기지 않는다. 변환은 개념적으로 `goal_B = R_WB^T (goal_W - position_WB)`이며 오도메트리 누적오차가 goal 허용범위와 비교해 어느 정도인지 잰다. 작은 행사장이라고 드리프트가 저절로 사라지는 것은 아니다. SLAM을 안 쓸 수는 있어도 상대 목표 갱신 근거는 필요하다.

**여러 방·반복 임무·지도 기반 목표:** SLAM/위치 추정 + Nav2 전역 경로 + HiPAN 구간 주행이 적합한 확장이다. `map → odom → base_link → sensors`와 시각 일관성을 갖추고, Nav2는 충분히 먼 subgoal을 주며 HiPAN은 구간 내 속도·자세를 정한다. [Nav2 공식 상태 추정 설명](https://docs.nav2.org/rolling/getting_started/navigation_concepts/state_estimation/).

여기서 Nav2의 일반 local controller와 HiPAN이 동시에 속도를 보내면 안 된다. HiPAN을 controller adapter로 쓰거나 전역 planner만 이용하고, 명령 발행자는 하나로 둔다. subgoal을 너무 자주 바꾸면 recurrent 문맥·목표 분포가 달라진다. Nav2가 최종 목표 대신 촘촘한 waypoint를 주는 시스템은 HiPAN 단독 성능과 구분해서 평가한다. 평면 costmap만으로는 낮은 통로의 자세 가능성·낙하·디딤면을 정확히 표현하지 못하므로 보행 가능성/상부 여유 정보를 별도로 연결한다.

11/30에 끝나는 SLAM/Nav2 완성 트랙을 11/7 첫 시연의 필수 의존성으로 만들지는 말자. 11/25까지 학습한다면 pose·goal·명령 인터페이스와 기록 재생기는 미리 맞추고, 큰 경로 결합은 트랙 진행에 따라 검증한다. SLAM 추가와 전역 계획 추가도 효과가 다르므로 별도 비교한다.

## 5. 넣었을 때·뺐을 때: 최소한의 식별 가능한 비교

각 행은 앞의 모든 실험이 끝나야 GPU가 돌 수 있다는 승인 절차가 아니다. 서로 독립인 센서 기록·오프라인 비교·바탕 학습은 병행하고, 제한된 예산에서는 위쪽의 질문부터 답한다. 아래 C·F·E·N·J는 비교 이름이며 확정 실행 목록이 아니다.

| 질문 | 넣었을 때 / 뺐을 때 | 같게 둘 것 · 볼 것 |
|---|---|---|
| C. L1이 정보를 더 주나 | D435i+L1 / D435i만. L1만은 보조 진단 | 같은 지형·출발·명령·카메라 조건. 실측 관측 셀 수·age·edge 오차·거짓 발판과 보행 실패. 센서 하나씩 가림도 비교 |
| F. 지능적 융합이 필요한가 | 학습 gate / valid 기반 단순 융합·예시 0.3/0.7 | 같은 센서 입력·시간 보정·map decoder·학습 예산. 현재만/prior만은 기억 기여 진단. 확률 융합은 추가 선택 |
| E. JEPLO식 encoder/목적이 도움이 되나 | 구면 ViT / 단순 encoder, 이후 같은 ViT+JEPA / JEPA 없음 | 입력 FoV·관측 창·actor·보상 유지. 모델 크기/연산량 차이는 보고. 새 센서와 새 목적을 한 번에 바꾸지 않음 |
| N. 전역 경로의 이득인가 | 같은 pose+Nav2 subgoal+HiPAN / 같은 pose+최종 goal+HiPAN | 같은 저수준·목표쌍·장애물·제한시간. 성공·SPL·충돌·정체·subgoal 전환 수. pose source 차이는 별도 시험 |
| J. 언어 판단이 이득인가 | 같은 허용 동작의 Laya 선택 / 규칙 또는 작은 MLP 선택 | 같은 관측 요약·trigger·동작·거부권. 멈춤/우회 옵션을 대조군에서도 허용. 실행 지연 포함한 임무 효과 |

**학습을 바꾼 효과와 시험 때 센서를 꺼 본 효과는 구분한다.** 융합으로 학습한 정책에서 L1만 끄는 것은 장애 내성 시험이며, D435i 단독으로 충분히 학습한 정책과의 기여 비교를 대신하지 않는다. 추가 sensor/encoder로 파라미터 수가 늘면 “센서+구조 묶음의 이득”인지, 파라미터를 맞춘 대조로도 남는지 표현을 나눈다.

고정 평가 장면은 최소한 정상, 전방 가림/회전 후 보행, 얇은 디딤면·gap, 오래된 지도/새 장애물, sensor 지연·손실, U자 막다른 길, 낮은 통로로 나눈다. HiPAN 전역 경로 비교는 장소 조건, L1 보강 비교는 센서 조건을 섞어 전체 평균 하나로 숨기지 않는다. 미측정 마찰을 지도 신뢰도만으로 알아냈다고 해석하지 않는다.

팀장 방향대로 **한 training seed를 끝까지 관찰한 뒤 재현**한다. 다만 각 후보는 동일 update뿐 아니라 환경 상호작용 수·wall time·encoder 비용도 함께 보고한다. 한 seed에서 고정된 다수 장면/시작점으로 평가하고 같은 장면끼리 차이를 낸다. 반복 프레임·같은 맵의 여러 출발을 독립 training seed처럼 세지 않는다. 장면 묶음별 paired bootstrap 등의 구간은 그 학습판에 조건부인 구간이며 seed 간 일반화 증거는 아니다. 이후 유망한 최종판과 바로 전 대조군을 새 training seed로 같이 재현한다.

기존 다른 의뢰의 “세 칸 하한·10%p”를 이번 탐색에 자동 적용하지 않는다. 핵심 주장은 센서 보강 시 관련 실패가 줄고 정상 조건 퇴행/지연 비용이 어떤가이다. 실패·timeout·사용자 개입을 제외하지 않고 전체 분모에 포함한다. 샘플 수와 채택할 차이는 원하는 구간 폭·예산을 보고 결과 전에 정할 값이다. 현재 효과 크기와 필요한 학습 시간은 **미확인**이다.
