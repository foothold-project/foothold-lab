# 실험 설계 v2: MoE-CTS 바탕 + 지형 모듈 비교 (10/18 일 ~ 10/21 수)

## 0. 팀장 방향 (lead 창 직접 입력 요지)

1. 출발선은 MoE-CTS(E1). student 가 몸 상태 0.2 초로 teacher 의 지형 latent 를 짐작하는 보행 기본기다.
2. MARG · AME-2 · START 의 방식을 이 바탕에 붙여 「우리만의 실험」 을 만든다. 실제 논문 기조를 붙인 효과가 핵심이다. M0(지도 없이 다시 학습)는 나중 비교 대상.
3. 쉬운 것부터. 먼저 최종 목적(gap · 징검다리 등)에 도달, 차별점은 그다음.
4. 월요일까지 학습이 돌아도 된다. 화요일 쯤 유의미한 결과가 나오면 그 실험을 골라 고정하고, 수요일까지 유의미하면 Linux 에서 규모를 키워 이어 간다.
5. 세션 토큰은 설계 · 지시 · 중간 확인에만. 학습이 끝나면 평가를 따라가 아티팩트에 올린다.
6. 석헌 님 지형 · 평가 세트는 지금 쓰지 않는다. 석헌 님 코드에 기대지 않는다.

## 1. 물음

**같은 고유수용감각 바탕(E1) 위에, 어느 논문의 지형 모듈을 붙여야 gap → 징검다리를 건너면서 바탕 보행을 지키나?**

- 붙이는 것은 각 논문의 「지형 정보를 어떻게 인코딩해 actor 에 합치나」 이다. 학습 레시피 전체를 가져오지 않는다. 세 방식은 신경망 구조가 달라 위로 쌓지 않고 **나란히** 비교한다.
- 명령 체계: MARG · START 는 우리와 같은 속도 추종, AME-2 는 목표 위치형이다(`PAPERS-architecture.md` 1 · 2 · 3 절). AME-2 에서는 attention 지도 encoder 만 가져오고 명령은 속도 추종을 유지한다. 「속도 추종에서 AME-2 식 encoder 가 효과가 있나」 는 미확인이고, 그 자체가 우리 질문이다.

## 2. 판

| 판 | 무엇 | 언제 |
|---|---|---|
| E1 | `model_20000.pt` (SHA c8951b79…) 그대로 | 기준 |
| **M1** | E1 + MARG 식 지형 갈래: height 187 → MLP [128, 64, 16] → actor 입력에 더함 | 1 차 |
| **M2** | E1 + AME-2 식 지형 갈래: 같은 187 칸을 점마다 (x, y, z) 로 보고, 몸 상태로 만든 query 가 점들에 multi-head attention → 출력을 actor 입력에 더함 (세부 3 절) | 1 차 |
| M0 | E1 + 같은 학습 묶음(구멍 +1 · gap · 발 보상), 지형 갈래 없음 | 대조 (GPU 가 비는 때) |
| M3 | E1 + START 식: 깊이 영상 → 지도 재구성 → 융합 | 다음 주 (깊이 렌더 · TR-Net 코드 복원 필요, DeepCode 를 우리 형태로 쓸지는 팀장 · super · pipeline 논의) |

M1 · M2 의 차이는 **지형 encoder 하나**다. 입력(같은 187 칸, 구멍 = +2.5), 출발 체크포인트, 학습 묶음, 보상, 지형, 명령, env 수, PPO 설정, 평가가 같다.

## 3. 공통 학습 묶음 (ASTRA 18a 반영)

- 지형 갈래는 actor 입력에만 붙인다. student 증류 구조(별도 Adam · teacher latent 회귀)는 유지한다. teacher rollout · student rollout · PPO 재계산 · act_inference 가 같은 지도 경로. 지도 encoder 는 PPO optimizer 에 등록. actor 첫 층은 기존 77 열을 복사하고 새 열만 0 (첫 행동 = E1, CPU 확인 차이 0.0).
- 구멍: 수정한 critic 관측의 height 187 (`height_scan_with_gap` → clip [-1, 1] → × 2.5, 구멍 = +2.5) 을 teacher · critic · 지형 갈래가 함께 쓴다.
- 이어받기: `model_20000.pt`. PPO lr 5e-5 에서 50 iteration 동안 1.708e-4 까지 올림, adaptive(KL 0.01) 는 그 상한 안. student lr 1e-4. 갱신 KL 기록 · 초과 시 lr 축소 · 남은 최적화 중단. optimizer 이어받기가 어려우면 모든 판 같은 원칙으로 재시작. 환경 curriculum 끝값(base_height -10 · lin_vel_z 0 · zero-command 0.1 · 명령 x/y ±1.0 · yaw ±1.5) 명시.
- 보상: E1 15 항 + feet air time 1.0 · stumble -1.0 · feet center -0.01 (우리 변형, 학습 adapter 가 안 되면 모든 판에서 제외).
- 종료: 기존 + 바닥 없는 틈 낙하 종료(모든 판 같게). 무효 광선에서 base height 보상이 꺼지는 발생률 기록.
- 추정 머리(v̂ · ĉ) 없음 (지도 효과와 섞이지 않게, 18a 1 절).

### M2 지형 갈래 세부 (안 · ASTRA 검토)

| 부분 | 안 | 근거 |
|---|---|---|
| 점 특징 | 187 점마다 [x, y (base 고정 좌표), z (위 높이)] → MLP 3 → 32 → 64 | AME-2 의 점 특징 (논문 CNN 은 26 × 16 이상 격자용, 17 × 11 에서는 점 MLP 로 시작) |
| 전역 특징 | 점 특징 max-pool → 64 | AME-2 전역 max pool |

| attention | MHA d = 64, head 4, query 1 개가 187 점을 봄 | AME-1 d 64 · head 16, 석헌 이식 96 · 32 (우리 격자가 작아 head 4 로 시작, ASTRA 의견) |
| 출력 | [attention 64, 전역 64] → actor 입력에 더함 (새 열 0 시작) | M1 과 같은 붙이는 방식 |

## 5. 평가 (결과 전 등록)

- 명령 0.5 m/s (학습 범위 안, 18a 3 절). 1.0 m/s 는 따로.
- 사례: 기존 등록 gap 20 · 평지 10 사례를 새 명령으로 E1 · M1 · M2 모두 다시 잰다. P2 부터 징검다리 20 사례.
- 폭별 gap: 0.10 · 0.20 · 0.30 · 0.40 · 0.50 · 0.60 m 각 N 판 (새 평가 장면, 시드 고정).
- 성분: 기준선 도달 · 끝까지 생존 · 둘 다, 넘어짐 이유, gap 조우 대비 통과 · 추락 · 회피 · 정체.
- 걸음 모양(18a 6 절): 정체 비율, 명령 대비 속도, 네 발 비접촉 비율, 두 발 지지 중 대각 비율(분모 같이). 구간별(평지 · 접근 · 통과 · 착지).
- 지형 갈래 기여 0 (지도 latent 를 직접 0) 평가: 학습된 판의 지도 의존도. 입력 지도 0 은 별도 입력 고장 시험.
- 영상: 같은 gap 의 접근부터 첫 착지까지 E1 · M1 · M2 를 나란히.

## 6. 판정 · 선택 규칙 (결과 전 등록, 화요일 판단에 씀)

1. **유의미 (gap)**: M − E1 gap 성공의 Tango 95 % 짝 구간 하한 > 0, 평균 차 ≥ 20 %p. 폭별 표에서 0.30 m 이상 칸이 E1 보다 높음.
2. **바탕 보행 유지**: 평지 성공이 E1 대비 구간 전체로 나쁘지 않음, 두 발 지지 중 대각 비율 ≥ E1 - 15 %p, 네 발 비행 ≤ E1 + 10 %p. 못 지키면 「보행 실패」 로 따로 보고 (학습을 막는 관문은 아님).
3. **M1 대 M2**: 공통 iteration 체크포인트에서 gap 성공 짝 비교. 구간이 0 을 걸치면 「차이 입증 못 함」 이고, 그때는 0.40 m 이상 칸과 P2 징검다리 결과로 고른다. 그래도 같으면 단순한 M1.
4. **고정**: 1 · 2 를 만족한 판이 화요일 판단 시점에 있으면 그 판을 「우리 실험」 으로 고정하고 Linux 에서 학습량을 늘린다. 수요일까지 없으면 원인 보고와 다음 판 설계.
5. 낮은 결과를 다시 돌려 고르지 않는다. 판정 뒤 기준을 넓히지 않는다. 한 시드라 「경향」 으로 쓴다.

## 7. 실행 방식 (세션 토큰 절약 · 멈추지 않기)

- 학습 · 평가는 **대기열 실행기**가 돌린다: GPU 0 M1, GPU 1 M2 → 각 학습 끝나면 같은 GPU 에서 자동 평가 → 결과 JSON · 영상 · 걸음 표 생성. 세션은 띄움 · 첫 증거 확인 · 중간 확인(2 ~ 3 시간마다) · 끝난 뒤 판정 · 아티팩트만.
- 창을 띄우지 않는다 (`CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP`, 실행기는 숨김).
- 중간 체크포인트 500 iteration 마다. 긴 학습 붕괴(석헌 nogap2 20k 사례) 대비로 1,000 iteration 마다 짧은 자동 평가(평지 · gap 소수 사례)를 기록만 한다.
- GPU 1 은 화면용. 두 판 env 수를 같게, 메모리가 안 되면 함께 줄인다(18a 4 절). 비교는 둘 다 있는 같은 iteration.

## 8. 예산 (추정)

- M1: E1 처리량(8,192 env 초당 약 47,000 transition) 이면 13 시간 약 10,000 iteration. M2 는 attention 만큼 느리다(석헌 AME-2 는 4,096 env 업데이트당 약 8 s, 4090, 신경망이 더 큼). 짧은 확인에서 실측.
- 평가: 지금 도구는 사례마다 Kit 을 띄워 120 건 약 2 시간. 폭별 gap · 영상까지 넣으면 판당 1 ~ 2 시간 (미측정).

## 9. ASTRA 18b 에게 묻는 것 (냉정한 시니어 시뮬레이션 담당자로서)

1. 이 다일 계획이 「화요일 · 수요일에 우리 실험을 고른다」 는 목적에 맞나. 빠진 판 · 쓸데없는 판.
2. M2 세부(3 절 표)가 AME-2 의 핵심을 살리나. 17 × 11 · 0.1 m 격자에서 attention 이 의미가 있나, 격자를 바꿔야 하나(DELTA 의 해상도 결과).
3. M1 · M2 를 GPU 0 · 1 에 동시에: 처리량 차이를 공통 iteration 으로만 맞추면 되나, 같은 wall-clock 비교도 둬야 하나.
4. 6 절 판정 · 선택 규칙의 숫자(20 %p · 0.30 m 칸 · 대각 -15 %p · 비행 +10 %p)가 합리적인가.
5. P2 징검다리 · 평균대를 Isaac Lab 생성기로 근사하는 것이 MARG 비교에 쓸 만한가.
6. 평가 도구: 사례마다 Kit 을 띄우는 지금 방식을 유지할지, 한 Kit 에 여러 env 를 함께 돌리는 빠른 평가를 만들지.
7. 이 실험이 실패하는 가장 그럴듯한 경로 셋과 미리 막을 방법.
