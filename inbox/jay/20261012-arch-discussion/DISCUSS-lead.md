# 어떤 구조로 갈까: lead 의 생각과 물음

## 1. 우리 실측이 이미 말하는 것

| 우리 실측 | 논문 쪽 같은 방향의 사실 |
|---|---|
| E1 (MoE-CTS 재현) 의 배포 정책은 student 만 쓰고 지형을 보지 않는다 (체크포인트 가중치 모양으로 확인). 미경험 gap 고리에서 0.5 m/s 전진 명령: 생존 46/100 · 추종 통과 0/100 (E1 20499, 10/12 밤 평가 중간값) | MARG 관측 ablation: 지형 입력을 뺀 판 (⑥) 은 gap · 돌 · 평균대 혼합 코스 성공률 0.0 (Fig. 7). MoE-CTS 저자도 「exteroceptive 지각 결합」 을 향후 과제로 적었다 (VII) |
| v2 (우리 MVP) 는 지도 187 칸을 actor 가 직접 보는 MLP 였고, gap 을 10 % 섞어 배워 gap 은 99~100 % (판 2 잣대) 였다. 같은 v2 의 징검다리는 0~24 % | 지형을 보는 넷 (AME-2 · MARG · START · JEPLO) 중 gap · 디딤돌 숫자를 낸 셋은 모두 **학습 지형에 gap · 디딤돌을 넣었고** (MARG 60 cm · START 0.7 m · AME-2 1.1 m), MARG · START 는 **발 디딤 자리 보상** 을 썼다. 빼면 무너졌다 (MARG 발 보상 전부 뺀 판 돌 지형 0/20 · START w/o FtEdge gap 0.0) |
| E1 · E2 는 정지 · 저속 명령에 약하다 (20,499 에서 더 나빠짐 · 오늘 밤 CMD-R 로 원인 하나를 가리는 중) | 정지 명령을 학습 분포에 명시: START · JEPLO · MoE-CTS. 지형 횡단 논문 중 저속 · 정지 추종을 따로 잰 것은 없다 (지형 숫자와 명령 능력은 다른 물음) |

그래서 lead 의 읽기: **「gap · 징검다리를 건넌다」 는 목표에는 배포 정책이 지형을 보는 구조가 필요하다.** 우리 v2 와 MARG ⑥ 이 같은 말을 한다. MoE-CTS 처럼 지형을 안 보는 구조에 gap 만 섞는 실험 (G1) 은 「안 보고도 어디까지 버티나」 를 재는 진단으로는 뜻이 있지만, 그것으로 gap 을 해결하리라고 기대하기는 어렵다 (추정).

## 2. 선택지 (논문에서 가져올 수 있는 것)

| 선택지 | 무엇을 가져오나 | 우리 쪽 비용 · 위험 (추정) |
|---|---|---|
| **가. MARG 식** | 시뮬 높이 표본 187 칸 → 작은 MLP (16 차원) 를 정책에 넣고, 속도 · 발 접촉 추정기를 PPO 와 함께 학습. **학습 중 센서 렌더가 없다** (Table III). feet center 보상 · 가장자리 기준 | 가장 싸다. 지금 MoE-CTS teacher 가 이미 같은 187 칸을 본다. 층 크기가 논문에 있다 (입력 258 모순 하나). 실기에서는 LiDAR 지도가 필요하다는 점이 남지만, 8/19 결정대로 RL 정책은 시뮬에서 완결한다 |
| **나. START 식** | D435i 같은 depth 60 × 60 을 시뮬에서 렌더 → 지도 재구성 (CNN + GRU + U-Net) → 정책. feet edge 보상 · 지형 진행 curriculum · GT 지도를 섞어 주는 AdaSmpl | 우리 실기 카메라 (D435i) 와 같은 센서라 「다리」 이야기가 서기 좋다. 대신 env 마다 depth 렌더 (논문은 Warp) 비용이 우리 RTX 5080 에서 미확인이고, 층 크기 · 이력 길이 · DR 이 논문에 없다 (빠진 숫자 6 개로 여섯 편 중 최다). 명령이 전진 + 제자리 회전뿐이다 |
| **다. AME-2 식** | attention 지도 encoder (점별 국소 특징 + global + MHA) · 학습형 고도 지도 + 불확실도 · teacher → student 3 단계 | 일반화 근거가 가장 강하다 (student 희소 지형 묶음 91.8 % · 처음 보는 디딤돌 90.0 %). 비용이 가장 크다 (ANYmal-D 약 60 RTX-4090-day). 명령이 목표형이다. 팀장 10/8 「AME-2 는 마지막에」 |
| **라. JEPLO 식** | LiDAR 구면 depth → JEPA latent → CTS (우리 구조와 같은 꼴) | Go2 + Isaac Lab + 우리와 같은 판이라 **바로 돌려 볼 수 있는 유일한 공개 코드**. 논문 학습 지형에 gap 이 없고 (코드는 켬), 센서가 Mid-360 이라 우리 D435i 와 다르다 |
| **마. 지금 MoE-CTS 유지 + gap 노출 (G1)** | 구조는 그대로, 학습 지형에만 gap 추가 | 진단으로는 싸고 바로 된다 (실행기 준비됨). 해결책으로는 위 1 절 근거상 기대가 낮다 (추정) |

여러 편이 같이 쓰는 생각 (논문 사실, `PAPERS-architecture.md` 8 절): 학습 중 privileged 정보 6/6 · 단일 단계 4/6 · 속도 · 접촉 추정 감독 3/6 · stumble 벌점 3/6 · gap 과 디딤돌 학습 지형 3/6 · 발 디딤 자리 보상 2/6 (AME-2 는 일부러 안 씀).

## 3. lead 가 지금 생각하는 순서 (의견 · 확정 아님)

1. **먼저 「보게 하면 얼마나 좋아지나」 를 싸게 잰다.** 지금 E1 부모에 student 쪽 입력으로 시뮬 높이 187 칸 (작은 encoder) 을 더한 판 (설계 문서의 P1, MARG 식과 같은 계열) 을 짧게 이어 학습해, 같은 미경험 gap · 징검다리 평가에서 blind 와 견준다. 이것이 크게 안 좋아지면 구조보다 지형 · 보상 쪽이 먼저다.
2. 좋아지면 **지형 · 보상** 을 붙인다: gap · 디딤돌 학습 지형 + 발 디딤 자리 보상 (MARG feet center 또는 START feet edge) + stumble 벌점. 이 셋은 세 논문이 공통으로 쓴 것이고, 우리 v2 의 징검다리 0~24 % 를 설명할 후보다.
3. 그다음에야 **센서를 현실적으로** 만들지 (START 식 depth · 지도 잡음 DR) 를 정한다. 이 단계는 「시뮬 완결」 이라는 8/19 결정과 실기 Go2 + D435i 이야기 (트랙 B · foothold-app) 를 어떻게 잇느냐에 달려 있다.
4. AME-2 식은 마지막 (팀장 10/8).

## 4. 같이 정해야 할 물음

1. **시뮬 높이 표본을 「완벽한 센서」 로 써도 되나.** RL 정책은 시뮬에서 완결하므로 v2 처럼 써도 되는지, 아니면 「미경험 험지 일반화」 를 말하려면 D435i 같은 현실적 센서 모형 (잡음 · 가림 · 지연) 까지 가야 하는지.
2. **목표의 무게.** gap · 징검다리 횡단 (희소 발판) 과 명령 능력 (정지 · 저속 · 전방위) 중 최종 발표에서 무엇을 앞에 두나. START 는 전진 + 회전만 배웠고, MoE-CTS 는 전방위지만 gap 이 없다. 둘 다 잡는 판은 여섯 편 중 없다 (AME-2 는 목표형).
3. **발 디딤 자리 보상을 쓸까.** MARG · START 는 썼고 뺐을 때 무너졌다. AME-2 는 지형마다 정의가 어려워 일반화를 해친다며 안 썼다. 「미경험 지형」 이 주제인 우리에게 어느 쪽이 맞나.
4. **예산.** MARG 규모 (A100 한 장 약 12 시간) 와 AME-2 규모 (GPU 수십 일) 사이에서 이번 학기 (11/7 RL 잠정 마감) 안에 쓸 수 있는 GPU 시간.

## 5. 이 글이 기대는 것과 모르는 것

- 미경험 지형 숫자 (gap 46/100 등) 는 10/12 밤 진행 중인 평가의 중간값이다. 전부 끝나면 바뀔 수 있다.
- 논문 숫자는 `PAPERS-architecture.md` 를 옮겼고 lead 가 원문에서 다시 재지 않았다. 그 문서의 「못 본 것」 (9 절) 도 그대로 남는다.
- 우리 기계에서 depth · LiDAR 렌더 비용은 아무도 재지 않았다.
