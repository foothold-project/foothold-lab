## 2. 물음

1. **팀장 절차 제거안.** 기술 안전(프로세스 소유 감독기 · Job Object · VRAM 하한 · GPU lease · USD lock · 독립 관찰자 기록 · watchdog)은 그대로 두고, 팀장에게 올라오는 절차(매 실행 동의 · 참석 · 단회)를 **상시 위임 기록 한 건**(팀장 원문 보존, 범위 · 유효기간 · 철회 방법)으로 대체하는 설계. 필요한 코드 변경 파일과 줄, 새로 생기는 위험, 그리고 이 변경이 어떤 기존 판정(17y · 17aa · 17ab · 17af · 17ah · 17ai · 17aj)을 어떻게 바꾸는지.
2. **무인 실행 · 학습 허용 조건.** 지금까지 실제 정상 정리가 확인된 실행은 몇 번이고 어떤 사고가 남아 있는지. 팀장이 요구하므로 「허용하지 않는다」보다 「이 조건이 갖춰지면 허용」으로 쓴다. 조건은 CPU 로 닫을 수 있는 것과 실제 Kit 로만 닫히는 것으로 나눈다.
3. **정오 하드코딩 상한.** 종료 시각을 팀장이 정하는 매개변수로 바꿔도 안전한지(현재 \`deadline=now+1500\`, 검증기 상한 1792206000). 팀장이 지정하는 값이 계약에 어떻게 결박돼야 하는지.
4. **정리 관찰자 오검출.** lead 의 도구 셸이 잔존으로 읽히는 문제를 HOLD 를 PASS 로 고치지 않고 푸는 방법(예: 기준선에 lead 셸 소유 근거를 기록, 별도 소유 표지).
5. **자동 모드 분류기.** 이것은 ASTRA 설정이 아니라 Claude Code 권한 설정이다. 팀장이 직접 바꿔야 하는 항목이 무엇인지 ASTRA 가 알면 적는다(모르면 미확인).
6. **노드 사이 lead 확인.** 노드마다 lead 가 원자료를 읽고 NIGHT-PLAN 에 적는 규칙(17ai)이 필요한 이유와, 자동 합격 판정 스크립트로 대신해도 되는 부분.
