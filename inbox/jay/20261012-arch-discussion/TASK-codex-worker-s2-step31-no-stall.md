# sol 작업서: 실험이 멈추지 않는 실행 장치 (step31)

## 0. 지킬 것

새 사본 `codexE/s2_step31/`. 학습 · 평가 · 지도 · 센서 · 판정 코드는 바꾸지 않는다(기동기 · 감독 · 대기열 층만). 보호를 없애지 말 것: GPU 임대, USD 잠금, 워치독의 실제 사망 판정(연속 부재 · stale heartbeat · hard deadline), 가족 정리, 해시 봉인은 그대로. 바꾸는 것은 **사람이 매번 개입해야 하는 지점**뿐이다.

## 1. 오늘 실험을 멈춘 지점 (근거)

1. 기동기마다 동의 파일의 `scope` 가 달라서 실행마다 새 동의 파일이 필요했다(학습 A/B, 예행 평가, 최종 평가). lead 는 팀장이 쓴 말만 파일에 적을 수 있어서, 팀장 한 줄을 기다리는 동안 멈췄다.
2. `observer_mode` 가 `attended` 만 허용. 팀장이 자는 밤에는 정직하게 쓸 수 없다.
3. 다음 실험을 띄우는 것이 lead 세션의 예약에 달려 있다. 세션이 바쁘거나 꺼지면 GPU 가 논다.
4. 띄운 뒤 실제로 돌았는지를 사람이 확인해야 했다(첫 시도는 창이 바로 닫혀 출력 없이 끝났다).

## 2. 필요한 것

1. **상시 동의 파일 하나.** `consent_standing_s2.json` 스키마: 팀장 인용(원문 그대로), 허용 범위 목록(scope 문자열 목록: `s2_short_attended_one_shot_arm_A/B` 계열, `s2_eval_kit_smoke_once`, `s2_eval_kit_full_once`, 영상, 지도 지우기 탐침, S2-2 · S2-3 · S2-4 학습), 유효 기간, 무인 허용 여부. 각 기동기는 기존 단회 파일 **또는** 이 상시 파일을 받는다. 상시 파일이면 자기 scope 가 목록에 있고 기간 안일 때만 통과. 단회 파일 경로는 그대로 동작(회귀).
2. **무인 모드.** `--unattended` 일 때 `observer_mode=unattended`, 상시 파일의 무인 허용이 참이어야 함. 무인일 때 추가 조건은 ASTRA 17ak 대로: (a) step27 워치독(이미 보강) 사용, (b) Kit canary: 띄운 뒤 정해진 시간 안에 첫 증거(학습은 첫 update 줄 1 개, 평가는 첫 case 의 `start` 와 `end`)가 없으면 감독기가 정상 정리 후 **한 번 재시도**하고, 그래도 안 되면 대기열에 실패 영수증을 남기고 다음 항목으로 넘어간다(멈춰서 사람을 기다리지 않는다).
3. **실험 대기열** `s2_queue.py`: json 대기열(항목마다 기동기 경로 · 인자 · 선행 조건 · 상시 동의 경로). 한 번에 하나만 GPU 0 에서 실행하고, 앞 항목이 끝나면(영수증 확인) 다음 항목을 띄운다. 선행 조건 예: 「B 영수증 verdict 가 RUN_COMPLETE_UNVERIFIED 일 때만 최종 평가」. 대기열 자체는 Windows 작업 스케줄러나 독립 PowerShell 로 떠서 **lead 세션이 꺼져도 돈다**. 상태 파일(`queue_status.json`: 현재 항목 · 시작 시각 · 마지막 증거 시각 · 끝난 항목 영수증 SHA)을 남겨 lead 가 언제든 읽을 수 있게.
4. **돌았는지 확인 보고.** 항목마다 `launched` (프로세스 PID · 생성 시각) → `first_evidence` (첫 update 또는 첫 case) → `finished` (영수증 verdict) 세 줄을 대기열 로그에 남긴다. 이 셋 중 하나라도 없으면 그 항목은 「돌았다」가 아니다.
5. **시험(CPU):** 상시 파일 통과 · 범위 밖 scope 거절 · 기간 만료 거절, 무인 + canary 시간 초과 → 재시도 1 회 → 실패 영수증 → 다음 항목 진행(가짜 자식으로), 대기열 순서와 선행 조건, lead 세션이 없는 상태에서 대기열이 끝까지 가는 것(가짜 자식). 기존 B 전체 회귀.
