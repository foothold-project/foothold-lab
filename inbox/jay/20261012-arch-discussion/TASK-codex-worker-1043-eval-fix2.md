# Codex Worker 작업서 · 1043 평가 후보 17s 결함 고침

## 0. 규칙

- 앞 작업서 (`TASK-codex-worker-1043-eval-fix.md`) 0 절의 규칙을 그대로 따른다: 커밋 금지 · 삭제 금지 · GPU · Isaac 실행 금지 · `CUDA_VISIBLE_DEVICES=-1` · `_eval` 쓰기 금지 (읽기만) · 격리 단언 · 정직한 보고 · em dash 금지 · 관문을 시간 때문에 완화하지 않기.
- **`VERIFY-astra-17s.md` 를 먼저 끝까지 읽고 그 줄 번호 · 반례 · 문구를 그대로 따른다.** 아래는 요약이다. 모르는 것은 추측하지 말고 보고서의 「미확인」 으로.
- UNDECIDED 값 (GPU 배정 · 독점 시간창 · 마감의 의미 · launch / retry / 벽시계 상한 값 · 원본 반복 예산 · 재기동 범위) 은 **팀장 결정**이다. 임의로 채우지 않는다. 메커니즘만 만들고 값은 UNDECIDED 로 둔다.
- **변이는 정상 소스에서 같은 시험이 먼저 통과하고, 지정한 시험이 의도한 위치에서 `failed [..] want [..]` 로 실패할 때만 CAUGHT.** 17s 의 지적대로 「이름이 다른 입력 변조」 와 「코드 검사를 하나씩 끈 변이」 는 다르다. 이번 새 검사는 **코드 검사를 끈 변이**로 만들고, 둘의 개수를 따로 센다.
- 프로세스: 옛 CPU 시험 프로세스 PID 175820 은 팀장 확인 전에는 종료하지 않는다. 새로 띄운 시험 자식은 자연 종료까지 기다리고, 시험 중 종료는 **그 시험이 직접 띄운 자식 트리에만** 한다.
- 먼저 `codexE/cand/` 를 `codexE/cand_17s_base/` 로 보존하고 해시를 대조한다 (17r 때와 같이). 보존 전에는 고치지 않는다.

## 1. 고칠 것 (17s 1 절 · 3 절 · 5 절)

**P1 (먼저)**

1. **D:995, 1478 부근 · 원본 q 의 정상 결과를 거절함.** `main_diagnostic()` 이 원본 q (`ka_orig`) 와 반복 원본 (`ka_orig2`) 에도 `validate(..., need_iter=True)` 를 적용한다. 고정된 `q_eval.py` 는 `loaded_iter` 를 기록하지 않는다 (실제 `_eval/out/cq_test_8d384fcb_g0t141025p134176_ka_orig/meta.json` 에 필드 없음, 읽기만). **원본 q 에 한정해 필드 유무를 처리하고, checkpoint 해시 · 원본 소스 · 나머지 검사는 유지한다.** q_cmdr 실행은 계속 iteration 을 요구한다. 모든 평가기의 iteration 검사를 끄면 안 된다. 원본 반복에도 같은 수정. 시험: (가) 실제 원본 meta (읽기 전용 사본, SHA256 `4c4bed8364cf6cc1c873585dc895ec1fee99ab1bc699cf71bed9c19a834bb093`) 를 정상 입력으로 넣으면 오류 0 (나) 같은 meta 에 20000 을 추가한 양성 대조도 통과 (다) checkpoint 해시 변조는 계속 거절 (라) q_cmdr 입력에서 iteration 이 없으면 거절.
2. **D:620, 664, 845 · `max_wall_s` 가 실행 중 상한이 아님.** 한도 2 초에 4 초 수면하는 실제 CPU 자식을 연결한 시험에서 5.8 초 뒤 `guarded rc=0` 으로 반환됐다 (`wait_child_tree()` 에 마감 · STOP · 벽시계 검사 · 중단 집행 없음). **시작 금지 시각 (`deadline_epoch`) 과 강제 종료 상한 (`max_wall_s`) 을 구분**하고, 강제 상한은 **이 후보가 소유한 자식 트리**에만 실제 적용하며 (STOP 파일도 같은 경로) **종료를 확인하기 전에는 lease 를 풀지 않는다.** 강제 종료 방식 (종료 시점 · 유예 · 부분 결과 처리) 의 정책은 팀장 결정 사항이므로 manifest 에 UNDECIDED 로 두고, 메커니즘과 시험만 만든다. 시험: 한도 2 초 · 4 초 자식 → 한도 근처에서 트리 종료 + 비정상 종료 코드 + lease 보유 유지 후 해제, 정상 종료 자식은 영향 없음, 손자 포함, STOP 파일 반응.
3. **M:72, D:190, 225 · 승인 한 묶음의 예산 결박 미완성.** 같은 승인 파일 · 외부 digest 에서 `execution.attempt` 만 바꿔도 오류 0 이고, D 는 새 ATTEMPT 를 만들며 launch 수를 프로세스마다 0 으로 시작한다. 현재 `max_child_launches` 는 한 프로세스의 상한이지 같은 승인의 누적 상한이 아니다. **승인 ID (또는 승인 파일 digest) · 실제 attempt · 로그를 묶고, 재시작 시 소비된 launch / retry 횟수를 이어받거나 재사용을 거절**한다. 이 장부는 `write_root` 안에 두고 **원자적으로** 쓴다 (동시에 두 번 시작해도 하나만 통과). 승인 B 스키마가 바뀌면 (승인 ID · 누적 예산 범위 추가) **스키마 변경 사실과 정확한 필드 목록을 보고서에 적는다** (ASTRA 가 새 스키마 그대로 재검한다). 시험: 같은 승인으로 두 번째 시작 → 소비분 이어받음 또는 거절 / attempt 만 바꾼 재사용 거절 / 동시 시작 경쟁.

**P2**

4. **M:239 · 재시도 0 회를 표현할 수 없음.** 모든 risk 값에 `> 0` 을 요구한다. `max_child_launches` 와 `max_wall_s` 는 양수, `max_retries_per_run` 은 0 이상으로 구분. 시험: `max_retries_per_run=0` 정상 승인이 통과하고 음수 · 문자열 · bool 은 거절, 0 일 때 실제 코드가 재시도를 하지 않음 (현재 정상 진단 기본 tries=4 와의 관계를 정리: 승인 값이 실제 tries 를 제한하는지).

**3 절 · 진단 계약 보완**

5. **D:1512 · JSON 의미 · JSON 파일 SHA · traj 파일 SHA 를 모두 요구.** 의미와 trajectory 바이트가 같고 JSON 공백 · 키 순서만 다른 경우도 `held_mismatch/3`. 보수적 보류 자체는 유지할 수 있으나 **물리 비결정성으로 쓰지 말고 byte-only 차이를 별도 원인 코드로 표시**한다. 보고서 필드: `semantic_equal` · `json_sha_equal` · `traj_sha_equal` 을 각각 기록. 어느 것을 통과선으로 삼을지는 ASTRA / 팀장 결정이므로 현재 판정 규칙은 그대로 두고 UNDECIDED 표시를 manifest 에 둔다.
6. **보고 항목 동등성:** 기본 세 run 보고에 있는 항목 (시간 · guard peak / 여유 · 지문 · 버퍼 · 입력) 이 `orig_repeat` 와 실패 run 에도 같은 수준으로 남게 한다 (peak · preflight · reset · 지문 · tries). 보고의 peak 는 장치 전체 값이며 이 작업의 전용 사용량이 아니라는 문구를 유지. 미실행 · 보류 · 실패를 분리 표시.

**5 절 · 배치 (17s)**

7. **`write_root` 격리 검사와 공통 경로:** M 은 모든 `WRITE_KEYS` 가 `source_eval` 밖이어야 하므로 `_eval/slot` 같은 기존 공통 lock / lease / registry 경로를 그대로 넣으면 거절된다. **격리 검사 전체를 제거하지 말고**, 공통 경로를 `write_root` 안에 두는 안과 기존 경로를 **명시적 allowlist (정확한 경로 일치)** 로 허용하는 안 둘 다 manifest 에서 선택 가능하게 하거나 둘 중 하나를 구현하고, 어느 쪽인지 보고서에 적는다. 어떤 안을 쓸지는 팀장 / ASTRA 결정이므로 값은 UNDECIDED. 시험: allowlist 없이 `_eval/slot` 경로 → 거절 / 정확히 일치하는 allowlist → 통과 / allowlist 에 없는 다른 경로 → 거절 / 부분 문자열 · 대소문자 별칭 우회 거절.

## 2. 시험 보강 (17s 2 절)

8. **새 검사마다 코드 검사를 끈 변이**: 1 (원본 필드 처리) · 2 (벽시계 집행) · 3 (예산 장부) · 4 (retry 0) · 5 (byte-only 표시) · 7 (allowlist) 각각. 변이 파일은 정상 소스에서 같은 시험을 통과시킨 로그가 먼저 있어야 한다. 17r 의 입력 변조 12 종과 **섞어 세지 말고** 「입력 변조 N 종」 「코드 검사 끈 변이 M 종」 으로 따로 적는다.
9. **실제 결과 사본 양성 시험:** 1 번의 실제 원본 meta 사본을 `validate` 에 넣는 시험을 `test_17r_*` 와 별도 파일 (예: `test_17s_*.py`) 로 만든다. 가짜 validate 로 교체한 연결 시험 (`test_17r_e.py`) 의 한계를 보고서에 다시 적는다 (ready · validate · fingerprint 를 성공 함수로 교체).
10. 묶음 실행기 (`run_all_17r.py` 또는 새 `run_all_17s.py`) 에 새 시험을 넣고, 새 run-id 로 전체를 한 번 돌려 종료 코드 · 시간 · 로그 경로를 `evidence_17s/` 에 남긴다.
