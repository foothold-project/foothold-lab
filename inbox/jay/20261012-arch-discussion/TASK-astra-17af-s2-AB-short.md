비판적이면서도 냉정하고 현실적인 전문가로서 답해 주십시오. 분량 `VERIFY-astra-17af.md` 한 파일, 첫 줄 한 문장 판정. 코드 수정 · GPU · Isaac · 커밋 금지, em dash 금지. 17ae 까지 닫힌 것은 다시 보지 말고 아래만 봐 주세요. 확인됨 / 추정 / 미확인을 나눠 주세요.

## 사실

- 현재 B 번들(step8)의 `stage=short` 는 코드와 CPU 시험이 있다(계약: `s2_train_contract.py` 의 `short` 분기, `gpu_index==0`, `num_envs==1024`, gap/stones 각 0.15, `updates==2000`, `checkpoint_interval==200`, 증분 `[500]`, `max_total_updates>=2500`, 두 arm 의 barrier/pair commit 은 `s2_increment_barrier.py`). 그러나 **실제 Isaac 에서 한 번도 돈 적이 없고**, 17ad · 17ae 는 plumbing 만 검토했다.
- 실제 학습 속도 참고: E1(N=8192)은 약 860 update/h. N=1,024 의 update 당 시간 · VRAM 은 **미측정**.
- GPU 0 은 10/15 15:07 부터 비어 있다(팀장 동의 대기). GPU 1 은 데스크톱 앱이 13.4 GB 를 쓴다(미정리).
- 0단계 A3.2 4차 수집과 첫 배관(arm A, 합성, N=32, 1 iteration)은 준비가 끝나 팀장 동의만 남았다.

## 질문

1. **short 단계의 첫 실행 전에 ASTRA 판정이 따로 필요한가, 아니면 17ae 7절 식으로 「배관 PASS + lead 검증 기록 + 팀장 단회 동의」 로 충분한 범위가 있는가.** 필요하다면 이 의뢰에서 판단할 수 있도록 **무엇을 더 보면 되는지**(새 파일 · 줄) 구체적으로. 필요한 CPU 증거가 있으면 지정해 달라.
2. **0단계 PASS 전에 short A/B 를 돌려도 되는가.** lead 제안: 결과를 「잠정」 으로 표기하고 0단계가 PASS 해야만 효과 주장으로 승격, 0단계가 HOLD 면 폐기. GPU 가 이틀째 비는 것이 가장 큰 손실이라는 팀장 지시와 17ae 4절(분류된 검증 실패면 별도 진행 가능)을 함께 읽은 제안이다. 거절 가능하며 이유를 달아 달라. 허용한다면 조건(표기 · 결과 사용 금지선 · 폐기 규칙).
3. **두 arm 의 배치:** GPU 0 에서 순차(A 2,000 update 뒤 B)만 허용하는가. 시간이 두 배 걸린다. N=1,024 의 VRAM 이 GPU 0(15.6 GiB 여유)에서 충분한지는 미측정이므로, 먼저 짧은 측정 단회(예: 5~10 update, 시간 · VRAM 최고치만 기록, `plumbing_only` 와 같은 격리)를 두는 것이 맞는가. GPU 1 병렬은 17ad 4절대로 현재 불가라는 입장이 그대로인가(앱 점유도 있음).
4. **판정 기준:** 첫 short 의 합격 표기 문구와 HOLD 목록(17ad 3절 틀 그대로 옮기되 학습 길이에 맞게 추가: 수렴 · 보상 추세 · 비유한 · eval 등)을 제안해 달라. A/B 비교에 필요한 최소 측정(같은 seed · 같은 parent · 같은 평가 장면)은.
5. **연속 동의 해석:** 17ae 는 「팀장의 해당 단회 직접 동의」 를 요구한다. 팀장이 한 메시지에서 두 단회를 이름으로 모두 적고(예: 「4차 수집을 하고, 관찰자 PASS 면 이어서 배관 arm A 를 한 번 실행해라」) EULA · 참석 · 실행을 동의하면 **각 단회의 직접 동의로 읽어도 되는가.** 단회마다 새 chain · manifest · approval · claim · 출력을 만드는 것은 그대로 둔다.
