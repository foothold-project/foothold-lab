# ASTRA 17v · S2 학습 연결과 무인 사슬

**확인됨**은 이번에 직접 읽거나 재현한 사항, **권고**는 사전 등록할 설계안, **미확인**은 실제로 재지 않은 사항이다. 아래 숫자 권고는 최적값이나 기동 승인값이 아니다. 추가 전달의 Windows 종료 상한은 **2026-10-17 12:00 KST**, UTC 03:00, epoch **1792206000**으로 계산했다. 이전 GPU 작업의 허용을 이번 코드의 허용으로 옮기지 않는다.

## 1. CPU 후보의 정상성

**판정: 일부 연결은 확인됐지만, ‘teacher/student 분리만 제거한 부모와 같은 PPO’와 ‘reset 뒤 오래된 지도 거절’이라는 주장은 현재 그대로 성립하지 않는다.**

### 독립 시험과 그 범위

고정 목록 10개와 step1 6개, 총 16개를 임시 폴더에 복사했다. 전체 목록 SHA256은 의뢰의 `91737d563dab78778a51b72dcca42a20f6b7358fecf12b97cf20ee21aef8c5e9`와 일치한다. `isaac311-moects/python.exe -B -u`, `CUDA_VISIBLE_DEVICES=-1`에서 변경하지 않은 `run_all_s2_step2.py`를 재실행했다.

| 이름 | 실제 변경과 검출 범위 |
|---|---|

step1은 실제 E1 정책과 CPU 자료를 사용하지만, step2 runner 시험의 환경·센서·정책은 `FakeEnv/FakePolicy`다. 추가로 **실제 E1 checkpoint에서 만든 S2 정책**을 같은 가짜 환경의 실제 입력 차원으로 연결해 A/B 각 1 update를 돌렸다. 두 군 모두 4 optimizer step, encoder 가중치 동일·grad 없음이 확인됐다. 이는 연결 시험이며 로봇 학습 결과가 아니다.

### 고쳐야 할 항목

**P1 · 시간제한 종료를 진짜 terminal과 섞는다.** 부모 `moe_cts.py:187~193`은 `extras["time_outs"]`에 대해 reward에 gamma × 저장 value를 더한다. 후보 `s2_runner.py:128~158`은 이를 읽지 않고 모든 done에서 bootstrap을 끊는다. 실제 부모 메서드를 AST로 추출하고 주변 저장소만 가짜로 둔 알려진 답에서 reward=1, value=2, gamma=.99, timeout=True이면 부모 보정 reward는 **2.98**, 후보의 1-step return은 **1.00**이었다. 진짜 terminal 대조군은 둘 다 1.00, 비종료 후보의 return은 2.98로 맞았다. 후보가 timeout의 의미를 바꾼 것은 확인됐다.

부모 동치를 목표로 하면 이 보정을 복원해야 한다. 더 엄밀하게 terminal observation의 value를 쓸 것이라면 auto-reset 전 terminal observation과 종료 종류를 별도로 보존하는 **명시적 알고리즘 변경**으로 등록한다. reset 뒤 새 episode value를 timeout 보정에 쓰면 안 된다.

**P1 · 새 번호가 오래된 sensor packet을 새 자료로 만들 수 있다.** `_frame:72~90`은 obs·sensor·episode ID·frame token을 따로 받는다. reset 검사는 외부 번호의 증가/변화만 본다. 첫 sensor packet을 계속 반환하고 환경의 episode/token만 정상 증가시킨 반례에서, 정상 지도의 env0 값은 `[0, .01, .32]`, 오래된 지도는 `[0, 0, 0]`였는데 **둘 다 status=valid**였다. 저장 후 clone이 있는 것은 맞지만, 잘못된 시점의 자료를 clone해도 잘못은 남는다.

실제 어댑터가 센서 갱신 뒤 만든 obs·map·pose·episode ID·simulation step을 하나의 packet으로 넘기고, 센서 자료를 갱신한 근거와 함께 대조해야 한다. 번호만 별도로 증가시키는 구현은 금지한다. 같은 XY에서 높이만 바뀌는 reset, yaw가 같은 이동, reset된 일부 환경과 나머지 환경을 포함한다. 라이브러리가 모든 센서 지연을 자체 추론할 수는 없으므로 **입력 계약과 실제 어댑터 시험**을 함께 고친다.

**P1 · yaw 비유한값이 기하 검사를 우회한다.** `s2_env_adapter.py:expected_world_xy/verify_hit_geometry`는 yaw의 유한성을 검사하지 않는다. 정상 pos/hit에 yaw=NaN을 넣으면 NaN과의 크기 비교가 false라서 **유한한 지도를 반환하며 통과**했다. yaw·quaternion·변환 결과의 유한성과 quaternion 정규화 규약을 앞에서 검사한다.

**조우 집계는 아직 성공률 계산에 쓸 완성된 사건 기록기가 아니다.** `EncounterLog`에 같은 env/episode로 assigned, approach, pass, pass, fall을 넣으면 assigned=1, approach=1, pass=2, fall=1을 그대로 받았다. 사건의 장애물 ID·episode·최초 진입·종료 상태를 정하고 중복 및 상충 결과를 막아야 한다. 로깅 카운터만 두었다는 한계를 밝히는 것은 가능하지만, 현재 수를 그대로 비교기에 넣으면 안 된다.

### 부모와 같은 것, 달라진 것

- value clipping, entropy 부호, KL 식과 adaptive LR 문턱·상하한·step 이전 적용은 대응한다. S2 control은 backward/clip 이후 step 전에 group LR·고정을 재확인한다. 두 군은 같은 규칙을 타며 실제 KL과 LR 궤적까지 같아야 하는 것은 아니다.
- 부모는 두 군 surrogate **평균의 합**, 후보는 전체 평균이다. 단순히 두 배 차이라는 설명도 부정확하다. 부모는 군별 가중치가 다르다. 단일 student PPO로 바꾸는 선택은 가능하지만 value·entropy 대비 surrogate의 비중까지 달라졌다고 명시해야 한다.
- 부모의 전체 advantage 정규화는 `std()`, 후보는 `std(unbiased=False)`다. 작은 시험에서는 차이가 크고, 큰 batch에서는 작아져도 동일 연산은 아니다.
- 실제 부모 저장소는 `rollout_storage_cts.py:130~190`다. teacher/student별 순열을 epoch 밖에서 만들고 나눈다. 후보는 epoch마다 새 전체 순열과 `tensor_split`을 쓴다. 군 제거 외에 재추출 규칙도 바뀐다. 첫 비교는 부모의 순열 재사용 규칙·표준편차 정의를 맞추거나 변경을 사전 등록한다. minibatch로 정확히 나누어지는 batch 크기를 강제하면 불균등 batch의 추가 효과를 피할 수 있다.
- E1 설정은 observation normalizer 없음, RND·symmetry 없음이다. 해당 기능을 뺀 것 때문에 이 E1에서 경로가 달라진 것은 아니다.
- A는 지도와 mask가 상수이고, B와 같은 runner·PPO를 쓴다. **A도 privileged critic의 지형 정보를 학습 신호로 받는다.** ‘지형 정보가 전혀 없는 학습’이라고 쓰지 않는다.
- 정상 가짜 환경에서는 rollout 지도 저장·다음 관측 bootstrap·모든 minibatch의 지도 사용·CPU RNG/optimizer/환경 재개 동치가 확인됐다. 실제 Isaac 물리 상태·명령/지형 curriculum·관측 이력·센서 갱신·CUDA RNG까지 복원되는지는 미확인이다.
- 수치 고장은 업데이트 전에 거절하지만 `collect()`의 invalid는 상태 반환이다. 실행기가 이를 무시하고 다음 update를 호출하지 못하도록 사슬에서 **보류를 지속 상태로 고정**해야 한다. 갱신 도중 실패의 held_update 처리와 구분한다.

**남길 미확인:** 실제 timeout 전달 방식, Isaac 센서 시점, 장기 PPO 안정성, 실제 재개 동치. 이 후보에는 실제 학습 진입점이 없고 shell은 exit 99이므로, 실행 승인이 빠진 완성품이 아니라 아직 연결할 부분이 남은 후보다.

## 2. 첫 GPU 일: 학습 없는 Isaac 접속 확인

**판정: 학습과 분리한 작은 알려진 답 시험을 먼저 하되, 이 시험에 전체 장기학습 구현의 완성을 기다릴 필요는 없다. 센서·소유권·실행 종료 관문은 먼저 갖춘다.**

**권고 · 고정 시험안:** 8환경 = 평지·0.20m 단차·틈·비대칭 징검다리 × yaw 0/90도. 환경당 256 제어 step, 초기 안정화 16 step은 별도 기록한다. 64에서 알려진 평행 이동, 128에서 다른 높이/위치로 명시적 reset, 192에서 yaw 변경을 준다. optimizer는 만들지 않는다. 알려진 자세를 고정하는 구간과 실제 Go2 센서 갱신 구간을 구분한다. 모델이 못 걸어서 답이 바뀌는 것을 센서 정답 시험에 섞지 않는다.

단차·돌의 높이와 XY 위치는 해시가 고정된 비대칭 표식으로 둬 x/y 뒤바뀜이 드러나게 한다. 틈에는 **충돌 바닥이 없는 부분**과 **깊은 유한 바닥이 있는 부분**을 따로 둔다. 실제 학습용 gap·stones 생성기의 최종 메시도 같은 실행에서 스캔하여 표식 시험과 연결한다. 눈으로 보이는 구멍 아래에 숨은 plane이 있으면 정상 no-hit 시험이 아니다.

| 확인할 것 | 알려진 답과 거절 기준 |
|---|---|
| 187칸 순서 | x-fast, 17×11. yaw 0에서 index 0=(-.8,-.5), 1=(-.7,-.5), 17=(-.8,-.4), 93=(0,0). yaw 90에서 첫 좌표는 (.5,-.8). 실제 raw hit를 독립 표식 좌표와 대조한다. |
| 높이·offset | body/sensor z=.5, 평지 hit z=0이면 height=0. 단차 hit z=.2이면 -.2. 현재 설치 소스는 cfg.offset 20m를 ray starts에 더한다. data.pos_w에 다시 더하지 않는다. prim과 physics view 사이 변환인 내부 _offset과 cfg.offset을 혼동하지 않는다. |
| miss와 깊은 바닥 | xyz 모두 +inf인 정상 miss는 (height=1, mask=0), 깊은 유한 바닥은 clip 후 height=1이어도 mask=1. NaN·일부 inf·-inf는 고장이다. |
| 메시 | render 모양이 아니라 RayCaster가 읽은 prim·vertices/faces·world transform·캐시와 실제 충돌 메시를 기록한다. 바닥 메시 누락을 ‘구멍 발견’으로 승인하지 않는다. |
| 시점 | 제어 step, physics step, episode ID, raw sensor 갱신 시각/세대, root pose, obs·map packet ID를 함께 기록한다. reset 전후 같은 XY·다른 높이도 즉시 달라져야 한다. |
| 허용 오차 | 해석적으로 정의한 평면/박스의 내부 점은 XY/Z 각 2mm 이내를 출발 후보로 등록. 경계 5mm 안의 애매한 점은 사전 목록으로 분리해 모두 보고한다. 오차가 크다고 시험 뒤 허용 폭을 늘리지 않는다. |

원자료는 raw `pos_w/quat_w/ray_hits_w`, 원점·방향·ray index, clip 전 높이·mask·최종 지도, 관측 이력·명령, reset 이유·timeout, 메시 해시·설정·실제 import 경로, 단계별 step 수·종료 기록이다. 사진/영상은 보조 자료다. 첫·변환 직전·직후 packet과 전체 자동 판정 입력을 보존한다.

실제 어댑터에서 일부러 1-step 오래된 packet, 새 번호만 붙인 오래된 packet, 순서 교환, 20m 재가산, yaw NaN, 바닥 메시 누락을 넣었을 때 각각 거절하는 CPU/기록 재생 시험도 필요하다. 단차를 전부 같은 높이로 만든 가짜 지도와 어댑터 자체 좌표 계산으로 만든 정답만 비교하면 오류를 함께 복제한다.

**남길 미확인:** 8환경이 실제 GPU에서 걸리는 시간과 VRAM, Isaac의 reset/센서 갱신 순서, 실제 메시 해상도에 맞는 오차. 2mm는 검증된 기기 정밀도가 아닌 시험안이다. 실패 원인을 확인한 뒤 **새 시험 계약**으로 바꾸어야 한다.

## 3. 기존 승인 사슬의 재사용

**판정: 구성요소를 재사용할 수는 있지만, 예전에 허용된 실행이라는 이유로 S2 무인 사슬까지 승인할 수 없다. GPU당 Isaac 하나라는 말만으로 상호 배제는 보장되지 않는다.**

17u에서 재현한 두 반례의 직접 대상은 1043의 새 감시기였다. 그것과 S2가 같은 함수를 쓴다고 단정하는 것은 틀리다. 그러나 현재 로컬 공통 도구를 다시 읽으니 다른 형태의 공백도 있다.

- `_eval/isaac_slot_v3.py:145~152`는 저장된 PID로 새 `psutil.Process`를 만들며 원래 생성 시각을 결박하지 않는다. 이 **변경하지 않은 함수**를 가짜 OS에 연결해 root PID 700이 다른 프로세스로 재사용된 상황을 주자 그 프로세스의 kill을 호출했다. 실제 프로세스 종료는 하지 않았다.
- 같은 파일 `:361,500~505`는 직계 wrapper의 종료를 기준으로 감시·wait를 끝낸다. `gpu_guard.py:29~48`도 직계 자식을 기준으로 한다. 고아 후손까지 모두 종료됐다는 증거가 아니다.
- slot의 변환 lock은 scene_built 뒤 풀린다. GPU 전체 실행 lease가 아니다. S2 shell의 출력 폴더별 mkdir lease도 다른 출력 경로·다른 실행기와 배제되지 않는다. shell 종료 trap에서 디렉터리를 지우는 것은 후손 종료 증명이 아니다.
- 현재 S2 shell에는 frozen_exec 결박과 실제 단계 validator 호출이 없다. approval 함수는 전달받은 문자열을 JSON과 비교한다. 실제 source/environment 해시 확인·외부에 고정된 승인 digest·단회 claim까지 대신하지 않는다.

**최소 조건:** 세션과 분리된 감독 프로세스가 자신의 실행 가족을 OS 수준에서 묶고, 생성 시점부터 소유를 확보하며, 그 가족만 중단하고 완전 종료를 확인한 뒤 lease를 반납한다. Windows 작업 객체 등 구현 수단은 정상 생성·부모 조기 종료·PID 재사용·AccessDenied·새 후손·감독 프로세스 장애 시험으로 검증한다. 기존 slot/guard의 내부 종료 경로도 그 소유 경계 안에서 안전하게 동작해야 한다. 외부 감시기만 새로 붙였다고 내부의 잘못된 PID 종료가 저절로 안전해지지 않는다.

자원 잠금은 **GPU UUID별 전체 실행 lease**와 **호스트 공통 USD 변환 lock/registry**를 구분한다. 두 GPU가 각각 하나씩 학습하는 것까지 전역 run lock 하나로 불필요하게 직렬화하지 않는다. 같은 GPU를 쓸 수 있는 모든 실행 경로가 같은 lease를 지키거나, 이번 시간 상자 동안 시작 가능한 경로를 하나의 감독기로 제한해야 한다. 비참여 예약 실행기가 남아 있으면 ‘지금 비어 있음’은 다음 기동의 배제 근거가 아니다. 기존 파일을 이번 검증자가 바꾸라는 뜻은 아니다.

S2별 출력·USD root·attempt·장치 UUID·해석기/의존성·승인 digest를 실제 자식 기록과 연결한다. VRAM은 장치 전체 사용량과 내 PyTorch 할당량을 나눠 적고, guard 표본이 0인 기록을 통과로 쓰지 않는다. 현재 slot 기본 registry는 구판 이름이므로 경로를 명시적으로 고정해야 한다.

**남길 미확인:** 지금 GPU가 둘 다 비어 있는지, 참여 가능한 예약 실행기의 전 목록, 실제 OS 소유 경계, 동시 USD 변환·종료 동작. 이번에는 GPU 조회·Isaac 기동·프로세스 종료를 하지 않았다.

## 4. 단계별 사슬 승인과 토요일 정오까지의 연장

**판정: 방식은 채택할 수 있다. 승인 단위를 ‘프로세스 한 번’에서 ‘한 번 claim하는 유한한 사슬’로 명시적으로 넓히면 된다. 현재 후보/미작성 추가 arm에 대한 실행 승인은 아니다.**

팀장 추가 전달의 취지를 반영하면, LLM 세션이 다음 명령을 보내야 하는 구조를 없애는 것이 우선이다. **실험 무결성 통과와 지도 효과의 방향 판정은 서로 다른 관문**으로 둔다. 지도 효과가 아직 안 보인다는 이유만으로 매 증분마다 GPU를 세워 재승인을 받을 필요는 없다. 반대로 NaN·잘못된 센서·소유권 불명 상태를 GPU 가동률 때문에 계속 돌리면 자원은 쓰지만 유효한 실험은 쌓이지 않는다.

### 한 번 동결할 계약

manifest와 승인 digest에 다음을 결박한다.

- 사슬 ID·단회 claim·단계 그래프·허용 arm/시드/부모 checkpoint·encoder·PPO·환경·평가 및 비교 코드 해시. 해석기와 실제 import된 의존성·USD 자산까지 포함한다.
- 장치 UUID, 공통 lease/registry, 출력·STOP 경로, 단계별 wall-time·update·transition·VRAM·출력 용량 상한, 절대마감 1792206000.
- 정상 진행·보류·중단·완료 상태, 검증할 산출물과 hash/schema, 허용 checkpoint 경계, 마지막 증분 크기 표, 검사 빈도, 자동 재시도 횟수. 기본 재시도는 0.
- 성능 방향 기준 파일과 해시, 분모·비교 창·표본·checkpoint 선택 규칙. 계약에는 미정값·NaN·무한 마감·임의 shell 문자열·미등록 실행 파일이 들어갈 수 없다.

claim은 승인 묶음 전체에 한 번만 원자적으로 소비한다. A와 B 자식의 실행권은 그 claim에서 stage/arm별로 딱 한 번 파생한다. 자식들이 같은 승인을 각각 새로 claim하거나, 출력 폴더를 바꿔 재사용하면 안 된다. 승인 취소·만료·이미 claim됨은 모두 기동 전 거절한다.

### 자동 진행표

| 단계 | 자동으로 다음으로 가는 조건 | 보류 조건 |
|---|---|---|
| 사전 관문 | 승인/manifest/실제 bytes 일치, 소유권·장치·잠금 확보, STOP 없음, 시간·용량 여유 확인 | 불명도 거절. 기존 파일을 지워 새 실행으로 위장하지 않음 |
| 0 · 센서 연결 | §2의 정답·reset·packet·메시 검증, optimizer step=0, 허용 종료와 산출물 완전성 | 잘못된 packet, 누락된 자료, 시험 개수 미달 |
| 1 · A/B smoke | 각 200 update를 같은 계획으로 완료, 매 update 20 optimizer step, 수치/고정/시점 관문 통과, 실제 성능·VRAM 기록 | 한 arm invalid 또는 부분 완료면 같은 비교 묶음 보류 |
| 2 · 짧은 비교 | 각 2,000 update 같은 노출 예산, 사전 지정 checkpoint와 조우 자료 확보, 무결성 통과 | 한쪽의 규칙·부모·노출량 변경, 누락·고장 |
| 3 · 고정 연장 | 같은 살아 있는 학습 프로세스에서 각 +500 update, 증분마다 checkpoint·검증 영수증, 같은 비교 경계 | 한 arm 고장·STOP·예산/시간 부족·불명 산출물 |
| 종료 | 마지막 공통 경계 checkpoint·전체 집계와 각 자식 종료를 확인한 뒤 lease 반납 | 후손 생존 여부 불명은 성공 종료가 아니라 격리/보류 |

200·2,000·500은 §5의 **권고값**이다. 처음 smoke를 검증 자료로 별도 취급하려면 단계2는 두 군 모두 같은 부모에서 새로 시작한다. 단계2 이후 연장은 프로세스와 환경을 유지한 update 경계에서 이어가면 된다. 단계마다 Isaac을 재기동하고 실제 환경 재개 동치를 증명하지 않은 채 ‘동일 연속 학습’이라고 부르는 방식은 피한다. 살아 있는 learner가 checkpoint를 쓰고 다음 증분 허가를 기다리는 짧은 barrier로 구현할 수 있다.

각 영수증에는 chain/claim/stage/arm/attempt, 앞 영수증 hash, 실제 코드·설정·부모·checkpoint hash, 시작/끝/제어·optimizer step, 고장·폐기량, 장치 UUID, 프로세스 가족 종료 또는 다음 증분 대기 상태를 넣는다. JSON의 pass라는 글자나 exit 0만 읽지 않는다. 원자료를 별도 validator가 다시 세고, 임시 파일 쓰기 후 원자적 교체로 영수증을 확정한다. 오래된 로그·중복 receipt·뒤바뀐 arm·중간 단계 건너뛰기·0-byte 산출물·불완전 checkpoint는 거절한다.

**두 GPU:** A/B를 별도 1-GPU 프로세스로 두고, 같은 비교 경계에서만 짝으로 판정한다. DDP가 아니다. 코드가 WORLD_SIZE=1만 허용하는 것과 충돌하지 않는다. 변환 구간은 공통 lock으로 짧게 직렬화한다. 한쪽 고장은 그 비교 묶음의 다른 쪽도 소유권이 확인된 경로로 중단/체크포인트 보류 처리한다. 손상된 쪽만 optimizer를 초기화해 계속 비교하지 않는다. 빠른 arm의 잉여 update는 같은 예산의 비교에 섞지 않는다.

### 세션 독립성과 마감

감독 프로세스와 learner 가족은 Orca/CLI의 종료 범위에서 분리되어야 한다. 작업서의 ‘다른 학습이 부모 없이 돌았다’는 사례만으로 이번 실행기의 분리를 확인할 수 없다. 가짜 작업으로 터미널 부모 종료 후에도 상태 갱신·다음 단계 진행이 되는지, 감독기 장애 때 자기 후손만 정리되는지, 상태 기록이 끊겼을 때 외부 감시가 무엇을 하는지 시험한다. 이 외부 감시 역시 LLM에 의존하지 않는다. 본 검증에서는 그런 프로세스 종료 시험을 실행하지 않았다.

`chain_status.json`은 예를 들어 30초 주기로 현재 단계·update·마지막 유효 packet/산출물 시각·잔여 예산·다음 경계를 기록한다. 읽기 권한 오류·중단된 heartbeat·디스크 부족은 보류 사유다. heartbeat가 살아 있는 것만으로 학습이 진전된다고 보지 않는다. 자동 재시작을 원한다면 ‘감독기 재접속’과 ‘GPU 작업 새 실행’을 구분한 별도 복구 계약과 단회 소비 기록이 먼저 필요하다.

마감은 **새 작업 시작 금지 시각만이 아니라 모든 Windows GPU 작업의 종료 상한**이다. 학습 update 중간을 임의로 잘라 정상 checkpoint로 만들지 않는다. 마지막 증분은 사전 고정한 크기 목록, 예를 들어 500/250/100/50/10/1 중 두 군 모두 끝낼 수 있는 것으로 정한다. 성능이 아니라 시간만으로 선택하고 마지막 공통 경계를 보고한다. 직전 증분 평균만 믿으면 긴 저장·종료 지연에 늦는다. 최근 보수적 처리시간과 checkpoint·종료 reserve를 사용하고, 최소 15분 reserve를 출발 제안으로 둔다. 이 reserve의 충분성은 실측으로 확인해야 한다. 별도 hard deadline 감시가 소유한 실행만 정리할 권한·시간 여유도 계약에 포함한다.

고정 증분 반복에도 최대 update 수·실행 횟수·디스크 용량 상한을 둔다. wall clock 뒤로 이동에 무한 연장되지 않게 시작 시 남은 시간을 monotonic 시간에도 결박한다. 정오에 세션을 기다리지 않고 종료 보고를 남긴다.

### ‘쉬지 않는 GPU’와 보류

승인된 정상 경로는 세션 한도와 무관하게 계속 간다. 준비·체크포인트·무결성 고장까지 포함해 GPU 사용률 100%를 보장할 수는 없다. 자료가 틀렸을 때도 계속 계산시키는 것을 팀장 원칙의 구현으로 읽지 않는다.

고장 때 다른 유효한 일을 채우려면 **코드·값·조건이 이미 승인된 별도 후보/시드의 대기열**을 함께 동결할 수 있다. 실패한 claim을 재사용하지 않고 새 하위 실행권을 한 번 소비하며, 출력과 결론을 분리한다. 그런 대기열이 없으면 HOLD가 맞다. 가동률을 맞추려고 임의 arm·무한 재시도·동일 실패 반복을 만들지 않는다.

### 추가 encoder와 학습 중 방향 판정

작업서의 A/B-MLP/B-attn 세 군은 **탐색 패키지 비교**로는 가능하다. 하지만 ‘모든 arm의 다른 것은 encoder 구조뿐’은 틀리다. A와 B는 지도 정보가 다르고, B-MLP와 B-attn은 구조·매개변수 수·연산량·최적화 특성이 달라진다. 구조별 지도 효과까지 분리하려면 A-MLP/B-MLP와 A-attn/B-attn의 2×2 설계가 필요하다. 세 군만 돌리면 B-attn 대 공통 A의 차이에 구조 차이도 섞인다고 쓴다.

attn의 높이·mask·상대좌표·전역 특징 중 A로 들어갈 값은 상수/고정 위치여야 한다. 지형 유효점 수나 mask로 attention을 차단하는 경로도 A에서는 실제 지형을 읽으면 안 된다. 출력 64차원과 초기 부모 action 동치만 같다고 학습 조건까지 같아지지 않는다. dropout·정규화·연산량·실제 step 수·학습 가능한 parameter·지도 열 초기화·checkpoint 호환성을 동결한다. 이름만 바꾸어 같은 checkpoint를 로드하지 않는다.

현재 attn 코드는 미작성·미검증이므로 이번 기존 묶음의 자동 실행 대상으로 넣을 수 없다. 교체 인터페이스와 CPU 시험은 지금 만들 수 있다. 구현·의존성·관문을 확인한 뒤 **새 manifest/승인 묶음**으로 추가한다. 실행 중 플러그인을 내려받거나 논문 이름만 등록해서 스스로 승인하면 안 된다. MARG/AME-2와 실제 구현이 같은지는 이번 범위에서 미확인이다.

학습 중 조우 비교를 먼저 하는 것은 가능하지만 **독립 평가 이전의 방향 관찰**이다. 아래 §5의 분모·불확실성 문제를 고친다. 방향 기준 미통과만으로 매 증분 ASTRA 대기를 걸지 않고, 미리 정한 예산 동안 계속 관찰할 수 있다. 이 관찰을 이유로 임의 LR·보상·지도 의미를 바꾸는 것은 새 실험이다.

**새 판정이 필요한 변경:** source/의존성/encoder/부모·입력 의미·보상·지형/명령 규칙·PPO·재개 방식·성공 정의·CI·반복점검 규칙·예산 확대·장치/소유권 계약 변경. **새 판정 없이 가능한 진행:** 동결된 다음 단계·+500 증분·동결된 시간 기반 마지막 크기·사전 승인 대기열. 실패 후 재기동은 명시적으로 승인된 유한 복구 분기가 없는 한 새 승인이다.

### 학습 중 조우 비교기의 수정

1. **분모를 둘 다 공개한다.** 배정된 episode/임무 대비 통과율을 주 모니터로, 접근 대비 통과율은 보조로 둔다. 접근을 안 하는 정책은 어려운 틈을 제외하고 쉬운 것만 통과해 후자의 비율을 높일 수 있다. 배정·접근·회피·추락·정체·진행 중·미상·검열 수를 함께 둔다.
2. 사건 단위는 terrain instance/seed·난이도·env·episode·obstacle ID로 고정한다. 접근선 통과는 최초 1회, 장애물 뒤 완료선·몸체/발 접촉·추락·시간 상한 등의 종료 정의를 고정한다. pass 뒤 먼 곳에서 fall한 기록과 장애물 통과 중 fall을 구분한다. 중복 사건을 성공 2회로 세지 않는다.
3. 같은 update 창, 같은 지형/난이도/명령 층별로 A/B의 배정과 조우를 비교한다. 누적값만 쓰면 옛 미숙 정책과 새 정책이 섞인다. 직전500 update 같은 비중첩 창과 누적 곡선을 함께 보고한다. 배정·실제 조우 조건이 달라진 차이는 표시한다.
4. **Wilson은 한 이항 비율의 구간이다.** 두 Wilson 하한을 빼서 B−A의 95% 구간으로 쓰면 틀리다. 현재 자료는 같은 env의 반복 episode·변하는 정책·공유 학습 과정으로 상관되므로 독립 이항 가정도 약하다. 지형 seed/환경·시간 묶음을 보존한 block/cluster 재표집을 탐색용으로 설계하되, 한 학습 seed의 학습 변동성이나 비정상성을 해결했다고 주장하지 않는다. 독립 평가에서는 짝 case를 재표집한다.
5. 기준 파일 hash를 먼저 고정하는 것은 필요하지만, **반복해서 들여다보다 처음 95% 하한이 0을 넘는 순간 성공 선언하는 오류**를 없애지는 않는다. 매 증분 결과는 ‘탐색 방향’으로 표시하고, 정식 판정은 미리 정한 마지막 공통 경계에서 한 번 하거나 사전 고정된 순차검정 절차를 쓴다.
6. 새 attn arm의 제안·선택을 이 곡선으로 한다면 탐색 선택 이력을 남기고 최종 독립 평가 자료로 재사용하지 않는다.

두 목표 칸 하한>0이고 동일 가중 평균≥10%p라는 기준은 **사전 선택한 실용적 목표**로는 가능하다. 한 seed의 on-policy 자료에서 이 기준을 넘었다고 지도 입력의 일반적·인과적 효과가 입증된 것은 아니다. ‘해당 학습 창의 관찰 기준 충족’이라고 적는다. 오히려 같은 초기조건의 정적 checkpoint 대조와 여러 학습 seed가 효과 주장에 필요하다.

### 표본과 이후 독립 평가

첫 독립 pilot은 **지형당 200개 같은 case**를 A/B에 주는 안을 권고한다. gap/돌 크기·배치·마찰·초기 자세·명령·시간 상한을 case에 고정하고 무작위화 seed 목록도 동결한다. 학습/진단 seed와 다른 목록을 쓴다. 예비 목록 10000~10199, 이후 별도 평가 20000 이후처럼 명시할 수 있으나 번호 자체는 독립성을 보장하지 않는다. 생성 절차와 중복도 검사한다.

주 지형 통과는 예를 들어 전진 .5m/s, 시작점·진행축·완료선·25초 상한을 고정하고, 평지 전진/횡/후진/회전/정지 보존은 별도 칸으로 둔다. 실제 공통 평가 계약이 다른 값을 정했다면 그 계약을 먼저 동결한다. 어려운 조건을 본 뒤 빼거나 시간 상한을 바꾸지 않는다.

200은 탐색 예산이지 ‘+10%p 검출에 충분’이라는 수치가 아니다. 짝 결과 D∈{-1,0,1}, 불일치율 q, 차이 δ이면 독립 짝 근사 분산은 (q−δ²)/n이다. δ=.10에서 q=.2/.5/1이라면 95% 양측 구간과 단일 칸 약80% 검정력을 위한 정규근사 n은 각각 약149/385/777이다. 두 칸 동시 성공 확률·학습 seed 변동·집락 상관·추가 arm·반복점검은 포함하지 않은 계산이다. n=200의 보수적 95% 반폭은 약14%p이므로 작은 차이는 판정 불가일 수 있다.

또한 실제 평균 효과가 정확히10%p이면 표본 평균≥10%p라는 부가 문턱의 통과 확률은 큰 표본에서도 대략 절반이다. ‘10%p 효과를 80% 확률로 기준 통과’라는 표본 계산은 이 점을 빼면 틀린다. 최종 표본은 기대 효과가 문턱보다 얼마나 큰지, pilot의 짝 불일치율과 집락을 사용해 **최종 결과를 보기 전에** 정한다. 한 학습 seed의 episode를 늘려 seed 재현성을 대신하지 않는다. 확증 단계는 별도 학습 seed 최소3개를 출발점으로 검토하되 이것도 보편적으로 충분한 개수는 아니다.

**남길 미확인:** 적정 N·VRAM, 지형 난도/조우량, 명령 curriculum의 실제 배포 상태, 필요한 최종 표본/학습 seed 수, A/B 효과. ‘이 조건에서 못 배웠다’를 MoE-CTS 구조 전체가 불가능하다는 결론으로 확대하지 않는다.
