## 미확인

- E1 부모(`model_20000.pt`)가 위 `RewardsCfg` 와 같은 보상으로 학습됐는지. E1 실행 폴더의 `params/env.yaml` 과 대조해야 한다 (sol 작업서 첫 항목).

- MARG 식(7)의 정확한 형태. `PAPERS-architecture.md` 에는 「c_t(n² + 2n³) 가중 -0.01 · 발 주변 9점 · 접촉점 Type 1 · 5 cm 안 Type 2 · √50 cm 안 Type 3 · 점 높이 < -0.2 면 가장자리」 라고 옮겨 적혀 있지만, 이 문장만으로는 n 과 c_t 가 무엇인지 구현할 수 없다. 원문 대조는 ASTRA 17ag 의 일이다.

## 비교 틀: 2 × 2

| | 발 디딤 보상 없음 | 발 디딤 보상 있음 |
|---|---|---|
| 지도 상수 (A) | A0 | A1 |
| 이상적 지도 (B) | B0 | B1 |

- S2-1 은 왼쪽 열(A0 · B0). S2-2 는 오른쪽 열(A1 · B1). 같은 시드(11) · 같은 부모 · 같은 지형 덮개 · 같은 평가 장면.
- 보상은 정책 입력과 무관한 **특권 정보(시뮬 지형)** 로 계산한다. 그래야 A1 과 B1 의 보상이 같다. A 가 지도를 못 봐도 보상은 발이 가장자리에 놓였는지를 안다.
- 읽는 법: B0 - A0 = 보게 하는 효과, A1 - A0 = 발 디딤 보상만의 효과, B1 - A1 = 보상이 있을 때 보게 하는 효과. 네 칸이 다 있어야 둘이 섞였는지 갈린다.
- 비용: 짧은 학습 한 번에 2,000 update. N=1,024 의 update 당 시간은 **미측정** 이라 먼저 재야 한다 (MEASURE-N1024.md). 측정 전에는 네 번의 시간을 말하지 않는다.

## 발 아래 높이를 어디서 얻나 (선택지만 적는다)

1. **발마다 광선 센서(RayCaster) 4개, 3 × 3 격자 간격 약 5 cm.** 장점: 크기가 발에 맞는다. 단점: 이 환경에서 Kit 안 RayCaster 는 한 번 크게 막혔다 (offset 의 +20 m 가 광선 시작점을 옮기고 `pos_w` 는 그 offset 을 쓰지 않는다 · 환경 reset 때 센서 시계가 0 으로 돌아간다). 새 센서를 쓰면 실제 Kit 에서 정답을 아는 입력으로 한 번 검증해야 하고 이것도 GPU 단회 동의가 든다.
2. **기존 187칸 지도를 쌍선형 보간.** 장점: 새 센서 없음. 단점: 격자 0.1 m 에 gap 폭 0.10 ~ 0.25 m 라 가장자리가 번진다. 발이 가장자리 3 cm 에 있는지 못 가른다.
3. **지형 mesh 에 직접 질의(sim 내부 높이장).** 장점: 정확. 단점: Isaac Lab 하위 지형 mesh 라 해석적 마스크가 없다. 구현 난이도 미확인.

lead 추천: 1번. 이유는 MARG 가 쓴 것이 「발 주변 9점」 이라 해상도가 발 크기여야 하기 때문이다. 단 2번을 대체안으로 두고, 1번이 Kit 에서 막히면 2번으로 돌아가 효과의 하한만 본다. 최종 선택은 ASTRA 17ag 판정 뒤.

## 위험

- **학습 지형이 쉬운 쪽일 수 있다.** 돌 폭 0.5 ~ 0.7 m 에 간격 0.10 m 면 걸쳐 넘을 수 있는 틈에 가깝다. START 의 가장 어려운 디딤돌은 돌 0.2 m · 틈 0.25 m, 평균대는 0.175 m 이다 (PAPERS 8절, 원문 미대조). S2-1 에서 A0 와 B0 가 비슷하게 나오면 「보는 것의 효과가 없다」가 아니라 「이 지형이 보지 않아도 된다」일 수 있다. 결론 문구는 학습 지형 난이도와 평가 장면 치수를 대조한 뒤에 쓴다. S2-2 에서 돌 난이도를 올리는 안은 팀장 결정 사항이 아니라 설계 변수로 ASTRA 에게 묻는다.
- **보상 가중치가 크면 걸음이 얼어붙는다.** MARG 는 -0.01. 우리 보상은 `feet_regulation` -0.05 등이 이미 있어 합이 달라진다. 값은 ASTRA 17ag 와 짧은 측정으로 정한다.
- **S2-1 실행과 코드를 섞지 않는다.** 발 디딤 보상은 새 번들(step10)에만 넣고, S2-1 의 step9 바이트는 건드리지 않는다. 기본값 `reward_variant = none` 이면 step9 와 동작이 같아야 한다 (시험으로 닫을 항목).
