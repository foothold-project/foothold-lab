# S2 결과 내기와 다음 실험

## 1. 결과가 나오는 길과 막힐 곳

| 단계 | 상태 (10/17 14:25) | 막힐 수 있는 곳 |
|---|---|---|
| 노드 2 합성 배관 → 학습 진입 | 실제 학습 env 생성까지 성공, 합성 지도 정답 대조에서 보류. sol 진단 추가 중 | 원인 미확인 |
| 실제 B 부분 reset 연결 확인 | 코드 결선됨, Kit 미실행 | 짧은 학습 시작 검사에서 처음 실행 |
| N=1,024 첫 10 update | 미측정 | 시간 · VRAM 이 마감 안에 들어가는지 |
| A 학습 → B 학습 (각 2,000 update, 같은 E1 부모 · 시드 11) | 미실행 | 처리량 미측정 · 한 GPU 순차 |
| **평가 (체크포인트 update 0 · 2000, A · B)** | **노드 3 이 첫 case-arm 뒤 `raycaster_cache_not_released` 로 멈춤 (7/8 미실행)** | **학습이 끝나도 평가가 안 되면 결과가 없다. 지금 가장 긴 줄이다** |
| 분석 | 도구(Tango 짝 CI) 있음 | 평가가 나와야 한다 |

중요: 학습 중 지형 조우 기록(encounter)은 현재 비어 있다(ASTRA 17al, `s2_train_entry_17v.py:259~260`). 학습 로그만으로는 지도 효과를 말할 수 없다. 결과는 **체크포인트 평가**에서 나온다. 그래서 평가기 수리(캐시 해제 또는 case-arm 당 자식)를 학습과 병행해서 끝내야 한다.

## 2. 병행 계획 (GPU 가 놀지 않게)

- GPU 0: 노드 2 재실행 통과 → 첫 10 update 판독 → A 학습 → B 학습(순차, 같은 부모 · 시드 · 학습량).
- CPU(sol): 평가기 close 수리(RayCaster 캐시 소유자 계측 vs case-arm 당 자식). Kit 검증은 학습 중 GPU 0 에 여유 VRAM 이 있으면 같은 GPU, 없으면 GPU 1 (크롬 등 정리 후, 팀장 10/17 허용).
- GPU 1: 지금 데스크톱 앱이 약 13.8 GB 를 쓴다(유휴 여유 약 2.4 GB). 평가기 Kit 검증이나 B arm 병렬이 필요해지는 순간 정리한다. 병렬 arm 은 비교 변수가 되므로(GPU 를 가른 것이 둘째 변수) 쓰려면 양쪽 조건을 같게 맞추는 설계가 먼저다.

## 3. 판정 기준 (결과 보기 전에 고정)

- 비교 단위: gap · stepping_stones 칸마다, 쌍 (같은 지형 · 같은 seed · 같은 명령) 의 A 대 B 성공 차.
- 「지도가 좋다」: 목표 칸(gap, stones) 마다 쌍 차의 95 % 신뢰구간 하한 > 0 이고 평균 차 ≥ 10 %p. 구간은 Tango 짝 CI(Wilson 차 아님). 우선 명령 fwd10 (1.0 m/s), 부차 fwd03.
- 대조 칸: flat · stairs_up 은 퇴행 감시 (B 가 A 보다 나빠지지 않는지).
- 「불명」: 구간이 0 을 포함하거나 차 < 10 %p. 「낮은 성능」은 유효한 부정 결과로 보고하고 좋아질 때까지 선별 반복하지 않는다.
- 학습 길이(2,000 update)가 짧아서 불명이 나올 수 있다. 그 해석은 U 를 양쪽 같게 늘린 뒤 같은 기준으로 다시 본다(연장 계약은 구현 · 시험 후, 17ak 2절).

## 4. 결과별 다음 실험 (로드맵의 S2-2 ~ S2-4 와 연결)

| 결과 | 다음 | 출처 |
|---|---|---|

HiPAN(D435i 로 주행)은 정책 학습 경로가 아니라 11/30 SLAM · Nav2 쪽이다.

## 5. 이 계획이 모르는 것

학습 update 당 시간과 VRAM, 평가 8 case-arm 이 한 프로세스에서 돌 수 있는지, 2,000 update 가 효과를 보기에 충분한지는 모두 **미측정**이다. 논문 숫자는 `PAPERS-architecture.md` 를 옮긴 것이고 원문에서 다시 재지 않았다.
