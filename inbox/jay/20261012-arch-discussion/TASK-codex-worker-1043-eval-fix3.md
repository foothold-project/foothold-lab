# Codex Worker 작업서 · 1043 평가 후보 17t 결함 고침

## 0. 규칙

- 앞 작업서(`TASK-codex-worker-1043-eval-fix.md`, `TASK-codex-worker-1043-eval-fix2.md`) 0 절의 규칙을 그대로 따른다: 커밋 금지 · 삭제 금지 · GPU · Isaac 실행 금지 · `CUDA_VISIBLE_DEVICES=-1` · `_eval` 쓰기 금지(읽기만) · 격리 단언 · 정직한 보고 · em dash 금지 · 관문을 시간 때문에 완화하지 않기.
- **`VERIFY-astra-17t.md` 를 먼저 끝까지 읽고 그 줄 번호 · 반례 · 문구를 그대로 따른다.** 아래는 요약이다. 모르는 것은 추측하지 말고 보고서의 「미확인」 으로.
- UNDECIDED 값(GPU 배정 · 독점 시간창 · 종료 유예와 부분 결과 처리 · launch / retry / 벽시계 상한 값 · 원본 반복 예산 · 재기동 범위 · 비교 통과선의 최종 채택)은 **팀장 결정**이다. 임의로 채우지 않는다. 17t 4 절의 권고값(launch 3 · retry 0 · 반복 false · max_wall_s 1200~1800 · terminate_grace_s 5~10 · `single_start_no_reuse` · 통과선 `semantic_and_json_bytes_and_traj_bytes`)은 ASTRA 의 추정 권고이지 승인값이 아니다. manifest 에는 넣지 말고, **검사 코드는 값 자체가 아니라 형식 · 지원 집합 · 범위 성질**만 검사한다.
- **변이는 정상 소스에서 같은 시험이 먼저 통과하고, 지정한 시험이 의도한 위치에서 `failed [..] want [..]` 로 실패할 때만 CAUGHT.** 17t 는 17s 의 코드 변이 6 종이 모두 「안전검사 비활성화」는 아니라고 정정했다(원본 필드 회귀 · 벽시계 비활성화 · claim 무력화 · retry 0 회귀 · byte-only 표기 오류 · allowlist 조건 제거). 보고서에서 변이 종류를 **실제로 바뀐 의미**로 적고 「안전검사를 끈 변이」라는 말은 해당하는 것에만 쓴다.
- 프로세스: 옛 CPU 시험 프로세스 PID 175820 은 팀장 확인 전에는 종료하지 않는다. 새로 띄운 시험 자식은 자연 종료까지 기다리고, 시험 중 종료는 **그 시험이 직접 띄운 자식 트리에만** 한다. **PID 재사용 시험은 실제 프로세스를 죽이지 말고 psutil 프로세스 표 · 시계를 대체한 결정적 시험으로 한다**(ASTRA 방식).
- 먼저 `codexE/cand/` 를 `codexE/cand_17t_base/` 로 보존하고 해시를 대조한다. 보존 전에는 고치지 않는다.

## 1. 고칠 것 (17t 1 절 · 3 절 · 2 절)

**P1 (기동 차단 · 먼저)**

1. **D:711~720, 753~766 · 소유권 판단이 PID 재사용에서 무관한 자식을 종료.** 감시기는 새 자식의 ppid 가 과거 `known` 에 있다는 이유만으로 등록한다. 그 부모 PID 가 지금도 같은 생성 시각의 프로세스인지 확인하지 않는다. ASTRA 반례: 루트 100 유지, 관찰했던 중간 자식 110 이 종료된 뒤 다른 프로세스가 PID 110 을 재사용해 새 자식 300 을 낳으면, 후보는 110 은 종료하지 않았지만 **무관한 300 을 known 에 넣고 kill 을 호출했다.** 300 의 생성 시각이 맞아도 우리 자식이라는 증거는 아니다. 고침: `known` 을 `(pid, create_time)` 쌍으로 두고, **새 자식의 부모가 known 의 (pid, create_time) 과 지금도 일치할 때만 등록**한다. 부모 신원을 확인할 수 없으면(없어졌거나 시각 불일치 · 접근 거부) 등록도 신호도 하지 않고 lease 를 계속 보유한 채 `unowned_unknown` 사유로 보류한다(운영자 인계). **종료 직전 자식 시각 비교만으로 해결했다고 쓰지 않는다**(17t 의 말). 관찰 간격 사이에 부모가 사라진 경우까지 보장하려면 OS 소유 집합(예: Windows Job Object) 이나 프로세스 핸들로 생명주기를 묶는 방안을 **검토해 보고서에 적는다**(구현은 ASTRA 가 요구하지 않았으므로 필수 아님. 구현하려면 별도 후보로 두고 복잡도 · 위험을 적는다). 시험: (가) ASTRA 반례(루트 100 · 중간 110 종료 후 PID 재사용 · 새 자식 300)에서 300 에 신호를 보내지 않음, (나) 정상 부모 대조군은 기존대로 정상 트리 정리, (다) 접근 거부 자식에는 신호를 보내지 않고 lease 유지, (라) 부모 신원 확인 불가 → `unowned_unknown` 보류, (마) 기존 손자 · STOP · 2 초 / 4 초 시험 유지.
2. **M:232~340, D:1590~1591 · 승인 필드의 값 검사 부재.** `comparison_pass_rule` 이 B 에 들어가지만 값 검사가 없어 엄격 규칙 · `UNDECIDED` · `ignore_all_differences` · `false` · `null` 이 모두 `launch_errors(require_files=True)==[]` 이다. D 는 승인값과 무관하게 엄격한 세 비교를 적용한다. 즉 **허용 규칙과 적용 규칙이 같지 않다.** 고침: 지원 규칙 집합을 코드에 명시(현재 `semantic_and_json_bytes_and_traj_bytes` 하나)하고, 승인의 값이 그 집합에 없으면 거절. D 는 승인된 값을 읽어 그 규칙으로 판정하게 하되 지원 규칙이 하나뿐이므로 현재 동작은 같게 유지한다. 새 필드 전체의 형식 검사도 같이: `approval_id` · `log_name` 은 영숫자 · `_` · `-` 만, `UNDECIDED` 등 예약어 거절, `log_name` 은 CLI 제한에 맞춰 50 자 이하, `attempt` 형식, `restart_scope` 는 지원 집합(현재 `single_start_no_reuse`) 외 거절, `termination_policy` 는 구조(부분 결과 처리 · 종료 유예 초) 형식과 양수 범위 성질만 검사(값은 결정하지 않음). 시험: 각 필드의 정상 · 미결정 · 예약어 · 빈 값 · 미지원 값 반례. 현재 미결정 manifest 가 여전히 기동 불가인 것(다른 UNDECIDED 가 막음)도 유지 확인.
3. **D:1522~1557 · 필수 지문 누락을 `valid` 로 남김.** `diagnostic_record` 가 지문 계산의 `OSError` · `ValueError` · `KeyError` 등을 삼키고 먼저 정한 `status=valid` 를 유지한다. ASTRA 반례: 실제 원본 결과 사본에서 `env_origins.npy` 만 옮기면 `validate` 는 통과하는데 보고는 `status=valid, fingerprint=null`. D:1616~1643 의 최종 완료 조건도 이 누락을 보지 않는다. 고침: **유효로 판정할 run 은 필수 지문(지형 · 배치 증거 포함)이 계산돼야 하며, 계산하지 못하면 why 를 남기고 `held`** 로 내린다. 기본 세 run 과 반복 원본에 같은 필수 조건을 적용. 실패 run 의 없는 증거를 `null` 로 남기는 것은 그대로(그것은 맞음). 최종 완료 조건이 필수 지문 누락을 보게 한다. 시험: 실제 원본 meta 사본(SHA256 `4c4bed8364cf6cc1c873585dc895ec1fee99ab1bc699cf71bed9c19a834bb093`) 의 정상 대조군 → fingerprint 생성 · valid, `env_origins.npy` 를 옮기면 → held + why, 복구하면 다시 정상. 반복 원본에도 같은 시험.

**P2**

4. **공통 지문 대조(17t 3 절 둘째 문단).** 세 run 이 같은 물리 조건이었는지를 **계약상 의도된 차이(평가기 소스 · 버퍼 설정 등)를 제외한 공통 지문**으로 대조하는 단계를 진단 비교에 넣는다. 의도된 차이의 목록은 코드에 명시하고 보고서에 적는다. 공통 지문이 어긋나면 `held` + 어긋난 항목. 이 대조의 통과 · 실패는 `comparison_pass_rule` 의 의미 비교와 따로 기록한다.
5. **비용 보고(17t 3 절 셋째 문단).** `wall_s` 가 마지막 try 시간이라는 점을 보고 필드 이름 · 설명에서 분명히 하고, run 별 전체 비용(`try_records` 합 · 준비 · 안정성 관찰 · 대기)을 합친 `total_wall_s` 를 추가한다. 승인된 조건부 반복이 실제 실행되지 않았다면 그 여부와 사유(`repeat_not_needed` / `repeat_not_approved` / `repeat_ran`) 를 보고에 명시한다.
6. **allowlist(17t 1 절 마지막 문단).** allowlist 가 `source_eval` 내부의 아무 파일이나 승인하지 않도록, registry · convert_lock · run_lease 세 키에 대해서만 key / exact path 쌍을 받고 그 밖의 키 · 디렉터리 · 와일드카드는 거절함을 시험으로 확인한다(이미 있다면 시험 이름만 보고서에 연결).

## 2. 시험 설명 정정과 시험 보강 (17t 2 절)

7. **정정:** `test_17s_original` 은 slot 경계만 대체한 것이 아니라 `log_done` · `usd_check` · `py_traceback` 도 성공 함수로 바꿨다(50~52 줄). 이 시험은 원본 필드 수정에는 유효하지만 실제 로그 · USD · traceback 통과의 근거가 아니다. 이 사실을 시험 파일 머리 주석과 보고서에 정확히 적는다. `test_17r_e` 의 validate · fingerprint 성공 대체와 runtime guarded 시험의 gate · preflight 대체도 보고서 「시험이 못 보는 것」 에 다시 적는다.
8. **새 코드 검사마다 변이:** 1(소유권 등록 조건) · 2(통과선 값 검사 또는 적용 규칙 일치) · 3(지문 누락 보류) 각각 변이를 만들어, 정상 소스에서 같은 시험이 통과하고 변이에서 지정한 라벨로 실패하는 것만 CAUGHT. 변이마다 「실제로 바뀐 의미」를 한 줄로 적고, 입력 변조(17r 12 종) · 17s 코드 변이 6 종 · 17t 새 변이를 **따로** 센다.
9. **묶음 실행:** `run_all_17t.py`(또는 `run_all_17s.py` 확장)에 새 시험을 넣고 새 run-id 로 전체를 한 번 돌려 종료 코드 · 시간 · 로그 경로를 `evidence_17t/` 에 남긴다. 기존 열 시험이 그대로 통과하는지도 같은 묶음에서 확인한다(회귀).
