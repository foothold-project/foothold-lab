# GPU 와 작업 상태 감시 도구 제안

## 1. 왜 필요한가
- 이번에 GPU 가 놀았던 시간(GPU 0 05:46 부터, GPU 1 09:40 부터)을 사람이 명령으로 잰 값을 모아 적었다. 도구가 놀음 구간 · 시작 시각 · 이유를 자동으로 기록하면 아침 보고와 점검이 정확해진다.
- lead 는 계속 도는 프로세스가 아니라 턴마다 · 한 시간마다(heartbeat) 깨어난다. 한 파일(`gpu_status.json`)만 읽으면 되게 하면 확인이 싸고 빠르다. 사람이 자는 동안에는 놀음 알림이 가장 쓸모 있다.

## 2. 구조 (수집기와 뷰어를 나눈다)
1. **수집기**(작은 Python 프로그램, 의존성 최소): N 초마다 `gpu_status.json` 한 장을 원자적으로 쓴다. 내용: 시각 · 장치별(index · UUID · 이름 · 사용률 · 메모리 사용 / 전체 · 온도 · 전력) · 실행 중 작업 목록 · 놀음 구간 장부(시작 · 끝 · 길이 · 이유).
2. **뷰어**: 위 JSON 만 읽는 정적 HTML 한 장(브라우저에서 자동 새로고침). 서버가 필요하면 `127.0.0.1` 에만 연다. 수집기와 뷰어가 분리되어 있어 뷰어를 바꿔도(터미널 표 · 웹 · 데스크톱 작은 창) 수집기는 그대로다.
3. **작업 어댑터**: 작업(학습 · 평가 · 사슬)이 자기 상태를 **약속된 작은 JSON** 으로 남긴다. S2 사슬의 `chain_status.json`(30 초 주기: 현재 단계 · arm · update · 마지막 유효 산출물 시각 · 잔여 예산 · 다음 경계 · 마감)이 첫 사례다. 수집기는 지정한 폴더의 `*status.json` 을 모아 장치와 연결한다. RL 전용이 아니라 어떤 작업도 같은 틀로 올라온다.

## 3. 어디서나 동작하게 하는 원칙
- 수집 방법을 겹으로 둔다: NVML(`pynvml`) → 없으면 `nvidia-smi` CSV 파싱 → 둘 다 없으면 「GPU 없음」 표시(죽지 않음). 다른 제조사는 나중에 같은 JSON 칸으로 어댑터만 추가.
- **Windows 의 제약을 설계에 넣는다:** WDDM 에서는 프로세스별 GPU 메모리가 `[N/A]` 로 나온다(이 기계에서 확인). 그래서 「이 작업이 얼마나 쓰나」 는 NVML 이 아니라 **작업이 스스로 적은 상태 + 가드 로그**로 채우고 장치 전체 값은 NVML 로 채운다. 장치 전체 값을 작업 몫으로 쓰지 않는다(ASTRA 17o · 17u 의 지적과 같음).
- 경로를 하드코딩하지 않는다: 설정 파일(YAML 또는 JSON) 한 장에 상태 폴더 · 갱신 주기 · 알림 규칙. 사용자 이름 · 한글 경로에 의존하지 않는다.
- 읽기 전용이 기본이다. 작업 중단(STOP 파일 만들기) 같은 조작은 나중에 별도 판정을 거쳐 확인창을 둔 기능으로만.
- 비밀값 · 키를 다루지 않는다. 기본은 로컬 `127.0.0.1` 만. 외부 노출 · 외부 서비스로 보내기는 하지 않는다.
- 의존성은 표준 라이브러리 + `psutil` 정도, 한 폴더로 실행(`python -m gpuwatch`). Windows 와 Linux 에서 같은 시험을 돌린다(토요일 Linux 이전이 두 번째 환경 시험의 기회). 라이선스 고지 · 시험 · README 를 갖추고 배포 가능한 모양으로 만든다.

## 4. 알림 규칙 (첫 판의 핵심)
- GPU 사용률이 낮고 실행 중 작업이 없는 상태가 N 분 이상(권고 10 분)이면 「놀고 있음」 으로 장부에 기록 · 표시(색) · 알림.
- 작업 상태 파일의 마지막 갱신이 오래됐으면(권고 90 초 = 30 초 주기의 3 배) 「죽었거나 멈춤」.
- VRAM 여유가 가드 바닥(4,096 MiB) 밑이면 경고. 온도 · 전력 한계 경고.
- 알림 경로: 장부 파일(lead 가 heartbeat 때 읽음) + 화면 표시. 소리 · 토스트 알림은 선택. 사람이 자는 동안은 파일 기록이 정본이다.
- 놀음 이유는 작업 쪽 상태(`hold_reason` 등)에서 읽어 오고, 없으면 「이유 미기록」 으로 남긴다(꾸며내지 않음).

## 5. 역할 제안
- **lead:** 작업 상태 JSON 의 RL 쪽 칸 정의(S2 `chain_status.json` 포함 · 일반 틀의 한 사례) · 놀음 이유 분류 · 아침 보고에 장부를 쓰는 방법.
- **super:** 수집기 · 뷰어 · 실행 방법(Windows 에서 로그인 때 자동 시작, Linux 에서는 서비스) · 설치 USB 데이터 폴더에 포함 여부.
- **pipeline:** 검증(알려진 입력으로 놀음 감지 · 멈춤 감지 · N/A 처리 · 가짜 nvidia-smi 출력 시험 · Windows / Linux 둘 다).
- 우선순위는 **첫 GPU 가동을 늦추지 않는 것.** Claude · Codex 한도가 빠듯하므로 첫 판은 작게(수집기 한 파일 + 정적 HTML 한 장 + 놀음 장부).

## 6. 오늘 밤 비용 없이 바로 쓰는 법
- 새 PowerShell 창에 `nvidia-smi --query-gpu=index,name,utilization.gpu,memory.used,memory.total,temperature.gpu,power.draw --format=csv -l 5`
- 선택(팀장이 직접 설치할 때): `nvitop`(터미널 GPU 뷰어). Windows 에서는 프로세스별 메모리가 N/A 로 나올 수 있다.
