# sol 작업서: S2 A/B 영상 도구 (step30)

## 0. 지킬 것

새 사본 `codexE/s2_step30/`. step29b 평가기 · 29a 학습 번들 · `_eval` 의 기존 파일은 **읽기만** 한다(복사해서 고친다). 영상은 판정 근거가 아니다(판정은 최종 평가 결과만). 그래서 영상 도구는 무거운 감독 계약 없이 단순하게 가되, **정책 입력이 평가와 똑같아야 한다**: A 는 지도 입력 0, B 는 187 ray 높이 지도 + 유효 마스크(374 열), 센서 `update_period` 0.0, 같은 env cfg, 같은 체크포인트 SHA(A: `0881c0b8…` update 2000, B: B 영수증의 `checkpoint_002000.pt` SHA). 평가 driver 의 env · 정책 구성 함수를 그대로 불러 쓰고 새로 짜지 마라.

## 1. 필요한 것

1. **어떻게 찍었는지 먼저 읽기.** E1/E2 영상(사이트 `site/v/<dir>/*.mp4`)을 만든 경로(`RECORD-HUD.md`, `full_record.py`, `hud_follow.py`, `hud_make.py`, `q_video.py`, `run_videos.sh`)를 읽고 카메라 위치 · 해상도 · fps · HUD 항목 · 포스터 규칙을 보고서에 표로 적어라. S2 영상은 같은 모양으로 맞춘다(사이트에 나란히 놓인다).
2. **도구** `s2_render_ab_videos.py`: 입력은 A/B 체크포인트 경로와 SHA, 사례 목록(case_id, seed, 지형층), 출력 폴더. 사례마다 A 와 B 를 **같은 시드 · 같은 지형 · 같은 명령(fwd10)** 으로 한 번씩 돌려 mp4 와 포스터 jpg 를 만든다. 평가와 같은 길이(평가 driver 의 에피소드 길이)와 같은 종료 규칙. 영상 옆에 그 판의 결과(기준선 도달 · 끝까지 생존)를 기록한 json 을 같이 쓴다.
3. **사례 선택 규칙(결과 전 고정, 이 작업서가 정본):**
   - 고정 8편: gap 시드 4000 · 4001, stepping_stones 시드 4020 · 4021 을 A 와 B 로 (결과를 보기 전에 정한 것).
   - 차이 예시 최대 8편: 최종 평가 결과에서 gap · stepping_stones 각각 「A 실패 · B 성공」 쌍의 시드 번호가 가장 작은 것 1개, 「A 성공 · B 실패」 쌍의 가장 작은 것 1개(없으면 없음이라고 적는다)를 A 와 B 로. 선택 규칙과 고른 시드를 json 에 기록.
   - 이 선택은 평가 결과 파일(`S2-AB-RESULT.json` 또는 평가기 episodes)을 읽어 자동으로 한다. 손으로 고르지 않는다.
4. **영상 검사:** 전 프레임 검사(검정 · 단색 · 빈 프레임 · 비율 · 검은 띠)와 로봇이 화면 안에 있는지(카메라가 로봇을 놓치지 않는지)를 E1/E2 의 `audit_full.py` 방식으로. 결과 json.
5. **실행 단위:** 한 Kit 프로세스에서 여러 편을 찍다 두 번째 환경 생성에서 멈춘 전례(step28)가 있으니, 한 편(한 case-arm)당 새 자식 프로세스로 가거나, 한 프로세스면 왜 괜찮은지 근거를 적어라. `usd_isolate_run_v3.py` 로 USD 변환 폴더를 시도별로 격리하라. 한 편 예상 시간을 적어라(평가 실측 건당 25 s + 렌더 부담은 미측정).
6. **CPU 시험:** 사례 선택 규칙(가짜 결과 파일로 고정 8 + 차이 예시 선택 PASS, 차이 없음 처리), 입력 SHA 불일치 거절, A 지도 입력이 0 이 아니면 거절, B 지도 입력이 비면 거절. GPU 없이 가능한 범위까지.
