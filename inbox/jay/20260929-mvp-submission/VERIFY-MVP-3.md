## 2. 제출 차단 오류

### B1. `push_robot`의 구현 상태가 서로 모순되며, 이벤트 옵션을 독립 시나리오처럼 설명한다

`확인됨`. HTML `s10-b051`과 본문 PDF 28쪽은 “외란 시나리오 push_robot은 구현돼 있지만 비교 평가 결과가 없다”고 한다. 같은 절의 표와 마지막 문장도 하네스가 있다고 한다. 반면 `s12-b015`, PDF 32쪽의 「나」 행은 험지 회전·횡보·장거리·`push_robot`을 묶어 “하네스가 없다”고 한다. 요청된 수정이 문서 전체에는 반영되지 않았다.

코드도 구분해서 읽어야 한다. `sim/eval/eval_command_response.py:267`의 `SCENARIOS`에는 열 개가 있으며 `push_robot`이라는 시나리오는 없다. 332행에는 `--keep_pushes`가 있고, 450~452행에서는 이 옵션이 없을 때 외부 밀기 이벤트를 끈다. 713~717행의 이름 검사상 `--scenario push_robot`은 등록된 실행 이름이 아니다. 따라서 확인한 것은 **기존 환경의 밀기 이벤트를 유지하는 옵션**이다. 별도 외란 평가 시나리오와 판정 조건까지 완성됐다는 뜻으로 확대해서는 안 된다.

로컬 `sim/eval/results/` 아래 `probe_manifest.json` 111개를 직접 읽었으며 `pushes_enabled`가 참인 것은 0개였다. 이 범위에서 외란 비교 결과를 찾지 못했다. 저장소 밖의 실행 결과 존재 여부는 `미확인`이다.

필요 조치: 28쪽과 32쪽을 함께 고쳐 「외부 밀기 이벤트를 켤 수 있는 옵션은 있음, 외란 비교 평가와 판정 조건은 미확인 또는 미측정」처럼 코드가 입증하는 범위로 통일한다. “기준선 셋만 돌리면 읽을 수 있다”도 밀기 조건과 평가 기준을 먼저 명시하는 표현으로 보정해야 한다.

### B2. 제외 요청한 제작 이력이 본문 표와 근거 표에 남아 있다

`확인됨`. 15개 블록을 제거한 사실만으로 편집 요청이 모두 반영됐다고 판정할 수 없다.

| 위치 | 제출본에 남은 내용 |
|---|---|
| `s12-b015`, PDF 32쪽 「나」 | “축 2 컷 HUD는 이 판에서 붙였다”, 하네스를 고칠 필요가 없었고 parquet을 읽었다는 제작 설명 |
| `s15-b002`, PDF 39~40쪽 근거 표 | 「HUD 유무를 센 것」 행의 있음 46·없음 3 집계와 설명 |
| 같은 근거 표의 학습 진행 행 | 앞 영상은 가운데가 1.6초였다는 설명과 “버린 4,096 판”의 경로 |

이들은 평가 조건·실패 사례·해석 한계를 보존하기 위해 필요한 설명과 다르며, 이번 의뢰에서 제외하기로 한 제작 이력에 해당한다. ZIP의 사용 안내는 이미 “제작 이력…제외했습니다”라고 적어 실제 내용과도 어긋난다.

필요 조치: 위 표 안의 제작 이력 문장을 정리한다. 현재 영상의 원자료 경로, 재현에 필요한 설정, 평가의 한계는 유지한다. `fs1`·`fs2` 전용 참고 절과 원문 판 이력은 실제 삭제됐다. 다만 32쪽 「라」 행에는 `fs1`·`fs2` 재개 계획이 남았다. 이는 전용 참고 항목과 다른 문맥이므로 그 이름의 잔존만을 별도 차단 근거로 삼지는 않았다.

### B3. 공통 약점이라는 관찰로 학습 레시피의 영향을 배제한다

`확인됨`. `s10-b048`, PDF 28쪽 강조 문단은 양의 요레이트 추종비를 나열한 뒤 “우리 레시피가 만든 하락이 아니다”라고 단정한다.

`sim/eval/results/20260929-axis2-ext-clips/{nvidia,v1,v2}/turn_rev/per_env.json`에서 `yaw_follow["+0.50"].ratio`를 모델별로 다시 평균했다. 세 모델 모두 유효 환경은 64개다.

| 모델 | 다시 계산한 추종비 | 본문 반올림 |
|---|---:|---:|
| NVIDIA | 0.4269159291 | 0.43 |
| foothold-v1 | -0.0038840038 | -0.00 |
| foothold-v2 | 0.0103328105 | 0.01 |

숫자는 맞지만 결론은 그 숫자에서 나오지 않는다. 기준선에도 추종 미달이 있다는 사실과 추가 학습이 손실에 기여하지 않았다는 주장은 다르다. 기준선 약 0.43에 비해 두 추가 학습 모델은 거의 0이며, 이 비교만으로 레시피의 영향을 배제할 수 없다. 원인 분리는 `미확인`이다.

필요 조치: “NVIDIA에도 양의 회전 추종 미달이 있으며, 추가 학습의 영향과 공통 원인은 분리해 확인하지 않았다” 정도로 제한한다. 새 실험을 요구하는 차단 항목이 아니라 현재 근거에 맞게 인과 단정을 바로잡는 항목이다.

### 페이지와 인쇄

`확인됨`. 본문 40쪽과 요약 2쪽을 직접 렌더해 전체 페이지를 확인했다. 새 영상이 모인 6·26~28쪽, 표가 이어지는 32쪽, 마지막 자료 표까지 확인했다. 내용 잘림·겹침·페이지 밖 텍스트는 발견하지 못했다. 최소 추출 글자 크기는 본문 약 6.45 pt, 요약 8 pt다. 도식의 작은 라벨은 확대하면 읽히지만 실물 출력 가독성은 별도다.

본문 PDF의 목차 목적지 15개는 해당 절 제목의 실제 페이지를 가리킨다. 영상 링크도 49개다. [자료 대응표](CONTENT-MAP.md)의 절별 페이지, 원문 그림 8개의 페이지, 영상 49개의 페이지를 인쇄 DOM과 PDF에서 다시 대응시켜 불일치를 찾지 못했다. 원문 수량 열과 제출본 수량을 혼동하지 않았다.

네트워크를 끈 Chrome 새 탭에서 기본 PDF 인쇄를 실행해 다시 40쪽을 얻었다. 버튼은 준비 함수를 거쳐 `window.print()`를 1회 호출했고, 기본 인쇄 종료 및 `afterprint` 이벤트 후에는 화면 본문이 보이고 인쇄 DOM이 숨겨졌다. 360·390·430 px 화면 너비에서 문서 가로 넘침은 0이었다. 브라우저 JavaScript 오류도 없었다.

Windows 인쇄 대화상자를 사람이 열어 「취소」 버튼을 누른 검사는 하지 않았다. 네이티브 대화상자의 취소 동작 자체는 `미확인`이다. 브라우저의 인쇄 종료 이벤트와 화면 복귀 처리는 직접 확인했다.

### ZIP과 링크

`확인됨`. 작성 세션의 해제 폴더를 재사용하지 않고 대상 ZIP을 새 임시 폴더에 풀었다. 파일은 54개이며 HTML 1개·PDF 2개·영상 49개·사용 안내·manifest로 구성된다. manifest에 기재된 53개 파일의 크기와 SHA-256을 모두 다시 계산해 일치했다.

브라우저를 `offline=True`로 설정한 상태에서 영상 49개 전부 `file:` 경로로 실제 재생시켰다. 재생 시간이 증가했고 미디어 오류는 0개였다. 비교 묶음 18개의 함께 재생·처음으로·2배속 조작도 확인했다. 두 PDF는 ZIP 밖 최종 파일과 바이트가 같다.

단독 HTML의 공개 영상 49개를 GET해 모두 HTTP 200과 로컬 영상의 SHA-256 일치를 확인했다. 나머지 고유 외부 링크 69개도 검사 시점 HTTP 200이었다. 외부 링크의 내용 전체를 이번 검증에서 감사했다는 뜻은 아니다. PDF의 영상 링크는 온라인 주소이고, ZIP 안내가 인터넷 연결 필요성을 명시한다. 오프라인 재생 통과 판정은 압축을 푼 HTML과 `media/`를 함께 전달하는 방식에 적용한다.
