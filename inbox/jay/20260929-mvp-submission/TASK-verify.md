# FOOTHOLD MVP 제출본 독립 검증 의뢰

> 분류: 운영
> 작성: Codex · 2026-09-29 12:19
> 근거: 공개 원보고서와 제출본 검증 의뢰
> 요지: 원문 보존과 전달 기능의 오류를 독립적으로 찾아 수정 여부를 재검증한다.
> 상태: 검증 의뢰 · 판정 `미확인`

원문: https://foothold-project.vercel.app/research-20260928-v2-mvp-report

작업 이슈는 #484다. 원보고서를 외부 제출용 HTML 한 페이지와 여러 장의 PDF로 옮기는 작업이다. 새 이슈·브랜치·학습 실행·정본 수정 없이 이 폴더의 `VERIFY-MVP.md`만 작성한다. 다른 검증자를 재귀 호출하지 않는다.

검증 대상:

- `source/report.html`: 사용자가 지정한 공개 보고서의 보존본. 공개 URL은 `https://foothold-project.vercel.app/research-20260928-v2-mvp-report`다.
- `output/FOOTHOLD-MVP.html`, `output/FOOTHOLD-MVP.pdf`: 제출용 초안. 작성 세션은 검증 중 레이아웃을 개선할 수 있으므로 최종 판정 파일 해시를 남긴다.
- `inventory.json`, `coverage.json`, `pagination-audit.json`: 작성 세션의 계산은 증거를 대신하지 않는다. 직접 다시 센다.
- `frame-selection.json`, `video-scenes.json`, `stills/`, `source/media/`: 공개 영상에서 추출한 주요 장면. `qa/`에 PDF 전 페이지와 영상 접촉 시트가 있다.

목적은 동의가 아니라 오류 발견이다. 핵심은 다음과 같다.

1. 원문의 본문, 표 45개, 본문 그림 8개, 직접 삽입 영상 22편이 보존됐는가. 수치·조건·실패·한계가 빠지거나 더 강한 주장으로 바뀌지 않았는가. 표와 주요 수치를 직접 대조한다. 공개 원문의 오류를 이 제출본이 새로 검증한 사실로 오인하게 만들지 않는가.
2. 개인 이름과 내부 직함을 외부 독자용 표현으로 바꾸면서 기술적 의미가 달라졌는가. 변경 기록 `editorial-changes.json`을 그대로 믿지 말고 실제 두 HTML을 비교한다.
3. PDF에도 그림·표·원문의 각 블록·영상별 대표 장면과 링크가 있는가. 잘림·누락·오버플로·작은 글씨·불필요하게 빈 면적을 본다.
4. 낙상 영상은 실제 넘어지는 장면을 골랐는가. 낙상 뒤 리셋되어 서 있는 끝 장면을 성공으로 보여 주지 않는가. 속도 추종 실패와 낙상을 구분하는가. V06/V09/V12/V15와 V20/V21을 특히 확인한다.
5. HTML 영상 재생 및 비교 조작, PDF 링크와 주요 장면의 시각·설명 일치, 상대 경로와 외부 링크의 전달 가능성을 본다.

원문 수치를 전부 새 실험으로 검증하는 의뢰는 아니다. 원자료가 바로 있다면 대표 성능 수치도 다시 계산하되, 이 제출본의 원문 충실도와 원보고서 자체의 기존 연구 주장에 관한 미확인을 구분한다. 별도 시뮬레이션을 실행하지 않는다. 현재 공개본의 모든 과학적 주장을 승인한 것처럼 판정하지 않는다.

한국어, em dash 금지, 시드 사용, actor·critic·optimizer 원어 유지. 발행 차단 사항과 선택적 보강을 구분하고 수정 후 재검증이 필요한 항목을 명확히 적는다. 작성자 메타데이터는 실제 도구 이름인 `Codex astra`를 쓴다.
