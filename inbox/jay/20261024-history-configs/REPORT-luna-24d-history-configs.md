# LUNA24d · EX09~25 저장 실행 설정 비교

`확인됨`: 29개 저장 run의 설정·SHA 추출 재현. `미확인`: 저장되지 않은 실제 물성 및 모든 부모 상태. 실험 문맥: [실험 이슈555](https://github.com/foothold-project/foothold-lab/issues/555).

## 범위와 방법

읽기 전용 원자료는 `sonnet-code/logs/rsl_rl/` 아래 `foothold_s2_diag`, `foothold_s2_x11`, `foothold_s2_x13`, `foothold_s2_x15`, `foothold_s2_x16n`, `foothold_s2_x17`~`foothold_s2_x23` 이다. CPU 추출기 `extract_history_configs.py` 는 저장된 `params/env.yaml`, `params/agent.yaml`, `manifest.json`을 파싱하고, 원문 파일의 상대 경로와 SHA-256, 전체 설정을 JSON에 보존한다. 코드 기본값이나 기존 문서 서술은 합치지 않았다.

총 29개 run 디렉터리가 발견됐다. smoke/dry run도 별도 레코드로 남겼으며, 아래 주 비교표에는 설정 확인을 위한 full run을 싣고 smoke 판은 결과 판으로 취급하지 않는다. EX09/10 진단 네 폴더에는 manifest가 없다. 설정 YAML은 있으나 체크포인트 부모/초기 상태 영수증은 없으므로 부모 계보는 미확인이다. 저장된 `resume: false`만으로 무조건 scratch 학습이었다고 단정하지 않는다.

이 YAML은 실행 때 저장된 설정 스냅샷이다. 값이 YAML에 있다는 사실은 확인되지만, 값이 명시 오버라이드인지 라이브러리 기본값에서 복사된 것인지는 이 파일만으로 구별할 수 없다. 추출기는 저장값을 빠뜨리지 않도록 전체 env/agent 트리를 함께 보존하고, 없는 값은 null로 남긴다.

YAML의 Python 태그는 코드를 실행하지 않고 tag 이름과 하위 값을 marker 객체로 보존한다. 예를 들어 `builtins.slice` 설정은 JSON에 tag marker와 인수 배열로 남는다. JSON의 원문 의미를 임의로 객체 생성해 바꾸지 않으며, source SHA-256이 원래 파일과의 연결을 고정한다.

## 이번 정정

- 실험 지도 매핑을 적용해 EX09는 `diag-G0-open`, EX10은 `diag-G0-start`로 바로잡았다. 비교는 두 번째 행의 EX10 START와 EX12 START로 다시 맞췄다.
- EX25 DR은 event label 의존으로 누락됐던 항목을 함수명과 params로 찾도록 고쳤다. EX25에 static friction 0.8, dynamic friction 0.6 고정과 base mass additive -1~3가 남아 있다.
- EX20/21/22 action은 일반 `JointPositionAction`이다. EX22는 `UniformVelocityCommand`와 `terrain_levels_vel`을 사용하므로 공통 START/mixed curriculum 행에 합치지 않았다.
- 두 EX23 저장 env YAML의 `sub_terrains`는 각각 키 7개이고 전부 non-null이다. 따라서 8개 키라는 별도 서술은 이번에 읽은 두 파일에서 재현되지 않았다. 있는 일곱 종류의 비율과 generator 함수만 표에 썼다.

## 실행 조건 세부 추적

- **부모/재개:** 저장 agent YAML에서 모두 `resume: false`, `load_run: .*`, `load_checkpoint: model_.*.pt`로 나타난다. manifest에는 run별 `initial_state_sha256`와 imported source SHA가 있지만, 부모 checkpoint 식별자는 없다. 따라서 이 값으로 scratch/resume 계보를 확정하지 않고, 각 파일 내용을 JSON에 남겼다.
- **지형과 승급:** 모든 full run은 generator `size: [8, 8]`, `num_rows: 10`, `num_cols: 23`, `horizontal_scale: 0.1`, `vertical_scale: 0.005`를 저장한다. 실제 `sub_terrains`는 EX09/10 각 13개, EX11~25 각 7개이며 저장 파일에서 null인 항은 없다. 각 종류·비율·함수 이름은 아래 전체 행과 JSON `execution_summary.terrain.non_null_sub_terrains`에 전 run 별로 적었다. EX09/10은 `terrain_levels_s2(t_start=1000,t_end=8000)`, EX11~21/23/25는 `terrain_levels_mixed`, EX22는 `terrain_levels_vel`이다. 실제 실행 초기 row 값은 저장 YAML/manifest에 없어 미확인이다. 각 env의 실제 승급 이력도 미확인이다.
- **명령:** 전 run의 명령을 개별 추출해 아래 행에 기록했다. EX09 open은 dynamic flags와 backoff, EX10 START 및 EX11~21/23/25는 MixedVelocityCommand START (`resampling_time_range: [4,4]`), EX22는 UniformVelocityCommand (`resampling_time_range: [10,10]`, `lin_vel_x: [0.4,1.5]`, `lin_vel_y: [0,0]`, `ang_vel_z: [-1,1]`, `heading: [-pi,pi]`, `terrain_levels_vel`)다. 따라서 EX11~25 전체를 mixed curriculum/START command로 뭉뚱그릴 수 없다.
- **행동/물리:** action scale은 모든 주 run 0.25, action clip은 null이다. EX09~19는 delayed action class와 max delay 0.015 s다. EX20~22와 EX23/25는 일반 `JointPositionAction`이며 설정된 delay field가 없다. 모든 행의 friction/mass/COM/gain/motor DR를 event 이름이 아니라 저장 function/params로 정리해 아래와 JSON에 적었다. 로봇 actuator stiffness/damping/effort limit, initial joint state, reset event와 termination 조건도 행/JSON에서 run별로 대조한다. 설정값과 DR 분포는 실제 샘플 물성 실측값이 아니다.
- **PPO:** full run은 모두 PPO, 5 learning epochs, 4 minibatches, learning rate 0.001, adaptive schedule, gamma 0.99, lambda 0.95, entropy 0.01, desired KL 0.01, clip 0.2, max grad norm 1.0이다. policy init noise std는 1.0이다. 전체 네트워크 구조와 그 외 optimizer 설정은 JSON에 있다.

## 재생성 및 남은 확인

```powershell
python extract_history_configs.py --output history-configs.json --report REPORT-luna-24d-history-configs.md
```

EX09/10 manifest 및 부모 checkpoint lineage, 실제 초기 terrain row/진급 로그, YAML 외부에서 바뀐 런타임 설정은 미확인이다.
