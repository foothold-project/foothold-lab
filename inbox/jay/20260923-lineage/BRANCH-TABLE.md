## 이 문서가 있는 까닭

지금까지는 한 번 돌리고 결과를 본 다음에 그 자리에서 다음을 정했습니다. 그렇게 하면 두 가지가 생깁니다.

**첫째, 판단이 결과에 끌려갑니다.** 결과를 보고 나서 「그러니까 다음은 이것」이라고 정하면, 그 판단이 맞는지 검증할 방법이 없습니다. 2026-09-20 부터 22 까지 우리 두 세션이 낸 잘못이 스무 건 가까이 되는데, 전부 다른 세션이 잡아 준 것입니다.

**둘째, 사람이 계속 붙어 있어야 합니다.** 학습 한 번이 세 시간이 넘는데 그때마다 사람이 다음을 정해 주면 며칠이 걸립니다.

**그래서 분기표를 먼저 씁니다.** 결과가 어떻게 나오든 다음에 무엇을 돌릴지 이 표에 이미 적혀 있습니다. 자동 실행이 표를 읽고 그대로 집행합니다. **표에 없는 결과가 나오면 자동 실행은 멈추고 사람을 기다립니다.**

## 성공 기준 (2026-09-23 확정)

```
축 1   네 체크포인트 전부에서 배포본 대비 하락 0
축 2   네 체크포인트 중 세 개 이상에서 9 / 9
재현   다른 GPU 에서 한 번 더 돌려 위 둘을 다시 만족
```

**루프는 둘 중 하나로 끝납니다.**

```
(가)  위 기준을 만족하는 배포 후보가 나온다
(나)  이 표의 모든 갈래를 다 돌렸고, 각 갈래가 왜 안 올랐는지 기록된다
      = 명령과 보상만으로 갈 수 있는 상한이 근거와 함께 확정된다
```

**(나)도 성공입니다.** 「정책 쪽으로는 여기까지가 한계다」를 근거와 함께 말할 수 있으면, 그것이 신경망 구조로 넘어가는 결정의 근거가 됩니다.

## [1] v2b-r · GPU 만 바꾼 재현

**왜 이것이 먼저인가** · `v2b` 의 모든 결과가 **한 번 돌린 것 위에 서 있고**, 게다가 설정이 세 항목 달랐습니다(의도한 것 하나, GPU 하나, 로그 경로 하나). 이 한 번이 셋을 한꺼번에 줍니다.

```
1. GPU 를 나눈 것이 결과에 얼마나 영향을 주는가
2. v2b 의 「축 1 네 체크포인트 전부 통과」가 재현되는가
3. 흔들리는 칸(회전 -0.5)이 얼마나 자주 통과하는가에 대한 두 번째 표본
```

**바꿀 설정** · `v2b` 와 전부 같고 `--device` 만 `cuda:1` 에서 `cuda:0` 으로 바꿉니다. **새 설정 파일을 만들지 않습니다.** GPU 는 설정 클래스가 아니라 실행 인자에서 오고, 설정 파일에는 작업 이름도 클래스 이름도 남지 않습니다. 파일을 따로 만들면 같은 내용을 내는 클래스가 둘이 되어 「전부 같다」는 주장이 흐려집니다.

**돌리기 전 확인** · 실행 직후 `config_diff_guard` 로 `v2b` 와 대조합니다. 의도한 차이(`sim.device`) 하나만 나와야 통과입니다. 다른 것이 나오면 그 자리에서 멈춥니다.

**예측 (돌리기 전에 적음)**

| | 예측 | 근거 |
|---|---|---|
| 축 1 하락 | 네 체크포인트 전부 0 | GPU 두 장이 같은 모델이라 영향이 작을 것 |
| 축 2 통과 | 5 ~ 7 범위 안 | v2b 가 7·5·6·6 이었음 |
| 회전 -0.5 | 네 개 중 0 ~ 2 개 통과 | v2b 는 0 개, v2a 는 1 개였음 |

**분기**

| 결과 | 다음 |
|---|---|
| 축 1 이 네 개 전부 0 | **[2] v2e 로 간다.** `v2b` 를 기준선으로 확정한다 |
| 축 1 하락이 1 ~ 2 | **[2] v2e 로 가되** 기준선을 `v2a` 로 되돌리고, GPU 차이를 판정문에 조건으로 붙인다 |
| 축 1 하락이 3 이상 | **멈춤.** GPU 차이가 크다는 뜻이고, 그러면 지금까지의 모든 비교를 다시 봐야 한다 |

## [2] v2e · 명령을 NVIDIA 원본 수준까지 연다

**왜 이것인가** · 팀장이 물은 「애초에 명령을 안 건드렸어야 했나」에 대한 직접 답입니다. **우리는 NVIDIA 원본의 명령 설정 전체를 우리 지형에 걸어 본 적이 한 번도 없습니다.**

계보를 보면 명령을 조금씩 열어 왔지만 두 항목은 계속 닫혀 있었습니다.

| 설정 항목 | NVIDIA 원본 | 우리 (D ~ v2b) |
|---|---|---|
| 전진 속도 범위 | −1.0 ~ 1.0 (뒤로 가는 것 포함) | 0.0 또는 0.4 ~ 1.5 |
| 옆방향 속도 범위 | −1.0 ~ 1.0 | **0.0 ~ 0.0 (완전히 닫힘)** |
| 회전 속도 범위 | −1.0 ~ 1.0 | 같음 |
| 목표 방향 관련 | 켜짐 | 같음 |

**바꿀 설정 두 개** · `v2b` 에서 전진 속도 범위를 원본과 같게 하고, 옆방향 속도를 엽니다. 지형과 보상은 건드리지 않습니다.

**예측**

| | 예측 | 근거 |
|---|---|---|
| 축 1 하락 | 2 ~ 5 | 원본 명령은 학습이 넓게 퍼져서 험지에 덜 집중된다 |
| 축 2 통과 | 7 ~ 9 | 원본이 9 를 하는 설정이고, v2b 가 이미 7 |
| 회전 +1.0 | 통과한다 | 원본이 통과하는 칸이고 우리 중 F 만 했다 |

**여기서 옆방향 속도에 붙는 조건** · 우리가 2026-09-20 에 이 항목을 열자는 설계(J)를 냈다가 철회했습니다. 난간에서 밀린다고 생각했는데 실측 옆방향 속도가 거의 0 이었기 때문입니다. **이번에는 까닭이 다릅니다.** 난간 때문이 아니라 **원본의 명령 설정을 그대로 재현하기 위해서**입니다. 이 구분을 판정문에 적어야 합니다.

**분기**

| 결과 | 다음 |
|---|---|
| 축 1 0 이고 축 2 가 9 | **후보 확정.** 다른 GPU 에서 재현하고 끝낸다 |
| 축 1 0 이고 축 2 가 8 | **[3] v2f 로 간다.** 한 칸이 남았고 보상으로 그것을 노린다 |
| 축 1 하락 1 이상 | **[3] v2f 로 간다.** 다만 기준선을 `v2b` 로 되돌린다. 명령을 여는 것이 축 1 을 깎았다는 뜻이다 |

## [3] v2f · 발과 관련된 보상을 넣는다

**왜 이것인가** · 우리는 아홉 정책을 돌리는 동안 **보상을 한 번도 건드리지 않았습니다.** 그런데 지금 보상 설정이 이렇습니다.

| 보상 항목 | 우리 | 참고 논문(MARG) |
|---|---|---|
| 발이 공중에 떠 있는 시간 | 0.01 | **1.0** (100 배) |
| 발이 걸려 넘어지는 것 | 없음 | −1.0 |
| 발 주변이 디딜 만한 곳인가 | 없음 | −0.01 |
| 지형과 충돌 | 없음 | −1.0 |
| 몸통 수평 유지 | **0 (꺼짐)** | −0.2 |
| 관절 한계 | **0 (꺼짐)** | −0.02 |

**중요한 성질 하나** · 보상은 관측이 아닙니다. 그래서 **관측 차원 235 를 깨지 않고 NVIDIA 사전학습 가중치를 그대로 이어받을 수 있습니다.** 신경망 구조를 바꾸는 것과는 비용이 다릅니다.

**「발 주변이 디딜 만한 곳인가」가 무엇인가** · MARG 가 쓰는 방식입니다. 발 하나마다 주변 아홉 점의 높이를 물어보고, 그중 구멍 위에 있는 점의 개수만큼 벌점을 줍니다. **우리가 지금 쓰는 높이 정보는 몸통 중심 격자 하나뿐**이고, 발 중심 정보는 없습니다. 조사한 논문 셋이 전부 발 중심 정보를 어딘가에 넣고 있는데 우리만 없습니다.

**바꿀 설정** · 발 관련 보상 세 개를 넣습니다. 지형과 명령은 직전 단계에서 확정된 것을 그대로 씁니다.

**예측**

| | 예측 | 근거 |
|---|---|---|
| 축 1 하락 | 직전보다 같거나 적다 | 발 배치가 좋아지면 험지에 유리하다 |
| 축 2 | 직전과 비슷 | 보상은 명령 응답과 직접 관계가 적다 |
| `stepping_stones` | 여전히 0 % | 열 개 정책 전부 0 이었고 원본도 0 이다 |

**세 번째 예측을 적어 두는 까닭** · 이것이 틀리면 큰 발견입니다. 지금까지 아무도 그 칸을 못 넘었는데 보상 하나로 넘으면, 그 칸이 「지각의 한계」가 아니라 「보상이 없어서」였다는 뜻이 됩니다.

**분기**

| 결과 | 다음 |
|---|---|
| 축 1 0 이고 축 2 가 9 | **후보 확정.** 재현하고 끝낸다 |
| 기준에 못 미침 | **[4] v2g 로 간다** |

## [4] v2g · 학습 순서를 바꾼다

**왜 이것인가** · 지금까지는 처음부터 끝까지 같은 조건으로 학습했습니다. 참고 논문 둘이 **순서를 나누는 방식**을 씁니다.

```
Zhang 2023    일반 지형으로 8000 회 -> 특정 지형으로 1000 ~ 3000 회 «추가 학습»
              처음부터 어려운 지형으로 10000 회는 «실패»했다고 적고 있다

AME 선행연구   정확한 관측으로 먼저 배우고 «나중에» 관측 잡음을 넣는다
              처음부터 잡음을 넣고 배운 쪽이 희소한 발판에서 더 약했다
```

**우리 조건에서 이것이 뜻하는 것** · 우리는 관측 잡음을 **처음부터 끝까지 최대 크기로** 주고 있습니다. 참고 논문들은 그 크기를 가장 거친 조건에만 쓰고 전체의 10 % 정도만 씁니다.

**바꿀 설정** · 관측 잡음을 학습 초반에 작게 시작해서 후반에 키웁니다. 그리고 지형 난이도도 같은 방식으로 나눕니다. 관측 차원과 신경망은 그대로입니다.

**예측** · 직전 단계 결과를 보고 적습니다. 지금 적으면 근거가 없습니다.

**분기**

| 결과 | 다음 |
|---|---|
| 기준 만족 | **후보 확정** |
| 기준에 못 미침 | **(나)로 끝낸다.** 명령과 보상만으로 갈 수 있는 상한을 이 네 갈래의 기록으로 확정한다 |

## 멈춤 조건

자동 실행은 아래 중 하나라도 걸리면 **더 진행하지 않고 사람을 기다립니다.**

| 멈추는 때 | 왜 |
|---|---|
| 결과가 분기표의 어느 칸에도 안 맞음 | 표가 예상하지 못한 일이 일어났다는 뜻이다. 그때 새로 판단해야 한다 |
| `config_diff_guard` 가 막음 | 의도하지 않은 설정 차이가 있다. 그대로 돌리면 무엇을 잰 것인지 알 수 없다 |
| 학습이 오류로 끝남 · 체크포인트가 없음 | |
| 게시된 영상 검사에서 하나라도 실패 | 결과를 보여 줄 수단이 깨진 상태로는 진행하지 않는다 |
| 같은 갈래에서 두 번 연속 기준 미달 | 같은 곳을 반복하고 있다는 뜻이다 |
| GPU 가 응답하지 않음 · 예상 시간의 1.5 배 초과 | |

**멈출 때는 왜 멈췄는지와 그때까지의 결과를 문서로 남깁니다.** 사람이 그것만 읽고 다음을 정할 수 있어야 합니다.

## 자동 실행이 지킬 것

```
1. GPU 두 장에 두 학습을 «동시에» 걸지 않는다
   2026-09-21 에 그렇게 했다가 GPU 번호가 두 번째 변수가 됐다
   한 장에 순서대로 건다

2. 예측을 «먼저» 적고 커밋한 다음에 학습을 시작한다
   나중에 적으면 결과에 맞춰 쓰게 된다

3. 판정문마다 codex 검증을 한 번 돌린다
   2026-09-21 ~ 22 에 우리가 낸 잘못은 전부 다른 세션이 잡았다
   자동 실행에서 그 두 번째 눈을 없애면 안 된다

4. 영상은 판정이 끝난 «뒤에» 찍는다
   그리고 최종 후보와 «예측이 틀린 칸» 만 찍는다
   전부 찍으면 시간이 많이 들고, 놀란 자리만 남기면 사람이 그것만 보면 된다

5. 게시돼 있는 영상 전부를 주기로 검사한다
   새로 찍은 것만 검사하면 과거 것이 빠진다.
   2026-09-20 에 만든 검사를 새 영상에만 걸어서, 이미 올라가 있던
   깨진 영상을 사흘 동안 못 잡았다

6. 그런데 «자주 돌리는 것만으로는» 부족하다. 관문이 무엇을 못 보는지도 잰다
   2026-09-23 에 확인한 것이다. 문제의 영상은 완전히 검은 것이 아니라
   «한 걸러 한 장» 이 검었다. 옛 검사는 표본 자리가 전부 짝수였고
   검은 장도 짝수였다. 홀수였으면 그냥 통과했을 것이다. 곧 잡은 것이 운이었다.
   고친 검사로 다시 훑으니 «둘째» 가 나왔다. 그것은 표본에 검은 장이 셋
   잡혔는데도 «평균» 이 문턱을 넘어 통과했었다.
   152 편을 매일 돌렸어도 둘째는 안 잡혔다.
   관문을 만들 때는 「통과하면 안 되는 표본」을 같이 만들어 두고, 그것이
   실제로 막히는지 주기로 확인한다

7. 실행 명령을 결과 폴더에 파일로 남긴다
   무엇으로 돌렸는지가 사람 기억에만 있으면 재현을 못 한다
```

## 예측을 적는 형식

각 단계를 시작하기 전에 이 형식으로 적고 커밋합니다.

**결과가 나오면 예측과 나란히 놓고 채점합니다.** 맞았는지 틀렸는지보다 **왜 틀렸는지**가 기록에 남아야 합니다.

## 이 표에 없는 것

**신경망 구조를 바꾸는 갈래는 이 표에 없습니다.** 관측 차원을 늘리거나 인코더를 붙이거나 기억을 넣는 것은 관측 차원 235 를 깨고, 그러면 NVIDIA 사전학습 가중치를 첫 층부터 이어받을 수 없습니다. 비용이 다른 종류입니다.

**그 갈래는 이 표가 (나)로 끝난 뒤에 따로 설계합니다.** 순서가 그래야 하는 까닭은, (나)의 기록이 곧 「정책 쪽으로는 여기까지가 한계다」의 근거이고, 그 근거가 있어야 신경망을 건드리는 비용을 정당화할 수 있기 때문입니다.

## 이 표의 근거는 어디서 왔나

| 무엇 | 어디서 | 표기 |
|---|---|---|
| 아홉 정책의 축 1 · 축 2 성적 | `LINEAGE.md` 요약표. 원시 csv 에서 다시 집계한 값입니다 | `실측` |
| 우리 명령 설정이 원본과 어떻게 다른지 | 두 쪽의 설정 파일을 항목별로 대조했습니다 | `코드확인` |
| 우리 보상 항목과 가중치 | `v2a` 가 실제로 돌아갈 때 저장된 `params/env.yaml` | `코드확인` |
| GPU 를 나눈 것이 두 번째 차이가 됐다는 것 | 685 개 항목을 대조해 확인했습니다 | `확인됨` |
| MARG 의 보상 가중치와 발 주변 아홉 점 | 논문 PDF 원문을 직접 열어 읽었습니다 | `확인됨` |
| Zhang 2023 의 일반 학습 후 추가 학습 | 조사 보고서를 거쳐 받은 값입니다 | `추측` |
| GPU 차이가 결과에 미치는 크기 | 재지 않았습니다. `v2b-r` 이 그것을 잽니다 | `미측정` |
| 각 단계의 예측 | 예측이지 결과가 아닙니다 | `가설` |
