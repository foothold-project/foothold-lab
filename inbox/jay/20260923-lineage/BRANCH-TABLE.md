## 이 문서가 있는 까닭

지금까지는 한 번 돌리고 결과를 본 다음에 그 자리에서 다음을 정했습니다. 그렇게 하면 두 가지가 생깁니다.

**첫째, 판단이 결과에 끌려갑니다.** 결과를 보고 나서 「그러니까 다음은 이것」이라고 정하면, 그 판단이 맞는지 검증할 방법이 없습니다. 2026-09-20 부터 22 까지 우리 두 세션이 낸 잘못이 스무 건 가까이 되는데, 전부 다른 세션이 잡아 준 것입니다.

**둘째, 사람이 계속 붙어 있어야 합니다.** 학습 한 번이 세 시간이 넘는데 그때마다 사람이 다음을 정해 주면 며칠이 걸립니다.

**그래서 분기표를 먼저 씁니다.** 결과가 어떻게 나오든 다음에 무엇을 돌릴지 이 표에 이미 적혀 있습니다. 자동 실행이 표를 읽고 그대로 집행합니다. **표에 없는 결과가 나오면 자동 실행은 멈추고 사람을 기다립니다.**

## 성공 기준 · 정본은 `CRITERIA.md` 입니다

**이 표는 기준을 정하지 않습니다.** 같은 폴더의 `CRITERIA.md` 가 정본이고, 여기서는 읽기 편하게 옮겨 적습니다. 둘이 어긋나면 `CRITERIA.md` 가 맞습니다.

```
축 1   «네 체크포인트 전부» 에서 foothold-v1 대비 진짜 하락 0
축 2   «네 체크포인트 전부» 에서 9 / 9      <- 3/4 에서 4/4 로 (2026-09-23)
재현   조건을 하나 바꿔 한 번 더 돌려 위 둘을 다시 만족

stepping_stones 를 «제외하지 않는다» (제외 규칙은 2026-09-23 에 철회 · CRITERIA 7-2)

보고에 «반드시» 넣는다
  세 열   v1 대비 하락/상승 · NVIDIA 대비 하락/상승 · «절대 최저 칸»
  미판정 칸 수 · 성공률 0 인 칸 목록 · 축 2 칸마다 표본 보유 수
  최종 보고서에는 속도별 · 난이도 스윕 · 지형별을 전부 편다
```

**판정 기준은 2026-09-23 에 동결했습니다.** 후진 · 횡보 · 험지 위 명령 응답 · 외란 회복 · 난이도 스윕 · 오래 걷기는 **관측**이고 통과 여부를 가르지 않습니다. 까닭은 `CRITERIA.md` 3 절에 있습니다.

**루프는 둘 중 하나로 끝납니다.**

```
(가)  위 기준을 만족하는 배포 후보가 나온다
(나)  이 표의 모든 갈래를 다 돌렸고, 각 갈래가 왜 안 올랐는지 기록된다
      = «이 갈래들에서는» 기준에 못 미쳤다는 기록이 남는다
```

**(가)가 나와도 끝이 아닙니다.** 후보를 동결하고 **추가 3 판**을 겁니다. 절대 최저 칸이 오른 판이 있으면 그것을 새 후보로 동결하고 다시 3 판, 3 판에서 개선이 없으면 멈추고 배포합니다 (`CRITERIA.md` 7-1 절).

**(나)도 성공입니다.** 다만 **「명령과 보상 접근의 상한을 증명했다」로 쓰면 안 됩니다.**

**갈래를 다 써 본 것과 상한을 증명한 것은 다릅니다.** 안 해 본 보상 크기 · 일정 · 조합 · 초기화 · 학습량이 남아 있습니다. 미리 정한 갈래가 끝났다는 사실을 「그러므로 신경망을 바꿔야 한다」의 근거로 다시 쓰면 그것이 순환입니다.

**(나)가 뒷받침하는 것은 이 정도입니다.**

```
쓸 수 있는 말   이 네 갈래에서는 기준에 못 미쳤다
                각 갈래가 어디서 막혔는지는 이러이러하다
                그래서 다음으로 «신경망 쪽을 시도해 볼» 근거가 생겼다

쓸 수 없는 말   명령과 보상으로는 여기까지가 «한계» 다
                그러므로 신경망을 바꿔야 «한다»
```

## 이 표가 지켜야 하는 설계 규칙

2026-09-23 에 팀장이 지적한 것입니다. **E 에서 겪은 일을 반복하지 않기 위한 규칙**입니다.

E 는 설정 항목을 둘 바꿨는데 하나만 바꾼 것처럼 읽었습니다. 실험 자체는 돌아갔지만 **결론을 낼 수 없는 구조**였습니다. 분기표 초판도 네 갈래 중 셋이 같은 문제를 갖고 있었습니다.

### 규칙 1 · 갈래마다 「답할 수 있는 물음」을 먼저 적는다

한 번에 여러 항목을 바꾸는 것 자체는 금지가 아닙니다. **바꾼 것을 묶어서만 결론 내는 것**이 규칙입니다.

```
설정 항목을 하나 바꾼 판   그 항목에 대해 결론을 낼 수 있다
설정 항목을 셋 바꾼 판     「셋을 함께 넣으면 이렇게 된다」까지만 말할 수 있다
                          셋 중 무엇이 기여했는지는 «말할 수 없다»
```

그래서 갈래마다 **답할 수 있는 물음**과 **답할 수 없는 물음**을 나란히 적습니다. 판정문을 쓸 때 「답할 수 없는 물음」 칸에 있는 말을 쓰면 검증에서 막습니다.

### 규칙 2 · 묶어서 효과가 나오면 가르는 판이 자동으로 뒤따른다

여러 항목을 묶어 돌렸는데 **효과가 나오면**, 그다음 갈래는 **그 묶음을 가르는 판**입니다. 효과가 없으면 가를 필요가 없으니 다음으로 넘어갑니다.

이렇게 하면 처음부터 다 쪼개지 않아도 되고, 효과가 있는 곳에서만 비용을 씁니다.

### 규칙 3 · 「한 항목만 다르다」는 주장하지 말고 «재서» 확인한다

2026-09-21 에 v2a 와 v2b 를 「한 항목만 다르다」로 설계했는데 실제로는 셋 달랐습니다. GPU 를 나눈 것이 두 번째 차이가 됐습니다.

**모든 학습은 시작 직후 `config_diff_guard` 로 기준 정책과 대조합니다.** 의도한 항목 말고 다른 것이 있으면 그 자리에서 멈춥니다.

### 규칙 4 · 갈래마다 「최종 보고서에 남길 한 문장」을 미리 적는다

이 프로젝트의 산출물은 숫자가 아니라 **왜 이런 시도를 했고 무엇을 보이려 했고 어떤 결과를 얻었는가** 입니다.

그래서 갈래마다 **돌리기 전에** 한 문장을 적습니다. 예를 들어 `[0-b]` 는 이렇습니다.

> 같은 설정을 시드만 바꿔 두 번 돌려서, 우리가 비교해 온 차이가 학습 잡음보다 큰지 확인했다.

**그 문장이 안 써지면 그 갈래는 돌릴 이유가 없습니다.**

### 규칙 5 · GPU 병렬은 「부모에 대해 단일 변수인 자식들」일 때 허용

```
허용   같은 부모에 대해 각각 한 항목만 다른 자식들을 병렬로 건다
       자식끼리는 비교하지 않는다. 각 자식을 부모와만 비교한다
       자식의 GPU 배정은 부모와의 차이가 한 항목이 되도록 정한다

금지   자식끼리 비교하는데 GPU 가 갈려 있는 것 (2026-09-21 에 이것을 했다)
```

자세한 것은 `CRITERIA.md` 9 절에 있습니다.

## 갈래 전체 그림

```
[0]  기준 재기 · 두 판을 «병렬» 로 건다 (부모도 병렬이었다)
       [0-a] v2b-r   시뮬 GPU 만 다름 (cuda:0 · 시드 42)  -> 결정성을 잰다
       [0-b] v2b-s   시드만 다름 (cuda:1 · 부모와 같은 GPU) -> «재현 분산» 을 잰다
       |
       +-- 둘 다 하락 0 --> 기준선 확정. [1] 로 간다
       +-- 분산이 크다   --> 멈춤. 계보 전체의 비교를 다시 봐야 한다

[1]  v2e-x   전진 속도 범위만 원본과 같게 (옆방향은 닫아 둔 채)
       |
       +-- 효과 있음 --> [1'] v2e-y  옆방향도 연다 (가르는 판)
       +-- 효과 없음 --> [2] 로 간다

[2]  v2f-1   feet_air_time 가중치만 0.01 -> 1.0
       |
       +-- 효과 있음 --> [2'] v2f-3  나머지 발 보상 둘을 더한다
       +-- 효과 없음 --> [2'] v2f-3  (묶음도 한 번 본다 · 아래 단서)

[3]  v2g     학습 순서 · 잡음을 나중에 올린다
       |
       +-- 기준 만족 --> 후보 확정
       +-- 미달      --> (나) 로 끝낸다
```

**[0] 이 둘로 갈라진 것이 초판과 다른 점입니다.** GPU 만 바꾸는 판은 「결정성」을 재고, 시드만 바꾸는 판은 **「같은 설정을 두 번 돌리면 얼마나 달라지는가」**를 잽니다. **후자를 한 번도 안 쟀습니다.** 그 값을 모르면 v2a(2,1,2,0) 대 v2b(0,0,0,0) 가 진짜 차이인지 잡음인지 말할 수 없습니다.

**[1] 과 [2] 가 둘로 갈라진 것도 초판과 다릅니다.** 초판은 한 갈래에서 항목을 둘 또는 셋씩 바꿨습니다. 이제 **먼저 하나만 바꾸고, 효과가 나오면 그때 나머지를 더합니다.**

## [0] 기준 재기 · 두 판을 «병렬» 로 건다

> **2026-09-23 정정** · 초판에 「순서대로 한 GPU 에 건다」라고 적었는데 **같은 문서 안에서 모순이었습니다.** `[0-a]` 는 `--device` 를 `cuda:0` 으로 바꾸는 것이 실험의 내용이고 `[0-b]` 는 부모와 같은 `cuda:1` 에 두어야 합니다. **둘을 한 GPU 에 올릴 수가 없습니다.** 그리고 부모 `v2a`·`v2b` 도 5 초 차이로 병렬이었으므로, 따로 돌리면 오히려 부모와 조건이 달라집니다. 규칙 5 의 「부모에 대해 각각 단일 변수인 자식들」에 정확히 해당하므로 병렬이 허용됩니다.

**왜 둘인가** · `v2b` 의 모든 결과가 한 번 돌린 것 위에 서 있습니다. 그런데 「한 번 돌린 것」을 의심하는 방법이 둘이고, 그 둘이 서로 다른 것을 잽니다.

### [0-a] v2b-r · **시뮬레이션** GPU 만 다르게

**바꾸는 것** · `--device` 하나. `v2b` 와 시드도 설정도 전부 같습니다. **새 설정 파일을 만들지 않습니다.** GPU 는 실행 인자에서 오고 설정 파일에는 작업 이름도 클래스 이름도 남지 않으므로, 파일을 따로 만들면 같은 내용을 내는 클래스가 둘이 되어 「전부 같다」는 주장이 흐려집니다.

> **2026-09-23 정정** · 이 갈래를 「GPU 만 다르게」라고 적었던 것을 고쳤습니다. `--device` 는 **시뮬레이션만** 옮깁니다. `train.py` 127 행이 `env_cfg.sim.device` 를 바꾸고, `agent_cfg.device` 는 138 행 곧 `--distributed` 일 때만 바뀝니다. 우리는 그것을 쓴 적이 없습니다. 실제로 `v2a` 와 `v2b` 의 `params/agent.yaml` 이 **둘 다 `cuda:0`** 입니다. **신경망은 두 판 다 GPU 0 에서 학습됐습니다.** 자세한 것은 `RUN-0.md` 0 절에 있습니다.

| | |
|---|---|
| **답할 수 있는 물음** | **시뮬레이션** GPU 를 나눈 것이 결과에 얼마나 영향을 주는가 |
| **답할 수 없는 물음** | 같은 설정을 두 번 돌리면 얼마나 달라지는가. 시드이 같으므로 잴 수 없다 |
| **답할 수 없는 물음** | 신경망을 다른 GPU 에서 학습하면 어떻게 되는가. 옮기려면 `train.py` 를 고쳐야 하고 그것이 두 번째 변수가 된다 |

**예측** · 축 1 네 체크포인트 전부 0. 축 2 는 5 ~ 7. 근거는 GPU 두 장이 같은 모델이고 드라이버도 같다는 것입니다.

### [0-b] v2b-s · 시드만 다르게

**바꾸는 것** · 학습 시드 42 를 다른 값으로. **GPU 는 부모와 같은 `cuda:1` 로 둡니다.**

`v2b` 가 `cuda:1` 에서 돌았기 때문입니다. `cuda:0` 으로 두면 시드과 GPU 둘이 바뀌어 단일 변수가 아니게 됩니다. (2026-09-23 감사에서 이 지시가 문서 사이에서 충돌하는 것을 지적받아 고쳤습니다.)

**왜 이것이 필요한가** · **우리는 재현 분산을 한 번도 잰 적이 없습니다.** 계보의 모든 정책이 시드 42 한 번씩입니다. 그 값을 모르면 이런 것을 말할 수 없습니다.

```
v2a   축 1 하락 2 · 1 · 2 · 0
v2b   축 1 하락 0 · 0 · 0 · 0

이 차이가 「정지 비율 때문」인가, 아니면 «같은 설정도 이만큼 흔들리는가»
```

| | |
|---|---|
| **답할 수 있는 물음** | 같은 설정을 두 번 돌렸을 때 축 1 하락과 축 2 통과가 얼마나 흔들리는가 |
| **답할 수 없는 물음** | 시드 둘로는 분포를 못 잰다. 「이 정도 흔들린다」의 하한만 나온다 |

**예측** · 축 1 하락 0 ~ 2. 축 2 4 ~ 7. 근거는 `v2a` 와 `v2b` 가 이미 그 범위 안에서 움직였다는 것이고, **이 예측이 맞으면 계보의 작은 차이들을 다시 봐야 합니다.**

### [0] 의 분기

| 결과 | 다음 |
|---|---|
| 둘 다 축 1 네 점 전부 0 | **[1] 로 간다.** `v2b` 를 기준선으로 확정한다 |
| `v2b-r` 만 흔들림 | **시뮬** GPU 차이가 있다는 뜻. 앞으로 모든 학습을 한 시뮬 GPU 에 고정하고 [1] 로 간다 |
| `v2b-s` 가 하락 2 이상 | **멈춤.** 재현 분산이 우리가 재 온 차이만큼 크다. 계보 전체의 비교를 다시 봐야 한다 |

**세 번째가 나오면 그것 자체가 중요한 결과입니다.** 실패가 아닙니다.

## [1] v2e · 명령 범위를 원본 쪽으로 연다

**왜 이것인가** · 팀장이 물은 「애초에 명령을 안 건드렸어야 했나」의 직접 답입니다. **NVIDIA 원본의 명령 설정을 우리 지형에 걸어 본 적이 한 번도 없습니다.**

| 설정 항목 | NVIDIA 원본 | 우리 (D ~ v2b) |
|---|---|---|
| 전진 속도 범위 | −1.0 ~ 1.0 (뒤로 가는 것 포함) | 0.0 또는 0.4 ~ 1.5 |
| 옆방향 속도 범위 | −1.0 ~ 1.0 | **0.0 ~ 0.0 (완전히 닫힘)** |
| 회전 속도 범위 | −1.0 ~ 1.0 | 같음 |

## 이 표가 다루지 못하는 것 다섯

여기까지 다 돌려도 남는 것들입니다. **(나)로 끝날 때 이 목록이 같이 나가야 합니다.**

### 1. 후진과 횡보를 재는 칸이 «없습니다»

`[1] v2e-x` 는 후진을 배우게 하는 판인데, **그것이 되는지 잴 방법이 우리에게 없습니다.** 축 2 는 회전 · 정지 · 유지만 보고 축 1 은 전진 속도 세 개만 씁니다.

```
배우게 하는 것    후진 · 횡보
재는 곳           없음
```

**그래서 `[1]` 을 돌리기 전에 정해야 합니다.** 축 2 에 칸을 더할지, 판정에 안 들어가는 관측 항목으로 둘지. 칸을 더하면 통과선이 9 에서 늘어나므로 **과거 판정이 또 뒤집힙니다.** 관측으로만 두는 쪽을 권합니다.

### 2. `stepping_stones` 를 겨냥한 갈래가 «없습니다»

1600 판 중 **여섯 판**만 건넜고 전부 `v2a` 입니다. NVIDIA 원본은 0 입니다. 그런데 **성공 기준에는 안 걸립니다** · 배포본도 0 이라 「하락」이 아니기 때문입니다. **제외 규칙은 2026-09-23 에 철회했습니다** (`CRITERIA.md` 7-2) · 제외해도 하락 수가 안 바뀌고 「절대 최저 칸」만 부풀었습니다.

**기준은 통과하는데 과제 이름에는 걸립니다.** 우리 주제가 「미경험 험지 적응」인데 험지 하나를 아무도 못 건넙니다. (나)로 끝낼 때 이것을 **「기준으로는 통과, 주제로는 미해결」** 로 따로 적어야 합니다.

### 3. 난이도 0.5 하나에서만 잽니다

평가가 난이도 0.5 로 고정돼 있습니다. **후보가 나와도 「난이도 0.5 에서」가 붙습니다.** 팀장이 물은 「우리 하네스 기준 외 평가에서 어디까지 올려야 성공인가」에 답하려면 난이도를 훑어야 합니다.

**후보가 확정된 뒤에 한 번만 돌립니다.** 난이도 0.3 · 0.5 · 0.7 · 0.9 로 같은 정책을 재면 「어디서 무너지는가」가 나옵니다. 학습이 아니라 평가라 비용이 작습니다.

### 4. 지금 후보는 실기로 못 내보냅니다

우리 정책은 관측 235 중 3 차원으로 **몸통 선속도 참값**을 받습니다. 실기 로봇은 그 값을 못 잽니다. 참고 논문(AME-2)은 그 항목을 두고 「교사만 접근 가능」이라고 적습니다.

**(가)에 도달해도 「시뮬레이션 기준 후보」이지 「실기 배포 후보」가 아닙니다.** 이 문장이 판정문에 붙어야 합니다.

### 5. 시드 둘로는 분포를 못 잽니다

`[0-b]` 가 재현 분산을 재지만 시드 두 개입니다. **「이 정도는 흔들린다」의 하한만 나옵니다.** 제대로 재려면 셋 이상이 필요하고, 그만큼 시간이 듭니다. 지금은 하한만 갖고 갑니다.

## 신경망을 바꾸는 갈래는 «일부러» 안 넣었습니다

관측 차원을 늘리거나 인코더를 붙이거나 기억을 넣는 것은 관측 차원 235 를 깨고, 그러면 NVIDIA 사전학습 가중치를 첫 층부터 이어받을 수 없습니다. 비용이 다른 종류입니다.

**그 갈래는 이 표가 (나)로 끝난 뒤에 따로 설계합니다.** (나)의 기록이 곧 「정책과 보상으로는 여기까지가 한계다」의 근거이고, 그 근거가 있어야 신경망을 건드리는 비용을 정당화할 수 있습니다.

## 예산

한 갈래가 학습 약 3 시간 20 분에 평가 약 1 시간 30 분입니다. **한 갈래에 다섯 시간**으로 봅니다.

(평가 에피소드 길이는 축 1 이 속도마다 **12 · 6 · 4 초**이고 축 2 는 시나리오마다 다릅니다. 앞서 「20 초」로 적었던 것은 인자 기본값이고 실제 실행값이 아니었습니다.)

```
[0-a] [0-b]          두 갈래   10 시간   (둘 다 돈다)
[1-a] (+ [1-b])      한둘      5 ~ 10 시간
[2-a] (+ [2-b])      한둘      5 ~ 10 시간
[3]                  하나      5 시간
                     합계      25 ~ 35 시간
```

**규칙 5 를 지키면 두 장을 같이 쓸 수 있습니다.** `[0-a]`·`[0-b]` 처럼 부모에 대해 각각 단일 변수인 자식들은 병렬입니다. 그러면 사흘보다 줄어듭니다. 중간에 멈춤 조건에 걸리면 그 자리에서 서고, 그때까지의 결과만으로 보고합니다.

**여기에 성공 뒤 3 판(`CRITERIA.md` 7-1)은 «안» 들어 있습니다.** 그 단계의 예산은 별도입니다.

**병렬은 규칙 5 를 지킬 때만 씁니다.** 부모에 대해 각각 단일 변수인 자식들은 동시에 걸 수 있고, 자식끼리는 비교하지 않습니다.
