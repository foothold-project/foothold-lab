## 1. 두 차례 감사에서 남은 지적과 그 처리

독립 감사를 두 번 받았습니다. **우리가 낸 잘못을 우리가 잡은 적이 없습니다.** 전부 다른 세션이 잡았습니다. 그래서 이 회차를 예산에서 뺄 수 없는 항목으로 두었습니다.

### 1-1. 고친 것

| 지적 | 무엇이 틀렸나 | 처리 |
|---|---|---|
| 1 차 2-1 | 「`v2a` 가 출발점을 바꿨다」 | **모든 정책이 NVIDIA 원본 가중치에서 이어 학습했습니다.** 「레시피를 배포본과 비교한 것」과 「배포본 가중치에서 이어받은 것」을 섞었습니다 |
| 1 차 2-2 | 지형 분류가 거꾸로 | `omni_gap` 은 원형 도랑이라 평가 `gap` 과 닿고, `floating_ring` 은 연속 바닥 위 부유물입니다. **주석이 아니라 생성 기하로** 다시 갈랐습니다 |
| 1 차 2-7 | 「E 는 D 와 한 항목 다르다」 | **셋** 다릅니다. 전진 하한 0 에서 0.4 를 빠뜨렸습니다 |
| 1 차 2-14 | 재현 계획의 GPU 지시가 문서 사이에서 충돌 | `[0-b]` 를 부모와 같은 `cuda:1` 로 고정했습니다 |
| 2 차 4 | **`stepping_stones` 가 전부 0 이 아니다** | `v2a` 가 여섯 판 건넜습니다. 제가 세 속도를 평균 내 반올림하는 바람에 0 으로 보였습니다. **제외 규칙을 철회했습니다** |
| 2 차 6 | 「성공 뒤 세 번」이 집행 가능한 정의가 아니다 | **`CRITERIA.md` v1.4 에서 다시 썼습니다** (아래 1-2) |
| 2 차 7 | 실행 코드가 새 문서와 다르다 | **이슈 #463** 으로 넘겼습니다 |
| 팀장 지적 | 축 1 은 4/4 인데 축 2 만 3/4 인 까닭 | 근거가 없었습니다. **통과할 수 있는 수를 고른 것**이었습니다. 4/4 로 대칭화했습니다 |

### 1-2. 이번에 새로 닫은 것 · 「성공 뒤 세 번」

감사가 이 절을 **「아직 실행 가능한 정의가 아니다」** 로 판정했습니다. 루프가 사람 없이 이것을 집행해야 하므로 미정 사항을 닫았습니다.

```
최저 칸의 분모     축 1 의 48 칸 전부 · stepping_stones «포함» · 성공률 점추정
                   체크포인트마다 하나씩 네 값 · 평균 금지 · 같은 시점끼리 비교

대체 조건에 추가    동결 후보 대비 «진짜 하락 0» (Wilson 95 %)
                   감사 반례를 막는다 · 50·100 -> 51·51 이면 최저값은 올라도
                   한 칸이 49 %p 무너진다

교체 시점          세 판을 «다 돌린 뒤». 즉시 교체하면 뒤의 판이
                   움직이는 기준과 겨룬다. 동점 처리까지 적었다

재현 판            세 판 «밖» 의 별도 판. 셋 중 고르는 행위 자체가
                   선택 편향을 만들기 때문이다

상한               대체 3 회 또는 학습 «16 판». 한 바퀴가 4 판이라 12 로는
                   세 바퀴째 재현을 못 돈다
```

**그리고 이 정의가 뜻하는 것을 명시했습니다.** `v2b` 의 최저 칸은 `0 · 0 · 0 · 0` 입니다. 대체하려면 네 시점 모두에서 모든 칸이 0 보다 커야 하고, **지금 0 인 칸은 `stepping_stones` 뿐입니다.**

**그래서 대체는 사실상 `stepping_stones` 를 뚫으라는 뜻이 됩니다.** 팀장 판단(「정책으로는 못 풀고 신경망 문제」)과 「추가 세 판은 신경망 쪽」이 같은 곳을 가리킵니다. 우연이 아니라 같은 사실의 두 표현입니다.

### 1-3. 아직 «안» 닫은 것 셋 · **닫지 않기로 한 것입니다**

| 지적 | 왜 지금 안 닫나 |
|---|---|
| 1 차 2-4 · 하락 미검출은 「보존」이 아니다 | **운영 결정입니다.** 절대 하한을 관문에 넣으면 기준이 또 움직입니다. 대신 **절대 수치를 보고에 강제**합니다(3-0 절). 통과를 「결함 없음」으로 번역하지 않습니다 |
| 1 차 2-5 · 아홉 칸은 명령 능력 전체가 아니다 | **맞습니다.** 정지 도달률 · 제동거리 · 잔류속도는 관문이 아니고 회전비에는 상한이 없습니다. 후보가 나오면 **그 후보 하나에** 관측 항목을 전부 돌리고, 그 결과로 다음 기준을 정합니다 |
| 1 차 2-9 · 회전 마지막 칸의 표본 | `F` 의 `0.4195` 는 **51/64** 에서 나온 값입니다. 64 대에 독립적으로 준 성적이 아닙니다. **표본 수 병기를 보고 강제에 넣었습니다.** 다만 병기가 순서 효과나 표본 편향 자체를 없애지는 않습니다 |

**셋 다 「후보가 나온 뒤에 그 후보만 다시 본다」로 미뤘습니다.** 지금 기준을 또 바꾸면 과거 판정과 비교할 수 없게 됩니다.

### 1-4. 이번에 «제가» 찾은 것 · `--device` 는 신경망을 안 옮깁니다

감사가 아니라 걸기 직전 확인에서 나왔습니다.

```
train.py 127     env_cfg.sim.device = args_cli.device      <- 시뮬레이션만
train.py 138     agent_cfg.device = ...                    <- --distributed 일 때만
cli_args.py      device 라는 글자가 «없다»
```

실행 폴더 여섯 개(`E`·`F`·`G`·`H`·`v2a`·`v2b`)의 `params/agent.yaml` 이 **전부 `cuda:0`** 입니다. **신경망은 여섯 판 모두 GPU 0 에서 학습됐습니다.**

그래서 계보의 「학습에 쓴 GPU 가 다르다」를 **「시뮬레이션 GPU 가 다르다」** 로 고쳤습니다. 설계는 안 바꿉니다.

## 2. 확정된 판정 기준 한 장

**정본은 `CRITERIA.md` v1.4 입니다.** 여기는 요약이고, 어긋나면 그쪽이 맞습니다.

```
배포 후보 =

  축 1   «네 체크포인트 전부» 에서 foothold-v1 대비 진짜 하락 0
         진짜 하락 = Wilson 95 % 구간이 겹치지 않으면서 낮은 칸

  축 2   «네 체크포인트 전부» 에서 9 / 9

  재현   조건을 하나 바꿔 한 번 더 돌려 위 둘을 다시 만족
```

**왜 둘 다 「네 체크포인트 전부」인가** · 우리는 체크포인트를 **하나** 골라 배포합니다. 어느 것이 좋은지 미리 고를 방법이 없습니다. 넷 중 셋만 요구하면 나쁜 하나를 **결과를 보고** 골라내야 하고 그것은 체리피킹입니다.

### 「하락 0」은 「잘한다」가 «아닙니다»

배포본보다 나쁘지 않다는 뜻뿐입니다. 그래서 보고에 세 열을 나란히 강제합니다.

| 정책 | v1 대비 | NVIDIA 대비 | 절대 최저 칸 (전체 지형) |
|---|---|---|---:|
| foothold-v1 | 0 / 0 | 0 / 31 | 0 % |
| D | 4 / 2 | 0 / 31 | 0 % |
| v2b 3000 | **0 / 5** | 0 / 31 | **0 %** |

**NVIDIA 기준으로는 우리 정책 «전부» 가 하락 0 이고 상승 28~31 입니다.** 다투고 있는 것은 배포본 대비 회복 과정의 손실이지 절대 성능이 아닙니다.

**그리고 셋 다 절대 최저가 0 입니다.** `stepping_stones` 때문입니다. 이것이 지금 우리 위치입니다.

### `stepping_stones` 0 % 가 뜻하는 것 · **성분을 펴 보면 「못 건넌다」가 아닙니다**

`overall_success` 는 네 축의 **AND** 입니다 (`metrics.py:522-524` · 생존 · 전진 · 속도추종 · 방향). 그래서 **「떨어진다」와 「느리다」가 같은 0 으로 내려옵니다.** 원자료에서 성분을 다시 폈습니다.

| 체크포인트 | 속도 | 종합 | 생존 | 전진 | 추종 | 방향 |
|---|---|---:|---:|---:|---:|---:|
| v2b 2000 | 1.0 | 0.00 | **0.49** | 0.00 | 0.00 | 0.00 |
| v2b 3000 | 0.5 | 0.00 | 0.38 | 0.00 | **0.37** | 0.00 |
| v2b 3000 | 1.0 | 0.00 | 0.39 | 0.02 | 0.02 | 0.02 |
| v2b 3000 | 1.5 | 0.00 | **0.44** | 0.05 | 0.00 | 0.05 |
| v2a 2500 | 1.0 | **0.04** | 0.18 | 0.08 | 0.08 | 0.09 |

**생존이 발목을 잡는 것이 아닙니다.** `v2b` 는 `stepping_stones` 에서 에피소드의 **38 ~ 49 %** 를 끝까지 살아남습니다. 무너지는 것은 **전진** 이고, 속도를 올리면 전진이 조금 살아나는 대신 **추종** 이 0 이 됩니다.

```
0.5 m/s   살아 있고 명령도 따라가는데 «앞으로 안 간다»
1.5 m/s   조금 가는데 «명령 속도를 못 맞춘다»
```

**「stepping_stones 를 못 건넌다」는 표현을 쓰지 않겠습니다.** 지금 자료가 말하는 것은 **「서 있을 수는 있는데 건너가지 못한다」** 입니다.

**주의 · 성분 비율은 «같은 에피소드» 를 뜻하지 않습니다.** 생존 0.44 와 전진 0.05 가 겹치는 에피소드가 몇인지는 이 표로 알 수 없습니다. AND 가 0 이라는 것만 확실합니다. 결합 분포를 보려면 원시 에피소드 표를 따로 세야 합니다. **아직 안 했습니다.**

### 판정이 «아닌» 것

```
후진 · 횡보          학습도 평가도 없다
험지 위 명령 응답     축 2 는 평지 전용 (terrain_type = "plane")
외란 회복            두 하네스 모두 push_robot 을 끈다
난이도 스윕          평가가 0.5 하나다
```

**전부 관측입니다.** 후보가 나오면 그 후보에만 돌립니다.

### 세 오류를 막는 규칙

팀장이 절대 금지로 지시한 셋입니다.

```
에코 체임버   검증자에게 «우리 결론을 안 준다». 원자료를 먼저 읽게 한다
자기 참조     문턱의 출처를 6-1 절에 전부 적는다. 원본으로 문턱을 만들고
              원본의 통과를 다시 그 문턱의 근거로 쓰지 않는다
순환 논리     결과를 못 맞출 때마다 기준을 다시 정의하지 않는다
              바꾸려면 4 절 절차를 밟고 «뒤집히는 판정을 전부» 적는다
```

## 3. 분기표 최종본

**정본은 `BRANCH-TABLE.md` 입니다.** 갈래마다 「답할 수 있는 물음」과 **「답할 수 없는 물음」** 이 같이 적혀 있습니다. 후자가 있어야 결과를 과대 해석하지 않습니다.

| 갈래 | 바꾸는 것 | 답하는 물음 | **답 못 하는 물음** |
|---|---|---|---|
| **[0-a] v2b-r** | 시뮬 GPU 하나 | 시뮬 GPU 를 나눈 것이 얼마나 영향을 주나 | 같은 설정 두 번의 차이. 씨앗이 같아 못 잰다 |
| **[0-b] v2b-s** | 학습 씨앗 하나 | 재현 분산이 얼마나 되나 | 씨앗 둘로는 분포를 못 잰다. 하한만 나온다 |
| [1] v2e | 명령 범위를 원본 쪽으로 | 명령을 더 열면 축 2 가 오르나 | 어느 명령 항목이 기여했나 (둘로 가른다) |
| [2] v2f | 발 관련 보상 | 보상 가중치가 험지를 바꾸나 | 보상 «설계» 가 옳은지. 가중치만 본다 |
| [3] v2g | 학습 순서 | 잡음을 늦게 넣으면 나아지나 | 커리큘럼과의 상호작용 |

### 이 표가 지키는 설계 규칙 다섯

```
1  갈래마다 「답할 수 있는 물음」을 «먼저» 적는다
2  묶어서 효과가 나오면 «가르는 판» 이 자동으로 뒤따른다
3  「한 항목만 다르다」를 주장하지 말고 «685 칸을 대조해» 확인한다
4  갈래마다 「최종 보고서에 남길 한 문장」을 미리 적는다
5  GPU 병렬은 «부모에 대해 각각 단일 변수인 자식들» 일 때만
```

**3 번이 왜 규칙이 됐나** · 2026-09-21 에 `v2a`·`v2b` 를 「한 항목만 다르다」로 설계했는데 실제로는 셋 달랐습니다. 대조해 보고 알았습니다.

**5 번이 왜 규칙이 됐나** · 같은 날 자식끼리 비교하면서 GPU 를 갈라 두 번째 변수가 됐습니다.

### 신경망을 바꾸는 갈래는 «일부러» 안 넣었습니다

지금 갈래는 전부 **설정 항목**만 만집니다. 신경망 쪽은 `[0]`~`[3]` 이 끝난 뒤 또는 성공 뒤 세 판에서 다룹니다. **설정으로 갈 수 있는 곳까지 간 뒤에 신경망을 건드려야 「설정으로는 여기까지였다」를 말할 수 있습니다.**

## 4. 첫 두 판 · **지금 돌고 있습니다**

### 무엇을 걸었나

```powershell
# [0-a] v2b-r · 시뮬 GPU 만 (cuda:1 -> cuda:0)
.\run_gap_train.ps1 -Task Isaac-Velocity-V2b-Unitree-Go2-v0 `
  -Iterations 3001 -NumEnvs 4096 -Seed 42 -Device cuda:0 `
  -RunName 20260923_v2b-r_seed42_iter3000 -Detached

# [0-b] v2b-s · 씨앗만 (42 -> 43) · 시뮬 GPU 는 부모와 같은 cuda:1
.\run_gap_train.ps1 -Task Isaac-Velocity-V2b-Unitree-Go2-v0 `
  -Iterations 3001 -NumEnvs 4096 -Seed 43 -Device cuda:1 `
  -RunName 20260923_v2b-s_seed43_iter3000 -Detached
```

**인자를 하나도 기본값에 맡기지 않았습니다.** `max_iterations` 의 등록된 기본값은 `gap_ppo_cfg.py` 에서 **100** 입니다. 3001 을 안 주면 오류 없이 100 판만 돌고 끝납니다.

### 걸고 나서 확인한 것

PID 가 돌아온 것은 「띄웠다」는 뜻일 뿐입니다. `Win32_Process` 의 `CommandLine` 으로 **각 프로세스가 어느 `--run_name` · `--device` · `--seed` 로 도는지** 확인했습니다.

```
PID 69380   20260923_v2b-r_seed42_iter3000   device=cuda:0  seed=42
PID 74392   20260923_v2b-s_seed43_iter3000   device=cuda:1  seed=43
```

### 병렬이 세 번째 변수가 되지 않는가

**부모가 이미 병렬이었습니다.** `v2a` 11:03:23, `v2b` 11:03:28. **5 초 차이입니다.**

그때 GPU 0 은 `v2a` 의 시뮬과 신경망, 그리고 `v2b` 의 신경망을 같이 들었습니다. 이번에도 같은 모양입니다. **따로 돌리면 오히려 부모와 조건이 달라집니다.**

### 예측 · **결과를 보기 전에 적어 커밋했습니다**

```
[0-a] v2b-r   축 1 하락  네 체크포인트 전부 0
              축 2 통과  5 ~ 7
              특히 볼 칸  회전 -0.5 (v2b 에서 흔들렸다)
              근거       GPU 두 장이 같은 모델이고 드라이버도 같다

[0-b] v2b-s   축 1 하락  0 ~ 2
              축 2 통과  4 ~ 7
              특히 볼 칸  회전 -0.5
              근거       v2a 와 v2b 가 이미 그 범위 안에서 움직였다
```

**`[0-b]` 의 예측이 맞으면 계보의 작은 차이들을 다시 봐야 합니다.** 재현 분산이 우리가 재 온 차이만 하다는 뜻이기 때문입니다.

### 결과별로 다음이 정해져 있습니다

| 결과 | 다음 |
|---|---|
| 둘 다 축 1 네 점 전부 0 | **[1] 로 간다.** `v2b` 를 기준선으로 확정 |
| `v2b-r` 만 흔들림 | 시뮬 GPU 차이가 있다는 뜻. 앞으로 한 GPU 에 고정하고 [1] 로 |
| `v2b-s` 가 하락 2 이상 | **멈춤.** 재현 분산이 우리가 재 온 차이만 하다. 계보 전체를 다시 본다 |

**세 번째가 나오면 그것 자체가 중요한 결과입니다. 실패가 아닙니다.**

### 끝나면 무엇을 도나

```
체크포인트   1500 · 2000 · 2500 · 3000  네 개
축 1         16 지형 x 3 속도 x 100 에피소드 · 난이도 0.5
축 2         평지 · env 64 · 아홉 칸
평가 씨앗     42 로 «고정». 학습 씨앗을 바꾼 것이 [0-b] 의 변수이고
              평가까지 바꾸면 변수가 둘이 된다
```

## 5. 이 설계로 **말할 수 없는 것**

두 축을 다 통과해도 아래는 입증되지 않습니다. 감사의 표를 그대로 옮깁니다.

| 남는 물음 | 왜 자료가 부족한가 |
|---|---|
| 독립 미경험 험지의 일반화 | 지금 평가 집합은 **우리가 설계하며 여러 번 들여다본 개발용 집합**입니다. 독립 보류 집합을 아직 안 만들었습니다 |
| 험지 위 정지 · 회전 · 후진 · 횡보 | 축 1 은 전진 고정, 축 2 는 평지입니다. **두 능력의 조합을 시험한 적이 없습니다** |
| `stepping_stones` 의 실용적 성공 | 성공 예외는 있지만 최대 4/100 입니다 |
| 장시간 안정성 · 외란 회복 | 평가창이 12 · 6 · 4 초이고 밀기와 관측 잡음이 꺼져 있습니다 |
| 실기 전이 | 상태추정 · 센서 오류 · 실기 접촉을 확인하지 않았습니다 |
| 실패의 고유 원인 | 설정 대조와 유한 탐색으로 모든 대안을 지울 수 없습니다 |

### 그리고 이 루프가 «못» 하는 것

```
학습 실패의 원인 진단     사람이나 LLM 이 봐야 한다
분기표에 없는 결과        그래서 «멈춘다». 멈춤은 실패가 아니다
설계가 틀렸을 때          루프는 틀린 설계를 성실히 집행한다
                          그래서 돌리기 «전» 에 감사를 받는다
재부팅 중의 학습          예약 작업은 살지만 돌던 학습은 죽는다
                          죽은 학습을 «자동으로 다시 걸지 않는다»
```

**마지막 것이 중요합니다.** 같은 이름의 결과가 둘 생기면 어느 것이 무엇인지 알 수 없게 됩니다.
