## 1. 현재 기준 (2026-09-23 동결)

```
배포 후보 =

  축 1   «네 체크포인트 전부» 에서 foothold-v1 대비 진짜 하락 0
         진짜 하락 = Wilson 95 % 신뢰구간이 겹치지 않으면서 낮은 칸

  축 2   «네 체크포인트 전부» 에서 9 / 9

  재현   조건을 하나 바꿔 한 번 더 돌려 위 둘을 다시 만족
```

### 왜 둘 다 「네 체크포인트 전부」인가

**우리는 체크포인트를 «하나» 골라 배포합니다.** 어느 것이 좋은지 미리 고를 방법이 없습니다. **넷이 다 좋아야 「아무거나 골라도 된다」가 성립합니다.**

넷 중 셋만 요구하면, 나쁜 하나가 어느 것인지를 **평가 결과를 보고** 골라내야 합니다. 그것은 체리피킹입니다.

**이 근거는 결과와 무관합니다.** 처음에 축 1 을 4/4, 축 2 를 3/4 로 적었는데, 그 비대칭에는 근거가 없었습니다. `v2b` 가 축 1 을 이미 4/4 로 해냈고 축 2 는 아무도 4/4 를 못 했기 때문에 **통과할 수 있는 수를 고른 것**이었습니다. 2026-09-23 에 고쳤습니다.

**지금 이 기준을 만족하는 정책은 없습니다.** 목표는 원래 아직 못 하는 것을 적는 자리입니다.

### 그 밖에 「사람이 정한 것」임을 밝힐 것

**어느 네 체크포인트를 고를지(1500 · 2000 · 2500 · 3000)도 우리가 정했습니다.** 같은 학습의 시점들은 서로 상관돼 있습니다. 시점마다 판정이 갈린 것은 민감도를 보여 주지만 **그 변화가 전부 우연이라는 증거는 아닙니다.**

**그리고 이 기준은 `v2a` · `v2b` 결과를 «본 뒤에» 정했습니다.** 앞으로의 실험에는 사전 기준이지만, 이미 나온 결과에 대해서는 사전 등록 기준이 아닙니다.

### 축 1 의 「하락 0」이 뜻하지 «않는» 것

**「하락 0」은 「잘한다」가 아닙니다.** 우리 배포본보다 나쁘지 않다는 뜻뿐입니다.

기준선이 둘이라는 것을 같이 봐야 합니다.

```
NVIDIA Go2 rough    우리가 출발한 «외부» 기준선
foothold-v1         우리 배포본. 명령을 잠근 채 나갔다는 것을 뒤늦게 알았다
                    축 1 은 «그 회복 과정에서 무엇을 잃었나» 를 보는 자다
```

**축 1 은 품질 등급이 아니라 진단자입니다.** 그래서 절대 하한을 이 관문에 넣지 않습니다. 대신 절대 수치를 **보고에 강제**합니다(3 절).

실제로 두 기준선으로 채점하면 이렇게 갈립니다.

| 정책 | v1 대비 하락/상승 | NVIDIA 대비 하락/상승 | `stepping_stones` 뺀 최저 칸 |
|---|---|---|---:|
| foothold-v1 | 0 / 0 | 0 / 31 | 21 % |
| D | 4 / 2 | 0 / 31 | **9 %** |
| G | 7 / 1 | 0 / 28 | **2 %** |
| H | 5 / 1 | 0 / 30 | **6 %** |
| F | 1 / 3 | 0 / 31 | 54 % |
| v2a 3000 | 0 / 7 | 0 / 31 | 74 % |
| v2b 1500 | 0 / 6 | 0 / 31 | 91 % |
| v2b 3000 | 0 / 5 | 0 / 31 | **95 %** |

**NVIDIA 기준으로는 우리 정책 전부가 하락 0 이고 상승 28~31 입니다.** 축 1 에서 우리는 이미 출발점보다 크게 낫습니다. 다투고 있는 것은 **배포본 대비 회복 과정의 손실**이지 절대 성능이 아닙니다.

**그리고 「하락 0」 하나로는 `D`(최저 9 %)와 `v2b`(최저 95 %)를 구별할 수 없습니다.** 세 번째 열이 있어야 갈립니다.

## 2. 축 1 은 «두 줄로» 읽습니다

평가 지형 16 종 중 일부는 학습에도 나옵니다. **이것 자체는 문제가 아닙니다.** 문제는 「하락 0 / 48」이라는 **한 숫자가 두 종류를 섞는 것**입니다.

**분류는 지형 «생성 코드의 기하» 로 정합니다. 이름이나 주석으로 정하지 않습니다.** 2026-09-23 감사에서 한 번 거꾸로 분류했다가 고쳤습니다.

```
omni_gap (학습)        중심 디딤판과 바깥 착지판 사이가 비어 있는 «원형 도랑»
gap (평가)             중앙 사각 디딤판 둘레의 «사각 도랑»          ← 도랑끼리 닿는다
floating_ring (평가)   «연속 바닥 위에» 떠 있는 물체 (바닥 상자를 따로 만든다)
```

`v2a` · `v2b` 기준의 분류입니다. **정책마다 학습 지형이 다르면 다시 나눠야 하고, 사람이 손으로 적지 말고 `params/env.yaml` 의 `sub_terrains` 에서 읽어 자동으로 갈라야 합니다.**

| 구분 | 칸 | 무엇을 말하는가 |
|---|---:|---|
| 학습한 지형 | 21 | 배운 조건을 유지했는가. **다만 같은 이름이 같은 난이도를 뜻하지 않습니다** (아래) |
| 도랑 경험이 닿는 지형 (`gap`) | 3 | 다른 기하의 도랑으로 옮겨 갔는가 |
| 학습에 없던 지형 | 24 | 학습에 없던 조건에서 어떠한가 |

**「학습 지형 = 조건 유지 시험」으로 읽으면 안 됩니다.** 이름이 같아도 범위가 다릅니다. 예를 들어 `boxes` 는 평가의 높이 값이 **0.125 m** 인데 학습 범위 상한은 **0.10 m** 입니다. 같은 생성기의 **범위 밖**입니다. 그래서 세 가지를 갈라 적습니다.

```
학습 계열을 «유지» 했는가
학습 범위 «밖» 으로 넓힌 것인가
«다른 생성기» 로 옮겨 간 것인가
```

**「일반화를 입증했다」로 쓰지 않습니다.** 지금 평가 집합은 우리가 설계하며 여러 번 들여다본 개발용 집합입니다. 독립 보류 집합에서의 성능과 다릅니다(7 절).

**통과 판정은 48 칸 전체로 합니다.** 나누는 것은 보고할 때이고 통과선을 두 개로 만들지 않습니다.

## 3. 판정에 들어가는 것과 «관측» 인 것

**판정에 들어가는 것은 1 절이 전부입니다.** 나머지는 재고 보고하되 통과 여부를 가르지 않습니다.

### 3-0. 보고에 «반드시» 넣을 것

판정을 요약 숫자로 하는 대신, **보고에는 아래를 강제합니다.** 빠뜨리면 검증에서 막습니다.

```
판정문마다
  세 열을 나란히    v1 대비 하락/상승 · NVIDIA 대비 하락/상승 · 절대 최저 칸
  미판정(겹침) 칸 수
  성공률이 0 인 칸의 목록
  축 2 는 칸마다 «표본 보유 env 수» 를 병기 (0.4195 (51/64) 처럼)

최종 보고서에는 추가로
  «속도별» 성적 (0.5 · 1.0 · 1.5)
  «난이도 스윕» 성적 (0.5 하나가 아니라 여러 난이도)
  «지형별» 성적 (16 종 전부)
```

**N/N 요약은 추적용입니다.** 최종 보고서에서 성능 향상을 보이려면 위 세 가지를 펴야 합니다.

### 3-0-1. 「절대 최저 칸」의 정의

이 지표를 순위에 쓰려다 감사에서 막혔습니다. **집계값으로 쓰지 않습니다.**

```
정의    각 체크포인트마다 «그 시점의 최저 칸 값» 을 하나씩 적는다
        v2b 는 네 값이다 · 0 · 0 · 0 · 0 (전체 지형 기준)
        stepping_stones 를 빼면 91 · 92 · 98 · 95 이지만 그것은 «평가 집합을
        바꿔서 생긴 값» 이므로 두 값을 섞어 쓰지 않는다

금지    네 값을 «평균» 내지 않는다 (관측된 칸의 성적이 아니다)
        네 값 중 «하나» 만 골라 정책을 대표시키지 않는다
        최저 칸을 «품질 등급» 이나 «실패 원인» 으로 쓰지 않는다
```

**최저 칸은 시점마다 다른 지형·속도에서 나옵니다.** `v2b` 는 1500 에서 `floating_ring` 1.5, 2500 에서 `floating_ring` 0.5 입니다. 그리고 그 값들의 Wilson 구간은 서로 겹칩니다. **「고정된 시험 범위 안에서 약한 칸을 찾는 용도」로만 씁니다.**

그리고 앞서 「`하락 0` 하나로는 `D` 와 `v2b` 를 구별할 수 없다」고 썼는데 **틀렸습니다.** 그것은 NVIDIA 기준일 때만 맞고, **배포본 기준으로는 `D`(하락 4)와 `v2b`(하락 0)가 이미 구별됩니다.**

| 항목 | 지금 | 왜 판정이 아닌가 |
|---|---|---|
| 후진 · 횡보 명령 응답 | **관측** | 학습도 평가도 없다. 새로 만들어야 한다 |
| 험지 위에서의 명령 응답 | **관측** | 축 2 는 평지 전용이다 (`terrain_type = "plane"`) |
| 외란 회복 | **관측** | 두 하네스 모두 `push_robot` 을 끈다 |
| 난이도 스윕 | **관측** | 평가가 난이도 0.5 하나다 |
| 오래 걷기 | **관측** | 축 1 은 속도마다 12 · 6 · 4 초, 축 2 는 시나리오마다 10 ~ 20 초다 |
| 저속 추종 | **관측** | 문턱이 없고 원본도 약한 자리다 |

### 왜 이것들을 판정에 안 넣는가

**기준이 계속 움직이면 통과를 선언할 수 없습니다.**

2026-09-23 에 축 2 통과선을 8 에서 9 로 올렸고 그 한 번으로 `D` 의 판정이 뒤집혔습니다. 여기에 항목을 더 넣으면 또 뒤집힙니다. 그러면 이렇게 됩니다.

```
목표를 못 맞출 때마다 목표를 다시 정의한다
  -> 과거 판정과 비교할 수 없다
  -> 통과를 선언할 수 없다
  -> 실험이 안 끝난다
```

**이것도 순환 논리의 한 형태입니다.**

### 그래서 순서를 정합니다

```
1  지금 기준으로 후보를 찾는다
2  후보가 나오면 «그 후보 하나에» 관측 항목을 전부 돌린다
3  그 결과를 보고 «다음 기준» 을 정한다. 그때 기준이 바뀌면 4 절 절차를 밟는다
```

**그 후보에 대해 정한 관측 문턱은 「탐색적 기준」으로 표시합니다.** 결과를 보고 정한 것이므로 그 후보의 검증에는 쓸 수 없습니다.

**그리고 이 동결이 「현재 관문이 과제 목적에 충분하다」는 뜻은 아닙니다.** 후보를 정의하려고 측정 범위를 고정한 것이고, 그 정의에 들어왔다는 이유로 연구 목적을 달성했다고 하면 결론이 전제를 다시 말하게 됩니다.

**과거 정책 전부를 새 항목으로 다시 재지 않습니다.** A 부터 H 까지는 이미 두 축을 못 넘은 것이 확정됐고, 새 항목으로 다시 줄을 세워도 결론이 안 바뀝니다. 필요하면 **후보와 배포본 둘만** 비교하면 이야기가 됩니다.

## 4. 기준을 바꾸는 절차

기준은 바꿀 수 있습니다. 다만 **조용히 바꾸면 안 됩니다.**

```
1  이 문서의 6 절에 «무엇을 왜» 바꾸는지 적는다
2  그 변경으로 «판정이 뒤집히는 정책» 을 전부 찾아 적는다
3  뒤집힌 판정이 있으면 그 판정문의 판을 major 로 올린다 (AGENTS.md 352 행)
4  `sim/eval/verdict_manifest.py` 의 상수를 고친다
5  과거 판정문은 «고치지 않는다» (5 절)
```

**2 번을 빠뜨리면 과거 보고가 조용히 거짓이 됩니다.**

## 5. 과거 판정문은 고치지 않습니다

판정문은 **그때 그 기준으로 그렇게 판정했다는 기록**입니다. 기준이 바뀌었다고 과거 문서를 고치면 기록이 아니게 됩니다.

**대신 이렇게 합니다.**

```
과거 판정문   그대로 둔다
              머리에 「기준 판 vN 으로 판정함」 한 줄만 붙인다
이 문서       그 판정이 지금 기준에서 어떻게 되는지 6 절에 적는다
```

## 6. 기준 변경 이력

### v1.0 · 2026-09-23 · 축 2 통과선 8 에서 9 로

**왜** · NVIDIA 원본이 이 아홉 칸을 전부 통과합니다. 8 을 통과라고 부르면 출발점이 하는 것보다 적게 요구하게 됩니다.

**다만 「원본만큼의 성능」이라는 뜻은 아닙니다.** 문턱은 **원본 측정치를 참고해 사람이 정한 허용선**이고, **원본보다 나빠도 같은 9/9 를 받을 수 있습니다.** 원본이 잘하는 항목으로 문턱을 만들고 원본의 통과를 다시 그 문턱의 타당성 근거로 쓰면 독립 검증이 아닙니다.

**변경 시점** · 이 변경은 `v2a`·`v2b` 결과가 나온 뒤였습니다. 다만 축 2 는 **완화가 아니라 엄격화**이고 `D` 를 탈락시키며 `v2b` 도 여전히 미달입니다. **현재 정책을 통과시키려고 바꿨다는 증거는 감사에서 찾지 못했습니다.**

**뒤집힌 판정**

| 정책 | 축 2 | 옛 기준(8) | 새 기준(9) |
|---|---|---|---|
| **D** | 8 / 9 | **통과** | **미달** |
| 나머지 전부 | 7 이하 | 미달 | 미달 (변화 없음) |

**함께 확정한 것** · 축 1 을 네 체크포인트 전부로, 축 2 를 네 체크포인트 중 셋 이상으로, 그리고 재현을 요구하는 것.

## 6-1. 문턱은 어디서 왔나

8-3 절 규칙에 따라 여기에 모읍니다. **자동으로 추정된 경계가 아니라 전부 사람이 정하거나 스냅샷에서 이어받은 값입니다.**

| 문턱 | 값 | 출처 |
|---|---|---|
| 축 2 아홉 칸의 각 문턱 | 여러 값 | NVIDIA 원본 실측을 **참고해** 사람이 정함 |
| 축 2 통과 칸 수 | 9 | 사람이 정함 (2026-09-23 · 그전엔 8) |
| 속도 오차 | 0.25 m/s | 2026-08-22 스냅샷에 이미 상수로 있었음. **최초 선정 이유는 못 찾음** |
| 방향 이탈 | 0.75 m | 같은 스냅샷의 상수 |

## 7. 최종 보류 지형 · 아직 만들지 않습니다

지금 평가에 쓰는 `unseen10` 은 **처음부터 평가용으로 우리가 골라 둔 것**입니다. 설계할 때 이미 우리 눈에 들어와 있었으므로, 엄밀한 의미의 보류 집합이 아닙니다.

**그래서 진짜 보류 집합을 따로 둡니다.**

```
만드는 시점    모든 설계와 학습이 끝난 «뒤»
쓰는 횟수      후보 정책 하나에 «한 번»
규칙           이 지형을 보고 나서 설계를 바꾸지 않는다
               바꾸면 보류 집합이 아니게 된다
```

**나중에 만들겠다는 계획만으로 독립성이 생기지는 않습니다.** 아래를 **결과를 보기 전에** 정해 두어야 합니다.

```
생성 규칙과 선정 규칙   무엇을 어떤 범위로 만들 것인가
씨앗                    지형 생성 씨앗을 미리 고정한다
평가할 대상             후보 정책과 기준선을 미리 정한다
실패도 남긴다는 규칙     결과가 나쁘면 안 쓰겠다는 여지를 없앤다
```

참고 논문들이 하는 것과 같습니다. MARG 는 실기 지형으로, AME-2 는 학습에 없던 지형으로 제로샷을 보입니다.

**지금은 만들지 않습니다.** 만들어 두면 설계가 그것을 향해 굽습니다.

## 7-1. 성공한 뒤에 멈추지 않습니다

기준을 만족한 정책이 나와도 끝이 아닙니다. **위로만 올라가는 반복**을 둡니다.

**2 차 감사에서 대체 조건이 「실행 가능한 정의가 아니다」라는 판정을 받아 다시 썼습니다.** 특히 「후보가 못 하던 칸을 하나 이상 연다」는 **정의상 공허했습니다** · 성공 후보는 이미 축 2 가 9/9 이고 축 1 하락이 0 이라 **관문 실패 칸이 없습니다.**

### 정의

```
한 번의 시도        «학습 한 판» 이다 (평가 반복이 아니다)
후보 동결          기준을 만족한 정책의 체크포인트 넷과 문서를 고정한다
비교 대상          «동결한 후보» 다 (배포본이 아니다)
```

### 대체 조건 (셋을 «전부» 만족)

```
1  1 절 기준을 그대로 만족한다 (축 1 4/4 · 축 2 4/4)
2  네 체크포인트 «전부» 에서 최저 칸 값이 동결 후보의 «같은 시점» 값보다 높다
   한 시점이라도 낮으면 대체하지 않는다
3  «재현» 에서도 1 과 2 가 다시 나온다
   재현은 기본 관문만이 아니라 «주장한 개선까지» 확인한다
```

**2 번을 「네 시점 전부」로 둔 까닭** · 한 시점만 오르면 잡음으로 교체될 수 있습니다. 100 회 시험에서 성공 하나가 바뀌면 1 %p 가 움직입니다.

**3 번을 「개선까지 재현」으로 둔 까닭** · 기본 관문만 다시 만족하는 것으로는 잡음 교체를 못 막습니다.

### 반복과 종료

```
대체가 일어나면   새 후보를 동결하고 다시 3 판
대체가 없으면     멈추고 배포
전체 상한        대체 «3 회» 또는 총 «12 판» 중 먼저 닿는 쪽에서 멈춘다
```

**전체 상한을 따로 두는 까닭** · 이론상으로는 점수가 유한 격자(45 칸 × 네 시점 × 100 회 → 정수 백분율)라 교체가 최대 100 회지만, **그건 운영상의 종료 보장이 아닙니다.** 감사 지적입니다.

**추가 3 판의 내용은 신경망 쪽으로 잡습니다.** 셋이 다 실패해도 「정책으로 여기까지, 신경망 첫 시도로 여기까지」가 최종 보고서의 마지막 절이 됩니다.

**시간 예산에 이 단계가 «안» 들어 있습니다.** 분기표의 25~35 시간은 기존 갈래 합계이고, 성공 뒤 3 판과 재시작 비용은 별도입니다.

## 7-2. `stepping_stones` · 제외 규칙을 «철회» 합니다

2026-09-23 에 「판정에서 제외한다」로 정했다가 **같은 날 2 차 감사에서 철회했습니다.** 두 가지가 틀렸습니다.

**① 「전부 0」이 사실이 아닙니다** `실측`

```
v2a 2500   0.5 m/s  1 / 100        1.0 m/s  4 / 100
v2a 3000                           1.0 m/s  1 / 100
합계 여섯 판. 생존 · 전진 · 추종 · 방향이 «전부» True 인 행이다
```

제 표가 세 속도를 합쳐 평균 내는 바람에 `5/300 = 1.67 %` 가 정수 반올림으로 0 이 됐습니다. **「같은 관측 구조로는 한 번도 못 넘었다」는 전제에 반례입니다.** (4/100 이 충분하다는 뜻은 아닙니다.)

**② 제외해도 판정이 안 바뀝니다** `확인됨`

축 1 은 절대 성공을 요구하지 않습니다. **기준선과 후보가 둘 다 0 이면 애초에 「하락」으로 세지 않습니다.** 배포본의 세 칸이 0/100 이고 후보의 최고 4/100 도 Wilson 구간이 겹칩니다.

```
제외 «전» 축 1 하락 수  =  제외 «후» 축 1 하락 수
v2b 는 제외 «전에도» 네 체크포인트를 통과했다
```

**곧 제외는 불통과 원인을 해결한 조치가 아니었습니다.** 「제외 없이는 통과할 정책이 없다」고 쓴 제 근거가 틀렸습니다.

**③ 게다가 제외가 지표를 부풀립니다**

`v2b` 의 「절대 최저 칸」은 `stepping_stones` 를 포함하면 네 시점 모두 **0** 이고 제외하면 **91 · 92 · 98 · 95** 가 됩니다. **정책은 그대로인데 평가 집합을 바꿔서 오른 값입니다.**

### 그래서 이렇게 합니다

```
판정        전체 지형으로 한다. «제외하지 않는다»
보고        성공률이 0 인 칸을 «반드시 별도 줄» 로 적는다 (3-0 절)
표현        「정책으로는 불가능」도 「한 번도 못 넘었다」도 «쓰지 않는다»
            쓸 수 있는 말 · 「거의 못 넘는다. 6/1600 판이 건넜고 전부 v2a 다」
```

**이것이 더 단순하고 더 정직합니다.** 제외는 게이트를 안 바꾸면서 지표만 부풀렸습니다.

**남은 사실** · 그래도 이 칸은 계보 전체에서 사실상 안 열립니다. 다음을 신경망 쪽에서 보는 판단은 유지합니다. 다만 **「접근 전체의 성질이다」로는 못 씁니다** · 보상 · 명령 · 노출량 · 기하 · 관측 · 최적화가 아직 분리되지 않았습니다.

## 8. 세 가지 오류를 막는 규칙

2026-09-23 에 팀장이 명시적으로 금지한 것입니다.

### 8-1. 에코 체임버

**증상** · 세션끼리 서로 검증하는데 같은 문서를 읽고 같은 전제를 씁니다. 2026-09-21 에 두 세션이 「한쪽을 얻으면 다른 쪽을 내준다」는 심상을 공유했고 **둘 다 못 잡았습니다.** 데이터가 잡았습니다.

**규칙**

```
검증자는 «우리 문서» 가 아니라 «원자료» 를 읽는다
  원자료 = 논문 PDF · 설정 파일 · 원시 csv · 학습 로그
검증 의뢰서에 우리 결론을 쓰지 않는다. 물음만 쓴다
```

실제로 지금까지 외부 검증이 잡은 것은 전부 원자료를 열어서 나왔습니다.

### 8-2. 자기 참조

**증상** · 축 1 기준선이 `foothold-v1`, 곧 우리 모델입니다. 「하락 0」은 「우리 옛 모델보다 안 나쁨」이지 「잘한다」가 아닙니다.

**가장 뾰족한 예** · `stepping_stones` 는 `foothold-v1` 이 0 %, 후계도 0 % 입니다. **하락이 아니므로 통과로 셈됩니다. 못 하는 것이 통과가 됩니다.**

**규칙**

```
성공률 «자체» 가 0 인 칸은 기준과 무관하게 «미해결» 로 따로 보고한다
  통과 판정과 별개의 줄로 적는다
축 1 을 학습 지형 / 새 지형으로 나눠 보고한다 (2 절)
```

### 8-3. 순환 논리

**증상 하나** · 축 2 문턱이 NVIDIA 원본 실측에서 왔습니다. 그래서 문턱이 원본 측정치에서 왔고 **원본이 못 하는 것은 물어보지도 않습니다.**

**증상 둘** · 목표를 못 맞출 때마다 기준을 다시 정의하는 것(3 절).

**규칙**

```
문턱의 «출처» 를 판정문마다 적는다. 원본 실측인지 우리가 정한 수인지
기준 변경은 4 절 절차를 밟는다. 실험 도중에 바꾸지 않는다
분기표의 갈래마다 「답할 수 없는 물음」 을 미리 적고, 판정문에서 그 말을 쓰면 막는다
```

## 9. GPU 병렬 규칙

2026-09-21 에 두 학습을 동시에 돌리려고 GPU 를 나눴는데, 그 GPU 번호가 **두 번째 변수**가 됐습니다. 그래서 한때 「동시에 걸지 않는다」로 정했는데 **그것은 과했습니다.**

**정확한 규칙은 이렇습니다.**

```
허용   같은 부모에 대해 «각각 한 항목만» 다른 자식들을 병렬로 건다
       자식끼리는 «비교하지 않는다». 각 자식을 부모와만 비교한다
       자식의 GPU 배정은 부모와의 차이가 한 항목이 되도록 정한다

금지   자식끼리 비교하는데 GPU 가 갈려 있는 것
```

**예시** · 부모 `v2b` 가 `cuda:1` 에서 돌았을 때

```
GPU0 : v2b-r    v2b 와 «GPU 만» 다르다        -> 결정성을 잰다
GPU1 : v2b-s    v2b 와 «씨앗만» 다르다        -> 재현 분산을 잰다
                (부모와 같은 GPU 이므로 GPU 는 변수가 아니다)
```

**둘 다 부모에 대해 단일 변수이고 동시에 돌 수 있습니다.** GPU 가 놀지 않습니다.

**그리고 `v2b-r` 이 병렬의 전제입니다.** GPU 효과가 0 에 가까우면 그 뒤로는 자유롭게 병렬해도 되고, 크면 그때 직렬로 바꿉니다.

**다만 한 번의 재실행으로 「GPU 효과」를 확정할 수 없습니다.** 같은 GPU · 같은 씨앗으로 반복해도 비결정적 실행이면 달라집니다. 그 변동을 먼저 갈라야 합니다. 마찬가지로 **씨앗 둘의 차이는 관측된 한 대조**일 뿐 모집단 분산의 하한도 아닙니다.

**모든 학습은 시작 직후 `config_diff_guard` 로 부모와 대조합니다.** 의도한 항목 외에 다른 것이 있으면 그 자리에서 멈춥니다.

## 10. 이 기준으로 바라볼 것

앞으로 만드는 모든 설계문 · 분기표 · 판정문은 이 문서를 근거에 적고, 아래를 지킵니다.

```
1  판정은 1 절 기준으로만 한다. 새 항목은 관측이다
2  축 1 은 학습 지형 / 새 지형으로 나눠 적는다
3  성공률이 0 인 칸은 통과와 별개로 «미해결» 로 적는다
4  갈래마다 「답할 수 있는 물음 / 답할 수 없는 물음」 을 적는다
5  문턱의 출처를 적는다
6  기준을 바꾸려면 4 절 절차를 밟고 6 절에 기록한다
7  갈래마다 「최종 보고서에 남길 한 문장」 을 미리 적는다
   그 문장이 안 써지면 그 갈래는 돌릴 이유가 없다
```

**7 번이 이 프로젝트의 목적입니다.** 최종 산출물은 숫자가 아니라 **왜 이런 시도를 했고, 무엇을 보이려 했고, 어떤 결과를 얻었는가** 입니다.
