## 0. 걸기 전에 바로잡은 것 · **`--device` 는 신경망을 안 옮깁니다**

분기표 `[0-a]` 를 「GPU 만 다르게」라고 적었습니다. **그 문구가 코드와 다릅니다.**

`train.py` 를 읽었습니다.

```
127 행   env_cfg.sim.device = args_cli.device if args_cli.device is not None else env_cfg.sim.device
136 행   if args_cli.distributed:
138 행       agent_cfg.device = f"cuda:{app_launcher.local_rank}"
199 행   runner = OnPolicyRunner(env, agent_cfg.to_dict(), log_dir=log_dir, device=agent_cfg.device)
```

`--device` 는 **127 행에서 시뮬레이션만** 옮깁니다. `agent_cfg.device` 는 **138 행, 즉 `--distributed` 일 때만** 바뀝니다. `cli_args.py` 에는 `device` 라는 글자가 아예 없습니다. 우리는 `--distributed` 를 쓴 적이 없습니다.

그래서 199 행이 신경망을 올리는 자리는 언제나 등록된 기본값입니다.

**실행 기록이 그것을 그대로 보여 줍니다.**

| | `agent.yaml` 의 `device` | `env.yaml` 의 `sim.device` |
|---|---|---|
| `v2a` | `cuda:0` | `cuda:0` |
| `v2b` | **`cuda:0`** | `cuda:1` |

`params/` 는 199 행에서 러너를 만든 **뒤** 213-214 행에서 씁니다. 그러니 이 값이 실제로 쓰인 값입니다.

### 그래서 계보의 문장 하나를 고칩니다

```
틀림   v2a 와 v2b 는 학습에 쓴 GPU 가 다르다
맞음   v2a 와 v2b 는 «시뮬레이션» GPU 가 다르다
       신경망은 둘 다 GPU 0 에서 학습됐다
```

### 이것이 설계를 바꾸지는 «않습니다»

`[0-a]` 는 그대로 `--device cuda:0` 한 개만 바꿉니다. 부모(`v2b`)에 대해 여전히 **한 항목**이고, 그 한 항목이 「시뮬 GPU」라는 것이 분명해졌을 뿐입니다. 신경망까지 옮기려면 `train.py` 를 고쳐야 하고, 그러면 변수가 둘이 됩니다. **안 합니다.**

### 왜 시뮬 GPU 가 결과를 바꿀 수 있는가 · **처음 쓴 설명은 틀렸습니다**

처음에 「`torch.cuda` 의 난수 상태는 장치마다 따로라서 같은 씨앗이어도 다른 수열을 받는다」고 적었습니다. **팀장이 이 대목을 의심했고, 재 보니 틀렸습니다.**

2026-09-23 에 이 기계에서 직접 쟀습니다 (`torch 2.7.0+cu128` · 두 장 다 RTX 5080 · SM 84 · cc 12.0).

```
같은 씨앗으로 두 장치에서 randn 100000 개      비트 동일
두 장치의 RNG 상태                              비트 동일
같은 입력의 matmul + sum                        비트 동일 · 차이 0.0
```

`torch.manual_seed` 는 **모든 장치를 같은 씨앗으로** 초기화합니다. 장치별 생성기가 «따로 있다» 는 것과 «다른 수열을 준다» 는 것은 다릅니다. **제가 그 둘을 섞었습니다.**

### 그런데 학습은 «실제로» 갈라졌습니다

같은 기계에서 `v2b` 와 `v2b-r` 의 체크포인트를 텐서로 대조했습니다.

| 체크포인트 | `actor.0.weight` 최대 절대차 |
|---|---:|
| `model_0` | 6.311e-03 |
| `model_25` | 8.967e-02 |
| `model_50` | 1.282e-01 |
| `model_150` | 1.853e-01 |

`model_0` 은 PPO 갱신을 **한 번** 받은 상태입니다(출발점 대비 1.2e-2 움직였습니다). 그 한 번의 갱신에서 이미 6.3e-3 이 갈렸고, 이는 그 층 가중치 평균 크기의 **10.9 %** 입니다. **첫 갱신부터 다른 궤적입니다.**

### **그래서 이것을 「GPU 효과」라고 부를 수 없습니다**

난수도 산술도 같은데 갈라졌다면 남는 후보는 물리 엔진의 병렬 감소 순서 같은 것입니다. **그런데 그것은 같은 GPU 에서 다시 돌려도 생깁니다.**

```
우리가 아는 것     같은 씨앗 · 같은 설정의 두 판이 «첫 갱신부터» 다르다
우리가 모르는 것   그것이 GPU 때문인지, 그냥 재실행이면 늘 그런 것인지

이유              «같은 GPU · 같은 씨앗의 재실행» 을 한 번도 안 쟀다
```

**그래서 `[0-a]` 의 이름을 다시 읽어야 합니다.** 이것은 「GPU 효과 측정」이 아니라 **「같은 설정의 재실행이 같은 판정을 주는가」** 입니다. 그것이 훨씬 중요한 물음입니다. **계보의 모든 숫자가 한 번씩 돌린 것 위에 서 있기 때문입니다.**

### 그리고 가중치가 갈렸다고 판정이 갈린다는 뜻은 아닙니다

`0.18` 만큼 다른 두 신경망이 48 칸에서 같은 성적을 낼 수 있습니다. **평가까지 가 봐야 압니다.** 팀장이 지적한 부분이 이것이고, 지금 자료로는 어느 쪽도 말할 수 없습니다.

### 싸게 가를 방법이 있습니다 · 지금은 «안» 겁니다

`v2b` 와 **완전히 같은 조건**(`cuda:1` · 씨앗 42)으로 **150 판만** 돌려 `model_0 · 25 · 50 · 150` 을 대조하면 됩니다. 갈라짐이 위 표와 비슷하면 **GPU 탓이 아닙니다.** 10 분이면 됩니다.

**지금 걸지 않습니다.** 세 번째 작업을 올리면 돌고 있는 두 판의 GPU 부하가 달라져 그 둘이 교란됩니다. **두 판이 끝난 뒤에 겁니다.**

## 1. 두 판의 명령 전문

두 판 다 `run_gap_train.ps1` 로 겁니다. `v2a`·`v2b` 를 건 것과 같은 도구입니다.

```powershell
# [0-a] v2b-r · 시뮬 GPU 만 다르게 (cuda:1 -> cuda:0)
.\run_gap_train.ps1 -Task Isaac-Velocity-V2b-Unitree-Go2-v0 `
  -Iterations 3001 -NumEnvs 4096 -Seed 42 -Device cuda:0 `
  -RunName 20260923_v2b-r_seed42_iter3000 -Detached

# [0-b] v2b-s · 씨앗만 다르게 (42 -> 43) · 시뮬 GPU 는 부모와 같은 cuda:1
.\run_gap_train.ps1 -Task Isaac-Velocity-V2b-Unitree-Go2-v0 `
  -Iterations 3001 -NumEnvs 4096 -Seed 43 -Device cuda:1 `
  -RunName 20260923_v2b-s_seed43_iter3000 -Detached
```

**새 설정 파일을 만들지 않습니다.** 둘 다 `Isaac-Velocity-V2b-Unitree-Go2-v0` 를 씁니다. 같은 내용을 내는 클래스가 둘이 되면 「전부 같다」는 주장이 흐려집니다.

### 인자를 하나도 기본값에 맡기지 않는 까닭

`max_iterations` 의 등록된 기본값은 `gap_ppo_cfg.py` 에서 **100** 입니다. 3001 을 안 주면 오류 없이 100 판만 돌고 끝납니다. `num_envs` 와 `seed` 도 같습니다. **기본값이 오류 없이 틀리는 것을 이미 세 번 겪었습니다.**

`3001` 인 까닭은 `rsl_rl` 이 `range(start, start+N)` 으로 돌기 때문입니다. `3000` 을 주면 `model_2999.pt` 에서 끝나고 `model_3000.pt` 가 안 생깁니다.

## 2. 부모와 무엇이 같고 무엇이 다른가

`v2b` 의 `params/{agent,env}.yaml` 에서 읽은 값입니다.

| | `v2b` (부모) | `[0-a]` v2b-r | `[0-b]` v2b-s |
|---|---|---|---|
| 작업 | `Isaac-Velocity-V2b-Unitree-Go2-v0` | 같음 | 같음 |
| 씨앗 | 42 | 42 | **43** |
| 시뮬 GPU | `cuda:1` | **`cuda:0`** | `cuda:1` |
| 신경망 GPU | `cuda:0` | `cuda:0` | `cuda:0` |
| 환경 수 | 4096 | 같음 | 같음 |
| 반복 | 3001 | 같음 | 같음 |
| 출발 가중치 | `nvidia_pretrained_source` / `nvidia_pretrained.pt` | 같음 | 같음 |
| 학습률 | 1.0e-4 | 같음 | 같음 |
| `rel_standing_envs` | 0.1 | 같음 | 같음 |

**각 자식은 부모에 대해 한 항목만 다릅니다.** 자식끼리는 비교하지 않습니다.

### 병렬로 거는 것이 세 번째 변수가 되지 않는가

**부모가 이미 병렬이었습니다.** 실행 폴더의 시각이 그것을 보여 줍니다.

```
v2a   2026-09-21_11-03-23   시뮬 GPU0 · 신경망 GPU0
v2b   2026-09-21_11-03-28   시뮬 GPU1 · 신경망 GPU0
      5 초 차이 · 같이 돌았다
```

그때 GPU 0 은 `v2a` 의 시뮬과 신경망 둘, 그리고 `v2b` 의 신경망을 같이 들고 있었습니다. 이번에도 **같은 모양**입니다. GPU 0 이 `[0-a]` 의 시뮬과 신경망 둘 그리고 `[0-b]` 의 신경망을 들고, GPU 1 이 `[0-b]` 의 시뮬을 듭니다.

**따로 돌리면 오히려 부모와 조건이 달라집니다.**

```
[0-a] v2b-r
```

**`[0-b]` 의 예측이 맞으면 계보의 작은 차이들을 다시 봐야 합니다.** 재현 분산이 우리가 재 온 차이만 하다는 뜻이기 때문입니다.
