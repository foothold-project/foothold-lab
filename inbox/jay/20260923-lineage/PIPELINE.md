## 팀장이 말한 공정

```
1  가설을 세운다 (A~H · v2a · v2b 위에 직렬로)
2  시뮬레이션을 돌린다 (학습)
3  두 축으로 평가한다
4  판단한다 · 나아졌나 · 가설이 검증됐나 · 다음 근거로 쓸 수 있나
5  분기표대로 다음 설계안을 건다
6  산출물을 만든다 · 수치 csv · mp4 영상
7  문서로 남기고 git 에 올린다
8  텔레그램으로 팀장에게 보고한다
9  세션들(super · lead · rl)이 서로 작업을 따라간다
10 위 전부가 2~3 일 자동으로 돈다
```

여기에 하나 더 있습니다.

```
11 문맥·한도를 «실시간으로» 보고 작업 단위로 수동 관리한다
   codex 한도가 차면 리셋권으로 다시 열어 쓴다
```

## 11 번은 제가 «못» 합니다 · 먼저 밝힙니다

```
제 토큰 사용량 · 주간 한도     조회할 도구가 «없습니다»
                              팀장 화면의 /status 에만 보입니다

codex 한도                     `codex --help` 에 usage·quota 하위 명령이
                              «없습니다». 78 % 도 팀장이 알려 준 값입니다

리셋권                         제가 쓸 수 없습니다. 사람이 누르는 것입니다
```

**그러니 「실시간으로 보고 관리한다」를 제가 하겠다고 말하면 거짓말입니다.**

### 대신 할 수 있는 것 · **한도를 «볼» 필요가 없게 만드는 것**

문맥이 문제가 되는 까닭은 루프가 제 대화에 기대기 때문입니다. **기대지 않게 만들면 문맥 관리 자체가 필요 없습니다.**

```
판단이 필요한 자리를 «미리» 없앤다      분기표가 그것이다
한 결정에 들어가는 입력을 «네 파일» 로 고정한다
    state.json · CRITERIA.md · BRANCH-TABLE.md · 직전 판정문
그 네 개면 대화 기록 없이 결정이 된다
```

그러면 LLM 을 부르는 자리가 **판정문 확정 전 검증 한 회차**로 줄어듭니다. 그 한 회차만 codex 에 보내고, 한도가 없으면 **「미검증」으로 표시하고 계속 갑니다.** 나중에 한도가 돌아오면 표시된 것만 몰아서 검증합니다.

**한도가 차면 루프가 서는 것이 아니라 «검증 없이 진행하고 표시» 합니다.**

그리고 리셋권은 **제가 팀장에게 알립니다.** 상태 파일의 `budget.codex_calls_this_week` 가 올라가면 텔레그램 보고에 같이 실어 보냅니다. 누르는 것은 팀장입니다.

## 빈 자리를 메우는 순서

**의존 순서가 있습니다.** 4 가 없으면 5 를 못 만들고, 5 가 없으면 2 를 자동으로 걸면 안 됩니다.

```
가  판정 코드            평가 산출물 -> 축1/축2 숫자 -> CRITERIA 대조
     없으면 나머지가 전부 의미가 없다. 여기부터다

나  분기 코드            판정 숫자 -> BRANCH-TABLE 의 조건 -> 다음 한 줄
     표에 맞는 칸이 «없으면» 멈추고 사람을 부른다

다  보고 · 텔레그램       판정문 한 장을 만들고 보낸다
     «먼저» 만든다. 자동으로 걸기 전에 «보이는» 것이 먼저다

라  자동 커밋·푸시        판정문과 csv 를 브랜치에 올린다
     사람이 git 에서 따라갈 수 있게

마  학습 걸기            여기서야 켠다. 가·나가 시험을 통과한 뒤다

바  영상                 판정이 끝난 «뒤» 최종 후보와 «예측이 틀린 칸» 만 찍는다
     찍은 것은 전부 깨짐 검사를 통과해야 한다
```

**「마」를 뒤에 두는 까닭** · 판정과 분기가 틀린 채로 학습을 자동으로 걸면, 루프가 **틀린 방향으로 사흘을 씁니다.** 지금은 제가 손으로 거는 편이 낫습니다.

**「다」를 앞에 두는 까닭** · 팀장이 무슨 일이 벌어지는지 못 보면 무인 운전이 아니라 깜깜이입니다.

## 각 자리에 필요한 것

### 가 · 판정 코드

이미 있는 것을 씁니다. `sim/eval/verdict_manifest.py` 와 `fourpoint_table.py` 가 **PR #444 에 있습니다.** 다만 **이슈 #463 의 결함 넷을 먼저 고쳐야 합니다.** 안 고치면 루프가 틀린 판정을 성실히 집행합니다.

```
막는 것   #463 · 제외 규칙 철회 · 출력별 제외 불일치 ·
          요약 병합 신원 검사 · 보고 강제 미적용
```

### 나 · 분기 코드

분기표를 사람이 읽는 산문에서 **기계가 읽는 표**로 한 벌 더 만듭니다.

```
_out/loop/branches.json

  갈래마다
    조건      축1 하락 · 축2 통과 · 절대 최저 칸의 «범위»
    다음      걸 명령 전문
    멈춤      맞는 칸이 없을 때
```

**산문을 없애는 것이 아닙니다.** 산문이 정본이고 json 은 «옮겨 적은 것» 입니다. 둘이 어긋나면 산문이 맞고, 옮길 때마다 사람이 한 번 봅니다.

### 다 · 텔레그램 · **팀장이 해 주실 것이 있습니다**

봇 토큰과 방 번호가 필요합니다. **제가 대화에서 받으면 안 됩니다.** 토큰이 대화 기록과 저장소에 남습니다.

이렇게 부탁드립니다.

```
팀장이   봇을 만들고 (@BotFather) 토큰을 받는다
         프롬프트에 «!» 를 붙여 직접 넣는다

           ! setx FOOTHOLD_TG_TOKEN "여기에토큰"
           ! setx FOOTHOLD_TG_CHAT  "여기에방번호"

제가     os.environ 에서 읽기만 합니다. 값은 안 봅니다
         로그에도 안 찍습니다
```

보내는 것은 이렇게 잡습니다.

```
한 판 끝날 때마다    이름 · 축1 · 축2 · 절대 최저 칸 · 분기표의 다음 · 커밋 해시
멈출 때              무엇이 표에 없었는지 · 사람이 무엇을 정해야 하는지
하루 한 번           예산 · 학습 판 수 · 누적 시간 · codex 호출 수
```

### 라 · 자동 커밋 · **승인이 필요합니다**

루프가 `git commit` 과 `git push` 를 스스로 하게 할지 정해 주십시오.

```
제 제안   커밋은 «한다» · 브랜치는 loop/<갈래이름> 로 따로
          푸시도 «한다» · 다만 main 에 직접 안 하고 PR 도 자동으로 안 연다
          PR 은 사람이 본 뒤에 연다
```

### 마 · 학습 걸기

`run_gap_train.ps1` 을 부르는 자리만 있으면 됩니다. **문제는 코드가 아니라 신뢰입니다.** 가·나가 한 바퀴를 제대로 돈 것을 본 뒤에 켭니다.

### 바 · 영상

```
언제      판정이 끝난 뒤
무엇을    최종 후보 · «예측이 틀린 칸» 만
검사      찍은 것 전부 + 이미 올라가 있는 152 편도 «주기로» 다시
```

**전부 찍지 않는 까닭** · 시간이 많이 들고, 놀란 자리만 남겨야 사람이 그것만 보면 됩니다.

**이미 올라간 것도 다시 훑는 까닭** · 2026-09-20 에 만든 검사를 새 영상에만 걸어서 이미 올라가 있던 깨진 영상을 사흘 동안 못 잡았습니다.

## 9 번 · 세션들이 서로 따라가는 것

지금 공유면은 `state.json` 하나입니다. 부족합니다.

```
_out/loop/sessions/<이름>.json

  누가        lead · rl · super
  지금 무엇   한 줄
  건 것       PID · 무엇을 · 언제
  막힌 것     있으면
  갱신        시각
```

**세션마다 자기 파일만 씁니다.** 한 파일을 여럿이 쓰면 반드시 덮어씁니다. 읽는 것은 전부 서로 읽습니다.
