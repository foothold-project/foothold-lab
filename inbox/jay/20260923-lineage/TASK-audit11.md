## 2. 결합이 실패했다 · 2 × 2 상호작용

`I = Y(C) − Y(S) − Y(G) + Y(R0)` · iter3000

| 지표 | R0 | S | G | C | I=0 이면 | **실제 I** |
|---|---:|---:|---:|---:|---:|---:|
| stones 진행 (1.0 m/s) · **주 지표** | 1 | 8 | **45** | **17** | 52 | **−35** |

| stones 종합 (1.0 m/s) | 0 | 4 | **24** | 7 | 28 | −21 |
| 48 칸 평균 | 92.79 | 91.79 | **94.19** | **91.69** | 93.19 | −1.50 |

**결합이 두 단독보다도 나쁘고 부모보다도 낮다.** 내가 사전에 적은 예측은
「진행에서 `I > 0`」이었고 **틀렸다.**

## 5. 팀장이 물은 것 · 사실 확인

### 5-1. 발 관련 보상 항목은 **하나뿐이다** `확인됨`

저장 `params/env.yaml` 의 `rewards` 를 전부 펴서 읽었다.

```
track_lin_vel_xy_exp      1.5
track_ang_vel_z_exp       0.75
lin_vel_z_l2             -2.0
ang_vel_xy_l2            -0.05
dof_torques_l2           -0.0002
dof_acc_l2               -2.5e-07
action_rate_l2           -0.01
feet_air_time             0.1      <- 발 관련은 «이것뿐이다»
flat_orientation_l2       0.0
dof_pos_limits            0.0
undesired_contacts        null
```

**`feet_stumble` · `feet_center` · `feet_slide` 는 설정에 «존재하지 않는다».**
가중치를 바꾸는 것이 아니라 **항목을 새로 만들어야 한다.**

### 5-2. 횡보와 후진은 **학습에 없다** `확인됨`

```
lin_vel_x   (0.4, 1.5)     최소가 +0.4 다 -> «후진이 닫혀 있다»
lin_vel_y   (0.0, 0.0)     -> «횡보가 완전히 닫혀 있다»
ang_vel_z   (-1.0, 1.0)    회전은 열려 있다
```

관측으로 잰 것은 `20260924-observe/backward`(`--command_vx -1.0`) 와
`20260924-observe/sweep`(난이도 0.1/0.3/0.7/0.9) 둘이고,
**`v2b-r` iter2500 한 시점에만** 있다. **횡보는 잰 적이 없다.**

## 6. 의뢰 · 답할 것

1. **지금까지 일반화가 가장 좋은 모델은 무엇인가.** 「48 칸 평균이 최고」와
   「관문을 넘었다」와 「미경험 지형에서 강하다」는 서로 다른 물음이다.
   각각에 대해 답하고, 하나를 골라야 한다면 무엇을 왜 고르는지 적어라.
   시드 42 와 43 이 갈린 것을 어떻게 다뤄야 하는가.

2. **다음 두 슬롯에 무엇을 걸어야 하는가.** 후보를 아래에 적었다. 순서와
   까닭을 근거로 정하고, 내가 빠뜨린 후보가 있으면 더하라.

   | 후보 | 무엇을 묻나 | 비용 |
   |---|---|---|
   | (가) 발 체공 0.1 · 시드 44 | 42 와 43 중 어느 쪽이 전형인가 | 3.5 시간 |
   | (나) 발 체공 0.03 또는 0.3 | 꼭짓점을 더 좁힌다 | 3.5 시간 |
   | (다) `feet_stumble` 항목 신설 | MARG 의 둘째 발 보상 | 구현 + 3.5 시간 |
   | (라) `feet_center` 항목 신설 | MARG 의 셋째 발 보상 | 구현 + 3.5 시간 |
   | (마) 횡보 `lin_vel_y` 개방 | 관측 항목을 «학습» 으로 | 3.5 시간 |
   | (바) 후진 `lin_vel_x` 하한 내리기 | 같음 | 3.5 시간 |
   | (사) 관측 항목 전체를 일곱 판에 재기 | GPU 만 쓰고 학습 없음 | 수 시간 |
   | (아) 표준편차 log 전환 | 폭주 구조 제거 | 구현 + 3.5 시간 |

3. **`feet_stumble` 과 `feet_center` 를 어떻게 구현해야 하는가.** IsaacLab 에
   이미 있는 `mdp` 함수가 있는가, 새로 써야 하는가. MARG 원문의 정의와
   우리 센서·접촉 설정으로 가능한 형태를 적어라. 가중치의 첫 점도 제안하라.

4. **횡보와 후진을 «학습에» 열면 무엇이 위험한가.** 명령 분포가 바뀌므로
   전진 1.5 m/s 경험이 줄어든다. 48 칸·9 칸 관문에 어떤 회귀가 예상되는가.
   연다면 한 번에 둘을 열 것인가 하나씩인가.

5. **관측 항목을 판정에 넣어야 하는가.** 팀장이 「관측 항목도 좋아졌다면
   좋은 부분」이라고 했다. `CRITERIA.md` v1.4 의 관문을 바꾸지 않으면서
   관측을 최종 모델 선택에 쓰는 방법이 있는가. 관문을 바꿔야 한다면
   v1.4 4 절의 변경 절차를 어떻게 밟는가.

6. **결합 실패를 어떻게 기록해야 하는가.** 「두 개입이 서로 깎는다」까지
   말할 수 있는가, 아니면 더 좁혀야 하는가. 그리고 이 결과가 앞으로
   「좋은 것들을 합치는」 시도 전체에 어떤 규칙을 세우게 하는가.

7. **전체 흐름 점검.** 지금까지 일곱 판이 「가설 하나 -> 근거 -> 단계적
   개선」으로 이어졌는가. 끊긴 자리가 있으면 무엇인가. 그리고 남은 예산으로
   **최적 모델에 닿는 가장 짧은 경로**를 적어라.
