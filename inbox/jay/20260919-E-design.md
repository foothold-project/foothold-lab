## 3. 왜 그 값인가

### 3-1. `heading` (-0.5, +0.5) · 노출을 되찾는다

gap 은 +x 에만 있고 리셋이 로봇을 +x 를 보게 세운다 (`gap_env_cfg.py:81`) `확인됨`.
±0.5 rad = **±28.6도** 다. 이 안에서는 틈을 **거의 직각으로** 만난다 (건너야 할 거리가 `w/cos 28.6°` = 1.14 `w`).

**0 으로 고정하지 않는 이유.** 고정하면 heading 오차가 늘 0 이라 요 출력이 다시 0 이 된다. **v1 을 다른 방법으로 재현하는 것**이다. ±0.5 를 남겨 **어긋난 것을 스스로 되잡게** 한다.

### 3-2. `rel_heading_envs` 0.75 · **rl 이 잡은 위험을 이것으로 푼다**

**rl 세션 지적** `확인됨`: `heading` 을 ±0.5 로 줄이면 요레이트 명령의 **크기**가 같이 줄어든다.

```
wz = clip(0.5 × heading_error, ang_vel_z 범위)
```

| | 리셋 직후 최대 heading 오차 | 그때 `|wz|` | ±1.0 클립 |
|---|---:|---:|---|
| D | 3.19 rad | **1.60** | 포화 |
| heading 만 좁힌 판 | 0.55 rad | **0.28** | **한 번도 안 닿음** |

**손잡이는 열려 있는데 그리로 들어오는 신호가 D 의 1/3.6 이 된다.** D 가 유일하게 이긴 rails 를 같이 잃을 수 있다.

**소스를 읽어 다른 길을 찾았다** `확인됨`.

```python
# _resample_command · 전 환경
vel_command_b[env_ids, 2] = r.uniform_(*self.cfg.ranges.ang_vel_z)     # ← 직접 요 명령
if self.cfg.heading_command:
    self.heading_target[env_ids]  = r.uniform_(*self.cfg.ranges.heading)
    self.is_heading_env[env_ids]  = r.uniform_(0.0, 1.0) <= self.cfg.rel_heading_envs

# _update_command · heading 환경만
env_ids = self.is_heading_env.nonzero(as_tuple=False).flatten()
vel_command_b[env_ids, 2] = clip(0.5 * heading_error, *ranges.ang_vel_z)
```

> **요 명령은 전 환경에 먼저 뽑히고, `is_heading_env` 인 것만 heading 값으로 덮어써진다.**
> **곧 `rel_heading_envs` 를 1.0 미만으로 두면, 나머지 환경은 `ang_vel_z` 범위에서 직접 뽑은 ±1.0 짜리 요 명령을 그대로 받는다.**

| | 비율 | 받는 요 명령 | 맡는 일 |
|---|---:|---|---|
| **heading 환경** | **75 %** | `clip(0.5 × ±0.5)` → 최대 0.28 | **gap 을 바라보고 건넌다** |
| **직접 요 환경** | **25 %** | `uniform(-1.0, +1.0)` **범위 전체** | **요 제어를 지킨다 (rails)** |

**노출과 요 크기가 더 이상 한 손잡이를 다투지 않는다.** 이것이 D 에도 v1 에도 없던 자유도다.

**0.75 인 이유.** gap 노출은 v1(실질 100 %)과 D(실질 절반 이하·비스듬) 사이에서 v1 쪽에 붙여야 하고, 요 신호는 D 가 준 크기를 유지할 최소 비율이 필요하다. **0.75 / 0.25 는 그 절충이며 유도된 값이 아니다** `추측`. 판정 뒤 조정할 손잡이로 남긴다.

### 3-3. `lin_vel_x` 하한 0.4 · **정확히 유도된다** `확인됨`

앞서 0.3 을 제안했으나 **근거가 없는 임의값이었다.** rl 이 커리큘럼에서 유도했다.

```
move_up   = distance > size[0] / 2                  = 4.0 m      (명령과 무관한 고정값)
move_down = distance < |cmd_xy| × T × 0.5 = vx × 10.0 m          (명령에 딸림)
move_down *= ~move_up
```

`size` = (8.0, 8.0) · `T` = 20.0 s · `lin_vel_y` = 0 이라 `|cmd_xy|` = `vx` `확인됨`.

| `vx` | 강등 문턱 | 승급 문턱 | **「그대로」 띠** |
|---:|---:|---:|---:|
| 0.20 | 2.0 m | 4.0 m | **2.0 m** |
| 0.30 | 3.0 m | 4.0 m | **1.0 m** |
| **0.40** | **4.0 m** | **4.0 m** | **0** |
| 1.00 | 10.0 m | 4.0 m | 0 |

```
포화 하한 = (size_x / 2) / (T × 0.5) = 4.0 / 10.0 = 0.40 m/s
```

**0.4 아래에서는 승급도 강등도 안 되는 띠가 생긴다.** `vx` 0.3 이면 3.0 ~ 4.0 m 를 간 환경이 **못 갔는데도 그 자리에 남는다.** 명령은 10 초마다 재표집되고 커리큘럼은 **그 순간의 명령**을 보므로, 하한이 0.4 면 **어느 환경도 띠에 안 들어간다.**

> **근거는 이 하나로만 적는다.** 응답곡선(추종비)도 우연히 비슷한 값을 가리키지만 **그 자료는 못 쓴다.** `ramp` 가 20 초에 0 → 1.5 를 한 번 훑는 것이라 낮은 명령 지점은 **출발 직후 가속 중**이고, 「저속을 못 따라간다」인지 「아직 못 붙었다」인지 안 갈린다 `미확인`. **근거가 둘인 것처럼 쓰지 않는다.**

## 5. 판정과 분기

### 5-1. 판정 기준 · 순서를 뒤집는다

**1 순위는 「안 무너지는 것」이다.** 앞 판까지 gap 회복을 앞에 놓았는데 팀장 지시로 바꾼다.

| 순위 | 무엇 | 선 |
|---|---|---|
| **1** | **축 1 에서 v1 대비 진짜 하락 0** | **이것이 통과선이다** |
| 2 | 축 2 에서 D 수준 유지 | 9 칸 중 8 칸 이상 |
| 3 | gap 회복 · rails 유지 · 저속 확인 | **보너스** |

> **gap 이 덜 회복돼도 아무것도 안 무너졌으면 성공이다.** D 는 gap 을 잃고 rails 를 얻었고, **그 교환 자체가 문제였다.** E 의 목표는 교환 없이 가는 것이다.

문턱과 계산법은 그대로다. **두 축의 AND** 다. 축 1 은 `models/foothold-v1.json` 칸 값을 속도별로, 축 2 는 NVIDIA 원본 실측 문턱을 그대로 쓴다.

**Wilson 95 % 신뢰구간으로 판정한다.** 100 판이라 ±10 퍼센트포인트는 우연일 수 있다. **구간이 겹치면 「달라졌다」고 말하지 않는다.** 겹치는 칸은 통과도 미달도 아닌 `null` 이다.

> **문턱 여유(tolerance)를 새로 만들지 않는다.** D 판정에서 `axis1_tolerance_pp: 3.0` 이 들어갔다가 Wilson 으로 다시 셌고, **「6 칸 미달」이 「진짜 하락 4 칸」으로 바뀌었다.** 같은 일을 반복하지 않는다.

### 5-1-1. 저속 고정 시나리오를 평가에 넣는다 (팀장 승인)

**하한을 0.4 로 올리는 대가를 이번에 처음으로 잰다.**

지금 가진 `ramp` 는 20 초에 0 에서 1.5 를 **한 번 훑는** 것이라 낮은 명령 지점이 **출발 직후 가속 중**이다. 「저속을 못 걷는다」인지 「아직 못 붙었다」인지 안 갈린다 `미확인`.

| | |
|---|---|
| 무엇 | **낮은 명령을 고정해 놓고 오래 걷는다** |
| 명령 | `vx` 를 **0.1 · 0.2 · 0.3 · 0.4** 각각 고정 · `wz` 0 · 평지 |
| 길이 | 정상상태를 볼 수 있게 충분히 (가속 구간을 지표에서 뺀다) |
| 정책 | **NVIDIA 원본 · v1 · D · E 넷** |
| 지표 | 추종비(실속도/명령) · 낙상률 · 잔류속도 · 관절 목표각 변화 |
| 시간 | 약 10 분 |

**판정에는 넣지 않는다.** 문턱이 없고 원본도 약한 자리라 **관측만 한다.** 결과가 「하한 0.4 가 비용이었나」에 답하고, 비용이면 그것은 **하한을 내려서가 아니라 커리큘럼을 고쳐서** 푼다(0-1-1 · 8 절).

### 5-2. 분기

| 결과 | 다음 |
|---|---|
| **gap 회복 + rails 유지 + 축 2 유지** | **E 채택.** 갤러리에 계보 넷으로 올리고 배포 검토 |
| gap 회복 · **rails 하락** | 직접 요 환경 비율을 25 % → 40 % 로. 한 손잡이만 움직인다 |

## 6. 실행 · **codex 세션으로 넘긴다**

**팀장 지시다.** rl 세션이 직접 돌리지 않는다. **rl 안에서 codex 세션을 열어 지시하고, 난이도에 따라 모델을 정하고, 실제로 착수했는지 반드시 확인한다.**

### 6-1. 모델 배정

| 작업 | 모델 | 왜 |
|---|---|---|
| **환경 설정 파일 작성** (`gap_e_env_cfg.py`) · 등록 | **sol** | 정해진 값을 정해진 자리에 넣는 일이다 |
| **학습 실행 · 관문 확인** | **sol** | 명령이 정해져 있다 |
| **평가 두 축 · Wilson 판정 · 매니페스트** | **astra** | 판정이 걸려 있고 검증이 필요하다 |
| 영상 · 갤러리 산출물 | terra | 정해진 규격대로 |

### 6-2. 착수 확인 · **지시로 끝내지 않는다**

오늘까지 **조용한 실패가 다섯**이었다. 전부 오류를 내지 않았다.

```
1  --resume 무시                19 iter 를 무작위 초기화로
2  max_iterations 100           의도는 1500
3  --terrains 기본 flat         평가가 한 판도 안 돔
4  probe_manifest.json 덮어씀   turn 요약이 날아감
5  영상 폴더가 성적 폴더 덮을 뻔
6  codex CLI 업데이트 화면       워커 넷이 지시를 못 받고 죽음 (3DGS 세션)
```

**그러므로 건 뒤 1 분 안에 되읽는다** (설계안 9-0 · 9-0-1 절).

| 언제 | 무엇을 되읽나 | 어긋나면 |
|---|---|---|

## 7. 산출물 규격 · **사이트 갤러리에 바로 들어가게 만든다**

site 세션이 준 규격이다 `확인됨`. **나중에 맞추면 두 번 일한다.**

```
gallery/E/
  manifest.json    schema "foothold-gallery-index/1"
  release.json     사람이 적는 한 줄 (headline · report · note)
  clips/*.mp4      LFS 추적됨
  posters/*.jpg    클립마다 1 장
```

`manifest.json` 필수 필드: `version` · `built_at` · `evaluated_at` · `main_model` · `difficulty` · `models`(딕셔너리라 계보 몇 개든 담긴다) · `protocol` · `counts` · `evaluations`(지형|모델|속도) · `clips`(sha256 포함).

> **`protocol.eval_spec_version` 을 반드시 2 로 넣는다.** 안 박으면 「이 판이 어느 규격으로 쟀는지」가 나중에 `미확인` 으로 빠진다.

판 목록 재생성: `python sim/eval/gallery_versions.py --root <site>/gallery`.
**색인에 적힌 컷이 `clips/` 에 전부 있어야 그 판이 목록에 잡힌다.** 덜 올라간 판은 자동으로 숨겨진다.

### 7-1. 영상 · **이번에는 판정과 맞춘다**

D 에서 **판정 전에 컷을 정해** `rails 0.5`(겹침 칸)를 찍고 진짜 상승인 `rails 1.0` · `1.5` 를 못 찍었다. **반복하지 않는다.**

> **영상은 Wilson 판정이 나온 뒤에 고른다.** 진짜 하락 칸 전부 · 진짜 상승 칸 전부 · 축 2 시나리오 셋.

같은 시드 · 같은 지형 인스턴스 · 같은 명령에서 **정책만 교체**. `num_envs 1` · 추적 카메라 · 겹쳐 보이는 그림 금지.
**영상은 성공률이 아니라 예시라고 매니페스트와 화면에 적는다.**

**밀린 것 둘을 같이 찍는다** · `rails 1.0` · `rails 1.5` 의 v1 대 D. 10 분이면 된다.

## 9. 「높이 스캔이 보상에 안 쓰인다」는 아직 설계되지 않았다

**팀장 물음에 정직하게 답한다. 이름만 붙여 뒀고 방법은 논의된 적이 없다.**

### 9-1. 지금 상태

관측에는 높이 스캔이 있다 (`height_scan_with_gap` · `miss_value` 1.0). 보상은 NVIDIA rough 원본 그대로이고 **높이 스캔을 쓰는 항이 하나도 없다.** 속도 추종 둘, 자세·토크·가속·행동변화 벌점, `feet_air_time`, 접촉 벌점, 관절 한계.

> **곧 「앞에 틈이 보이니 속도를 올리고 몸을 낮춘다」가 이득이 되는 자리가 없다.** 지금 gap 을 건너는 것은 **「1.0 m/s 로 가라」를 수행하다 부수적으로 일어나는 일**이다.

### 9-2. 후보 셋 (전부 미설계 · 검토 필요)

| # | 무엇 | 장점 | 위험 |
|---|---|---|---|
| **가** | **커리큘럼 지표 교체** (F). 「건넜는가」로 승급 | 보상을 안 건드려 기존 성적과 비교 가능 | 커리큘럼만으로 행동이 바뀌는지 미지 |
| **나** | **전진 진척 보상**. 틈 가장자리를 넘어선 만큼 보상 | 목표가 명시적이 된다 | 보상항 추가는 **기존 성적 전부를 재비교 대상으로 만든다** |
| **다** | **발 놓임 벌점**. 높이 스캔이 빈 곳이라 말한 자리에 발을 디디면 벌점 | 스캔을 **직접** 쓴다. 팀장이 말한 「바라보고 건넌다」에 가장 가깝다 | 스캔 빗나감(`miss_value` 1.0) 처리와 얽힌다 |

**셋 다 보상 지형을 바꾸므로 v1 · D · E 와 직접 비교가 안 된다.** 그래서 **E 판정이 끝난 뒤에 착수한다.** 먼저 하면 무엇이 좋아졌는지 못 가른다.

**속도 조절 · 높이 조절은 이 목표의 결과로 나와야 한다.** 명령으로 주입하면 그것은 또 하나의 「명령 좁히기」다.
