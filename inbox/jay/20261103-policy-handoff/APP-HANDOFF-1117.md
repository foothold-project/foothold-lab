# 앱 전달 사항 (11/17 · 정본 3 기준)

## 0. 먼저 한 줄

**지금 앱은 「순정 보행 로봇을 안전하게 조종하는 리모컨」 까지 됐다.** 다음 단계는 그 리모컨 뒤에 **우리 보행 정책**과 **HiPAN 주행층**을 Orin 위에 끼우는 것이다.

## 3. 앞으로 앱이 준비할 것

### 3.1 두 층을 잇는 모양

로봇 안 (Orin) 에서 위에서 아래로 이렇게 흐른다.

| 층 | 무엇 | 빠르기 | 들어가는 것 → 나오는 것 |
|---|---|---|---|
| 앱 | 조이스틱 · 목표 · STOP | 사람 | 손 → 속도 명령 또는 목표 |
| 주행층 (HiPAN ONNX) | 목표까지 길 고르기 | 10 Hz 쯤 (가정) | 깊이 영상 + 목표 → `vx · vy · wz` |
| 명령 정리기 | 허용 범위로 자르기 · STOP · 끊김 정지 | 50 Hz | 속도 명령 → 잘린 속도 명령 |
| 보행층 (START ONNX) | 다리 움직이기 | **50 Hz** | 몸 상태 + 깊이 + 속도 명령 → 관절 12 개 목표 |
| 모터 보드 | 관절 구동 | 500 Hz | LowCmd |

- 조이스틱을 쓸 때는 주행층을 건너뛰고 명령 정리기로 바로 간다.
- 지금 앱의 순정 길 (SportClient.Move) 은 **그대로 두고 비상 · 비교용으로 남긴다.** 정책 전환은 로봇을 세운 뒤에만 한다 (43 §5-4).

### 3.2 보행 ONNX (START) 계약

브라우저 시뮬이 이미 쓰는 판 (`start-demo-adapter.js`) 이 좋은 출발점이다. 지각 (GRU 둘) 과 정책이 한 파일에 들어 있다.

| 칸 | 모양 | 뜻 · 주의 |
|---|---|---|
| `obs45` | 1 × 45 | 몸 상태 (자세 · 각속도 · 관절 · 직전 행동 · **속도 명령**) |
| `hist` | 1 × 10 × 45 | 지난 10 칸 기록 |
| `depth2` | 1 × 2 × 60 × 60 | 깊이 두 장 (D435i · 10 Hz 갱신) |
| `h_prop` · `h_terr` | 1 × 128 씩 | **지각 GRU 상태**. 나온 값을 다음 칸에 다시 넣는다. 넘어짐 · 재시작 때 0 으로 비운다. |
| `depth_tick` · `first_after_reset` | 참 / 거짓 | 이번 칸에 새 깊이가 왔나 · 재시작 직후인가 |
| 출력 `action` | 1 × 12 | 관절 목표 (기본 자세 기준 차이) |
| 출력 `recon_map` | 1 × 32 × 16 | 다시 만든 지형 지도 (화면 표시용) |

정본 3 (11/17) 으로 정해진 것 · 남은 것:
- **파일 판 (정해짐)**: 새 판은 `start-m15500-app/` (정본 3 = EX-42 E1F `model_250.pt` · 누적 15,500 update) 이다. 앱 시뮬이 지금 쓰는 m13000 을 이것으로 바꾼다. 받는 법 · sha · 바꿀 곳은 [`HANDOFF-START-m15500-CANON3.md`](HANDOFF-START-m15500-CANON3.md) 1 절. ONNX 입출력은 위 표와 같고 m13000 과도 같다.
- **속도 추정 보정 b (정해짐 · 그래프 안)**: 학습 판에는 「지각이 추정한 앞 속도」 를 느린 띠 (0~0.3 m/s) 에서 조금 낮추는 보정이 있다 (정본 3 은 b = 0.010 m/s). 이 식은 **ONNX 안에 넣었다.** 앱은 더하지 않는다 (더하면 두 번 걸린다).
- **입력 수 (정리됨)**: 98 은 ONNX 안쪽 정책의 입력 수다 (몸 45 + 지각 추정 51 + 자세 명령 2 · 자세 명령은 ONNX 안에서 0 고정). 앱이 넣는 것은 위 표의 아홉 입력 그대로다.
- **돌리는 곳 (남음)**: 이번 묶음은 브라우저 · CPU 용으로 확인했다 (onnxruntime CPU 에서 PyTorch 와 최대 차이 7.5e-6). 실기는 Orin GPU (onnxruntime-gpu 또는 TensorRT) 에서 **50 Hz 를 지켜야 한다** (4 절 점검 5). 같은 ONNX 파일을 Orin 에서 돌려 보는 것은 아직 안 했다.
- **알고 가는 약점**: 계단을 올라 멈췄다 다시 갈 때 일부가 한쪽으로 돈다 · 듬성한 지형 (징검돌 · 틈) 은 아직 배우지 않았다 (`HANDOFF-START-m15500-CANON3.md` 4 절).

### 3.2a 목표 찍기 · 조이스틱의 속도는 앱이 고정하지 않는다 (팀장 11/16 23:4x · 원장 95a0f82b)

**한 줄:** 앱이 START 모드에서 걷는 속도를 0.4~0.8 m/s 로 고정해 둘 필요가 없다. 정책이 「속도 명령 (vx · vy · wz) 을 그대로 따라 걷고 도는 능력」 을 배웠기 때문이다.

| 무엇 | 지금 앱 (dev 1afae1ed 기준 · 팀장 설명) | 바꿀 것 | 근거 |
|---|---|---|---|
| 조이스틱 · 목표 찍기 때 속도 | 0.4~0.8 m/s 로 고정 | 고정을 풀고 명령 범위 안 아무 값이나 준다 (느린 0.1 m/s 포함) | EX-42 E1 · E1F 가 저속 0.1~0.3 m/s 와 깃발 (방향이 계속 바뀌는 vx · vy · wz) 을 학습. 정본 3 은 전진 0.1 m/s 명령에 평균 0.094 m/s 로 걷는다 (시뮬 64 대 가운데 57 대가 기준 안 · 정답 지도) |
| 목표 지점 → 속도 명령 바꾸기 | 앱 안 하드 코딩 | 시뮬 학습이 쓴 식을 그대로 옮긴다: `foothold_s2/commands/mixed_core.flag_step` (몸 기준 목표 방향 → vx · vy, wz = clip(방향 각, ±1 rad/s) · 속도 v < 0.3 이면 제자리 회전) | 정책은 이 식이 만든 명령으로 학습했다. 식이 같으면 시뮬에서 배운 움직임이 앱에서 그대로 나온다 |
| 움직이는 모양 | - | 「먼저 돌고 직진」 이 아니라 「걸으며 돈다」 (vx · vy · wz 를 동시에 줌). 깃발 90 도 출발 때 약 1.8~2.0 초에 몸이 목표 쪽을 본다 (CPU 실측 64/64) | planner 23:13 · 22:23 깃발 돌려 재기 |

- 학습이 다룬 명령 범위는 [`HANDOFF-START-m15500-CANON3.md`](HANDOFF-START-m15500-CANON3.md) 1-5 의 표에 있다 (전진 0.1~1.5 · 후진 −1.3~−0.2 · 옆 0.1~0.8 · 제자리 회전 0.15~1.5 · 걸으며 회전 wz 0.1~1.0 과 vx 0.3~1.2). 범위 밖 값은 앱이 자른다.
- 모드 1 (석헌 AME-2) 은 다르다: 목표 지점 (몸 기준 x · y · 방향 차) 을 받는 정책이라 앱의 기존 A* 경로 (foothold-app 안) 를 그대로 쓴다. 위 표는 모드 2 (START 보행 + 속도 명령) 에만 해당한다.
- 이 절은 팀원 코드를 나중에 다시 손볼 때 사람 · Agent 모두 이 표 하나로 판단하게 쓴 것이다. 바꾼 뒤에는 이 표에 커밋 sha 를 적는다.

### 3.3 HiPAN ONNX (주행층)

| 칸 | 내용 | 상태 |
|---|---|---|
| 입력 | 깊이 영상 + 목표 (지도 틀 `x · y · yaw` 또는 몸 기준 상대 위치) | 정확한 모양은 **lead · planner 가 정함 (미정)** |
| 출력 | `vx · vy · wz` (보행층 명령과 같은 단위) | 보행층 앞 「명령 정리기」 로 들어감 |
| 앱이 할 일 | 목표 찍기 화면 (시뮬 A* 화면을 실기용으로) · 주행 상태 (가는 중 · 도착 · 실패 · 취소) 표시 · 언제든 STOP | 화면은 시뮬에 이미 있음 |

### 3.4 Orin 연결 서버

- 이미 있는 agent (`fh-phone/1` · 승인 표식 · DDS) 를 그대로 쓴다. 여기에 「정책 노드」 하나를 붙인다 (ONNX 두 개를 돌리고 LowCmd 를 낸다).
- 정책 노드가 앱에 새로 보낼 것: 지금 정책 이름 · 판 sha · **허용 범위표** · 추론 주기 (실측 Hz) · 지각 GRU 초기화 횟수.
- 주의 (코드에서 확인): agent 는 `CYCLONEDDS_URI` 나 `LD_LIBRARY_PATH` 가 잡혀 있으면 SDK 를 거절한다 (`go2_direct/sdk.py:49`). 정책 노드의 GPU 실행 환경과 부딪히지 않는지 먼저 본다.
