# inbox/meang/AGENTS.md · 맹라현 에이전트 규제

**매 작업 시작 전에 이 파일을 읽고 시작한다.** 읽지 않고 쓰지 않는다.

그다음 루트 `AGENTS.md` 공통 규칙만 읽는다. 루트 파일에는 **한 줄도 쓰지 않는다.**
여기는 **맹라현 규칙만** 두는 곳이다. 남이 만든 파일은 건드리지 않는다.

작업 브랜치: `feature/research-meang`
쓰는 폴더: `inbox/meang/`만. `docs/`는 직접 고치지 않는다.
PR: 사용자가 «피알해줘» 또는 «PR 열어»라고 한 뒤에만 연다.

---

## 1. 아침(업무 시작)에 할 일

1. `origin/main`을 가져와서 **내 브랜치에 병합**한다. (메인을 내 브랜치가 덮지 않는다. 메인을 내 쪽으로 가져온다.)
2. 충돌이 없으면 병합을 마친다.
3. 사용자에게 **짧게 요약**한다.
   - main에 새로 들어온 커밋·파일
   - 새로 생긴 이슈 (목록을 열 수 있으면)
   - 규칙이 바뀐 곳

이슈 목록 API가 막혀 있으면, 막혔다고 말하고 커밋 요약만 한다. 없는 이슈를 지어내지 않는다.

---

## 2. 커밋하기 전에도 같다

내 브랜치에 커밋·푸시하기 전에:

```bash
git fetch origin main
git merge origin/main
```

메인의 최신을 **내 브랜치로 가져와서 합친다.**
`main`에 직접 push 하지 않는다. 새 브랜치를 만들지 않는다.

---

## 3. 충돌이 나면 (반드시 멈춘다)

에이전트가 혼자 고르지 않는다. **설명하고 멈춘다.**

초등학생에게 말하듯:

> 같은 공책 같은 줄을 두 사람이 다르게 적었어요.
> 내가 마음대로 지우면, 한쪽 글이 사라져요.
> 그래서 지금은 합치기를 멈춰요.

그다음 사용자에게 **고를 수 있게** 알린다.

| 선택 | 뜻 |
|---|---|
| 1. 메인 쪽 | 팀 공용 최신 글을 남긴다. 내 쪽 그 줄은 버린다 |
| 2. 내 브랜치 쪽 | 내가 적어 둔 글을 남긴다. 메인 그 줄은 버린다 |
| 3. 둘 다 살릴 방법 | 어떻게 섞을지 사용자가 한 줄로 말한다 |
| 4. 취소 | 이번 합치기를 되돌리고, 파일은 합치기 전으로 |

사용자가 1·2·3·4 중 하나를 말하기 전에는 `git add`로 충돌을 끝내지 않는다. 커밋하지 않는다.

---

## 4. 확인용 한 줄

충돌 난 파일을 고치기 전: «사용자가 이번 메시지에서 1·2·3·4를 골랐나?»
아니오 → 설명만 하고 멈춘다.
