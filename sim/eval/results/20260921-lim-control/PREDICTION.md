## 1. **못 확인한 것** · 숨기지 않는다 `미확인`

**`control_3000` 의 `env.yaml` 이 없다.** 받은 `params/` 는 `rails10` 것
하나뿐이다. 그래서 **「대조판의 지형이 v1 과 같다」를 내가 «읽어서» 확인하지
못했다.**

지금 근거는 이것뿐이다.

- 실행 이름 `0914_rough7_control` (`rough7` = v1 의 지형 일곱 종)
- `infos` 에 `arm` 키가 **없다** (`rails10` 에는 `"rails"` 가 있다)
- 리드가 그렇게 전해 주었다

**약한 반증도 적어 둔다** · `terrain_types` 가 둘 다 고유값 20 이고
`terrain_levels` 평균이 6.00 대 5.96 으로 거의 같다. **이 둘로는 지형 집합을
못 가른다** (타일 열 수라서 지형 종류 수와 다르다).

> **이 판의 결론은 「대조판 지형 = v1 지형」이라는 전제 위에 선다.**
> `control_3000` 의 `params/env.yaml` 을 받으면 **그때 확인하고 이 절을
> 고친다.** 못 받으면 결론에 이 단서를 붙인 채로 둔다.

### **덧 (2026-09-21 02:30) · 받아서 확인했다** `확인됨`

`params_control/` 을 받아 **내가 직접 읽었다.** 위 본문은 **안 고친다** ·
「이 자료로는 못 가른다」를 적어 둔 기록이 남는 편이 낫다.

```
control 의 config_diff.json 항목 수      1 개   (log_dir 뿐)
v1 지형 == control 지형                  True   (여덟 칸 전수 비교)
v1 명령 == control 명령                  True
control 명령 == rails10 명령             True
```

**그래서 전제가 «전언» 에서 «쟀다» 로 바뀌었다.** 세 판이 한 줄로 선다.

| 대비 | 무엇이 다른가 | 무엇을 가르나 |
|---|---|---|
| v1(1500) -> control(3000) | **iter +1500 만** | **학습량** |
| v1(1500) -> rails10(3000) | iter +1500 **과** 지형 | 학습량 + 지형 |
| **control(3000) -> rails10(3000)** | **지형만** (`rails` 0.10 추가 · 나머지 재분배) | **지형** · 깨끗하다 |

`parent_sha256` 동일 · `completed_additional_updates` 1500 동일은 앞서
체크포인트에서 확인했다. **이제 깨끗한 단일 변수 대비가 둘이다.**

## 2. 무엇을 가르나

세 판의 **명령 여섯 칸이 글자 하나까지 같다.** 처음 이 절을 쓸 때는 v1 과
rails10 만 확인했고 control 은 전언이었는데, **1 절의 덧에서 셋 다 읽어
확인했다.**

```
갈리는 것   학습 지형 하나뿐   (control 대 rails10 · «쟀다»)
같은 것     명령 · 부모 · 추가 학습량(1500)
```

| 결과 | 읽는 법 |
|---|---|
| `control` 이 `rails10` 과 **비슷하다** | 축 2 개선은 **학습량**이다. 지형과 무관 |
| `control` 이 **뚜렷이 낮다** | 축 2 개선은 **지형**이다 (`rails` 를 넣은 것) |
| `control` 이 **뚜렷이 높다** | `rails` 지형이 축 2 를 **깎았다.** 예상 밖 |

**둘 다 v1(0 / 7)보다 높으면** 「학습량이 올렸다」가 가장 단순한 설명이다.

## 3. 예측 · **판정 전에 고치지 않는다**

### 3-1. `control_3000` 축 2

| 항목 | v1 | rails10 **2950** | **예측 (control 3000)** |
|---|---:|---:|---|
| `stop` 낙상 | 0.203 | 0.406 | **미달** (0.1 이상) |
| `hold` 낙상 | 0.078 | 0.000 | **통과** (0.03 이하) |
| `hold` 잔류속도 | 0.0240 | 0.0011 | **통과** |
| `hold` 목표각변화 | 0.1258 | 0.0017 | **통과** |

| **9 칸 통과** | **0 / 7** | **4** | **3 ~ 5** |

**리드와 같은 쪽이다** · 축 2 는 평지에서 재므로 지형이 직접 안 걸린다.

**그런데 근거가 약하다는 것도 적어 둔다.** 어제 H 에서 **고리 지형이

움직인 전례가 이미 있다.** 그래서 「지형」 갈래를 닫지 않는다.

`wz -1.00` 만 **모름**으로 둔다 · rails10 이 0.045 에서 0.508 로 뛴 칸인데
**왜 뛰었는지를 모르므로** 대조판이 어느 쪽일지 못 고르겠다.

### 3-2. `rails10_3000` 대 `rails10_2950`

**50 iter 차이다.** 석헌 문서에 **2750 에서 `gap` 이 21 % 까지 떨어졌다가
3000 에서 90 % 로 회복**한 기록이 있다니 이 계열은 체크포인트마다 출렁인다.

**예측 · 축 2 는 4 칸 근처로 비슷하게 나온다** (3 ~ 5). 축 2 는 평지라
험지 성적만큼 안 출렁일 것으로 본다. **빗나가면 「축 2 도 50 iter 로
출렁인다」는 뜻이고 그러면 한 체크포인트의 축 2 숫자를 그 모델의 성적으로
읽으면 안 된다.**

### 3-3. `rails10_3000` 축 1 · **처음 잰다**

이 계열의 축 1 을 우리 하네스로 재는 것은 처음이다. v1 정답지와 견준다.

**`rails` 가 안 오르면** 「지형에 넣어도 그 지형이 안 는다」이고 그것이 가장

## 4. 각주 · 두 모델 다 붙는다

> **`rel_standing_envs` 0.0 · `ang_vel_z` (0, 0) · `lin_vel_x` (0.5, 1.5).**
> `stop` · `hold` · `turn` · 저속 네 칸은 **학습에서 한 번도 안 본 것을

>
> 거꾸로 **통과하는 칸은 「안 가르쳤는데 된다」**라 더 눈여겨볼 자리다.
