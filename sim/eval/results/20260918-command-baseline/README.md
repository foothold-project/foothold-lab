### 요레이트 추종비

| 명령 `wz` | NVIDIA 원본 | foothold-v1 |
|---:|---:|---:|
| -1.00 | 0.817 | **0.045** |

| +0.50 | 0.520 | 없음 (그전에 낙상) |

**-0.081 은 부호가 반대다.** 왼쪽으로 돌라는 명령에 오른쪽으로 돌았다.
`+` 쪽 두 칸은 그 구간에 닿기 전에 전부 넘어져 값이 없다.

> 시나리오는 `wz` 를 -1.0 · -0.5 · 0.0 · +0.5 · +1.0 순으로 3초씩 준다.
> v1 은 앞 두 칸에서 이미 무너진다.

## 2. 정지 · 「얼음」의 정체 `확인됨`

**멈추기는 한다. 버티기가 안 된다.**

| | NVIDIA | v1 | 배수 |
|---|---:|---:|---:|
| **stop** 정지 도달 (s) | 0.75 | 1.16 | 1.6 |
| **stop** 잔류속도 끝 1초 (m/s) | 0.0021 | 0.0947 | **44.7** |
| **stop** 롤 최대 (도) | 10.3 | **45.6** | 4.4 |
| **stop** 낙상 | 0 / 64 | **13 / 64** | |

| **hold** 롤 최대 (도) | 8.7 | **26.4** | 3.1 |
| **hold** 낙상 | 0 / 64 | **5 / 64** | |

도달 시각만 보면 v1 도 멈춘다(64/64). 문제는 **멈춘 뒤**다.

### 관절 목표각의 시간 변화량

| | NVIDIA | v1 | 배수 |
|---|---:|---:|---:|
| **stop** 끝 1초 (rad/스텝) | 0.0021 | **0.3370** | **164** |
| **hold** 끝 1초 (rad/스텝) | 0.0015 | **0.1258** | **81** |

**「얼음」이 아니다.** 정책 출력이 굳은 것이라면 이 값이 0 으로 수렴해야 하는데,
원본의 **80 ~ 164 배**로 계속 크다. v1 은 서 있으라는 명령에 **쉬지 않고 새
목표각을 내면서 안정점을 못 찾는다.**

굳어서 무너지는 것이 아니라 **떨면서 무너진다.**

> **이 한 줄로 원인을 확정하지는 못한다.** 「출력이 굳었다」는 이 값만으로 말할
> 수 있지만 그 반대는 아니다. 다만 「굳었다」가 **아니라는 것**은 말할 수 있고,
> 그것만으로도 처방이 갈린다.

## 3. 저속 · **예상과 달랐다** `확인됨`

**v1 은 저속을 안 잃었다.**

| 명령 (m/s) | NVIDIA | v1 |
|---:|---:|---:|
| 0.10 | 0.046 | 0.022 |
| 0.20 | 0.077 | **0.187** |
| 0.30 | 0.215 | 0.267 |
| 0.40 | 0.341 | 0.388 |
| 0.50 | 0.495 | 0.491 |
| 1.00 | 0.994 | 1.003 |
| 1.50 | 1.379 | 1.451 |

v1 은 `lin_vel_x` 를 (0.5, 1.5) 로만 학습했으니 0.1 ~ 0.4 는 **학습 범위 밖**인데
원본과 같거나 오히려 낫다. 설계 문서가 G2(저속)를 잃은 능력으로 꼽았는데
**이 측정에서는 안 보인다.**

**둘 다 0.3 아래에서는 명령을 못 따라간다.** 원본도 0.10 명령에 0.046 을 낸다.
저속 추종은 **v1 이 잃은 것이 아니라 원본부터 약한 자리**다.

> **한계.** 이 시나리오는 명령을 0 에서 1.5 까지 20초에 걸쳐 **한 번 훑는다.**
> 각 명령값에서 정상상태에 이르렀는지 확인하지 않았고, 낮은 명령 구간은
> 출발 직후라 아직 가속 중이다 `미확인`. 저속 «보행» 을 제대로 보려면 낮은
> 명령을 고정해 두고 오래 걷는 시나리오가 따로 있어야 한다.

ramp 에서 v1 은 7/64 가 넘어졌고 원본은 0 이다.

## 3-2. 회전의 좌우 비대칭 · **순서 효과가 아니었다** `확인됨`

D 의 `wz +1.00` 추종비가 0.253 으로 문턱(0.40) 아래였다. `turn` 시나리오에서
그 칸이 **맨 마지막**이라 「앞 네 칸이 쌓인 것 아니냐」를 의심했고, 그것을
가르려고 두 판을 더 돌렸다.

| 명령 | `turn` | `turn_rest` | `turn_rev` |
|---:|---:|---:|---:|
| -1.00 | **0.579** | **0.579** | **0.579** |
| -0.50 | 0.439 | 0.428 | 0.527 |
| +0.50 | 0.400 | 0.448 | **0.150** |
| +1.00 | **0.253** | **0.157** | **0.061** |

`+1.0` 이 몇 번째인가: `turn` 5번째 · `turn_rest` 5번째(앞에 쉼) ·
**`turn_rev` 1번째**.

**의심은 틀렸다.** `+1.0` 을 **맨 앞으로** 옮기자 0.253 에서 **0.061 로 더
나빠졌다.** 쉬는 구간을 넣은 판도 0.157 로 나빠졌다. 순서가 원인이면 앞으로
옮길 때 좋아져야 하는데 반대다.

**`-1.00` 이 세 판에서 0.579 로 똑같은 것**이 측정이 안정적이라는 증거다.
흔들리는 것은 `+` 쪽뿐이다.

### 읽는 법

**D 는 요레이트에 진짜 좌우 비대칭이 있다.** `-` 쪽은 자리와 무관하게
0.53 ~ 0.58 로 붙어 있고, `+` 쪽은 0.06 ~ 0.45 로 흔들리며 **일찍 물을수록
나쁘다.**

**왜 그런지는 이 자료로 말할 수 없다** `미확인`. `+` 쪽이 앞선 `-` 회전 뒤에
오면 나아지는 것으로 보아 「이미 한쪽으로 돌던 것을 되돌리는 것」이 쉬운
것일 수도 있고, 학습에서 한쪽 요레이트를 덜 본 것일 수도 있다. 가르려면
`+` 만 단독으로 주는 판이 따로 있어야 한다.

**앞선 판의 「맨 마지막 칸이라 오염됐을 수 있다」는 단서는 물린다.** 재 보니
아니었다.

## 4. 합격선 제안

**원본이 못 하는 것을 D 에 요구하지 않는다.**

| 축 | 제안 문턱 | 왜 |
|---|---|---|
| **회전 낙상** | `turn` 낙상 **10 % 이하** | 원본이 6 % 다. v1 은 100 % |
| **요레이트 추종비** | `wz ±0.5` · `±1.0` 네 칸 전부 **0.40 이상** | 원본 최저가 0.520 이다. 그 아래로 잡되 부호는 반드시 맞아야 한다 |
| **정지 유지** | `hold` 잔류속도 **0.005 m/s 이하** · 롤 최대 **15도 이하** | 원본이 0.0011 · 8.7 도 |
| **목표각 변화 (끝 1초)** | `hold` **0.01 이하** | 원본이 0.0015. 「떨림」이 남으면 여기서 걸린다 |
| **정지 낙상** | `stop` · `hold` 낙상 **3 % 이하** | 원본이 둘 다 0 이다 |
| **저속** | **문턱을 두지 않는다** | v1 이 안 잃었다. D 가 지켜야 할 것이지 되찾을 것이 아니다 |

**문턱은 전부 원본 실측에서 나왔다.** 절대값을 임의로 정하지 않았다.

## 6. 안 잰 것

- **험지에서의 명령 변화.** 전부 평지다. 「험지를 걷다가 멈추기」는 이 폴더에 없다
- **외란 복원.** `push_robot` 을 껐다. NVIDIA Go2 공식 설정도 이것이 꺼져 있어
  두 정책 다 학습한 적이 없다
- **횡이동.** `lin_vel_y` 는 내내 0 이다
- **주행 성적.** 험지 통과는 주행 하네스가 잰다. 이 폴더와 무관하다
