`foothold-site` 는 **여기서 구운 결과의 복사본**이다. site 를 직접 고치지 않는다.
고치면 다음 빌드에 사라진다.

## 굽는 법

```
cd web
python _build/build.py --check --verify --skip-secure
```

암호화 자산(`assets/secure/`)을 **바꾸지 않는 작업**에서는 `--skip-secure` 를 쓴다.
그 자산 자체를 갱신할 때는 빼야 하고, 그때만 조선대 원문이 필요하다.

진짜 배포본을 건드리지 않고 시험하려면 격리 빌드를 쓴다.

```
python _build/build.py --repro --build-time 2026-09-13T12:00:00+09:00 --out <빈 폴더>
```

## 무엇이 어디에

| 자리 | 무엇 |
|---|---|
| `_build/` | 빌드와 관문 (python 83) |
| `_build/roots.py` | **경로를 답하는 한 곳.** 아래 「왜 옮겼나」 참조 |
| `_src/*.base.html` | 손으로 쓰는 페이지 원본 8장 |
| `*.html` | 생성된 페이지 |
| `assets/` | 그림 · 영상 · 암호화 자산 |
| `02_team` · `04_plan` | 빌드가 읽는 팀 문서와 계획 |

문서 정본(`docs/`)은 **이 저장소의 형제 폴더**다. 빌드가 거기서 읽는다.

## 왜 옮겼나 (2026-09-13)

전까지 이 트리는 `MAI_UNIVERSE/03_PROJECTS/doyak-final/05_deliverables/` 에
있었다. 09-02 에 「`foothold-lab` = 비공개 개발 원본 · 문서·코드 전부」로
정했는데 **웹 빌드를 이름으로 부르지 않아** 그것만 남았다. 그 결과 셋이 났다.

1. **빌드가 사흘 전 문서를 읽고 있었다.** 입력을 `_lab-main` 이라는 고정
   워크트리로 잡아 두었는데 09-10 에 멈춰 있었다. 26 커밋이 조용히 가려졌고
   「고쳤는데 화면이 안 바뀐다」로 나타났다.
2. **빌드가 자기가 안 만든 파일을 지웠다.** `report-v1.html` 과 `gnav.*` 셋이
   site 에만 있고 생성 목록에 없어서 매 빌드마다 사라졌다.
3. **한 줄 고치는 데 네 단계가 들었다.** commit -> push -> 워크트리 동기화 ->
   빌드. 실제로 하루에 두 번 이것 때문에 막혔다.

이제 빌드와 문서가 같은 저장소에 있다. **커밋 하나가 곧 한 입력이다.**

`_lab-main` 은 지우지 않았다. 고정 입력이 필요한 재현 빌드가 쓸 수 있다.
다만 **기본값에서 내렸다.** 암묵적으로 옛 커밋을 읽는 일은 없어야 한다.
쓰려면 `FOOTHOLD_LAB` 로 명시해 부른다.
