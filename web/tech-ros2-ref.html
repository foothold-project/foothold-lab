ROS 2 기초

조선대 강의 자료 두 편(개발환경 구축 · Python 프로그래밍)을 PDF 없이 따라 할 수 있게 다시 쓴 학습 노트다. 모든 명령은 강의에서 친 것 그대로, 나온 순서대로 배치했고, 명령마다 바로 아래 해부 표에서 각 단어가 무슨 뜻인지 · 지금 왜 이 명령을 치는지 설명한다.

회차별 실습은 04 ROS 2에 누적된다 · 3회차 TF 좌표계 · RViz2 시각화는 그쪽 L3 섹션에 있다. 이 페이지는 회차와 무관하게 주제별로 찾아보는 레퍼런스다.

1ROS 2란 무엇인가 · 큰 그림 먼저

ROS 2(Robot Operating System 2)는 이름과 달리 운영체제(OS)가 아니다. Ubuntu 같은 진짜 OS 위에서 도는 로봇 소프트웨어 프레임워크다. 로봇 프로그램을 하나의 거대한 코드로 짜는 대신, 작은 프로그램 여러 개로 쪼개고 그들끼리 메시지를 주고받게 만들어 준다.

왜 쪼개는가? Go2 한 마리만 봐도 LiDAR 읽기, 카메라 읽기, 지도 만들기, 경로 계획, 다리 제어가 동시에 돌아야 한다. 이걸 한 프로그램에 넣으면 하나가 죽을 때 전부 죽고, 팀원끼리 나눠 개발할 수도 없다. ROS 2는 "각자 작은 프로그램을 만들고, 정해진 규격의 메시지로 대화한다"는 약속이다.

노드 (Node)
ROS 2 세계의 최소 실행 단위. "한 가지 일을 하는 작은 프로그램" 하나가 노드 하나다. 예: 카메라 영상을 읽어서 내보내는 노드, 그 영상을 받아 사람을 탐지하는 노드. 우리가 Python으로 작성하는 것이 바로 이 노드다.
메시지 (Message)
노드끼리 주고받는 데이터의 규격. 필드 이름과 타입이 미리 정해져 있다(예: 속도 명령 Twist는 직진 속도 linear + 회전 속도 angular). 규격이 고정돼 있어서 남이 만든 노드와도 바로 대화가 된다.
그래프 (Graph)
지금 실행 중인 모든 노드와, 그들 사이의 메시지 연결선을 그린 지도. 수학의 그래프(점과 선)에서 온 말이다 · 점이 노드, 선이 통신. rqt_graph 명령으로 실제 그림으로 볼 수 있다.
DDS
Data Distribution Service. 노드 사이에서 메시지를 실제로 배달해 주는 하부 통신 기술(택배 회사에 해당). ROS 2가 알아서 쓰므로 지금은 "이런 게 밑에 깔려 있다"만 알면 되고, 실기 Go2 연결 때 CycloneDDS라는 이름으로 다시 만난다.
배포판 (Distribution)
ROS 2의 버전 이름. Ubuntu 버전마다 짝이 정해져 있다. 우리는 Ubuntu 24.04 ↔ ROS 2 Jazzy 조합을 쓴다(조선대 수업 기준).
터미널 · shell · bash
터미널은 명령어를 입력하는 창, shell은 그 명령을 해석·실행해 주는 프로그램, bash는 리눅스의 기본 shell 이름. 아래 명령들은 전부 터미널에 입력한다. 줄 앞의 $는 "여기부터 입력"이라는 표시일 뿐이니 따라 치지 않는다. #으로 시작하는 줄은 주석(설명)이라 입력하지 않는다.
우리 프로젝트와의 연결

시뮬 Go2 의 카메라·LiDAR 를 내보내는 브릿지(28 Go2 CV·LiDAR)나 실기용 go2_ros2_sdk(채택 미확정, 14 §7)도 결국 "Go2의 센서를 ROS 2 메시지로 바꿔 내보내는 노드 묶음"이고, Nav2도 "경로를 계산해 속도 명령 메시지를 내보내는 노드 묶음"이다. 이 페이지의 개념만 잡히면 그 도구들은 전부 같은 문법으로 읽힌다.

2개발환경 구축 · 순서대로 따라 치기

Ubuntu 24.04를 설치한 직후부터 시작한다(설치 자체는 balenaEtcher로 부팅 USB를 만들어 화면 순서대로 진행하면 된다). 이후 흐름은 ① 기본 도구 → ② 파이썬 가상환경 → ③ Jupyter → ④ VSCode → ⑤ ROS 2 Jazzy → ⑥ 터미널 자동화 순서다. 앞 단계가 뒤 단계의 재료가 되므로 순서를 지킨다.

2-1. 기본 도구 설치

새 OS의 첫 명령. 소프트웨어 목록을 최신으로 맞추지 않으면 이후 모든 설치가 "그런 패키지 없음"으로 실패할 수 있어서 항상 이것부터 한다.

Bash / 우분투
$ sudo apt update && sudo apt upgrade -y
sudosuperuser do · "관리자 권한으로 실행". 시스템에 뭔가 설치·변경하는 명령엔 거의 항상 붙는다. 내 비밀번호를 물어본다.
aptUbuntu의 패키지 관리자(앱스토어 역할). 설치·삭제·업데이트를 담당.
update"설치 가능한 패키지 목록"만 새로 받아온다. 실제 설치는 안 함.
&&"앞 명령이 성공하면 뒤 명령 실행". 두 명령을 한 줄로 잇는 접착제.
upgrade목록 기준으로 이미 설치된 것들을 실제로 최신 버전으로 교체.
-yyes · 중간에 "계속할까요? [Y/n]" 질문이 나오면 자동으로 예라고 답함.

Terminator는 한 창을 여러 칸으로 쪼개는 터미널이다. ROS 2는 노드마다 터미널을 하나씩 쓰기 때문에(발행 하나, 구독 하나, 관찰 하나…) 분할 터미널이 사실상 필수다.

Bash / 우분투
$ sudo apt install terminator -y
install terminatorapt에게 terminator라는 이름의 패키지를 설치하라고 지시. sudo apt install 이름 -y가 이 페이지에서 가장 자주 반복될 패턴이다.

Chrome은 apt 목록에 없어서, 설치 파일(.deb)을 직접 내려받아 설치한다. "apt에 없는 프로그램 설치법"의 표준 패턴이므로 익혀두면 VSCode 설치에서 그대로 재사용된다.

Bash / 우분투
$ wget https://dl.google.com/linux/direct/google-chrome-stable_current_amd64.deb
$ sudo dpkg -i google-chrome*.deb
$ sudo apt --fix-broken install -y
wget <URL>web get · 그 주소의 파일을 현재 폴더로 다운로드.
dpkg -idebian package · .deb 설치 파일을 직접 설치. -i는 install.
google-chrome*.deb*는 "아무 글자나"라는 와일드카드. 버전 숫자가 섞인 긴 파일명을 다 치지 않으려는 요령.
--fix-brokendpkg는 의존성(이 프로그램이 필요로 하는 다른 패키지)을 못 챙긴다. 부족한 의존성을 apt가 자동으로 채워 넣는 마무리 명령.

터미널에서 돌아다니는 기본기 네 개. 이후 모든 단계에서 몸에 배어 있어야 한다.

출력
$ pwd          # 지금 내가 어느 폴더에 있는지 출력
$ ls -al       # 현재 폴더의 파일 목록 (숨김 파일 포함, 상세히)
$ cd ~         # 홈 폴더로 이동
$ mkdir -p ~/ros2_ws/src # 앞으로 실습 코드가 들어갈 워크스페이스
pwdprint working directory · 현재 위치 출력. 길을 잃으면 이것부터.
ls -allist · 파일 목록. -a는 all(숨김 파일 포함), -l은 long(권한·크기 상세 표시).
cd ~change directory · 폴더 이동. ~는 내 홈 폴더(/home/내이름)의 약자.
mkdir -p ~/ros2_ws/srcmake directory · 폴더 생성. -p는 parents로 중간 폴더까지 한 번에 만든다. ros2_ws는 ROS 2 workspace(작업 공간)의 줄임말이고, 소스는 그 안의 src/에 두는 것이 ROS 2의 관례다. 구 강의 PDF는 여기서 dev_ws를 만들라고 했지만, 09-04 배포된 새 교재는 dev_ws를 아예 쓰지 않는다.

2-2. Python 가상환경 (venv)

가상환경 = 프로젝트 전용 파이썬 패키지 방. Ubuntu 24.04는 시스템 파이썬에 직접 pip install하는 것을 아예 막아 놨다(PEP 668 정책 · 시스템 도구가 파이썬으로 만들어져 있어서, 잘못 건드리면 OS가 망가지기 때문). 실제로 시스템에서 pip install을 시도하면 error: externally-managed-environment가 뜬다. 그래서 가상환경이 선택이 아니라 필수다.

가상환경을 만들 도구(pip, venv)부터 설치한다. 최초 1회만.

Bash / 우분투
$ sudo apt update && sudo apt install python3-pip -y
$ sudo apt install python3.12-venv -y
python3-pippip = 파이썬 패키지 설치 도구(apt의 파이썬 버전이라고 생각하면 된다).
python3.12-venv가상환경 생성 기능. Ubuntu 24.04의 기본 파이썬이 3.12라서 버전이 이름에 붙는다.

실습 내내 쓸 가상환경 ros를 만들고 켠다. 프롬프트 맨 앞에 (ros)가 붙으면 켜진 것 · 이 상태에서의 pip install은 전부 이 방 안에만 설치된다.

Bash / 우분투
$ python3 -m venv ~/venv/ros
$ source ~/venv/ros/bin/activate
(ros) $ pip install --upgrade pip
(ros) $ deactivate   # 가상환경 끄기 (다시 켤 땐 위의 source 명령)
python3 -m venv-m은 module · "파이썬에 내장된 venv 모듈을 실행하라". 뒤의 경로가 가상환경이 만들어질 위치다.
~/venv/ros홈 아래 venv 폴더 안에 ros라는 이름으로 생성. 가상환경 여러 개를 venv 폴더에 모아두는 관례.
source ~/.../activatesource는 "이 스크립트를 지금 이 터미널에 적용하라". activate 스크립트가 이 터미널의 파이썬을 가상환경 것으로 바꿔치기한다. 터미널을 새로 열 때마다 다시 해야 한다.
pip install --upgrade pippip 자기 자신을 최신으로. --upgrade는 이미 있으면 버전을 올리라는 뜻.
deactivate가상환경 끄기. 이 명령만 source 없이 그냥 친다.

2-3. Jupyter Notebook

Jupyter = 브라우저에서 코드를 한 조각(셀)씩 실행하며 결과를 바로 보는 도구. rclpy를 처음 만질 때 "한 줄 치고 결과 보고"를 반복하기에 가장 좋다.

반드시 가상환경을 켠 상태에서 설치한다 · 시스템에 설치하려 하면 위의 PEP 668 에러가 난다. 작업 폴더를 만들고 그 안에서 실행하면 노트북 파일이 거기 저장된다.

Bash / 우분투
$ source ~/venv/ros/bin/activate
(ros) $ python -m pip install \
    jupyter ipykernel numpy matplotlib PyQt5 \
    empy catkin_pkg lark lark-parser transforms3d pyyaml setuptools
(ros) $ python -m ipykernel install --user --name ros --display-name "ros (venv)"
(ros) $ mkdir -p ~/ros2_ws/notebooks
(ros) $ cd ~/ros2_ws/notebooks
(ros) $ jupyter notebook     # 종료는 터미널에서 Ctrl + C
python -m pippip을 그냥 치지 않고 python -m으로 부르는 이유는, 지금 켜져 있는 파이썬에 확실히 설치되게 하려는 것이다. pip만 치면 가상환경 밖의 것이 잡히는 사고가 난다.
jupyter · ipykernel노트북 본체와, 노트북이 이 가상환경의 파이썬을 쓰게 해 주는 연결 부품.
empy · catkin_pkg · lark · lark-parser커스텀 메시지(.msg/.srv) 빌드에 필요한 것들. 이게 없으면 colcon build가 module 'em' has no attribute 'Interpreter'로 실패한다. 새 강의 교재가 이걸 준비 단계로 끌어올린 이유가 그 에러 때문이다.
transforms3dTF의 각도 변환에 쓰이는 수학 라이브러리.
numpy · matplotlib · PyQt524·25강 GUI 모니터가 쓰는 것들.
ipykernel install이 가상환경을 주피터의 커널 목록에 등록한다. 이걸 해야 노트북 오른쪽 위에서 커널을 고를 수 있다.
--user시스템 전체가 아니라 내 계정에만 등록. sudo가 필요 없어진다.
--name ros커널의 내부 이름(폴더 이름으로 쓰인다).
--display-name "ros (venv)"노트북 화면에 보이는 이름. 공백이 있어서 따옴표로 묶는다. 새 강의 교재가 정한 표기가 이것이라 그대로 쓴다.
mkdir -p-p는 parents · 중간 폴더(ros2_ws)가 없으면 같이 만들고, 이미 있어도 에러 내지 않음.
jupyter notebook노트북 서버를 켜고 브라우저를 자동으로 연다. 이 터미널은 서버가 점유하므로 다른 일은 새 터미널에서.
pip list(참고) 지금 가상환경에 설치된 패키지 목록 확인.
11강 메시지 빌드가 module 'em' has no attribute 'Interpreter'로 실패하면

가상환경 안에서 python -m pip install 'empy==3.3.4' catkin_pkg lark로 버전을 내려서 다시 깔고, rm -rf build install log 후 다시 빌드한다. 강의 화면에서는 empy 4.2로도 되지만 환경에 따라 3.3.4가 필요하다.

2-4. VSCode

code.visualstudio.com에서 .deb를 내려받은 뒤, Chrome 때와 똑같은 패턴으로 설치한다. 설치 후 확장(Extensions)에서 Python과 Jupyter를 추가하면 .py도 .ipynb도 VSCode 한 창에서 실행된다.

Bash / 우분투
$ sudo dpkg -i code_*.deb
$ sudo apt --fix-broken install -y
$ cd ~/ros2_ws/notebooks && code .
code .code는 VSCode 실행 명령, .은 "현재 폴더". 즉 "지금 이 폴더를 VSCode로 열어라". 프로젝트 폴더로 cd한 뒤 여는 게 습관이 되면 좋다.

2-5. ROS 2 Jazzy 설치

흐름을 먼저 이해하자. ROS 2는 Ubuntu 기본 앱 목록에 없으므로, ① 문자 인코딩(로케일)을 국제 표준으로 맞추고 → ② ROS가 의존하는 패키지가 있는 universe 저장소를 켜고 → ③ ROS 저장소 등록 패키지(ros2-apt-source.deb)를 설치해 서명 키와 주소를 한 번에 등록한 뒤 → ④ 설치 → ⑤ 5~25강에서 실제로 쓰는 추가 패키지를 채우는 순서다. 낯선 명령이 많지만 전부 "apt에게 새 가게 하나를 등록하는 절차"일 뿐이다.

등록 방식이 바뀌었다 · 옛 방식으로 치지 않는다 (09-04 정정)

예전 자료(구 강의 05번 PDF 포함)는 ros.key를 curl로 직접 받아 /usr/share/keyrings/에 넣고, echo "deb ..." | sudo tee로 저장소 줄을 손수 써 넣으라고 한다. 이 페이지도 그렇게 적혀 있었고, 09-04 배포된 새 강의 교재 기준으로 아래 방식으로 바로잡았다.

현재 ROS 공식 방식은 ros2-apt-source라는 .deb 패키지 하나를 설치하는 것이다. 이 패키지가 서명 키와 저장소 주소를 둘 다 넣어 주고, 키가 만료되면 apt upgrade로 같이 갱신된다 · 손으로 넣은 키는 만료되면 어느 날 갑자기 apt update가 NO_PUBKEY로 실패한다. 그게 방식이 바뀐 이유다.

① 로케일 · ROS 2는 UTF-8 인코딩을 전제한다. 시스템 언어 설정이 다르면 빌드·실행에서 이상한 문자 에러가 나므로 미리 맞춘다.

Bash / 우분투
$ sudo apt update && sudo apt install locales software-properties-common -y
$ sudo locale-gen en_US en_US.UTF-8
$ sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8
locales언어·인코딩 설정을 다루는 패키지.
software-properties-common다음 단계의 add-apt-repository 명령을 제공하는 패키지.
locale-gen en_US en_US.UTF-8영어(미국)·UTF-8 로케일 데이터를 생성.
update-locale LC_ALL=... LANG=...시스템 기본 로케일을 UTF-8로 지정. LC_ALL은 모든 항목 강제, LANG은 기본값.

② universe 저장소 · Ubuntu는 저장소를 신뢰 등급별로 나눠 두는데, ROS 2가 의존하는 커뮤니티 패키지들은 universe(커뮤니티 관리 구역)에 있다. 꺼져 있으면 설치가 의존성 에러로 실패한다.

Bash / 우분투
$ sudo add-apt-repository universe
add-apt-repositoryapt가 바라보는 저장소 목록에 항목을 추가하는 명령.
universeUbuntu 공식 4대 저장소 중 하나(main=공식지원 / universe=커뮤니티 / restricted·multiverse=비공개 라이선스 계열).

③ 저장소 등록 · 서명 키와 저장소 주소를 ros2-apt-source 패키지 하나로 한꺼번에 등록한다. 최신 버전 번호를 GitHub API에서 자동으로 알아내 그 .deb를 받아 설치하는 구조라, 줄은 길어 보여도 하는 일은 "받아서 깐다" 둘뿐이다.

Bash / 우분투
$ sudo apt update && sudo apt install curl -y
$ export ROS_APT_SOURCE_VERSION=$(curl -s \
    https://api.github.com/repos/ros-infrastructure/ros-apt-source/releases/latest \
    | grep -F "tag_name" | awk -F\" '{print $4}')
$ curl -L -o /tmp/ros2-apt-source.deb \
    "https://github.com/ros-infrastructure/ros-apt-source/releases/download/${ROS_APT_SOURCE_VERSION}/ros2-apt-source_${ROS_APT_SOURCE_VERSION}.$(. /etc/os-release && echo $VERSION_CODENAME)_all.deb"
$ sudo apt install -y /tmp/ros2-apt-source.deb
curlwget처럼 URL에서 데이터를 받아오는 도구. 옵션 조합이 유연해서 스크립트에 많이 쓰인다.
export 이름=값환경변수를 만든다. export를 붙이면 이 터미널에서 이후 실행되는 명령들도 그 값을 볼 수 있다 · 다음 줄의 ${ROS_APT_SOURCE_VERSION}이 그래서 동작한다.
$(...)명령 치환. 괄호 안 명령을 먼저 실행하고 그 출력을 그 자리에 끼워 넣는다.
-ssilent. 진행률 막대를 숨긴다. 출력을 다른 명령에 넘길 때 방해가 되기 때문이다.
api.github.com/.../releases/latestGitHub이 가장 최근 릴리스 정보를 JSON으로 돌려주는 주소. 버전 번호를 사람이 찾아 넣지 않기 위해 부른다.
|파이프. 왼쪽 명령의 출력을 오른쪽 명령의 입력으로 흘려 넣는다.
grep -F "tag_name"JSON 여러 줄 중 tag_name이 든 줄만 고른다. -F는 Fixed string · 찾을 문자열을 정규식이 아니라 글자 그대로 취급하라는 뜻이다.
awk -F\" '{print $4}'awk는 줄을 칸으로 쪼개 다루는 도구. -F\"는 큰따옴표를 구분자로 삼으라는 지정이고, {print $4}는 네 번째 칸을 출력하라는 뜻이다. "tag_name": "1.1.0"에서 버전 문자열만 뽑아낸다.
-LLocation. 주소가 다른 곳으로 옮겨졌으면(redirect) 따라간다. GitHub 릴리스 파일은 항상 다른 서버로 넘겨 주므로 이게 없으면 빈 파일을 받는다.
-o /tmp/ros2-apt-source.deboutput. 받은 내용을 이 경로에 저장. /tmp/는 껐다 켜면 비워지는 임시 폴더라, 설치하고 버릴 파일을 두기에 맞는 자리다.
${...}변수 값을 끼워 넣는 문법. 뒤에 글자가 바로 붙는 자리(..._${VER}.noble_all.deb)에서는 중괄호로 변수 이름의 끝을 알려 줘야 셸이 잘라 읽는다.
. /etc/os-release && echo $VERSION_CODENAME맨 앞의 점 .은 source의 짧은 형태. Ubuntu 버전 정보 파일을 읽어 들인 뒤 코드네임을 출력한다. 24.04면 noble이다.
apt install /경로/파일.deb내려받은 .deb를 설치. dpkg -i 대신 apt install에 경로를 주면 의존성까지 apt가 알아서 챙겨 준다 · 앞의 Chrome 설치에서 --fix-broken을 따로 쳤던 이유가 여기서는 없어진다.
성공 판정sudo apt update 출력에 packages.ros.org 줄이 보이면 등록된 것이다.

⑤ 설치 · 새 저장소를 등록했으니 update로 목록을 다시 받고, 개발 도구와 ROS 2 본체를 설치한다. 수 GB라서 시간이 걸린다.

Bash / 우분투
$ sudo apt update
$ sudo apt install ros-dev-tools -y
$ sudo apt install ros-jazzy-desktop -y
ros-dev-toolscolcon(빌드 도구) 등 ROS 2 개발에 필요한 도구 모음.
ros-jazzy-desktopROS 2 본체 + RViz(시각화) + 데모·튜토리얼까지 포함한 풀 패키지. 이름 규칙이 ros-배포판-패키지명이라서, 앞으로 ROS 관련 apt 설치는 전부 ros-jazzy-... 형태다.

⑤ 추가 패키지 · ros-jazzy-desktop만으로는 5~25강에서 쓰는 것이 다 안 들어온다. 새 강의 교재가 "실제로 쓰는 것 전부"로 정리해 둔 목록이라 여기서 한 번에 깔아 둔다. 나중에 ModuleNotFoundError·Package not found로 헤매는 시간을 여기서 산다.

Bash / 우분투
$ sudo apt install -y \
    python3-colcon-common-extensions python3-rosdep \
    ros-jazzy-turtlesim ros-jazzy-tf-transformations ros-jazzy-domain-bridge \

$ rosdep update
\ (줄 끝 역슬래시)"명령이 다음 줄에 이어진다"는 표시. 긴 명령을 보기 좋게 쪼갤 때 쓴다. 복사해 붙일 땐 한 줄로 쳐도 똑같다.
python3-colcon-common-extensionscolcon의 확장 묶음. --symlink-install 같은 옵션과 탭 자동완성이 여기서 온다.

python3-transforms3dtf_transformations가 내부에서 쓰는 수학 라이브러리.

sudo rosdep initrosdep의 의존성 규칙 목록을 시스템에 처음 한 번 설치한다.
2>/dev/null || true2>는 에러 출력만 딴 데로 보내라는 뜻이고 /dev/null은 휴지통이다. ||는 "앞이 실패하면 뒤를 실행"이므로 || true는 실패해도 성공한 셈 치라는 관용구다. rosdep init은 이미 되어 있으면 에러를 내는데 그게 정상이라, 그 에러로 스크립트가 멈추지 않게 하는 것이다.
rosdep update규칙 목록을 최신으로 받아온다. 이건 sudo 없이 친다 · 사용자 홈에 캐시를 만들기 때문이고, sudo로 치면 나중에 권한 문제가 난다.

ros2ROS 2의 총사령 명령. 모든 ROS 조작이 ros2 동사 ... 형태로 시작된다.

2-6. 터미널 자동화 · .bashrc · alias · ROS_DOMAIN_ID

.bashrc는 터미널을 열 때마다 자동 실행되는 내 설정 파일이다. 방금 본 source 명령을 여기 넣어두면 매번 치는 수고가 사라진다.

.bashrc를 열어 맨 아래에 두 줄을 추가하고 저장한다. 이후 새 터미널부터는 자동 적용된다.

출력
$ code ~/.bashrc      # 파일 열기 (gedit ~/.bashrc 도 가능)

# ─ 파일 맨 아래에 이 두 줄 추가 ─
source /opt/ros/jazzy/setup.bash
export ROS_DOMAIN_ID=13

$ source ~/.bashrc    # 저장 후, 지금 이 터미널에도 즉시 적용
~/.bashrc홈 폴더의 숨김 파일(이름이 점으로 시작하면 숨김). ls -al로만 보인다.
export 이름=값환경변수 등록 · 이 터미널에서 실행되는 모든 프로그램이 읽을 수 있는 전역 설정값.
ROS_DOMAIN_ID=13같은 네트워크의 ROS 2 컴퓨터는 서로 자동으로 연결된다(DDS의 자동 발견). 수업처럼 수십 명이 한 공유기를 쓰면 남의 거북이가 내 명령에 움직이는 사고가 나므로, 각자 다른 번호(0~101)를 정해 같은 번호끼리만 통신하게 격리한다.
source ~/.bashrc.bashrc는 "새 터미널"에만 자동 적용되므로, 지금 열려 있는 터미널에는 이렇게 수동 적용.

alias는 긴 명령에 붙이는 단축 이름. .bashrc에 넣어두면 영구 등록된다. 09-04 배포된 강의 교재는 이 alias 묶음을 스크립트(04_bashrc_setup.sh)로 제공한다 · 손으로 적을 필요 없이 L4-1에서 한 번에 붙인다. 아래는 그 스크립트가 만들어 주는 것들이고, 이 위키의 뒤쪽 명령이 전부 이 이름을 전제한다.

Bash / 우분투
export ROS2_VENV="$HOME/venv/ros"
export ROS2_WS="$HOME/ros2_lecture/ubuntu_practice/ros2_ws"

alias sb='source ~/.bashrc'
alias venv_ros='source "$ROS2_VENV/bin/activate"'
alias jazzy='venv_ros; source /opt/ros/jazzy/setup.bash; ros_domain'
alias ros2ws='jazzy; source "$ROS2_WS/install/local_setup.bash"'
alias 이름='명령'이후 jazzy만 쳐도 오른쪽 명령 전체가 실행된다. 등호(=) 양옆에 공백이 있으면 안 된다 · 이 문법의 단골 실수.
$HOME~와 같은 홈 폴더를 가리키는 환경변수. 따옴표 안에서도 값으로 풀린다는 점이 ~와 다르고, 그래서 스크립트에서는 이쪽을 쓴다.
jazzy가상환경 + ROS 2 + 도메인 번호를 한 번에 켠다. ros2 topic 같은 CLI만 쓸 때는 이것으로 충분하다.
ros2wsjazzy가 하는 일 전부 + 빌드한 워크스페이스까지 등록. 내 노드를 ros2 run하려면 이쪽이어야 한다.
local_setup.bashsetup.bash는 밑에 깔린 환경(ROS 2 본체)까지 같이 불러오고, local_setup.bash는 이 워크스페이스 것만 불러온다. jazzy가 이미 ROS 2를 켠 뒤라 여기서는 뒤쪽이면 충분하다.
get_status(스크립트가 함께 만들어 주는 함수) 지금 터미널의 ROS_DOMAIN_ID와 ROS_LOCALHOST_ONLY를 찍어 준다. 노드가 서로 안 보일 때 제일 먼저 칠 것.

3통신 4형제 · Topic · Service · Action · Parameter

ROS 2 공부의 심장부다. 노드끼리 대화하는 방식이 성격에 따라 4가지로 나뉘고, 모든 ROS 2 시스템은 이 4가지의 조합일 뿐이다. 실습은 전부 turtlesim(ROS 2에 내장된 거북이 시뮬레이터 · 화면 속 거북이 한 마리가 연습용 로봇 역할)으로 한다.

먼저 거북이를 띄우고, 지금 그래프에 어떤 노드가 살아 있는지 확인한다. 이후 모든 실습의 출발 상태다.

출력
# 터미널 1 · 거북이 창 띄우기
$ ros2 run turtlesim turtlesim_node

# 터미널 2 · 방향키로 조종해보기
$ ros2 run turtlesim turtle_teleop_key

# 터미널 3 · 그래프 조회
$ ros2 node list
$ ros2 node info /turtlesim
turtlesim turtlesim_nodeturtlesim 패키지 안의 turtlesim_node 노드 · 거북이 창 본체.
turtle_teleop_keyteleop = teleoperation(원격 조종). 키보드 입력을 속도 메시지로 바꿔 보내는 노드.
node list지금 살아 있는 노드 이름 전부 나열.
node info /turtlesim특정 노드의 상세 · 이 노드가 무엇을 구독/발행하고 어떤 서비스·액션을 제공하는지. 이름 앞 /는 ROS 이름 체계의 루트 표시(폴더 경로처럼).

토픽 (Topic) · 방송

토픽은 이름 붙은 방송 채널이다. 발행자(Publisher)가 채널에 메시지를 계속 흘려보내고, 그 채널을 구독(Subscribe)한 노드들이 받아 본다. 라디오처럼 발행자는 누가 듣는지 모르고, 답장도 없다(비동기). 여러 명이 발행하고 여러 명이 구독할 수 있다(다대다). 끊임없이 흐르는 데이터 · 센서값, 카메라 영상, 위치, 속도 명령 · 에 쓰며, ROS 2 통신의 90%는 토픽이다. Go2의 LiDAR 포인트클라우드도, Nav2의 속도 명령 /cmd_vel도 전부 토픽이다.

채널 목록을 보고 → 하나를 엿듣고 → 직접 발행해서 거북이를 움직여 본다. "구독자 입장 → 발행자 입장"을 순서대로 체험하는 흐름이다.

Bash / 우분투
$ ros2 topic list -t
$ ros2 topic echo /turtle1/pose

$ ros2 topic pub --once /turtle1/cmd_vel \
    geometry_msgs/msg/Twist \
    "{linear: {x: 2.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 1.8}}"
topic list -t토픽 목록. -t는 type · 각 토픽이 어떤 메시지 타입을 쓰는지 대괄호로 같이 표시. 다음 명령에 쓸 타입 이름을 여기서 알아낸다.
topic echo /turtle1/pose그 토픽에 흐르는 메시지를 실시간으로 화면에 출력(도청). pose = 위치+자세. Ctrl+C로 중단.
topic pubpublish · 터미널이 임시 발행자가 되어 메시지를 직접 쏜다. 코드 없이 로봇을 움직여보는 필수 디버깅 기술.
--once한 번만 발행하고 종료. --rate 1로 바꾸면 초당 1회씩 계속 발행(중단은 Ctrl+C).
/turtle1/cmd_vel보낼 채널 이름. cmd_vel = command velocity(속도 명령) · 로봇 세계 공통 관례라 Go2에서도 같은 이름을 만난다.
geometry_msgs/msg/Twist메시지 타입의 풀네임: geometry_msgs 패키지 / msg 폴더 / Twist 타입. Twist = 직진속도(linear)+회전속도(angular) 묶음.
"{linear: {x: 2.0, ...}}"메시지 내용을 YAML 문법(중괄호+콜론)으로 채운 것. linear.x=전진 2.0, angular.z=반시계 회전 1.8. 나머지 축은 0.

서비스 (Service) · 전화

서비스는 1:1 전화 통화다. 클라이언트(요청하는 쪽)가 요청(Request)을 보내면 서버(응답하는 쪽)가 처리하고 응답(Response)을 돌려준다. 전화처럼 걸면 답이 올 때까지 기다린다(동기). "지도 저장해줘", "거북이 한 마리 더 만들어줘"처럼 단발성 부탁에 쓴다.

서비스 목록 확인 → 요청서 양식(interface) 확인 → 호출. "양식을 먼저 보고 그대로 채운다"가 서비스 사용의 정석 순서다.

Bash / 우분투
$ ros2 service list -t
$ ros2 interface show turtlesim/srv/TeleportAbsolute

$ ros2 service call /turtle1/teleport_absolute \
    turtlesim/srv/TeleportAbsolute "{x: 2.0, y: 2.0, theta: 1.57}"
$ ros2 service call /reset std_srvs/srv/Empty "{}"
$ ros2 service call /spawn turtlesim/srv/Spawn "{x: 5.0, y: 5.0, name: 'turtle2'}"
interface show <타입>그 서비스의 요청/응답 양식을 출력. --- 윗부분이 Request 필드, 아랫부분이 Response 필드다. 무엇을 채워야 할지 여기서 확인.
service call터미널이 임시 클라이언트가 되어 요청을 보내고 응답을 받아 보여준다.
/turtle1/teleport_absolute서비스 이름. teleport_absolute = 절대좌표로 순간이동. theta는 바라볼 각도(라디안 · 1.57 ≈ 90°).
std_srvs/srv/Empty "{}"Empty = 채울 내용이 없는 빈 양식. 그래도 자리는 채워야 해서 빈 중괄호 {}를 준다. /reset은 화면 초기화.
/spawn거북이 추가 생성. name처럼 문자열 값은 작은따옴표로 감싼다.

액션 (Action) · 배달 주문

액션은 시간이 오래 걸리는 작업용 통신이다. 목표(Goal)를 보내면, 진행 상황(Feedback)이 계속 날아오다가, 끝나면 결과(Result)가 온다. 배달 앱의 주문 → "조리 중, 배달 중" → 도착과 같다. 서비스와 달리 기다리는 동안 다른 일을 할 수 있고 중간 취소도 된다. Nav2의 목표점 이동이 정확히 액션이다 · RViz에서 Goal을 찍으면 액션 Goal이 날아가고, 이동 중 Feedback이 오고, 도착하면 Result가 온다.

Bash / 우분투
$ ros2 action list
$ ros2 action send_goal /turtle1/rotate_absolute \
    turtlesim/action/RotateAbsolute "{theta: 3.14}" --feedback
action send_goal터미널에서 액션 목표를 전송. 인자 순서는 토픽·서비스와 같은 패턴: 이름 → 타입 → 값.
rotate_absolute절대 각도까지 회전하는 액션. 3.14 rad ≈ 180°.
--feedback진행 상황(남은 각도)을 실시간으로 같이 출력. 빼면 최종 결과만 보여준다.

파라미터 (Parameter) · 설정값

파라미터는 노드가 갖고 있는 이름 붙은 설정값이다. 통신이라기보다 "코드 수정·재빌드 없이 노드의 동작을 조정하는 손잡이"다.

조회(list/get) → 변경(set) → 파일로 저장/복원(dump/load) 순서. 튜닝이 끝난 설정을 yaml 파일로 보관하는 습관은 2단계 Nav2 튜닝에서 그대로 쓰인다.

Bash / 우분투
$ ros2 param list
$ ros2 param get /turtlesim background_g
$ ros2 param set /turtlesim background_r 250
$ ros2 param dump /turtlesim > ./turtlesim.yaml   # 지금 서 있는 폴더에 저장된다
$ ros2 param load /turtlesim ./turtlesim.yaml
param get /노드 이름"이 노드의 이 파라미터 값"을 조회. background_r/g/b는 거북이 창 배경색(0~255).
param set ... 250값 변경 · 즉시 배경색이 바뀐다. 재시작 불필요.
dump ... > 파일노드의 전체 파라미터를 출력하고, >(리다이렉트 · 화면 대신 파일로)로 yaml 파일에 저장.
load ... 파일저장해 둔 yaml을 다시 노드에 적용.
param load에서 failed: read-only가 몇 줄 나오는 건 정상이다

param dump는 노드의 모든 파라미터를 뽑는데, 그중 qos_overrides.*·start_type_description_service·use_sim_time은 노드를 띄울 때만 정할 수 있는 값(read-only)이라 되돌릴 때 그것들만 실패한다. background_r/g/b ... successful이 보이고 거북이 배경색이 실제로 바뀌면 성공이다.

고르는 기준 한 줄씩

흐르는 데이터 → 토픽 · 단발 부탁+즉답 → 서비스 · 오래 걸리는 작업+진행 보고 → 액션 · 동작 조정용 값 → 파라미터

4Python으로 노드 만들기 · rclpy

rclpy는 ROS 2를 Python에서 쓰게 해 주는 공식 라이브러리다(ROS Client Library for Python). 3장에서 터미널로 하던 일을 이제 코드로 한다.

준비 · Jupyter가 가상환경의 파이썬을 쓰도록 커널로 등록한다. 이걸 안 하면 노트북에서 import rclpy가 실패한다.

출력
(ros) $ pip3 install jupyter ipykernel
(ros) $ python -m ipykernel install --user --name ros --display-name ros
ipykernel파이썬 환경 하나를 Jupyter의 "커널"(노트북 코드를 실행해 주는 엔진)로 만들어 주는 패키지.
python -m ipykernel install지금 켜져 있는 가상환경을 커널로 등록.
--user시스템 전체가 아니라 내 계정에만 등록.
--name ros --display-name ros내부 이름과 노트북 화면에 보일 이름. 이후 노트북 우상단에서 커널 "ros"를 선택하면 된다.

핵심 개념 두 개만 잡으면 모든 rclpy 코드가 읽힌다:

콜백 (callback)
"메시지가 도착하면 이 함수를 불러줘"라고 맡겨 두는 함수. 내가 호출하는 게 아니라 ROS 2가 대신 호출해 준다.
spin
노드를 대기 상태로 돌리는 무한 루프. rclpy.spin(node)이 돌고 있어야 메시지가 도착할 때마다 콜백이 실행된다. spin이 없으면 구독을 등록해도 아무 일도 일어나지 않는다 · 초심자 1위 실수.

구독자(Subscriber)와 발행자(Publisher)의 최소 골격 · turtlesim의 위치를 받고, 속도 명령을 내보내는 예:

Python
import rclpy
from rclpy.node import Node
from turtlesim.msg import Pose
from geometry_msgs.msg import Twist

class MyNode(Node):
    def __init__(self):
        super().__init__('my_node')                     # 노드 이름
        # 구독: (메시지 타입, 토픽 이름, 콜백, 큐 크기)
        self.create_subscription(Pose, '/turtle1/pose', self.on_pose, 10)
        # 발행자 생성 + 0.5초마다 발행하는 타이머
        self.pub = self.create_publisher(Twist, '/turtle1/cmd_vel', 10)
        self.create_timer(0.5, self.on_timer)

    def on_pose(self, msg):                             # 콜백: 위치가 올 때마다 실행
        self.get_logger().info(f'x={msg.x:.2f} y={msg.y:.2f}')

    def on_timer(self):                                 # 콜백: 0.5초마다 실행
        cmd = Twist()
        cmd.linear.x = 1.0
        self.pub.publish(cmd)

rclpy.init()
node = MyNode()
rclpy.spin(node)                                        # 여기서 대기하며 콜백 처리

마지막 인자 10은 큐 크기 · 콜백 처리가 밀릴 때 메시지를 몇 개까지 쌓아둘지다. 관례적으로 10을 쓴다.

서비스 클라이언트는 패턴이 하나 더 붙는다: create_client()로 만들고 → wait_for_service()로 서버가 켜질 때까지 기다리고 → 요청 객체에 값을 채워 call_async()로 보내면 Future(아직 도착 안 한 결과를 담을 빈 상자 · 나중에 결과가 채워짐)가 돌아온다. 강의에서는 이걸로 turtlesim의 teleport_absolute를 호출했다.

5패키지와 빌드 · 실험 코드를 진짜 소프트웨어로

노트북(.ipynb) 실험은 나 혼자만 실행할 수 있다. 팀원이 ros2 run으로 실행하게 만들려면 패키지로 포장해야 한다.

패키지 (package)
노드 코드 + 설정을 배포 가능한 단위로 묶은 폴더. ROS 2 세계의 유통 단위 · go2_ros2_sdk도, Nav2도 전부 패키지 묶음이다.
워크스페이스 (workspace)
내 패키지들을 모아 두고 빌드하는 작업 폴더(여기서는 ~/ros2_ws). 소스는 그 안의 src/ 폴더에 두는 것이 관례이고, 빌드하면 옆에 install/ 폴더가 생긴다.
colcon
ROS 2의 표준 빌드 도구. 빌드(build) = 소스 코드를 실행 가능한 형태로 조립·등록하는 과정.

전체 흐름: src로 이동 → 패키지 뼈대 생성 → (코드 작성 + setup.py의 entry_points에 노드 등록) → 워크스페이스 루트에서 빌드 → source → 실행. 이 6단계 루프가 앞으로 모든 ROS 2 개발의 기본 사이클이다.

Bash / 우분투
$ mkdir -p ~/ros2_ws/src && cd ~/ros2_ws/src
$ ros2 pkg create --build-type ament_python \
    my_first_package --dependencies rclpy

# ... my_first_package/my_first_package/ 안에 노드 .py 작성,
#     setup.py의 entry_points에 등록한 뒤 ...

$ cd ~/ros2_ws
$ colcon build --symlink-install
$ source install/setup.bash
$ ros2 run my_first_package my_subscriber
pkg create패키지 폴더 뼈대(setup.py, package.xml 등)를 자동 생성.
--build-type ament_python빌드 방식 선택. ament_python = 순수 파이썬 패키지용. C++이나 메시지 정의용은 ament_cmake.
--dependencies rclpy"이 패키지는 rclpy가 필요하다"를 package.xml(패키지 신상명세서)에 미리 기재.
entry_pointssetup.py 안의 실행 명령 등록부. 'my_subscriber = my_first_package.my_subscriber:main'처럼 써야 ros2 run이 찾는다.
cd ~/ros2_ws빌드는 반드시 워크스페이스 루트에서. src 안에서 빌드하면 엉뚱한 곳에 install이 생긴다.
colcon buildsrc 안의 모든 패키지를 빌드해 install/ 폴더에 정리.
--symlink-install빌드 결과를 복사하는 대신 원본 파일을 가리키는 바로가기(symbolic link)로 깐다. 노드 .py의 내용만 고친 경우 다시 빌드하지 않아도 바로 반영된다. 새 강의 교재가 모든 빌드에서 이 옵션을 쓴다. 단 setup.py의 entry_points나 .msg·.srv·.action을 고쳤을 때는 이 옵션이 있어도 다시 빌드해야 한다.
source install/setup.bash방금 빌드한 내 패키지들을 이 터미널에 등록. 빌드할 때마다 다시 해야 한다 · "빌드했는데 ros2 run이 못 찾아요"의 원인 1위.

커스텀 메시지·서비스 정의 · 기본 제공 타입으로 부족할 때. 정의 전용 패키지는 ament_cmake로 따로 만들어야 한다(파이썬 패키지에는 못 넣는다). .msg는 필드 나열, .srv는 가운데 ---로 Request/Response 구분. CMakeLists.txt에 등록 후 빌드하면 기본 메시지처럼 import해 쓴다.

Bash / 우분투
$ cd ~/ros2_ws/src
$ ros2 pkg create --build-type ament_cmake my_first_package_msgs

# msg/MyFirstMsg.msg, srv/MyFirstSrv.srv 작성 + CMakeLists.txt 등록 후
$ cd ~/ros2_ws && colcon build --symlink-install && source install/setup.bash
$ ros2 interface show my_first_package_msgs/msg/MyFirstMsg
_msgs 접미사인터페이스(메시지·서비스·액션 정의) 전용 패키지에 붙이는 관례적 이름.
interface show내가 정의한 타입이 제대로 빌드·등록됐는지 확인하는 검증 명령.

강의 응용 예제: /spawn 서비스를 for문으로 8번 호출해 거북이를 원형으로 배치하고, 커스텀 액션(DistTurtle · 지정 거리만큼 이동)의 서버를 직접 작성해 ros2 action send_goal로 호출했다.

6디버깅 도구와 launch

rqt는 ROS 2의 GUI 도구 모음이다. 로그 콘솔·그래프·플롯·파라미터 슬라이더가 전부 이 안에 있다. 한 번에 전부 설치해 둔다.

Bash / 우분투
$ sudo apt install ros-jazzy-rqt* -y
$ rqt          # 도구 모음 창 (Plugins 메뉴에서 골라 쓴다)
$ rqt_graph    # 노드·토픽 연결 지도만 바로 열기
ros-jazzy-rqt** 와일드카드 · "ros-jazzy-rqt로 시작하는 패키지 전부"를 한 번에 설치.
rqt_graph지금 그래프(1장에서 정의한 그 지도)를 실제 그림으로 렌더링. 통신이 안 될 때 "화살표가 이어져 있는지"를 눈으로 확인하는 1차 진단 도구.
  • 로깅(logging) · print() 대신 self.get_logger().info('...'). 노드 이름·시각·레벨(info/warn/error)이 자동으로 붙고, ros2 run rqt_console rqt_console에서 레벨별로 필터링된다.
  • rqt_plot · Topic Monitor · 토픽의 숫자 값을 실시간 그래프로 / 표로 관찰. 코드 한 줄 없이 센서 값 검증.
  • Dynamic Reconfigure · 파라미터에 min/max 범위를 지정해 두면(rcl_interfaces의 ParameterDescriptor) rqt에서 슬라이더로 실시간 조정.

rosbag · 토픽을 통째로 녹화/재생한다. 실기 Go2의 LiDAR를 한 번 녹화해 두면 로봇 없이도 SLAM을 무한 반복 실험할 수 있는, 2단계의 핵심 도구다.

Bash / 우분투
$ cd ~          # 녹화 폴더가 여기 생긴다
$ ros2 bag record -o mybag /turtle1/cmd_vel /turtle1/pose
#   5초쯤 뒤 Ctrl+C

$ ros2 bag info mybag
$ ros2 bag play mybag
bag record지금 흐르는 토픽들을 파일로 녹화 시작. 중단은 Ctrl+C.
cd ~녹화 폴더는 지금 서 있는 폴더 아래에 만들어진다. 어디에 생길지를 먼저 정하는 습관이 없으면 나중에 못 찾는다.
-o mybagoutput · 녹화가 저장될 폴더 이름 지정. 생략하면 날짜시각 이름이 자동으로 붙는다.
/turtle1/cmd_vel /turtle1/pose녹화할 토픽을 이름으로 나열한다. 새 강의 교재가 -a 대신 이 방식을 쓰는 이유는, -a(all)가 이미지·포인트클라우드까지 전부 삼켜 파일이 순식간에 수 GB가 되기 때문이다. 필요한 것만 적는 게 기본이다.
bag info녹화 파일에 무엇이 몇 건 들어 있는지 요약해 준다. 재생 전에 이걸로 확인한다.
bag play녹화된 토픽을 당시 타이밍 그대로 재발행 · 구독자들 입장에선 실기가 다시 돌고 있는 것과 동일.
Jazzy의 녹화 형식은 mcap이다

ros2 bag play가 No storage id specified로 실패하면, 녹화가 Ctrl+C로 깨끗이 끝나지 않아 metadata.yaml이 안 만들어진 것이다. 파일을 지우고 다시 녹화한다. 정상이면 폴더 안에 metadata.yaml과 mybag_0.mcap이 있다.

launch · 노드 여러 개를 한 번에 켜는 실행 대본(Python 파일). 노드가 5개면 터미널 5개를 여는 대신 이 한 줄. Nav2를 켜면 노드 수십 개가 launch 파일 하나로 올라온다. launch 파일도 setup.py의 data_files에 등록하고 빌드해야 인식된다.

Bash / 우분투
$ colcon build && source install/setup.bash
$ ros2 launch my_first_package turtlesim_and_teleop.launch.py
launch <패키지> <launch파일>run이 "노드 하나"라면 launch는 "대본 하나(=노드 여러 개)". 파일명은 관례적으로 이름.launch.py.
