[실기 Go2 X 1] 앱과 로봇이 어떻게 이어지나

웹이나 휴대폰에서 낸 명령은 앱 서버를 지나 로봇 위 Jetson 의 agent 에 닿는다. 지금 실기는 Unitree 순정 보행 (Sport 경로) 하나로만 움직이고, 우리 정책은 사용자 브라우저의 앱 시뮬 안에서만 돈다. 실기에서 우리 정책을 돌릴 부품 셋은 앞으로 만든다.

그림 ① 전체 구조

오른쪽 아래 점선 상자 셋 (모드 관리자 · 저수준 실행기 · 안전 정지) 이 「만들 것」 이다. 실선은 지금 오가는 길, 점선은 만들 길이다.

자리무엇상태
사용자브라우저 웹 화면 · 앱 시뮬 (MuJoCo wasm + onnxruntime-web, 탭 안에서 돎)있음
사용자Android 앱 1.2.3-dev (Capacitor)있음
사용자iOS 앱계획 · 빌드 없음
앱 서버Caddy 443 (HTTPS) → API (uvicorn) → PostgreSQL 16 · GPU 안 씀있음
앱 서버주소 foothold-project.dev (app. · api. = A 레코드 · site. = CNAME)계획
Jetson서버 연결 (agent 가 먼저 wss 로 붙음 · 0.05 초 틱)있음
Jetson명령 출처 하나 (phone · nav2 · server) · lease 한 사람 · STOP 이 먼저있음
JetsonSport 경로 SportClient.Move(vx, vy, wz) · 서버 허용 값 9 개있음
Jetson모드 관리자 · 저수준 실행기 (ONNX + LowCmd) · 안전 정지 (Damp)계획
Jetsonagent 가 실제로 돌고 있나 (11/19 서비스는 enabled 인데 launch.py 가 없어 failed · 9539 · 9611 창구 안 열림)안 돎 · 실행 미확인

그래서 정책 계산은 두 곳뿐이다. 앱 시뮬은 브라우저 안 (있음), 실기는 Jetson 안 (계획). 서버는 명령과 상태만 나르고, 실시간 제어 고리는 Jetson 안에서만 돈다.

그림 ③ 명령 주인은 하나

로봇에 명령을 보내는 길은 agent 안 모드 관리자 하나만 둔다. 모드를 바꿀 때는 지금 모드 멈춤 → 정지 확인 → (저수준으로 갈 때만) Sport 서비스 해제 → 다음 모드 시작. 제안 · 팀장 01:27 「방법 제시 확인」

멈추는 말 셋

이름관절은언제상태
멈춤 (Stop)서 있음. Sport 는 Move(0,0,0) → StopMove, 저수준은 명령만 0평소있음 Sport 계획 저수준
안전 정지 (Damp)Kp 0 · Kd 만 → 천천히 앉음정책 이상 · 넘어짐 · 0.3 초 통신 끊김계획
조이스틱 L2+B순정 Damping (무름)언제나있음 순정 계획 직접 읽기
  • 저수준 모드에서 순정 L2+B 가 듣는지 미확인. 그래서 실행기가 LowState 의 wireless_remote 칸을 직접 읽어 L2+B 면 안전 정지로 간다.
  • Sport 멈춤이 계단 위에서도 서 있는지 미확인.

우리 모드 핫키 조합 (예: L1 + 방향키) 은 아직 정하지 않았다. 순정 조합과 겹치는지 먼저 본다. 앱 키보드 · 앱 시뮬 · 실기 조이스틱이 같은 입력 해석을 쓰면 「같은 입력에 시뮬과 실기가 같은 행동」 인지 바로 견줄 수 있다.
