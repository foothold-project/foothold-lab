# FOOTHOLD 웹 산출물 — 디자인 규칙

> **이건 완성된 디자인 시스템이 아니라, 이미 지키고 있는 규칙의 기록이다.**
> 새 레이아웃이 생기면 규칙이 뒤집히는 게 아니라 여기에 **추가**된다.
>
> 각 규칙에는 **왜**가 붙어 있다. "어두운 배경엔 밝은 글씨"만 적으면 안 지켜지고,
> "2026-08-05에 이걸 어겨서 도식이 안 보였다"까지 적으면 지켜지기 때문이다.
>
> 대상: `05_deliverables/` 의 모든 HTML. 팀원 누구든 이 사이트를 건드리기 전에 읽는다.

## 1. 색 토큰 — 다섯 갈래뿐이다

**새 색을 만들지 않는다.** 아래 다섯 갈래 + soft 변형이 전부다.

```css
:root{
  --paper:#f6f5f1;  --paper-2:#eeece6;  --card:#fff;
  --ink:#161c26;    --ink-2:#4a5566;    --ink-3:#7c8798;
  --rule:#d9d6cd;
  --dim:#0e7a6e;    --dim-soft:#e0f0ed;    /* 정상 · 정답 · 우리 것 */
  --note:#a86a08;   --note-soft:#fbf0dc;   /* 주의 · 미확인 · 함정 */
  --stop:#a3342a;   --stop-soft:#fbe9e7;   /* 금지 · 실패 · 없는 것 */
  --grid:rgba(22,28,38,.04);
}
```

| 토큰 | 언제 쓰나 | 예 |
|---|---|---|
| `--dim` | 정상 · 정답 · **우리가 채택한 것** | 논문 카드 테두리, 체크 통과, 숫자 강조 |
| `--brand` | **브랜드 대표색** (= 지금은 `--dim` 과 같은 값) | 로고, Hero, README, 굿즈 |
| `--note` | 주의 · **미확인** · 함정 | 「쓰면 안 되는 것」 표, 함정 5개, 실전 기록 |
| `--stop` | **금지** · 실패 · **없는 것** | 실패 카드, "센서가 없음", 금지 주장 목록 |
| `--ink-3` | 부차 정보 · 출처 | 캡션, 비고 칸 |

### 규칙 1-0 — **브랜드색과 상태색은 이름을 분리한다** (값은 당분간 같다)

```css
--brand:#0e7a6e;   /* 브랜드 대표 — 로고·Hero·굿즈 */
--dim:var(--brand); /* 상태: 정상·채택 — 웹 문서 (기존 코드 그대로 동작) */
```

> **왜** — `--dim` 하나가 *브랜드색*이자 *"정상/채택" 상태색* 두 역할을 겸하고 있다.
> 웹 문서만 만들 때는 편했지만, 포스터·PPT·README Hero·스티커로 확장하면
> "브랜드색을 바꾸고 싶은데 바꾸면 체크 통과 표시까지 바뀌는" 충돌이 난다.
>
> **지금 할 일은 이름만 나누는 것이다.** 값은 같게 두고 `--dim` 은 alias 로 남긴다.
> 기존 CSS·SVG 를 한 줄도 안 고쳐도 되고, 나중에 브랜드색이 바뀌면 `--brand` 만 바꾼다.
> ⚠️ **`--dim` 을 지우지 않는다.** 웹·도식·영상 컴포지션에 수백 곳이 참조 중이다.
> 새로 쓰는 브랜드 표현물만 `--brand` 를 쓴다.

### 🔴 규칙 1-1 — 변수는 **모든 페이지의 `:root`에 다 넣는다**

> **왜** — 커리큘럼 카드를 index 에 추가하면서 `var(--stop)` 을 썼는데
> index 의 `:root` 에만 그 변수가 없었다. 백과·커리큘럼에는 있었다.
> 그래서 **첫 카드의 테두리와 태그 색이 통째로 적용되지 않았다.**
> CSS 는 정의 안 된 변수를 **조용히 무시한다** — 에러가 안 난다.

새 페이지를 만들 때는 위 블록을 **통째로** 복사한다. 일부만 쓰지 않는다.

### 규칙 1-2 — 토큰의 **최종 원본은 이 문서가 아니다** (v1 예고)

지금은 각 페이지 `:root` 복사가 원본이다. 페이지가 8개라 아직 감당되지만,
브랜드 자산(Figma·SVG·발표자료)이 붙으면 값이 갈라진다.

**v1 이행 방향** — `brand/tokens/foothold.tokens.json` 을 단일 원본으로 두고
CSS 는 **생성물**로 만든다. 그때 이 문서는 값을 다시 적지 않고 **원본 파일을 가리키기만** 한다.

> ⚠️ **지금 옮기지 않는다.** 사이트가 잘 돌고 있고, 토큰 파이프라인은
> 브랜드 레이어(`FOOTHOLD Design System v1`, Codex 담당)와 함께 도입해야 한 번에 끝난다.
> 이 문서는 **웹 구현 기준**을 지키고, 브랜드 상위 레이어는 별도로 정의한다.
> 상세: [`../FOOTHOLD_DESIGN_SYSTEM_V1_HANDOFF.md`](../FOOTHOLD_DESIGN_SYSTEM_V1_HANDOFF.md)

## 2. 대비 — 어두운 배경엔 반드시 밝은 글씨

### 🔴 규칙 2-1

| 배경 | 글씨 |
|---|---|
| `--ink` (진한 남색) | `--paper` 또는 `#fff` |
| `--dim` (진한 초록) | `#fff` |
| `--dim-soft` · `--note-soft` · `--stop-soft` | `--ink` 계열 |
| `--card` · `--paper` | `--ink` 계열 |

> **왜** — ASCII 도식을 SVG로 바꾸면서 강조 박스를 `fill:var(--ink)` 로 칠하고
> 글씨도 `fill:var(--ink)` 로 뒀다. **어두운 남색 위에 어두운 남색 글씨** —
> "②정책 (신경망)" 이 통째로 안 보였다.
>
> 지금은 **강조를 어두운 채움으로 하지 않는다.** `--dim-soft` 배경 + `--dim` 테두리로 한다.
> 진한 채움이 꼭 필요하면 글씨를 `#fff` 로 명시한다.

### 규칙 2-2 — SVG 안에서는 `fill`, HTML 에서는 `color`

SVG `<text>` 는 `color` 가 아니라 `fill` 로 색이 정해진다. 클래스를 만들 때 헷갈리지 않는다.

---

### 🔴 규칙 2-3 — 연한 배경(`--*-soft`) 위 글자에 `--dim`/`--note`를 쓰지 않는다

```css
--dim-ink:#0b6459;   /* --dim-soft 위에 올릴 때 */
--note-ink:#8a5600;  /* --note-soft 위에 올릴 때 */
```

> **왜** — 실측하니 `--dim` on `--dim-soft` = **4.43**, `--note` on `--note-soft` = **3.93**.
> 둘 다 4.5:1 미달이다. "우리 토큰이니 괜찮겠지"가 통하지 않는다.
> 어두운 모드에서는 soft 배경이 어두워지므로 원래 토큰이 이미 충분하다 — **밝은 모드만** 갈아끼운다.
> 확인법은 §9의 대비 측정 스크립트. 눈으로 판단하지 않는다.

## 3. 본문 폭 — 페이지 유형별로 고정

| 유형 | `--measure` | 왜 |
|---|---|---|
| 스크롤 문서 (백과 · 커리큘럼) | **720px** | 한글 본문 한 줄 약 45자 |
| 절차 문서 (setup) | **760px** | 코드 블록이 넓어야 줄바꿈이 덜 남 |
| 요약 문서 (brief) | **780px** | 표가 많음 |
| 슬라이드 (team-intro) | 해당 없음 | 화면 전체 |

### 🔴 규칙 3-1 — `ch` 단위를 쓰지 않는다

> **왜** — `ch` 는 숫자 "0" 글리프 폭 기준인데 **한글은 대략 2배 폭**이다.
> `66ch` 로 잡으면 한글은 33자밖에 안 들어가 지나치게 좁아진다. **px 로 지정한다.**

### 규칙 3-2 — 도식은 본문 폭 제한을 벗어난다

`figure.fdia` 는 `max-width:none`. 본문은 읽기 폭을 지키되, 도식은 컬럼 전체를 쓴다.
그래야 SVG 안 글자가 본문 대비 적정 크기로 렌더된다.

## 4. 페이지 유형 — 두 가지뿐이다

### ① 스크롤 문서 — `index` · `encyclopedia` · `setup` · `brief`

```
.top      상단 바 (sticky)  ← 「← 표지로」 + 「PDF 저장」
.wrap     본문 (max-width: --measure + 4rem)
  .hero   표지 블록
  section 각 절 (id 로 앵커)
.foot     하단
```

### ② 슬라이드 문서 — `team-intro` · `curriculum`

```
section.slide          한 장. .on 이 붙은 것만 표시
  .head / .eyebrow     상단 머리
  본문 블록 (flex:1)    ← 여기가 세로 정렬을 담당
하단 이전/다음 바
```

### 규칙 4-1 — 필수 요소 (모든 페이지)

- `<meta name="viewport" content="width=device-width,initial-scale=1">`
- `@page{ size:A4 …; margin:14mm 12mm; }`
- `.pdfbtn` + `window.print()`
- `← 표지로` 링크 (index 제외)
- 32px 격자 배경 (`--grid` 2겹 linear-gradient)

## 6. 네임스페이스 — 새 클래스에는 접두사

### 🔴 규칙 6-1 — 원본이 이미 쓰는 이름을 확인하고 짓는다

> **왜** — 도식 컴포넌트를 `.dia` 로 지었는데, 팀원이 쓴 원본에 이미
> `<pre class="dia">` (ASCII 도식) 가 있었다. 결과:
> ① 캡션이 **monospace 로 렌더**됐고 ② `overflow:auto` 가 툴팁을 잘라냈다.
> `.fdia` 로 바꿔 해결했다.
>
> **새 클래스를 만들기 전에 `grep 'class="이름"'` 을 먼저 돌린다.**

접두사 규칙: 도식 `f`(figure) · 논문 `p`(paper) · 실전 `fl`(field) · 실패 `fx`.

### 🔴 규칙 6-2 — 두 문서를 합칠 때는 CSS 를 **범위 격리**한다

> **왜** — 킥오프를 팀소개에 병합할 때 두 문서가 `.eyebrow` · `h1` · `h2` · `.sub` 등
> **43개 선택자를 다른 값으로** 쓰고 있었다. 그대로 합치니 팀소개 레이아웃이 무너졌다.
>
> 해법: 합쳐 오는 쪽 섹션에 `data-deck="ko"` 를 달고, 그쪽 CSS 전체를
> `[data-deck="ko"]` 로 좁혀 이관한다. 전역 규칙(`:root` · `html` · `body` · `#deck`)은 이관하지 않는다.

### 🔴 규칙 6-3 — CSS 를 파싱하기 전에 **주석을 제거**한다

> **왜** — 범위 격리 스크립트가 `/* ... */` 주석의 앞부분을 **선택자로 오인**해
> `[data-deck="ko"] 좌측 표를 그 안에서 ... */` 같은 깨진 CSS 를 만들었다.
> **그 지점부터 파싱이 무너져 뒤따르는 규칙이 통째로 무시됐고**, 슬라이드 3장의 세로 정렬이 사라졌다.
>
> `strip_comments()` 를 먼저 돌리고, **"격리를 벗어난 규칙이 하나라도 있으면 빌드 중단"** 검사를 둔다.

### 규칙 6-4 — SVG 안에는 HTML 태그를 넣지 않는다

> **왜** — 용어 툴팁(`<span class="term">`)이 SVG `<text>` 안의 "IMU" 에 주입돼
> **SVG 파싱이 그 지점에서 끊겼다.** 도식 절반이 사라지고 나머지가 글자로 흩어졌다.
>
> 주입 순서를 뒤집고(용어 → 도식), **"SVG 안에 term 이 있으면 빌드 중단"** 검사를 넣었다.

## 7. 인쇄 · PDF — 오늘 배운 함정 다섯

### 규칙 7-1 — `@page` 는 **모든 페이지에** 넣는다

```css
@page{ size:A4 portrait; margin:14mm 12mm; }   /* 문서 */
@page{ size:A4 landscape; margin:0; }          /* 슬라이드 */
```

> **왜** — index 에만 `@page` 가 없어 **US Letter(612×792)** 로 출력됐다. 나머지는 A4였다.

### 🔴 함정 ① 애니메이션이 걸린 요소는 인쇄에서 **투명하게 잡힌다**

> 커리큘럼 `.slide` 에 `animation:fade` 가 걸려 있어 인쇄 시 `opacity:0` 상태로 캡처됐다.
> **PDF 54쪽이 전부 백지.** 인쇄 블록에서 `animation:none!important; opacity:1!important` 로 해제한다.

### 🔴 함정 ② 닫힌 `<details>` 는 `display:block` 만으로 안 펼쳐진다

> 크롬은 `content-visibility` 로 숨긴다. 인쇄에서 함정 5개 내용이 통째로 빠졌다.
> ```css
> details:not([open])>*:not(summary){content-visibility:visible!important}
> details::details-content{content-visibility:visible!important;block-size:auto!important}
> ```
> 여기에 `beforeprint` 훅으로 `open` 을 세팅하는 이중 안전장치를 둔다.
>
> **⚠️ 재발함(2026-08-05).** 용어 사전의 「자세히」(`details.gmore`)를 새로 만들면서
> 이 규칙을 적용하지 않았다. PDF 에 **링크 79개 중 26개만** 찍혔고,
> 접힌 본문(짐벌락·MuJoCo 한계 등)이 통째로 빠졌다.
> **규칙이 문서에 있어도 새 컴포넌트에 옮겨 적지 않으면 그대로 재발한다.**
> `<details>` 를 새로 쓸 때마다 이 절을 다시 읽는다.
> 확인법 — PDF 를 뽑아 **접힌 안쪽에만 있는 문구**를 grep 한다. 쪽수·백지 수만 보면 못 잡는다.

### 🔴 함정 ③ **인쇄 폭이 모바일 분기에 걸린다**

> A4 세로 폭이 595px 라 `@media (max-width:700px)` 같은 모바일 규칙이 **인쇄에도 적용된다.**
> `overflow-x:auto` 가 도식을 잘라내고 `position:sticky` 캡션이 흘러내렸다.
> 인쇄 블록에서 모바일 규칙을 **명시적으로 해제**한다.

### 🔴 함정 ④ flex 컨테이너는 페이지 분할이 불안정하다

> 크롬이 flex 컨테이너를 페이지 경계에서 쪼갤 때 SVG 가 깨졌다.
> 인쇄에서는 `display:block` 으로 바꾼다.

### 🔴 함정 ⑤ `white-space:pre` 가 상속돼 캡션 줄바꿈이 죽는다

## 11. 외부 링크 — 사이트가 아니라 **등급**으로 통일한다

### 배경 — 이 분야엔 위키피디아 같은 단일 정본이 없다

ML 용어 백과 노릇을 하던 **Papers with Code 는 2025-07-24 폐쇄**됐다
(후속인 Hugging Face *Trending Papers* 는 논문 피드지 용어 백과가 아니다).
그래서 "한 사이트로 통일"은 애초에 불가능하다.

### 규칙 11-1 — 링크에는 반드시 **등급 배지**를 단다

| 배지 | 무엇 | 언제 |
|---|---|---|
| `공식` | 그 도구·규격을 **만든 곳**의 문서 | 도구·버전·설정 |
| `교재` | 표준 교재·강의의 **무료 공개본** | 개념의 정의 |
| `논문` | **arXiv abs** 영구링크 | **숫자를 인용할 때는 반드시 여기** |
| `해설` | 정평 난 해설(Spinning Up · Lil'Log) | 빠른 이해. **정본 아님** |
| `백과` | 영문 위키피디아 | 물리·수학 **일반 용어에만** |

적용 순서는 **공식 → 교재 → 논문 → 해설 → 백과**. 위에서부터 있는 것을 쓴다.

> **왜 배지를 보여주나** — 우리는 이미 **블로그 수치를 논문 수치로 착각**해
> 카드 5장을 배포한 뒤 고쳤다. 읽는 사람이 *정본인지 해설인지 알고* 읽어야 그 사고가 안 난다.

### 규칙 11-2 — 링크는 **한 곳에만** 쓴다

`_build/glossary.py` 의 `LINKS` 딕셔너리가 유일한 원본이다.
카드 정의(`MORE`·`NEW`) 안에 URL 을 적지 않는다.

> **왜** — 처음엔 카드마다 인라인으로 적었는데, 같은 URL 이 흩어져 있어
> 등급을 붙이려면 전수 수정이 필요했다. 한 곳이면 정책이 바뀌어도 한 번에 끝난다.
> `LINKS` 에 카드 없는 slug 가 있으면 빌드가 선다(고아 가드).

### 🔴 규칙 11-3 — 위키피디아는 **리다이렉트를 확인하고** 건다

```bash
curl -sL "https://en.wikipedia.org/api/rest_v1/page/summary/<제목>" | python -c "…titles.canonical"
```

> **왜** — `Domain_randomization` 은 **문서가 없고** 뜻이 다른 `Domain_adaptation` 으로 넘어간다.
> HTTP 200 만 보면 통과한다. **200 은 "그 문서가 있다"는 뜻이 아니다.**
> `Series_elastic_actuator`(→`Actuator`) 도 같은 함정이었다.
> `Sim-to-real_transfer` · `Temporal_convolutional_network` · `Disturbance_(control)` 는 아예 404다.

### 규칙 11-4 — 넣기 전에 **전부 실측**한다

HTTP 200 + 리다이렉트 확인. `doi.org`·IEEE·Semantic Scholar 는 봇 차단(202)이라 쓰지 않는다.
확인한 날짜를 `glossary.py` 머리말에 적는다.

### 🔴 규칙 5-0 — **웹 밖으로 나가는 컴포지션에도 리셋을 옮겨 적는다**

영상 씬(hyperframes)·독립 HTML 은 사이트 CSS 를 상속받지 않는다.
`*{margin:0;padding:0;box-sizing:border-box}` 를 **매번 다시 쓴다.**

> **왜** — 영상 씬에서 오른쪽 컬럼이 화면 밖으로 잘렸다.
> `width:1080px` + `padding:0 40px` 인데 `box-sizing` 기본값이 `content-box` 라
> 실제 폭이 **1160px** 이 되었다. 사이트에는 리셋이 있는데 씬에 안 옮겨 적었다.
> §7 함정② 와 **같은 부류의 사고**다 — 규칙이 있어도 새 매체에 옮기지 않으면 재발한다.
>
> 확인법 — 렌더한 mp4 에서 프레임을 뽑아 **가장자리 픽셀**을 본다.
> ⚠️ 단, 전폭(full-bleed) 요소가 있으면 그 자체가 가장자리에 닿으므로
> **의도된 전폭과 잘림을 구분**해야 한다. (그 구분을 안 해서 오탐이 났다.)

### 규칙 5-1 — 코드 블록에는 **문법 강조**를 넣는다

`_build/hl.py` 가 단일 원본이다. 지원: `powershell` · `python` · `bash`.
언어를 못 알아보면 **강조하지 않는다** — 잘못 칠하느니 안 칠하는 게 낫다.

> **왜** — 팀원이 복사해서 그대로 실행하는 코드다. 전부 같은 색이면
> **명령·인자·경로가 구분되지 않아** 붙여넣기 전에 눈으로 검증할 수 없다.
> 실제 PowerShell/Python 창의 색감에 맞춰, 화면과 문서를 오갈 때 같은 것이 같게 보이게 한다.
> 외부 CDN 금지이므로 highlight.js 류를 쓰지 않는다.

### 🔴 규칙 5-2 — 강조는 **HTML 엔티티를 쪼개면 안 된다**

> **왜** — 주석 규칙 `#[^
]*` 이 `&#x27;` 안의 `#` 을 물어서
> `&` 와 `#x27;` 사이에 `<span>` 이 끼었다. 화면에 **`&#x27;` 가 글자 그대로** 찍혔다.
>
> 더 나쁜 건 **검사를 통과했다는 것**이다 — 태그를 떼고 unescape 하면 원문이 복원되니까.
> 그래서 `hl.verify()` 는 두 가지를 본다: ① 원문 보존 ② **엔티티 무결성**.
> 엔티티 구간을 원자로 보고, **반만 덮는 매치는 버린다.**
> (통째로 덮는 건 허용해야 한다 — `&quot;YES&quot;` 는 문자열로 칠해져야 정상이다.
>  처음엔 엔티티를 통째로 선점시켰다가 문자열 강조가 전부 사라졌다.)

## 12. 사실 정확성 — 사람이 다시 읽는 방식은 반드시 무너진다

### 배경

사이트가 커지면서 검증 가능한 사실 주장이 수백 개가 됐다.
그중 상당수는 **남이 관리하는 것**이라 우리 모르게 바뀐다 —
라이브러리 최신판, 공식 문서 문구, 지원 태스크 목록.
그때 우리 사이트는 **조용히 거짓말을 시작한다.** 아무 에러도 안 난다.

### 규칙 12-1 — 검증 가능한 주장은 `_build/claims.py` 에 등록한다

```bash
python _build/build.py --verify   # 배포 전 필수
```

각 주장은 **실제 원본을 조회하는 검사 함수**를 갖는다. 거짓이 되면 **빌드가 선다.**

| 넣는다 | 안 넣는다 |
|---|---|
| 라이브러리 최신 버전 · 태그 존재 | 우리가 잰 실측치 (안 바뀐다) |
| 공식 문서의 원문 문구 | 해석 · 의견 · 설계 결정 |
| 지원 목록에 무엇이 있고 없는지 | 남이 안 바꿀 사실 |
| 외부 자산(체크포인트) 생존 | |

실측치는 검증이 아니라 **출처 표기**가 목적이므로 `claims.MEASURED` 에 둔다.

### 🔴 규칙 12-2 — HTTP 200 은 "그 문서가 있다"는 뜻이 아니다

리다이렉트 **목적지**까지 본다. §11-3 참조 (`Domain_randomization` → `Domain_adaptation`).

### 규칙 12-3 — 단정형으로 쓸 때는 **원문을 인용할 수 있어야** 한다

> **왜** — "Newton은 험지 로코모션 미지원"이라고 반년을 써 놓고, 근거 문서를 링크하지 않았다.
> 확인해 보니 **사실이었지만**(원문: *"only a limited set of ... flat terrain locomotion ... examples"*),
> 확인하기 전까지는 **우리도 그게 맞는지 몰랐다.** 맞았던 건 운이다.
> 검증 가능한 형태로 다시 쓰면 더 강해진다 —
> *"지원 태스크 목록에 `Isaac-Velocity-Rough-Unitree-Go2-v0` 가 없다"* 는 **이름으로 반박 불가**하다.

### 규칙 12-4 — 확정과 미확정을 **시각적으로** 구분한다

`미확인 / 미정 / 미설치 / 미조사 / 미측정` 은 빨간 배지(`.unk`)로 표시한다.

> **왜** — 팀원이 둘을 구분 못 하면 *"스트리밍으로 5명이 각자 본다"* 같은 잘못된 계획이 선다.
> 스트리밍 다중 접속은 **미확인**이다.

### 🔴 규칙 12-5 — 배포 전 **민감정보 검사는 코드로** 한다

```bash
python _build/build.py          # [4] 단계가 자동으로 검사한다
python _build/scan.py           # 따로 돌릴 때
```

- **복사한 뒤** 검사한다. 볼트가 아니라 **실제로 공개될 파일**을 봐야 한다.
- `REDACT` — 원문(private 볼트)은 실제 값을 유지하고 **웹으로 나갈 때만** 자리표시자로 바꾼다.
- `ALLOW` — 통과시키려면 **사유와 날짜를 적어야** 한다. 그 한 줄이 "알고 넣었다"는 증거다.

> **왜** — 2026-08-05 팀원 가이드에 워크스테이션 LAN 주소가 그대로 공개 저장소로 나갔다.
> `foothold-site` 는 PUBLIC 이고 **한 번 push 하면 되돌려도 히스토리에 남는다.**

### 🔴 규칙 12-6 — 탐지기는 **자기가 작동하는지 먼저 증명**한다

`scan.SELFTEST` 가 매 실행마다 알려진 샘플 15개를 실제로 잡는지 확인한다.

> **왜** — 첫 판에서 사설 IP 정규식이 옥텟을 잘못 세어 `<워크스테이션>` 를 못 잡았다.
> 화면에는 **"민감정보 없음"** 이라고 떴다.
> **아무것도 못 잡은 것과 잡을 능력이 없는 것은 화면에서 똑같아 보인다.**
>
> 같은 함정을 CSS 주입에서도 밟았다 — `'.cb pre .k{' not in s` 로 판정했는데
> 원본에 이미 그 선택자가 있어서 주입을 통째로 건너뛰고도 "CSS OK" 로 보였다.
> **존재 검사는 "우리만 쓰는 표식"으로 한다.**

### 13-1. 기존에 걸리는 것은 명부에 적고 시작한다

새 관문을 켜면 대개 **이미 걸리는 것이 여럿** 나온다. 그것을 그 자리에서
전부 막으면 관문이 못 들어온다. 그래서 **켜는 날의 위반은 명부에 적고,
그 뒤로 «늘어날 때만» 막는다.**

```
brand_grandfather.txt · ascii_grandfather.txt · metacheck_grandfather.txt
pagesloop_grandfather.txt · emptycheck_grandfather.txt
```

**명부는 면제가 아니다.** 매 빌드에 줄 수를 찍고, 늘어나면 막는다.
그 줄 수가 남은 일의 크기다. 줄이면서 지운다.

명부 없이 켤 수 있으면 그게 제일 좋다. 위반이 0이라 명부가 빈 채로
시작하는 관문도 있다.

### 13-2. 되돌릴 수 없는 것 앞에서만 막는다

**막는 것이 많아지면 사람이 관문을 우회한다.** 빌드가 쉰 번 서면 쉰
번째에는 `--yes` 를 붙이게 되고, 그때부터 그 관문은 없는 것과 같다.

**막는다** — 셋 중 하나일 때만.

| | 왜 |
|---|---|
| 공개되면 되돌릴 수 없다 | 민감정보 · 금액 · 개인정보. 한 번 나가면 회수가 안 된다 |
| 배포본이 «틀린 것을 말하거나 깨진 화면» 을 낸다 | 읽는 사람이 그걸 근거로 판단한다 |
| 산출물이 아예 안 만들어졌다 | 생성 실패. 이건 검사가 아니라 빌드가 죽은 것이다 |

**알린다** — 나머지 전부. 특히 셋.

| | 왜 |
|---|---|
| 지금은 안 깨졌는데 «막을 보장이 없다» | 위반이 아니라 «구조적 위험» 이다. 소리는 내되 세우지 않는다 |
| 이미 명부에 있는 빚 | 13-1 |
| 고칠 사람이 이 세션이 아니다 | 남의 저장소 · 남의 생성기. 막아도 여기서 못 고친다 |

실측 근거. 2026-09-14 에 `hub-research` 는 «실제로 깨져» 있었고 (29행이
화면에 그대로 남음) `hub-schedule` 은 «오늘은 안 새지만 안전망이 없는»
상태였다. 둘을 같은 무게로 막았고 그날은 운 좋게 한 줄로 둘 다 고쳐졌다.
고칠 사람이 마침 대기 중이었기 때문이다. 그것은 규칙이 아니라 운이다.

### 13-3. «무엇을 안 막는가» 를 함께 적는다

관문의 문서 첫머리에 **이 관문이 못 잡는 것**을 적는다. 안 적으면 다음
사람이 그 관문을 안전망으로 착각한다.

기준 사례는 `[3.4796] plan_vs_record.py` 다. 「분류: 계획」 문서를 실행
기록처럼 인용한 사고에서 나왔는데, 그 관문은 **「5종이 아니라 gap 하나」를
알 수 없다.** 실행 기록이 없으니 기계가 판단할 근거가 없다. 그래서 문서
머리에 그렇게 적혀 있다.

적는 순간 **그 관문이 언제 쓸모없어지는지도 같이 정해진다.** 실행 기록이
채워지면 `[3.4796]` 은 역할이 바뀐다. 적어 두면 다음 사람이 언제 손봐야
하는지 안다.

### 13-4. 이 정책 자체를 관문이 본다

`gatepolicy.py` 가 각 관문 모듈에 13-3 이 적혀 있는지 본다. 이 관문도
13-1 을 따른다 — 켜는 날 안 적혀 있던 것은 `gatepolicy_grandfather.txt`
에 담고, **새로 생기는 관문만 막는다.**

**이 관문이 못 잡는 것**: 적혀 «있는지» 만 본다. 적힌 내용이 **맞는지는
못 본다.** 「없음」이라고 적어 두면 통과한다. 그건 사람이 읽고 판단한다.
