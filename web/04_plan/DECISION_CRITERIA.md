## 1. 손절선 (사용자 원문 요지)

> **"이 프로젝트가 우리에게(나에게) 남을 것이 무엇이며, 얻을 것이 무엇인가."**
> 1등할 수 없는 프로젝트라면 — 즉 **단순 프로젝트 하나 했다로 끝나는 것**이라면 접는다.

- 손절선은 **"못 한다"가 아니라 "해봐야 남는 게 없다"**이다.
- ★ 기각된 손절선 후보(에이전트 가설, 사용자가 반박):
  - ~~"산업 용도를 못 찾겠다"~~ → **Go2가 실제로 판매·개발되는 제품이라는 사실 자체가 수요의 증거.** 못 찾으면 시장이 없어서가 아니라 조사가 부실한 것
  - ~~"멘토를 못 만난다"~~ → 매칭데이에서 못 만나도 **프로젝트 진입 후 담당 멘토가 배정된다.** 매칭데이는 "정보를 더 정확히·더 일찍 얻는 자리"지 유일한 기회가 아니다. 리스크지 손절선 아님

## 2. 이 프로젝트로 얻어야 하는 것 (전부, 사용자 열거)

1. **포트폴리오**
2. **취업 전선 투입 가능한 무기**
3. **기술적 인정**
4. **대학원 진학에도 유효한 것** (진로 100% 확정은 아님)
5. **사관학교 최우수 성적** → 우수생 → **인턴십 + 해외연수** ⚠️ *해외연수는 사용자 진술, 볼트 내 공식 근거 미확보*
6. **본인이 가려는 방향으로 가는 힘의 시너지와 관성**

## 3. ★ 볼트가 이미 확인한 사실 — 보상 구조가 "팀 1등"과 분리돼 있다

`02_LEARNING/doyak-handbook.md` §5·§8·§11 기준:

| 항목 | 확인된 사실 | 신뢰도 |
|---|---|---|
| **배점표·평가 기준표·심사 방식** | **두 공식 PDF 모두에 없음** (fabrication 방지 차원에서 명시됨) | 확인됨(부재가 확인됨) |
| **인턴십 트리거** | 성적순·랜덤이 아니라 **"프로젝트에서 두각을 나타내는 사람 = 팀 리딩·발표·PM"**에게 이스트소프트가 자체 베네핏 부여 | 구두 브리핑 출처, **공식 문서 근거 없음** |
| 팀 배정 | 학생별 정량 점수(시험 포함)로 밸런스 배정 | 구두 브리핑 |
| 진행 구조 | 중간점검 → 멘토 자문 → 결과 보완 → 최종발표·성과공유 | 공식 PDF |
| 우수교육생 선발 기준 | **두 PDF 모두에 없음.** 구두로 "월말평가 합산, 출석 비중 큼, 시험 ~7%" | 구두 |

**함의**: 개인 베네핏(인턴십)의 트리거가 **팀 순위가 아니라 개인의 PM·발표·리딩 두각**이라면, 손절선 "1등 못 하면 접는다"는 재검토 대상이다. 주제는 "1등용"이 아니라 **"내가 PM으로 이끌고 서사를 만들 수 있는가"**로 판단해야 할 수 있다.
→ ⚠️ 단 이 정보는 구두 출처다. **멘토·운영진에게 확인할 질문 목록(4순위)에 반드시 포함할 것.**

## 4. ★ 1등 공식 — 사용자가 3회 검증한 것 (본인 진술)

> *"단순히 기술적으로 이거 했어요가 아니라 — **왜 이 기술적 탐구를 했고, 그 결과 무엇을 보여주고 의미할 수 있는지, 그게 비즈니스적으로 좋은 ROI 평가를 받을 수 있는지**에 대해 아주 심도 있는 고찰을 했다. 이 기술로 만든 서비스·기획이 **문제 정의의 본질을 꿰뚫고 PRD에서 우수했기 때문**이라고 생각한다. 기술적으로도 그 목적에 맞는 탄탄함이 있었다."*

- **작동 순서**: 대주제 → 소주제로 좁힘 → 인접 기술로 확장 → 하나의 시스템 → 결과로 우수성 입증 (SKN 패턴)
- **전제 조건**: *"그게 나에게 설득이 되어야 한다."* 스토리텔링이 **비즈니스적으로도, 문제해결 방법으로서도 둘 다** 충족돼야 함
- 실증 사례: `RAG를 통한 사내 문서 연결 AI Agent` 대주제 → 소주제 → PRD 기획부터 탄탄 → 1등

### ★ 이번이 다른 단 하나의 지점 (핵심 진단)

사용자 본인 관찰: *"지금은 주제가 구체적으로 정해져 있는 상태로 시작한다는 점이 다르다. 상황은 다르지만 본질은 다르지 않다고 본다."*

**에이전트 진단**: 그 차이는 순서의 역전이다.
- **기존 승리 공식** = 문제 → (해결에 필요한) 기술
- **이번 출발점** = 기술("Online Adaptation 정책 개발") → 문제 없음

주제 원문은 **비즈니스 문제 서술이 아니라 연구 과제 서술**이다. 즉 **PRD가 아직 존재하지 않는다.**
→ **2순위 작업의 정확한 정의 = "역전된 순서를 되돌리는 것".** 주어진 기술에서 출발해 거꾸로 문제·사용자·ROI를 찾아내 PRD를 만든다. 그게 되면 이 프로젝트는 기존 1등 공식 위에 올라서고, 안 되면 손절선에 걸린다.

## 5. 산출물이 통과해야 하는 체크 (이 문서의 실사용법)

2·3·5순위 산출물은 아래를 전부 통과해야 한다. 하나라도 "아니오"면 미완성이다.

- [ ] **누가** 이걸 손에 쥐고 **무엇**을 하는가가 한 문장으로 나오는가 (기술 설명 말고)
- [ ] 그 사람이 지금 겪는 고통이 **숫자**로 제시되는가
- [ ] 우리가 만든 것이 그 숫자를 **얼마나** 바꾸는가 (ROI)
- [ ] 이 기술적 탐구를 **왜** 했는지가 결과와 연결되는가
- [ ] 어디서 멈춰도 **그 자체로 완결된 이야기**가 되는가
- [ ] 팀원 5인이 각자 **자기 것으로 설명**할 수 있는가
- [ ] 사용자 본인이 **납득**하는가 ← 최종 게이트

## 6. 미확인 (반드시 확인할 것)

- **해외연수 베네핏의 존재·조건** — 사용자 진술뿐, 볼트 내 공식 근거 없음
- **심사 배점·평가 항목** — 공식 PDF에 부재 확인됨. 별도 안내 자료가 나오는지 운영진에 확인
- **"두각→인턴십"의 정확한 판정 주체·시점** — 구두 출처
- 최종 발표 일시·형식·시간 제한
