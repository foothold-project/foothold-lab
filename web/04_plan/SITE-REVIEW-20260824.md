## 0. 한 줄 결론

**사이트는 '정보 전달성'에서는 최상급 발행물이지만, '잡지'로 설계된 것을 '작업 공간'으로 쓰고 있어 나머지 목적(생산성·찾기 효율·성장기록)에 구조적으로 실패하고 있다.** 원인은 콘텐츠가 아니라 **사람이 손으로 유지하는 구조(수기 index·수기 상태·수기 질문지도)가 문서 34개 규모에서 무너진 것**이다. DESIGN.md §12가 외부 사실에 세운 원칙 — *"사람이 다시 읽는 방식은 반드시 무너진다"* — 이 사이트 자기 자신의 구조·상태에는 적용되지 않았고, 지금 무너지는 게 바로 그 부분이다. 해법은 비주얼 리빌딩이 아니라 **IA(정보 아키텍처) 리빌딩 = 메타데이터 표준 + 구조의 생성물화**다.

## 4. 구조적 원인 5 (찾기 실패의 해부)

1. **수기 큐레이션 표지 하나가 IA의 전부.** 새 문서 1개 = index 카드 + questions 행 + README 표 + 각종 카운트를 사람이 N군데 수정. 자동 영역(`<!--research:auto-->`)은 연구 13편 중 3편만 내보내고 멈춰 있음.
2. **허브가 연구에만 존재.** `research.html`은 13편 전량 목록화. 회의·현장점검·digest 허브는 없음. 회의 3건은 "길잡이" 섹션에 덱·보고서와 뒤섞임. **index에서 연결 안 되는 페이지 11개**, digest는 `research.html:410` 배너가 유일 진입로인 완전 고아(index에 "digest" 언급 0회).
3. **돌아가는 길이 5표기·3구조·2목적지.** 전역 내비 없음. research 13편+digest는 홈 직행 링크가 없어 표지까지 2단계. 깨진 내부 링크 1건(`research-visual-evidence.html:518` → `training-benchmarks.html`, 올바른 파일명은 `research-training-benchmarks.html`).
4. **찾기 도구 2종이 둘 다 땜질.** questions.html = 수기·정체(§3). Ctrl+K 검색 = 34페이지 커버하나 깊이 극단 불균등 — **바이트 최대 4페이지(curriculum 268KB/38슬라이드·team-intro·project-report·pitch)가 검색 항목 각 1개** = 사실상 검색 불가.
5. **메타데이터가 통제 어휘가 아님.** 날짜·증거 카운트는 연구 페이지에만, 회의는 meta에 날짜 없음(파일명뿐), **저자 명시는 34페이지 중 1개**(project-report). 타입 태그는 자유 텍스트라 기계 분류 불가 → 아무 구조도 생성할 수 없음.

**근본 원인 한 줄**: 구조를 생성할 메타데이터가 없어 구조를 손으로 유지하고 있고, 규모가 그 방식을 넘었다. 이 실패 부류를 막는 도구(§10-0 md 생성 규칙, glossary.py 고아 가드, claims.py)는 **이미 팀에 있다** — 콘텐츠에만 적용하고 구조에는 적용하지 않았을 뿐.

## 5. 재점검(2차)에서 추가 발견 5

1. **이용 계측 0.** 34페이지 어디에도 방문 측정 없음(스크립트 grep 0건). "팀원이 읽는다"는 전제가 한 번도 실측된 적 없음 — 검증 조항 원칙 3의 자기 미적용. 리빌딩 우선순위 판단에 필요한 데이터가 부재.
2. **원본 체계 이원화 미명시.** site `README.md:46` "수정은 foothold-lab 이슈/lab docs로" vs `DESIGN.md` §9-1 "05_deliverables가 유일 원본". 실제는 문서 유형별 이원 파이프라인«추측: 연구·회의=lab, 가이드=볼트»인데 그 규칙이 어디에도 없음 → 기여 경로 불명 = 버스팩터 1 강화.
3. **글자 크기 규칙 부재.** index font-size 선언 26개 중 22개가 13px 미만, 최빈값 .55rem(≈8.8px). 대비는 규칙(§2-3)으로 방어했으나 크기는 규칙이 없음. 모바일·멘토 연령대에서 실질 비용.
4. **자료실 게이트 위협 모델 미결정.** PBKDF2+WebCrypto 클라이언트 복호화는 정적 사이트로선 준수한 설계. 단 공개 레포라 암호화 blob 19MB가 오프라인 무차별 대입에 노출, 방어력 = 디스코드로 공유한 비밀번호 강도. 수업 자료는 무방하나 **08-21 예산 문서가 이 게이트 아래 추가됨**(site 커밋 `67470c4`) — 의식적 결정 필요.
5. **미디어가 공개 레포 히스토리에 축적 중.** assets 60MB(video 21M·visual 19M·secure 19M). 지금 추세면 레포=미디어 저장소. 거처 결정 필요.

## 6. 리빌딩 방향 (우선순위순) — 비주얼이 아니라 IA

> 전제: 타이포·색 토큰·인쇄·다크모드는 상위 수준이고 DESIGN.md로 방어됨. **스킨은 건드리지 않는다.**

1. **[핵심] 메타데이터 표준 + 구조의 100% 생성물화.** 모든 원본 md에 front-matter 5필드 — `type`(연구/회의/가이드/참고/현장/digest) · `date` · `author` · `status`(living/snapshot/superseded) · `source`. index·허브·검색인덱스·questions를 전부 생성물로 전환. "페이지가 있는데 index에 없으면 빌드 중단"(고아 가드의 전 사이트 확장). → §4의 1·2·4·5를 동시 제거.
2. **자기 참조 사실의 검증.** 수기 `현재 상태` 블록은 lab LEDGER/보드에서 생성하거나 삭제(git 날짜 기반 "최종 갱신"으로 대체). 팀 인원·덱 장수·안건 수는 claims.py에 셀프 클레임 등록 — 틀리면 빌드가 선다.
3. **전역 내비 1종 + 5구역.** 시작하기(flow·collab·curriculum) / 지금(상태·plan·미결 안건) / 기록(회의·digest·타임라인 — 허브 신설) / 근거(research 허브) / 참고(encyclopedia·setup·자료실). 모든 페이지 동일 상단바, research 계열에 표지 직행(빵부스러기: 표지/연구 기록/현재 문서).
4. **시간축 페이지 신설.** "이번 주" 하나로 회의·digest·최근 갱신(git 날짜에서 자동 생성) 통합. digest는 주간 뼈대 자동 생성으로 부활 — 수동이면 W33처럼 또 죽는다. 전담 멘토(매일 오전 3시간)의 착륙 지점이 된다.
5. **저자 필드 소급 적용.** 성장기록·포트폴리오 목적의 최소 단위. 5개월 뒤 각자가 "내가 한 것"을 가리킬 수 있어야 한다.
6. **잔손질**: 깨진 링크 1건 수정 · 덱 4종 슬라이드 단위 검색 인덱싱 · questions.html은 "자주 묻는 질문 큐레이션"으로 역할 축소 · Vercel Analytics(또는 경량 계측) 도입 · DESIGN.md에 최소 글자 크기 규칙 1줄 추가.
