# Task 분해 — 칸반 운영용

> 작성 2026-07-30 · 팀 FOOTHOLD
> **이 파일은 GitHub Projects(또는 Linear) 카드로 그대로 옮기는 것을 전제로 쓴다.**
> 각 항목이 카드 하나이고, `DoD`가 카드의 완료 조건이다.

---

## 운영 규칙

| 항목 | 규칙 |
|---|---|
| **컬럼** | `Backlog` → `This Week` → `In Progress` → `Review` → `Done` |
| **WIP 제한** | 1인당 `In Progress` **최대 2장.** 넘으면 새로 시작하지 말고 끝내라 |
| **카드 크기** | **하루 안에 끝나는 크기.** 이틀 넘으면 쪼갠다 |
| **Review** | 다른 사람이 **재현해보고** 넘긴다. 혼자 Done으로 못 옮긴다 |
| **막힘** | 하루 이상 진전 없으면 `Blocked` 라벨 + 회의 안건 자동 등록 |
| **기록** | 실험 카드는 닫을 때 **설정·커맨드·결과·커밋해시**를 코멘트로 남긴다 |

**라벨**: `ENV`(환경·인프라) · `POLICY`(정책·학습) · `SCENE`(지형·시각화) · `TWIN`(공간재구성) · `DATA`(검증·지표) · `DOC`(문서·산출물) · `BLOCKED` · `GATE`

## GitHub Projects로 옮기는 법

1. 저장소 → **Projects** → **New project** → `Board` 템플릿
2. 컬럼을 위 운영 규칙대로 5개 생성
3. 이 파일의 각 항목을 **Issue**로 만들고 (제목 = `ID · 과업명`), 본문에 `DoD` 붙여넣기
4. 라벨(`ENV`/`POLICY`/`SCENE`/`TWIN`/`DATA`/`DOC`/`GATE`) 생성 후 부여
5. **Milestone**을 `W4` `W9` `W14` `W18` `W20`으로 만들어 게이트와 연결

> 대안: Linear·Notion도 무방하다. **중요한 건 도구가 아니라 "DoD가 붙어 있는가"와 "WIP 제한을 지키는가"**다.
