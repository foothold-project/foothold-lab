> 홈페이지 WBS 그림과 같은 데이터에서 나오면 `확정`.

## 왜 3층인가

이슈 제목을 그대로 WBS 에 넣으면 중구난방이 된다. 사람마다 쓰는 말이 다르기 때문이다.
**그래서 위 두 층은 우리가 미리 짜 두고, 이슈는 맨 아래 층에만 들어간다.**

| 층 | 무엇 | 누가 정하나 | 개수 |
|---|---|---|---|
| **1** | 작업 영역 | 사람 (고정) | 8 |
| **2** | 마일스톤별 산출물 | 사람 (관문마다) | 관문당 2~4 |
| **3** | 세부 작업 | **이슈에서 자동** | 계속 늘어남 |

1층과 2층이 **WBS 계획서**다. 발표 때 보여주는 큰 그림이 이것이고, 이슈가 하나도
없어도 그려진다. 3층은 진척률을 채우는 데 쓴다.

## 3층 · 깃에서 자동으로 채워지는 칸

운영진 양식의 열한 칸이 우리 데이터와 이렇게 맞는다.

| 공식 칸 | 우리 데이터 | 지금 |
|---|---|---|
| WBS | 작업 영역 라벨 | 만들 것 |
| 작업 이름 | 이슈 제목 (`[작업]` 접두어 뗀 것) | 있음 |
| 시작날짜 | 보드 `start date` | **자동** |
| 예상 완료 날짜 | 보드 `end date` | **자동** |
| 실제 완료 날짜 | 이슈 닫힌 날 | **자동** |
| 기간 · 계획율 · 기간경과율 | 수식 | 계산 |
| 완료율 | Status (Todo 0 · In Progress 50 · Done 100) | **자동** |
| 담당자 | Assignee | **자동** |
| 산출물 | 마일스톤에 걸린 `deliverables/` 파일 | 만들 것 |

## 갱신 주기

| 무엇 | 언제 | 방법 |
|---|---|---|
| `wbs.xlsx` | 주간 다이제스트가 돌 때 함께 | 같은 워크플로에 한 단계 추가. 별도 스케줄을 만들지 않는다 |
| `wbs.xlsx` (수시) | 제출 직전 등 필요할 때 | GitHub Actions 의 Run workflow 단추. 실행 후 1~2분 안에 반영 |
| 홈페이지 WBS 그림 | 웹을 빌드할 때 | 같은 데이터에서 그린다 |

즉시 반영이 아닌 이유: 이슈가 바뀔 때마다 파일을 다시 만들면 커밋 이력이
지저분해지고 얻는 것이 없다. 보는 시점에 최신이면 충분하다.
