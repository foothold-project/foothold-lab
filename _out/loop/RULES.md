## 1. 판별식 · 「끝났는가」를 무엇으로 보는가

```
학습이 끝났나       model_3000.pt 가 «있고» 그 PID 가 «죽었나»
                    로그의 마지막 iteration «과» finished exit= 를 «둘 다» 본다
평가가 끝났나       산출물 파일 수가 «기대 수와 같나» (축1 24 · 축2 4)
                    «그리고» eval_ 프로세스가 0 개인가
검증이 끝났나       **그 검증자가 쓰기로 한 «파일» 이 있고 «더 안 자라나»**
                    터미널이 도는지가 «아니다»
```

**금지 · 아래를 「끝났다」의 증거로 쓰지 않는다.**

```
내가 명령을 «걸었다»            거는 것과 끝나는 것은 다르다
터미널이 «살아 있다»            TUI 는 일이 끝나도 산다
로그 꼬리에 오류가 «없다»        침묵은 성공이 아니다
집계 숫자가 «그럴듯하다»         자료 0 개에도 「하락 0」이 나온다
```

## 2. 규칙 · **긴 작업을 걸 때마다 대기자를 «같이» 건다**

| 작업 | 같이 걸 것 |
|---|---|
| 학습 | `bash _out/loop/chain.sh` (`WATCH_RUNS` 로 판 지정) |
| 평가 | `chain.sh` 안에 들어 있다 |
| **검증자 (astra · fable)** | **`bash _out/loop/await_output.sh <산출물경로> "<설명>" <최대분>`** |

**대기자를 안 걸면 또 기다린다.** 「나중에 확인하겠습니다」는 지킬 수단이 없다.

### 검증자를 띄우는 절차

```
1  의뢰서를 쓴다                inbox/jay/.../TASK-*.md
2  워크트리에 복사한다
3  검증자에 보낸다              orca terminal send ... 또는 Agent
4  **같은 턴에 대기자를 건다**   await_output.sh <그 검증자가 쓸 파일> ...
                               배경으로 걸어야 나를 깨운다
```

4 를 빼먹은 것이 2026-09-26 의 사고다. astra 는 12:58 에 끝났고 내가
15:21 에 알았다. **GPU 가 3 시간 놀았다.**

```

이미 있는 파일          -> 60 초 뒤 「끝났다 · 11675 bytes · 139 행」
```

## 4. 검증자가 끝나면 «파일을 저장소로 가져온다»

2026-09-26 에 전수로 훑어 `AUDIT5-device.md` (11,675 바이트) 가 **워크트리에만
있고 저장소에 없는 것**을 찾았다. 이틀 전 터미널 요약만 읽고 문서를 안
가져왔다. **요약을 읽은 것은 문서를 가져온 것이 아니다.**

```
검증이 끝나면
  1  워크트리 -> 저장소로 복사
  2  커밋
  3  «읽고» 보고 · 내 주장이 뒤집힌 곳을 먼저 적는다
```
